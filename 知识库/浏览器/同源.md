# 同源策略

**同源策略**是一种关键的安全机制，它限制了一个[源](https://developer.mozilla.org/en-US/docs/Glossary/Origin)加载的文档或脚本如何与来自另一个源的资源进行交互。

它有助于隔离潜在的恶意文档，减少可能的攻击途径。例如，它可以防止互联网上的恶意网站在浏览器中运行 JS 来读取第三方 Web 邮件服务（用户已登录）或公司内网（由于没有公共 IP 地址，攻击者无法直接访问）的数据，并将这些数据转发给攻击者。

## 源的定义

如果两个 URL 的[协议](https://developer.mozilla.org/en-US/docs/Glossary/Protocol)、[端口](https://developer.mozilla.org/en-US/docs/Glossary/Port)（如果指定）和[主机](https://developer.mozilla.org/en-US/docs/Glossary/Host)都相同，则它们具有*相同的源*。你可能会看到这被称为“scheme/host/port 元组”，或简称为“元组”。（“元组”是一组共同构成整体的项——双元组/三元组/四元组/五元组等的通用形式。）

下表给出了与 URL `http://store.company.com/dir/page.html` 进行源比较的示例：

| URL | 结果 | 原因 |
| --- | --- | --- |
| `http://store.company.com/dir2/other.html` | 同源 | 仅路径不同 |
| `http://store.company.com/dir/inner/another.html` | 同源 | 仅路径不同 |
| `https://store.company.com/page.html` | 失败 | 协议不同 |
| `http://store.company.com:81/dir/page.html` | 失败 | 端口不同（`http://` 默认端口为 80） |
| `http://news.company.com/dir/page.html` | 失败 | 主机不同 |

### 继承的源

从具有 `about:blank` 或 [`javascript:` URL](https://developer.mozilla.org/en-US/docs/Web/URI/Reference/Schemes/javascript) 的页面执行的脚本会继承包含该 URL 的文档的源，因为这些类型的 URL 不包含源服务器的信息。

例如，`about:blank` 经常被用作新的空白弹出窗口的 URL，父脚本将内容写入其中（例如，通过 [`Window.open()`](https://developer.mozilla.org/en-US/docs/Web/API/Window/open) 机制）。如果此弹出窗口也包含 JavaScript，则该脚本将继承创建它的脚本的相同源。

`data:` URL 会获得一个新的、空的安全上下文。

### 文件源

现代浏览器通常将通过 `file:///` 方案加载的文件的源视为*不透明源*。这意味着如果一个文件包含来自同一文件夹（比如）的其他文件，它们不会被假定来自同一源，并可能触发 [CORS](https://developer.mozilla.org/en-US/docs/Glossary/CORS) 错误。

请注意，[URL 规范](https://url.spec.whatwg.org/#origin)指出文件的源取决于实现，某些浏览器可能会将同一目录或子目录中的文件视为同源，尽管这会带来[安全隐患](https://www.mozilla.org/en-US/security/advisories/mfsa2019-21/#CVE-2019-11730)。

## 更改源

> **警告：**
> 此处描述的方法（使用 [`document.domain`](https://developer.mozilla.org/en-US/docs/Web/API/Document/domain) setter）已被弃用，因为它破坏了同源策略提供的安全保护，并使浏览器中的源模型复杂化，导致互操作问题和安全漏洞。

页面可以在一定限制下更改自己的源。脚本可以将 [`document.domain`](https://developer.mozilla.org/en-US/docs/Web/API/Document/domain) 的值设置为其当前域或当前域的父域。如果设置为当前域的父域，则较短的父域将用于同源检查。

例如，假设来自文档 `http://store.company.com/dir/other.html` 的脚本执行以下操作：

```js
document.domain = "company.com";
```

之后，该页面可以通过 `http://company.com/dir/page.html` 的同源检查（假设 `http://company.com/dir/page.html` 将其 `document.domain` 设置为 `"company.com"` 以表示它希望允许这样做——更多信息请参见 [`document.domain`](https://developer.mozilla.org/en-US/docs/Web/API/Document/domain)）。但是，`company.com` **不能**将 `document.domain` 设置为 `othercompany.com`，因为那不是 `company.com` 的父域。

端口号由浏览器单独检查。任何对 `document.domain` 的调用，包括 `document.domain = document.domain`，都会导致端口号被覆盖为 `null`。因此，**不能**仅通过在第一个中设置 `document.domain = "company.com"` 来使 `company.com:8080` 与 `company.com` 通信。必须在两者中都设置，以便它们的端口号都为 `null`。

该机制有一些限制。例如，如果文档位于沙盒化的 [`<iframe>`](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe) 中，它将抛出 `SecurityError` [`DOMException`](https://developer.mozilla.org/en-US/docs/Web/API/DOMException)，并且以这种方式更改源不会影响许多 Web API（例如 [`localStorage`](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage)、[`indexedDB`](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API)、[`BroadcastChannel`](https://developer.mozilla.org/en-US/docs/Web/API/BroadcastChannel)、[`SharedWorker`](https://developer.mozilla.org/en-US/docs/Web/API/SharedWorker)）使用的源检查。更详尽的失败案例列表可以在 [Document.domain > 失败](https://developer.mozilla.org/en-US/docs/Web/API/Document/domain#failures) 中找到。

> **注意：**
> 当使用 `document.domain` 允许子域访问其父域时，你需要在父域和子域中将 `document.domain` 设置为*相同的值*。即使这样做是将父域设置回其原始值，这也是必要的。否则可能会导致权限错误。

## 跨源网络访问

同源策略控制两个不同源之间的交互，例如当你使用 [`fetch()`](https://developer.mozilla.org/en-US/docs/Web/API/Window/fetch) 或 [`<img>`](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/img) 元素时。这些交互通常分为三类：

- 跨源*写入*通常被允许。例如链接、重定向和表单提交。某些 HTTP 请求需要[预检](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS#preflighted_requests)。
- 跨源*嵌入*通常被允许。（示例如下。）
- 跨源*读取*通常被禁止，但读取访问通常通过嵌入泄露。例如，你可以读取嵌入图像的尺寸、嵌入脚本的操作，或[嵌入资源的可用性](https://bugzil.la/629094)。

以下是一些可以跨源嵌入的资源的示例：

- 使用 `<script src="…"></script>` 的 JavaScript。语法错误的错误详情仅对同源脚本可用。
- 使用 `<link rel="stylesheet" href="…">` 应用的 CSS。由于 CSS 的宽松语法规则，跨源 CSS 需要正确的 `Content-Type` 头。如果跨源加载的 MIME 类型不正确且资源不以有效的 CSS 构造开头，浏览器会阻止样式表加载。
- 由 [`<img>`](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/img) 显示的图像。
- 由 [`<video>`](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/video) 和 [`<audio>`](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/audio) 播放的媒体。
- 使用 [`<object>`](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/object) 和 [`<embed>`](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/embed) 嵌入的外部资源。
- 使用 [`@font-face`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@font-face) 应用的字体。某些浏览器允许跨源字体，其他浏览器要求同源。
- 由 [`<iframe>`](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe) 嵌入的任何内容。站点可以使用 [`X-Frame-Options`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/X-Frame-Options) 头来防止跨源框架。

### 如何允许跨源访问

使用 [CORS](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS) 允许跨源访问。CORS 是 [HTTP](https://developer.mozilla.org/en-US/docs/Glossary/HTTP) 的一部分，允许服务器指定浏览器应允许从哪些其他主机加载内容。

### 如何阻止跨源访问

- 要防止跨源写入，请检查请求中不可猜测的令牌——称为[跨站请求伪造（CSRF）](https://community.owasp.org/attacks/csrf)令牌。你必须防止对需要此令牌的页面进行跨源读取。
- 要防止对资源的跨源读取，请确保它不可嵌入。通常有必要防止嵌入，因为嵌入资源总会泄露有关它的一些信息。
- 要防止跨源嵌入，请确保你的资源不能被解释为上面列出的可嵌入格式之一。浏览器可能不遵守 `Content-Type` 头。例如，如果你将 `<script>` 标签指向 HTML 文档，浏览器将尝试将 HTML 解析为 JavaScript。当你的资源不是站点的入口点时，你也可以使用 CSRF 令牌来防止嵌入。

## 跨源脚本 API 访问

像 [`iframe.contentWindow`](https://developer.mozilla.org/en-US/docs/Web/API/HTMLIFrameElement/contentWindow)、[`window.parent`](https://developer.mozilla.org/en-US/docs/Web/API/Window/parent)、[`window.open`](https://developer.mozilla.org/en-US/docs/Web/API/Window/open) 和 [`window.opener`](https://developer.mozilla.org/en-US/docs/Web/API/Window/opener) 这样的 JavaScript API 允许文档直接相互引用。当两个文档不具有相同的源时，这些引用对 [`Window`](https://developer.mozilla.org/en-US/docs/Web/API/Window) 和 [`Location`](https://developer.mozilla.org/en-US/docs/Web/API/Location) 对象的访问非常有限，如下两节所述。

要在来自不同源的文档之间进行通信，请使用 [`window.postMessage`](https://developer.mozilla.org/en-US/docs/Web/API/Window/postMessage)。

规范：[HTML Living Standard § Cross-origin objects](https://html.spec.whatwg.org/multipage/browsers.html#cross-origin-objects)。

## 跨源数据存储访问

对存储在浏览器中的数据（如 [Web Storage](https://developer.mozilla.org/en-US/docs/Web/API/Web_Storage_API) 和 [IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API)）的访问按源分隔。每个源都有自己独立的存储，一个源中的 JavaScript 无法读取或写入属于另一个源的存储。

[Cookie](https://developer.mozilla.org/en-US/docs/Glossary/Cookie) 使用单独的源定义。页面可以为其自己的域或任何父域设置 cookie，只要父域不是公共后缀。Firefox 和 Chrome 使用[公共后缀列表](https://publicsuffix.org/)来确定域是否为公共后缀。设置 cookie 时，你可以使用 `Domain`、`Path`、`Secure` 和 `HttpOnly` 标志限制其可用性。读取 cookie 时，你无法看到它是在哪里设置的。即使你只使用安全的 https 连接，你看到的任何 cookie 都可能是在不安全的连接上设置的。
