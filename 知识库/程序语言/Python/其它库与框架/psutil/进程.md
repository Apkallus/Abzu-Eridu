# 进程

## 函数

### psutil.pids()

返回当前正在运行的 PID 的排序列表。  
要遍历所有进程并避免竞态条件，应优先使用 `process_iter()`。

```pycon
>>> import psutil
>>> psutil.pids()
[1, 2, 3, 5, 7, 8, 9, 10, 11, 12, 13, 14, 15, 17, 18, 19, ..., 32498]
```

> **版本 5.6.0 变更：** PID 按排序顺序返回

### psutil.process_iter()

```py
psutil.process_iter(attrs=None, ad_value=None)
```

返回一个迭代器，为本地机器上所有正在运行的进程生成 `Process` 类实例。  
应优先使用它而不是 `psutil.pids()` 来遍历进程，因为获取信息时不会受到竞态条件影响。

每个 `Process` 实例只会创建一次，然后缓存起来供下次调用 `psutil.process_iter()` 时使用（前提是 PID 仍然存活）。  
可以通过 `process_iter.cache_clear()` 选择性地清除缓存。

`attrs` 和 `ad_value` 的含义与 `Process.as_dict()` 中相同。  
如果指定了 `attrs`，则 `Process.as_dict()` 的结果会作为 `info` 属性附加到返回的 `Process` 实例上。  
如果 `attrs` 是空列表，则会获取所有进程信息（较慢）。

进程返回的排序顺序基于它们的 PID。

示例：

```pycon
>>> import psutil
>>> for proc in psutil.process_iter(['pid', 'name', 'username']):
...     print(proc.info)
...
{'name': 'systemd', 'pid': 1, 'username': 'root'}
{'name': 'kthreadd', 'pid': 2, 'username': 'root'}
{'name': 'ksoftirqd/0', 'pid': 3, 'username': 'root'}
...
```

使用字典推导式创建 `{pid: info, ...}` 数据结构：

```pycon
>>> import psutil
>>> procs = {p.pid: p.info for p in psutil.process_iter(['name', 'username'])}
>>> procs
{1: {'name': 'systemd', 'username': 'root'},
 2: {'name': 'kthreadd', 'username': 'root'},
 3: {'name': 'ksoftirqd/0', 'username': 'root'},
 ...}
```

清除内部缓存：

```pycon
>>> psutil.process_iter.cache_clear()
```

> **版本 5.3.0 变更：** 添加了 `attrs` 和 `ad_value` 参数。

> **版本 6.0.0 变更：** 不再检查每个生成的进程 PID 是否已被重用。

> **版本 6.0.0 变更：** 添加了 `psutil.process_iter.cache_clear()` API。

### psutil.pid_exists()

```py
psutil.pid_exists(pid)
```

检查给定 PID 是否存在于当前进程列表中。  
这比执行 `pid in psutil.pids()` 更快，应优先使用。

### psutil.wait_procs()

```py
psutil.wait_procs(procs, timeout=None, callback=None)
```

便捷函数，等待一组 `Process` 实例终止。  
返回一个 `(gone, alive)` 元组，表示哪些进程已消失、哪些仍然存活。已消失的进程会有一个新的 `returncode` 属性，表示由 `Process.wait()` 返回的进程退出状态。  
`callback` 是一个函数，当被等待的某个进程终止时会被调用，并将一个 `Process` 实例作为回调参数传入（该实例也会设置 `returncode` 属性）。  
该函数会在所有进程终止或发生 `timeout`（秒）时尽快返回。  
与 `Process.wait()` 不同，如果发生超时，它不会抛出 `TimeoutExpired`。  
典型用例可能是：

- 向一组进程发送 `SIGTERM`
- 给它们一些时间终止
- 向仍然存活的进程发送 `SIGKILL`

示例：终止并等待当前进程的所有子进程：

```py
import psutil

def on_terminate(proc):
    print("process {} terminated with exit code {}".format(proc, proc.returncode))

procs = psutil.Process().children()
for p in procs:
    p.terminate()
gone, alive = psutil.wait_procs(procs, timeout=3, callback=on_terminate)
for p in alive:
    p.kill()
```

## 异常

### psutil.Error

基异常类。所有其他异常都继承自它。

### psutil.NoSuchProcess()

```py
psutil.NoSuchProcess(pid, name=None, msg=None)
```

当当前进程列表中找不到给定 `pid` 的进程，或进程不再存在时，由 `Process` 类方法抛出。  
`name` 是进程消失前拥有的名称，仅当之前调用过 `Process.name()` 时才会设置。

### psutil.ZombieProcess()

```py
psutil.ZombieProcess(pid, name=None, ppid=None, msg=None)
```

在 UNIX 上查询僵尸进程时，可能由 `Process` 类方法抛出（Windows 没有僵尸进程）。  
如果在进程变成僵尸之前调用过 `Process.name()` 或 `Process.ppid()` 方法，则 `name` 和 `ppid` 属性可用。

> **注意**
>
> 这是 `NoSuchProcess` 的子类，因此如果你不关心获取僵尸进程（例如使用 `process_iter()` 时），可以忽略此异常，只捕获 `NoSuchProcess`。

> **版本 3.0.0 添加。**

### psutil.AccessDenied()

```py
psutil.AccessDenied(pid=None, name=None, msg=None)
```

当由于权限不足而拒绝执行操作时，由 `Process` 类方法抛出。  
如果之前调用过 `Process.name()`，则 `name` 属性可用。

### psutil.TimeoutExpired()

```py
psutil.TimeoutExpired(seconds, pid=None, name=None, msg=None)
```

如果超时时间到期且进程仍然存活，由 `Process.wait()` 方法抛出。  
如果之前调用过 `Process.name()`，则 `name` 属性可用。

## Process 类

### psutil.Process()

```py
psutil.Process(pid=None)
```

表示具有给定 `pid` 的操作系统进程。  
如果省略 `pid`，则使用当前进程的 `pid`（`os.getpid`）。  
如果 `pid` 不存在，则抛出 `NoSuchProcess`。  
在 Linux 上，`pid` 也可以指线程 ID（`threads()` 方法返回的 `id` 字段）。  
访问此类的方法时，始终要准备好捕获 `NoSuchProcess` 和 `AccessDenied` 异常。  
可以对这类实例使用内建函数 `hash`，以便在时间上唯一标识一个进程（哈希由进程 PID + 创建时间混合决定）。因此它也可以与 `set` 一起使用。

> **注意**
>
> 为了高效地同时获取多个进程信息，请确保使用 `oneshot()` 上下文管理器或 `as_dict()` 实用方法。

> **注意**
>
> 该类绑定到进程的方式是通过其 **PID**。这意味着如果进程终止且操作系统复用了其 PID，你可能会无意中查询到另一个进程。为避免此问题，可以先使用 `is_running()`。  
> 唯一会预先检查 PID 是否被复用（通过 PID + 创建时间）的方法有：  
> `nice()`（设置）、`ionice()`（设置）、`cpu_affinity()`（设置）、`rlimit()`（设置）、`children()`、`ppid()`、`parent()`、`parents()`、`suspend()`、`resume()`、`send_signal()`、`terminate()` 和 `kill()`。

#### oneshot()

用于同时获取多个进程信息时可显著提速的实用上下文管理器。  
内部不同的进程信息（例如 `name()`、`ppid()`、`uids()`、`create_time()` 等）可能通过同一例程获取，但只返回一个值，其他值会被丢弃。  
使用此上下文管理器时，内部例程只执行一次（在下面的示例中是在 `name()` 上），返回感兴趣的值，并缓存其他值。  
后续共享同一内部例程的调用将返回缓存值。  
退出上下文管理器块时会清除缓存。  
建议每次获取多个进程信息时都使用它。如果幸运的话，你会获得极大的加速。  
示例：

```pycon
>>> import psutil
>>> p = psutil.Process()
>>> with p.oneshot():
...     p.name()  # execute internal routine once collecting multiple info
...     p.cpu_times()  # return cached value
...     p.cpu_percent()  # return cached value
...     p.create_time()  # return cached value
...     p.ppid()  # return cached value
...     p.status()  # return cached value
...
>>>
```

#### pid

进程 PID。这是该类唯一的（只读）属性。

#### ppid()

进程父 PID。在 Windows 上，返回值在第一次调用后会被缓存。POSIX 上不会，因为如果进程变成僵尸，ppid 可能会改变。  
另请参阅 `parent()` 和 `parents()` 方法。

#### name()

进程名称。在 Windows 上，返回值在第一次调用后会被缓存。POSIX 上不会，因为进程名称可能会改变。  
另请参阅如何“按名称查找进程”。

#### exe()

进程可执行文件的绝对路径。在某些系统上，如果由于某些内部原因（例如系统进程或路径不再存在）无法确定 exe，则可能为空字符串。返回值在第一次调用后会被缓存。

```pycon
>>> import psutil
>>> psutil.Process().exe()
'/usr/bin/python3'
```

#### cmdline()

调用此进程时使用的命令行，作为字符串列表。返回值不会被缓存，因为进程的 cmdline 可能会改变。

```pycon
>>> import psutil
>>> psutil.Process().cmdline()
['python', 'manage.py', 'runserver']
```

#### create_time()

进程创建时间，以浮点数表示，单位为自 epoch（1970 年 1 月 1 日午夜 UTC）以来的秒数。返回值在第一次调用后会被缓存，它基于系统时钟，这意味着它可能会受到手动调整或时间同步（例如 NTP）等变化的影响。

```pycon
>>> import psutil, datetime
>>> p = psutil.Process()
>>> p.create_time()
1307289803.47
>>> datetime.datetime.fromtimestamp(p.create_time()).strftime("%Y-%m-%d %H:%M:%S")
'2011-03-05 18:03:52'
```

#### as_dict()

```py
as_dict(attrs=None, ad_value=None)
```

以字典形式获取多个进程信息的实用方法。  
如果指定了 `attrs`，它必须是一个字符串列表，反映可用的 `Process` 类属性名。以下是可能的字符串值：  
`'cmdline'`、`'net_connections'`、`'cpu_affinity'`、`'cpu_num'`、`'cpu_percent'`、`'cpu_times'`、`'create_time'`、`'cwd'`、`'environ'`、`'exe'`、`'gids'`、`'io_counters'`、`'ionice'`、`'memory_full_info'`、`'memory_info'`、`'memory_maps'`、`'memory_percent'`、`'name'`、`'nice'`、`'num_ctx_switches'`、`'num_fds'`、`'num_handles'`、`'num_threads'`、`'open_files'`、`'pid'`、`'ppid'`、`'status'`、`'terminal'`、`'threads'`、`'uids'`、`'username'`。  
如果未传入 `attrs` 参数，则假定所有公共只读属性。  
`ad_value` 是在获取特定进程信息时如果抛出 `AccessDenied` 或 `ZombieProcess` 异常，分配给字典键的值。  
内部 `as_dict()` 使用 `oneshot()` 上下文管理器，因此你无需再使用它。

```pycon
>>> import psutil
>>> p = psutil.Process()
>>> p.as_dict(attrs=['pid', 'name', 'username'])
{'username': 'giampaolo', 'pid': 12366, 'name': 'python'}
>>>
>>> # get a list of valid attrs names
>>> list(psutil.Process().as_dict().keys())
['cmdline', 'connections', 'cpu_affinity', 'cpu_num', 'cpu_percent', 'cpu_times', 'create_time', 'cwd', 'environ', 'exe', 'gids', 'io_counters', 'ionice', 'memory_full_info', 'memory_info', 'memory_maps', 'memory_percent', 'name', 'net_connections', 'nice', 'num_ctx_switches', 'num_fds', 'num_threads', 'open_files', 'pid', 'ppid', 'status', 'terminal', 'threads', 'uids', 'username']
```

> **版本 3.0.0 变更：** 当遇到 `ZombieProcess` 异常时也会使用 `ad_value`，而不仅是 `AccessDenied`

> **版本 4.5.0 变更：** 得益于 `oneshot()` 上下文管理器，`as_dict()` 显著更快。

#### parent()

实用方法，返回父进程作为 `Process` 对象，并预先检查 PID 是否已被重用。如果不知道父 PID，则返回 `None`。  
另请参阅 `ppid()` 和 `parents()` 方法。

#### parents()

实用方法，返回此进程的父进程列表，作为 `Process` 实例列表。如果不知道父进程，则返回空列表。  
另请参阅 `ppid()` 和 `parent()` 方法。

> **版本 5.6.0 添加。**

#### status()

当前进程状态，作为字符串。返回的字符串是 `psutil.STATUS_*` 常量之一。

#### cwd()

进程当前工作目录，作为绝对路径。如果由于某些内部原因（例如系统进程或目录不再存在）无法确定 cwd，则可能返回空字符串。

> **版本 5.6.4 变更：** 添加 NetBSD 支持

#### username()

拥有该进程的用户名。在 UNIX 上，这是通过真实进程 `uid` 计算得出的。

#### uids()

此进程的真实、有效和保存的用户 ID，作为命名元组。  
这与 `os.getresuid` 相同，但可用于任何进程 PID。

可用性：UNIX

#### gids()

此进程的真实、有效和保存的组 ID，作为命名元组。  
这与 `os.getresgid` 相同，但可用于任何进程 PID。

可用性：UNIX

#### terminal()

与此进程关联的终端（如果有），否则为 `None`。这类似于 `tty` 命令，但可用于任何进程 PID。

可用性：UNIX

#### nice()

```py
nice(value=None)
```

获取或设置进程的 niceness（优先级）。  
在 UNIX 上，这是一个通常从 `-20` 到 `20` 的数字。nice 值越高，进程优先级越低。

```pycon
>>> import psutil
>>> p = psutil.Process()
>>> p.nice(10)  # set
>>> p.nice()  # get
10
>>>
```

从 Python 3.3 开始，此功能也可通过 `os.getpriority` 和 `os.setpriority` 使用（参见 [BPO-10784](https://bugs.python.org/issue10784)）。  
在 Windows 上，这是通过 [GetPriorityClass](https://docs.microsoft.com/en-us/windows/desktop/api/processthreadsapi/nf-processthreadsapi-getpriorityclass) 和 [SetPriorityClass](https://docs.microsoft.com/en-us/windows/desktop/api/processthreadsapi/nf-processthreadsapi-setpriorityclass) Windows API 实现的，`value` 是 `psutil.*_PRIORITY_CLASS` 常量之一，反映 MSDN 文档。  
在 Windows 上提高进程优先级的示例：

```pycon
>>> p.nice(psutil.HIGH_PRIORITY_CLASS)
```

#### ionice()

```py
ionice(ioclass=None, value=None)
```

获取或设置进程的 I/O niceness（优先级）。  
如果未提供参数，则作为 getter 使用，在 Linux 上返回 `(ioclass, value)` 元组，在 Windows 上返回 `ioclass` 整数。  
如果提供了 `ioclass`，则作为 setter 使用。在这种情况下，仅在 Linux 上可以指定额外的 `value`，以进一步增加或降低 I/O 优先级。  
以下是可能的平台相关 `ioclass` 值。

Linux（参见 [ioprio_get](https://linux.die.net/man/2/ioprio_get) 手册）：

- `IOPRIO_CLASS_RT`  
    （高）进程每次都能优先访问磁盘。请谨慎使用，因为它可能使整个系统饥饿。可以指定额外的优先级 `level`，范围从 `0`（最高）到 `7`（最低）。

- `IOPRIO_CLASS_BE`  
    （普通）任何未设置特定 I/O 优先级的进程的默认值。额外优先级 `level` 范围从 `0`（最高）到 `7`（最低）。

- `IOPRIO_CLASS_IDLE`  
    （低）当没有其他进程需要磁盘时才获得 I/O 时间。不接受额外 `value`。

- `IOPRIO_CLASS_NONE`  
    当之前未设置优先级时返回。

Windows：

- `IOPRIO_HIGH`  
    最高优先级。

- `IOPRIO_NORMAL`  
    默认优先级。

- `IOPRIO_LOW`  
    低优先级。

- `IOPRIO_VERYLOW`  
    最低优先级。

以下示例根据所在平台设置最高 I/O 优先级：

```pycon
>>> import psutil
>>> p = psutil.Process()
>>> if psutil.LINUX:
...     p.ionice(psutil.IOPRIO_CLASS_RT, value=7)
... else:
...     p.ionice(psutil.IOPRIO_HIGH)
...
>>> p.ionice()  # get
pionice(ioclass=<IOPriority.IOPRIO_CLASS_RT: 1>, value=7)
```

可用性：Linux、Windows Vista+

> **版本 5.6.2 变更：** Windows 接受新的 `IOPRIO_*` 常量，包括新的 `IOPRIO_HIGH`。

#### rlimit()

```py
rlimit(resource, limits=None)
```

获取或设置进程资源限制（参见 [man prlimit](https://linux.die.net/man/2/prlimit)）。`resource` 是 `psutil.RLIMIT_*` 常量之一。  
`limits` 是一个 `(soft, hard)` 元组。  
这与 `resource.getrlimit` 和 `resource.setrlimit` 相同，但可用于任何进程 PID，而不仅是 `os.getpid`。  
对于 get，返回值是 `(soft, hard)` 元组。每个值可以是整数或 `psutil.RLIMIT_*`。  
示例：

```pycon
>>> import psutil
>>> p = psutil.Process()
>>> p.rlimit(psutil.RLIMIT_NOFILE, (128, 128))   # process can open max 128 file descriptors
>>> p.rlimit(psutil.RLIMIT_FSIZE, (1024, 1024))  # can create files no bigger than 1024 bytes
>>> p.rlimit(psutil.RLIMIT_FSIZE)                # get
(1024, 1024)
>>>
```

另请参阅 [procinfo.py](https://github.com/giampaolo/psutil/blob/master/scripts/procinfo.py) 脚本。

可用性：Linux、FreeBSD

> **版本 5.7.3 变更：** 添加 FreeBSD 支持

#### io_counters()

返回进程 I/O 统计信息，作为命名元组。  
对于 Linux，可以参考 [/proc filesystem documentation](https://stackoverflow.com/questions/3633286/)。

- `read_count`  
    执行的读取操作数（累计）。在 UNIX 上，这应计数与读取相关的系统调用，例如 `read()` 和 `pread()`。

- `write_count`  
    执行的写入操作数（累计）。在 UNIX 上，这应计数与写入相关的系统调用，例如 `write()` 和 `pwrite()`。

- `read_bytes`  
    读取的字节数（累计）。在 BSD 上始终为 `-1`。

- `write_bytes`  
    写入的字节数（累计）。在 BSD 上始终为 `-1`。

Linux 特定：

- `read_chars`（Linux）  
    此进程传递给 `read()` 和 `pread()` 系统调用的字节量（累计）。与 `read_bytes` 不同，它不关心是否发生了实际物理磁盘 I/O。

- `write_chars`（Linux）  
    此进程传递给 `write()` 和 `pwrite()` 系统调用的字节量（累计）。与 `write_bytes` 不同，它不关心是否发生了实际物理磁盘 I/O。

Windows 特定：

- `other_count`（Windows）  
    除读写操作之外执行的 I/O 操作数。

- `other_bytes`（Windows）  
    除读写操作之外传输的字节数。

```pycon
>>> import psutil
>>> p = psutil.Process()
>>> p.io_counters()
pio(read_count=454556, write_count=3456, read_bytes=110592, write_bytes=0, read_chars=769931, write_chars=203)
```

#### cpu_times()

返回表示累计进程时间的命名元组，单位为秒（参见[解释](http://stackoverflow.com/questions/556405/)）。  
这类似于 `os.times`，但可用于任何进程 PID。

- `user`  
    在用户模式下花费的时间。

- `system`  
    在内核模式下花费的时间。

- `children_user`  
    所有子进程的用户时间（在 Windows 和 macOS 上始终为 `0`）。

- `children_system`  
    所有子进程的系统时间（在 Windows 和 macOS 上始终为 `0`）。

- `iowait`  
    （Linux）等待阻塞 I/O 完成所花费的时间。此值不计入 `user` 和 `system` 时间（因为 CPU 没有做任何工作）。

```pycon
>>> import psutil
>>> p = psutil.Process()
>>> p.cpu_times()
pcputimes(user=0.03, system=0.67, children_user=0.0, children_system=0.0, iowait=0.08)
>>> sum(p.cpu_times()[:2])  # cumulative, excluding children and iowait
0.70
```

> **版本 4.1.0 变更：** 返回两个额外字段：`children_user` 和 `children_system`。

> **版本 5.6.4 变更：** 在 Linux 上添加 `iowait`。

#### cpu_percent()

```py
cpu_percent(interval=None)
```

返回一个浮点数，表示进程 CPU 利用率百分比；如果进程在多个 CPU 上运行多个线程，该值也可能 `> 100.0`。  
当 `interval` > `0.0` 时，会比较间隔前后经过的系统 CPU 时间与进程时间（阻塞）。当 interval 为 `0.0` 或 `None` 时，会比较自上次调用以来经过的系统 CPU 时间与进程时间，并立即返回。这意味着第一次调用时会返回一个无意义的 `0.0` 值，你应该忽略它。在这种情况下，为了准确性，建议在至少间隔 `0.1` 秒后第二次调用此函数。  
示例：

```pycon
>>> import psutil
>>> p = psutil.Process()
>>> # blocking
>>> p.cpu_percent(interval=1)
2.0
>>> # non-blocking (percentage since last call)
>>> p.cpu_percent(interval=None)
2.9
```

> **注意**
>
> 如果进程在多个 CPU 核心上运行多个线程，返回值可能 > 100.0。

> **注意**
>
> 返回值明确地 **不会** 在所有可用 CPU 之间平均分配（不同于 `psutil.cpu_percent()`）。这意味着在具有 2 个逻辑 CPU 的系统上运行忙碌循环进程时，会报告 100% CPU 利用率，而不是 50%。这样做是为了与 UNIX `top` 实用程序保持一致，并且更容易识别占用 CPU 资源的进程，而不受 CPU 数量影响。必须注意，Windows 上的 `taskmgr.exe` 不会这样表现（它会报告 50% 使用率）。要模拟 Windows `taskmgr.exe` 的行为，可以执行：`p.cpu_percent() / psutil.cpu_count()`。

> **警告**
>
> 第一次以 interval = `0.0` 或 `None` 调用此方法时，会返回一个无意义的 `0.0` 值，你应该忽略它。

#### cpu_affinity()

```py
cpu_affinity(cpus=None)
```

获取或设置进程当前的 [CPU affinity](http://www.linuxjournal.com/article/6799?page=0,0)。  
CPU affinity 是指告诉操作系统仅在有限的一组 CPU 上运行进程（在 Linux 命令行中，通常使用 `taskset` 命令）。  
如果未传入参数，则返回当前 CPU affinity，作为整数列表。  
如果传入参数，则必须是一个整数列表，指定新的 CPU affinity。如果传入空列表，则假定（并设置）所有符合条件的 CPU。在某些系统（例如 Linux）上，这可能不一定意味着所有可用逻辑 CPU，如 `list(range(psutil.cpu_count()))`。

```pycon
>>> import psutil
>>> psutil.cpu_count()
4
>>> p = psutil.Process()
>>> # get
>>> p.cpu_affinity()
[0, 1, 2, 3]
>>> # set; from now on, process will run on CPU #0 and #1 only
>>> p.cpu_affinity([0, 1])
>>> p.cpu_affinity()
[0, 1]
>>> # reset affinity against all eligible CPUs
>>> p.cpu_affinity([])
```

可用性：Linux、Windows、FreeBSD

> **版本 2.2.0 变更：** 添加 FreeBSD 支持

> **版本 5.1.0 变更：** 可以传入空列表，以针对所有符合条件的 CPU 设置 affinity。

它可以与 `psutil.cpu_percent(percpu=True)` 结合使用，以观察系统工作负载在多个 CPU 上的分布，如 [cpu_distribution.py](https://github.com/giampaolo/psutil/blob/master/scripts/cpu_distribution.py) 示例脚本所示。

#### memory_info()

返回一个命名元组，其字段因平台而异，表示进程的内存信息。  
所有平台上可用的“可移植”字段是 `rss` 和 `vms`。  
所有数字均以字节表示。

| Linux | macOS | BSD | Solaris | AIX | Windows |
|---|---|---|---|---|---|
| `rss` | `rss` | `rss` | `rss` | `rss` | `rss`（`wset` 的别名） |
| `vms` | `vms` | `vms` | `vms` | `vms` | `vms`（`pagefile` 的别名） |
| `shared` | `pfaults` | `text` |  |  | `num_page_faults` |
| `text` | `pageins` | `data` |  |  | `peak_wset` |
| `lib` |  | `stack` |  |  | `wset` |
| `data` |  |  |  |  | `peak_paged_pool` |
| `dirty` |  |  |  |  | `paged_pool` |
|  |  |  |  |  | `peak_nonpaged_pool` |
|  |  |  |  |  | `nonpaged_pool` |
|  |  |  |  |  | `pagefile` |
|  |  |  |  |  | `peak_pagefile` |
|  |  |  |  |  | `private` |

- `rss`  
    又名“Resident Set Size”，这是进程已使用的非交换物理内存。在 UNIX 上，它匹配 `top` 的 RES 列。在 Windows 上，它是 `wset` 字段的别名，匹配 taskmgr.exe 的“Mem Usage”列。

- `vms`  
    又名“Virtual Memory Size”，这是进程使用的虚拟内存总量。在 UNIX 上，它匹配 `top` 的 VIRT 列。在 Windows 上，它是 `pagefile` 字段的别名，匹配 taskmgr.exe 的“Mem Usage”“VM Size”列。

- `shared`（Linux）  
    可能与其他进程共享的内存。这匹配 `top` 的 SHR 列。

- `text`（Linux、BSD）  
    又名 TRS（text resident set），专门用于可执行代码的内存量。这匹配 `top` 的 CODE 列。

- `data`（Linux、BSD）  
    又名 DRS（data resident set），专门用于可执行代码之外的物理内存量。它匹配 `top` 的 DATA 列。

- `lib`（Linux）  
    共享库使用的内存。

- `dirty`（Linux）  
    脏页数量。

- `pfaults`（macOS）  
    页面错误数量。

- `pageins`（macOS）  
    实际 pagein 数量。

有关 Windows 字段的解释，请依赖 [PROCESS_MEMORY_COUNTERS_EX](https://docs.microsoft.com/en-us/windows/desktop/api/psapi/ns-psapi-_process_memory_counters_ex) 结构文档。Linux 示例：

```pycon
>>> import psutil
>>> p = psutil.Process()
>>> p.memory_info()
pmem(rss=15491072, vms=84025344, shared=5206016, text=2555904, lib=0, data=9891840, dirty=0)
```

> **版本 4.0.0 变更：** 返回多个字段，而不仅是 `rss` 和 `vms`。

#### memory_full_info()

此方法返回与 `memory_info()` 相同的信息，此外，在某些平台（Linux、macOS、Windows）上还提供额外指标（USS、PSS 和 swap）。  
这些额外指标能更好地表示“有效”进程内存消耗（对于 USS），详见这篇[博客文章](https://gmpy.dev/blog/2016/real-process-memory-and-environ-in-python)。  
它通过遍历整个进程地址空间来实现。因此，它通常比 `memory_info()` 需要更高的用户权限，并且明显更慢。  
在未实现额外字段的平台上，它只返回与 `memory_info()` 相同的指标。

- `uss`（Linux、macOS、Windows）  
    又名“Unique Set Size”，这是进程独有的内存；如果进程现在终止，这部分内存会被释放。

- `pss`（Linux）  
    又名“Proportional Set Size”，是与其他进程共享的内存量，按共享它的进程数量平均分配。例如，如果一个进程有 10 MB 独享内存，并与另一个进程共享 10 MB，则其 PSS 为 15 MB。

- `swap`（Linux）  
    已换出到磁盘的内存量。

> **注意**
>
> `uss` 可能是确定进程实际使用多少内存的最具代表性的指标。它表示如果进程现在终止，会释放多少内存。

Linux 示例：

```pycon
>>> import psutil
>>> p = psutil.Process()
>>> p.memory_full_info()
pfullmem(rss=10199040, vms=52133888, shared=3887104, text=2867200, lib=0, data=5967872, dirty=0, uss=6545408, pss=6872064, swap=0)
>>>
```

另请参阅 [procsmem.py](https://github.com/giampaolo/psutil/blob/master/scripts/procsmem.py) 示例应用。

#### children()

```py
children(recursive=False)
```

返回此进程的子进程，作为 `Process` 实例列表。  
如果 recursive 为 `True`，则返回所有父级后代。  
伪代码示例，假设 *A == 此进程*：

```text
A ─┐
   │
   ├─ B (child) ─┐
   │             └─ X (grandchild) ─┐
   │                                └─ Y (great grandchild)
   ├─ C (child)
   └─ D (child)

>>> p.children()
B, C, D
>>> p.children(recursive=True)
B, X, Y, C, D
```

注意，在上面的示例中，如果进程 X 消失，进程 Y 也不会被返回，因为对进程 A 的引用丢失了。  
这个概念很好地总结在这个[单元测试](https://github.com/giampaolo/psutil/blob/65a52341b55faaab41f68ebc4ed31f18f0929754/psutil/tests/test_process.py#L1064-L1075)中。  
另请参阅如何“终止进程树”和“终止我的子进程”。

#### open_files()

返回进程打开的常规文件，作为命名元组列表，包括以下字段：

- `path`  
    绝对文件名。

- `fd`  
    文件描述符编号；在 Windows 上始终为 `-1`。

仅 Linux：

- `position`（Linux）  
    文件（偏移）位置。

- `mode`（Linux）  
    一个字符串，表示文件是如何打开的，类似于 `open` 内建函数的 `mode` 参数。可能的值是 `'r'`、`'w'`、`'a'`、`'r+'` 和 `'a+'`。二进制或文本模式（`"b"` 或 `"t"`）打开的文件之间没有区别。

- `flags`（Linux）  
    打开文件时传递给底层 `os.open` C 调用的标志（例如 `os.O_RDONLY`、`os.O_TRUNC` 等）。

```pycon
>>> import psutil
>>> f = open('file.ext', 'w')
>>> p = psutil.Process()
>>> p.open_files()
[popenfile(path='/home/giampaolo/svn/psutil/file.ext', fd=3, position=0, mode='w', flags=32769)]
```

> **警告**
>
> 在 Windows 上，由于底层 Windows API 的某些限制，此方法不可靠；检索某些文件句柄时可能会挂起。为了绕过这个问题，psutil 会生成一个线程来确定文件句柄名称，如果 100ms 后没有响应就杀掉它。这意味着在 Windows 上此方法不保证枚举所有常规文件句柄（参见 issue [597](https://github.com/giampaolo/psutil/pull/597)）。像 ProcessHacker 这样的工具也有同样的限制。

> **警告**
>
> 在 BSD 上，由于内核 bug，此方法可能返回路径为 null（`""`）的文件，因此不可靠（参见 issue [595](https://github.com/giampaolo/psutil/pull/595)）。

> **版本 3.1.0 变更：** 在 Windows 上不再挂起。

> **版本 4.1.0 变更：** 在 Linux 上新增 `position`、`mode` 和 `flags` 字段。

#### net_connections()

```py
net_connections(kind='inet')
```

返回进程打开的套接字连接，作为命名元组列表。  
要获取系统范围连接，请使用 `psutil.net_connections()`。  
每个命名元组提供 6 个属性：

- `fd`  
    套接字文件描述符。如果连接指的是当前进程，可以将其传给 `socket.fromfd` 以获得可用的套接字对象。在 Windows、FreeBSD 和 SunOS 上，这始终设置为 `-1`。

- `family`  
    地址族，可能是 `AF_INET`、`AF_INET6` 或 `AF_UNIX`。

- `type`  
    地址类型，可能是 `SOCK_STREAM`、`SOCK_DGRAM` 或 `SOCK_SEQPACKET`。

- `laddr`  
    本地地址，作为 `(ip, port)` 命名元组；对于 AF_UNIX 套接字则是 `path`。对于 UNIX 套接字，请参阅下面的注释。

- `raddr`  
    远程地址，作为 `(ip, port)` 命名元组；对于 UNIX 套接字则是绝对 `path`。当远程端点未连接时，你会得到空元组（AF_INET*）或 `""`（AF_UNIX）。对于 UNIX 套接字，请参阅下面的注释。

- `status`  
    表示 TCP 连接的状态。返回值是 `psutil.CONN_*` 常量之一。对于 UDP 和 UNIX 套接字，这始终是 `psutil.CONN_NONE`。

`kind` 参数是一个字符串，用于过滤符合以下条件的连接：

Kind value, Connections using

- `"inet"`  
    IPv4 和 IPv6

- `"inet4"`  
    IPv4

- `"inet6"`  
    IPv6

- `"tcp"`  
    TCP

- `"tcp4"`  
    TCP over IPv4

- `"tcp6"`  
    TCP over IPv6

- `"udp"`  
    UDP

- `"udp4"`  
    UDP over IPv4

- `"udp6"`  
    UDP over IPv6

- `"unix"`  
    UNIX 套接字（UDP 和 TCP 协议）

- `"all"`  
    所有可能的族和协议的总和

示例：

```pycon
>>> import psutil
>>> p = psutil.Process(1694)
>>> p.name()
'firefox'
>>> p.net_connections()

 pconn(fd=117, family=<AddressFamily.AF_INET: 2>, type=<SocketType.SOCK_STREAM: 1>, laddr=addr(ip='10.0.0.1', port=43761), raddr=addr(ip='72.14.234.100', port=80), status='CLOSING'),
```

>
> 在 Linux 上，检索某些进程的连接需要 root 权限。如果 psutil 未以 root 运行，这些连接会被静默跳过，而不是抛出 `psutil.AccessDenied`。这意味着返回的列表可能不完整。

> **注意**

> **注意**
>
> （OpenBSD）UNIX 套接字的 `laddr` 和 `raddr` 字段始终设置为 `""`。这是操作系统的限制。

> **注意**
>
> （AIX）除非以 root 运行，否则始终抛出 `psutil.AccessDenied`（lsof 也是如此）。

#### connections()

与 `net_connections()` 相同（已弃用）。

> **警告**
>
> 在版本 6.0.0 中已弃用；请改用 `net_connections()`。

#### is_running()

返回当前进程是否在当前进程列表中运行。  
即使进程已消失且其 PID 被另一个进程复用，这也是可靠的，因此必须优先于执行 `psutil.pid_exists(p.pid)`。  
如果 PID 已被复用，此方法还会从 `process_iter()` 内部缓存中移除该进程。

> **注意**
>
> 如果进程是僵尸进程（`p.status() == psutil.STATUS_ZOMBIE`），这也会返回 `True`。

> **版本 6.0.0 变更：** 如果 PID 已被另一个进程复用，自动从 `process_iter()` 内部缓存中移除进程。

#### send_signal()

```py
send_signal(signal)
```

向进程发送信号（参见 `signal` 模块常量），并预先检查 PID 是否已被复用。  
在 UNIX 上，这与 `os.kill(pid, sig)` 相同。  
在 Windows 上，仅支持 `SIGTERM`、`CTRL_C_EVENT` 和 `CTRL_BREAK_EVENT` 信号，并且 `SIGTERM` 被视为 `kill()` 的别名。  
另请参阅如何“终止进程树”和“终止我的子进程”。

> **版本 3.2.0 变更：** 添加对 Windows 上 CTRL_C_EVENT 和 CTRL_BREAK_EVENT 信号的支持。

#### suspend()

使用 `SIGSTOP` 信号暂停进程执行，并预先检查 PID 是否已被复用。  
在 UNIX 上，这与 `os.kill(pid, signal.SIGSTOP)` 相同。  
在 Windows 上，这是通过暂停所有进程线程执行来实现的。

#### resume()

使用 `SIGCONT` 信号恢复进程执行，并预先检查 PID 是否已被复用。  
在 UNIX 上，这与 `os.kill(pid, signal.SIGCONT)` 相同。  
在 Windows 上，这是通过恢复所有进程线程执行来实现的。

#### terminate()

使用 `SIGTERM` 信号终止进程，并预先检查 PID 是否已被复用。  
在 UNIX 上，这与 `os.kill(pid, signal.SIGTERM)` 相同。  
在 Windows 上，这是 `kill()` 的别名。  
另请参阅如何“终止进程树”和“终止我的子进程”。

#### kill()

使用 `SIGKILL` 信号杀死当前进程，并预先检查 PID 是否已被复用。  
在 UNIX 上，这与 `os.kill(pid, signal.SIGKILL)` 相同。  
在 Windows 上，这是通过 [TerminateProcess](https://docs.microsoft.com/en-us/windows/desktop/api/processthreadsapi/nf-processthreadsapi-terminateprocess) 完成的。  
另请参阅如何“终止进程树”和“终止我的子进程”。

#### wait()

```py
wait(timeout=None)
```

等待进程 PID 终止。返回值的详细信息在 UNIX 和 Windows 上有所不同。

*在 UNIX 上*：如果进程正常终止，返回值是一个 >= 0 的正整数，表示退出码。  
如果进程被信号终止，则返回导致终止的信号的负值（例如 `-SIGTERM`）。  
如果 PID 不是 `os.getpid`（当前进程）的子进程，则只等待进程消失并返回 `None`。  
如果 PID 不存在，则立即返回 `None`。

*在 Windows 上*：始终返回退出码，它是由 [GetExitCodeProcess](https://docs.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getexitcodeprocess) 返回的正整数。

`timeout` 以秒为单位。如果指定且进程仍然存活，则抛出 `TimeoutExpired` 异常。  
`timeout=0` 可用于非阻塞应用：它要么立即返回，要么抛出 `TimeoutExpired`。

返回值会被缓存。  
要等待多个进程，请使用 `psutil.wait_procs()`。

```pycon
>>> import psutil
>>> p = psutil.Process(9891)
>>> p.terminate()
>>> p.wait()
<Negsignal.SIGTERM: -15>
```

> **注意**
>
> 当 `timeout` 不为 `None` 且平台支持时，会使用高效的事件驱动机制等待进程终止：
>
> - Linux >= 5.3 且 Python >= 3.9 使用 `os.pidfd_open` + `select.poll`
> - macOS 和其他 BSD 变体使用 `select.kqueue` + `KQ_FILTER_PROC` + `KQ_NOTE_EXIT`
> - Windows 使用 `WaitForSingleObject`
>
> 如果这些机制都不可用，函数会退回到忙循环（非阻塞调用和短暂休眠）。

> **版本 3.15 变更：** 如果 `timeout` 不为 `None`，在 Linux >= 5.3 和 macOS / BSD 上使用高效的事件驱动实现。

> **版本 5.7.1 变更：** 返回值会被缓存（而不是返回 `None`）。

> **版本 5.7.1 变更：** 在 POSIX 上，如果信号为负，则将其作为人类可读的枚举返回。

> **版本 7.2.2 变更：** 在 Linux >= 5.3 + Python >= 3.9 和 macOS/BSD 上，分别使用 `os.pidfd_open` 和 `select.kqueue`，而不是效率较低的忙循环轮询。

### psutil.Popen()

```py
psutil.Popen(*args, **kwargs)
```

与 `subprocess.Popen` 相同，但此外还在单个类中提供所有 `psutil.Process` 方法。  
对于以下两个类共有的方法，psutil 实现优先：`send_signal()`、`terminate()`、`kill()`。  
这样做是为了避免在其 PID 被复用时杀死另一个进程，修复 [BPO-6973](https://bugs.python.org/issue6973)。

```pycon
>>> import psutil
>>> from subprocess import PIPE
>>>
>>> p = psutil.Popen(["/usr/bin/python", "-c", "print('hello')"], stdout=PIPE)
>>> p.name()
'python'
>>> p.username()
'giampaolo'
>>> p.communicate()
('hello\n', None)
>>> p.wait(timeout=2)
0
>>>
```
