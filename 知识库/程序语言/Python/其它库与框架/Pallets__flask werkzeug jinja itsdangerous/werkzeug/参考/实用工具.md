# 实用工具

Werkzeug 附带的各种实用函数。

## 通用辅助函数

### `class werkzeug.utils.cached_property()`

```py
class werkzeug.utils.cached_property(fget, name=None, doc=None)
```

一个仅求值一次的 `property()`。后续访问返回缓存值。设置该属性会设置缓存值。删除该属性会清除缓存值，再次访问时会重新求值。

```py
class Example:
    @cached_property
    def value(self):
        # 在此计算重要内容
        return 42

e = Example()
e.value  # 求值
e.value  # 使用缓存
e.value = 16  # 设置缓存
del e.value  # 清除缓存
```

如果类定义了 `__slots__`，则必须将 `_cache_{name}` 添加为槽位。也可以添加 `__dict__`，但通常不推荐这样做。

> **变更日志**
>
> - 变更于 2.1：支持 `__slots__`。
> - 变更于 2.0：`del obj.name` 会清除缓存值。

- `fget` (`t.Callable[[t.Any], _T]`)
- `name` (`str | None`)
- `doc` (`str | None`)

### `class werkzeug.utils.environ_property()`

```py
class werkzeug.utils.environ_property(name, default=None, load_func=None, dump_func=None, read_only=None, doc=None)
```

将请求属性映射到环境变量。这不仅适用于 Werkzeug 请求对象，也适用于任何具有 `environ` 属性的其他类：

```pycon
>>> class Test(object):
...     environ = {'key': 'value'}
...     test = environ_property('key')
>>> var = Test()
>>> var.test
'value'
```

如果传入第二个值，则当键不存在时将其用作默认值；第三个值可以是一个转换器，接收一个值并转换它。如果转换器引发 `ValueError` 或 `TypeError`，则使用默认值。如果未提供默认值，则使用 `None`。

默认情况下该属性为只读。必须通过向构造函数传入 `read_only=False` 显式启用写入。

- `name` (`str`)
- `default` (`_TAccessorValue | None`)
- `load_func` (`t.Callable[[str], _TAccessorValue] | None`)
- `dump_func` (`t.Callable[[_TAccessorValue], str] | None`)
- `read_only` (`bool | None`)
- `doc` (`str | None`)

### `werkzeug.utils.redirect()`

```py
werkzeug.utils.redirect(location, code=302, Response=None)
```

返回一个响应对象（WSGI 应用），调用时会将客户端重定向到目标位置。支持的代码为 301、302、303、305、307 和 308。不支持 300，因为它不是真正的重定向；也不支持 304，因为它是带有已定义 `If-Modified-Since` 请求头的请求的响应。

> **变更日志**
>
> - 添加于 0.10：现在可以传入用于 Response 对象的类。
> - 添加于 0.6：位置现在可以是用 `iri_to_uri()` 函数编码的 Unicode 字符串。

- `location` (`str`)  
    响应应重定向到的位置。

- `code` (`int`)  
    重定向状态码。默认为 302。

- `Response` (`class`)  
    实例化响应时使用的 Response 类。如果未指定，默认为 `werkzeug.wrappers.Response`。

**返回类型：** `Response`

### `werkzeug.utils.append_slash_redirect()`

```py
werkzeug.utils.append_slash_redirect(environ, code=308)
```

重定向到当前 URL 并追加一个斜杠。

如果当前 URL 是 `/user/42`，重定向 URL 将是 `42/`。在响应处理期间或由浏览器将其与当前 URL 连接时，将产生 `/user/42/`。

如果路径已经以斜杠结尾，则行为未定义。如果无条件地对某个 URL 调用它，可能会产生重定向循环。

- `environ` (`WSGIEnvironment`)  
    使用此 WSGI 环境中的路径和查询来生成重定向 URL。

- `code` (`int`)  
    重定向的状态码。

**返回类型：** `Response`

> **变更日志**
>
> - 变更于 2.1：生成仅修改最后一段的相对 URL。当前路径包含多个段时相关。
> - 变更于 2.1：默认状态码为 308 而不是 301。这会保留请求方法和请求体。

### `werkzeug.utils.send_file()`

```py
werkzeug.utils.send_file(
    path_or_file,
    environ,
    mimetype=None,
    as_attachment=False,
    download_name=None,
    conditional=True,
    etag=True,
    last_modified=None,
    max_age=None,
    use_x_sendfile=False,
    response_class=None,
    _root_path=None,
)
```

将文件内容发送给客户端。

第一个参数可以是文件路径或文件类对象。大多数情况下首选路径，因为 Werkzeug 可以管理文件并从路径获取额外信息。传入文件类对象要求文件以二进制模式打开，并且主要在使用 `io.BytesIO` 在内存中构建文件时有用。

切勿传入用户提供的文件路径。该路径被假定为可信的，因此用户可能构造路径来访问你无意访问的文件。请使用 `send_from_directory()` 安全地提供用户提供的路径。

如果 WSGI 服务器在 `environ` 中设置了 `file_wrapper`，则使用它；否则使用 Werkzeug 内置的包装器。或者，如果 HTTP 服务器支持 `X-Sendfile`，`use_x_sendfile=True` 会告诉服务器发送给定路径，这比在 Python 中读取要高效得多。

- `path_or_file` (`os.PathLike[str] | str | t.IO[bytes]`)  
    要发送的文件的路径；如果给出相对路径，则相对于当前工作目录。也可以是以二进制模式打开的文件类对象。确保文件指针已定位到数据开头。

- `environ` (`WSGIEnvironment`)  
    当前请求的 WSGI 环境。

- `mimetype` (`str | None`)  
    要为文件发送的 MIME 类型。如果未提供，将尝试从文件名检测。

- `as_attachment` (`bool`)  
    向浏览器指示应提供保存文件而不是显示文件。

- `download_name` (`str | None`)  
    浏览器保存文件时使用的默认名称。默认为传入的文件名。

- `conditional` (`bool`)  
    根据请求头启用条件响应和范围响应。要求传入文件路径和 `environ`。

- `etag` (`bool | str`)  
    为文件计算 ETag，这要求传入文件路径。也可以是一个字符串以代替计算值。

- `last_modified` (`datetime | int | float | None`)  
    要为文件发送的最后修改时间（秒）。如果未提供，将尝试从文件路径检测。

- `max_age` (`None | (int | t.Callable[[str | None], int | None])`)  
    客户端应缓存文件的时长（秒）。如果设置，`Cache-Control` 将为 `public`，否则为 `no-cache` 以优先使用条件缓存。

- `use_x_sendfile` (`bool`)  
    设置 `X-Sendfile` 请求头，让服务器高效发送文件。需要 HTTP 服务器支持。要求传入文件路径。

- `response_class` (`type[Response] | None`)  
    使用此构建响应。默认为 `Response`。

- `_root_path` (`os.PathLike[str] | str | None`)  
    不要使用。仅供内部使用。请使用 `send_from_directory()` 安全地发送某路径下的文件。

**返回类型：** `Response`

> **变更日志**
>
> - 变更于 2.0.2：仅当禁用 `as_attachment` 时，`send_file` 才设置检测到的 `Content-Encoding`。
> - 添加于 2.0：改编自 Flask 的实现。
> - 变更于 2.0：`download_name` 取代 Flask 的 `attachment_filename` 参数。如果 `as_attachment=False`，则改为以 `Content-Disposition: inline` 传递。
> - 变更于 2.0：`max_age` 取代 Flask 的 `cache_timeout` 参数。默认启用 `conditional`，且默认不设置 `max_age`。
> - 变更于 2.0：`etag` 取代 Flask 的 `add_etags` 参数。可以是一个字符串以代替生成值。
> - 变更于 2.0：如果从 `download_name` 猜测 `mimetype` 时返回编码，则设置 `Content-Encoding` 请求头。

### `werkzeug.utils.send_from_directory()`

```py
werkzeug.utils.send_from_directory(directory, path, environ, **kwargs)
```

使用 `send_file()` 从目录内发送文件。

这是从文件夹（例如静态文件或上传文件）提供文件的安全方式。使用 `safe_join()` 确保来自客户端的路径不会被恶意构造为指向指定目录之外。

如果最终路径不指向现有的常规文件，则返回 404 `NotFound` 错误。

- `directory` (`os.PathLike[str] | str`)  
    `path` 必须位于其下的目录。此值*绝不能*由客户端提供，否则会变得不安全。

- `path` (`os.PathLike[str] | str`)  
    要发送的文件路径，相对于 `directory`。这是由客户端提供的路径部分，会进行安全检查。

- `environ` (`WSGIEnvironment`)  
    当前请求的 WSGI 环境。

- `kwargs` (`t.Any`)  
    传递给 `send_file()` 的参数。

**返回类型：** `Response`

> **变更日志**
>
> - 添加于 2.0：改编自 Flask 的实现。

### `werkzeug.utils.import_string()`

```py
werkzeug.utils.import_string(import_name, silent=False)
```

基于字符串导入对象。如果要将导入路径用作端点或类似用途，这会很有用。导入路径可以用点号表示法（`xml.sax.saxutils.escape`）指定，也可以用冒号作为对象分隔符（`xml.sax.saxutils:escape`）。

如果 `silent` 为 `True`，则导入失败时返回值为 `None`。

- `import_name` (`str`)  
    要导入对象的点号名称。

- `silent` (`bool`)  
    如果设置为 `True`，则忽略导入错误并改为返回 `None`。

**返回：** 导入的对象

**返回类型：** `Any`

### `werkzeug.utils.find_modules()`

```py
werkzeug.utils.find_modules(import_path, include_packages=False, recursive=False)
```

查找包下面的所有模块。这对于自动导入所有视图/控制器很有用，以便它们的元类/函数装饰器有机会在应用上注册自身。

除非 `include_packages` 为 `True`，否则不返回包。也可以递归列出模块，但在这种情况下会导入所有包以获取该模块的正确加载路径。

- `import_path` (`str`)  
    要查找子模块的包的点号名称。

- `include_packages` (`bool`)  
    如果也应返回包，则设置为 `True`。

- `recursive` (`bool`)  
    如果应递归，则设置为 `True`。

**返回：** 生成器

**返回类型：** `Iterator[str]`

### `werkzeug.utils.secure_filename()`

```py
werkzeug.utils.secure_filename(filename)
```

验证并修改文件名，使其在常规文件系统和 `os.path.join()` 中安全可用。如果文件名中没有任何内容可以安全保留，则可能产生空字符串。

仅允许 ASCII 字母、数字和 `._-` 字符，其他所有字符都会被移除或替换。Unicode 字符会根据 NFKD 分解并替换为 ASCII 等价物。`/`（在 Windows 上还有 `\`）和空白会被替换为 `_`。周围的 `._` 字符会被移除。

在 Windows 上，诸如 `CON` 和 `NUL` 之类的特殊设备名会加上 `_` 前缀以避免访问。

这只考虑文件名，不验证文件是否存在、是否为符号链接或文件的其他属性。

- `filename` (`str`)  
    要验证和修改的文件名。

**返回类型：** `str`

> **变更日志**
>
> - 添加于 0.5。

## 安全辅助函数

### `werkzeug.security.generate_password_hash()`

```py
werkzeug.security.generate_password_hash(password, method='scrypt', salt_length=16)
```

安全地哈希密码以进行存储。可以使用 `check_password_hash()` 将密码与存储的哈希进行比较。

支持以下方法：

- `scrypt`，默认方法。参数为 `n`、`r` 和 `p`，默认值为 `scrypt:32768:8:1`。参见 `hashlib.scrypt()`。
- `pbkdf2`，安全性较低。参数为 `hash_method` 和 `iterations`，默认值为 `pbkdf2:sha256:600000`。参见 `hashlib.pbkdf2_hmac()`。

默认参数可能会更新以反映当前指南，并且如果某些方法不再被认为安全，可能会被弃用和移除。要迁移旧哈希，可以在检查旧哈希时生成新哈希，或联系用户并提供重置密码的链接。

- `password` (`str`)  
    明文密码。

- `method` (`str`)  
    密钥派生函数及其参数。

- `salt_length` (`int`)  
    为盐生成的字符数。

**返回类型：** `str`

> **变更日志**
>
> - 变更于 3.1：pbkdf2 的默认迭代次数增加到 1,000,000。
> - 变更于 2.3：添加了对 Scrypt 的支持。
> - 变更于 2.3：pbkdf2 的默认迭代次数增加到 600,000。
> - 变更于 2.3：所有普通哈希均已弃用，并将在 Werkzeug 3.0 中不再支持。

- `pwhash` (`str`)  
    哈希后的密码。

- `password` (`str`)

**返回类型：** `bool`

> **变更日志**

### `werkzeug.security.safe_join()`

```py
werkzeug.security.safe_join(directory, *untrusted)
```

安全地将零个或多个不可信路径组件连接到可信基础目录，以避免逃逸基础目录。如果路径不安全，则返回 `None`。

不可信路径假定来自 URL 或用于 URL，例如用于提供文件。因此，它应只使用正斜杠 `/` 作为路径分隔符，并将使用该分隔符连接。在 Windows 上，不允许使用反斜杠 `\` 分隔符。

这只考虑路径名，不验证它是否存在、是否为符号链接或文件/文件系统的其他属性。应用应确保 `directory` 的内容可信。

在 Windows 上，不允许诸如 `CON` 和 `NUL` 之类的特殊设备名，因为这用于通过 `send_from_directory()` 提供文件，而这些文件在读取时会挂起。

允许 NTFS 备用数据流（ADS），例如 `filename:stream`。`secure_filename()` 在保存时会移除 `:`。

- `directory` (`str`)  
    可信基础目录。

- `untrusted` (`str`)  
    相对于基础目录的不可信路径组件。

**返回：** 安全路径，否则为 `None`。

**返回类型：** `str | None`

> **变更日志**
>
> - 变更于 3.1.9：在 Windows 上不允许带有空 ADS 流标记的特殊设备名。
> - 变更于 3.1.6：在 Windows 上不允许多段路径中的特殊设备名。
> - 变更于 3.1.5：在 Windows 上不允许更多特殊设备名，无论扩展名或尾随空格如何。
> - 变更于 3.1.4：在 Windows 上不允许特殊设备名。

## 日志

Werkzeug 使用标准 Python `logging`。日志记录器名为 `"werkzeug"`。

```py
import logging
logger = logging.getLogger("werkzeug")
```

如果未设置日志记录器级别，首次使用时会将其设置为 `INFO`。如果该级别没有处理器，则会添加一个 `StreamHandler`。
