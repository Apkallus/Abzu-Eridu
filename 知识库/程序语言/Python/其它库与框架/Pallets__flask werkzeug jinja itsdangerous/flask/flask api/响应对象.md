## 响应对象

### `flask.Response(...)`

```py
class flask.Response(response=None, status=None, headers=None, mimetype=None, content_type=None, direct_passthrough=False)
```

Flask 默认使用的响应对象。其行为类似 Werkzeug 的响应对象，但默认 mimetype 为 HTML。通常不必自己创建此对象，因为 `make_response()` 会处理。

如果要替换使用的响应对象，可以子类化此类，并将 `response_class` 设置为子类。

> **变更日志**
>
> 在 1.0 版本中更改：响应新增 JSON 支持，类似请求。这在测试时获取测试客户端响应数据为 JSON 很有用。
>
> 在 1.0 版本中更改：新增 `max_cookie_size`。

参数：

- `response`（`Iterable[str] | Iterable[bytes]`）
- `status`（`int | str | HTTPStatus | None`）
- `headers`（`Headers`）
- `mimetype`（`str | None`）
- `content_type`（`str | None`）
- `direct_passthrough`（`bool`）

#### `default_mimetype`

```py
default_mimetype: str | None = 'text/html'
```

如果未提供 mimetype，则使用的默认 mimetype。

#### `accept_ranges`

```py
accept_ranges
```

`Accept-Ranges` 标头。尽管名称暗示支持多个值，但它必须只是一个字符串标记。常见值为 `'bytes'` 和 `'none'`。

> **变更日志**
>
> 在 0.7 版本中新增。

#### `access_control_allow_credentials`

```py
access_control_allow_credentials: bool
```

浏览器是否可以将凭据共享给 JavaScript 代码。作为预检请求的一部分，它指示跨源请求是否可以使用凭据。

#### `access_control_allow_headers`

```py
access_control_allow_headers
```

跨源请求可以发送哪些标头。

#### `access_control_allow_methods`

```py
access_control_allow_methods
```

跨源请求可以使用哪些方法。

#### `access_control_allow_origin`

```py
access_control_allow_origin
```

可以发起跨源请求的源，或 `'*'` 表示任何源。

#### `access_control_expose_headers`

```py
access_control_expose_headers
```

浏览器可以将哪些标头共享给 JavaScript 代码。

#### `access_control_max_age`

```py
access_control_max_age
```

访问控制设置可以缓存的最长时间（秒）。

#### `add_etag()`

```py
add_etag(overwrite=False, weak=False) → None
```

如果当前响应还没有 ETag，则添加一个。

> **变更日志**
>
> 在 2.0 版本中更改：使用 SHA-1 生成值。某些环境可能没有 MD5。

参数：

- `overwrite`（`bool`）
- `weak`（`bool`）

返回类型：`None`

#### `age`

```py
age
```

Age 响应头字段传达发送方对响应（或其重新验证）在源服务器生成后经过时间的估计。

Age 值是非负十进制整数，表示秒。

#### `allow`

```py
allow: HeaderSet
```

Allow 实体头字段列出 Request-URI 标识的资源支持的方法集合。此字段的目的严格来说是告知接收方与资源关联的有效方法。405（方法不允许）响应中必须存在 Allow 头字段。

#### `automatically_set_content_length`

```py
automatically_set_content_length = True
```

此响应对象是否应在可能时自动设置 content-length 标头？默认是 true。

> **变更日志**
>
> 在 0.8 版本中新增。

#### `cache_control`

```py
cache_control: ResponseCacheControl
```

Cache-Control 通用头字段用于指定请求/响应链上的所有缓存机制必须遵守的指令。

#### `calculate_content_length()`

```py
calculate_content_length() → int | None
```

如果可用则返回内容长度，否则返回 `None`。

返回类型：`int | None`

#### `call_on_close()`

```py
call_on_close(func) → Callable[[], Any]
```

将函数添加到内部函数列表，在关闭响应时调用。自 0.7 起，此函数还返回传入的函数，因此可用作装饰器。

> **变更日志**
>
> 在 0.6 版本中新增。

参数：

- `func`（`Callable[[], Any]`）

返回类型：`Callable[[], Any]`

#### `close()`

```py
close() → None
```

如果可能，关闭封装的响应。也可以在 `with` 语句中使用对象，它会自动关闭。

> **变更日志**
>
> 在 0.9 版本中新增：现在可在 `with` 语句中使用。

返回类型：`None`

#### `content_encoding`

```py
content_encoding
```

Content-Encoding 实体头字段用作媒体类型的修饰符。存在时，其值指示已对实体正文应用了哪些附加内容编码，以及必须应用哪些解码机制才能获得 Content-Type 头字段引用的媒体类型。

#### `content_language`

```py
content_language: HeaderSet
```

Content-Language 实体头字段描述所附实体预期受众的自然语言。注意这可能不等同于实体正文中使用的所有语言。

#### `content_length`

```py
content_length
```

Content-Length 实体头字段指示发送给接收方的实体正文大小，以十进制八位字节数表示；对于 HEAD 方法，则表示如果请求是 GET 时会发送的实体正文大小。

#### `content_location`

```py
content_location
```

当实体可从与请求资源 URI 不同的位置访问时，Content-Location 实体头字段可用于提供消息中所附实体的资源位置。

#### `content_md5`

```py
content_md5
```

按 RFC 1864 定义，Content-MD5 实体头字段是实体正文的 MD5 摘要，用于提供实体正文的端到端消息完整性检查（MIC）。（注意：MIC 适合检测传输中实体正文的意外修改，但不能证明可抵御恶意攻击。）

#### `content_range`

```py
content_range: ContentRange
```

`Content-Range` 标头作为 [`ContentRange`](https://werkzeug.palletsprojects.com/en/stable/datastructures/#werkzeug.datastructures.ContentRange) 对象。即使未设置该标头也可用。

> **变更日志**
>
> 在 0.7 版本中新增。

#### `content_security_policy`

```py
content_security_policy: ContentSecurityPolicy
```

`Content-Security-Policy` 标头作为 `ContentSecurityPolicy` 对象。即使未设置该标头也可用。

Content-Security-Policy 标头增加额外安全层，帮助检测和缓解某些类型的攻击。

#### `content_security_policy_report_only`

```py
content_security_policy_report_only: ContentSecurityPolicy
```

`Content-Security-policy-report-only` 标头作为 `ContentSecurityPolicy` 对象。即使未设置该标头也可用。

Content-Security-Policy-Report-Only 标头添加不强制执行但会报告的 CSP 策略，从而帮助检测某些类型的攻击。

#### `content_type`

```py
content_type
```

Content-Type 实体头字段指示发送给接收方的实体正文的媒体类型；对于 HEAD 方法，则表示如果请求是 GET 时会发送的媒体类型。

#### `cross_origin_embedder_policy`

```py
cross_origin_embedder_policy
```

阻止文档加载任何未显式授予文档权限的跨源资源。值必须是 `werkzeug.http.COEP` 枚举的成员。

#### `cross_origin_opener_policy`

```py
cross_origin_opener_policy
```

允许控制与跨源文档共享浏览上下文组。值必须是 `werkzeug.http.COOP` 枚举的成员。

#### `data`

```py
data: bytes | str
```

调用 `get_data()` 和 `set_data()` 的描述符。

#### `date`

```py
date
```

Date 通用头字段表示消息产生的日期和时间，其语义与 RFC 822 中的 orig-date 相同。

> **变更日志**
>
> 在 2.0 版本中更改：`datetime` 对象是时区感知的。

#### `default_status`

```py
default_status = 200
```

如果未提供状态，则使用的默认状态。

#### `delete_cookie()`

```py
delete_cookie(key, path='/', domain=None, secure=False, httponly=False, samesite=None, partitioned=False) → None
```

删除 cookie。如果键不存在则静默失败。

参数：

- `key`（`str`）  
    cookie 的键（名称）。
- `path`（`str | None`）  
    如果要删除的 cookie 限制在某个路径，则必须在此处定义路径。
- `domain`（`str | None`）  
    如果要删除的 cookie 限制在某个域，则必须在此处定义该域。
- `secure`（`bool`）  
    如果为 `True`，cookie 只能通过 HTTPS 使用。
- `httponly`（`bool`）  
    禁止 JavaScript 访问 cookie。
- `samesite`（`str | None`）  
    将 cookie 的作用范围限制为仅附加到“同站”请求。
- `partitioned`（`bool`）  
    如果为 `True`，cookie 将被分区。

返回类型：`None`

#### `expires`

```py
expires
```

Expires 实体头字段给出响应被视为过期的日期/时间。过期的缓存条目通常不应由缓存返回。

> **变更日志**
>
> 在 2.0 版本中更改：`datetime` 对象是时区感知的。

#### `force_type()`

```py
classmethod force_type(response, environ=None) → Response
```

强制 WSGI 响应是当前类型的响应对象。Werkzeug 在许多情况下（如异常）会在内部使用 `Response`。如果你在异常上调用 `get_response()`，即使使用自定义子类，也会返回常规 `Response` 对象。

此方法可以强制给定响应类型，并且如果提供 environ，还会将任意 WSGI 可调用对象转换为响应对象：

```py
# 将 Werkzeug 响应对象转换为 MyResponseClass 子类的实例。
response = MyResponseClass.force_type(response)

# 将任意 WSGI 应用转换为响应对象
response = MyResponseClass.force_type(response, environ)
```

这在主调度器中后处理响应并使用子类功能时特别有用。

请记住，如果可能，这会就地修改响应对象！

参数：

- `response`（`Response`）  
    响应对象或 WSGI 应用。
- `environ`（`WSGIEnvironment | None`）  
    WSGI 环境对象。

返回：响应对象。

返回类型：`Response`

#### `freeze()`

```py
freeze() → None
```

使响应对象准备好被 pickle。执行以下操作：

- 将响应缓冲到列表，忽略 `implicity_sequence_conversion` 和 `direct_passthrough`。
- 设置 `Content-Length` 标头。
- 如果尚未设置 `ETag` 标头，则生成一个。

> **变更日志**
>
> 在 2.1 版本中更改：移除 `no_etag` 参数。
>
> 在 2.0 版本中更改：始终添加 `ETag` 标头。
>
> 在 0.6 版本中更改：设置 `Content-Length` 标头。

返回类型：`None`

#### `from_app()`

```py
classmethod from_app(app, environ, buffered=False) → Response
```

从应用程序输出创建新响应对象。如果传入始终返回生成器的应用程序，效果最好。有时应用程序可能使用 `start_response` 函数返回的 `write()` 可调用对象。此方法会尝试自动解决此类边缘情况。但如果没有得到预期输出，应将 `buffered` 设置为 `True` 以强制缓冲。

参数：

- `app`（`WSGIApplication`）  
    要执行的 WSGI 应用。
- `environ`（`WSGIEnvironment`）  
    要针对其执行的 WSGI 环境。
- `buffered`（`bool`）  
    设置为 `True` 以强制缓冲。

返回：响应对象。

返回类型：`Response`

#### `get_app_iter()`

```py
get_app_iter(environ) → Iterable[bytes]
```

返回给定 environ 的应用程序迭代器。根据请求方法和当前状态码，返回值可能是空响应而不是响应中的响应。

如果请求方法是 `HEAD` 或状态码处于 HTTP 规范要求空响应的范围内，则返回空可迭代对象。

> **变更日志**
>
> 在 0.6 版本中新增。

参数：

- `environ`（`WSGIEnvironment`）  
    请求的 WSGI 环境。

返回：响应可迭代对象。

返回类型：`Iterable[bytes]`

#### `get_data()`

```py
get_data(as_text=False) → bytes | str
```

响应正文的字符串表示。每当调用此属性时，响应可迭代对象会被编码并展平。如果流式传输大数据，可能导致不希望的行为。

可以通过将 `implicit_sequence_conversion` 设置为 `False` 来禁用此行为。

如果 `as_text` 设置为 `True`，返回值将是解码后的字符串。

> **变更日志**
>
> 在 0.9 版本中新增。

参数：

- `as_text`（`bool`）

返回类型：`bytes | str`

#### `get_etag()`

```py
get_etag() → tuple[str, bool] | tuple[None, None]
```

返回形式为 `(etag, is_weak)` 的元组。如果没有 ETag，返回值为 `(None, None)`。

返回类型：`tuple[str, bool] | tuple[None, None]`

#### `get_json()`

```py
get_json(force=False, silent=False) → Any | None
```

将 `data` 解析为 JSON。在测试期间有用。

如果 mimetype 不表示 JSON（`application/json`，参见 `is_json`），则返回 `None`。

与 `Request.get_json()` 不同，结果不会缓存。

参数：

- `force`（`bool`）  
    忽略 mimetype 并始终尝试解析 JSON。
- `silent`（`bool`）  
    静默解析错误并返回 `None`。

返回类型：`Any | None`

#### `get_wsgi_headers()`

```py
get_wsgi_headers(environ) → Headers
```

在响应开始前自动调用，并返回针对给定环境修改后的标头。它返回响应标头的副本，并在必要时应用一些修改。

例如，位置标头（如果存在）会与环境根 URL 连接。此外，对于某些状态码，内容长度会自动设置为零。

> **变更日志**
>
> 在 0.6 版本中更改：以前该函数称为 `fix_headers` 并就地修改响应对象。同样从 0.6 起，位置和内容位置标头中的 IRI 会被正确处理。
>
> 同样从 0.6 起，Werkzeug 如果能够自行确定内容长度，将尝试设置它。如果响应可迭代对象中的所有字符串都已编码且可迭代对象已缓冲，则属于这种情况。

参数：

- `environ`（`WSGIEnvironment`）  
    请求的 WSGI 环境。

返回：新的 `Headers` 对象。

返回类型：`Headers`

#### `get_wsgi_response()`

```py
get_wsgi_response(environ) → tuple[Iterable[bytes], str, list[tuple[str, str]]]
```

返回最终 WSGI 响应元组。元组第一项是应用迭代器，第二项是状态，第三项是标头列表。返回的响应是针对给定环境专门创建的。例如，如果 WSGI 环境中的请求方法是 `'HEAD'`，响应将为空，只存在标头和状态码。

> **变更日志**
>
> 在 0.6 版本中新增。

参数：

- `environ`（`WSGIEnvironment`）  
    请求的 WSGI 环境。

返回：`(app_iter, status, headers)` 元组。

返回类型：`tuple[Iterable[bytes], str, list[tuple[str, str]]]`

#### `make_conditional()`

```py
make_conditional(request_or_environ, accept_ranges=False, complete_length=None) → Response
```

使响应对请求具有条件性。如果已经为响应定义了 etag，此方法效果最好。可以使用 `add_etag` 方法做到这一点。如果未使用 etag 调用，则只设置日期标头。

如果请求或 environ 中的请求方法不是 GET 或 HEAD，则此方法不执行任何操作。

为了在处理范围请求时获得最佳性能，建议响应数据对象实现 `io.IOBase` 描述的 `seekable`、`seek` 和 `tell` 方法。`wrap_file()` 返回的对象自动实现这些方法。

它不会移除响应正文，因为 `__call__()` 函数会自动为我们完成此操作。

返回 self，因此可以执行 `return resp.make_conditional(req)`，但会就地修改对象。

参数：

- `request_or_environ`（`WSGIEnvironment | Request`）  
    用于使响应具有条件性的请求对象或 WSGI 环境。
- `accept_ranges`（`bool | str`）  
    此参数决定 `Accept-Ranges` 标头的值。如果为 `False`（默认），则不设置标头。如果为 `True`，则设置为 `"bytes"`。如果是字符串，则使用此值。
- `complete_length`（`int | None`）  
    仅在有效的范围请求中使用。它将设置 `Content-Range` 完整长度值并计算 `Content-Length` 实际值。此参数对于成功完成范围请求是必需的。

引发：`RequestedRangeNotSatisfiable` 如果无法解析或满足 `Range` 标头。

返回类型：`Response`

> **变更日志**
>
> 在 2.0 版本中更改：如果长度为 0，则跳过范围处理，而不是引发 416 Range Not Satisfiable 错误。

> **变更日志**
>
> 在 0.6 版本中新增。

返回类型：`None`

#### `set_cookie()`

```py
set_cookie(key, value='', max_age=None, expires=None, path='/', domain=None, secure=False, httponly=False, samesite=None, partitioned=False) → None
```

设置 cookie。

如果 cookie 标头的大小超过 `max_cookie_size`，会发出警告，但仍会设置标头。

参数：

- `key`（`str`）  
    cookie 的键（名称）。
- `value`（`str`）  
    cookie 的值。
- `max_age`（`timedelta | int | None`）  
    应为秒数，如果 cookie 只持续客户端浏览器会话，则为 `None`（默认）。
- `expires`（`str | datetime | int | float | None`）  
    应为 `datetime` 对象或 UNIX 时间戳。
- `path`（`str | None`）  
    将 cookie 限制到给定路径，默认覆盖整个域。
- `domain`（`str | None`）  
    如果要设置跨域 cookie。例如，`domain="example.com"` 将设置一个可由域 `www.example.com`、`foo.example.com` 等读取的 cookie。否则，cookie 只能由设置它的域读取。
- `secure`（`bool`）  
    如果为 `True`，cookie 只能通过 HTTPS 使用。
- `httponly`（`bool`）  
    禁止 JavaScript 访问 cookie。
- `samesite`（`str | None`）  
    将 cookie 的作用范围限制为仅附加到“同站”请求。
- `partitioned`（`bool`）  
    如果为 `True`，cookie 将被分区。

返回类型：`None`

> **变更日志**
>
> 在 3.1 版本中更改：新增 `partitioned` 参数。

#### `www_authenticate`

```py
www_authenticate: WWWAuthenticate
```

`WWW-Authenticate` 标头解析为 [`WWWAuthenticate`](https://werkzeug.palletsprojects.com/en/stable/datastructures/#werkzeug.datastructures.WWWAuthenticate) 对象。修改对象将修改标头值。

默认不设置此标头。要设置此标头，请将 `WWWAuthenticate` 实例赋值给此属性。

```py
response.www_authenticate = WWWAuthenticate(
    "basic", {"realm": "Authentication Required"}
)
```

可以为此标头发送多个值，以向客户端提供多个选项。赋值列表可设置多个标头。但是，修改列表中的项不会自动更新标头值，访问此属性将始终只返回第一个值。

要取消设置此标头，请赋值 `None` 或使用 `del`。

> **变更日志**
>
> 在 2.3 版本中更改：可以赋值此属性来设置标头。可以赋值列表来设置多个标头值。使用 `del` 取消设置标头。
>
> 在 2.3 版本中更改：`WWWAuthenticate` 不再是 `dict`。为使用令牌而不是参数的认证挑战新增了 `token` 属性。

#### `response`

```py
response: Iterable[str] | Iterable[bytes]
```

要作为 WSGI 可迭代对象发送的响应正文。字符串或字节列表表示固定长度响应，任何其他可迭代对象是流式响应。字符串按 UTF-8 编码为字节。

不要设置为普通字符串或字节，否则发送响应会非常低效，因为会一次迭代一个字节。

#### `direct_passthrough`

```py
direct_passthrough
```

将响应正文直接作为 WSGI 可迭代对象传递。当正文是二进制文件或其他字节迭代器时，可用于跳过一些不必要的检查。请使用 [`send_file()`](https://werkzeug.palletsprojects.com/en/stable/utils/#werkzeug.utils.send_file) 而不是手动设置此项。

#### `autocorrect_location_header`

```py
autocorrect_location_header = False
```

如果重定向 `Location` 标头是相对 URL，则将其设为绝对 URL，包括 scheme 和 domain。

> **变更日志**
>
> 在 2.1 版本中更改：默认禁用，因此响应将发送相对重定向。
>
> 在 0.8 版本中新增。
