# flask.Flask()

```py
class flask.Flask(
    import_name,
    static_url_path=None,
    static_folder='static',
    static_host=None,
    host_matching=False,
    subdomain_matching=False,
    template_folder='templates',
    instance_path=None,
    instance_relative_config=False,
    root_path=None,
)
```

Flask 对象实现一个 WSGI 应用，并作为中心对象。它接收应用程序的模块或包名称。创建后，它作为视图函数、URL 规则、模板配置等的中心注册表。

包名用于解析包内资源或模块所在文件夹，具体取决于包参数解析为实际 Python 包（包含 `__init__.py` 的文件夹）还是标准模块（仅 `.py` 文件）。

有关资源加载的更多信息，请参阅 `open_resource()`。

通常在主模块或包的 `__init__.py` 文件中创建 `Flask` 实例，如下所示：

```py
from flask import Flask
app = Flask(__name__)
```

> **关于第一个参数**
>
> 第一个参数用于让 Flask 知道什么属于你的应用。此名称用于在文件系统上查找资源，可被扩展用于改进调试信息等。
>
> 因此提供什么很重要。如果使用单个模块，`__name__` 始终是正确值。如果使用包，通常建议硬编码包名。
>
> 例如应用程序定义在 `yourapplication/app.py`，应使用以下两个版本之一创建：
>
> ```py
> app = Flask('yourapplication')
> app = Flask(__name__.split('.')[0])
> ```
>
> 为什么？即使使用 `__name__`，应用也能工作，得益于资源查找方式。但这会使调试更痛苦。某些扩展会根据应用的导入名称做出假设。例如 Flask-SQLAlchemy 扩展在调试模式下会查找触发 SQL 查询的代码。如果导入名称设置不正确，调试信息会丢失。（例如它只会拾取 `yourapplication.app` 中的 SQL 查询，而不是 `yourapplication.views.frontend`）

**变更记录**

- 1.0 新增：添加 `host_matching` 和 `static_host` 参数。
- 1.0 新增：添加 `subdomain_matching` 参数。现在需要手动启用子域匹配。设置 `SERVER_NAME` 不会隐式启用。
- 0.11 新增：添加 `root_path` 参数。
- 0.8 新增：添加 `instance_path` 和 `instance_relative_config` 参数。
- 0.7 新增：添加 `static_url_path`、`static_folder` 和 `template_folder` 参数。

**参数**

- `import_name` (`str`)  
    应用程序包名称。

- `static_url_path` (`str | None`)  
    可用于指定 Web 上静态文件的不同路径。默认为 `static_folder` 文件夹的名称。

- `static_folder` (`str | os.PathLike[str] | None`)  
    静态文件文件夹，通过 `static_url_path` 提供。相对于应用程序 `root_path` 或绝对路径。默认为 `'static'`。

- `static_host` (`str | None`)  
    添加静态路由时使用的主机。默认为 `None`。当使用 `host_matching=True` 且配置了 `static_folder` 时需要。

- `host_matching` (`bool`)  
    设置 `url_map.host_matching` 属性。默认为 `False`。

- `subdomain_matching` (`bool`)  
    匹配路由时考虑相对于 `SERVER_NAME` 的子域。默认为 `False`。

- `template_folder` (`str | os.PathLike[str] | None`)  
    包含应用程序应使用模板的文件夹。默认为应用程序根路径中的 `'templates'` 文件夹。

- `instance_path` (`str | None`)  
    应用程序的备用实例路径。默认假定包或模块旁边的 `'instance'` 文件夹为实例路径。

- `instance_relative_config` (`bool`)  
    如果设为 `True`，加载配置的相对文件名假定相对于实例路径而不是应用程序根路径。

- `root_path` (`str | None`)  
    应用程序文件根目录路径。仅当无法自动检测时才手动设置，例如命名空间包。

## open_resource()

```py
open_resource(resource, mode='rb', encoding=None)
```

打开相对于 `root_path` 的资源文件进行读取。

例如，如果文件 `schema.sql` 与定义 `Flask` 应用的 `app.py` 位于同一目录，可以使用以下方式打开：

```py
with app.open_resource("schema.sql") as f:
    conn.executescript(f.read())
```

**参数**

- `resource` (`str`)  
    相对于 `root_path` 的资源路径。

- `mode` (`str`)  
    以该模式打开文件。仅支持读取，有效值为 `"r"`（或 `"rt"`）和 `"rb"`。

- `encoding` (`str | None`)  
    以文本模式打开时使用此编码。以二进制模式打开时忽略。

**返回类型**

`IO`

变更记录：3.1 变更：添加 `encoding` 参数。

## run()

```py
run(host=None, port=None, debug=None, load_dotenv=True, **options)
```

在本地开发服务器上运行应用程序。

不要在生产环境中使用 `run()`。它不旨在满足生产服务器的安全和性能要求。相反，请参阅“部署到生产环境”以获取 WSGI 服务器建议。

如果设置了 `debug` 标志，服务器会在代码更改时自动重新加载，并在发生异常时显示调试器。

如果要在调试模式下运行应用程序，但禁用交互式调试器上的代码执行，可以传入 `use_evalex=False` 作为参数。这会保持调试器的回溯屏幕活动，但禁用代码执行。

不建议使用此函数进行自动重载开发，因为支持很差。相反，应使用 `flask` 命令行脚本的 `run` 支持。

> **请记住**
>
> 除非处于调试模式，否则 Flask 会用通用错误页面抑制任何服务器错误。因此，要仅启用交互式调试器而不启用代码重载，必须使用 `debug=True` 和 `use_reloader=False` 调用 `run()`。在非调试模式下设置 `use_debugger` 为 `True` 不会捕获任何异常，因为不会有异常可捕获。

**参数**

- `host` (`str | None`)  
    要监听的主机名。设置为 `'0.0.0.0'` 可使服务器也可从外部访问。默认为 `'127.0.0.1'`，如果存在 `SERVER_NAME` 配置变量则使用其中的主机。

- `port` (`int | None`)  
    Web 服务器端口。默认为 `5000`，如果存在 `SERVER_NAME` 配置变量则使用其中定义的端口。

- `debug` (`bool | None`)  
    如果给出，启用或禁用调试模式。参见 `debug`。

- `load_dotenv` (`bool`)  
    加载最近的 `.env` 和 `.flaskenv` 文件以设置环境变量。还会将工作目录更改为找到的第一个文件所在目录。

- `options` (`Any`)  
    转发给底层 Werkzeug 服务器的选项。更多信息请参阅 `werkzeug.serving.run_simple()`。

**返回类型**

`None`

变更记录：1.0 变更：如果安装了 python-dotenv，将用于从 `.env` 和 `.flaskenv` 文件加载环境变量。`FLASK_DEBUG` 环境变量将覆盖 `debug`。默认启用线程模式。0.10 变更：默认端口现在从 `SERVER_NAME` 变量中选择。

## test_client()

```py
test_client(use_cookies=True, **kwargs)
```

为此应用程序创建测试客户端。有关单元测试的信息，请参阅“测试 Flask 应用程序”。

请注意，如果正在测试应用程序代码中的断言或异常，必须设置 `app.testing = True`，以便异常传播到测试客户端。否则，异常将由应用程序处理（对测试客户端不可见），AssertionError 或其他异常的唯一指示将是对测试客户端的 500 状态码响应。参见 `testing` 属性。例如：

```py
app.testing = True
client = app.test_client()
```

测试客户端可以在 `with` 块中使用，以将上下文的关闭推迟到 `with` 块结束。这对于想要访问上下文局部变量进行测试很有用：

```py
with app.test_client() as c:
    rv = c.get('/?vodka=42')
    assert request.args['vodka'] == '42'
```

此外，可以传递可选关键字参数，这些参数将传递给应用程序的 `test_client_class` 构造函数。例如：

```py
from flask.testing import FlaskClient

class CustomClient(FlaskClient):
    def __init__(self, *args, **kwargs):
        self._authentication = kwargs.pop("authentication")
        super(CustomClient, self).__init__(*args, **kwargs)

app.test_client_class = CustomClient
client = app.test_client(authentication='Basic ....')
```

更多信息请参阅 `FlaskClient`。

变更记录：0.11 变更：添加 `**kwargs` 以支持向 `test_client_class` 构造函数传递额外关键字参数。0.7 新增：添加 `use_cookies` 参数，以及通过设置 `test_client_class` 属性覆盖要使用的客户端的能力。0.4 变更：添加对客户端 `with` 块用法的支持。

**参数**

- `use_cookies` (`bool`)

- `kwargs` (`t.Any`)

**返回类型**

`FlaskClient`

## handle_exception()

```py
handle_exception(e)
```

处理没有关联错误处理器的异常，或从错误处理器引发的异常。这始终导致 500 `InternalServerError`。

始终发送 `got_request_exception` 信号。

如果 `PROPAGATE_EXCEPTIONS` 为 `True`（例如在调试模式下），错误将重新引发，以便调试器显示。否则，记录原始异常，并返回 `InternalServerError`。

如果为 `InternalServerError` 或 `500` 注册了错误处理器，将使用它。为保持一致，处理器始终接收 `InternalServerError`。原始未处理异常可通过 `e.original_exception` 获取。

变更记录：1.1.0 变更：始终将 `InternalServerError` 实例传递给处理器，并将 `original_exception` 设置为未处理错误。1.1.0 变更：即使没有处理器，默认 500 响应也会执行 `after_request` 函数和其他收尾工作。0.3 新增。

**参数**

- `e` (`Exception`)

**返回类型**

`Response`

## url_for()

```py
url_for(
    endpoint,
    *,
    _anchor=None,
    _method=None,
    _scheme=None,
    _external=None,
    **values,
)
```

使用给定值生成指向给定端点的 URL。

这由 `flask.url_for()` 调用，也可以直接调用。

*endpoint* 是 URL 规则的名称，通常通过 `@app.route()` 添加，通常与视图函数同名。在 `Blueprint` 中定义的路由会将蓝图名称加上 `.` 前缀添加到端点。

在某些情况下，例如电子邮件消息，你希望 URL 包含协议和域名，如 `https://example.com/hello`。不在活动请求中时，URL 默认是外部的，但这需要设置 `SERVER_NAME`，以便 Flask 知道要使用的域。还应根据需要配置 `APPLICATION_ROOT` 和 `PREFERRED_URL_SCHEME`。此配置仅在不在活动请求中时使用。

函数可以用 `url_defaults()` 装饰，以在构建 URL 之前修改关键字参数。

如果由于某种原因构建失败，例如未知端点或错误值，将调用应用的 `handle_url_build_error()` 方法。如果它返回字符串，则返回该字符串，否则引发 `BuildError`。

**参数**

- `endpoint` (`str`)  
    与要生成的 URL 关联的端点名称。如果以 `.` 开头，将使用当前蓝图名称（如果有）。

- `_anchor` (`str | None`)  
    如果给出，将其作为 `#anchor` 追加到 URL。

- `_method` (`str | None`)  
    如果给出，为端点生成与此方法关联的 URL。

- `_scheme` (`str | None`)  
    如果给出，且 URL 是外部的，则 URL 将使用此协议。

- `_external` (`bool | None`)  
    如果给出，优先使用内部 URL（`False`）或要求外部 URL（`True`）。外部 URL 包含协议和域名。不在活动请求中时，URL 默认是外部的。

- `values` (`Any`)  
    用于 URL 规则可变部分的值。未知键作为查询字符串参数追加，如 `?a=b&c=d`。

**返回类型**

`str`

变更记录：2.2 新增：从 `flask.url_for` 移出，后者调用此方法。

## make_response()

```py
make_response(rv)
```

将视图函数的返回值转换为 `response_class` 的实例。

**参数**

- `rv` (`ft.ResponseReturnValue`)  
    视图函数的返回值。视图函数必须返回响应。不允许返回 `None`，也不允许视图结束而没有返回。`view_rv` 允许以下类型：
    - `str`：创建响应对象，字符串编码为 UTF-8 作为正文。
    - `bytes`：创建响应对象，字节作为正文。
    - `dict`：转换为 JSON 响应。
    - `list`：转换为 JSON 响应。
    - `generator` 或 `iterator`：返回 `str` 或 `bytes` 的生成器，作为响应流式传输。
    - `tuple`：`(body, status, headers)`、`(body, status)` 或 `(body, headers)`，其中 `body` 是此处允许的任何其他类型，`status` 是字符串或整数，`headers` 是字典或 `(key, value)` 元组列表。如果 `body` 是 `response_class` 实例，`status` 覆盖现有值，`headers` 扩展。
    - `response_class`：对象原样返回。
    - 其他 `Response` 类：对象被强制转换为 `response_class`。
    - `callable()`：函数作为 WSGI 应用调用。结果用于创建响应对象。

**返回类型**

`Response`

变更记录：2.2 变更：生成器将转换为流式响应。列表将转换为 JSON 响应。1.1 变更：字典将转换为 JSON 响应。0.9 变更：以前元组被解释为响应对象的参数。

## add_url_rule()

```py
add_url_rule(
    rule,
    endpoint=None,
    view_func=None,
    provide_automatic_options=None,
    **options,
)
```

注册用于路由传入请求和构建 URL 的规则。`route()` 装饰器是使用 `view_func` 参数调用此方法的快捷方式。以下等价：

```py
@app.route("/")
def index():
    ...
```

```py
def index():
    ...

app.add_url_rule("/", view_func=index)
```

参见“URL 路由注册”。

如果未传入 `endpoint` 参数，路由的端点名称默认为视图函数名称。如果已为端点注册函数，将引发错误。

`methods` 参数默认为 `["GET"]`。`HEAD` 始终自动添加，`OPTIONS` 默认自动添加。

`view_func` 不一定需要传入，但如果规则应参与路由，必须在某个时候通过 `endpoint()` 装饰器将端点名称与视图函数关联。

```py
app.add_url_rule("/", endpoint="index")

@app.endpoint("index")
def index():
    ...
```

如果 `view_func` 具有 `required_methods` 属性，这些方法会添加到传入和自动方法中。如果它具有 `provide_automatic_methods` 属性，则在未传入参数时用作默认值。

**参数**

- `rule` (`str`)  
    URL 规则字符串。

- `endpoint` (`str | None`)  
    与规则和视图函数关联的端点名称。用于路由和构建 URL。默认为 `view_func.__name__`。

- `view_func` (`ft.RouteCallable | None`)  
    与端点名称关联的视图函数。

- `provide_automatic_options` (`bool | None`)  
    添加 `OPTIONS` 方法并自动响应 `OPTIONS` 请求。

- `options` (`t.Any`)  
    传递给 `Rule` 对象的额外选项。

**返回类型**

`None`

## teardown_appcontext()

```py

```

注册当应用程序上下文弹出时调用的函数。应用程序上下文通常在每个请求的请求上下文之后、CLI 命令结束时或手动推入的上下文结束后弹出。

```py
with app.app_context():
    ...
```

当 `with` 块退出（或调用 `ctx.pop()`）时，拆卸函数在应用程序上下文变为非活动之前调用。由于请求上下文通常也管理应用程序上下文，因此弹出请求上下文时也会调用它。

当拆卸函数因未处理异常而调用时，将传递一个错误对象。如果注册了 `errorhandler()`，它将处理异常，拆卸将不会接收它。

拆卸函数必须避免引发异常。如果它们执行可能失败的代码，必须用 `try`/`except` 块包围并记录任何错误。

拆卸函数的返回值被忽略。

变更记录：0.9 新增。

**参数**

- `f` (`T_teardown`)

**返回类型**

`T_teardown`
