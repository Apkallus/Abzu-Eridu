## 传入请求数据

### class flask.Request()

```py
class flask.Request(environ, populate_request=True, shallow=False)
```

Flask 默认使用的请求对象。会记住匹配的端点与视图参数。

它就是最终作为 `request` 的对象。如果想替换所使用的请求对象，可以继承此类并将 `request_class` 设置为你的子类。

请求对象是 [`Request`](https://werkzeug.palletsprojects.com/en/stable/wrappers/#werkzeug.wrappers.Request) 的子类，提供 Werkzeug 定义的所有属性以及一些 Flask 特有的属性。

参数：

- `environ` (`WSGIEnvironment`)
- `populate_request` (`bool`)
- `shallow` (`bool`)

#### url_rule

```py
url_rule: Rule | None = None
```

匹配该请求的内部 URL 规则。这对于在前置/后置处理器中检查该 URL 允许哪些方法很有用（`request.url_rule.methods`）等。不过，如果请求的方法对该 URL 规则无效，有效列表反而在 `routing_exception.valid_methods` 中可用（Werkzeug 异常 [`MethodNotAllowed`](https://werkzeug.palletsprojects.com/en/stable/exceptions/#werkzeug.exceptions.MethodNotAllowed) 的一个属性），因为请求从未在内部绑定。

> **变更记录**
>
> 新增于版本 0.6。

#### view_args

```py
view_args: dict[str, t.Any] | None = None
```

匹配该请求的视图参数字典。如果匹配时发生异常，则为 `None`。

#### routing_exception

```py
routing_exception: HTTPException | None = None
```

如果 URL 匹配失败，这是将引发/已作为请求处理一部分引发的异常。通常是 [`NotFound`](https://werkzeug.palletsprojects.com/en/stable/exceptions/#werkzeug.exceptions.NotFound) 异常或类似异常。

#### max_content_length

```py
property max_content_length: int | None
```

此请求期间将读取的最大字节数。如果超过此限制，会引发 413 [`RequestEntityTooLarge`](https://werkzeug.palletsprojects.com/en/stable/exceptions/#werkzeug.exceptions.RequestEntityTooLarge) 错误。如果设置为 `None`，则在 Flask 应用级别不强制限制。但是，如果为 `None`，且请求没有 `Content-Length` 头，并且 WSGI 服务器未指示其终止流，则不会读取任何数据，以避免无限流。

每个请求默认使用 `MAX_CONTENT_LENGTH` 配置，其默认值为 `None`。可以在特定 `request` 上设置，以将该限制应用于该特定视图。应根据应用或视图的具体需求适当设置。

> **变更记录**
>
> 在版本 3.1 中变更：可按请求设置。
>
> 在版本 0.6 中变更：可通过 Flask 配置进行配置。

`multipart/form-data` 正文中任何非文件表单字段的最大字节数。如果超过此限制，会引发 413 [`RequestEntityTooLarge`](https://werkzeug.palletsprojects.com/en/stable/exceptions/#werkzeug.exceptions.RequestEntityTooLarge) 错误。如果设置为 `None`，则在 Flask 应用级别不强制限制。

每个请求默认使用 `MAX_FORM_MEMORY_SIZE` 配置，其默认值为 `500_000`。可以在特定 `request` 上设置，以将该限制应用于该特定视图。应根据应用或视图的具体需求适当设置。

> **变更记录**

#### classmethod application()

```py
classmethod application(f)
```

将一个函数装饰为响应器，该函数接受请求作为最后一个参数。其工作方式类似于 `responder()` 装饰器，但函数会以请求对象作为最后一个参数传入，并且请求对象会自动关闭：

```py
@Request.application
def my_wsgi_app(request):
    return Response('Hello World!')
```

自 Werkzeug 0.14 起，HTTP 异常会被自动捕获并转换为响应，而不是失败。

参数：

- `f` (`t.Callable[[Request], WSGIApplication]`)  
    要装饰的 WSGI 可调用对象。

返回：新的 WSGI 可调用对象。

返回类型：`WSGIApplication`

#### files

```py

```

包含所有上传文件的 [`MultiDict`](https://werkzeug.palletsprojects.com/en/stable/datastructures/#werkzeug.datastructures.MultiDict) 对象。`files` 中的每个键来自 `<input type="file" name="">` 的 name。每个值是 Werkzeug [`FileStorage`](https://werkzeug.palletsprojects.com/en/stable/datastructures/#werkzeug.datastructures.FileStorage) 对象。

#### get_data()

```py
get_data(cache=True, as_text=False, parse_form_data=False)
```

将客户端传入的缓冲数据读入一个 bytes 对象。默认缓存，但可通过将 `cache` 设置为 `False` 更改。

通常不建议在不先检查内容长度的情况下调用此方法，因为客户端可能发送数十兆字节或更多，导致服务器内存问题。

注意，如果表单数据已经解析，此方法将不返回任何内容，因为表单数据解析不会像此方法那样缓存数据。要隐式调用表单数据解析函数，请将 `parse_form_data` 设置为 `True`。这样做时，如果表单解析器处理了数据，此方法的返回值将为空字符串。通常不需要这样做，因为如果整个数据已缓存（默认），表单解析器将使用缓存数据解析表单数据。请在任何情况下都注意先检查内容长度，再调用此方法，以避免耗尽服务器内存。

如果 `as_text` 设置为 `True`，返回值将是解码后的字符串。

> **变更记录**
>
> 新增于版本 0.9。

参数：

- `cache` (`bool`)
- `as_text` (`bool`)
- `parse_form_data` (`bool`)

返回类型：`bytes` | `str`

#### stream

```py
property stream: IO[bytes]
```

带有安全检查的 WSGI 输入流。此流只能消费一次。

使用 `get_data()` 获取完整数据为 bytes 或文本。`data` 属性仅当完整字节不表示表单数据时才包含完整字节。在这种情况下，`form` 属性将包含解析后的表单数据。

与 `input_stream` 不同，此流防止无限流或读取超过 `content_length` 或 `max_content_length`。

如果设置了 `max_content_length`，且设置了 `wsgi.input_terminated`，则可以在流上强制执行。否则返回空流。

如果在底层流耗尽之前达到限制（例如文件太大或无限流），则无法安全读取流的剩余内容。取决于服务器处理方式，客户端可能显示“连接重置”失败，而不是看到 413 响应。

> **变更记录**
>
> 在版本 2.3 中变更：预先检查 `max_content_length` 并在读取过程中检查。
>
> 在版本 0.9 中变更：即使首先访问了表单解析，流也始终会被设置（但可能已被消费）。

#### trusted_hosts

```py
trusted_hosts: list[str] | None = None
```

处理请求时有效的主机名。默认信任所有主机，这意味着无论客户端说主机是什么都会被接受。

由于 `Host` 和 `X-Forwarded-Host` 头可被恶意客户端设置为任意值，建议设置此属性或在代理中实现类似验证（如果应用运行在代理后）。

> **变更记录**
>
> 新增于版本 0.9。

#### user_agent

> **变更记录**
>
> 在版本 2.1 中变更：内置解析器已移除。将 `user_agent_class` 设置为 `UserAgent` 的子类以从字符串解析数据。

#### user_agent_class

[`UserAgent`](https://werkzeug.palletsprojects.com/en/stable/utils/#werkzeug.user_agent.UserAgent) 的别名。

#### values

```py
property values: CombinedMultiDict[str, str]
```

一个 [`werkzeug.datastructures.CombinedMultiDict`](https://werkzeug.palletsprojects.com/en/stable/datastructures/#werkzeug.datastructures.CombinedMultiDict)，组合 `args` 和 `form`。

对于 `GET` 请求，仅存在 `args`，不存在 `form`。

> **变更记录**
>
> 在版本 2.0 中变更：对于 `GET` 请求，仅存在 `args`，不存在 `form`。

#### shallow

创建请求对象时设置。如果为 `True`，从请求体读取将引发 `RuntimeException`。用于防止中间件修改流。

#### method

发出请求所用的方法，例如 `GET`。

#### scheme

请求所用协议的 URL 方案，例如 `https` 或 `wss`。

#### server

#### headers

随请求接收的头。

#### remote_addr

发送请求的客户端地址。

### flask.request

要访问传入请求数据，可以使用全局 `request` 对象。Flask 会为你解析传入请求数据，并通过该全局对象提供访问。内部而言，Flask 确保如果你处于多线程环境中，你始终获得活动线程的正确数据。

这是一个代理。有关更多信息，请参阅“Notes On Proxies”。

请求对象是 `Request` 的实例。
