## format() 格式化

```py
format(value, format_spec='', /)
```

将值转换为由 `format_spec` 控制的“格式化”表示形式。`format_spec` 的解释取决于 `value` 参数的类型；不过，大多数内置类型都使用一种标准的格式化语法：[格式规范迷你语言]。

默认的 `format_spec` 为空字符串，其效果通常与调用 `[str(value)]` 相同。

对 `format(value, format_spec)` 的调用会被转换为 `type(value).__format__(value, format_spec)`，这在查找值的 `[__format__()]` 方法时会绕过实例字典。

如果方法查找到达 `[object]` 且 `format_spec` 非空，或者 `format_spec` 或返回值不是字符串，则会引发 `[TypeError]` 异常。

在 3.4 版本发生变更：如果 `format_spec` 不是空字符串，`object().__format__(format_spec)` 会引发 `[TypeError]`。


示例

```py
# 设置模板字符串
template = 'Host: {target_host}'
# 填充模板字符串
template.format(target_host="localhost")
```

## `ord(c)` —— 转字符为 Unicode 码

对表示单个 Unicode 字符的字符串，返回代表它 Unicode 码点的整数。这是 `chr()` 的逆函数。

例如 
```py
ord('a') # 整数 97
ord('€') # 返回 8364 
```

## `class int([x])` —— 转为选定进制的 int 对象

```py
class int(x, base=10)
```

返回一个基于数字或字符串 `x` 构造的整数对象，或者在未给出参数时返回 0。 

默认的 `base` 为 10。 允许的基数为 0 和 2--36。 对于基数 2, -8 和 -16 来说字符串前面还能加上可选的 `0b/0B`, `0o/0O` 或 `0x/0X` 前缀，就像代码中的整数字面值那样。 

## next

```py
next(iterator, /)
next(iterator, default, /)
```

通过调用 `iterator` 的 `__next__()` 方法获取下一个元素。如果迭代器耗尽，则返回给定的 `default`，如果没有默认值则触发 `StopIteration。`

## chr()

```py
chr(codepoint, /)
```

返回表示具有指定 Unicode 码点的字符的字符串。例如，`chr(97)` 返回字符串 `'a'`，而 `chr(8364)` 返回字符串 `'€'`。这是 `[ord()]` 的逆操作。

参数的有效范围是从 0 到 1,114,111（十六进制的 `0x10FFFF`）。如果超出该范围，将引发 `[ValueError]`。

## open()

```python
open(file, mode='r', buffering=-1, encoding=None, errors=None, newline=None, closefd=True, opener=None)
```

打开 `file` 并返回相应的[文件对象]。如果文件无法打开，则引发 `OSError`。有关如何使用此函数的更多示例，请参见[读写文件]。

`file` 是[类路径对象]，给出要打开文件的路径名（绝对路径或相对于当前工作目录的路径），或要包装的文件的整数文件描述符。（如果给出文件描述符，则当返回的 I/O 对象关闭时，该文件描述符会关闭，除非 `closefd` 设置为 `False`。）

`mode` 是可选字符串，指定打开文件的模式。默认值为 `'r'`，表示以文本模式打开读取。其他常见值包括 `'w'` 用于写入（如果文件已存在则截断文件）、`'x'` 用于独占创建、`'a'` 用于追加（在*某些* Unix 系统上，这意味着*所有*写入都追加到文件末尾，而不管当前 seek 位置）。在文本模式下，如果未指定 `encoding`，默认使用 UTF-8；如果 [Python UTF-8 模式] 被禁用，则调用 `locale.getencoding()` 获取当前区域设置编码。（要读写原始字节，请使用二进制模式并让 `encoding` 未指定。）可用模式如下：

- `'r'`：打开读取（默认）
- `'w'`：打开写入，先截断文件
- `'x'`：打开独占创建，如果文件已存在则失败
- `'a'`：打开写入，如果文件存在则追加到文件末尾
- `'b'`：二进制模式
- `'t'`：文本模式（默认）
- `'+'`：打开更新（读取和写入）

默认模式是 `'r'`（打开读取文本，是 `'rt'` 的同义词）。模式 `'w+'` 和 `'w+b'` 会打开并截断文件。模式 `'r+'` 和 `'r+b'` 打开文件时不截断。

如[概述]中所述，Python 区分二进制 I/O 和文本 I/O。以二进制模式打开的文件（包括 `mode` 参数中包含 `'b'`）返回 `bytes` 对象作为内容，不进行任何解码。在文本模式（默认，或 `mode` 参数中包含 `'t'`）下，文件内容作为 `str` 返回，字节首先使用默认编码解码，或在指定 `encoding` 时使用指定编码解码。

> **备注**
>
> Python 不依赖底层操作系统的文本文件概念；所有处理都由 Python 本身完成，因此与平台无关。

`buffering` 是可选整数，用于设置缓冲策略。传递 0 以关闭缓冲（仅允许在二进制模式下），传递 1 以选择行缓冲（仅在文本模式下写入时可用），传递大于 1 的整数以指示固定大小块缓冲区的字节大小。注意，以这种方式指定缓冲区大小适用于二进制缓冲 I/O，但 `TextIOWrapper`（即，以 `mode='r+'` 打开的文件）会有另一种缓冲。要在 `TextIOWrapper` 中禁用缓冲，考虑使用 `io.TextIOWrapper.reconfigure()` 的 `write_through` 标志。未给出 `buffering` 参数时，默认缓冲策略如下：

- 二进制文件按固定大小块缓冲；当设备块大小可用时，缓冲区大小为 `max(min(blocksize, 8 MiB), DEFAULT_BUFFER_SIZE)`。在大多数系统上，缓冲区通常为 128 KiB。
- “交互式”文本文件（`isatty()` 返回 `True` 的文件）使用行缓冲。其他文本文件使用上述二进制文件的策略。

`encoding` 是用于解码或编码文件的编码名称。只应在文本模式下使用。默认编码是 UTF-8；如果 [Python UTF-8 模式] 被禁用，默认值取决于平台（即 `locale.getencoding()` 返回的值）。可以使用 Python 支持的任何[文本编码]；`encoding="locale"` 显式指定当前区域设置编码。有关支持的编码列表，请参见 `codecs` 模块。

`errors` 是可选字符串，指定如何处理编码和解码错误——不能在二进制模式下使用。有多种标准错误处理方案可用，不过任何已通过 `codecs.register_error()` 注册的错误处理名称也有效。标准名称可在[错误处理方案]中找到。

`newline` 决定如何从流中解析换行字符。它可以是 `None`、`''`、`'\n'`、`'\r'` 和 `'\r\n'`。其工作方式如下：

- 从流中读取输入时，如果 `newline` 为 `None`，则启用通用换行模式。输入中的行可以以 `'\n'`、`'\r'` 或 `'\r\n'` 结尾，这些在返回给调用者之前会被转换为 `'\n'`。如果为 `''`，则启用通用换行模式，但行尾会不经转换返回给调用者。如果为任何其他合法值，则输入行仅由给定字符串终止，并且行尾会不经转换返回给调用者。
- 向流写入输出时，如果 `newline` 为 `None`，则写入的任何 `'\n'` 字符都会转换为系统默认行分隔符 `os.linesep`。如果 `newline` 为 `''` 或 `'\n'`，则不发生转换。如果 `newline` 为任何其他合法值，则写入的任何 `'\n'` 字符都会转换为给定字符串。

如果 `closefd` 为 `False`，并且给出的是文件描述符而不是文件名，则关闭文件时底层文件描述符将保持打开。如果给出的是文件名，`closefd` 必须为 `True`（默认值）；否则会引发错误。

可以通过传递可调用对象作为 `opener` 来使用自定义打开器。然后通过以 (`file`, `flags`) 调用 `opener` 来获取文件对象的底层文件描述符。`opener` 必须返回一个打开的文件描述符（将 `os.open` 作为 `opener` 传递会产生与传递 `None` 类似的功能）。

新创建的文件是[不可继承]的。

以下示例使用 `os.open()` 函数的 [dir_fd] 参数打开相对于给定目录的文件：

```py
>>> import os
>>> dir_fd = os.open('somedir', os.O_RDONLY)
>>> def opener(path, flags):
...     return os.open(path, flags, dir_fd=dir_fd)
...
>>> with open('spamspam.txt', 'w', opener=opener) as f:
...     print('This will be written to somedir/spamspam.txt', file=f)
...
>>> os.close(dir_fd)  # 不要泄漏文件描述符
```

`open()` 函数返回的[文件对象]类型取决于模式。当 `open()` 用于以文本模式（`'w'`、`'r'`、`'wt'`、`'rt'` 等）打开文件时，它返回 `io.TextIOBase` 的子类（具体是 `io.TextIOWrapper`）。当用于以带缓冲的二进制模式打开文件时，返回的类是 `io.BufferedIOBase` 的子类。具体类会有所不同：在读取二进制模式下，返回 `io.BufferedReader`；在写入二进制和追加二进制模式下，返回 `io.BufferedWriter`；在读写模式下，返回 `io.BufferedRandom`。当禁用缓冲时，返回原始流，即 `io.RawIOBase` 的子类 `io.FileIO`。

另请参见文件处理模块，例如 `fileinput`、`io`（`open()` 声明所在处）、`os`、`os.path`、`tempfile` 和 `shutil`。

引发审计事件 `open`，参数为 `path`、`mode`、`flags`。

`mode` 和 `flags` 参数可能已被修改或从原始调用推断。

**在 3.3 版本发生变更：**

- 添加了 `opener` 参数。
- 添加了 `'x'` 模式。
- 过去引发 `IOError`，现在它是 `OSError` 的别名。
- 如果以独占创建模式（`'x'`）打开的文件已存在，现在会引发 `FileExistsError`。

**在 3.4 版本发生变更：**

- 文件现在不可继承。

**在 3.5 版本发生变更：**

- 如果系统调用被中断且信号处理程序未引发异常，函数现在会重试系统调用，而不是引发 `InterruptedError` 异常（理由见 [PEP 475](https://peps.python.org/pep-0475/)）。
- 添加了 `'namereplace'` 错误处理程序。

**在 3.6 版本发生变更：**

- 添加了对接受实现 `os.PathLike` 的对象的支持。
- 在 Windows 上，打开控制台缓冲区可能返回 `io.RawIOBase` 的子类，而不是 `io.FileIO`。

**在 3.11 版本发生变更：** 已移除 `'U'` 模式。

**在 3.15 版本发生变更：** UTF-8 现在是默认编码，而不是依赖平台的区域设置编码（[PEP 686](https://peps.python.org/pep-0686/)）。
