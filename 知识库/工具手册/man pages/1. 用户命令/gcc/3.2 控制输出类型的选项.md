https://gcc.gnu.org/onlinedocs/gcc/Overall-Options.html

## 3.2 控制输出种类的选项

编译最多涉及四个阶段：预处理、编译本身、汇编和链接，始终按此顺序。GCC 能够预处理并编译多个文件，可以生成多个汇编器输入文件，也可以生成一个汇编器输入文件；然后每个汇编器输入文件生成一个目标文件，链接将所有目标文件（新编译的目标文件以及作为输入指定的目标文件）合并为一个可执行文件。

对于任何给定输入文件，文件名后缀决定执行何种编译：

- `file.c`  
    C 源代码，必须预处理。

- `file.i`  
    C 源代码，不应预处理。

- `file.ii`  
    C++ 源代码，不应预处理。

- `file.m`  
    Objective-C 源代码。注意，必须与 `libobjc` 库链接才能使 Objective-C 程序正常工作。

- `file.mi`  
    Objective-C 源代码，不应预处理。

- 
    ```
    file.mm
    file.M
    ```
    Objective-C++ 源代码。注意，必须与 `libobjc` 库链接才能使 Objective-C++ 程序正常工作。注意，`.M` 指的是字面量大写 M。

- `file.mii`  
    Objective-C++ 源代码，不应预处理。

- `file.h`  
    C、C++、Objective-C 或 Objective-C++ 头文件，默认转换为预编译头；或者通过 `-fdump-ada-spec` 开关将 C、C++ 头文件转换为 Ada 规范。

- 
    ```
    file.cc
    file.cp
    file.cxx
    file.cpp
    file.CPP
    file.c++
    file.C
    ```
    C++ 源代码，必须预处理。注意，在 `.cxx` 中，最后两个字母必须都是字面量 `x`。同样，`.C` 指的是字面量大写 C。

- 
    ```
    file.mm
    file.M
    ```
    Objective-C++ 源代码，必须预处理。

- `file.mii`  
    Objective-C++ 源代码，不应预处理。

- 
    ```
    file.hh
    file.H
    file.hp
    file.hxx
    file.hpp
    file.HPP
    file.h++
    file.tcc
    ```
    C++ 头文件，要转换为预编译头或 Ada 规范。

- 
    ```
    file.f
    file.for
    file.ftn
    file.fi
    ```
    固定格式 Fortran 源代码，不应预处理。

- 
    ```
    file.F
    file.FOR
    file.fpp
    file.FPP
    file.FTN
    ```
    固定格式 Fortran 源代码，必须预处理（使用传统预处理器）。

- 
    ```
    file.f90
    file.f95
    file.f03
    file.f08
    file.fii
    ```
    自由格式 Fortran 源代码，不应预处理。

- 
    ```
    file.F90
    file.F95
    file.F03
    file.F08
    ```
    自由格式 Fortran 源代码，必须预处理（使用传统预处理器）。

- 
    ```
    file.cob
    file.COB
    file.cbl
    file.CBL
    ```
    COBOL 源代码。

- `file.go`  
    Go 源代码。

- `file.d`  
    D 源代码。

- `file.di`  
    D 接口文件。

- `file.dd`  
    D 文档代码（Ddoc）。

- `file.ads`  
    Ada 源代码文件，包含库单元声明（包、子程序或泛型的声明，或泛型实例化），或库单元重命名声明（包、泛型或子程序重命名声明）。此类文件也称为“规范”（specs）。

- `file.adb`  
    Ada 源代码文件，包含库单元主体（子程序或包体）。此类文件也称为“主体”（bodies）。

- `file.s`  
    汇编器代码。

- 
    ```
    file.S
    file.sx
    ```
    必须预处理的汇编器代码。

- `other`  
    要直接送入链接的目标文件。任何没有可识别后缀的文件名都按此方式处理。

可以使用 `-x` 选项显式指定输入语言：

### `-x language`, `--language=language`, `--language language`

```
-x language
--language=language
--language language
```

为后续输入文件显式指定 `language`（而不是让编译器根据文件名后缀选择默认值）。此选项适用于所有后续输入文件，直到下一个 `-x` 选项。`language` 的可能值有：

```
c  c-header  cpp-output
c++  c++-header  c++-system-header c++-user-header c++-cpp-output
c++-system-module
objective-c  objective-c-header  objective-c-cpp-output  objc-cpp-output
objective-c++  objective-c++-header  objective-c++-cpp-output
objc++-cpp-output
assembler  assembler-with-cpp
ada  adascil  adawhy
cobol
d
f77  f77-cpp-input  f95  f95-cpp-input
go
modula-2  modula-2-cpp-output
rust
algol68
lto
```

注意，`-x` 不暗示特定语言标准。例如，对于某些较旧源代码，`-x f77` 可能还需要 `-std=legacy`。

### `-x none`

```
-x none
```

关闭任何语言指定，因此后续文件根据文件名后缀处理（就像根本没有使用 `-x` 一样）。

如果只需要编译的某些阶段，可以使用 `-x`（或文件名后缀）告诉 `gcc` 从哪里开始，并使用 `-c`、`-S` 或 `-E` 之一说明 `gcc` 在哪里停止。注意，某些组合（例如 `-x cpp-output -E`）会指示 `gcc` 什么都不做。

### `-c`, `--compile`

```
-c
--compile
```

编译或汇编源文件，但不链接。链接阶段完全不执行。最终输出为每个源文件一个目标文件。

默认情况下，源文件的目标文件名是将后缀 `.c`、`.i`、`.s` 等替换为 `.o`。

不需要编译或汇编的无法识别输入文件会被忽略。

### `-S`, `--assemble`

```
-S
--assemble
```

在编译本身阶段后停止；不进行汇编。对于每个指定的非汇编器输入文件，输出为汇编器代码文件。

默认情况下，源文件的汇编器文件名是将后缀 `.c`、`.i` 等替换为 `.s`。

不需要编译的输入文件会被忽略。

### `-E`, `--preprocess`

```
-E
--preprocess
```

在预处理阶段后停止；不运行编译器本身。输出为预处理后的源代码，发送到标准输出。

不需要预处理的输入文件会被忽略。

### `-o file`, `--output=file`, `--output file`

```
-o file
--output=file
--output file
```

将主要输出放入文件 `file`。这适用于正在生成的任何类型的输出，无论是可执行文件、目标文件、汇编器文件还是预处理后的 C 代码。

如果未指定 `-o`，默认将可执行文件放在 `a.out`，将 `source.suffix` 的目标文件放在 `source.o`，将其汇编器文件放在 `source.s`，将预编译头文件放在 `source.suffix.gch`，并将所有预处理后的 C 源代码输出到标准输出。

尽管 `-o` 只命名主要输出，它也会影响辅助输出和转储输出的命名。参见下面的示例。除非被覆盖，辅助输出和转储输出都放在与主要输出相同的目录中。在辅助输出中，输入文件的后缀替换为辅助输出文件类型的后缀；在转储输出中，转储文件的后缀追加到输入文件后缀之后。在编译命令中，辅助输出和转储输出的基名都是主要输出的基名；在编译并链接命令中，主要输出名减去可执行文件后缀后，与输入文件名组合。如果两者共享相同基名（忽略后缀），组合结果就是该基名，否则用短横线分隔连接。

```sh
gcc -c foo.c ...
```

将使用 `foo.o` 作为主要输出，并将辅助输出和转储输出放在其旁边，例如 `-gsplit-dwarf` 的辅助文件 `foo.dwo`，以及 `-fdump-rtl-final` 的转储文件 `foo.c.???r.final`。

如果显式指定了非链接器输出文件，辅助文件和转储文件默认采用相同基名：

```sh
gcc -c foo.c -o dir/foobar.o ...
```

将辅助输出命名为 `dir/foobar.*`，转储输出命名为 `dir/foobar.c.*`。

链接器输出则会为辅助输出和转储输出添加前缀：

```sh
gcc foo.c bar.c -o dir/foobar ...
```

通常会将辅助输出命名为 `dir/foobar-foo.*` 和 `dir/foobar-bar.*`，将转储输出命名为 `dir/foobar-foo.c.*` 和 `dir/foobar-bar.c.*`。

上述情况的一个例外是可执行文件与单个输入共享基名：

```sh
gcc foo.c -o dir/foo ...
```

此时辅助输出命名为 `dir/foo.*`，转储输出命名为 `dir/foo.c.*`。

辅助输出和转储输出的位置和名称可以通过 `-dumpbase`、`-dumpbase-ext`、`-dumpdir`、`-save-temps=cwd` 和 `-save-temps=obj` 选项调整。

### `-dumpbase dumpbase`

```
-dumpbase dumpbase
```

此选项设置辅助输出文件和转储输出文件的基名。它不影响主要输出文件的名称。保留的中间输出不被视为主要输出，而被视为辅助输出：

```sh
gcc -save-temps -S foo.c
```

将（不再是临时的）预处理文件保存到 `foo.i`，然后编译到（隐含的）输出文件 `foo.s`，而：

```sh
gcc -save-temps -dumpbase save-foo -c foo.c
```

预处理到 `save-foo.i`，编译到 `save-foo.s`（现在是中间文件，因此是辅助输出），然后汇编到（隐含的）输出文件 `foo.o`。

如果没有此选项，转储文件和辅助文件从输入文件取名，或者如果显式指定了（非链接器）输出文件，则从该输出文件取名：转储输出文件（例如由 `-fdump-*` 选项请求的文件）带有输入名称后缀，而辅助输出文件（由其他非转储选项请求的文件，例如 `-save-temps`、`-gsplit-dwarf`、`-fcallgraph-info`）不带该后缀。

对于显式给出的 `-dumpbase basename.suf`，也可以通过同时指定 `-dumpbase-ext .suf` 来实现类似的转储输出和辅助输出后缀区分。

如果显式指定的 `dumpbase` 含有任何目录组件，则任何 `dumppfx` 指定（例如 `-dumpdir` 或 `-save-temps=*`）都会被忽略，并且 `dumpbase` 不是追加到它，而是完全覆盖它：

```sh
gcc foo.c -c -o dir/foo.o -dumpbase alt/foo \
  -dumpdir pfx- -save-temps=cwd ...
```

创建名为 `alt/foo.*` 的辅助输出和转储输出，忽略 `-o` 中的 `dir/`、`-save-temps=cwd` 隐含的 `./` 前缀，以及 `-dumpdir` 中的 `pfx-`。

当在编译多个输入、或编译然后链接的命令中指定 `-dumpbase` 时，它可能会与 `dumppfx` 组合，具体如 `-dumpdir` 下所述。然后，每个输入文件使用组合后的 `dumppfx` 编译，并为每个输入文件计算 `dumpbase` 和 `auxdropsuf` 的默认值：

```sh
gcc foo.c bar.c -c -dumpbase main ...
```

创建 `foo.o` 和 `bar.o` 作为主要输出，并通过使用 `dumpbase` 作为前缀来避免覆盖辅助输出和转储输出，创建名为 `main-foo.*` 和 `main-bar.*` 的辅助输出和转储输出。

将空字符串指定为 `dumpbase` 可避免编译期间输出基名对辅助输出和转储输出命名的影响，并计算默认值：

```sh
gcc -c foo.c -o dir/foobar.o -dumpbase '' ...
```

将辅助输出命名为 `dir/foo.*`，转储输出命名为 `dir/foo.c.*`。注意，它们的基名取自输入名称，但目录仍然默认为输出所在目录。

空字符串 `dumpbase` 不会阻止链接期间输出使用输出基名：

```sh
gcc foo.c bar.c -o dir/foobar -dumpbase '' -flto ...
```

源文件的编译将辅助输出命名为 `dir/foo.*` 和 `dir/bar.*`，转储输出命名为 `dir/foo.c.*` 和 `dir/bar.c.*`。链接期间的 LTO 重新编译将使用 `dir/foobar.` 作为转储文件和辅助文件的前缀。

### `-dumpbase-ext auxdropsuf`

```
-dumpbase-ext auxdropsuf
```

在形成辅助（但不是转储）输出文件的名称时，在追加任何后缀之前，从 `dumpbase` 中删除末尾的 `auxdropsuf`。如果未指定，此选项默认为默认 `dumpbase` 的后缀，即当命令行中不存在 `-dumpbase`，或 `dumpbase` 与 `dumppfx` 组合时，为输入文件的后缀。

```sh
gcc foo.c -c -o dir/foo.o -dumpbase x-foo.c -dumpbase-ext .c ...
```

创建 `dir/foo.o` 作为主输出，并在 `dir/x-foo.*` 中生成辅助输出，采用主输出的位置，并从 `dumpbase` 中去掉 `.c` 后缀。转储输出保留后缀：`dir/x-foo.c.*`。

如果该选项与指定 `dumpbase` 的后缀不匹配，则会被忽略，但作为在将链接器输出基名追加到 `dumppfx` 时替代可执行文件后缀的方式除外，如下所述：

```sh
gcc foo.c bar.c -o main.out -dumpbase-ext .out ...
```

创建 `main.out` 作为主要输出，并通过使用可执行文件名减去 `auxdropsuf` 作为前缀，避免覆盖辅助输出和转储输出，创建名为 `main-foo.*` 和 `main-bar.*` 的辅助输出，以及名为 `main-foo.c.*` 和 `main-bar.c.*` 的转储输出。

### `-dumpdir dumppfx`

```
-dumpdir dumppfx
```

在形成辅助输出或转储输出文件的名称时，使用 `dumppfx` 作为前缀：

```sh
gcc -dumpdir pfx- -c foo.c ...
```

创建 `foo.o` 作为主要输出，并创建名为 `pfx-foo.*` 的辅助输出，将给定的 `dumppfx` 与从默认主要输出派生的默认 `dumpbase` 组合，而默认主要输出又派生自输入名称。转储输出还采用输入名称后缀：`pfx-foo.c.*`。

如果 `dumppfx` 要用作目录名，则它必须以目录分隔符结尾：

```sh
gcc -dumpdir dir/ -c foo.c -o obj/bar.o ...
```

创建 `obj/bar.o` 作为主要输出，并创建名为 `dir/bar.*` 的辅助输出，将给定的 `dumppfx` 与从主要输出名称派生的默认 `dumpbase` 组合。转储输出还采用输入名称后缀：`dir/bar.c.*`。

它默认为输出文件的位置，除非输出文件是像 `/dev/null` 这样的特殊文件。选项 `-save-temps=cwd` 和 `-save-temps=obj` 会覆盖此默认值，就像显式的 `-dumpdir` 选项一样。如果给出了多个此类选项，最后一个生效：

```sh
gcc -dumpdir pfx- -c foo.c -save-temps=obj ...
```

输出 `foo.o`，辅助输出命名为 `foo.*`，因为 `-save-temps=*` 覆盖了较早的 `-dumpdir` 选项给出的 `dumppfx`。`=obj` 是 `-save-temps` 的默认值，以及输出目录隐含为当前目录，这些都无关紧要。转储输出命名为 `foo.c.*`。

当从多个输入文件编译时，如果指定了 `-dumpbase`，则将 `dumpbase` 减去 `auxdropsuf` 后缀，再加一个短横线，追加到显式或默认的 `dumppfx`（或者如果含有任何目录组件，则覆盖它），以便多个编译中的每一个都获得不同命名的辅助输出和转储输出。

```sh
gcc foo.c bar.c -c -dumpdir dir/pfx- -dumpbase main ...
```

将辅助转储输出到 `dir/pfx-main-foo.*` 和 `dir/pfx-main-bar.*`，将 `dumpbase-` 追加到 `dumppfx`。转储输出保留输入文件后缀：分别为 `dir/pfx-main-foo.c.*` 和 `dir/pfx-main-bar.c.*`。与此对比单输入编译：

```sh
gcc foo.c -c -dumpdir dir/pfx- -dumpbase main ...
```

将 `-dumpbase` 应用于单个源文件时，不会为每个输入文件计算并追加单独的 `dumpbase`。其辅助输出和转储输出位于 `dir/pfx-main.*`。

当从多个输入文件编译然后链接时，默认或显式指定的 `dumppfx` 也会经历上述 `dumpbase-` 变换（例如上面 `foo.c` 和 `bar.c` 的编译，但不带 `-c`）。如果既未给出 `-dumpdir` 也未给出 `-dumpbase`，则将链接器输出基名减去 `auxdropsuf`（如果指定）或可执行文件后缀（否则），再加一个短横线，改为追加到默认 `dumppfx`。但请注意，与先前的链接情况不同：

```sh
gcc foo.c bar.c -dumpdir dir/pfx- -o main ...
```

不会将输出名 `main` 追加到 `dumppfx`，因为显式指定了 `-dumpdir`。目标是，如果需要，显式指定的 `dumppfx` 可以将指定输出名作为前缀的一部分包含在内；只有显式指定的 `-dumpbase` 才会与它组合，以避免简单地丢弃一个有意义的选项。

当从单个输入文件编译然后链接时，只有当链接器输出基名不与单个输入文件名共享基名时，才会像上面那样将其追加到默认 `dumppfx`。这已在上面单输入链接情况中涵盖，但没有涵盖显式 `-dumpdir` 抑制组合的情况，即使被 `-save-temps=*` 覆盖：

```sh
gcc foo.c -dumpdir alt/pfx- -o dir/main.exe -save-temps=cwd ...
```

辅助输出命名为 `foo.*`，转储输出命名为 `foo.c.*`，位于当前工作目录中，最终由 `-save-temps=cwd` 请求。

总结起来，用直观但略不精确的数据流来说：主要输出名被分解为目录部分和基名部分；`dumppfx` 设置为前者，除非被 `-dumpdir` 或 `-save-temps=*` 覆盖；`dumpbase` 设置为后者，除非被 `-dumpbase` 覆盖。如果有多个输入或链接，这个 `dumpbase` 可能与 `dumppfx` 组合，并从每个输入文件取得。每个输入的辅助输出名称通过组合 `dumppfx`、减去后缀的 `dumpbase` 和辅助输出后缀形成；转储输出名称的唯一不同是保留 `dumpbase` 中的后缀。

当涉及 LTO 重新编译期间创建的辅助输出和转储输出时，`dumppfx` 和 `dumpbase` 的组合（按给定值，或从链接器输出名而非输入派生，即使该组合在其他情况下不会如此使用）会以末尾句点替换编译器添加的短横线（如果有）的形式，作为 `-dumpdir` 选项传递给 `lto-wrapper`；由于参与链接，该程序通常不会获得任何 `-dumpbase` 和 `-dumpbase-ext`，并且会忽略它们。

在运行子编译器时，`lto-wrapper` 将 LTO 阶段名追加到接收到的 `dumppfx`，确保它包含目录组件，以便覆盖任何 `-dumpdir`，并将其作为 `-dumpbase` 传递给子编译器。

### `-v`, `--verbose`

```
-v
--verbose
```

在标准错误输出上打印执行编译各阶段所运行的命令。还打印编译器驱动程序程序、预处理器和编译器本身的版本号。

### `-###`

类似 `-v`，但不执行命令，并且除非参数仅包含字母数字字符或 `./-_`，否则会对参数加引号。这对于 shell 脚本捕获驱动程序生成的命令行很有用。

### `--help`

在标准输出上打印 `gcc` 理解的命令行选项说明。如果还指定了 `-v`，则 `--help` 也会传递给 `gcc` 调用的各个进程，以便它们显示其接受的命令行选项。如果还指定了 `-Wextra`（在 `--help` 选项之前），则还会显示没有相关文档的命令行选项。

### `--target-help`

在标准输出上打印每个工具的目标特定命令行选项说明。对于某些目标，还可能打印额外的目标特定信息。

### `--help={class|[^]qualifier}[,…]`

```
--help={class|[^]qualifier}[,…]
```

在标准输出上打印编译器理解的、符合所有指定类和限定符的命令行选项说明。支持的类如下：

- `optimizers`  
    显示编译器支持的所有优化选项。

- `warnings`  
    显示控制编译器生成的警告消息的所有选项。

- `target`  
    显示目标特定选项。但与 `--target-help` 选项不同，链接器和汇编器的目标特定选项不会显示。这是因为这些工具目前不支持扩展的 `--help=` 语法。

- `params`  
    显示 `--param` 选项识别的值。

- `language`  
    显示 `language` 支持的选项，其中 `language` 是此版本 GCC 支持的语言之一的名称。如果某个选项被所有语言支持，则需要选择 `common` 类。

- `common`  
    显示所有语言共有的选项。

支持的限定符如下：

- `undocumented`  
    仅显示未记录的选项。

- `joined`  
    显示参数出现在同一连续文本中等号之后的选项，例如 `--help=target`。

- `separate`  
    显示参数作为单独单词出现在原始选项之后的选项，例如 `-o output-file`。

因此，例如要显示编译器支持的所有未记录的目标特定开关，请使用：

```
--help=target,undocumented
```

限定符的含义可以通过在前面加 `^` 字符来反转，例如要显示所有有描述的二元警告选项（即只有开或关且不接受参数的选项），请使用：

```
--help=warnings,^joined,^undocumented
```

`--help=` 的参数不应仅由反转限定符组成。

可以组合多个类，尽管这通常会将输出限制得太多以至于没有可显示内容。然而，有一种情况确实可行，即其中一个类是 `target`。例如，要显示所有目标特定优化选项，请使用：

```
--help=target,optimizers
```

`--help=` 选项可以在命令行上重复。每次后续使用都会显示其请求的选项类，跳过已经显示过的选项。如果命令行上任何位置还指定了 `--help`，则其优先于任何 `--help=` 选项。

如果 `-Q` 选项出现在 `--help=` 选项之前的命令行上，则 `--help=` 显示的描述文本会改变。不是描述所显示的选项，而是给出该选项是启用、禁用还是设置为特定值的指示（假设编译器在用到 `--help=` 选项时知道这一点）。

下面是来自 `gcc` ARM 移植的截断示例：

```
  % gcc -Q -mabi=2 --help=target -c
  The following options are target specific:
  -mabi=                                2
  -mabort-on-noreturn                   [disabled]
  -mapcs                                [disabled]
```

输出对先前命令行选项的影响敏感，因此例如可以通过以下方式找出在 `-O2` 下启用了哪些优化：

```
-Q -O2 --help=optimizers
```

或者，可以通过以下方式发现 `-O3` 启用了哪些二元优化：

```sh
gcc -c -Q -O3 --help=optimizers > /tmp/O3-opts
gcc -c -Q -O2 --help=optimizers > /tmp/O2-opts
diff /tmp/O2-opts /tmp/O3-opts | grep enabled
```

### `--version`

显示所调用 GCC 的版本号和版权信息。

### `-pass-exit-codes`, `--pass-exit-codes`

```
-pass-exit-codes
--pass-exit-codes
```

通常，如果编译器的任何阶段返回非成功返回码，`gcc` 程序会以代码 1 退出。如果指定 `-pass-exit-codes`，则 `gcc` 程序改为返回任何返回错误指示的阶段产生的数值最高的错误。如果遇到内部编译器错误，C、C++ 和 Fortran 前端返回 4。

### `-pipe`, `--pipe`

```
-pipe
--pipe
```

在编译各阶段之间使用管道而不是临时文件进行通信。在某些汇编器无法从管道读取的系统上这会失败；但 GNU 汇编器没有问题。

### `-wrapper`

在包装程序下调用所有子命令。包装程序的名称及其参数以逗号分隔列表传递。

```sh
gcc -c t.c -wrapper gdb,--args
```

这会在 `gdb --args` 下调用 `gcc` 的所有子程序，因此 `cc1` 的调用为 `gdb --args cc1 …`。

### `-ffile-prefix-map=old=new`

```
-ffile-prefix-map=old=new
```

编译位于目录 `old` 中的文件时，在编译结果中记录对它们的任何引用，就像这些文件位于目录 `new` 中一样。指定此选项等效于指定所有单独的 `-f*-prefix-map` 选项。这可用于使构建可重现且与位置无关。由指令引用的目录不受这些选项影响。另请参见 `-fmacro-prefix-map`、`-fdebug-prefix-map`、`-fprofile-prefix-map` 和 `-fcanon-prefix-map`。

### `-fcanon-prefix-map`

对于 `-f*-prefix-map` 选项，通常将 `old` 前缀与编译结果中通常引用的文件名进行比较时，使用前缀的文本比较，或者在大小写不敏感的文件系统上忽略字符大小写，并在基于 DOS 的文件系统上将斜杠和反斜杠视为相等。`-fcanon-prefix-map` 会使此类比较在 `old` 和所引用文件名的规范化路径上进行。

### `-fplugin=name.so`

```
-fplugin=name.so
```

加载文件 `name.so` 中的插件代码，假定为要由编译器 `dlopen` 的共享对象。共享对象文件的基名用于在参数解析时标识插件（参见下面的 `-fplugin-arg-name-key=value`）。每个插件应定义 Plugins API 中指定的回调函数。

### `-fplugin-arg-name-key=value`

```
-fplugin-arg-name-key=value
```

为名为 `name` 的插件定义一个名为 `key`、值为 `value` 的参数。

### `-fdump-ada-spec[-slim]`

```
-fdump-ada-spec[-slim]
```

对于 C 和 C++ 源文件及包含文件，生成相应的 Ada 规范。参见《GNAT 用户指南》中的[为 C 和 C++ 头文件生成 Ada 绑定](https://gcc.gnu.org/onlinedocs/gnat_ugn/Generating-Ada-Bindings-for-C-and-C_002b_002b-headers.html#Generating-Ada-Bindings-for-C-and-C_002b_002b-headers)，其中提供了此功能的详细文档。

### `-fada-spec-parent=unit`

```
-fada-spec-parent=unit
```

与上面的 `-fdump-ada-spec[-slim]` 一起使用时，生成作为父单元 `unit` 的子单元的 Ada 规范。

### `-fdump-go-spec=file`

```
-fdump-go-spec=file
```

对于任何语言的输入文件，在 `file` 中生成相应的 Go 声明。这会生成 Go `const`、`type`、`var` 和 `func` 声明，这可能是开始为用其他语言编写的代码编写 Go 接口的有用方式。

### `@file`

```
@file
```

从 `file` 读取命令行选项。读取的选项会插入到原始 `@file` 选项的位置。如果 `file` 不存在或无法读取，则该选项将被按字面处理，不会被移除。

`file` 中的选项由空白分隔。可以通过将整个选项括在单引号或双引号中，在选项中包含空白字符。任何字符（包括反斜杠）都可以通过在要包含的字符前加反斜杠来包含。`file` 本身可以包含额外的 `@file` 选项；任何此类选项都会被递归处理。
