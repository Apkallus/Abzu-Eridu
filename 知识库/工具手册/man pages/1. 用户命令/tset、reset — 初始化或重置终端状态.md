# `tset`、`reset` — 初始化或重置终端状态

## 概要

```sh
tset [-IQVcqrsw] [-] [-e ch] [-i ch] [-k ch] [-m mapping]
     [terminal-type]
reset [-IQVcqrsw] [-] [-e ch] [-i ch] [-k ch] [-m mapping]
      [terminal-type]
```

## 描述

### `tset` — 初始化

此程序初始化终端。

首先，`tset` 获取你所用终端的当前终端模式设置。它通过依次测试以下各项来获得终端设置：

- 标准错误，
- 标准输出，
- 标准输入，以及
- 最终是 `/dev/tty`。

获取这些设置后，`tset` 会记住在更新设置时应使用哪个文件描述符。

接下来，`tset` 确定你正在使用的终端类型。该确定过程如下，使用找到的第一个终端类型。

1. 命令行中指定的 `terminal` 参数。
2. `TERM` 环境变量的值。
3. （仅 BSD 系统。）`/etc/ttys` 文件中与标准错误输出设备关联的终端类型。（在 System V 主机和使用该约定的系统上，`getty(8)` 通过根据 `/etc/inittab` 传递给它的类型设置 `TERM` 来完成此工作。）
4. 默认终端类型 `unknown` 不适合 `curses` 应用程序。

如果终端类型未在命令行中指定，则随后应用 `-m` 选项映射；请参见“终端类型映射”小节。然后，如果终端类型以问号（`?`）开头，会提示用户确认终端类型。空响应表示确认该类型，或者可以输入另一类型来指定新类型。一旦确定了终端类型，就会检索该终端的终端描述。如果未找到该类型的终端描述，会提示用户输入另一终端类型。

一旦检索到终端描述，

- 如果启用了 `-w` 选项，`tset` 可能会更新终端的窗口大小。

  如果无法从操作系统获得窗口大小，但终端描述（或环境，例如 `LINES` 和 `COLUMNS` 变量指定了此信息）提供了该信息，则使用它来设置操作系统所认为的窗口大小。

- 如果启用了 `-c` 选项，则会设置退格、中断和行删除字符（以及许多其他设置）。

- 除非启用了 `-I` 选项，否则会将终端和制表符 `initialization` 字符串发送到标准错误输出；并且，如果终端设备看起来不是伪终端（终端模拟器程序可能使用的类型），`tset` 会等待一秒钟，以防发出了硬件复位。

- 最后，如果擦除、中断和行删除字符已更改，或未设置为其默认值，则将其值显示到标准错误输出。

### `reset` — 重新初始化

当以 `reset` 调用时，`tset` 将终端模式设置为“sane”值：

- 设置规范（“cooked”）和回显模式，
- 关闭 cbreak 和 raw 模式，
- 开启换行转换，以及
- 将特殊输入字符重置为其默认值，

然后再执行上述终端初始化。此外，它不使用终端 `initialization` 字符串，而是使用终端 `reset` 字符串。

`reset` 命令在程序死亡后使终端处于异常状态时很有用：

- 你可能需要键入

    ```
    <LF>reset<LF>
    ```

    （换行字符通常是 control-J）才能使终端工作，因为在异常状态下回车可能不再起作用。

- 另外，终端通常不会回显该命令。

### 设置环境

将终端类型以及关于终端能力的信息输入到 shell 的环境中通常是可取的。这通过 `-s` 选项完成。

当指定 `-s` 选项时，用于将信息输入到 shell 环境的命令会写入标准输出。如果 `SHELL` 环境变量以 `csh` 结尾，则命令用于 `csh(1)`；否则用于 `sh(1)`。`csh` 命令会设置并取消设置 shell 变量 `noglob`，最终使其处于未设置状态。`.login` 或 `.profile` 文件中的以下行将正确初始化环境：

```sh
eval `tset -s options ... `
```

### 终端类型映射

当终端未硬接线到系统（或当前系统信息不正确）时，从 `/etc/ttys` 文件或 `TERM` 环境变量推导出的终端类型通常是某种通用类型，例如 `network`、`dialup` 或 `unknown`。在启动脚本中使用 `tset` 时，通常需要提供关于此类端口上所用终端类型的信息。

`-m` 选项从某组条件映射到一种终端类型，也就是告诉 `tset`：“如果我在这个端口上以特定速度运行，就猜测我在那种终端上”。

`-m` 选项的参数由可选的端口类型、可选的运算符、可选的波特率规格、可选的冒号（`:`）字符以及终端类型组成。端口类型是一个字符串（由运算符或冒号字符分隔）。运算符可以是 `>`、`<`、`@` 和 `!` 的任意组合；`>` 表示大于，`<` 表示小于，`@` 表示等于，`!` 反转测试的含义。波特率以数字指定，并与标准错误输出（应为控制终端）的速度进行比较。终端类型是一个字符串。

如果终端类型未在命令行中指定，则对终端类型应用 `-m` 映射。如果端口类型和波特率与映射匹配，则映射中指定的终端类型将替换当前类型。如果指定了多个映射，则使用第一个适用的映射。

例如，考虑以下映射：`dialup>9600:vt100`。端口类型是 `dialup`，运算符是 `>`，波特率规格是 `9600`，终端类型是 `vt100`。此映射的结果是：如果终端类型是 `dialup`，且波特率大于 9600 波特，则使用终端类型 `vt100`。

如果未指定波特率，则终端类型将匹配任何波特率。如果未指定端口类型，则终端类型将匹配任何端口类型。例如，`-m dialup:vt100 -m :?xterm` 会导致任何 `dialup` 端口（无论波特率如何）匹配终端类型 `vt100`，而任何非 `dialup` 端口类型匹配终端类型 `?xterm`。注意，由于前导问号，用户将在默认端口上被询问他们是否确实在使用 `xterm` 终端。

`-m` 选项参数中不允许出现空白字符。另外，为避免元字符问题，建议将整个 `-m` 选项参数放在单引号中，并且 `csh` 用户应在任何感叹号（`!`）前插入反斜杠（`\`）。

## 选项

选项如下：

- `-c`  
    设置控制字符和模式。

- `-e ch`  
    将擦除字符设置为 `ch`。

- `-I`  
    不向终端发送终端或制表符初始化字符串。

- `-i ch`  
    将中断字符设置为 `ch`。

- `-k ch`  
    将行删除字符设置为 `ch`。

- `-m mapping`  
    指定从端口类型到终端的映射；请参见“终端类型映射”小节。

- `-Q`  
    不显示擦除、中断和行删除字符的任何值。通常 `tset` 会显示与系统默认值不同的控制字符的值。

- `-q`  
    终端类型显示到标准输出，并且终端不以任何方式初始化。选项 `-` 本身等价，但已过时。

- `-r`  
    将终端类型打印到标准错误输出。

- `-s`  
    将用于初始化环境变量 `TERM` 的 shell 命令序列打印到标准输出；请参见“设置环境”小节。

- `-V`  
    报告此程序中使用的 `ncurses` 版本，然后退出。

- `-w`  
    调整窗口大小，以匹配通过 `setupterm(3X)` 推导出的大小。通常这没有效果，除非 `setupterm` 无法检测窗口大小。

`-e`、`-i` 和 `-k` 选项的参数可以输入为实际字符，也可以使用“hat”表示法，即 control-h 可以指定为 `^H` 或 `^h`。

如果既未给出 `-c` 也未给出 `-w`，则假定两者均已给出。

## 环境

`tset` 命令使用以下环境变量：

- `SHELL`  
    告诉 `tset` 是使用 `sh(1)` 还是 `csh(1)` 语法初始化 `TERM`。

- `TERM`  
    表示你的终端类型。每种终端类型都是不同的，尽管许多类型相似。

- `TERMCAP`  
    可能表示 termcap 数据库的位置。如果它不是绝对路径名（例如以 `/` 开头），`tset` 会在查找终端描述之前从环境中移除该变量。

## 文件

- `/etc/ttys`  
    系统端口名到终端类型映射数据库（仅 BSD 版本）。

- `terminfo`  
    编译后的终端描述数据库目录。

## 可移植性

IEEE Std 1003.1/The Open Group Base Specifications Issue 7（POSIX.1-2008）和 X/Open Curses Issue 7 均未记录 `tset` 或 `reset`。

AT&T `tput` 工具（AIX、HP-UX、Solaris）整合了终端模式操作以及基于 termcap 的特性（例如从 BSD（4.1c）的 `tset` 重置制表位），大概意图是让 `tset` 过时。然而，这些系统仍然各自提供 `tset`。事实上，常用的 `reset` 工具始终是 `tset` 的别名。

`tset` 工具提供对 BSD 环境的向后兼容；在大多数现代 Unix 上，`/etc/inittab` 和 `getty(8)` 可以适当地为每个拨号线路设置 `TERM`，从而消除了 `tset` 最重要的用途。此实现的行为类似于 `4.4BSD` 的 `tset`，但有几个例外，我们现在来考虑。

少数选项不同，因为基于 terminfo 的 `ncurses` 不再支持 `TERMCAP` 变量：

- BSD `tset` 的 `-S` 选项不再工作；它会将错误消息打印到标准错误并终止。
- `-s` 选项仅设置 `TERM`，不设置 `TERMCAP`。

有一个未记录的 `4.4BSD` 特性：通过名为 `TSET`（或以任何其他以大写字母开头的名称）的链接调用 `tset` 会将终端设置为仅使用大写。此特性已被省略。

`-A`、`-E`、`-h`、`-u` 和 `-v` 选项在 `4.4BSD` 中已从 `tset` 工具中删除。它们在 `4.3BSD` 中均未被记录，且充其量只有有限的用途。`-a`、`-d` 和 `-p` 选项同样未被记录或没有用处，但因其似乎被广泛使用而保留。强烈建议将这三个选项的任何用法改为使用 `-m` 选项。因此，`-a`、`-d` 和 `-p` 选项在上面的用法摘要中被省略。

非常古老的系统（例如 `3BSD`）使用了不同的终端驱动程序，该驱动程序在 1980 年代初的 `4BSD` 中被替换。为适应这些较老的系统，`4BSD` 的 `tset` 提供了 `-n` 选项以指定应使用新的终端驱动程序。此实现不提供该选择。

仍然允许指定 `-e`、`-i` 和 `-k` 选项而不带参数，尽管强烈建议将此类用法修正为显式指定字符。

自 `4.4BSD` 起，以 `reset` 执行 `tset` 不再隐含 `-Q` 选项。另外，在某些历史实现中，`-` 选项与 `terminal` 参数之间的交互已被移除。

`-c` 和 `-w` 选项在早期实现中未出现。然而，`4.4BSD` 中提供了不同的窗口大小更改特性。

- 在 `4.4BSD` 中，如果 `tset` 无法从操作系统获得窗口大小，则使用 termcap 描述中的窗口大小来设置窗口大小。
- 在 `ncurses` 中，`tset` 使用 `setupterm(3X)` 获取窗口大小，该大小可能来自操作系统、`LINES` 和 `COLUMNS` 环境变量或终端描述。

从终端的类型描述获取窗口大小在两种实现中都很常见，但被认为已过时。其唯一实际用途是用于硬件终端。通常，只有在从操作系统获取值时遇到问题（且 `setupterm` 仍会失败）时，窗口大小才会保持未初始化状态。因此，`LINES` 和 `COLUMNS` 环境变量可能有助于解决窗口大小问题，但缺点是如果窗口被调整大小，必须重新计算并重新分配它们的值。`xterm(1)` 随附的 `resize(1)` 程序可协助此活动。

## 历史

Kurt Shoens 编写的 `reset` 命令出现在 `1BSD`（1978 年 3 月）中。它将 `erase` 和 `kill` 字符分别设置为 `^H`（退格）和 `@`。Mark Horton 在 `3BSD`（1979 年 10 月）中改进了此 `reset`，添加了 `intr`、`quit`、`start`/`stop` 和 `eof` 字符，并更改了程序以避免修改任何用户设置。该版本的 `reset` 不使用 `termcap`。

Eric Allman 为 `1BSD` 编写了一个独立的 `tset` 命令，使用名为 `ttycap` 的 `termcap` 前身。Allman 在源代码中的注释表明他于 1977 年 10 月开始工作，并在接下来的几年中继续开发。到 1979 年底，它已迁移到 `termcap` 并处理 `TERMCAP` 变量。后来的注释表明，`tset` 在 1980 年 9 月被修改为在以 `reset` 调用时使用从 `3BSD` “reset”程序复制的逻辑。此版本出现在 `4.1cBSD`（1982 年末）中。其他开发者（如 Keith Bostic 和 Jim Bloom）继续修改 `tset`，直到 `4.4BSD` 于 1993 年发布。

`ncurses` 实现由 Eric S. Raymond ⟨esr@snark.thyrsus.com⟩ 从 `4.4BSD` 源代码稍作调整以使用 `terminfo` API。
