## 名称

`ar` - 创建、修改和从归档中提取

## 概要

```sh
ar [-X32_64] [-]p[mod] [--plugin name] [--target bfdname]
[--output dirname] [--record-libdeps libdeps] [--thin] [relpos]
[count] archive [member...]
```

## 描述

GNU `ar` 程序创建、修改和从归档中提取。*归档*是单个文件，它以某种结构保存其他文件的集合，使得可以取回原始的单个文件（称为归档的*成员*）。

原始文件的内容、模式（权限）、时间戳、所有者和组都保留在归档中，并可在提取时恢复。

GNU `ar` 可以维护成员名称可为任意长度的归档；但是，取决于系统上 `ar` 的配置方式，为了与使用其他工具维护的归档格式兼容，可能会对成员名称长度施加限制。如果存在限制，通常是 15 个字符（`a.out` 相关格式的典型值）或 16 个字符（`coff` 相关格式的典型值）。

`ar` 被视为二进制实用程序，因为此类归档最常用作保存常用子例程的*库*。由于库通常依赖其他库，当指定 `--record-libdeps` 选项时，`ar` 还可以记录库的依赖关系。

当你指定修饰符 `s` 时，`ar` 会为归档中可重定位对象模块定义的符号创建索引。一旦创建，每当 `ar` 更改其内容时（`q` 更新操作除外），该索引都会在归档中更新。带有此类索引的归档可加快链接到库的速度，并允许库中的例程互相调用，而无需考虑它们在归档中的位置。

你可以使用 `nm -s` 或 `nm --print-armap` 列出此索引表。如果归档缺少该表，可以使用 `ar` 的另一种形式 `ranlib` 仅添加该表。

GNU `ar` 可以选择创建*薄*归档，其中包含符号索引和对归档成员文件原始副本的引用。这对于在本地构建树中构建库很有用，因为可重定位对象预期保持可用，而复制每个对象的内容只会浪费时间和空间。

归档可以是*薄*归档，也可以是普通归档。它不能同时是两者。归档一旦创建，其格式就无法更改，除非先删除它，然后在原位置创建新归档。

薄归档也是*扁平化*的，因此将一个薄归档添加到另一个薄归档不会像普通归档那样嵌套。相反，第一个归档的元素会逐个添加到第二个归档中。

归档元素的路径相对于归档本身存储。

GNU `ar` 设计为与两种不同的设施兼容。你可以使用命令行选项控制其活动，就像 Unix 系统上各种 `ar` 变体那样；或者，如果指定单个命令行选项 `-M`，则可以通过标准输入提供的脚本控制它，就像 MRI“librarian”程序那样。

## 选项

GNU `ar` 允许在第一个命令行参数内以任意顺序混合操作码 `p` 和修饰符标志 `mod`。

如果愿意，可以用短横线开始第一个命令行参数。

`p` 操作码字母指定要执行的操作；它可以是以下任意一个，但只能指定其中一个：

- `d`  
    *删除*归档中的模块。将要删除的模块名称指定为 `member...`；如果未指定要删除的文件，则归档不受影响。

    如果指定 `v` 修饰符，`ar` 会在删除每个模块时列出它。

- `m`  
    使用此操作在归档中*移动*成员。

    如果符号在多个成员中定义，归档中成员的顺序可能会影响使用该库链接程序的方式。

    如果 `m` 没有使用修饰符，你在 `member` 参数中指定的任何成员都会被移动到归档的*末尾*；你可以使用 `a`、`b` 或 `i` 修饰符将它们移动到指定位置。

- `p`  
    将归档的指定成员*打印*到标准输出文件。如果指定 `v` 修饰符，则在将其内容复制到标准输出之前显示成员名称。

    如果未指定 `member` 参数，则打印归档中的所有文件。

- `q`  
    *快速追加*；历史上，将文件 `member...` 添加到 `archive` 末尾，而不检查替换。

    修饰符 `a`、`b` 和 `i` *不*影响此操作；新成员始终放在归档末尾。

    修饰符 `v` 使 `ar` 在追加每个文件时列出它。

    由于此操作的重点是速度，`ar` 的实现可以选择在存在符号表时不更新归档的符号表。然而，太多不同系统假定符号表始终是最新的，因此 GNU `ar` 即使进行快速追加也会重建该表。

    注意：GNU `ar` 将命令 `qs` 视为 `r` 的同义词——替换归档中已存在的文件，并在末尾追加新文件。

- `r`  
    将文件 `member...` 插入 `archive`（*替换*）。此操作与 `q` 的不同之处在于，如果任何先前存在的成员名称与要添加的名称匹配，则删除这些成员。

    如果 `member...` 中指定的某个文件不存在，`ar` 会显示错误消息，并且不打扰归档中与该名称匹配的任何现有成员。

    默认情况下，新成员添加到文件末尾；但你可以使用 `a`、`b` 或 `i` 修饰符之一请求相对于某个现有成员放置。

    与此操作一起使用的修饰符 `v` 会为插入的每个文件输出一行，并带有字母 `a` 或 `r` 之一，以指示文件是追加的（未删除旧成员）还是替换的。

- `s`  
    向归档添加索引，或者如果索引已存在则更新它。注意：此命令是“只能有一个命令字母”规则的例外，因为它既可以用作命令，也可以用作修饰符。无论哪种情况，它都做同样的事情。

- `t`  
    显示列出 `archive` 内容的*表格*，或列出 `member...` 中列出且存在于归档中的文件。通常只显示成员名称，但如果指定修饰符 `O`，则还会显示成员的相应偏移量。最后，为了查看模式（权限）、时间戳、所有者、组和大小，应包含 `v` 修饰符。

    如果未指定 `member`，则列出归档中的所有文件。

    如果归档中（例如 `b.a`）有多个同名文件（例如 `fie`），`ar t b.a fie` 只列出第一个实例；要查看所有实例，必须请求完整列表——在我们的示例中，即 `ar t b.a`。

- `x`  
    从归档中*提取*成员（名为 `member`）。你可以与此操作一起使用 `v` 修饰符，以请求 `ar` 在提取每个名称时列出它。

    如果未指定 `member`，则提取归档中的所有文件。

    无法从薄归档中提取文件，并且从使用 `P` 创建的归档中提取文件存在限制：路径不能是绝对路径，不能包含 `..`，并且路径中的任何子目录都必须存在。如果希望避免这些限制，则使用 `--output` 选项指定输出目录。

许多修饰符（`mod`）可以紧跟在 `p` 操作码字母之后，以指定操作行为的变体：

- `a`  
    在归档的现有成员*之后*添加新文件。如果使用修饰符 `a`，则必须在 `archive` 规范之前将现有归档成员的名称作为 `relpos` 参数给出。

- `b`  
    在归档的现有成员*之前*添加新文件。如果使用修饰符 `b`，则必须在 `archive` 规范之前将现有归档成员的名称作为 `relpos` 参数给出。（与 `i` 相同）。

- `c`  
    *创建*归档。当请求更新时，如果指定的 `archive` 不存在，它总是会被创建。但除非你通过使用此修饰符事先指定期望创建它，否则会发出警告。

- `D`  
    以*确定性*模式操作。添加文件和归档索引时，对 UID、GID、时间戳使用零，并对所有文件使用一致的文件模式。使用此选项时，如果 `ar` 使用相同选项和相同输入文件，则无论输入文件的所有者、组、文件模式或修改时间如何，多次运行都会创建相同的输出文件。

    如果 *binutils* 配置了 `--enable-deterministic-archives`，则此模式默认开启。可以使用下面的 `U` 修饰符禁用。

- `f`  
    截断归档中的名称。GNU `ar` 通常允许任意长度的文件名。这会导致它创建的归档与某些系统上的本机 `ar` 程序不兼容。如果这是一个问题，可以使用 `f` 修饰符在将文件名放入归档时截断它们。

- `i`  
    在归档的现有成员*之前*插入新文件。如果使用修饰符 `i`，则必须在 `archive` 规范之前将现有归档成员的名称作为 `relpos` 参数给出。（与 `b` 相同）。

- `l`  
    指定此库的依赖关系。依赖关系必须紧跟在选项字符之后，必须使用与链接器命令行相同的语法，并且必须在单个参数中指定。也就是说，如果需要多个项，必须引用它们以形成单个命令行参数。例如 `l "-L/usr/local/lib -lmydep1 -lmydep2"`。

- `N`  
    使用 `count` 参数。当归档中有多个同名条目时使用。提取或删除归档中给定名称的第 `count` 个实例。

- `o`  
    提取成员时保留成员的*原始*日期。如果未指定此修饰符，则从归档中提取的文件会以提取时间作为时间戳。

- `O`  
    显示归档内的成员偏移量。与 `t` 选项一起使用。

- `P`  
    在归档中匹配或存储名称时使用完整路径名。使用完整路径名创建的归档不符合 POSIX，因此可能无法与最新 GNU 工具以外的工具一起使用。在不使用 `P` 的情况下用 GNU `ar` 修改此类归档将移除完整路径名，除非归档是薄归档。注意：将文件添加到薄归档时，`P` 可能很有用，因为不带 `P` 的 `r` 在选择要替换的元素时会忽略路径。因此

    ```sh
    ar rcST archive.a subdir/file1 subdir/file2 file1
    ```

    将导致第一个 `subdir/file1` 被当前目录中的 `file1` 替换。添加 `P` 将阻止此替换。

- `s`  
    将对象文件索引写入归档，或更新现有索引，即使对归档没有做其他更改。你可以将此修饰符标志与任何操作一起使用，也可以单独使用。对归档运行 `ar s` 等同于对其运行 `ranlib`。

- `S`  
    不生成归档符号表。这可以在分几步构建大型库时加快速度。生成的归档不能与链接器一起使用。为了构建符号表，必须在最后一次执行 `ar` 时省略 `S` 修饰符，或者必须对归档运行 `ranlib`。

- `T`  
    `--thin` 的已弃用别名。不建议使用 `T`，因为在许多 `ar` 实现中，`T` 具有不同的含义，如 X/Open System Interface 所规定。

- `u`  
    通常，`ar r`... 会将列出的所有文件插入归档。如果你希望*只*插入所列文件中比同名现有成员更新的文件，请使用此修饰符。`u` 修饰符仅允许用于操作 `r`（替换）。特别是，不允许组合 `qu`，因为检查时间戳会失去操作 `q` 的任何速度优势。

    注意：如果归档是以确定性方式创建的，例如通过使用 `D` 修饰符，那么替换将始终发生，`u` 修饰符将无效。

- `U`  
    *不*以*确定性*模式操作。这与上面的 `D` 修饰符相反：添加的文件和归档索引将获得其实际的 UID、GID、时间戳和文件模式值。

    除非 *binutils* 配置了 `--enable-deterministic-archives`，否则这是默认值。

- `v`  
    此修饰符请求操作的*详细*版本。当附加修饰符 `v` 时，许多操作会显示附加信息，例如处理的文件名。

- `V`  
    此修饰符显示 `ar` 的版本号。

`ar` 程序还支持一些既不是修饰符也不是操作的命令行选项，但它们确实以特定方式改变其行为：

- `--help`  
    显示 `ar` 支持的命令行选项列表，然后退出。

- `--version`  
    显示 `ar` 的版本信息，然后退出。

- `-X32_64`  
    `ar` 忽略拼写为 `-X32_64` 的初始选项，以便与 AIX 兼容。此选项产生的行为是 GNU `ar` 的默认行为。`ar` 不支持任何其他 `-X` 选项；特别是，它不支持 `-X32`，而这是 AIX `ar` 的默认值。

- `--plugin` `name`  
    可选命令行开关 `--plugin` `name` 使 `ar` 加载名为 `name` 的插件，该插件增加对更多文件格式的支持，包括带有链接时优化信息的对象文件。

    仅当工具链在构建时启用了插件支持，此选项才可用。

    如果未提供 `--plugin`，但已启用插件支持，则 `ar` 会按字母顺序遍历 `${libdir}/bfd-plugins` 中的文件，并使用第一个声称支持相关对象的插件。

    请注意，此插件搜索目录*不是* `ld` 的 `-plugin` 选项所使用的目录。为了使 `ar` 使用链接器插件，必须将其复制到 `${libdir}/bfd-plugins` 目录中。对于基于 GCC 的编译，链接器插件称为 `liblto_plugin.so.0.0.0`。对于基于 Clang 的编译，它称为 `LLVMgold.so`。GCC 插件始终向后兼容早期版本，因此仅复制最新的一个即可。

- `--target` `target`  
    可选命令行开关 `--target` `bfdname` 指定归档成员采用的目标代码格式与系统默认格式不同。参见

- `--output` `dirname`  
    `--output` 选项可用于指定一个目录路径，归档成员应提取到该目录中。如果未指定此选项，则使用当前目录。

    注意：尽管此选项的存在确实意味着 `x` 提取操作，但该选项仍必须包含在命令行中。

- `--record-libdeps` `libdeps`  
    `--record-libdeps` 选项与 `l` 修饰符相同，只是以长格式处理。

- `--thin`  
    将指定的 `archive` 设为*薄*归档。如果它已存在并且是常规归档，则现有成员必须存在于与 `archive` 相同的目录中。

- `@file`  
    从 `file` 读取命令行选项。读取的选项会插入到原始 `@file` 选项的位置。如果 `file` 不存在或无法读取，则该选项将按字面处理，并且不会被移除。

    `file` 中的选项由空白分隔。可以通过将整个选项用单引号或双引号括起来，在选项中包含空白字符。可以通过在要包含的字符前加反斜杠来包含任何字符（包括反斜杠）。`file` 本身可以包含额外的 `@file` 选项；任何此类选项都将被递归处理。
