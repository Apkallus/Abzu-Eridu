# `sh` — shell，标准命令语言解释器

## 概要

```sh
sh [-abCefhimnuvx] [-o option]... [+abCefhimnuvx] [+o option]...
    [command_file [argument...]]

sh -c [-abCefhimnuvx] [-o option]... [+abCefhimnuvx] [+o option]...
    command_string [command_name [argument...]]

sh -s [-abCefhimnuvx] [-o option]... [+abCefhimnuvx] [+o option]...
    [argument...]
```

## 描述

`sh` 实用程序是一个命令语言解释器，应执行从命令行字符串、标准输入或指定文件读取的命令。应用程序应确保要执行的命令以第 2 章《Shell 命令语言》中描述的语言表达。

路径名展开不应因文件大小而失败。

Shell 输入和输出重定向具有在打开文件描述中建立的、由实现定义的偏移最大值。

## 选项

`sh` 实用程序应符合 POSIX.1-2017 基础定义卷《第 12.2 节 实用程序语法准则》，并如下文所述扩展支持前导加号（`+`）。

`-a`、`-b`、`-C`、`-e`、`-f`、`-m`、`-n`、`-o` `option`、`-u`、`-v` 和 `-x` 选项作为 `set` 实用程序的一部分在第 2.14 节《特殊内置实用程序》中描述。源自 `set` 特殊内置的选项字母也应接受前导加号（`+`）而不是前导连字符（意味着本 POSIX.1-2017 卷中描述的选项的反向情况）。

应支持以下附加选项：

- `-c`  
    从 `command_string` 操作数读取命令。将特殊参数 0（参见第 2.5.2 节《特殊参数》）的值设置为 `command_name` 操作数的值，并按顺序从其余 `argument` 操作数设置位置参数（`$1`、`$2` 等）。不应从标准输入读取任何命令。

- `-i`  
    指定 shell 为*交互式*；见下文。如果调用进程的实际用户 ID 不等于有效用户 ID，或实际组 ID 不等于有效组 ID，实现可以将指定 `-i` 选项视为错误。

- `-s`  
    从标准输入读取命令。

如果没有操作数且未指定 `-c` 选项，则应假定 `-s` 选项。

如果存在 `-i` 选项，或者没有操作数且 shell 的标准输入和标准错误连接到终端，则 shell 被视为*交互式*。

## 操作数

应支持以下操作数：

- `-`  
    单个连字符应被视为第一个操作数，然后被忽略。如果同时将 `-` 和 `--` 作为参数给出，或者如果其他操作数位于单个连字符之前，则结果未定义。

- `argument`  
    位置参数（`$1`、`$2` 等）应设置为 `argument`（如果有）。

- `command_file`  
    包含命令的文件的路径名。如果路径名包含一个或多个斜杠字符，实现尝试读取该文件；该文件不必可执行。如果路径名不包含斜杠字符：
    - 实现应尝试从当前工作目录读取该文件；该文件不必可执行。
    - 如果文件不在当前工作目录中，实现可以使用 `PATH` 的值执行可执行文件搜索，如第 2.9.1.1 节《命令搜索和执行》所述。

    特殊参数 0（参见第 2.5.2 节《特殊参数》）应设置为 `command_file` 的值。如果使用省略 `command_file` 的概要形式调用 `sh`，则特殊参数 0 应设置为从父进程传递给 `sh` 的第一个参数的值（例如，对于 C 程序为 `argv[0]`），这通常是用于执行 `sh` 实用程序的路径名。

- `command_name`  
    在执行 `command_string` 中的命令时分配给特殊参数 0 的字符串。如果未指定 `command_name`，则特殊参数 0 应设置为从父进程传递给 `sh` 的第一个参数的值（例如，对于 C 程序为 `argv[0]`），这通常是用于执行 `sh` 实用程序的路径名。

- `command_string`  
    应由 shell 解释为一个或多个命令的字符串，如同该字符串是 POSIX.1-2017 系统接口卷中定义的 `system()` 函数的参数。如果 `command_string` 操作数为空字符串，则 `sh` 应以零退出状态退出。

## 标准输入

仅在以下条件之一为真时应使用标准输入：

- 指定了 `-s` 选项。
- 未指定 `-c` 选项且未指定操作数。
- 脚本执行一个或多个需要从标准输入获取输入的命令（例如不重定向其输入的 `read` 命令）。

参见“输入文件”部分。

当 shell 使用标准输入并且它调用也使用标准输入的命令时，shell 应确保标准输入文件指针在命令开始执行时直接指向 shell 已读取的命令之后。它不应以这样的方式预读：使被调用命令打算读取的任何字符被 shell 消耗（无论 shell 是否解释它们），或者使被调用命令未读取的字符不被 shell 看到。当期望读取标准输入的命令由交互式 shell 异步启动时，字符是由命令读取还是由 shell 解释未指定。

如果 `sh` 的标准输入是 FIFO 或终端设备并设置为非阻塞读取，则 `sh` 应在标准输入上启用阻塞读取。这在命令完成后应保持有效。

## 输入文件

输入文件应为文本文件，但行长应不受限制。如果输入文件仅由零个或多个空行和注释组成，则 `sh` 应以零退出状态退出。

## 环境变量

以下环境变量应影响 `sh` 的执行：

- `ENV`  
    仅当调用交互式 shell 时，此变量应由 shell 进行参数展开（参见第 2.6.2 节《参数展开》），结果值应用作包含要在当前环境中执行的 shell 命令的文件的路径名。该文件不必可执行。如果 `ENV` 的展开值不是绝对路径名，则结果未指定。如果进程的实际和有效用户 ID 或实际和有效组 ID 不同，则应忽略 `ENV`。

- `FCEDIT`  
    当由 shell 展开时，此变量应确定 `-e` `editor` 选项的 `editor` 选项参数的默认值。如果 `FCEDIT` 为空或未设置，则应使用 `ed` 作为编辑器。

- `HISTFILE`  
    确定命名命令历史文件的路径名。如果未设置 `HISTFILE` 变量，shell 可以尝试在 `HOME` 环境变量引用的目录中访问或创建文件 `.sh_history`。如果 shell 无法获得对历史文件的读写访问权限或创建它，则应使用允许历史正常操作的未指定机制。（在本节中，对历史“文件”的引用应理解为在这种情况下指此未指定机制。）实现可以选择仅在初始化历史文件时访问此变量；此初始化应在 `fc` 或 `sh` 第一次尝试从文件检索条目或向文件添加条目时发生，这些操作由用户发出的命令、`ENV` 变量命名的文件或实现定义的系统启动文件引起。实现可以选择对未设置 `HISTFILE` 的具有适当特权的用户禁用历史列表机制；发生这种情况的具体情况由实现定义。如果多个 shell 实例使用同一历史文件，则这些 shell 对历史文件的更新如何交互未指定。当从历史文件删除条目时，应按最旧优先删除。历史文件条目何时从历史文件中物理移除未指定。

- `HISTSIZE`  
    确定表示可访问的先前命令数量限制的十进制数。如果未设置此变量，则应使用大于或等于 128 的未指定默认值。历史列表中的最大命令数未指定，但应至少为 128。实现可以选择仅在初始化历史文件时访问此变量，如 `HISTFILE` 下所述。因此，在历史文件初始化后对 `HISTSIZE` 所做的更改是否有效未指定。

- `HOME`  
    确定用户主目录的路径名。`HOME` 的内容用于波浪号展开，如第 2.6.1 节《波浪号展开》所述。

- `LANG`  
    为未设置或为空的国际化变量提供默认值。（关于用于确定区域类别值的国际化变量的优先级，参见 POSIX.1-2017 基础定义卷《第 8.2 节 国际化变量》。）

- `LC_ALL`  
    如果设置为非空字符串值，则覆盖所有其他国际化变量的值。

- `LC_COLLATE`  
    确定模式匹配中范围表达式、等价类和多字符整理元素的行为。

- `LC_CTYPE`  
    确定将文本数据字节序列解释为字符的区域设置（例如，参数和输入文件中的单字节与多字节字符），哪些字符定义为字母（字符类 `alpha`），以及模式匹配中字符类的行为。

- `LC_MESSAGES`  
    确定应用于影响写入标准错误的诊断消息格式和内容的区域设置。

- `MAIL`  
    确定用于 incoming mail 通知的用户邮箱文件路径名。如果设置了此变量，则当变量命名的文件被创建或其修改时间已更改时，shell 应通知用户。通知用户应通过在写入下一个主提示符字符串之前向标准错误写入未指定格式的字符串来完成。此类检查应仅在自上次此类检查后由 `MAILCHECK` 变量定义的间隔完成后执行。仅当设置了 `MAIL` 且未设置 `MAILPATH` 时才应通知用户。

- `MAILCHECK`  
    建立一个十进制整数值，指定 shell 应多久（以秒为单位）检查 `MAILPATH` 或 `MAIL` 变量指定的文件中的邮件到达。默认值应为 600 秒。如果设置为零，则 shell 应在发出每个主提示符之前检查。

- `MAILPATH`  
    提供由冒号字符分隔的路径名和可选消息列表。如果设置了此变量，则当变量命名的任何文件被创建或其任何修改时间更改时，shell 应通知用户。（关于邮件到达和用户通知的描述，参见前面 `MAIL` 条目。）每个路径名后可以跟 `%` 和一个字符串，该字符串应进行参数展开并在修改时间更改时写入标准错误。如果路径名中的 `%` 字符前面有反斜杠，则应在路径名中将其视为字面量 `%`。默认消息未指定。

    `MAILPATH` 环境变量优先于 `MAIL` 变量。

- `NLSPATH`  
    确定用于处理 `LC_MESSAGES` 的消息目录位置。

- `PATH`  
    建立按 POSIX.1-2017 基础定义卷《第 8 章 环境变量》所述格式化的字符串，用于影响命令解释；参见第 2.9.1.1 节《命令搜索和执行》。

- `PWD`  
    此变量应表示当前工作目录的绝对路径名。对此变量的赋值可能被忽略。

## 异步事件

`sh` 实用程序应对所有信号采取标准操作（参见第 1.4 节《实用程序描述默认值》），但以下例外。

如果 shell 是交互式的，命令行编辑期间收到的 SIGINT 信号应按扩展描述中所述处理，其他时间收到的 SIGINT 信号应被捕获但不执行任何操作。

如果 shell 是交互式的：

- 应忽略 SIGQUIT 和 SIGTERM 信号。
- 如果 `-m` 选项生效，应忽略 SIGTTIN、SIGTTOU 和 SIGTSTP 信号。
- 如果 `-m` 选项未生效，SIGTTIN、SIGTTOU 和 SIGTSTP 信号是被忽略、设置为默认操作还是被捕获未指定。如果它们被捕获，shell 应在信号捕获函数中将信号设置为默认操作并引发该信号（在采取任何适当步骤之后，例如恢复终端设置）。

标准操作以及上述针对交互式 shell 描述的操作可以通过使用 `trap` 特殊内置实用程序覆盖（参见“trap(1p)”和第 2.11 节《信号和错误处理》）。

## 标准输出

参见“标准错误”部分。

## 标准错误

除非另有说明（由任何被调用实用程序的描述或交互模式说明），标准错误应仅用于诊断消息。

## 输出文件

无。

## 扩展描述

参见第 2 章《Shell 命令语言》。扩展描述部分其余部分描述的功能应在支持用户可移植性实用程序选项的实现上提供（本节其余部分不再对此选项进一步遮蔽）。

### 命令历史列表

当 `sh` 实用程序交互使用时，它应在 `HISTFILE` 环境变量命名的文件中维护先前从终端输入的命令列表。此文件的类型、大小和内部格式未指定。如果文件访问权限允许，多个 `sh` 进程可以共享对文件的访问；参见 `HISTFILE` 环境变量的描述。

### 命令行编辑

当 `sh` 从终端交互使用时，当前命令和命令历史（参见“fc(1p)”）可以使用 `vi` 模式命令行编辑进行编辑。此模式使用下文描述的命令，类似于 `vi` 实用程序中描述的命令子集。实现可以提供对应于其他编辑实用程序的其他命令行编辑模式。

命令 `set -o vi` 应启用 `vi` 模式编辑并将 `sh` 置于 `vi` 插入模式（参见“命令行编辑（vi 模式）”）。此命令还应禁用实现可能提供的任何其他编辑模式。命令 `set +o vi` 禁用 `vi` 模式编辑。

某些块模式终端可能无法支持 shell 命令行编辑。如果终端无法提供任一编辑模式，则在此终端上使用 shell 时不必能够 `set -o vi`。

在以下各节中，字符 `erase`、`interrupt`、`kill` 和 `end-of-file` 是由 `stty` 实用程序设置的字符。

### 命令行编辑（vi 模式）

在 `vi` 编辑模式中，应有一条可区分的行，即编辑行。修改行的所有编辑操作都影响编辑行。编辑行始终是命令历史缓冲区中最新的行。

启用 `vi` 模式后，`sh` 可以在插入模式和命令模式之间切换。

在插入模式中，输入的字符应插入命令行，除非“vi 行编辑插入模式”中另有说明。进入 `sh` 后以及上一个命令终止后，`sh` 应处于插入模式。

输入转义字符应将 `sh` 切换到命令模式（参见“vi 行编辑命令模式”）。在命令模式中，输入的字符应调用已定义的操作、作为多字符操作的一部分使用，或被视为错误。未被识别为编辑命令一部分的字符应终止任何特定编辑命令并提醒终端。如果 `sh` 在命令模式中收到 SIGINT 信号（无论是通过输入 `interrupt` 字符还是其他方式生成），它应终止当前命令行的命令行编辑，在终端的下一行重新发出提示符，并重置命令历史（参见“fc(1p)”），使最近执行的命令成为前一个命令（即，被中断时正在编辑的命令不会重新进入历史）。

在以下各节中，短语“将光标移到单词开头”应表示“将光标移到当前单词的第一个字符”，短语“将光标移到单词末尾”应表示“将光标移到当前单词的最后一个字符”。短语“命令行开头”表示 shell 发出的提示符字符串末尾（或如果没有提示符字符串，则为终端行开头）与命令文本第一个字符之间的点。

### vi 行编辑插入模式

在插入模式中，输入的 any 字符应插入当前命令行，除非它来自以下集合。

##### `<newline>`

```text
<newline>
```

执行当前命令行。如果当前命令行非空，则此行应进入命令历史（参见“fc(1p)”）。

##### `erase`

```text
erase
```

删除当前光标位置之前的字符并将当前光标位置向后移动一个字符。在插入模式中，退格时应从屏幕和缓冲区中删除字符。

##### `interrupt`

```text
interrupt
```

如果 `sh` 在插入模式中收到 SIGINT 信号（无论是通过输入 `interrupt` 字符还是其他方式生成），它应以与中断命令模式所述相同的效果终止命令行编辑；参见“命令行编辑（vi 模式）”。

##### `kill`

```text
kill
```

清除输入行中的所有字符。

##### `<control>-V`

```text
<control>-V
```

插入下一个输入字符，即使该字符在其他情况下是特殊插入模式字符。

##### `<control>-W`

```text
<control>-W
```

从光标前一个字符删除到前一个单词边界。此情况下的单词边界是行开头或不属于当前区域设置的 `blank` 和 `punct` 字符分类的字符中更接近光标的位置。

##### `end-of-file`

```text
end-of-file
```

在 `sh` 中解释为输入结束。此解释应仅在输入行开头发生。如果 `end-of-file` 不在行开头输入，则结果未指定。

##### `<ESC>`

```text
<ESC>
```

将 `sh` 置于命令模式。

### vi 行编辑命令模式

在命令行编辑功能的命令模式中，命令字母之前不以 0 开头的十进制数字应被记住。某些命令使用这些十进制数字作为影响操作的计数。

术语 `motion command` 表示以下命令之一：

```text
<space>  0  b  F  l  W  ^  $  ;  E  f  T  w  |  ,  B  e  h  t
```

如果当前行不是编辑行，任何修改当前行的命令应使当前行的内容替换编辑行的内容，并且当前行应成为编辑行。此替换不能撤销（参见下面的 `u` 和 `U` 命令）。然后应对编辑行执行请求的修改。当当前行是编辑行时，应直接对编辑行进行修改。

任何前面有 `count` 的命令应采用计数（任何前导十进制数字的数值）。除非另有说明，此计数应使指定操作重复计数指定的次数。同样除非另有说明，超出范围的 `count` 被视为错误条件，应提醒终端，但光标位置和命令行均不应更改。

术语 `word` 和 `bigword` 按 `vi` 描述中定义使用。术语 `save buffer` 对应于 `vi` 中的术语 `unnamed buffer`。

在命令模式中应识别以下命令：

##### `<newline>`

```text
<newline>
```

执行当前命令行。如果当前命令行非空，则此行应进入命令历史（参见“fc(1p)”）。

##### `<control>-L`

```text
<control>-L
```

重绘当前命令行。将光标定位在重绘行上的同一位置。

##### `#`

```text
#
```

在当前命令行开头插入字符 `#`，并将结果编辑行视为注释。此行应进入命令历史；参见“fc(1p)”。

##### `=`

```text
=
```

显示当前命令行位置处 bigword 的可能 shell 单词展开（参见第 2.6 节《单词展开》）。

> **注意：** 这不会修改当前行的内容，因此不会使当前行成为编辑行。

这些展开应显示在后续终端行上。如果 bigword 不包含字符 `?`、`*` 或 `[`，则应隐式假定末尾有星号（`*`）。如果匹配任何目录，这些展开应附加 `/` 字符。展开后，应重绘该行，将光标重新定位到当前光标位置，并将 `sh` 置于命令模式。

##### `\`

```text
\
```

## 退出状态

应返回以下退出值：

- `0`  
    要执行的脚本仅由零个或多个空行或注释，或两者组成。

- `1-125`  
    非交互式 shell 检测到除未找到或不可执行的 `command_file` 之外的错误，包括但不限于语法、重定向或变量赋值错误。

- `126`  
    指定的 `command_file` 由于 `[ENOEXEC]` 错误而无法执行（参见第 2.9.1.1 节《命令搜索和执行》第 2 项）。

- `127`  
    非交互式 shell 无法找到指定的 `command_file`。

否则，shell 应返回其调用或尝试调用的最后一个命令的退出状态（另请参见第 2.14 节《特殊内置实用程序》中的 `exit` 实用程序）。

## 应用用法

标准输入和标准错误是确定未指定 `-i` 时 shell 是否交互的文件。例如：

```sh
sh > file
```

和：

```sh
sh 2> file
```

分别创建交互式和非交互式 shell。尽管两者都接受终端输入，但错误条件的结果不同，如第 2.8.1 节《Shell 错误的后果》所述；在第二个示例中，特殊内置实用程序遇到的重定向错误会中止 shell。

符合规范的应用程序必须保护其第一个操作数（如果它以加号开头），方法是在其前面加上表示选项结束的 `--` 参数。

应用程序应注意，shell 的标准 `PATH` 不能假定为 `/bin/sh` 或 `/usr/bin/sh`，应通过询问 `getconf PATH` 返回的 `PATH` 来确定，确保返回的路径名是绝对路径名而不是 shell 内置。

例如，要确定标准 `sh` 实用程序的位置：

```sh
command -v sh
```

在某些实现上，这可能返回：

```log
/usr/xpg4/bin/sh
```

此外，在支持可执行脚本（`#!` 构造）的系统上，建议使用可执行脚本的应用程序在安装时使用 `getconf PATH` 确定 shell 路径名，并相应地更新 `#!` 脚本（例如使用 `sed`）。例如：

```sh
#
# 安装时脚本，用于安装正确的 POSIX shell 路径名
#
# 获取要检查的路径列表
#
Sifs=$IFS
Sifs_set=${IFS+y}
IFS=:
set -- $(getconf PATH)
if [ "$Sifs_set" = y ]
then
    IFS=$Sifs
else
    unset IFS
fi
#
# 检查每个路径中是否有 'sh'
#
for i
do
    if [ -x "${i}"/sh ]
    then
        Pshell=${i}/sh
    fi
done
#
# 这是要更新的脚本列表。它们应采用 '${name}.source' 形式，
# 并将转换为 '${name}'。
# 每个脚本应以以下内容开头：
#
# #!INSTALLSHELLPATH
#
scripts="a b c"
#
# 转换每个脚本
#
for i in ${scripts}
do
    sed -e "s|INSTALLSHELLPATH|${Pshell}|" < ${i}.source > ${i}
done
```

## 示例

1. 从字符串执行 shell 命令：

    ```sh
    sh -c "cat myfile"
    ```

2. 从当前目录中的文件执行 shell 脚本：

    ```sh
    sh my_shell_cmds
    ```

## 原理

`sh` 实用程序和 `set` 特殊内置实用程序共享一组公共选项。

名称 `IFS` 最初是“Input Field Separators”的缩写；然而，这个名称具有误导性，因为 `IFS` 字符实际上用作字段终止符。在进入脚本时忽略 `IFS` 内容的理由（除了安全考虑之外）是帮助可能的未来 shell 编译器。允许从环境导入 `IFS` 会阻止许多原本可以通过脚本本身的数据流分析执行的优化。

标准输入部分中关于非阻塞读取的文本涉及 `sh` 的实例，该实例可能由 C 语言程序调用，其标准输入已使用 `O_NONBLOCK` 标志打开；参见 POSIX.1-2017 系统接口卷中的 `open()`。如果 shell 不重置此标志，它将立即终止，因为尚无可用输入数据，而这将被视为与文件结束相同。

与*受限 shell*（命令名 `rsh` 和 `-r` 选项）相关的选项被排除，因为标准开发者认为无法实现隐含的安全级别，并且他们不想引起虚假期望。

在支持 set-user-ID 脚本的系统上，一个历史后门是将脚本链接到名称 `-i`。当通过如下序列调用时：

```sh
sh -
```

或通过：

```sh
#! usr/bin/sh -
```

历史系统假定后面没有选项字母。因此，本 POSIX.1-2017 卷允许单个连字符标记选项结束，除了使用常规 `--` 参数之外，因为认为旧做法如此普遍。KornShell 采取了另一种方法，其中交互式 shell 的实际和有效用户/组 ID 必须匹配；本 POSIX.1-2017 卷特别允许此行为。

> **注意：** set-user-ID 脚本还有其他问题，这里描述的两种方法都无法解决。

历史文件的初始化过程可能依赖于系统启动文件，因为它们可能包含有效抢占用户对 `HISTFILE` 和 `HISTSIZE` 设置的命令。例如，函数定义命令会记录在历史文件中，除非设置了 `set -o nolog` 选项。如果系统管理员在 `ENV` 文件之前调用的某个系统启动文件中包含函数定义，则历史文件在用户有机会影响其特征之前就已初始化。在某些历史 shell 中，历史文件在 `ENV` 文件处理之后立即初始化。因此，在历史文件初始化后对 `HISTFILE` 所做的更改是否有效由实现定义。

各种 `MAIL` 相关消息的默认消息未指定，因为它们因实现而异。典型消息是：

```log
you have mail
```

或：

```log
you have new mail
```

命令行编辑的描述引用与 POSIX.1-2008 中相同的 shell 很重要，这样交互式用户也可以作为应用程序员，而不必处理其两个环境中的编程差异。同样重要的是指定实用程序名称 `sh`，因为这种显式实用程序名称在应用程序的历史实践中根深蒂固，无法更改。

曾考虑在尝试在不支持命令行编辑的终端上设置 `vi` 模式时强制发出诊断消息。然而，shell 了解所有终端类型并因此能够在所有情况下检测不适当终端并非历史做法。鼓励实现在此情况下尽可能提供诊断，而不是让用户处于编辑命令工作不正常的状态。

在早期提案中，包含了源自 KornShell 的 `emacs` 模式命令行编辑，即使 `emacs` 编辑器本身并未包含。`emacs` 支持者社区坚持不应标准化完整的 `emacs` 编辑器，因为他们担心试图标准化这个非常强大的环境会鼓励供应商发布严格符合标准的版本，而缺少社区所需的可扩展性。原始 `emacs` 程序的作者也表达了他希望省略该程序的愿望。此外，有许多历史系统不包含 `emacs`，或包含但不支持它，但很少有系统不包含和不支持 `vi`。shell `emacs` 命令行编辑模式最终被省略，因为很明显 KornShell 版本和 GNU 系统分发的编辑器在某些方面已经分歧。`emacs` 的作者要求删除 POSIX `emacs` 模式或使其具有大量未指定条件。尽管 KornShell 作者同意考虑更改以使 shell 保持一致，但标准开发者决定当时推迟规范。当时假设会在后续草案中就可接受的定义达成一致，但这并未发生，而且似乎没有动力这样做。无论如何，实现可以自由提供基于其用户最熟悉的编辑器确切模型的其他命令行编辑模式。

早期提案在 `vi 行编辑插入模式` 中有以下列表项：

- `\`  
    如果后面跟 `erase` 或 `kill` 字符，则该字符应插入输入行。否则，反斜杠本身应插入输入行。

然而，这实际上不是 `sh` 命令行编辑插入模式的功能，而是某些历史终端行驱动程序的功能。某些符合规范的实现当设置了 `stty` 的 `iexten` 标志时继续这样做。

在交互式 shell 中，忽略 SIGTERM，以便 `kill 0` 不会杀死 shell；捕获 SIGINT，以便 `wait` 可中断。如果 shell 在交互式且 `-m` 选项未生效时不忽略 SIGTTIN、SIGTTOU 和 SIGTSTP 信号，则如果它不是会话领导者，这些信号会挂起 shell。如果它是会话领导者，则按照 POSIX.1-2017 系统接口卷《第 2.4.3 节 信号操作》对孤儿进程组的要求，如果这些信号会停止进程，则丢弃它们。
