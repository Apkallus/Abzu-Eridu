# unzip(1) - Linux 手册页

## 名称

`unzip` - 列出、测试和提取 ZIP 归档中的压缩文件

## 概要

```sh
unzip [-Z] [-cflptTuvz[abjnoqsCDKLMUVWX$/:^]] file[.zip] [file(s) ...] [-x xfile(s) ...] [-d exdir]
```

## 描述

`unzip` 将列出、测试或提取 ZIP 归档中的文件，此类归档常见于 MS-DOS 系统。默认行为（不带选项）是将指定 ZIP 归档中的所有文件提取到当前目录（及其子目录）。配套程序 `zip`(1L) 创建 ZIP 归档；两个程序都与 PKWARE 为 MS-DOS 开发的 `PKZIP` 和 `PKUNZIP` 创建的归档兼容，但在许多情况下程序选项或默认行为不同。

## 参数

- `file[.zip]`  
    ZIP **归档**的路径。如果文件规范是通配符，则每个匹配文件按操作系统（或文件系统）确定的顺序处理。只有文件名可以是通配符；路径本身不能。通配符表达式类似于常用 Unix shell（`sh`、`ksh`、`csh`）支持的表达式，可以包含：
    
    - `*`  
        匹配 0 个或多个字符的序列
    - `?`  
        恰好匹配 1 个字符
    - `[...]`  
        匹配方括号内找到的任何单个字符；范围由起始字符、连字符和结束字符指定。如果左方括号后跟感叹号或脱字符（`!` 或 `^`），则方括号内的字符范围被取反（即，除方括号内字符之外的任何内容都被视为匹配）。要指定字面左方括号，必须使用三字符序列 `[[]`。
    
    （请务必对可能被操作系统解释或修改的任何字符加引号，尤其是在 Unix 和 VMS 下。）如果未找到匹配项，则假定该规范是字面文件名；如果仍然失败，则追加后缀 `.zip`。请注意，支持自解压 ZIP 文件，与任何其他 ZIP 归档一样；只需显式指定 `.exe` 后缀（如果有）。

- `[file(s)]`  
    可选的归档成员列表，用空格分隔，要处理。（使用定义了 `VMSCLI` 编译的 VMS 版本必须用逗号分隔文件。参见下面 **选项** 中的 `-v`。）可以使用正则表达式（通配符）匹配多个成员；参见上文。同样，请务必对会被操作系统展开或修改的表达式加引号。

- `[-x xfile(s)]`  
    可选的归档成员列表，要从处理中排除。由于通配符字符通常匹配（`/`）目录分隔符（例外参见选项 `-W`），此选项可用于排除子目录中的任何文件。例如，`unzip foo *.[ch] -x */*` 将提取主目录中的所有 C 源文件，但不提取任何子目录中的文件。不使用 `-x` 选项时，将提取 zipfile 内所有目录中的所有 C 源文件。

- `[-d exdir]`  
    可选的目标目录，用于提取文件。默认情况下，所有文件和子目录都在当前目录中重新创建；`-d` 选项允许提取到任意目录（始终假定有写入该目录的权限）。此选项不必出现在命令行末尾；它也可以出现在 zipfile 规范之前（与普通选项一起）、紧接 zipfile 规范之后，或在 `file(s)` 与 `-x` 选项之间。选项和目录可以连接在一起，之间没有任何空白，但请注意，这可能会抑制正常的 shell 行为。特别是，`-d ~`（波浪号）会被 Unix C shell 展开为用户主目录名，但 `-d~` 会被视为当前目录的字面子目录 `~`。

## 选项

请注意，为了支持过时硬件，`unzip` 的使用屏幕限制为 22 或 23 行，因此应仅视为基本 `unzip` 语法的提醒，而不是所有可能标志的详尽列表。详尽列表如下：

- `-Z`  
    `zipinfo`(1L) 模式。如果命令行上的第一个选项是 `-Z`，则其余选项被视为 `zipinfo`(1L) 选项。有关这些选项的说明，请参见相应手册页。

- `-A`  
    [OS/2, Unix DLL] 打印 DLL 编程接口（API）的扩展帮助。

- `-c`  
    将文件提取到 stdout/屏幕（“CRT”）。此选项类似于 `-p` 选项，但提取时会打印每个文件的名称，允许 `-a` 选项，并在适当时自动执行 ASCII-EBCDIC 转换。此选项未列在 `unzip` 使用屏幕中。

- `-f`  
    刷新现有文件，即仅提取磁盘上已存在且比磁盘副本更新的文件。默认情况下，`unzip` 在覆盖前会查询，但可以使用 `-o` 选项抑制查询。请注意，在许多操作系统下，必须正确设置 TZ（时区）环境变量，`-f` 和 `-u` 才能正常工作（在 Unix 下该变量通常自动设置）。原因有些微妙，但与 DOS 格式文件时间（始终为本地时间）和 Unix 格式时间（始终为 GMT/UTC）之间的差异以及比较两者的必要性有关。典型的 TZ 值是 `PST8PDT`（美国太平洋时间，自动调整夏令时或“夏季时间”）。

- `-l`  
    列出归档文件（短格式）。打印指定文件的名称、未压缩文件大小和修改日期时间，以及所有指定文件的总计。如果 UnZip 编译时定义了 `OS2_EAS`，`-l` 选项还会列出存储的 OS/2 扩展属性（EA）和 OS/2 访问控制列表（ACL）大小的列。此外，还会显示 zipfile 注释和单个文件注释（如果有）。如果文件是从单大小写文件系统（例如旧的 MS-DOS FAT 文件系统）归档的，并且给出了 `-L` 选项，则文件名转换为小写并加上脱字符（`^`）前缀。

- `-p`  
    将文件提取到管道（stdout）。除了文件数据外，不向 stdout 发送任何内容，并且文件始终以二进制格式提取，与存储时完全一样（无转换）。

- `-t`  
    测试归档文件。此选项在内存中提取每个指定文件，并将展开文件的 CRC（循环冗余校验，一种增强校验和）与原始文件存储的 CRC 值进行比较。

- `-T`  
    [大多数操作系统] 将**归档**的时间戳设置为每个归档中最新文件的时间戳。这对应于 `zip` 的 `-go` 选项，但可用于通配符 zipfile（例如 `unzip -T \*.zip`），并且快得多。

- `-u`  
    更新现有文件，并在需要时创建新文件。此选项执行与 `-f` 选项相同的功能，提取（带查询）比磁盘上同名文件更新的文件，此外还提取磁盘上尚不存在的文件。有关正确设置时区的信息，请参见上面的 `-f`。

- `-v`  
    列出归档文件（详细格式）或显示诊断版本信息。此选项已演变，现在既作为选项又作为修饰符。作为选项，它有两个目的：当指定 zipfile 且没有其他选项时，`-v` 详细列出归档文件，在基本 `-l` 信息中添加压缩方法、压缩大小、压缩比和 32 位 CRC。与大多数竞争实用程序不同，`unzip` 从压缩大小数字中移除加密条目的 12 个额外头字节。因此，压缩大小和压缩比数字与条目的加密状态无关，并显示正确的压缩性能。（zipfile 条目的加密压缩数据流的完整大小由更详细的 `zipinfo`(1L) 报告报告，请参见单独手册。）当未指定 zipfile 时（即完整命令只是 `unzip -v`），会打印诊断屏幕。除了带有发布日期和版本的正常标题外，`unzip` 还列出主 Info-ZIP ftp 站点以及在哪里可以找到其他 ftp 和非 ftp 站点列表；编译所针对的目标操作系统，以及（可能）编译所用的硬件、使用的编译器和版本以及编译日期；可能影响程序操作的任何特殊编译选项（另请参见下面的**解密**）；以及可能产生相同影响的任何存储在环境变量中的选项（参见下面的**环境选项**）。作为修饰符，它与其他选项（例如 `-t`）一起工作以产生更详细或调试输出；这尚未完全实现，但将在未来版本中实现。

- `-z`  
    仅显示归档注释。

## 修饰符

- `-a`  
    转换文本文件。通常所有文件都完全按照存储方式提取（作为“二进制”文件）。`-a` 选项使 `zip` 标识为文本文件的文件（在 `zipinfo` 列表中带有 `t` 标签而非 `b` 的文件）自动按文本提取，根据需要转换行尾、文件结束字符和字符集本身。（例如，Unix 文件使用换行符（LF）作为行尾（EOL），没有文件结束（EOF）标记；Macintosh 使用回车符（CR）作为 EOL；大多数 PC 操作系统使用 CR+LF 作为 EOL，并使用 control-Z 作为 EOF。此外，IBM 大型机和 Michigan Terminal System 使用 EBCDIC 而不是更常见的 ASCII 字符集，NT 支持 Unicode。）请注意，`zip` 对文本文件的识别绝非完美；某些“文本”文件实际上可能是二进制文件，反之亦然。因此，使用 `-a` 选项时，`unzip` 会为提取的每个文件打印 `[text]` 或 `[binary]` 作为视觉检查。`-aa` 选项强制将所有文件作为文本提取，而不管假定的文件类型。在 VMS 上，另请参见 `-S`。

- `-b`  
    [通用] 将所有文件视为二进制（无文本转换）。这是 `---a` 的快捷方式。

- `-b`  
    [Tandem] 在提取标记为“文本”的 Zip 条目时，强制创建文件代码类型 180（`C`）的文件。（在 Tandem 上，`-a` 默认启用，见上文）。

- `-b`  
    [VMS] 将二进制文件（参见上面的 `-a`）自动转换为固定长度、512 字节记录格式。加倍选项（`-bb`）强制所有文件以这种格式提取。当提取到标准输出（`-c` 或 `-p` 选项生效）时，二进制（`-b`）文件或所有（`-bb`）文件的文本记录分隔符的默认转换被禁用。

- `-B`  
    [当编译时定义了 `UNIXBACKUP`] 为每个被覆盖的文件保存备份副本。备份文件获得目标文件的名称，并附加波浪号以及可选的唯一序列号（最多 5 位数字）。当原始名称加波浪号的另一个文件已存在时，会应用序列号。与“全部覆盖”选项 `-o` 一起使用时，永远不会创建编号备份文件。在这种情况下，所有备份文件都命名为原始文件并附加波浪号，现有备份文件会被删除而不通知。此功能在许多位置类似于 `“emacs”(1)` 的默认行为。
    
    示例：`foo` 的旧副本被重命名为 `foo~`。
    
    警告：用户应意识到，`-B` 选项并不能在所有情况下防止现有数据丢失。例如，当 `unzip` 以全部覆盖模式运行时，现有的 `foo~` 文件会在 `unzip` 尝试将 `foo` 重命名为 `foo~` 之前被删除。当此重命名尝试失败时（由于文件锁、权限不足等），`foo~` 的提取被取消，但旧备份文件已经丢失。当编号备份文件的序列号范围耗尽时（99999，或 16 位系统为 65535），也会发生类似情况。在这种情况下，具有最大序列号的备份文件会被删除并替换为新备份版本，而不通知。

- `-C`  
    对从命令行提取选择模式列表中选择归档条目时使用不区分大小写的匹配。`unzip` 的理念是“你得到你所要求的”（这也是 `-L`/`-U` 更改的原因；参见下面相关选项）。由于某些文件系统完全区分大小写（尤其是 Unix 操作系统下的文件系统），并且 ZIP 归档和 `unzip` 本身都可跨平台移植，`unzip` 的默认行为是区分大小写地匹配通配符和字面文件名。也就是说，在命令行上指定 `makefile` 将**仅**匹配归档中的 `makefile`，而不是 `Makefile` 或 `MAKEFILE`（通配符规范类似）。由于这不符合许多其他操作系统/文件系统的行为（例如 OS/2 HPFS，它保留混合大小写但不区分大小写），因此可以使用 `-C` 选项强制所有文件名匹配不区分大小写。在上面的示例中，三个文件都会匹配 `makefile`（或 `make*` 等）。`-C` 选项影响普通文件列表和排除文件列表（xlist）中的文件规范。
    
    请注意，`-C` 选项既不影响**zipfile**的搜索，也不影响归档条目与提取路径上现有文件的匹配。在区分大小写的文件系统上，`unzip` 在提取条目 `foo` 时绝不会尝试覆盖文件 `FOO`！

- `-D`  
    跳过提取项的时间戳恢复。通常，`unzip` 尝试恢复 Zip 归档中提供的提取项的所有元信息（且不需要特权或构成安全风险）。通过指定 `-D`，告诉 `unzip` 抑制对从 Zip 归档条目显式创建的目录的时间戳恢复。此选项仅适用于支持为目录设置时间戳的移植版（目前为 ATheOS、BeOS、MacOS、OS/2、Unix、VMS、Win32；对于其他 `unzip` 移植版，`-D` 无效）。重复选项 `-DD` 强制抑制所有提取条目（文件和目录）的时间戳恢复。此选项会将所有提取条目的时间戳设置为当前时间。
    
    在 VMS 上，此选项的默认设置为 `-D`，以与 BACKUP 的行为保持一致：恢复文件时间戳，提取目录的时间戳保留为当前时间。要启用目录时间戳恢复，应指定否定选项 `--D`。在 VMS 上，选项 `-D` 禁用所有提取 Zip 归档项的时间戳恢复。（此处，命令行上的单个 `-D` 与默认 `-D` 结合，执行其他系统上显式 `-DD` 所做的工作。）

- `-E`  
    [仅 MacOS] 在恢复操作期间显示 MacOS 扩展字段的内容。

- `-F`  
    [仅 Acorn] 抑制从存储的文件名中移除 NFS 文件类型扩展名。

- `-F`  
    [支持带嵌入逗号的长文件名的非 Acorn 系统，且仅当编译时定义了 `ACORN_FTYPE_NFS`] 将 ACORN RISC OS 扩展字段块中的文件类型信息转换为 NFS 文件类型扩展名，并附加到提取文件的名称后。（当存储的文件名似乎已经附加了 NFS 文件类型扩展名时，将其替换为扩展字段中的信息。）

- `-i`  
    [仅 MacOS] 忽略存储在 MacOS 扩展字段中的文件名。相反，使用条目头通用部分中存储的最兼容文件名。

- `-j`  
    丢弃路径。不重新创建归档的目录结构；所有文件都放置在提取目录中（默认是当前目录）。

- `-J`  
    [仅 BeOS] 丢弃文件属性。不恢复文件的 BeOS 文件属性，仅恢复文件数据。

- `-J`  
    [仅 MacOS] 忽略 MacOS 扩展字段。跳过所有 Macintosh 特定信息。数据分支和资源分支作为单独文件恢复。

- `-K`  
    [仅 AtheOS、BeOS、Unix] 保留 SUID/SGID/Tacky 文件属性。没有此标志，出于安全原因会清除这些属性位。

- `-L`  
    将源自仅大写操作系统或文件系统的任何文件名转换为小写。（这是 5.11 之前版本中 `unzip` 的默认行为；新的默认行为与使用 `-U` 选项的旧行为相同，`-U` 现已过时，将在未来版本中移除。）取决于归档器，在单大小写文件系统（VMS、旧 MS-DOS FAT 等）下归档的文件可能存储为全大写名称；当提取到保留大小写的文件系统（如 OS/2 HPFS）或区分大小写的文件系统（如 Unix）时，这可能难看或不方便。默认情况下，`unzip` 完全按照存储方式列出和提取此类文件名（截断、不支持字符转换等除外）；此选项导致来自某些系统的所有文件名转换为小写。`-LL` 选项强制将每个文件名转换为小写，无论其来源文件系统如何。

- `-M`  
    将所有输出通过类似于 Unix `“more”(1)` 命令的内部寻呼器管道传输。在一屏输出结束时，`unzip` 暂停并显示 `--More--` 提示；按 Enter（Return）键或空格键可查看下一屏。可以按 `q` 键终止 `unzip`，在某些系统上也可以按 Enter/Return 键。与 Unix `“more”(1)` 不同，没有向前搜索或编辑功能。此外，`unzip` 不会注意长行是否在屏幕边缘换行，实际上会导致打印两行或更多行，并且某些文本可能在查看之前从屏幕顶部滚出。在某些系统上，无法检测屏幕上的可用行数，在这种情况下，`unzip` 假定高度为 24 行。

- `-n`  
    从不覆盖现有文件。如果文件已存在，则跳过该文件的提取而不提示。默认情况下，`unzip` 在提取任何已存在的文件之前会查询；用户可以选择仅覆盖当前文件、覆盖所有文件、跳过当前文件的提取、跳过所有现有文件的提取，或重命名当前文件。

- `-N`  
    [Amiga] 将文件注释提取为 Amiga 文件注释。文件注释由 `zip`(1L) 的 `-c` 选项创建，或由 Amiga 移植版 `zip`(1L) 的 `-N` 选项创建，后者将文件注释存储为注释。

- `-o`  
    覆盖现有文件而不提示。这是一个危险的选项，请谨慎使用。（然而，它通常与 `-f` 一起使用，并且是在 OS/2 下覆盖目录 EA 的唯一方法。）

- `-P` `password`  
    使用 `password` 解密加密的 zipfile 条目（如果有）。**这是不安全的！** 许多多用户操作系统提供任何用户查看任何其他用户当前命令行的方法；即使在独立系统上，也始终存在肩窥威胁。将明文密码作为自动化脚本命令行的一部分存储更糟。尽可能使用不回显的交互式提示输入密码。（在安全真正重要的地方，使用强加密，例如 Pretty Good Privacy，而不是标准 zipfile 实用程序提供的相对较弱的加密。）

- `-q`  
    安静地执行操作（`-qq` = 更安静）。通常 `unzip` 会打印正在提取或测试的文件名、提取方法、可能存储在归档中的任何文件或 zipfile 注释，以及每个归档完成时可能的摘要。`-q[q]` 选项抑制部分或全部这些消息的打印。

- `-s`  
    [OS/2, NT, MS-DOS] 将文件名中的空格转换为下划线。由于所有 PC 操作系统都允许文件名中有空格，`unzip` 默认提取文件名时保留空格（例如 `EA DATA. SF`）。但这可能很别扭，因为 MS-DOS 尤其不能很好地支持文件名中的空格。在某些情况下，将空格转换为下划线可以消除这种别扭。

- `-S`  
    [VMS] 将文本文件（`-a`、`-aa`）转换为 Stream_LF 记录格式，而不是文本文件默认的可变长度记录格式。（Stream_LF 是 VMS `unzip` 的默认记录格式。除非请求转换（`-a`、`-aa` 和/或 `-b`、`-bb`）或处理 VMS 特定条目，否则会应用它。）

- `-U`  
    [仅 `UNICODE_SUPPORT`] 修改或禁用 UTF-8 处理。当 `UNICODE_SUPPORT` 可用时，选项 `-U` 强制 `unzip` 将 UTF-8 编码文件名中的所有非 ASCII 字符转义为 `#Uxxxx`（对于 UCS-2 字符，或需要 3 个八位字节的 Unicode 码点为 `#Lxxxxxx`）。此选项主要用于调试目的，当怀疑相当新的 UTF-8 支持会弄乱提取的文件名时。
    
    选项 `-UU` 允许完全禁用对 UTF-8 编码文件名的识别。`unzip` 内文件名编码的处理回退到以前版本的行为。
    
    [旧、过时用法] 如果在 MS-DOS、VMS 等下创建，则保留文件名大写。参见上面的 `-L`。

- `-V`  
    保留（VMS）文件版本号。VMS 文件可以存储版本号，格式为 `file.ext;##`。默认情况下，`;##` 版本号会被剥离，但此选项允许保留它们。（在将文件名限制为特别短长度的文件系统上，无论此选项如何，版本号都可能被截断或剥离。）

- `-W`  
    [仅当启用 `WILD_STOP_AT_DIR` 编译时选项] 修改模式匹配例程，使 `?`（单字符通配符）和 `*`（多字符通配符）都不匹配目录分隔符字符 `/`。（两字符序列 `**` 充当多字符通配符，其匹配字符包括目录分隔符。）示例：
    
    ```
    "*.c" 匹配 "foo.c"，但不匹配 "mydir/foo.c"
    "**.c" 同时匹配 "foo.c" 和 "mydir/foo.c"
    "*/*.c" 匹配 "bar/foo.c"，但不匹配 "baz/bar/foo.c"
    "??*/*" 匹配 "ab/foo" 和 "abc/foo"
            但不匹配 "a/foo" 或 "a/b/foo"
    ```
    
    此修改后的行为等价于 UnZip 支持的某些目标 OS 的 shell 所使用的模式匹配风格（一个例子是 Acorn RISC OS）。在 Zip 归档的内部目录分隔符字符 `/` 允许作为本机操作系统文件名中的常规字符的系统上，此选项可能不可用。（目前，UnZip 在大多数移植版中对通配符 zipfile 规范和 zip 条目选择模式使用相同的模式匹配规则。对于允许 `/` 作为常规文件名字符的系统，`-W` 选项在通配符 zipfile 规范上不会按预期工作。）

- `-X`  
    [VMS, Unix, OS/2, NT, Tandem] 在 VMS 下恢复所有者/保护信息（UIC 和 ACL 条目），或在 Unix 下恢复用户和组信息（UID/GID），或在某些启用网络的 OS/2 版本（Warp Server 配合 IBM LAN Server/Requester 3.0 至 5.0；Warp Connect 配合 IBM Peer 1.0）下恢复访问控制列表（ACL），或在 Windows NT 下恢复安全 ACL。在大多数情况下，这需要特殊系统权限，在 NT 下加倍选项（`-XX`）指示 `unzip` 使用特权进行提取；但在 Unix 下，例如，属于多个组的用户可以恢复属于这些组中任何组的文件，只要用户 ID 与其自己的匹配。请注意，普通文件属性始终恢复——此选项仅适用于某些操作系统上可用的可选额外所有权信息。[NT 的访问控制列表似乎与 OS/2 的不特别兼容，因此没有尝试访问权限的跨平台可移植性。也不清楚这在什么条件下会有用。]

- `-Y`  
    [VMS] 将归档文件名结尾 `.nnn`（其中 `nnn` 是十进制数字）视为 VMS 版本号（`;nnn`）。（默认将它们视为文件类型。）示例：
    
    ```
    "a.b.3" -> "a.b;3"。
    ```

- `-$`  
    [MS-DOS, OS/2, NT] 如果提取介质可移动（例如磁盘），则恢复卷标。加倍选项（`-$$`）也允许标记固定介质（硬盘）。默认情况下，忽略卷标。

- `-/` `extensions`  
    [仅 Acorn] 覆盖由 `Unzip$Ext` 环境变量提供的扩展名列表。提取期间，与此扩展名列表中某一项匹配的文件名扩展名会交换到提取文件的基名前面。

- `-:`  
    [除 Acorn、VM/CMS、MVS、Tandem 外的所有系统] 允许将归档成员提取到当前“提取根文件夹”之外的位置。出于安全原因，`unzip` 通常会从提取文件名中移除“父目录”路径组件（`../`）。此安全功能（5.50 版新增）防止 `unzip` 意外将文件写入活动提取文件夹树头之外的“敏感”区域。`-:` 选项让 `unzip` 切换回以前更自由的行为，以允许精确提取使用 `../` 组件在当前提取文件夹级别创建多个目录树的（较旧）归档。此选项不会启用显式写入根目录（`/`）。为此，需要将提取目标文件夹设置为根（例如 `-d /`）。但是，当指定 `-:` 选项时，仍然可以通过在 zip 归档中指定足够的 `../` 路径组件来隐式写入根目录。请极其谨慎地使用此选项。

- `-^`  
    [仅 Unix] 允许提取的 ZIP 归档条目的名称中包含控制字符。在 Unix 上，文件名可以包含任何（8 位）字符代码，但 `/`（目录分隔符）和 NUL（0x00，C 字符串终止指示符）除外，除非特定文件系统有更严格的约定。通常，这允许在文件名中嵌入 ASCII 控制字符（甚至复杂的控制序列），至少在“本机”Unix 文件系统上。然而，利用此 Unix“特性”可能非常可疑。文件名中嵌入的控制字符在某些列表代码显示在屏幕上而没有足够过滤时可能会产生讨厌的副作用。而且，对于普通用户来说，处理此类文件名可能很困难（例如，在尝试为打开、复制、移动或删除操作指定它时）。因此，`unzip` 默认应用过滤器，从提取的文件名中移除潜在危险的控制字符。`-^` 选项允许在罕见情况下覆盖此过滤器，即有意恢复嵌入的文件名控制字符。

- `-2`  
    [VMS] 强制无条件将文件名转换为 ODS2 兼容名称。默认是利用目标文件系统，在 ODS5 目标文件系统上保留大小写和扩展文件名字符；在 ODS2 目标文件系统上应用 ODS2 兼容文件名过滤。

## 环境选项

`unzip` 的默认行为可以通过放置在环境变量中的选项修改。这可以用于任何选项，但可能对 `-a`、`-L`、`-C`、`-q`、`-o` 或 `-n` 修饰符最有用：使 `unzip` 默认自动转换文本文件，使其将来自大写系统的文件名转换为小写，使其不区分大小写地匹配名称，使其更安静，或使其在提取时始终覆盖或从不覆盖文件。例如，要使 `unzip` 尽可能安静，仅报告错误，可以使用以下命令之一：

- Unix Bourne shell:
    
    ```sh
    UNZIP=-qq; export UNZIP
    ```
- Unix C shell:
    
    ```csh
    setenv UNZIP -qq
    ```
- OS/2 或 MS-DOS:
    
    ```bat
    set UNZIP=-qq
    ```
- VMS（小写加引号）:
    
    ```sh
    define UNZIP_OPTS "-qq"
    ```

环境选项实际上被视为与任何其他命令行选项一样，只是它们实际上是命令行上的第一批选项。要覆盖环境选项，可以使用“减号运算符”将其移除。例如，要覆盖上面示例中的一个安静标志，使用命令

```sh
unzip --q[其他选项] zipfile
```

第一个连字符是普通开关字符，第二个是减号，作用于 q 选项。因此，这里的效果是取消一个单位的安静度。要取消两个安静标志，可以使用两个（或更多）减号：

```sh
unzip -t--q zipfile
unzip ---qt zipfile
```

（两者等价）。这可能看起来别扭或令人困惑，但相当直观：只需忽略第一个连字符，然后从那里开始。这也与 Unix `“nice”(1)` 的行为一致。

如上面的示例所示，默认变量名对于 VMS 是 `UNZIP_OPTS`（用于将 `unzip` 安装为外部命令的符号否则会与环境变量混淆），对于所有其他操作系统是 `UNZIP`。为了与 `zip`(1L) 兼容，也接受 `UNZIPOPT`（不要问）。但是，如果同时定义了 `UNZIP` 和 `UNZIPOPT`，则 `UNZIP` 优先。`unzip` 的诊断选项（不带 zipfile 名称的 `-v`）可用于检查所有四个可能的 `unzip` 和 `zipinfo` 环境变量的值。

应根据本地时区设置时区变量（TZ），以便 `-f` 和 `-u` 正确操作。有关详细信息，请参见上面的 `-f` 描述。此变量也可能需要正确设置提取文件的时间戳。`unzip` 的 WIN32（Win9x/ME/NT4/2K/XP/2K3）移植版从注册表获取时区配置，假设它在控制面板中正确设置。此移植版忽略 TZ 变量。

## 解密

Info-ZIP 软件完全支持加密归档，但由于美国出口限制，编译的二进制文件可能禁用了加/解密支持。然而，自 2000 年春季以来，美国出口限制已放开，我们的源代码归档现在包含完整的加密代码。如果您需要启用加密支持的二进制分发版，请参见任何 Info-ZIP 源代码或二进制分发版中的 `WHERE` 文件，了解美国境内外的位置。

某些编译版本的 `unzip` 可能不支持解密。要检查版本是否支持加密，可以尝试测试或提取加密归档，或者检查 `unzip` 的诊断屏幕（参见上面的 `-v` 选项）中是否有 `[decryption]` 作为特殊编译选项之一。

如上所述，`-P` 选项可用于在命令行上提供密码，但会牺牲安全性。首选解密方法就是正常提取；如果 zipfile 成员已加密，`unzip` 将提示输入密码，而不回显输入内容。`unzip` 会继续使用同一密码，只要它看起来有效，通过测试每个文件上的 12 字节头。正确密码始终会通过头检查，但错误密码也有 1/256 的几率通过。（这是 PKWARE zipfile 格式的安全特性；它有助于防止暴力攻击，否则这些攻击可能仅通过测试头获得巨大速度优势。）如果给出了错误密码但它通过了头测试，则提取数据会生成错误的 CRC，或者 `unzip` 会在提取期间失败，因为“解密”字节不构成有效的压缩数据流。

如果第一个密码在某个文件的头检查中失败，`unzip` 将提示输入另一个密码，依此类推，直到所有文件都被提取。如果不知道密码，输入空密码（即仅回车或 `Enter`）被视为跳过所有进一步提示的信号。此后仅提取**归档**中的未加密文件。（事实上，这并不完全正确；旧版本的 `zip`(1L) 和 `zipcloak`(1L) 允许空密码，因此 `unzip` 会检查每个加密文件以查看空密码是否有效。如上所述，这可能导致“误报”和提取错误。）

使用 8 位密码（例如带有重音欧洲字符的密码）加密的归档可能无法跨系统和/或其他归档器移植。此问题源于对此类字符使用多种编码方法，包括 Latin-1（ISO 8859-1）和 OEM 代码页 850。DOS `PKZIP` 2.04g 使用 OEM 代码页；Windows `PKZIP` 2.50 使用 Latin-1（因此与 DOS `PKZIP` 不兼容）；Info-ZIP 在 DOS、OS/2 和 Win3.x 移植版上使用 OEM 代码页，但在其他地方使用 ISO 编码（Latin-1 等）；Nico Mak 的 `WinZip` 6.x 根本不允许 8 位密码。`UnZip` 5.3（或更新版本）尝试先使用默认字符集（例如 Latin-1），然后使用备用字符集（例如 OEM 代码页）来测试密码。在 EBCDIC 系统上，如果两者都失败，将最后测试 EBCDIC 编码。（在非 EBCDIC 系统上不测试 EBCDIC，因为没有已知的归档器使用 EBCDIC 编码加密。）不支持 Latin-1 以外的 ISO 字符编码。`UnZip` 6.0 中新添加的（部分）Unicode（或 UTF-8）支持尚未适应 `unzip` 中的加密密码处理。在使用 UTF-8 作为本机字符编码的系统上，`unzip` 只是尝试使用本机 UTF-8 编码密码解密；内置的以翻译编码检查密码的尝试尚未适应 UTF-8 支持，因此会失败。

## 示例

要使用 `unzip` 将归档 `letters.zip` 的所有成员提取到当前目录及其子目录中，根据需要创建任何子目录：

```sh
unzip letters
```

要仅将 `letters.zip` 的所有成员提取到当前目录：

```sh
unzip -j letters
```

要测试 `letters.zip`，仅打印指示归档是否正常的摘要消息：

```sh
unzip -tq letters
```

要测试当前目录中的**所有** zipfile，仅打印摘要：

```sh
unzip -tq \*.zip
```

（仅当 shell 展开通配符时才需要星号前的反斜杠，如在 Unix 中；也可以使用双引号，如下面的源示例所示。）要将 `letters.zip` 中名称以 `.tex` 结尾的所有成员提取到标准输出，自动转换为本地行尾约定，并将输出管道传输到 `“more”(1)`：

```sh
unzip -ca letters \*.tex | more
```

要将二进制文件 `paper1.dvi` 提取到标准输出并管道传输到打印程序：

```sh
unzip -p articles paper1.dvi | dvips
```

要将所有 FORTRAN 和 C 源文件——`*.f`、`*.c`、`*.h` 和 `Makefile`——提取到 `/tmp` 目录：

```sh
unzip source.zip "*.[fch]" Makefile -d /tmp
```

（双引号仅在 Unix 中且仅在开启通配时才需要）。要提取所有 FORTRAN 和 C 源文件，无论大小写（例如，同时包括 `*.c` 和 `*.C`，以及任何 `makefile`、`Makefile`、`MAKEFILE` 或类似文件）：

```sh
unzip -C source.zip "*.[fch]" makefile -d /tmp
```

要提取任何此类文件，但将任何大写 MS-DOS 或 VMS 名称转换为小写，并将所有文件的行尾转换为本地标准（不考虑任何可能标记为“二进制”的文件）：

```sh
unzip -aaCL source.zip "*.[fch]" makefile -d /tmp
```

要仅提取当前目录中已有文件的较新版本，而不查询（注意：在一个时区解压另一个时区创建的 zipfile 时要小心——Zip 2.1 或更高版本以外的 ZIP 归档不包含时区信息，来自东部时区的“较新”文件实际上可能更旧）：

```sh
unzip -fo sources
```

要提取当前目录中已有文件的较新版本，并创建尚不存在的任何文件（与上一个示例相同的注意事项）：

```sh
unzip -uo sources
```

要显示诊断屏幕，显示哪些 `unzip` 和 `zipinfo` 选项存储在环境变量中、是否编译了解密支持、`unzip` 使用哪个编译器编译等：

```sh
unzip -v
```

在最后五个示例中，假设 `UNZIP` 或 `UNZIP_OPTS` 设置为 `-q`。要进行单安静列表：

```sh
unzip -l file.zip
```

要进行双安静列表：

```sh
unzip -ql file.zip
```

（请注意，通常不需要 `.zip`。）要进行标准列表：

```sh
unzip --ql file.zip
```

或

```sh
unzip -l-q file.zip
```

或

```sh
unzip -l--q file.zip
```

（选项中的额外减号不会有害。）

## 提示

当前维护者是个懒人，发现定义一对别名非常有用：`tt` 用于 `unzip -tq`，`ii` 用于 `unzip -Z`（或 `zipinfo`）。然后可以简单地输入 `tt zipfile` 来测试归档，这值得养成习惯。运气好的话，`unzip` 会报告 `No errors detected in compressed data of zipfile.zip`，之后可以松一口气。

维护者还发现将 `UNZIP` 环境变量设置为 `-aL` 很有用，并很想再加上 `-C`。他的 `ZIPINFO` 变量设置为 `-z`。

## 诊断

退出状态（或错误级别）近似于 PKWARE 定义的退出代码，并采用以下值，VMS 除外：

- `0`  
    正常；未检测到错误或警告。

- `1`  
    遇到一个或多个警告错误，但处理仍然成功完成。这包括由于不支持的压缩方法或使用未知密码加密而跳过一个或多个文件的 zipfile。

- `2`  
    检测到 zipfile 格式中的一般错误。处理可能已成功完成；其他归档器创建的某些损坏 zipfile 有简单的解决方法。

- `3`  
    检测到 zipfile 格式中的严重错误。处理可能立即失败。

- `4`  
    `unzip` 在程序初始化期间无法为一个或多个缓冲区分配内存。

- `5`  
    `unzip` 无法分配内存或无法获得 tty 来读取解密**密码**。

- `6`  
    `unzip` 在解压到磁盘期间无法分配内存。

- `7`  
    `unzip` 在内存解压期间无法分配内存。

- `8`  
    [当前未使用]

- `9`  
    未找到指定的 zipfile。

- `10`  
    命令行上指定了无效选项。

- `11`  
    未找到匹配文件。

- `50`  
    提取期间磁盘已满（或曾经已满）。

- `51`  
    过早遇到 ZIP 归档末尾。

- `80`  
    用户使用 control-C（或类似方式）提前中止了 `unzip`。

- `81`  
    由于不支持的压缩方法或不支持的解密，一个或多个文件的测试或提取失败。

- `82`  
    由于错误的解密**密码**，未找到文件。（但是，如果即使一个文件成功处理，退出状态为 1。）

VMS 将标准 Unix（或 PC）返回值解释为其他更可怕的东西，因此 `unzip` 改为将它们映射为 VMS 风格的状态代码。当前映射如下：正常退出为 1（成功），警告错误为 `0x7fff0001`，所有其他错误为 `(0x7fff000? + 16*normal_unzip_exit_status)`，其中 `?` 对于 `unzip` 值 2、9-11 和 80-82 为 2（错误），对于其余值（3-8、50、51）为 4（致命错误）。此外，还有一个编译选项可以扩展此行为：定义 `RETURN_CODES` 会产生错误状态含义的人类可读解释。

## 缺陷

尚不支持多部分归档，除非与 `zip` 结合使用。（所有部分必须按顺序连接在一起，然后必须对连接后的归档执行 `zip -F`（对于 `zip 2.x`）或 `zip -FF`（对于 `zip 3.x`）以“修复”它。此外，`zip 3.0` 及更高版本可以使用 `zip -s- inarchive -O outarchive` 将多部分（分割）归档合并为单个文件归档。有关更多信息，请参见 `zip 3` 手册页。）这肯定会在下一个主要版本中修正。

尚不支持从标准输入读取归档，除非使用 `funzip`（并且只能提取归档的第一个成员）。

使用 8 位密码（例如带有重音欧洲字符的密码）加密的归档可能无法跨系统和/或其他归档器移植。参见上面**解密**中的讨论。

`unzip` 的 `-M`（“more”）选项尝试考虑长行的自动换行。但是，代码可能无法检测正确的换行位置。首先，TAB 字符（和类似控制序列）未被考虑，它们被当作普通可打印字符处理。其次，取决于实际系统/OS 移植版，`unzip` 可能无法检测真实屏幕几何形状，而是依赖“常用”默认尺寸。正确处理制表符需要实现查询输出控制台上实际制表符设置的机制。

除 Unix 外，不恢复存储目录的日期、时间和权限。（在 Windows NT 及后续版本上，现在会恢复时间戳。）

[MS-DOS] 在从有缺陷的软盘提取或测试归档中的文件时，如果从 DOS 的 `Abort, Retry, Fail?` 消息中选择 `Fail` 选项，旧版本的 `unzip` 可能会使系统挂起，需要重新启动。此问题似乎已修复，但仍可以使用 control-C（或 control-Break）终止 `unzip`。

在 DEC Ultrix 下，`unzip` 有时会在长 zipfile 上失败（CRC 错误，不总是可重现）。这显然是由于硬件错误（缓存内存）或操作系统错误（页面错误处理不当？）。由于 Ultrix 已被 Digital Unix（OSF/1）取代，这可能不再是问题。

[Unix] Unix 特殊文件，如 FIFO 缓冲区（命名管道）、块设备和字符设备，即使它们以某种方式表示在 zipfile 中也不会恢复，硬链接文件也不会重新链接。基本上，`unzip` 恢复的唯一文件类型是常规文件、目录和符号（软）链接。

[OS/2] 仅当给出 `-o`（“全部覆盖”）选项时，才会更新现有目录的扩展属性。这是操作系统的限制；因为目录只关联创建时间，`unzip` 无法确定存储的属性比磁盘上的属性新还是旧。在实践中，这可能意味着需要两遍方法：首先正常解包归档（无论是否刷新/更新现有文件），然后仅覆盖目录条目（例如 `unzip -o foo */`）。

[VMS] 当提取到另一个目录时，`-d` 选项只接受 `[.foo]` 语法；简单的 Unix `foo` 语法会被静默忽略（较少见的 VMS `foo.dir` 语法也是如此）。

[VMS] 当要提取的文件已存在时，`unzip` 的查询仅允许跳过、覆盖或重命名；还应该有一个创建文件新版本的选项。实际上，“覆盖”选择确实会创建新版本；旧版本不会被覆盖或删除。
