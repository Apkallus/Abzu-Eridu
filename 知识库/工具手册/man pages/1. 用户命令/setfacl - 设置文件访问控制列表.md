# `setfacl` - 设置文件访问控制列表

## 概要

```sh
setfacl [-bkndRLPvh] [{-m|-x} acl_spec] [{-M|-X} acl_file] file
...
setfacl [-P] --restore={file|-}
```

## 描述

此工具设置文件和目录的访问控制列表（ACL）。在命令行上，一系列命令后跟一系列文件（后者又可以后跟另一系列命令，……）。

`-m` 和 `-x` 选项期望在命令行上给出 ACL。多个 ACL 条目由逗号字符（`,`）分隔。`-M` 和 `-X` 选项从文件或标准输入读取 ACL。ACL 条目格式在“ACL 条目”一节中描述。

`--set` 和 `--set-file` 选项设置文件或目录的 ACL。先前的 ACL 被替换。此操作的 ACL 条目必须包含权限。

`-m`（`--modify`）和 `-M`（`--modify-file`）选项修改文件或目录的 ACL。此操作的 ACL 条目必须包含权限。

`-x`（`--remove`）和 `-X`（`--remove-file`）选项移除 ACL 条目。移除不存在的条目不是错误。除非定义了 `POSIXLY_CORRECT`，否则仅接受不带 `perms` 字段的 ACL 条目作为参数。

使用 `-M` 和 `-X` 选项从文件读取时，`setfacl` 接受 `getfacl` 产生的输出。每行至多有一个 ACL 条目。在井号（`#`）之后，直到行尾的所有内容都被视为注释。

如果 `setfacl` 用于不支持 ACL 的文件系统，`setfacl` 将作用于文件模式权限位。如果 ACL 不能完全适配权限位，`setfacl` 会修改文件模式权限位以尽可能接近地反映 ACL，向标准错误写入错误消息，并返回大于 0 的退出状态。

### 权限

文件所有者和具有 `CAP_FOWNER` 能力的进程被授予修改文件 ACL 的权利。这类似于访问文件模式所需的权限。（在当前 Linux 系统上，`root` 是唯一具有 `CAP_FOWNER` 能力的用户。）

## 选项

- `-b, --remove-all`  
  移除所有扩展 ACL 条目。保留所有者、组和其他人的基本 ACL 条目。

- `-k, --remove-default`  
  移除默认 ACL。如果不存在默认 ACL，则不发出警告。

- `-n, --no-mask`  
  不重新计算有效权限掩码。`setfacl` 的默认行为是重新计算 ACL 掩码条目，除非显式给出了掩码条目。掩码条目被设置为所属组以及所有命名用户和组条目的所有权限的并集。（这些正是受掩码条目影响的条目。）

- `--mask`  
  即使显式给出了 ACL 掩码条目，也重新计算有效权限掩码。（参见 `-n` 选项。）

- `-d, --default`  
  所有操作应用于默认 ACL。输入集中的常规 ACL 条目被提升为默认 ACL 条目。输入集中的默认 ACL 条目被丢弃。（如果发生这种情况，会发出警告。）

- `--restore={file|-}`  
  恢复由 `getfacl -R` 或类似命令创建的权限备份。使用此机制恢复完整目录子树的所有权限。如果输入包含所有者注释或组注释，`setfacl` 会尝试恢复所有者和所属组。如果输入包含标志注释（定义 `setuid`、`setgid` 和 `sticky` 位），`setfacl` 会相应设置这三个位；否则清除它们。此选项不能与除 `-P` 和 `--test` 之外的任何其他选项组合。与 `-P` 组合时，`setfacl` 在解析路径名时不会跟随符号链接。如果给定文件为 `-`，则从标准输入读取。

- `--test`  
  测试模式。不更改任何文件的 ACL，而是列出结果 ACL。

- `-R, --recursive`  
  递归应用于所有文件和目录。此选项不能与 `--restore` 组合。

- `-L, --logical`  
  逻辑遍历，跟随符号链接。默认行为是跟随命令行上给出的符号链接，并跳过子目录中遇到的符号链接。此选项不能与 `--restore` 组合。

- `-P, --physical`  
  物理遍历，不跟随符号链接。命令行上给出的符号链接会被拒绝。（对于命令行上给出的路径名，此选项仅适用于最终组件；前面的路径组件仍可能是符号链接。）

- `-v, --version`  
  打印 `setfacl` 的版本并退出。

- `-h, --help`  
  打印解释命令行选项的帮助。

- `--`  
  命令行选项结束。所有剩余参数都被解释为文件名，即使它们以短横线开头。

- `-`  
  如果文件名参数是单个短横线，`setfacl` 从标准输入读取文件列表。

### ACL 条目

`setfacl` 工具识别以下 ACL 条目格式（为清晰起见插入了空格）：

- `[d[efault]:] [u[ser]:]uid [:perms]`  
  命名用户的权限。若 `uid` 为空，则为文件所有者的权限。

- `[d[efault]:] g[roup]:gid [:perms]`  
  命名组的权限。若 `gid` 为空，则为所属组的权限。

- `[d[efault]:] m[ask][:] [:perms]`  
  有效权限掩码

- `[d[efault]:] o[ther][:] [:perms]`  
  其他人的权限。

分隔符字符和非分隔符字符之间的空白会被忽略。

包含权限的完整 ACL 条目用于修改和设置操作（选项 `-m`、`-M`、`--set` 和 `--set-file`）。不带 `perms` 字段的条目用于删除条目（选项 `-x` 和 `-X`）。

对于 `uid` 和 `gid`，可以指定名称或数字。字符字面量可以用反斜杠后跟与该字符 ASCII 码对应的 3 位八进制数字来表示（例如，`\101` 表示 `'A'`）。如果名称包含字面反斜杠后跟 3 位数字，则反斜杠必须转义（即 `\\`）。

`perms` 字段是指示读（`r`）、写（`w`）、执行（`x`）权限的字符组合。`perms` 字段中的短横线字符（`-`）会被忽略。如果文件是目录或已经对某个用户具有执行权限，则字符 `X` 表示执行权限。或者，`perms` 字段可以以数字形式定义权限，即读（`4`）、写（`2`）和执行（`1`）的按位组合。为零的 `perms` 字段或仅由短横线组成的 `perms` 字段表示无权限。

### 自动创建的条目

初始时，文件和目录仅包含所有者、组和其他人的三个基本 ACL 条目。为了使 ACL 有效，需要满足一些规则：

* 三个基本条目不能被移除。每种基本条目类型必须恰好有一个条目。
* 只要 ACL 包含命名用户条目或命名组对象，它还必须包含有效权限掩码。
* 只要 ACL 包含任何默认 ACL 条目，三个默认 ACL 基本条目（默认所有者、默认组和默认其他人）也必须存在。
* 只要默认 ACL 包含命名用户条目或命名组对象，它还必须包含默认有效权限掩码。

为帮助用户确保这些规则，`setfacl` 在以下条件下从现有条目创建条目：

* 如果 ACL 包含命名用户或命名组条目，且不存在掩码条目，则创建一个与组条目具有相同权限的掩码条目。除非给出 `-n` 选项，否则掩码条目的权限会进一步调整，以包含受掩码条目影响的所有权限的并集。（参见 `-n` 选项描述。）
* 如果创建了默认 ACL 条目，且默认 ACL 不包含所有者、所属组或其他人条目，则将 ACL 所有者、所属组或其他人条目的副本添加到默认 ACL。
* 如果默认 ACL 包含命名用户条目或命名组条目，且不存在掩码条目，则添加一个与默认 ACL 的组条目具有相同权限的掩码条目。除非给出 `-n` 选项，否则掩码条目的权限会进一步调整，以包含受掩码条目影响的所有权限的并集。（参见 `-n` 选项描述。）

## 示例

- 授予额外用户读访问权限  
  ```sh
  setfacl -m u:lisa:r file
  ```

- 撤销所有组和所有命名用户的写访问权限（使用有效权限掩码）  
  ```sh
  setfacl -m m::rx file
  ```

- 从文件的 ACL 中移除命名组条目  
  ```sh
  setfacl -x g:staff file
  ```

- 将一个文件的 ACL 复制到另一个文件  
  ```sh
  getfacl file1 | setfacl --set-file=- file2
  ```

- 将访问 ACL 复制到默认 ACL  
  ```sh
  getfacl --access dir | setfacl -d -M- dir
  ```

## 符合 POSIX 1003.1e 草案标准 17

如果定义了环境变量 `POSIXLY_CORRECT`，`setfacl` 的默认行为按以下方式改变：所有非标准选项被禁用。禁用 `default:` 前缀。`-x` 和 `-X` 选项也接受权限字段（并忽略它们）。
