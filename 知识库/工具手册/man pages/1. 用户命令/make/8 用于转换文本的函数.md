### 8.1 函数调用语法

函数调用类似于变量引用。它可以出现在变量引用可以出现的任何位置，并使用与变量引用相同的规则展开。函数调用如下所示：

```makefile
$(function arguments)
```

或者如下所示：

```makefile
${function arguments}
```

这里 `function` 是函数名；它是 `make` 内置的简短名称列表之一。你还可以通过使用 `call` 内置函数来本质上创建自己的函数。

`arguments` 是函数的参数。它们与函数名之间用一个或多个空格或制表符分隔；如果有多个参数，则用逗号分隔。此类空白和逗号不属于参数值。用于包围函数调用的分隔符（圆括号或花括号）在参数中只能成对出现；另一种分隔符可以单独出现。如果参数本身包含其他函数调用或变量引用，最明智的做法是对所有引用使用同一种分隔符；写 `$(subst a,b,$(x))`，而不是 `$(subst a,b,${x})`。这是因为这样更清晰，而且只有一种分隔符会被匹配以查找引用的结尾。

每个参数都会在调用函数之前展开，除非下面另有说明。替换按参数出现的顺序进行。

#### 特殊字符

当使用对 `make` 有特殊含义的字符作为函数参数时，你可能需要隐藏它们。GNU `make` 不支持用反斜杠或其他转义序列转义字符；但是，由于参数在展开之前会被拆分，你可以通过将它们放入变量来隐藏它们。

你可能需要隐藏的字符包括：

- 逗号
- 第一个参数中的前导空白
- 不匹配的左圆括号或花括号
- 如果你不希望某个左圆括号或花括号开始一个匹配对，则隐藏它

例如，你可以定义变量 `comma` 和 `space`，其值分别是孤立的逗号和空格字符，然后在需要这些字符的地方替换这些变量，如下所示：

```makefile
comma:= ,
empty:=
space:= $(empty) $(empty)
foo:= a b c
bar:= $(subst $(space),$(comma),$(foo))
# bar 现在为 ‘a,b,c’。
```

这里 `subst` 函数通过 `foo` 的值将每个空格替换为逗号，并替换结果。

### 8.2 用于字符串替换和分析的函数

以下是一些操作字符串的函数：

#### `$(subst)`

```makefile
$(subst from,to,text)
```

对文本 `text` 执行文本替换：每次出现的 `from` 都替换为 `to`。结果替换函数调用。例如，

```makefile
$(subst ee,EE,feet on the street)
```

产生值 `‘fEEt on the strEEt’`。

#### `$(patsubst)`

```makefile
$(patsubst pattern,replacement,text)
```

在 `text` 中查找匹配 `pattern` 的以空白分隔的单词，并将它们替换为 `replacement`。这里 `pattern` 可以包含 `%`，它充当通配符，匹配单词内任意数量的任意字符。如果 `replacement` 也包含 `%`，则 `%` 被替换为匹配 `pattern` 中 `%` 的文本。不匹配模式的单词会原样保留在输出中。只有 `pattern` 和 `replacement` 中的第一个 `%` 会这样处理；任何后续 `%` 保持不变。

`patsubst` 函数调用中的 `%` 字符可以用前面的反斜杠（`\`）引用。否则会引用 `%` 字符的反斜杠可以用更多反斜杠引用。引用 `%` 字符或其他反斜杠的反斜杠会在模式被比较文件名或替换词干之前从模式中移除。不处于引用 `%` 字符危险中的反斜杠保持不变。例如，模式 `the\%weird\\%pattern\\` 在起作用的 `%` 字符之前有 `‘the%weird\’`，之后有 `‘pattern\\’`。最后两个反斜杠保持不变，因为它们不能影响任何 `%` 字符。

单词之间的空白会折叠为单个空格字符；前导和尾随空白会被丢弃。

例如，

```makefile
$(patsubst %.c,%.o,x.c.c bar.c)
```

产生值 `‘x.c.o bar.o’`。

替换引用（参见“替换引用”）是获得 `patsubst` 函数效果的更简单方法：

```makefile
$(var:pattern=replacement)
```

等价于

```makefile
$(patsubst pattern,replacement,$(var))
```

第二种简写简化了 `patsubst` 最常见的用途之一：替换文件名末尾的后缀。

```makefile
$(var:suffix=replacement)
```

等价于

```makefile
$(patsubst %suffix,%replacement,$(var))
```

例如，你可能有一个目标文件列表：

```makefile
objects = foo.o bar.o baz.o
```

要获得相应源文件列表，你可以简单地写：

```makefile
$(objects:.o=.c)
```

而不是使用通用形式：

```makefile
$(patsubst %.o,%.c,$(objects))
```

#### `$(strip)`

```makefile
$(strip string)
```

移除 `string` 的前导和尾随空白，并将每个内部的一个或多个空白字符序列替换为单个空格。因此，`$(strip a b  c )` 结果为 `a b c`。

`strip` 函数在与条件判断一起使用时非常有用。当使用 `ifeq` 或 `ifneq` 将某物与空字符串 `‘’` 比较时，你通常希望仅由空白组成的字符串匹配空字符串（参见“Makefile 的条件部分”）。

因此，以下内容可能无法达到预期结果：

```makefile
.PHONY: all
ifneq   "$(needs_made)" ""
all: $(needs_made)
else
all:;@echo 'Nothing to make!'
endif
```

在 `ifneq` 指令中将变量引用 `$(needs_made)` 替换为函数调用 `$(strip $(needs_made))` 会使其更健壮。

#### `$(findstring)`

```makefile
$(findstring find,in)
```

在 `in` 中搜索 `find` 的出现。如果出现，值为 `find`；否则值为空。你可以在条件判断中使用此函数来测试给定字符串中是否存在特定子字符串。因此，下面两个示例：

```makefile
$(findstring a,a b c)
$(findstring a,b c)
```

分别产生值 `‘a’` 和 `‘’`（空字符串）。关于 `findstring` 的实际应用，参见“测试标志的条件判断”。

#### `$(filter)`

```makefile
$(filter pattern…,text)
```

返回 `text` 中与任何 `pattern` 单词*匹配*的所有以空白分隔的单词，移除*不匹配*的单词。模式使用 `%` 编写，就像上面的 `patsubst` 函数中使用的模式一样。

`filter` 函数可用于分离变量中不同类型的字符串（例如文件名）。例如：

```makefile
sources := foo.c bar.c baz.s ugh.h
foo: $(sources)
        cc $(filter %.c %.s,$(sources)) -o foo
```

表示 `foo` 依赖于 `foo.c`、`bar.c`、`baz.s` 和 `ugh.h`，但编译器的命令中只应指定 `foo.c`、`bar.c` 和 `baz.s`。

#### `$(filter-out)`

```makefile
$(filter-out pattern…,text)
```

返回 `text` 中*不*匹配任何 `pattern` 单词的所有以空白分隔的单词，移除*匹配*一个或多个模式的单词。这与 `filter` 函数正好相反。

例如，给定：

```makefile
objects=main1.o foo.o main2.o bar.o
mains=main1.o main2.o
```

以下生成一个列表，包含所有不在 `‘mains’` 中的目标文件：

```makefile
$(filter-out $(mains),$(objects))
```

#### `$(sort)`

```makefile
$(sort list)
```

按字典顺序对 `list` 的单词排序，移除重复单词。输出是以单个空格分隔的单词列表。因此，

```makefile
$(sort foo bar lose)
```

返回值 `‘bar foo lose’`。

顺便说一句，由于 `sort` 会移除重复单词，即使你不关心排序顺序，也可以将其用于此目的。

#### `$(word)`

```makefile
$(word n,text)
```

返回 `text` 的第 `n` 个单词。`n` 的合法值从 1 开始。如果 `n` 大于 `text` 中的单词数，则值为空。例如，

```makefile
$(word 2, foo bar baz)
```

返回 `‘bar’`。

#### `$(wordlist)`

```makefile
$(wordlist s,e,text)
```

返回 `text` 中从第 `s` 个单词开始到第 `e` 个单词结束（含）的单词列表。`s` 的合法值从 1 开始；`e` 可以从 0 开始。如果 `s` 大于 `text` 中的单词数，则值为空。如果 `e` 大于 `text` 中的单词数，则返回直到 `text` 末尾的单词。如果 `s` 大于 `e`，则不返回任何内容。例如，

```makefile
$(wordlist 2, 3, foo bar baz)
```

返回 `‘bar baz’`。

#### `$(words)`

```makefile
$(words text)
```

返回 `text` 中的单词数。因此，`text` 的最后一个单词是 `$(word $(words text),text)`。

#### `$(firstword)`

```makefile
$(firstword names…)
```

参数 `names` 被视为一系列名称，用空白分隔。值为该系列中的第一个名称。其余名称被忽略。

例如，

```makefile
$(firstword foo bar)
```

产生结果 `‘foo’`。尽管 `$(firstword text)` 与 `$(word 1,text)` 相同，但保留 `firstword` 函数是为了其简单性。

#### `$(lastword)`

```makefile
$(lastword names…)
```

参数 `names` 被视为一系列名称，用空白分隔。值为该系列中的最后一个名称。

例如，

```makefile
$(lastword foo bar)
```

产生结果 `‘bar’`。尽管 `$(lastword text)` 与 `$(word $(words text),text)` 相同，但添加 `lastword` 函数是为了其简单性和更好的性能。

下面是一个使用 `subst` 和 `patsubst` 的实际示例。假设一个 makefile 使用 `VPATH` 变量来指定 `make` 应搜索先决文件的目录列表（参见“所有先决条件的 `VPATH` 搜索路径”）。此示例展示如何告诉 C 编译器在同一目录列表中搜索头文件。

`VPATH` 的值是用冒号分隔的目录列表，例如 `‘src:../headers’`。首先，使用 `subst` 函数将冒号改为空格：

```makefile
$(subst :, ,$(VPATH))
```

这产生 `‘src ../headers’`。然后使用 `patsubst` 将每个目录名转换为 `-I` 标志。这些可以添加到变量 `CFLAGS` 的值中，该变量会自动传递给 C 编译器，如下所示：

```makefile
override CFLAGS += $(patsubst %,-I%,$(subst :, ,$(VPATH)))
```

效果是将文本 `‘-Isrc -I../headers’` 追加到之前给定的 `CFLAGS` 值中。使用 `override` 指令是为了即使先前的 `CFLAGS` 值是用命令参数指定的，也会分配新值（参见“`override` 指令”）。

### 8.3 用于文件名的函数

若干内置展开函数专门用于拆解文件名或文件名列表。

以下每个函数对文件名执行特定转换。函数的参数被视为一系列文件名，用空白分隔。（前导和尾随空白会被忽略。）系列中的每个文件名以相同方式转换，结果用单个空格连接。

#### `$(dir)`

```makefile
$(dir names…)
```

提取 `names` 中每个文件名的目录部分。文件名的目录部分是从开头直到（并包括）其中最后一个斜杠的所有内容。如果文件名不包含斜杠，则目录部分为字符串 `‘./’`。例如，

```makefile
$(dir src/foo.c hacks)
```

产生结果 `‘src/ ./’`。

#### `$(notdir)`

```makefile
$(notdir names…)
```

提取 `names` 中每个文件名除目录部分外的所有内容。如果文件名不包含斜杠，则保持不变。否则，从其中移除直到最后一个斜杠的所有内容。

以斜杠结尾的文件名变为空字符串。这很不幸，因为这意味着结果不总是与参数具有相同数量的以空白分隔的文件名；但我们没有看到任何其他有效的替代方案。

例如，

```makefile
$(notdir src/foo.c hacks)
```

产生结果 `‘foo.c hacks’`。

#### `$(suffix)`

```makefile
$(suffix names…)
```

提取 `names` 中每个文件名的后缀。如果文件名包含句点，则后缀是从最后一个句点开始的所有内容。否则，后缀为空字符串。这通常意味着当 `names` 非空时结果可能为空；如果 `names` 包含多个文件名，结果可能包含更少的文件名。

例如，

```makefile
$(suffix src/foo.c src-1.0/bar.c hacks)
```

产生结果 `‘.c .c’`。

#### `$(basename)`

```makefile
$(basename names…)
```

提取 `names` 中每个文件名除后缀外的所有内容。如果文件名包含句点，则基名是从开头直到（但不包括）最后一个句点的所有内容。目录部分中的句点被忽略。如果没有句点，则基名为整个文件名。例如，

```makefile
$(basename src/foo.c src-1.0/bar hacks)
```

产生结果 `‘src/foo src-1.0/bar hacks’`。

#### `$(addsuffix)`

```makefile
$(addsuffix suffix,names…)
```

参数 `names` 被视为一系列名称，用空白分隔；`suffix` 作为一个单元使用。`suffix` 的值追加到每个单独名称的末尾，得到的更大名称用单个空格连接。例如，

```makefile
$(addsuffix .c,foo bar)
```

产生结果 `‘foo.c bar.c’`。

#### `$(addprefix)`

```makefile
$(addprefix prefix,names…)
```

参数 `names` 被视为一系列名称，用空白分隔；`prefix` 作为一个单元使用。`prefix` 的值前置到每个单独名称的开头，得到的更大名称用单个空格连接。例如，

```makefile
$(addprefix src/,foo bar)
```

产生结果 `‘src/foo src/bar’`。

#### `$(join)`

```makefile
$(join list1,list2)
```

逐词连接两个参数：前两个单词（每个参数一个）连接形成结果的第一个单词，第二个两个单词形成结果的第二个单词，依此类推。因此结果的第 `n` 个单词来自每个参数的第 `n` 个单词。如果一个参数比另一个有更多单词，多余的单词原样复制到结果中。

例如，`$(join a b,.c .o)` 产生 `‘a.c b.o’`。

列表中单词之间的空白不会保留；它会替换为单个空格。

此函数可以合并 `dir` 和 `notdir` 函数的结果，以产生传给这两个函数的原始文件列表。

#### `$(wildcard)`

```makefile
$(wildcard pattern)
```

参数 `pattern` 是文件名模式，通常包含通配符字符（如 shell 文件名模式）。`wildcard` 的结果是匹配该模式的现有文件名的空格分隔列表。参见“在文件名中使用通配符字符”。

#### `$(realpath)`

```makefile
$(realpath names…)
```

对于 `names` 中的每个文件名，返回规范绝对名称。规范名称不包含任何 `.` 或 `..` 组成部分，也不包含任何重复的路径分隔符（`/`）或符号链接。失败时返回空字符串。关于可能的失败原因列表，请查阅 `realpath(3)` 文档。

#### `$(abspath)`

```makefile
$(abspath names…)
```

对于 `names` 中的每个文件名，返回一个绝对名称，该名称不包含任何 `.` 或 `..` 组成部分，也不包含任何重复的路径分隔符（`/`）。请注意，与 `realpath` 函数不同，`abspath` 不解析符号链接，也不要求文件名引用现有文件或目录。使用 `wildcard` 函数测试是否存在。

### 8.4 用于条件判断的函数

有四个提供条件展开的函数。这些函数的一个关键方面是并非所有参数都会在初始时展开。只有需要展开的参数才会被展开。

#### `$(if)`

```makefile
$(if condition,then-part[,else-part])
```

`if` 函数在函数式上下文中提供条件展开支持（与 GNU `make` 的 makefile 条件判断如 `ifeq` 相对，参见“条件判断的语法”）。

第一个参数 `condition` 首先去除所有前导和尾随空白，然后展开。如果它展开为任何非空字符串，则条件被视为真。如果它展开为空字符串，则条件被视为假。

如果条件为真，则求值第二个参数 `then-part`，并将其作为整个 `if` 函数求值的结果。

如果条件为假，则求值第三个参数 `else-part`，并作为 `if` 函数的结果。如果没有第三个参数，`if` 函数求值为空（空字符串）。

注意只会求值 `then-part` 或 `else-part` 之一，绝不会同时求值两者。因此，任一部分都可以包含副作用（例如 `shell` 函数调用等）。

#### `$(or)`

```makefile
$(or condition1[,condition2[,condition3…]])
```

`or` 函数提供“短路”OR 操作。每个参数按顺序展开。如果某个参数展开为非空字符串，则处理停止，展开结果就是该字符串。如果在所有参数展开后，所有参数都为假（空），则展开结果为空字符串。

#### `$(and)`

```makefile
$(and condition1[,condition2[,condition3…]])
```

`and` 函数提供“短路”AND 操作。每个参数按顺序展开。如果某个参数展开为空字符串，则处理停止，展开结果为空字符串。如果所有参数都展开为非空字符串，则展开结果是最后一个参数的展开。

#### `$(intcmp)`

```makefile
$(intcmp lhs,rhs[,lt-part[,eq-part[,gt-part]]])
```

`intcmp` 函数提供整数数值比较支持。此函数在 GNU `make` 的 makefile 条件判断中没有对应物。

左侧 `lhs` 和右侧 `rhs` 会被展开并解析为十进制整数。其余参数的展开由数值左侧与数值右侧的比较结果控制。

如果没有更多参数，则如果左侧和右侧不相等，函数展开为空；如果它们相等，则展开为它们的数值。

否则，如果左侧严格小于右侧，`intcmp` 函数求值为第三个参数 `lt-part` 的展开。如果两侧相等，则 `intcmp` 函数求值为第四个参数 `eq-part` 的展开。如果左侧严格大于右侧，则 `intcmp` 函数求值为第五个参数 `gt-part` 的展开。

如果缺少 `gt-part`，则默认为 `eq-part`。如果缺少 `eq-part`，则默认为空字符串。因此，`$(intcmp 9,7,hello)` 和 `$(intcmp 9,7,hello,world,)` 都求值为空字符串，而 `$(intcmp 9,7,hello,world)`（注意 `world` 后没有逗号）求值为 `‘world’`。

### 8.5 `let` 函数

`let` 函数提供限制变量作用域的方法。`let` 表达式中命名变量的赋值仅在 `let` 表达式提供的文本内有效，并且此赋值不会影响任何外层作用域中的同名变量。

此外，`let` 函数通过将所有未赋值分配给最后一个命名变量来启用列表解包。

`let` 函数的语法是：

```makefile
$(let var [var ...],[list],text)
```

前两个参数 `var` 和 `list` 在做其他任何事情之前展开；注意最后一个参数 `text` **不会**同时展开。接下来，`list` 展开值的每个单词依次绑定到每个变量名 `var`，最后一个变量名绑定到展开后的 `list` 的剩余部分。换句话说，`list` 的第一个单词绑定到第一个变量 `var`，第二个单词绑定到第二个变量 `var`，依此类推。

如果 `var` 中的变量名多于 `list` 中的单词，剩余的 `var` 变量名设置为空字符串。如果 `var` 少于 `list` 中的单词，则最后一个 `var` 设置为 `list` 中所有剩余的单词。

在 `let` 执行期间，`var` 中的变量被赋值为简单展开变量。参见“变量的两种风格”。

在所有变量如此绑定后，展开 `text` 以提供 `let` 函数的结果。

例如，此宏反转其第一个参数给出的列表中单词的顺序：

```makefile
reverse = $(let first rest,$1,\
            $(if $(rest),$(call reverse,$(rest)) )$(first))

all: ; @echo $(call reverse,d c b a)
```

将打印 `a b c d`。首次调用时，`let` 会将 `$1` 展开为 `d c b a`。然后它将 `first` 赋值为 `d`，将 `rest` 赋值为 `c b a`。然后展开 if 语句，其中 `$(rest)` 非空，因此我们递归调用 `reverse` 函数，使用 `rest` 的值，现在为 `c b a`。递归调用 `let` 将 `first` 赋值为 `c`，将 `rest` 赋值为 `b a`。递归继续，直到 `let` 仅以单个值 `a` 调用。这里 `first` 为 `a`，`rest` 为空，因此我们不递归，而只是将 `$(first)` 展开为 `a` 并返回，这添加了 ` b`，等等。

在 `reverse` 调用完成后，`first` 和 `rest` 变量不再设置。如果之前存在这些名称的变量，它们不受 `reverse` 宏展开的影响。

### 8.6 `foreach` 函数

`foreach` 函数类似于 `let` 函数，但与其他函数非常不同。它使一段文本被重复使用，每次对其进行不同的替换。`foreach` 函数类似于 shell `sh` 中的 `for` 命令和 C-shell `csh` 中的 `foreach` 命令。

`foreach` 函数的语法是：

```makefile
$(foreach var,list,text)
```

前两个参数 `var` 和 `list` 在做其他任何事情之前展开；注意最后一个参数 `text` **不会**同时展开。然后对于 `list` 展开值的每个单词，将由 `var` 展开值命名的变量设置为该单词，并展开 `text`。假定 `text` 包含对该变量的引用，因此其展开每次都会不同。

结果是 `text` 被展开的次数与 `list` 中以空白分隔的单词数相同。`text` 的多次展开用空格连接，构成 `foreach` 的结果。

这个简单示例将变量 `‘files’` 设置为列表 `‘dirs’` 中目录内所有文件的列表：

```makefile
dirs := a b c d
files := $(foreach dir,$(dirs),$(wildcard $(dir)/*))
```

这里 `text` 是 `$(wildcard $(dir)/*)`。第一次重复为 `dir` 找到值 `‘a’`，因此它产生与 `$(wildcard a/*)` 相同的结果；第二次重复产生 `$(wildcard b/*)` 的结果；第三次产生 `$(wildcard c/*)` 的结果。

此示例与以下示例具有相同结果（除了设置 `‘dirs’`）：

```makefile
files := $(wildcard a/* b/* c/* d/*)
```

当 `text` 复杂时，你可以通过使用附加变量为其命名来提高可读性：

```makefile
find_files = $(wildcard $(dir)/*)
dirs := a b c d
files := $(foreach dir,$(dirs),$(find_files))
```

这里我们以这种方式使用变量 `find_files`。我们使用普通 `=` 定义递归展开变量，以便其值包含实际的函数调用，在 `foreach` 控制下重新展开；简单展开变量不行，因为 `wildcard` 只会在定义 `find_files` 时调用一次。

与 `let` 函数一样，`foreach` 函数对变量 `var` 没有永久影响；在 `foreach` 函数调用之后，其值和风格与之前相同。从 `list` 获取的其他值仅在 `foreach` 执行期间临时有效。在 `foreach` 执行期间，变量 `var` 是简单展开变量。如果 `var` 在 `foreach` 函数调用之前未定义，则调用后也未定义。参见“变量的两种风格”。

当使用复杂变量表达式产生变量名时必须小心，因为许多奇怪的名称是有效变量名，但很可能不是你所想要的。例如，

```makefile
files := $(foreach Esta-escrito-en-espanol!,b c ch,$(find_files))
```

如果 `find_files` 的值引用名为 `‘Esta-escrito-en-espanol!’` 的变量（这是一个相当长的名字，不是吗？），这可能有用，但更可能是一个错误。

### 8.7 `file` 函数

`file` 函数允许 makefile 写入文件或从文件读取。支持两种写入模式：覆盖，文本写入文件开头并丢失任何现有内容；追加，文本写入文件末尾，保留现有内容。在两种情况下，如果文件不存在则创建它。如果无法打开文件进行写入，或写入操作失败，则是致命错误。写入文件时，`file` 函数展开为空字符串。

从文件读取时，`file` 函数展开为文件的逐字内容，但会去除最后的换行符（如果有）。尝试从不存在的文件读取会展开为空字符串。

`file` 函数的语法是：

```makefile
$(file op filename[,text])
```

求值 `file` 函数时，首先展开其所有参数，然后以 `op` 描述的模式打开 `filename` 指示的文件。

运算符 `op` 可以是 `>` 表示文件将被新内容覆盖，`>>` 表示将追加到文件当前内容，或 `<` 表示读取文件内容。`filename` 指定要写入或读取的文件。运算符和文件名之间可以有可选的空白。

读取文件时，提供 `text` 值是错误的。

写入文件时，`text` 将写入文件。如果 `text` 尚未以换行符结尾，则写入最后的换行符（即使 `text` 是空字符串）。如果根本没有给出 `text` 参数，则不写入任何内容。

例如，如果你的构建系统命令行大小有限，并且你的配方运行一个也可以从文件接受参数的命令，`file` 函数可能很有用。许多命令使用这样的约定：以 `@` 为前缀的参数指定一个包含更多参数的文件。然后你可以这样编写配方：

```makefile
program: $(OBJECTS)
        $(file >$@.in,$^)
        $(CMD) $(CMDFLAGS) @$@.in
        @rm $@.in
```

如果命令要求每个参数位于输入文件的单独行上，你可以这样编写配方：

```makefile
program: $(OBJECTS)
        $(file >$@.in) $(foreach O,$^,$(file >>$@.in,$O))
        $(CMD) $(CMDFLAGS) @$@.in
        @rm $@.in
```

### 8.8 `call` 函数

`call` 函数独特之处在于它可用于创建新的参数化函数。你可以将复杂表达式写为变量的值，然后使用 `call` 以不同的值展开它。

`call` 函数的语法是：

```makefile
$(call variable,param,param,…)
```

当 `make` 展开此函数时，它将每个 `param` 分配给临时变量 `$(1)`、`$(2)` 等。变量 `$(0)` 将包含 `variable`。参数参数数量没有上限。也没有下限，但没有参数使用 `call` 没有意义。

然后在这些临时赋值上下文中将 `variable` 作为 `make` 变量展开。因此，`variable` 值中对 `$(1)` 的任何引用都将解析为 `call` 调用中的第一个 `param`。

注意 `variable` 是变量的*名称*，而不是对该变量的*引用*。因此，编写时通常不使用 `$` 或圆括号。（但是，如果你希望名称不是常量，可以在名称中使用变量引用。）

如果 `variable` 是内置函数的名称，则始终调用内置函数（即使也存在同名的 `make` 变量）。

`call` 函数在将 `param` 参数分配给临时变量之前展开它们。这意味着包含对具有特殊展开规则的内置函数（如 `foreach` 或 `if`）的引用的 `variable` 值可能无法按预期工作。

一些示例可能使这一点更清楚。

此宏简单地反转其参数：

```makefile
reverse = $(2) $(1)

foo = $(call reverse,a,b)
```

这里 `foo` 将包含 `‘b a’`。

这个示例稍微更有趣：它定义一个宏来在 `PATH` 中搜索程序的第一个实例：

```makefile
pathsearch = $(firstword $(wildcard $(addsuffix /$(1),$(subst :, ,$(PATH)))))

LS := $(call pathsearch,ls)
```

现在变量 `LS` 包含 `/bin/ls` 或类似内容。

`call` 函数可以嵌套。每个递归调用都有自己的 `$(1)` 等局部值，掩盖更高层 `call` 的值。例如，这里是一个 *map* 函数的实现：

```makefile
map = $(foreach a,$(2),$(call $(1),$(a)))
```

现在你可以一步将通常只接受一个参数的函数（如 `origin`）映射到多个值：

```makefile
o = $(call map,origin,o map MAKE)
```

最终 `o` 包含类似 `‘file file default’` 的内容。

最后提醒：在向 `call` 添加参数空白时要小心。与其他函数一样，第二个及后续参数中包含的任何空白都会保留；这可能导致奇怪的效果。通常最安全的做法是在向 `call` 提供参数时移除所有多余空白。

### 8.9 `value` 函数

`value` 函数提供了一种使用变量值而*不*展开它的方法。请注意，这不会撤销已经发生的展开；例如，如果你创建简单展开变量，其值在定义期间展开；在这种情况下，`value` 函数将返回与直接使用变量相同的结果。

`value` 函数的语法是：

```makefile
$(value variable)
```

注意 `variable` 是变量的*名称*，而不是对该变量的*引用*。因此，编写时通常不使用 `$` 或圆括号。（但是，如果你希望名称不是常量，可以在名称中使用变量引用。）

此函数的结果是包含 `variable` 值的字符串，不发生任何展开。例如，在此 makefile 中：

```makefile
FOO = $PATH

all:
        @echo $(FOO)
        @echo $(value FOO)
```

第一行输出将是 `ATH`，因为 “$P” 会作为 `make` 变量展开；而第二行输出将是你 `$PATH` 环境变量的当前值，因为 `value` 函数避免了展开。

`value` 函数最常与 `eval` 函数一起使用（参见“`eval` 函数”）。

### 8.10 `eval` 函数

`eval` 函数非常特殊：它允许你定义非常量的新 makefile 构造；这些构造是求值其他变量和函数的结果。`eval` 函数的参数会被展开，然后展开结果被解析为 makefile 语法。展开结果可以定义新的 `make` 变量、目标、隐式或显式规则等。

`eval` 函数的结果始终是空字符串；因此，它几乎可以放在 makefile 中的任何位置而不会导致语法错误。

重要的是要意识到 `eval` 参数会被展开*两次*：首先由 `eval` 函数展开，然后展开结果在解析为 makefile 语法时再次展开。这意味着使用 `eval` 时，你可能需要为 “$” 字符提供额外级别的转义。`value` 函数（参见“`value` 函数”）有时在这些情况下很有用，以绕过不需要的展开。

以下示例展示如何使用 `eval`；此示例结合了许多概念和其他函数。尽管在此示例中使用 `eval` 而不是直接写出规则可能显得过于复杂，但请考虑两点：第一，模板定义（在 `PROGRAM_template` 中）可能比这里复杂得多；第二，你可以将此示例中复杂的“通用”部分放入另一个 makefile，然后将其包含在所有单独的 makefile 中。现在你的单独 makefile 非常直接。

```makefile
PROGRAMS    = server client

server_OBJS = server.o server_priv.o server_access.o
server_LIBS = priv protocol

client_OBJS = client.o client_api.o client_mem.o
client_LIBS = protocol

# 这之后的所有内容都是通用的

.PHONY: all
all: $(PROGRAMS)

define PROGRAM_template =
 $(1): $$($(1)_OBJS) $$($(1)_LIBS:%=-l%)
 ALL_OBJS   += $$($(1)_OBJS)
endef

$(foreach prog,$(PROGRAMS),$(eval $(call PROGRAM_template,$(prog))))

$(PROGRAMS):
        $(LINK.o) $^ $(LDLIBS) -o $@

clean:
        rm -f $(ALL_OBJS) $(PROGRAMS)
```

### 8.11 `origin` 函数

`origin` 函数与大多数其他函数不同，它不操作变量的值；它告诉你关于变量的某些*信息*。具体来说，它告诉你变量来自哪里。

`origin` 函数的语法是：

```makefile
$(origin variable)
```

注意 `variable` 是要查询的变量的*名称*，而不是对该变量的*引用*。因此，编写时通常不使用 `$` 或圆括号。（但是，如果你希望名称不是常量，可以在名称中使用变量引用。）

此函数的结果是一个字符串，告诉你变量 `variable` 是如何定义的：

- `‘undefined’`  
    如果 `variable` 从未定义。

- `‘default’`  
    如果 `variable` 有默认定义，就像 `CC` 等通常那样。参见“隐式规则使用的变量”。请注意，如果你重新定义了默认变量，`origin` 函数将返回后来定义的来源。

- `‘environment’`  
    如果 `variable` 继承自提供给 `make` 的环境。

- `‘environment override’`  
    如果 `variable` 继承自提供给 `make` 的环境，并且由于 `-e` 选项而覆盖了 makefile 中对 `variable` 的设置（参见“选项摘要”）。

- `‘file’`  
    如果 `variable` 在 makefile 中定义。

- `‘command line’`  
    如果 `variable` 在命令行上定义。

- `‘override’`  
    如果 `variable` 在 makefile 中使用 `override` 指令定义（参见“`override` 指令”）。

- `‘automatic’`  
    如果 `variable` 是为每条规则的配方执行而定义的自动变量（参见“自动变量”）。

此信息主要有用（除了满足你的好奇心）于确定你是否想相信变量的值。例如，假设你有一个 makefile `foo`，它包含另一个 makefile `bar`。如果你运行命令 `make -f bar`，你希望变量 `bletch` 在 `bar` 中定义，即使环境包含 `bletch` 的定义。但是，如果 `foo` 在包含 `bar` 之前定义了 `bletch`，你不想覆盖该定义。这可以通过在 `foo` 中使用 `override` 指令来完成，使该定义优先于 `bar` 中的后续定义；不幸的是，`override` 指令也会覆盖任何命令行定义。因此，`bar` 可以包含：

```makefile
ifdef bletch
ifeq "$(origin bletch)" "environment"
bletch = barf, gag, etc.
endif
endif
```

如果 `bletch` 已从环境定义，这将重新定义它。

如果你想覆盖 `bletch` 的先前定义（如果它来自环境），即使在 `-e` 下，你也可以改为写：

```makefile
ifneq "$(findstring environment,$(origin bletch))" ""
bletch = barf, gag, etc.
endif
```

这里如果 `$(origin bletch)` 返回 `‘environment’` 或 `‘environment override’`，则发生重新定义。参见“用于字符串替换和分析的函数”。

### 8.12 `flavor` 函数

`flavor` 函数与 `origin` 函数一样，不操作变量的值，而是告诉你关于变量的某些*信息*。具体来说，它告诉你变量的风格（参见“变量的两种风格”）。

`flavor` 函数的语法是：

```makefile
$(flavor variable)
```

注意 `variable` 是要查询的变量的*名称*，而不是对该变量的*引用*。因此，编写时通常不使用 `$` 或圆括号。（但是，如果你希望名称不是常量，可以在名称中使用变量引用。）

此函数的结果是一个字符串，标识变量 `variable` 的风格：

- `‘undefined’`  
    如果 `variable` 从未定义。

- `‘recursive’`  
    如果 `variable` 是递归展开变量。

- `‘simple’`  
    如果 `variable` 是简单展开变量。

### 8.13 控制 make 的函数

这些函数控制 make 的运行方式。通常，它们用于向 makefile 的用户提供信息，或在检测到某种环境错误时使 make 停止。

#### `$(error)`

```makefile
$(error text…)
```

生成致命错误，消息为 `text`。注意，每当此函数被求值时就会生成错误。因此，如果你将其放在配方中或递归变量赋值的右侧，它不会在稍后求值。`text` 会在生成错误之前展开。

例如，

```makefile
ifdef ERROR1
$(error error is $(ERROR1))
endif
```

如果定义了 `make` 变量 `ERROR1`，则在读取 makefile 期间生成致命错误。或者，

```makefile
ERR = $(error found an error!)

.PHONY: err
err: ; $(ERR)
```

如果调用了 `err` 目标，则在 `make` 运行时生成致命错误。

#### `$(warning)`

```makefile
$(warning text…)
```

此函数的工作方式类似于上面的 `error` 函数，但 `make` 不会退出。相反，展开 `text` 并显示结果消息，但 makefile 的处理继续。

此函数展开的结果是空字符串。

#### `$(info)`

```makefile
$(info text…)
```

此函数除了将其（展开后的）参数打印到标准输出外，不做其他任何事情。不添加 makefile 名称或行号。此函数展开的结果是空字符串。

### 8.14 `shell` 函数

`shell` 函数与除 `wildcard` 函数之外的任何其他函数都不同（参见“`wildcard` 函数”），因为它与 `make` 之外的世界通信。

`shell` 函数为 `make` 提供了与大多数 shell 中反引号（`` ` ``）相同的功能：它执行*命令展开*。这意味着它接受一个 shell 命令作为参数，并展开为该命令的输出。`make` 对结果所做的唯一处理是将每个换行符（或回车/换行对）转换为单个空格。如果有尾随（回车和）换行符，则直接移除。

调用 `shell` 函数运行的命令在函数调用展开时运行（参见“`make` 如何读取 Makefile”）。由于此函数涉及生成新 shell，你应仔细考虑在递归展开变量与简单展开变量中使用 `shell` 函数的性能影响（参见“变量的两种风格”）。

`shell` 函数的替代方法是 `!=` 赋值运算符；它提供类似行为，但有细微差别（参见“设置变量”）。`!=` 赋值运算符包含在较新的 POSIX 标准中。

使用 `shell` 函数或 `!=` 赋值运算符后，其退出状态会放入 `.SHELLSTATUS` 变量。

以下是 `shell` 函数的一些使用示例：

```makefile
contents := $(shell cat foo)
```

将 `contents` 设置为文件 `foo` 的内容，每行之间用空格（而不是换行符）分隔。

```makefile
files := $(shell echo *.c)
```

将 `files` 设置为 `‘*.c’` 的展开。除非 `make` 使用非常奇怪的 shell，否则这与 `$(wildcard *.c)` 具有相同结果（只要至少存在一个 `‘.c’` 文件）。

所有标记为 `export` 的变量也会传递给由 `shell` 函数启动的 shell。可以创建变量展开循环：考虑这个 `makefile`：

```makefile
export HI = $(shell echo hi)
all: ; @echo $$HI
```

当 `make` 想运行配方时，它必须将变量 `HI` 添加到环境中；为此必须展开它。此变量的值需要调用 `shell` 函数，而调用它必须创建其环境。由于 `HI` 已导出，我们需要展开它以创建其环境。如此循环。在这种晦涩的情况下，`make` 将使用提供给 `make` 的环境中的变量值，如果没有则使用空字符串，而不是循环或发出错误。这通常是你想要的；例如：

```makefile
export PATH = $(shell echo /usr/local/bin:$$PATH)
```

但是，在这里一开始就使用简单展开变量（`:=`）会更简单、更高效。

### 8.15 `guile` 函数

如果 GNU `make` 在构建时支持 GNU Guile 作为嵌入式扩展语言，则 `guile` 函数将可用。`guile` 函数接受一个参数，首先由 `make` 以正常方式展开，然后传递给 GNU Guile 求值器。求值器的结果转换为字符串，并用作 makefile 中 `guile` 函数的展开。关于用 Guile 编写 `make` 扩展的详细信息，参见“GNU Guile 集成”。

你可以通过检查 `.FEATURES` 变量中是否有 `guile` 一词来确定 GNU Guile 支持是否可用。
