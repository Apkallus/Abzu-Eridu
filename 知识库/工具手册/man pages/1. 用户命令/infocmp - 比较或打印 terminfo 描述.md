# `infocmp` - 比较或打印 `terminfo` 描述

## 概要

```sh
infocmp [-1cCdDeEFgGiIKlLnpqrtTuUVWx] [-A directory] [-B directory] [-Q encoding] [-R subset] [-s key] [-v level] [-w width] [terminal-type ...]
```

## 描述

`infocmp` 从 `terminfo` 数据库中的已编译条目报告人类可读的终端类型描述，支持多种可选格式；它也可以比较这些条目，并通过引用其他条目的内容重写某个条目，以替换 `use` 表达式。一个 `terminfo` 条目由一个或多个终端类型标识符、终端类型的人类可读描述，以及描述其编程接口的终端能力列表组成。在所有情况下，程序都会先报告布尔值能力，再报告数值能力，最后报告字符串值能力。

### 默认选项

如果未指定任何选项，且指定零个或一个 `terminal-types`，`infocmp` 假定使用 `-I` 选项。如果指定多个 `terminal-types`，程序假定使用 `-d` 选项。

### 源清单选项 [`-I`] [`-L`] [`-C`] [`-r`]

`-I`、`-L` 和 `-C` 选项会为每个指定终端生成源清单。

- `-I`  
    使用 `terminfo` 能力代码

- `-L`  
    使用“长”能力名称

- `-C`  
    使用 `termcap` 能力代码

- `-r`  
    与 `-C` 一起使用时，包含非标准能力

- `-K`  
    与 `-C` 一起使用时，改进 BSD 兼容性

如果未给出 `terminal-types`，将使用环境变量 `TERM` 作为终端名称。

`-C` 选项生成的源可以直接用作 `termcap` 条目，但并非所有参数化字符串都能转换为 `termcap` 格式。`infocmp` 会尝试转换大多数参数化信息，未转换的内容会在输出中明确标记并注释掉。这些内容应手工编辑。

要获得转换为 `termcap` 格式的最佳结果，应同时使用 `-C` 和 `-r`。通常，termcap 描述限制为 1023 字节。`infocmp` 会修剪不太重要的部分以使其适配。如果要转换为接受无限大小 termcap 的（少见）termcap 实现，可能需要添加 `-T` 选项。然而更常见的是，必须帮助 termcap 实现，并修剪多余空白（为此使用 `-0` 选项）。

字符串的所有填充信息会被收集在一起，并放在字符串开头，也就是 `termcap` 期望的位置。强制填充（带尾部 `/` 的填充信息）将变为可选。

所有不再受 `terminfo` 支持、但可从其他 `terminfo` 变量派生的 `termcap` 变量都会被输出。并非所有 `terminfo` 能力都会被翻译；通常只输出属于 `termcap` 的变量。指定 `-r` 选项会取消这一限制，允许所有能力以 `termcap` 形式输出。通常应同时使用 `-C` 和 `-r` 选项。实际使用的格式包含一些针对转义字符的改进。若要进行更严格的 BSD 兼容转换，请使用 `-K` 选项而不是 `-C`。

注意，由于填充会被收集到能力开头，并非所有能力都会输出。不支持强制填充。由于 `termcap` 字符串不够灵活，并不总是能够将 `terminfo` 字符串能力转换为等价的 `termcap` 格式。之后将 `termcap` 文件转换回 `terminfo` 格式时，不一定能重现原始 `terminfo` 源。

一些常见 `terminfo` 参数序列、它们的 `termcap` 等价项，以及通常具有这些序列的一些终端类型如下：

| `terminfo` | `termcap` | 终端类型 |
| --- | --- | --- |
| `%p1%c` | `%.` | ansi-m |
| `%p1%d` | `%d` | ansi, vt100 |
| `%p1%' '%+%c` | `%+x` | vt52 |
| `%i` | `%iq` | ansi, vt100 |
| `%p1%?%'x'%>%t%p1%'y'%+%;` | `%>xy` | annarbor4080 |
| `%p2...%p1` | `%r` | hpgeneric |

### 条目比较选项 [`-d`] [`-c`] [`-n`]

给定 `-c`、`-d` 或 `-n` 时，`infocmp` 会将第一个指定 `terminal-type` 的 `terminfo` 描述与后续每个操作数的描述进行比较。如果指定的 `terminal-types` 少于所需数量，`infocmp` 会用环境变量 `TERM` 代替。

如果某个能力只为一个终端类型定义，报告的值取决于该能力的类型：

- 缺失的布尔变量为 `F`
- 缺失的整数或字符串变量为 `NULL`

`-c` 和 `-d` 选项会在 `'` 字符之间报告字符串能力值。使用 `-q` 选项区分缺失和取消的能力；参见 `terminfo(5)`。

比较选项选择报告形式。

- `-d`  
    列出两个条目之间不同的每个能力。每个能力名后跟 `:` 和逗号分隔的能力值，然后是一个句点。

- `-c`  
    列出两个条目共有的每个能力。`infocmp` 会忽略任一条目中缺失的能力。每个能力名后跟 `=`、一个空格和能力值，然后是一个句点。

如果进一步指定 `-u` 选项，`infocmp` 会重写第一个类型的描述，使用 `use=` 语法将第二个类型作为构建块。

- `-n`  
    列出所有给定条目中都不存在的能力。每个能力名前缀 `!`，后缀一个句点。

通常只显示常规能力。使用 `-x` 选项添加 BSD 兼容能力（名称前缀为 `OT`）。

### Use= 选项 [`-u`]

`-u` 选项会生成第一个终端 `terminal-type` 的 `terminfo` 源描述，该描述相对于其他 `terminal-types` 条目描述之和。它通过分析第一个 `terminal-types` 与其他 `terminal-types` 之间的差异，并生成带有其他终端 `use=` 字段的描述来实现。通过这种方式，可以将通用 terminfo 条目改造为某个终端的描述。或者，如果两个相似终端存在，但由不同时间或不同人编写，因此每个描述都是完整描述，使用 `infocmp` 可以显示如何修改一个描述，使其相对于另一个描述。

如果某个能力在第一个 `terminal-type` 中不再存在，但其他某个 `terminal-type` 条目包含它的值，则该能力会带 at 符号（`@`）打印。如果第一个 `terminal-type` 中的值未在其他任何 `terminal-type` 条目中找到，或者第一个包含该能力的其他 `terminal-type` 条目给出的值与第一个 `terminal-type` 中的值不同，则会打印该能力的值。

其他 `terminal-type` 条目的顺序很重要。由于 terminfo 编译器 `tic` 会从左到右扫描能力，指定两个包含相同能力不同条目的 `use=` 条目时，结果会因条目给出的顺序不同而不同。`infocmp` 会在发现其他 `terminal-type` 条目之间的此类不一致时进行标记。

另外，如果在包含某个能力的 `use=` 条目之后指定该能力，会导致第二个规范被忽略。使用 `infocmp` 重建描述可以作为有用的检查，以确保原始源描述中所有内容都正确指定。

另一个不会导致编译文件错误、但会减慢编译时间的错误是：指定了多余的、不必要的 `use=` 字段。`infocmp` 会标记任何其他不需要的 `terminal-type use=` 字段。

### 更改数据库 [`-A` `directory`] [`-B` `directory`]

与其他 `ncurses` 工具一样，`infocmp` 会在多个位置查找终端描述。可以使用 `TERMINFO` 和 `TERMINFO_DIRS` 环境变量覆盖编译内置的默认搜索位置列表。参见 `curses(3X)`，以及 `terminfo(5)` 中的“获取已编译描述”一节。

在比较终端描述时，也可以使用 `-A` 和 `-B` 选项覆盖搜索位置列表：

- `-A` 选项设置第一个 `terminal-type` 的位置
- `-B` 选项设置其他 `terminal-types` 的位置

使用这些选项，可以比较位于两个不同数据库中的同名终端的描述。例如，可以使用此功能比较不同人创建的同一终端的描述。

### 其他选项

- `-0`  
    使字段打印在一行中，不换行。

- `-1`  
    使字段每行打印一个。否则，字段会每行打印多个，最大宽度为 60 个字符。

- `-a`  
    告诉 `infocmp` 保留被注释掉的能力，而不是丢弃它们。能力通过前缀句点来注释。

- `-D`  
    告诉 `infocmp` 打印它知道的数据库位置，然后退出。

- `-E`  
    将给定终端的能力转储为表，这些表是 `TERMTYPE` 结构（`<term.h>` 中的终端能力结构）的 C 初始化器所需要的。此选项适用于准备为给定终端类型硬编码的 curses 库版本。所有表都声明为 `static`，并根据对应终端条目的类型和名称命名。

    在 `ncurses` 5.0 之前，不需要区分 `-e` 和 `-E` 选项；但对扩展名称的支持要求将终端能力数组与 `TERMTYPE` 结构分离。

- `-e`  
    将给定终端的能力转储为 `TERMTYPE` 结构（`<term.h>` 中的终端能力结构）的 C 初始化器。此选项适用于准备为给定终端类型硬编码的 curses 库版本。

- `-F`  
    比较 terminfo 文件。这假定后面两个参数是文件名。会在文件中搜索条目之间的成对匹配，如果两个条目的任一名称相同，则认为它们匹配。打印到标准输出的报告会列出在另一个文件中没有匹配的条目，以及有多个匹配的条目。对于恰好只有一个匹配的条目，会包含差异报告。通常，为减少报告量，在查找差异之前不会解析 `use` 引用，但也可以通过同时指定 `-r` 强制解析。

- `-f`  
    显示包含 if/then/else/endif 表达式的复杂 terminfo 字符串，并进行缩进以提高可读性。

- `-G`  
    以十进制形式显示常量字面量，而不是其字符等价形式。

- `-g`  
    以带引号形式显示常量字符字面量，而不是其十进制等价形式。

- `-i`  
    分析条目中的初始化字符串（`is1`、`is2`、`is3`）和重置字符串（`rs1`、`rs2`、`rs3`），以及用于启动/停止光标定位模式的字符串（`smcup`、`rmcup`）和启动/停止键盘映射模式的字符串（`smkx`、`rmkx`）。

    对于每个字符串，代码会尝试将其分析为以下动作：条目中的其他能力、某些 X3.64/ISO 6429/ECMA-48 能力，以及某些 DEC VT 系列私有模式（所识别的特殊序列集合是为了完整性而选择的，优先于现有 terminfo 数据库）。每个报告行由能力名、冒号和空格，以及能力字符串的可打印展开组成，其中匹配已识别动作的部分会转换为 `{}` 括起的描述。

    以下是识别到的 DEC/ANSI 特殊序列：

    动作, 含义

    - `RIS`  
        完全重置

    - `SC`  
        保存光标

    - `RC`  
        恢复光标

    - `LL`  
        移到左下角（home-down）

    - `RSR`  
        重置滚动区域

    - `DECSTR`  
        软重置（VT320）

    - `S7C1T`  
        7 位控制（VT220）

    - `ISO DEC G0`  
        为 G0 启用 DEC 图形

    - `ISO UK G0`  
        为 G0 启用 UK 字符

    - `ISO US G0`  
        为 G0 启用 US 字符

    - `ISO DEC G1`  
        为 G1 启用 DEC 图形

    - `ISO UK G1`  
        为 G1 启用 UK 字符

    - `ISO US G1`  
        为 G1 启用 US 字符

    - `DECPAM`  
        应用小键盘模式

    - `DECPNM`  
        普通小键盘模式

    - `DECANSI`  
        进入 ANSI 模式

    - `ECMA[+-]AM`  
        键盘动作模式

    - `ECMA[+-]IRM`  
        插入/替换模式

    - `ECMA[+-]SRM`  
        发送/接收模式

    - `ECMA[+-]LNM`  
        换行模式

    - `DEC[+-]CKM`  
        应用光标键

    - `DEC[+-]ANM`  
        设置 VT52 模式

    - `DEC[+-]COLM`  
        132 列模式

    - `DEC[+-]SCLM`  
        平滑滚动

    - `DEC[+-]SCNM`  
        反显模式

    - `DEC[+-]OM`  
        原点模式

    - `DEC[+-]AWM`  
        自动换行模式

    - `DEC[+-]ARM`  
        自动重复模式

    它还识别对应于 ANSI/ISO 6429/ECMA Set Graphics Rendition 的 `SGR` 动作，其值为 `NORMAL`、`BOLD`、`UNDERLINE`、`BLINK` 和 `REVERSE`。除 `NORMAL` 外，都可以加上前缀：

    - `+`（开启），或
    - `-`（关闭）。

    `SGR0` 表示空高亮序列（等价于 `{SGR:NORMAL}`）。

- `-l`  
    将输出格式设置为 terminfo。

- `-p`  
    比较字符串时忽略填充规范。

- `-Q` `n`  
    不显示 terminfo（文本）格式的源，而是根据选项值以十六进制或 base64 形式打印已编译（二进制）格式：

    - `1`  
        十六进制

    - `2`  
        base64

    - `3`  
        十六进制和 base64

    例如，以下命令会打印已编译的 terminfo 值作为字符串，可将其赋值给 `TERMINFO` 环境变量：

    ```sh
    infocmp -0 -q -Q2
    ```

- `-q`  
    使输出稍微简短一些：

    - 通过省略子标题，并使用 `-` 表示缺失能力、`@` 表示取消能力而不是 `NULL`，使比较列表更短。
    - 但是，显示缺失能力和取消能力之间的差异。
    - 对于源清单，省略 “Reconstructed from” 注释。

- `-R` `subset`  
    将输出限制为给定子集。此选项用于与旧版 terminfo 一起使用，例如 SVr1、Ultrix 或 HP-UX 上的版本，它们不支持完整的 SVR4/XSI Curses terminfo；也用于 AIX 等具有自己的扩展、与 SVr4/XSI 不兼容的变体。

    - 可用的 terminfo 子集有 `SVr1`、`Ultrix`、`HP` 和 `AIX`；详情参见 `terminfo(5)`。
    - 也可以选择子集 `BSD`，它仅选择 4.4BSD 识别的具有 termcap 等价项的能力。
    - 如果为 `-R` 选择任何其他值，则等同于没有子集，即使用所有能力。

    如果某些选项在命令参数中稍后处理，它们会覆盖通过 `-R` 选择的子集：

    - `-C`  
        作为副作用设置 `BSD` 子集。

    - `-I`  
        将子集设置为所有能力。

    - `-r`  
        将子集设置为所有能力。

- `-s` `[d|i|l|c]`  
    `-s` 选项根据以下参数对每个类型内的字段排序：

    - `d`  
        保持字段按它们在 `terminfo` 数据库中存储的顺序。

    - `i`  
        按 `terminfo` 名称排序。

    - `l`  
        按长 C 变量名排序。

    - `c`  
        按 `termcap` 名称排序。

    如果未给出 `-s` 选项，打印出的字段会在每个类型内按 `terminfo` 名称字母排序，除非使用了 `-C` 或 `-L` 选项，此时分别按 `termcap` 名称或长 C 变量名排序。

- `-T`  
    消除对生成文本的大小限制。这主要用于测试和分析，因为编译后的描述是有限的（例如，termcap 为 1023，terminfo 为 4096）。

- `-t`  
    告诉 `tic` 丢弃被注释掉的能力。通常，在从 terminfo 转换为 termcap 时，无法翻译的能力会被注释掉。

- `-U`  
    告诉 `infocmp` 在解析源文件后不对数据进行后处理。此功能有助于比较两个源文件的实际内容，因为它排除了 `infocmp` 为填充缺失数据所做的推断。

- `-V`  
    报告此程序中使用的 `ncurses` 版本，然后退出。

- `-v` `n`  
    在程序运行时将跟踪信息打印到标准错误。

    可选参数 `n` 是 1 到 10（含）的数字，表示所需的信息详细程度。如果 `ncurses` 构建时没有跟踪支持，则忽略可选参数。

- `-W`  
    单独使用 `-w` 选项不会强制长字符串换行。使用 `-W` 选项来做到这一点。

- `-w` `width`  
    将输出更改为 `width` 个字符。

- `-x`  
    打印用户定义能力的信息（参见 `user_caps(5)`）。这些是 terminfo 能力集的扩展，可以使用 `tic` 的 `-x` 选项加载。

## 扩展

`-0`、`-1`、`-a`、`-e`、`-E`、`-f`、`-F`、`-g`、`-G`、`-i`、`-l`、`-p`、`-q`、`-Q`、`-R`、`-t`、`-T` 和 `-V` 选项是 `ncurses` 扩展。

## 可移植性

X/Open Curses Issue 7（2009）规定了 `infocmp`。它没有提到用于生成 `termcap` 格式描述的选项。

SVr4 `infocmp` 不区分缺失能力和取消能力。此外，它将缺失的整数能力报告为 `-1`（其内部表示）。`ncurses` 将这些显示为 `NULL`，以与缺失字符串能力保持一致。

`ncurses` `infocmp` 的 `-r` 选项使用 SVr4 的“termcap”能力概念。BSD `curses` 有更受限的集合。要仅查看 4.4BSD 中存在的能力，请使用 `-r -RBSD`。

## 历史

尽管 System V Release 2 提供了 terminfo 库，但它没有用于反编译终端描述的文档化工具。Tony Hansen（AT&T）于 1984 年初为 System V Release 3 编写了第一个 `infocmp`。

Eric Raymond 在 1995 年使用 AT&T 文档为 `ncurses` 提供了等效的 `infocmp`。此外，他还添加了一些新功能，例如：

- `-e` 选项，用于支持回退（编译内置）终端描述
- `-i` 选项，用于帮助分析

后来，Thomas Dickey 添加了 `-x`（用户定义能力）选项，以及用于支持带用户定义能力的回退条目的 `-E` 选项。

完整列表请参见“扩展”一节。

2010 年，Roy Marples 为 NetBSD 提供了一个 `infocmp` 程序。它的能力不如 SVr4 或 `ncurses` 版本（例如，它缺少 X/Open 中记录的排序选项），但确实包含改编自 `ncurses` 的 `-x` 选项。

## 缺陷

`infocmp(1M)` 的 `-F` 选项应该是一个 `toe(1M)` 模式。
