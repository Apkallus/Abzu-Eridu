# xxd(1) - Linux 手册页

## 名称

`xxd` - 制作十六进制转储或执行反向操作。

## 概要

```sh
xxd -h[elp]
xxd [options] [infile [outfile]]
xxd -r[evert] [options] [infile [outfile]]
```

## 描述

`xxd` 为给定文件或标准输入创建十六进制转储。它还可以将十六进制转储转换回原始二进制形式。与 “uuencode(1)” 和 “uudecode(1)” 类似，它允许以“邮件安全”的 ASCII 表示形式传输二进制数据，但其优点是可以解码到标准输出。此外，它还可用于执行二进制文件修补。

## 选项

如果未给出 `infile`，则读取标准输入。如果 `infile` 指定为 `-` 字符，则从标准输入获取输入。如果未给出 `outfile`（或在其位置使用 `-` 字符），则结果发送到标准输出。

注意，使用了一个“惰性”解析器，除非选项后跟参数，否则它不会检查超过第一个选项字母的内容。单个选项字母与其参数之间的空格是可选的。选项参数可以用十进制、十六进制或八进制表示法指定。因此，`-c8`、`-c 8`、`-c 010` 和 `-cols 8` 都是等价的。

- `-a`, `-autoskip`  
    切换自动跳过：单个 `*` 替换 `nul` 行。默认关闭。

- `-b`, `-bits`  
    切换到二进制位（二进制数字）转储，而不是十六进制转储。此选项将八位字节写为八个 `1` 和 `0` 数字，而不是常规十六进制转储。每行前面有十六进制行号，后面有 ASCII（或 EBCDIC）表示。命令行开关 `-r`、`-p`、`-i` 不适用于此模式。

- `-c cols`, `-cols cols`  
    每行格式化 `<cols>` 个八位字节。默认 `16`（`-i`：`12`，`-ps`：`30`，`-b`：`6`）。最大 `256`。

- `-E`, `-EBCDIC`  
    将右栏的字符编码从 ASCII 改为 EBCDIC。这不会改变十六进制表示。该选项与 `-r`、`-p` 或 `-i` 组合时无意义。

- `-g bytes`, `-groupsize bytes`  
    用空白分隔每 `<bytes>` 字节（每个为两个十六进制字符或八个位数字）的输出。指定 `-g 0` 以抑制分组。`<bytes>` 在普通模式下默认为 `2`，在位模式下默认为 `1`。分组不适用于 PostScript 或 include 样式。

- `-h`, `-help`  
    打印可用命令摘要并退出。不执行十六进制转储。

- `-i`, `-include`  
    以 C include 文件样式输出。除非 `xxd` 从标准输入读取，否则会写入完整的静态数组定义（以输入文件命名）。

- `-l len`, `-len len`  
    写入 `<len>` 个八位字节后停止。

- `-p`, `-ps`, `-postscript`, `-plain`  
    以 PostScript 连续十六进制转储样式输出。也称为纯十六进制转储样式。

- `-r`, `-revert`  
    反向操作：将十六进制转储转换（或修补）为二进制。如果不写入标准输出，`xxd` 会写入其输出文件而不截断它。使用 `-r -p` 组合可读取不含行号信息且没有特定列布局的纯十六进制转储。允许在任何位置出现额外空白和换行。

- `-seek offset`  
    在 `-r` 之后使用时：还原时将 `<offset>` 加到十六进制转储中找到的文件位置上。

- `-s [+][-]seek`  
    从 `<seek>` 字节的绝对（或相对）输入文件偏移量开始。`+` 表示 seek 相对于当前标准输入文件位置（当不是从标准输入读取时无意义）。`-` 表示 seek 应从输入末尾往前那么多字符（或者如果与 `+` 组合：在当前标准输入文件位置之前）。没有 `-s` 选项时，`xxd` 从当前文件位置开始。

- `-u`  
    使用大写十六进制字母。默认为小写。

- `-v`, `-version`  
    显示版本字符串。

## 注意事项

`xxd -r` 在评估行号信息时有一些内置魔法。如果输出文件可 seek，那么每个十六进制转储行开头的行号可能乱序、缺失或重叠。在这些情况下，`xxd` 会 “lseek(2)” 到下一个位置。如果输出文件不可 seek，则只允许间隙，这些间隙将由空字节填充。

`xxd -r` 从不产生解析错误。垃圾内容会被静默跳过。

编辑十六进制转储时请注意，`xxd -r` 在读取足够列的十六进制数据（参见选项 `-c`）后，会跳过输入行上的所有内容。这也意味着，对可打印 ASCII（或 EBCDIC）列的更改始终会被忽略。使用 `xxd -r -p` 还原纯（或 PostScript）样式十六进制转储不依赖于正确的列数。这里任何看起来像一对十六进制数字的内容都会被解释。

注意以下两者的区别：

```console
% xxd -i file
```

与

```console
% xxd -i < file
```

`xxd -s +seek` 可能与 `xxd -s seek` 不同，因为 “lseek(2)” 用于“回退”输入。如果输入源是标准输入，并且到启动 `xxd` 并向其提供输入时，标准输入的文件位置不在文件开头，那么 `+` 会产生差异。以下示例可能有助于澄清（或进一步混淆！）……

读取前回退标准输入；这是必需的，因为 `cat` 已经读到标准输入末尾。

```console
% sh -c "cat > plain_copy; xxd -s 0 > hex_copy" < file
```

从文件位置 `0x480`（=1024+128）开始进行十六进制转储。`+` 号表示“相对于当前位置”，因此 `128` 会加到 `dd` 停止处的 1k 上。

```console
% sh -c "dd of=plain_snippet bs=1k count=1; xxd -s +128 > hex_snippet" < file
```

从文件位置 `0x100`（=1024-768）开始进行十六进制转储。

```console
% sh -c "dd of=plain_snippet bs=1k count=1; xxd -s +-768 > hex_snippet" < file
```

然而，这种情况很少见，`+` 的使用也很少需要。每当使用 `-s` 时，作者更倾向于用 “strace(1)” 或 “truss(1)” 监视 `xxd` 的效果。

## 示例

打印 `file` 除前三行（十六进制 `0x30` 字节）之外的所有内容。

```console
% xxd -s 0x30 file
```

从 `file` 末尾打印 3 行（十六进制 `0x30` 字节）。

```console
% xxd -s -0x30 file
```

以每行 20 个八位字节的连续十六进制转储打印 120 字节。

仅显示文件 `xxd.1` 中的日期。

```
% xxd -s 0x36 -l 13 -c 13 xxd.1
0000036: 3231 7374 204d 6179 2031 3939 36 21st May 1996
```

将 `input_file` 复制到 `output_file`，并在前面添加 100 个值为 `0x00` 的字节。

```console
% xxd input_file | xxd -r -s 100 > output_file
```

修补文件 `xxd.1` 中的日期。

```
% echo "0000037: 3574 68" | xxd -r - xxd.1
% xxd -s 0x36 -l 13 -c 13 xxd.1
0000036: 3235 7468 204d 6179 2031 3939 36 25th May 1996
```

创建一个 65537 字节的文件，所有字节均为 `0x00`，最后一个字节为 `'A'`（十六进制 `0x41`）。

```console
% echo "010000: 41" | xxd -r > file
```

使用自动跳过对该文件进行十六进制转储。

```
% xxd -a -c 12 file
0000000: 0000 0000 0000 0000 0000 0000 ............
*
000fffc: 0000 0000 40 ....A
```

创建一个包含单个 `'A'` 字符的 1 字节文件。`-r -s` 后的数字会加到文件中的行号上；实际上，前导字节被抑制。

```console
% echo "010000: 41" | xxd -r -s -0x10000 > file
```

在诸如 “vim(1)” 之类的编辑器中将 `xxd` 用作过滤器，以对标记在 `'a'` 和 `'z'` 之间的区域进行十六进制转储。

```vim
:'a,'z!xxd
```

在诸如 “vim(1)” 之类的编辑器中将 `xxd` 用作过滤器，以恢复标记在 `'a'` 和 `'z'` 之间的二进制十六进制转储。

```vim
:'a,'z!xxd -r
```

在诸如 “vim(1)” 之类的编辑器中将 `xxd` 用作过滤器，以恢复十六进制转储的一行。将光标移到该行并输入：

```vim
!!xxd -r
```

从串行线路读取单个字符

```console
% xxd -c1 < /dev/term/b &
% stty < /dev/term/b -echo -opost -isig -icanon min 1
% echo -n foo > /dev/term/b
```

## 返回值

返回以下错误值：

- `0`  
    未遇到错误。

- `-1`  
    操作不受支持（`xxd -r -i` 仍不可能）。

- `1`  
    解析选项时出错。

- `2`  
    输入文件有问题。

- `3`  
    输出文件有问题。

- `4`, `5`  
    无法到达期望的 seek 位置。
