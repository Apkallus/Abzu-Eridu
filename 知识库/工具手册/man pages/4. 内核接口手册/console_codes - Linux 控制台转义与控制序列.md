# `console_codes` - Linux 控制台转义与控制序列

## DESCRIPTION

Linux 控制台实现了 VT102 与 ECMA-48 / ISO/IEC 6429 / ANSI X3.64 终端控制的一个大子集，并额外支持某些私有模式序列，用于修改调色板、字符集映射等。在下文的表格化描述中，第二列给出对应功能的 ECMA-48 或 DEC 助记符（若带 DEC 前缀则为后者）。没有助记符的序列既不属于 ECMA-48，也不属于 VT102。

在所有正常输出处理完成之后，当一串字符到达控制台驱动以进行实际打印时，首先发生的是从处理所用编码到打印所用编码的转换。

如果控制台处于 UTF-8 模式，则传入字节首先被组装为 16 位 Unicode 码。否则，每个字节会根据当前映射表进行转换（该映射表将其转换为一个 Unicode 值）。讨论见下文 **字符集** 一节。

在通常情况下，Unicode 值会被转换为字体索引，并存入视频内存，从而使对应字形（位于视频 ROM 中）出现在屏幕上。注意，使用 Unicode（以及 PC 硬件的设计）允许我们同时使用 512 个不同字形。

如果当前 Unicode 值是控制字符，或者我们当前正在处理一个转义序列，则该值会被特殊处理。它可能不会转换为字体索引并渲染为字形，而是触发光标移动或其他控制功能。讨论见下文 **Linux 控制台控制** 一节。

通常，不应把终端控制硬编码到程序中。Linux 支持 `terminfo(5)` 终端能力数据库。与其手工发出控制台转义序列，几乎总是应当使用能识别 terminfo 的屏幕库或工具，例如 `ncurses(3)`、`tput(1)` 或 `reset(1)`。

### Linux 控制台控制

本节描述在 Linux 控制台上调用特殊功能（即除在当前光标位置写入字形之外的任何功能）的所有控制字符和转义序列。

#### 控制字符

如果某个字符（在根据映射表转换之前）具有以下 14 个码值之一：`00`（`NUL`）、`07`（`BEL`）、`08`（`BS`）、`09`（`HT`）、`0a`（`LF`）、`0b`（`VT`）、`0c`（`FF`）、`0d`（`CR`）、`0e`（`SO`）、`0f`（`SI`）、`18`（`CAN`）、`1a`（`SUB`）、`1b`（`ESC`）、`7f`（`DEL`），那么它就是一个控制字符。可以设置“显示控制字符”模式（见下文），并允许 `07`、`09`、`0b`、`18`、`1a`、`7f` 作为字形显示。另一方面，在 UTF-8 模式下，所有 `00–1f` 码都被视为控制字符，无论是否设置了“显示控制字符”模式。

如果遇到控制字符，它会立即生效，然后被丢弃（即使正处于转义序列中间），转义序列继续处理下一个字符。（不过，`ESC` 会开始一个新的转义序列，可能中止先前未完成的序列；`CAN` 和 `SUB` 会中止任何转义序列。）可识别的控制字符为 `BEL`、`BS`、`HT`、`LF`、`VT`、`FF`、`CR`、`SO`、`SI`、`CAN`、`SUB`、`ESC`、`DEL`、`CSI`。它们执行人们预期的操作：

- `BEL`（`0x07`，`^G`）  
    蜂鸣；

- `BS`（`0x08`，`^H`）  
    向后退一列（但不越过行首）；

- `HT`（`0x09`，`^I`）  
    转到下一个制表位；如果前面没有制表位，则转到行尾；

- `LF`（`0x0A`，`^J`）、`VT`（`0x0B`，`^K`）、`FF`（`0x0C`，`^L`）  
    均产生换行；如果设置了 LF/NL（换行模式），还会产生回车；

- `CR`（`0x0D`，`^M`）  
    产生回车；

- `SO`（`0x0E`，`^N`）  
    激活 G1 字符集；

- `SI`（`0x0F`，`^O`）  
    激活 G0 字符集；

- `CAN`（`0x18`，`^X`）、`SUB`（`0x1A`，`^Z`）  
    中止转义序列；

- `ESC`（`0x1B`，`^[`）  
    开始一个转义序列；

- `DEL`（`0x7F`）  
    被忽略；

- `CSI`（`0x9B`）  
    等价于 `ESC [`。

#### ESC 序列（非 CSI 序列）

- `ESC c`（`RIS`）  
    重置。

- `ESC D`（`IND`）  
    换行。

- `ESC E`（`NEL`）  
    新行。

- `ESC H`（`HTS`）  
    在当前列设置制表位。

- `ESC M`（`RI`）  
    反向换行。

- `ESC Z`（`DECID`）  
    DEC 私有标识。内核返回字符串 `ESC [ ? 6 c`，声称自己是 VT102。

- `ESC 7`（`DECSC`）  
    保存当前状态（光标坐标、属性、G0/G1 指向的字符集）。

- `ESC 8`（`DECRC`）  
    恢复最近由 `ESC 7` 保存的状态。

- `ESC %`  
    开始选择字符集的序列。

    - `ESC % @`：选择默认（ISO/IEC 646 / ISO/IEC 8859-1）。
    - `ESC % G`：选择 UTF-8。
    - `ESC % 8`：选择 UTF-8（已过时）。

- `ESC # 8`（`DECALN`）  
    DEC 屏幕对齐测试——用 `E` 填满屏幕。

- `ESC (`  
    开始定义 G0 字符集（后跟 `B`、`0`、`U`、`K` 之一，如下）。

    - `ESC ( B`：选择默认（ISO/IEC 8859-1 映射）。
    - `ESC ( 0`：选择 VT100 图形映射。
    - `ESC ( U`：选择空映射——直接使用字符 ROM。
    - `ESC ( K`：选择用户映射——由工具 `mapscrn(8)` 加载的映射。

- `ESC )`  
    开始定义 G1（后跟 `B`、`0`、`U`、`K` 之一，同上）。

- `ESC >`（`DECPNM`）  
    设置数字小键盘模式。

- `ESC =`（`DECPAM`）  
    设置应用小键盘模式。

- `ESC ]`（`OSC`）  
    操作系统命令前缀。

- `ESC ] R`  
    重置调色板。

- `ESC ] P`  
    设置调色板，参数在最后的 `P` 之后以 7 个十六进制数字 `nrrggbb` 给出。其中 `n` 是颜色（`0–15`），`rrggbb` 表示红/绿/蓝值（`0–255`）。

#### ECMA-48 CSI 序列

`CSI`（或 `ESC [`）后跟一串参数，最多 `NPAR`（`16`）个，这些参数是用分号分隔的十进制数。空参数或缺失参数取为 `0`。参数序列前可以有一个问号。

不过，在 `CSI [`（或 `ESC [ [`）之后会读取单个字符，并且整个序列被忽略。（其思路是忽略回显的功能键。）

CSI 序列的动作由其最终字符决定。

- `@`（`ICH`）  
    插入指定数量的空白字符。

- `A`（`CUU`）  
    将光标向上移动指定行数。

- `B`（`CUD`）  
    将光标向下移动指定行数。

- `C`（`CUF`）  
    将光标向右移动指定列数。

- `D`（`CUB`）  
    将光标向左移动指定列数。

- `E`（`CNL`）  
    将光标向下移动指定行数，并移到第 1 列。

- `F`（`CPL`）  
    将光标向上移动指定行数，并移到第 1 列。

- `G`（`CHA`）  
    将光标移到当前行的指定列。

- `H`（`CUP`）  
    将光标移到指定行、列（原点为 `1,1`）。

- `J`（`ED`）  
    擦除显示（默认：从光标到显示末尾）。

    - `ESC [ 1 J`：从开头擦除到光标。
    - `ESC [ 2 J`：擦除整个显示。
    - `ESC [ 3 J`：擦除整个显示，包括回滚缓冲区（自 Linux 3.0 起）。

- `K`（`EL`）  
    擦除行（默认：从光标到行尾）。

    - `ESC [ 1 K`：从行首擦除到光标。
    - `ESC [ 2 K`：擦除整行。

- `L`（`IL`）  
    插入指定数量的空白行。

- `M`（`DL`）  
    删除指定数量的行。

- `P`（`DCH`）  
    删除当前行上指定数量的字符。

- `X`（`ECH`）  
    擦除当前行上指定数量的字符。

- `a`（`HPR`）  
    将光标向右移动指定列数。

- `c`（`DA`）  
    回答 `ESC [ ? 6 c`：“我是 VT102”。

- `d`（`VPA`）  
    将光标移到指定行、当前列。

- `e`（`VPR`）  
    将光标向下移动指定行数。

- `f`（`HVP`）  
    将光标移到指定行、列。

- `g`（`TBC`）  
    无参数：清除当前位置的制表位。  
    `ESC [ 3 g`：删除所有制表位。

- `h`（`SM`）  
    设置模式（见下文）。

- `l`（`RM`）  
    重置模式（见下文）。

- `m`（`SGR`）  
    设置属性（见下文）。

- `n`（`DSR`）  
    状态报告（见下文）。

- `q`（`DECLL`）  
    设置键盘 LED。

    - `ESC [ 0 q`：清除所有 LED。
    - `ESC [ 1 q`：设置 Scroll Lock LED。
    - `ESC [ 2 q`：设置 Num Lock LED。
    - `ESC [ 3 q`：设置 Caps Lock LED。

- `r`（`DECSTBM`）  
    设置滚动区域；参数为顶行和底行。

- `s`（`SCOSC`）  
    保存光标位置。

- `u`（`SCORC`）  
    恢复光标位置。

- `` ` ``（`HPA`）  
    将光标移到当前行的指定列。

#### ECMA-48 选择图形再现（SGR）

ECMA-48 SGR 序列 `ESC [ parameters m` 设置显示属性。可以在同一序列中设置多个属性，用分号分隔。空参数（位于分号之间、字符串起始符或终止符处）被解释为零。

- `0`  
    将所有属性重置为默认值。

- `1`  
    设置粗体。

- `2`  
    设置半亮（在彩色显示器上用颜色模拟）。

- `3`  
    设置斜体（自 Linux 2.6.22 起；在彩色显示器上用颜色模拟）。

- `4`  
    设置下划线（在彩色显示器上用颜色模拟）（用于模拟暗色或下划线的颜色通过 `ESC ] ...` 设置）。

- `5`  
    设置闪烁。

- `7`  
    设置反显。

- `10`  
    重置选定的映射、显示控制标志，并切换 meta 标志（ECMA-48 称之为“主字体”）。

- `11`  
    选择空映射，设置显示控制标志，重置 toggle meta 标志（ECMA-48 称之为“第一替代字体”）。

- `12`  
    选择空映射，设置显示控制标志，设置 toggle meta 标志（ECMA-48 称之为“第二替代字体”）。toggle meta 标志会使字节的高位在映射表转换之前被翻转。

- `21`  
    设置下划线；在 Linux 4.17 之前，此值设置正常强度（正如许多其他终端所做的那样）。

- `22`  
    设置正常强度。

- `23`  
    关闭斜体（自 Linux 2.6.22 起）。

- `24`  
    关闭下划线。

- `25`  
    关闭闪烁。

- `27`  
    关闭反显。

- `30`  
    设置黑色前景。

- `31`  
    设置红色前景。

- `32`  
    设置绿色前景。

- `33`  
    设置棕色前景。

- `34`  
    设置蓝色前景。

- `35`  
    设置品红色前景。

- `36`  
    设置青色前景。

- `37`  
    设置白色前景。

- `38`  
    后续为 256/24 位前景色，被塞入 16 种基本颜色（Linux 3.16 之前：开启下划线并设置默认前景色）。

- `39`  
    设置默认前景色（Linux 3.16 之前：关闭下划线并设置默认前景色）。

- `40`  
    设置黑色背景。

- `41`  
    设置红色背景。

- `42`  
    设置绿色背景。

- `43`  
    设置棕色背景。

- `44`  
    设置蓝色背景。

- `45`  
    设置品红色背景。

- `46`  
    设置青色背景。

- `47`  
    设置白色背景。

- `48`  
    后续为 256/24 位背景色，被塞入 8 种基本颜色。

- `49`  
    设置默认背景色。

- `90..97`  
    将前景设置为 `30..37` 的亮色版本。

- `100..107`  
    设置背景，与 `40..47` 相同（不支持亮色）。

命令 `38` 和 `48` 需要进一步参数：

- `;5;x`  
    256 色：值 `0..15` 为 IBGR（黑、红、绿、……、白），`16..231` 为 6×6×6 色立方，`232..255` 为灰度渐变。

- `;2;r;g;b`  
    24 位色，`r`/`g`/`b` 分量范围为 `0..255`。

#### ECMA-48 模式开关

- `ESC [ 3 h`  
    `DECCRM`（默认关闭）：显示控制字符。

- `ESC [ 4 h`  
    `DECIM`（默认关闭）：设置插入模式。

- `ESC [ 20 h`  
    `LF/NL`（默认关闭）：在回显 `LF`、`VT` 或 `FF` 后自动跟随 `CR`。

#### ECMA-48 状态报告命令

- `ESC [ 5 n`  
    设备状态报告（`DSR`）：回答为 `ESC [ 0 n`（终端正常）。

- `ESC [ 6 n`  
    光标位置报告（`CPR`）：回答为 `ESC [ y ; x R`，其中 `x,y` 是光标位置。

#### DEC 私有模式（DECSET/DECRST）序列

这些序列未在 ECMA-48 中描述。下面列出设置模式序列；将末尾的 `h` 替换为 `l` 即可得到重置模式序列。

- `ESC [ ? 1 h`  
    `DECCKM`（默认关闭）：设置后，光标键发送 `ESC O` 前缀，而不是 `ESC [`。

- `ESC [ ? 3 h`  
    `DECCOLM`（默认关闭 = 80 列）：80/132 列模式切换。驱动源码指出，仅此还不够；需要某些用户态工具（例如 `resizecons(8)`）修改控制台视频卡上的硬件寄存器。

- `ESC [ ? 5 h`  
    `DECSCNM`（默认关闭）：设置反显模式。

- `ESC [ ? 6 h`  
    `DECOM`（默认关闭）：设置后，光标寻址相对于滚动区域的左上角。

- `ESC [ ? 7 h`  
    `DECAWM`（默认开启）：开启自动换行。在此模式下，在第 80 列（若 `DECCOLM` 开启则为第 132 列）之后发出的图形字符会先强制换行到下一行开头。

- `ESC [ ? 8 h`  
    `DECARM`（默认开启）：开启键盘自动重复。

- `ESC [ ? 9 h`  
    X10 鼠标报告（默认关闭）：将报告模式设为 1（或重置为 0）——见下文。

- `ESC [ ? 25 h`  
    `DECTECM`（默认开启）：使光标可见。

- `ESC [ ? 1000 h`  
    X11 鼠标报告（默认关闭）：将报告模式设为 2（或重置为 0）——见下文。

#### Linux 控制台私有 CSI 序列

以下序列既不属于 ECMA-48，也不是原生 VT102。它们是 Linux 控制台驱动原生的。颜色使用 SGR 参数：`0` = 黑，`1` = 红，`2` = 绿，`3` = 棕，`4` = 蓝，`5` = 品红，`6` = 青，`7` = 白；`8–15` = `0–7` 的亮色版本。

- `ESC [ 1 ; n ]`  
    将颜色 `n` 设为下划线颜色。

- `ESC [ 2 ; n ]`  
    将颜色 `n` 设为暗色。

- `ESC [ 8 ]`  
    使当前颜色对成为默认属性。

- `ESC [ 9 ; n ]`  
    将屏幕空白超时设为 `n` 分钟。

- `ESC [ 10 ; n ]`  
    设置蜂鸣频率（Hz）。

- `ESC [ 11 ; n ]`  
    设置蜂鸣持续时间（毫秒）。

- `ESC [ 12 ; n ]`  
    将指定控制台带到前台。

- `ESC [ 13 ]`  
    取消屏幕空白。

- `ESC [ 14 ; n ]`  
    设置 VESA 掉电间隔（分钟）。

- `ESC [ 15 ]`  
    将上一个控制台带到前台（自 Linux 2.6.0 起）。

- `ESC [ 16 ; n ]`  
    设置光标闪烁间隔（毫秒）（自 Linux 4.2 起）。

### 字符集

内核知道 4 种从字节到控制台屏幕符号的转换。四个表为：a) Latin1 -> PC，b) VT100 图形 -> PC，c) PC -> PC，d) 用户定义。

有两个字符集，称为 `G0` 和 `G1`，其中一个是当前字符集。（初始为 `G0`。）键入 `^N` 会使 `G1` 成为当前字符集，`^O` 会使 `G0` 成为当前字符集。

这些变量 `G0` 和 `G1` 指向转换表，并可由用户更改。初始时它们分别指向表 a) 和 b)。序列 `ESC ( B`、`ESC ( 0`、`ESC ( U`、`ESC ( K` 分别使 `G0` 指向转换表 a)、b)、c)、d)。序列 `ESC ) B`、`ESC ) 0`、`ESC ) U`、`ESC ) K` 分别使 `G1` 指向转换表 a)、b)、c)、d)。

序列 `ESC c` 会导致终端重置；如果屏幕完全乱码，这正是你想要的。常被建议的 `echo ^V^O` 只会使 `G0` 成为当前字符集，但不能保证 `G0` 指向表 a)。在某些发行版中有一个程序 `reset(1)`，它只是执行 `echo ^[c`。如果你用于控制台的 terminfo 条目是正确的（并且有 `rs1=\Ec` 条目），那么 `tput reset` 也会起作用。

用户定义映射表可以使用 `mapscrn(8)` 设置。映射的结果是：如果打印符号 `c`，则符号 `s = map[c]` 被发送到视频内存。与 `s` 对应的位图位于字符 ROM 中，并可使用 `setfont(8)` 更改。

### 鼠标跟踪

鼠标跟踪设施旨在返回与 `xterm(1)` 兼容的鼠标状态报告。由于控制台驱动无法知道鼠标的设备或类型，这些报告只有在虚拟终端驱动收到鼠标更新 `ioctl` 时才会返回到控制台输入流中。这些 `ioctl` 必须由能感知鼠标的用户态应用（例如 `gpm(8)` 守护进程）生成。

`xterm(1)` 生成的鼠标跟踪转义序列将数值参数编码为单个字符：`value+040`。例如，`'!'` 是 `1`。屏幕坐标系以 1 为基。

X10 兼容模式在按下按钮时发送一个转义序列，编码位置和按下的鼠标按钮。它通过发送 `ESC [ ? 9 h` 启用，通过 `ESC [ ? 9 l` 禁用。按下按钮时，`xterm(1)` 发送 `ESC [ M bxy`（6 个字符）。其中 `b` 是按钮 1，`x` 和 `y` 是按下按钮时鼠标的 x、y 坐标。内核产生的也是同样的编码。

普通跟踪模式（Linux 2.0.24 中未实现）在按钮按下和释放时都发送转义序列。还会发送修饰键信息。它通过发送 `ESC [ ? 1000 h` 启用，通过 `ESC [ ? 1000 l` 禁用。按下或释放按钮时，`xterm(1)` 发送 `ESC [ M bxy`。`b` 的低两位编码按钮信息：`0`=按下 `MB1`，`1`=按下 `MB2`，`2`=按下 `MB3`，`3`=释放。高位编码按钮按下时按下的修饰键，并将它们相加：`4`=Shift，`8`=Meta，`16`=Control。同样，`x` 和 `y` 是鼠标事件的 x、y 坐标。左上角为 `(1,1)`。

### 与其他终端的比较

许多不同类型的终端（例如 Linux 控制台）都被描述为“VT100 兼容”。这里讨论 Linux 控制台与另外两个最重要的终端——DEC VT102 和 `xterm(1)`——之间的差异。

#### 控制字符处理

VT102 还识别以下控制字符：

- `NUL`（`0x00`）  
    被忽略；

- `ENQ`（`0x05`）  
    触发应答消息；

- `DC1`（`0x11`，`^Q`，XON）  
    恢复传输；

- `DC3`（`0x13`，`^S`，XOFF）  
    使 VT100 忽略（并停止发送）除 XOFF 和 XON 之外的所有码。

终端驱动可以启用类似 VT100 的 `DC1`/`DC3` 处理。

`xterm(1)` 程序（在 VT100 模式下）识别控制字符 `BEL`、`BS`、`HT`、`LF`、`VT`、`FF`、`CR`、`SO`、`SI`、`ESC`。

#### 转义序列

Linux 控制台未实现的 VT100 控制台序列：

- `ESC N`（`SS2`）  
    单次移位 2。（仅对下一个字符选择 G2 字符集。）

- `ESC O`（`SS3`）  
    单次移位 3。（仅对下一个字符选择 G3 字符集。）

- `ESC P`（`DCS`）  
    设备控制字符串（由 `ESC \` 结束）。

- `ESC X`（`SOS`）  
    字符串开始。

- `ESC ^`（`PM`）  
    隐私消息（由 `ESC \` 结束）。

- `ESC \`（`ST`）  
    字符串终止符。

- `ESC * ...`  
    指定 G2 字符集。

- `ESC + ...`  
    指定 G3 字符集。

`xterm(1)` 程序（在 VT100 模式下）识别 `ESC c`、`ESC # 8`、`ESC >`、`ESC =`、`ESC D`、`ESC E`、`ESC H`、`ESC M`、`ESC N`、`ESC O`、`ESC P ... ESC \`、`ESC Z`（它回答 `ESC [ ? 1 ; 2 c`，“我是带高级视频选项的 VT100”），以及 `ESC ^ ... ESC \`，其含义与上面所示相同。它接受 `ESC (`、`ESC )`、`ESC *`、`ESC +` 后跟 `0`、`A`、`B`，分别表示 DEC 特殊字符与画线集、UK、US-ASCII。

用户可以配置 `xterm(1)` 以响应 VT220 特有的控制序列，并且它会根据配置和初始化方式将自己标识为 VT52、VT100 及更高版本。

它接受 `ESC ]`（`OSC`）用于设置某些资源。除了 ECMA-48 字符串终止符（`ST`）之外，`xterm(1)` 还接受 `BEL` 来终止 `OSC` 字符串。以下是 `xterm(1)` 识别的一些 `OSC` 控制序列：

- `ESC ] 0 ; txt ST`  
    将图标名和窗口标题设为 `txt`。

- `ESC ] 1 ; txt ST`  
    将图标名设为 `txt`。

- `ESC ] 2 ; txt ST`  
    将窗口标题设为 `txt`。

- `ESC ] 4 ; num ; txt ST`  
    将颜色 `num`（`0-255`）设为 `txt`。

- `ESC ] 5 ; 0 ; txt ST`  
    设置粗体替代颜色为 `txt`。

- `ESC ] 5 ; 1 ; txt ST`  
    设置下划线替代颜色为 `txt`。

- `ESC ] 5 ; 2 ; txt ST`  
    设置闪烁替代颜色为 `txt`。

- `ESC ] 5 ; 3 ; txt ST`  
    设置反显替代颜色为 `txt`。

- `ESC ] 5 ; 4 ; txt ST`  
    设置斜体替代颜色为 `txt`。

- `ESC ] 6 ; 0 ; val ST`  
    切换粗体再现方式：`0`=粗体，`1`=用颜色替代。

- `ESC ] 6 ; 1 ; val ST`  
    切换下划线再现方式：`0`=下划线，`1`=颜色。

- `ESC ] 6 ; 2 ; val ST`  
    切换闪烁再现方式：`0`=闪烁，`1`=颜色。

- `ESC ] 6 ; 3 ; val ST`  
    切换反显再现方式：`0`=反显，`1`=颜色。

- `ESC ] 6 ; 4 ; val ST`  
    切换斜体再现方式：`0`=斜体，`1`=颜色。

- `ESC ] 10 ; txt ST`  
    将前景文本颜色设为 `txt`。

- `ESC ] 11 ; txt ST`  
    将背景颜色设为 `txt`。

- `ESC ] 12 ; txt ST`  
    将文本光标颜色设为 `txt`。

- `ESC ] 13 ; txt ST`  
    将鼠标光标前景颜色设为 `txt`。

- `ESC ] 14 ; txt ST`  
    将鼠标光标背景颜色设为 `txt`。

- `ESC ] 15 ; txt ST`  
    将 Tektronix 前景颜色设为 `txt`。

- `ESC ] 16 ; txt ST`  
    将 Tektronix 背景颜色设为 `txt`。

- `ESC ] 17 ; txt ST`  
    将高亮（选中）文本的背景文本颜色设为 `txt`。

- `ESC ] 18 ; txt ST`  
    将 Tektronix 光标颜色设为 `txt`。

- `ESC ] 19 ; txt ST`  
    将高亮（选中）文本的前景文本颜色设为 `txt`。

- `ESC ] 46 ; name ST`  
    将日志文件改为 `name`（通常由编译时选项禁用）。

- `ESC ] 50 ; fn ST`  
    将字体设为 `fn`（该转义码通常被禁用；参见 `xterm(1)` 中的 `allowFontOps`）。

- `ESC ] 104 ; num ST`  
    重置模式 4 的颜色；`num`。

- `ESC ] 105 ; num ST`  
    重置模式 5 的颜色；`num`。

- `ESC ] 106 ; num ; val ST`  
    完全等同于 `6;num;val`。（没有“重置”逻辑。）

- `ESC ] 110 ST`  
    重置模式 10 的颜色。码 `111-119` 映射为分别重置模式 `11-19`。

- `ESC ] mode ; ? ST`  
    查询相应属性/颜色等（模式 `4,5,10-19,50`）。

它识别以下序列，但含义略有修改（保存更多状态，行为更接近 VT100/VT220）：

- `ESC 7`（`DECSC`）  
    保存光标。

- `ESC 8`（`DECRC`）  
    恢复光标。

它还识别：

- `ESC F`  
    将光标移到屏幕左下角（如果通过 `xterm(1)` 的 `hpLowerleftBugCompat` 资源启用）。

- `ESC l`  
    内存锁定（按 HP 终端）。锁定光标上方内存。

- `ESC m`  
    内存解锁（按 HP 终端）。

- `ESC n`（`LS2`）  
    调用 G2 字符集。

- `ESC o`（`LS3`）  
    调用 G3 字符集。

- `ESC |`（`LS3R`）  
    将 G3 字符集作为 GR 调用。

- `ESC }`（`LS2R`）  
    将 G2 字符集作为 GR 调用。

- `ESC ~`（`LS1R`）  
    将 G1 字符集作为 GR 调用。

它还识别 `ESC %`，并提供比 Linux 控制台更完整的 UTF-8 实现。

#### CSI 序列

旧版本的 `xterm(1)`（例如来自 X11R5 的版本）将闪烁 SGR 解释为粗体 SGR。后来实现 ANSI 颜色的版本（例如 1995 年的 XFree86 3.1.2A）对此进行了改进，允许闪烁属性显示为颜色。现代版本的 `xterm(1)` 将闪烁 SGR 实现为闪烁文本，同时仍允许彩色文本作为 SGR 的替代渲染。Stock X11R6 版本直到 X11R6.8 发布（该版本合并了 XFree86 `xterm(1)`）才识别设置颜色的 SGR。Linux 识别的所有 ECMA-48 CSI 序列也都被 `xterm(1)` 识别，不过 `xterm(1)` 实现了若干 Linux 不识别的 ECMA-48 和 DEC 控制序列。

`xterm(1)` 程序识别上面列出的所有 DEC 私有模式序列，但不识别任何 Linux 私有模式序列。关于 `xterm(1)` 自身私有模式序列的讨论，请参阅 Edward Moy、Stephen Gildea 和 Thomas E. Dickey 编写的 *Xterm Control Sequences* 文档，该文档随 X 发行版提供。该文档虽然简洁，但比本手册页长得多。按时间顺序的概览：

<http://invisible-island.net/xterm/xterm.log.html>

详细说明了 `xterm(1)` 的变更。

`vttest(1)` 程序

<http://invisible-island.net/vttest/>

演示了许多这些控制序列。`xterm(1)` 源码发行版还包含练习其他功能的示例脚本。

## NOTES

`ESC 8`（`DECRC`）无法恢复通过 `ESC %` 更改的字符集。

## BUGS

在 Linux 2.0.23 中，`CSI` 是损坏的，并且 `NUL` 在转义序列内部不会被忽略。

一些较旧的内核版本（Linux 2.0 之后）会解释 8 位控制序列。这些“C1 控制”使用 `128` 到 `159` 之间的码来替代 `ESC [`、`ESC ]` 以及类似的两字节控制序列起始符。现代内核中仍有其碎片（要么被忽视，要么因支持 UTF-8 的更改而损坏），但实现不完整，应视为不可靠。

Linux“私有模式”序列不遵循 ECMA-48 中关于私有模式控制序列的规则。特别是，以 `]` 结尾的那些序列不使用标准终止字符。`OSC`（设置调色板）序列问题更大，因为 `xterm(1)` 可能将其解释为需要字符串终止符（`ST`）的控制序列。与 `setterm(1)` 序列不同（后者因为无效控制序列而被忽略），调色板序列会让 `xterm(1)` 看起来挂起（不过按回车键可以修复）。为了容纳那些硬编码使用 Linux 控制序列的应用，请将 `xterm(1)` 资源 `brokenLinuxOSC` 设置为 true。

本文档的旧版本暗示 Linux 识别用于不可见文本的 ECMA-48 控制序列。该序列会被忽略。
