# 20.3. 可执行脚本

https://refspecs.linuxfoundation.org/LSB_5.0.0/LSB-Core-generic/LSB-Core-generic/executable-scripts.html

可执行脚本是一种可执行文件，其前两个字符是可移植字符集中定义的 `#!`。在 [POSIX 1003.1-2008 (ISO/IEC 9945-2009)] 中，此构造未定义，但保留给希望提供此功能的实现。符合 LSB 的实现应支持可执行脚本。

以可执行脚本作为第一个参数成功调用 `exec` 族函数时，应产生一个新进程，其中启动的进程映像是解释器的进程映像。解释器的路径名跟在 `#!` 字符之后。

如果可执行脚本的第一行是

```text
#! interpreter [arg]
```

那么调用 `interpreter` 时，参数数组应由未指定的第零个参数、`arg`（如果存在）、脚本的路径名，以及脚本的 `exec` 调用中第零个参数之后的参数组成。

解释器不应对可执行脚本的第一行执行任何操作。

可执行脚本的第一行应满足以下所有条件，否则结果未指定：

1. 是以下形式之一：

    ```text
    #!interpreter
    #! interpreter
    #!interpreter arg
    #! interpreter arg
    ```

2. `interpreter` 参数是某个可执行文件的绝对路径名，且该文件不是可执行脚本。

3. `interpreter` 参数和 `arg` 参数（如果存在）均不包含任何引号字符。

4. `interpreter` 参数和 `arg` 参数（如果存在）均不包含任何空白字符。

5. 整行的长度不超过 80 字节。

如果本规范要求解释器位于某个特定命名目录中，则符合规范的应用必须将该路径用于 `interpreter`，因为不禁止实现在系统上安装同一解释器的其他可能不符合规范的版本。如果解释器是本规范中的必需命令，但没有必需的路径，应用应采取特殊措施以确保选择适当的版本。如果解释器不是本规范中的必需命令，应用必须做出适当安排，确保解释器在适当路径可用。

> **注意：** 如果未指定路径，建议可执行脚本的安装脚本使用通过调用带参数 `PATH` 的 `getconf` 命令返回的标准 `PATH`，并结合 `command` 命令来确定标准命令的位置。
>
> 例如，要确定标准 `awk` 命令的位置：
>
> ```sh
> PATH=`getconf PATH` command -v awk
> ```
>
> 安装脚本应确保返回的路径名在使用前是绝对路径名，因为某些实用程序可能返回 shell 内建命令。
>
> 不推荐使用常见形式 `#!/usr/bin/env interpreter`，因为执行时 `PATH` 未知，可能会选择 `interpreter` 的替代版本。
