# 15 管道与 FIFO

https://sourceware.org/glibc/manual/latest/html_node/Pipes-and-FIFOs.html

`pipe`（管道）是一种进程间通信机制；一个进程写入管道的数据可以被另一个进程读取。数据按先进先出（FIFO）顺序处理。管道没有名称；它为单次使用而创建，并且两端都必须从创建该管道的单个进程继承。

`FIFO special file`（FIFO 特殊文件）与管道类似，但它不是匿名、临时的连接，而是像其他文件一样具有一个或多个名称。进程按名称打开 FIFO，以便通过它进行通信。

管道或 FIFO 必须同时打开两端。如果你从没有任何进程写入的管道或 FIFO 文件读取（也许是因为它们都已关闭该文件或已退出），读取会返回文件末尾。向没有读取进程的管道或 FIFO 写入会被视为错误情况；它会产生 `SIGPIPE` 信号，并且如果该信号被处理或阻塞，则会失败并返回错误码 `EPIPE`。

管道和 FIFO 特殊文件都不允许文件定位。读取和写入操作都按顺序进行；从文件开头读取，并在末尾写入。

## 15.3 FIFO 特殊文件

FIFO 特殊文件与管道类似，但创建方式不同。FIFO 特殊文件不是匿名通信通道，而是通过调用 `mkfifo` 将其加入文件系统。

一旦你以这种方式创建了 FIFO 特殊文件，任何进程都可以像普通文件一样打开它进行读取或写入。然而，在对它进行任何输入或输出操作之前，必须同时打开两端。以读取方式打开 FIFO 通常会阻塞，直到某个其他进程以写入方式打开同一个 FIFO，反之亦然。

`mkfifo` 函数声明在头文件 `sys/stat.h` 中。

> 缺失读写时：普通管道将失败，而命名管道将阻塞

### 函数：int `mkfifo`

```c
int mkfifo(const char *filename, mode_t mode)
```

初步：| MT-Safe | AS-Safe | AC-Safe | 参见 [POSIX 安全概念]。

`mkfifo` 函数创建一个名为 `filename` 的 FIFO 特殊文件。`mode` 参数用于设置文件权限；参见 [分配文件权限]。

`mkfifo` 的正常成功返回值为 `0`。出错时返回 `-1`。除了通常的文件名错误（参见 [文件名错误]）外，此函数还定义了以下 `errno` 错误条件：

- `EEXIST`  
  命名文件已存在。

- `ENOSPC`  
  目录或文件系统无法扩展。

- `EROFS`  
  将包含该文件的目录位于只读文件系统上。
