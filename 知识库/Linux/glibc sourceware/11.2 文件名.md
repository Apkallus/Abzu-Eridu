# 11.2 文件名

https://sourceware.org/glibc/manual/latest/html_node/File-Names.html

为了打开与文件的连接，或执行删除文件等其他操作，你需要某种方式来引用文件。几乎所有文件都有字符串名称——甚至实际上是磁带驱动器或终端等设备的文件也是如此。这些字符串称为*文件名*。你通过指定文件名来说明要打开或操作哪个文件。

本节描述文件名的约定以及操作系统如何处理它们。

## 11.2.2 文件名解析

文件名由以斜杠（`/`）字符分隔的文件名组件组成。在 GNU C 库支持的系统上，多个连续的 `/` 字符等价于单个 `/` 字符。
> 文件路径载荷中包含大量连续 `/` 的文档源

确定一个文件名所指文件的过程称为*文件名解析*。该过程按从左到右的顺序检查构成文件名的各个组件，并在前一个组件所指的目录中定位每个后续组件。当然，每个被引用为目录的文件都必须实际存在、是目录而非普通文件，并具有允许进程访问的适当权限；否则文件名解析失败。

如果文件名以 `/` 开头，则文件名中的第一个组件位于进程的*根目录*中（通常系统上的所有进程具有相同的根目录）。这样的文件名称为*绝对文件名*。

否则，文件名中的第一个组件位于当前工作目录中（参见 [工作目录]）。这种文件名称为*相对文件名*。

文件名组件 `.`（“点”）和 `..`（“双点”）具有特殊含义。每个目录都有这些文件名组件的条目。文件名组件 `.` 指目录本身，而 `..` 指其*父目录*（包含所讨论目录的链接的目录）。作为特殊情况，根目录中的 `..` 指根目录本身，因为它没有父目录；因此 `/..` 与 `/` 相同。

以下是文件名的一些示例：

- `/a`  
    根目录中名为 `a` 的文件。
- `/a/b`  
    根目录中名为 `a` 的目录中名为 `b` 的文件。
- `a`  
    当前工作目录中名为 `a` 的文件。
- `/a/./b`  
    与 `/a/b` 相同。
- `./a`  
    当前工作目录中名为 `a` 的文件。
- `../a`  
    当前工作目录的父目录中名为 `a` 的文件。

命名目录的文件名可以选择以 `/` 结尾。可以指定文件名 `/` 来引用根目录，但空字符串不是有意义的文件名。如果要引用当前工作目录，请使用文件名 `.` 或 `./`。

与某些其他操作系统不同，GNU 系统在文件名语法中不内建支持文件类型（或扩展名）或文件版本。许多程序和实用工具对文件名使用约定——例如，包含 C 源代码的文件通常带有 `.c` 后缀——但文件系统本身没有任何机制强制实施这种约定。
