# 26 基本程序/系统接口

https://sourceware.org/glibc/manual/latest/html_node/Program-Basics.html


*进程*是分配系统资源的原始单元。每个进程都有自己的地址空间，并且（通常）有一个控制线程。进程执行程序；你可以有多个进程执行同一个程序，但每个进程都在自己的地址空间中拥有该程序的自己的副本，并独立于其他副本执行它。尽管同一程序内可能有多个控制线程，并且一个程序可能由多个逻辑上独立的模块组成，但一个进程始终只执行一个程序。

请注意，出于本手册的目的，我们使用“程序”的特定定义，它对应于 Unix 系统上下文中的常见定义。在通俗用法中，“程序”的定义要宽泛得多；例如，它可以指系统内核、编辑器宏、复杂的软件包，或进程中执行的离散代码段。

编写程序正是本手册的全部内容。本章解释你的程序与运行或调用它的系统之间最基本的接口。这包括从系统传递参数（参数和环境）、向系统请求基本服务，以及告诉系统程序已完成。

程序通过 `exec` 系列系统调用启动另一个程序。本章从被 exec 的程序（execee）的角度考察程序启动。要从执行 exec 的程序（execor）的角度查看该事件，参见[执行文件]。

## 26.1 程序参数

https://sourceware.org/glibc/manual/latest/html_node/Program-Arguments.html

系统通过调用函数 `main` 启动 C 程序。你需要编写一个名为 `main` 的函数——否则甚至无法无错误地链接程序。

在 ISO C 中，你可以将 `main` 定义为不接受参数，或接受两个表示程序命令行参数的参数，如下所示：

```c
int main (int argc, char *argv[])
```

命令行参数是用于调用程序的 shell 命令中由空白分隔的标记；因此，在 `cat foo bar` 中，参数是 `foo` 和 `bar`。程序查看其命令行参数的唯一方式是通过 `main` 的参数。如果 `main` 不接受参数，则无法获取命令行。

`argc` 参数的值是命令行参数的数量。`argv` 参数是一个 C 字符串向量；其元素是各个命令行参数字符串。正在运行的程序的文件名也作为第一个元素包含在向量中；`argc` 的值会计入该元素。空指针总是跟在最后一个元素之后：`argv[argc]` 就是这个空指针。

对于命令 `cat foo bar`，`argc` 为 3，`argv` 有三个元素：`"cat"`、`"foo"` 和 `"bar"`。

在 Unix 系统中，你可以用第三种方式定义 `main`，即使用三个参数：

```c
int main (int argc, char *argv[], char *envp[])
```

前两个参数完全相同。第三个参数 `envp` 给出程序的环境；它与 `environ` 的值相同。参见[环境变量]。POSIX.1 不允许这种三参数形式，因此为了可移植性，最好将 `main` 写成接受两个参数，并使用 `environ` 的值。

### 26.1.1 程序参数语法约定

https://sourceware.org/glibc/manual/latest/html_node/Argument-Syntax.html

POSIX 建议对命令行参数采用以下约定。`getopt`（参见[使用 `getopt` 解析程序选项]）和 `argp_parse`（参见[使用 Argp 解析程序选项]）使这些约定易于实现。

- 如果参数以连字符分隔符（`-`）开头，则它们是选项。
- 如果选项不接受参数，多个选项可以跟在单个标记中的连字符分隔符之后。因此，`-abc` 等价于 `-a -b -c`。
- 选项名称是单个字母数字字符（如同 `isalnum`；参见[字符分类]）。
- 某些选项需要参数。例如，`ld` 命令的 `-o` 选项需要一个参数——一个输出文件名。
- 选项及其参数可以或可以不作为单独的标记出现。（换句话说，分隔它们的空白是可选的。）因此，`-o foo` 和 `-ofoo` 是等价的。
- 选项通常位于其他非选项参数之前。

  GNU C 库中 `getopt` 和 `argp_parse` 的实现通常会使解析时看起来好像所有选项参数都在所有非选项参数之前指定，即使你的程序的用户混合了选项和非选项参数。它们通过重新排列 `argv` 数组的元素来实现这一点。此行为是非标准的；如果你想抑制它，请定义 `_POSIX_OPTION_ORDER` 环境变量。参见[标准环境变量]。

- 参数 `--` 终止所有选项；任何后续参数都被视为非选项参数，即使它们以连字符开头。
- 由单个连字符字符组成的标记被解释为普通的非选项参数。按照惯例，它用于指定来自标准输入流和输出流的输入或输出。
- 选项可以以任意顺序提供，或多次出现。解释留给特定的应用程序。

GNU 在这些约定基础上添加了*长选项*。长选项由 `--` 后跟一个由字母数字字符和连字符组成的名称构成。选项名称通常为一到三个单词长，单词之间用连字符分隔。只要缩写唯一，用户可以缩写选项名称。

要为长选项指定参数，请写成 `--name=value`。此语法使长选项能够接受本身可选的参数。

最终，GNU 系统将在 shell 中提供长选项名称的补全。
