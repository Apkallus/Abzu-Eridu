# `ls` — 列出目录内容

https://www.man7.org/linux/man-pages/man1/ls.1p.html

## 概要

```sh
ls [-ikqrs] [-glno] [-A|-a] [-C|-m|-x|-1] \
    [-F|-p] [-H|-L] [-R|-d] [-S|-f|-t] [-c|-u] [file...]
```

## 描述

对于每个命名文件类型不是目录或指向目录的符号链接的操作数，`ls` 应写出文件名以及任何请求的关联信息。对于每个命名文件类型为目录的操作数，`ls` 应写出该目录中包含的文件名以及任何请求的关联信息。以句点（`.`）开头的文件名及任何关联信息不应写出，除非显式引用、提供了 `-A` 或 `-a` 选项，或实现定义的条件导致其被写出。如果指定了一个或多个 `-d`、`-F` 或 `-l` 选项，且未指定 `-H` 或 `-L` 选项，则对于每个命名文件类型为指向目录的符号链接的操作数，`ls` 应写出文件名以及任何请求的关联信息。如果未指定 `-d`、`-F` 或 `-l` 中的任何一个，或指定了 `-H` 或 `-L` 选项，则对于每个命名文件类型为指向目录的符号链接的操作数，`ls` 应写出该目录中包含的文件名以及任何请求的关联信息。在写出目录中包含的文件名的每种情况下，如果目录包含任何符号链接，则 `ls` 应评估文件信息和文件类型为符号链接本身的信息和类型，除非指定了 `-L` 选项。

如果未指定操作数，`ls` 应表现为指定了单个操作数点（`.`）。如果指定了多个操作数，`ls` 应首先写出非目录操作数；它应根据当前语言环境的排序序列分别对目录和非目录操作数排序。

每当 `ls` 根据当前语言环境的排序序列对文件名或路径名排序时，如果该排序序列对所有字符没有全序（见 POSIX.1‐2017 基础定义卷 *第 7.3.2 节*，`LC_COLLATE`），则任何排序相等的文件名或路径名应进一步使用 POSIX 语言环境的排序序列逐字节比较。

`ls` 实用程序应检测无限循环；即进入一个先前访问过的、作为最后遇到文件的祖先的目录。当检测到无限循环时，`ls` 应向标准错误写出诊断消息，并应恢复其在层次结构中的位置或终止。

## 选项

`ls` 实用程序应符合 POSIX.1‐2017 基础定义卷 *第 12.2 节*，*实用程序语法准则*。

应支持以下选项：

- `-A`：写出所有目录项，包括名称以句点（`.`）开头的项，但不包括点（`.`）和点点（`..`）项（如果存在）。
- `-C`：按排序序列，以多文本列输出，条目按列向下排序。文本列数和列分隔字符未指定，但应适应输出设备的性质。此选项禁用长格式输出。
- `-F`：除非指定了 `-H` 或 `-L` 选项，否则不跟随作为操作数命名的符号链接。在每个是目录的路径名后立即写一个斜杠（`/`），在每个可执行文件后写星号（`*`），在每个 FIFO 后写竖线（`|`），在每个符号链接后写 at 符号（`@`）。对于其他文件类型，可以写出其他符号。
- `-H`：将命令行上指定的符号链接的文件信息和文件类型评估为链接所引用文件的信息和类型，而不是链接本身；但是，`ls` 应写出链接本身的名称，而不是链接所引用的文件。
- `-L`：将所有符号链接（无论是在命令行上命名还是在文件层次结构中遇到）的文件信息和文件类型评估为链接所引用文件的信息和类型，而不是链接本身；但是，`ls` 应写出链接本身的名称，而不是链接所引用的文件。当 `-L` 与 `-l` 一起使用时，以长格式写出符号链接的内容（见标准输出部分）。
- `-R`：递归列出遇到的子目录。当遇到指向目录的符号链接时，除非指定了 `-L` 选项，否则不应递归列出该目录。将 `-R` 与 `-d` 或 `-f` 一起使用会产生未指定结果。
- `-S`：排序主键为文件大小（降序），次键为按排序序列的文件名（升序）。
- `-a`：写出所有目录项，包括名称以句点（`.`）开头的项。
- `-c`：使用文件状态信息的最后修改时间（见 POSIX.1‐2017 基础定义卷，`[sys_stat.h(0p)]`）代替文件本身的最后修改时间，用于排序（`-t`）或写出（`-l`）。
- `-d`：除非指定了 `-H` 或 `-L` 选项，否则不跟随作为操作数命名的符号链接。不将目录与其他类型的文件区别对待。将 `-d` 与 `-R` 或 `-f` 一起使用会产生未指定结果。
- `-f`：按目录操作数中条目在目录中出现的顺序列出这些条目。非目录操作数的行为未指定。此选项应打开 `-a`。当指定 `-f` 时，任何出现的 `-r`、`-S` 和 `-t` 选项应被忽略，任何出现的 `-A`、`-g`、`-l`、`-n`、`-o` 和 `-s` 选项可以被忽略。将 `-f` 与 `-R` 或 `-d` 一起使用会产生未指定结果。
- `-g`：打开 `-l`（字母 ell）选项，但禁用写出文件的所有者名称或编号。禁用 `-C`、`-m` 和 `-x` 选项。
- `-i`：对于每个文件，写出该文件的文件序列号（见 POSIX.1‐2017 系统接口卷中的 `stat()`）。
- `-k`：将 `-s` 选项的块大小，以及为 `-l`、`-n`、`-s`、`-g` 和 `-o` 选项写出的每目录块计数，设置为 1024 字节（见标准输出部分）。
- `-l`：（字母 ell。）除非指定了 `-H` 或 `-L` 选项，否则不跟随作为操作数命名的符号链接。以长格式写出（见标准输出部分）。禁用 `-C`、`-m` 和 `-x` 选项。
- `-m`：流式输出格式；跨页列出路径名，以逗号字符后跟一个空格字符分隔。当一行上没有空间容纳下一个列表条目时，使用换行字符作为列表终止符和分隔序列之后的分隔符。此选项禁用长格式输出。
- `-n`：打开 `-l`（字母 ell）选项，但在写出文件的所有者或组时，分别写出文件的数字 UID 或 GID，而不是用户或组名称。禁用 `-C`、`-m` 和 `-x` 选项。
- `-o`：打开 `-l`（字母 ell）选项，但禁用写出文件的组名称或编号。禁用 `-C`、`-m` 和 `-x` 选项。
- `-p`：如果文件是目录，则在每个文件名后写出一个斜杠（`/`）。
- `-q`：强制将每个不可打印的文件名字符和制表符写为问号（`?`）字符。如果输出到终端设备，实现可以将此选项设为默认。
- `-r`：反转排序顺序，以获得反向排序序列（最旧在前），或根据给出的其他选项获得最小文件大小在前。
- `-s`：指示每个显示文件消耗的文件系统块总数。如果还指定了 `-k` 选项，块大小应为 1024 字节；否则块大小由实现定义。
- `-t`：排序主键为最后修改时间（最近修改的在前），次键为按排序序列的文件名。对于符号链接，用作排序键的时间是符号链接本身的时间，除非 `ls` 将其文件信息评估为链接所引用文件的信息（见 `-H` 和 `-L` 选项）。
- `-u`：使用最后访问时间（见 POSIX.1‐2017 基础定义卷，`[sys_stat.h(0p)]`）代替文件的最后修改时间，用于排序（`-t`）或写出（`-l`）。
- `-x`：与 `-C` 相同，不同之处在于多文本列输出中的条目按列横向排序，而不是按列向下排序。此选项禁用长格式输出。
- `-1`：（数字一。）强制输出为每行一个条目。此选项不禁用长格式输出。（长格式输出由 `-g`、`-l`（字母 ell）、`-n` 和 `-o` 启用；由 `-C`、`-m` 和 `-x` 禁用。）

如果启用长格式输出的选项（`-g`、`-l`（字母 ell）、`-n` 和 `-o`）与禁用长格式输出的选项（`-C`、`-m` 和 `-x`）一起给出，这不应视为错误。最后指定的这些选项应决定是否写出长格式输出。

如果指定了 `-R`、`-d` 或 `-f`，指定这些互斥选项的结果由上面这些选项的描述规定。如果概要部分所示的互斥集合中的任何其他选项给出了多个，这不应视为错误；每个集合中最后指定的选项应决定输出。

注意，如果指定了 `-t`，`-c` 和 `-u` 不仅彼此互斥，而且在确定排序顺序时也与 `-S` 互斥。但是，即使 `-S` 在所有出现的 `-c`、`-t` 和 `-u` 之后指定，最后使用的 `-c` 或 `-u` 决定产生长格式输出时打印的时间戳。

## 操作数

应支持以下操作数：

- `file`：要写出的文件的路径名。如果指定的文件未找到，应向标准错误输出诊断消息。

## 环境变量

以下环境变量应影响 `ls` 的执行：

- `COLUMNS`：确定用户偏好的列位置宽度，用于写出多文本列输出。如果此变量包含表示十进制整数的字符串，`ls` 实用程序应根据提供的宽度计算要写出的路径名文本列数（见 `-C`）。如果 `COLUMNS` 未设置或无效，应基于实现对其输出设备的了解假定一个实现定义的列位置数。用于写出任何给定目录中文件名的列宽应保持不变。文件名不应被截断以适应多文本列输出。
- `LANG`：为未设置或为空的国际化变量提供默认值。（关于用于确定语言环境类别值的国际化变量优先级，见 POSIX.1‐2017 基础定义卷 *第 8.2 节*，*国际化变量*。）
- `LC_ALL`：如果设置为非空字符串值，则覆盖所有其他国际化变量的值。
- `LC_COLLATE`：确定用于确定路径名排序序列的字符排序信息所在的语言环境。
- `LC_CTYPE`：确定用于将文本数据的字节序列解释为字符（例如，参数中的单字节字符与多字节字符）以及哪些字符定义为可打印字符（字符类 `print`）的语言环境。
- `LC_MESSAGES`：确定应用于影响写到标准错误的诊断消息的格式和内容的语言环境。
- `LC_TIME`：确定 `ls` 写出的日期和时间字符串的格式和内容。
- `NLSPATH`：确定用于处理 `LC_MESSAGES` 的消息目录位置。
- `TZ`：确定 `ls` 写出的日期和时间字符串的时区。如果 `TZ` 未设置或为空，应使用未指定的默认时区。

## 异步事件

默认。

## 标准输出

默认格式应向标准输出每行列出一个条目；例外是输出到终端，或指定了 `-C`、`-m` 或 `-x` 选项之一。如果输出到终端，格式由实现定义。

当指定 `-m` 时，列表最后一个元素使用的格式应为：

```text
"%s\n", <filename>
```

列表其他每个元素使用的格式应为：

```text
"%s,%s", <filename>, <separator>
```

其中，如果当前行长度内没有空间容纳列表的下一个元素，则 `<separator>` 是包含一个可选空格字符和一个必需换行字符的字符串；否则它是一个空格字符。

如果指定了 `-i` 选项，应在对应条目的任何其他输出之前，按以下格式写出文件的文件序列号（见 POSIX.1‐2017 基础定义卷，`[sys_stat.h(0p)]`）：

```text
%u ", <file serial number>
```

如果指定了 `-l` 选项，对于字符特殊文件和块特殊文件以外的文件，应写出以下信息：

```text
"%s %u %s %s %u %s %s\n", <file mode>, <number of links>,
    <owner name>, <group name>, <size>, <date and time>,
    <pathname>
```

如果指定了 `-l` 选项，对于字符特殊文件和块特殊文件，应写出以下信息：

```text
"%s %u %s %s %s %s %s\n", <file mode>, <number of links>,
    <owner name>, <group name>, <device info>, <date and time>,
    <pathname>
```

在两种情况下，如果文件是符号链接且还指定了 `-L` 选项，则该信息应针对从符号链接解析出的文件，但 `<pathname>` 字段应包含符号链接本身的路径名。如果文件是符号链接且未指定 `-L` 选项，则该信息应关于链接本身，且 `<pathname>` 字段应采用以下形式：

```text
"%s -> %s", <pathname of link>, <contents of link>
```

`-n`、`-g` 和 `-o` 选项使用与 `-l` 相同的格式，但省略某些项及其关联的空白字符。参见选项。

在上述两种 `-l` 形式中，如果无法确定 `<owner name>` 或 `<group name>`，或者给出了 `-n`，则应将它们替换为关联的数值，使用格式 `%u`。

`<size>` 字段应包含 `struct stat` 的 `st_size` 字段中为该文件返回的值（见 POSIX.1‐2017 基础定义卷，`[sys_stat.h(0p)]`）。注意，对于某些文件类型，此值未指定。

`<device info>` 字段应包含与所涉设备关联的实现定义信息。

`<date and time>` 字段应包含文件最后修改时的适当日期和时间戳。在 POSIX 语言环境中，该字段应等效于以下 `date` 命令的输出：

```sh
date "+%b %e %H:%M"
```

如果文件在最近六个月内修改过；或者：

```sh
date "+%b %e %Y"
```

（其中在 `%e` 和 `%Y` 之间使用两个空格字符）如果文件未在最近六个月内修改过，或修改日期在未来；但在两种情况下，`date` 产生的最后换行不应包含在内，且输出应如同 `date` 命令在文件最后修改时间执行一样，而不是在当前时间执行。当 `LC_TIME` 语言环境类别未设置为 POSIX 语言环境时，可以使用该字段的不同格式和呈现顺序。

如果路径名作为 `file` 操作数指定，则应按照指定内容写出。

在 `-l`、`-n`、`-g` 和 `-o` 选项下写出的文件模式应由以下格式组成：

```text
"%c%s%s%s%s", <entry type>, <owner permissions>,
    <group permissions>, <other permissions>,
    <optional alternate access method flag>
```

如果没有与文件关联的备用或附加访问控制方法，`<optional alternate access method flag>` 应为空字符串；否则它应是一个包含单个可打印字符且该字符不是空白的字符串。

`<entry type>` 字符应描述文件类型，如下所示：

- `d`：目录。
- `b`：块特殊文件。
- `c`：字符特殊文件。
- `l`（字母 ell）：符号链接。
- `p`：FIFO。
- `-`：普通文件。

实现可以在此列表中添加其他字符，以表示其他实现定义的文件类型。

接下来的三个字段每个应为三个字符：

- `<owner permissions>`：文件所有者类的权限（见 POSIX.1‐2017 基础定义卷 *第 4.5 节*，*文件访问权限*）。
- `<group permissions>`：文件组类的权限。
- `<other permissions>`：文件其他类的权限。

每个字段应具有三个字符位置：

1. 如果为 `r`，文件可读；如果为 `-`，文件不可读。
2. 如果为 `w`，文件可写；如果为 `-`，文件不可写。
3. 以下第一个适用项：
   - `S`：如果在 `<owner permissions>` 中，文件不可执行且设置了设置用户 ID 模式。如果在 `<group permissions>` 中，文件不可执行且设置了设置组 ID 模式。
   - `s`：如果在 `<owner permissions>` 中，文件可执行且设置了设置用户 ID 模式。如果在 `<group permissions>` 中，文件可执行且设置了设置组 ID 模式。
   - `T`：如果在 `<other permissions>` 中且文件是目录，未向其他用户授予搜索权限，并且设置了受限删除标志。
   - `t`：如果在 `<other permissions>` 中且文件是目录，已向其他用户授予搜索权限，并且设置了受限删除标志。
   - `x`：文件可执行或目录可搜索。
   - `-`：`S`、`s`、`T`、`t` 或 `x` 的属性均不适用。

实现可以为第三个字符位置添加其他字符。然而，此类添加项在文件可执行或可搜索时应以小写写出，否则以大写写出。

如果指定了 `-l`、`-n`、`-s`、`-g` 或 `-o` 中的任何一个，则目录内的每个文件列表前应有一行状态行，指示目录中文件占用的文件系统块数：如果未指定 `-k` 选项，以 512 字节为单位；如果指定了 `-k` 选项，以 1024 字节为单位；如有必要，向上舍入到下一个整数单位。在 POSIX 语言环境中，格式应为：

```text
"total %u\n", <number of units in the directory>
```

如果写出多个目录，或非目录文件与目录的组合，无论是由于指定多个操作数，还是由于 `-R` 选项，目录内的每个文件列表前应加上：

```text
"\n%s:\n", <directory name>
```

如果该字符串是要写出的第一项内容，则不应写出第一个换行。该输出应位于目录中的单位数之前。

如果给出了 `-s` 选项，则每个文件应连同该文件使用的块数一起写出。与 `-C`、`-1`、`-m` 或 `-x` 一起使用时，块数和一个空格应位于文件名之前；与 `-l`、`-n`、`-g` 或 `-o` 一起使用时，它们应位于描述文件的每一行之前。

## 应用用法

许多实现使用等号（`=`）来表示通过 `-F` 选项绑定到文件系统的套接字。类似地，许多历史实现使用 `s` 字符作为 `-l` 选项的条目类型字符来表示套接字。

应用程序很难以可移植的方式使用 `ls -l` 文件模式字段的每一部分。某些文件类型和可执行位不保证与所示完全一致，因为实现可能具有扩展。应用程序可以使用此字段直接传递给用户打印输出或提示，但基于其内容的操作通常应推迟到 `test` 实用程序。

`ls`（带 `-l` 及相关选项）的输出包含逻辑上可供 `chmod` 和 `touch` 等实用程序用来将文件恢复到已知状态的信息。然而，这些信息呈现的格式无法被那些实用程序直接使用，也不容易转换为可使用的格式。已在权限字符串末尾添加一个字符，以便应用程序至少能获得指示：它们可能正在处理自己不完全理解的区域，而不是假设自己可以将权限字符串转换为可用的内容。未来版本或相关文档可能基于不同的标准附加或替代访问控制机制定义一个或多个特定字符。

与许多处理文件名的实用程序一样，在文件名可能包含嵌入空白的系统上，必须谨慎使用 `ls` 对多个文件或长列表格式之一的输出。系统和系统管理员应制定策略和用户培训，以限制此类文件名的使用。

`ls` 报告的每个文件占用的磁盘块数因底层文件系统类型、报告的块大小单位以及计算块数的方法而异。在某些文件系统类型上，该数字是文件实际占用的块数（计算间接块并忽略文件中的空洞）；在其他文件系统上，则基于文件大小计算（通常为间接块留出余量，但忽略空洞）。

## 基本原理

`ls` 实用程序的一些历史实现在超级用户未指定 `-a` 选项调用 `ls` 时显示目录中的所有条目，但点和点点除外。当“普通”用户未指定 `-a` 调用 `ls` 时，除非这些文件作为 `file` 操作数命名，否则他们不应看到名称以句点开头的任何文件的信息。

处理 `-R` 选项时，期望实现遍历任意深度。对深度的唯一限制应基于用于跟踪未遍历目录的物理存储耗尽。

`-1`（一）选项历史上仅见于 BSD 和 BSD 派生实现。本卷 POSIX.1‐2017 要求它，以便符合标准的应用程序可以确保输出为每行一个条目，即使输出到终端也是如此。

`-S` 选项在第 7 版中添加，但多年来已由多个实现提供。标准中给出的描述记录了历史实践，但与许多描述其行为的文档不符。历史文档通常这样描述：

> `-S` 按大小排序（最大在前）而不是按名称。特殊字符设备（列在最后）按名称排序。

尽管排序输出时从未考虑文件类型。字符特殊文件通常确实排序在列表接近末尾的位置，因为在大多数实现上它们的文件大小为 0。但它们与任何其他恰好具有相同文件大小（0）的文件一起按字母顺序排序，而不是单独排序并添加到末尾。

本卷 POSIX.1‐2017 经常不说明指定互斥选项时会发生什么。除 `-R`、`-d` 和 `-f` 外，要求 `ls` 实用程序接受每个互斥选项集中的多个选项而不将其视为错误，并使用每个互斥集合中最后给出的选项所指定的行为。由于 `ls` 是最常被别名的命令之一，实现执行直觉行为很重要。例如，如果别名是：

```sh
alias ls="ls -C"
```

而用户输入 `ls -1`（一），则应产生单文本列输出，而不是错误。

`-g`、`-l`（字母 ell）、`-n` 和 `-o` 选项不是互斥选项。它们都启用长格式输出。它们共同决定是否写出文件的所有者（如果存在 `-g` 则不写）、是否写出文件的组（如果存在 `-o` 则不写），以及如果写出文件的组或所有者，是以名称（默认）还是以 UID 或 GID 数字的字符串表示（如果存在 `-n`）写出。`-C`、`-m`、`-x` 和 `-1`（一）是互斥选项，前三个禁用长格式输出。`-1`（一）选项不直接改变是否启用长格式输出，但通过覆盖 `-C`、`-m` 和 `-x`，它可以重新启用被这些选项之一禁用的长格式输出。

本标准早期版本未描述 BSD `-A` 选项（类似 `-a`，但不写出点和点点）。由于广泛实现，已添加该选项。

实现可以将 `-q` 设为终端的默认选项，以防止针对具有特殊转义序列的终端的木马攻击。这不是必需的，因为：

- 某些控制字符在某些终端上可能有用；例如，系统可能将它们写为 `"\001"` 或 `"^A"`。
- 终端的特殊行为与应用程序可移植性无关。

早期提案规定，如果文件使用了备用访问方法，`<optional alternate access method flag>` 必须为 `+`；如果未使用，则为空格。后来改为：如果没有，则为空格；如果有，则为单个可打印字符。这样做有三个原因：

1. 有历史实现使用 `+` 以外的字符。
2. 有实现会改变该位置使用的字符，以区分正在使用的各种备用访问方法。
3. 标准开发者不想排除未来可能需要一种方式来指定多个备用访问方法的规范。

尽管如此，提供单一备用访问方法的实现被鼓励使用 `+`。

本标准早期版本没有 `-k` 选项，这意味着 `-s` 选项无法可移植地使用，因为其块大小由实现定义，而且 `ls -l` 列表中用于指定目录中文件占用块数的单位固定为 512 字节单位。已添加 `-k` 选项，为 `-s` 选项提供可移植使用的方式，并且为了一致性，它还将上述单位从 512 字节改为 1024 字节。

`-l` 格式中的 `<date and time>` 字段仅为 POSIX 语言环境规定。如前所述，在其他语言环境中格式可以不同。本卷 POSIX.1‐2017 中没有定义此格式的机制，因为适当的载体是消息系统；也就是说，格式应指定为一条“消息”。

## 未来方向

允许 `-f` 忽略 `-A`、`-g`、`-l`、`-n`、`-o` 和 `-s` 选项的做法可能会在未来版本中移除。

本标准未来版本可能要求：如果当前语言环境的排序序列对所有字符没有全序，则任何排序相等的文件名或路径名应进一步使用 POSIX 语言环境的排序序列逐字节比较。
