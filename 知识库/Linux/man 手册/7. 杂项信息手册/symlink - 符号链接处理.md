# `symlink` - 符号链接处理

https://man7.org/linux/man-pages/man7/symlink.7.html

## 描述

符号链接是指向其他文件的文件。要理解其行为，必须首先理解硬链接如何工作。

对文件的硬链接与原文件无法区分，因为它是对原始文件名底层对象的引用。（准确地说：对文件的每个硬链接都是对同一 `inode number` 的引用，其中 inode 编号是 inode 表的索引，inode 表包含文件系统上所有文件的元数据。参见 [`stat(2)`]。）对文件的更改与用于引用该文件的名称无关。硬链接不能引用目录（以防止文件系统树中可能出现循环，从而迷惑许多程序），也不能引用不同文件系统上的文件（因为 inode 编号在不同文件系统之间不唯一）。

符号链接是一种特殊类型的文件，其内容是一个字符串，即另一个文件的路径名，也就是该链接所引用的文件。（符号链接的内容可以使用 [`readlink(2)`] 读取。）换句话说，符号链接是指向另一个名称的指针，而不是指向底层对象。因此，符号链接可以引用目录，也可以跨越文件系统边界。

不要求符号链接所引用的路径名存在。引用不存在路径名的符号链接称为 `dangling link`（悬空链接）。

因为符号链接及其引用对象共存于文件系统命名空间中，在区分链接本身与被引用对象时可能产生混淆。在历史系统上，命令和系统调用以某种临时方式采用各自的链接跟随约定。这里概述在 Linux 和其他系统上实现的更统一方法规则。站点本地应用程序也应遵循这些规则，以便用户界面尽可能一致。

### 魔法链接

有一类特殊的类似符号链接的对象，称为“magic links”（魔法链接），可在某些伪文件系统中找到，例如 [`proc(5)`]（示例包括 `/proc/pid/exe` 和 `/proc/pid/fd/*`）。与普通符号链接不同，魔法链接不通过路径名展开解析，而是作为对内核自身文件句柄表示的直接引用。因此，这些魔法链接允许用户访问无法用普通路径引用的文件（例如仍被运行中程序引用的已取消链接文件）。

由于它们可以绕过基于 [`mount_namespaces(7)`] 的普通限制，魔法链接已在各种漏洞利用中被用作攻击向量。

### 符号链接的所有权、权限和时间戳

现有符号链接的所有者和组可以使用 [`lchown(2)`] 更改。当在设置了粘滞位的目录中删除或重命名链接时（参见 [`inode(7)`]），以及设置了 `fs.protected_symlinks` sysctl 时（参见 [`proc(5)`]），符号链接的所有权很重要。

符号链接的最后访问和最后修改时间戳可以使用 [`utimensat(2)`] 或 [`lutimes(3)`] 更改。

在 Linux 上，普通符号链接的权限不用于任何操作；权限始终为 `0777`（所有用户类别均可读、写和执行），且不能更改。

然而，魔法链接不遵循此规则。它们可以具有非 `0777` 模式，尽管此模式目前不用于任何权限检查。

### 获取引用符号链接的文件描述符

将 `O_PATH` 和 `O_NOFOLLOW` 标志组合用于 [`open(2)`]，可产生一个文件描述符，该描述符可作为 `dirfd` 参数传递给 [`fstatat(2)`]、[`fchownat(2)`]、[`fchmodat(2)`]、[`linkat(2)`] 和 [`readlinkat(2)`] 等系统调用，以便操作符号链接本身（而不是其引用的文件）。

默认情况下（即，如果未指定 `AT_SYMLINK_FOLLOW` 标志），如果将 [`name_to_handle_at(2)`] 应用于符号链接，它会生成符号链接的句柄（而不是其引用的文件）。然后，可以通过在后续调用 [`open_by_handle_at(2)`] 中指定 `O_PATH` 标志，获得符号链接的文件描述符（而不是其引用的文件）。同样，该文件描述符可用于前述系统调用，以操作符号链接本身。

### 系统调用和命令对符号链接的处理

符号链接的处理方式可以是操作链接本身，也可以是操作链接所引用的对象。在后一种情况下，应用程序或系统调用被称为 *跟随* 该链接。符号链接可以引用其他符号链接，此时会解引用这些链接，直到找到非符号链接的对象、找到引用不存在文件的符号链接，或检测到循环。（循环检测通过对可跟随的链接数量设置上限来完成；如果超过该限制，则产生错误。）

需要讨论三个独立领域，如下：

- 用作系统调用文件名参数的符号链接。
- 指定为不遍历文件树的实用程序命令行参数的符号链接。
- 遍历文件树的实用程序所遇到的符号链接（无论是在命令行上指定，还是在文件层次结构遍历中遇到）。

在描述系统调用和命令对符号链接的处理之前，需要一些术语。给定形式为 `a/b/c` 的路径名，最后一个斜杠之前的部分（即 `a/b`）称为 `dirname` 组件，最后一个斜杠之后的部分（即 `c`）称为 `basename` 组件。

### 系统调用中对符号链接的处理

第一个领域是用作系统调用文件名参数的符号链接。

传递给系统调用的路径名中符号链接的处理如下：

1. 在路径名的 `dirname` 组件内，几乎所有系统调用都会始终跟随符号链接。（对于命令也是如此。）唯一的例外是 [`openat2(2)`]，它提供可用于显式阻止跟随 `dirname` 组件中符号链接的标志。
2. 除下文所述外，所有系统调用都会跟随路径名 `basename` 组件中的符号链接。例如，如果有一个符号链接 `slink` 指向名为 `afile` 的文件，则系统调用 `open("slink" ...)` 将返回引用文件 `afile` 的文件描述符。

各种系统调用不会跟随路径名 `basename` 组件中的链接，而是操作符号链接本身。它们是：[`lchown(2)`]、[`lgetxattr(2)`]、[`llistxattr(2)`]、[`lremovexattr(2)`]、[`lsetxattr(2)`]、[`lstat(2)`]、[`readlink(2)`]、[`rename(2)`]、[`rmdir(2)`] 和 [`unlink(2)`]。

某些其他系统调用可以选择性跟随路径名 `basename` 组件中的符号链接。它们是：[`faccessat(2)`]、[`fchownat(2)`]、[`fstatat(2)`]、[`linkat(2)`]、[`name_to_handle_at(2)`]、[`open(2)`]、[`openat(2)`]、[`open_by_handle_at(2)`] 和 [`utimensat(2)`]；详情参见其手册页。由于 [`remove(3)`] 是 [`unlink(2)`] 的别名，该库函数也不会跟随符号链接。当 [`rmdir(2)`] 应用于符号链接时，它会失败并返回错误 `ENOTDIR`。

[`link(2)`] 值得特别讨论。POSIX.1-2001 规定，如果 `oldpath` 是符号链接，[`link(2)`] 应解引用它。然而，Linux 不这样做。（默认情况下，Solaris 也是如此，但可以通过适当的编译器选项获得 POSIX.1-2001 指定的行为。）POSIX.1-2008 修改了规范，允许实现采用任一行为。

### 不遍历文件树的命令

第二个领域是指定为命令行文件名参数、传给不遍历文件树的命令的符号链接。

除下文所述外，命令会跟随作为命令行参数命名的符号链接。例如，如果有一个符号链接 `slink` 指向名为 `afile` 的文件，则命令 `cat slink` 将显示文件 `afile` 的内容。

重要的是要认识到，此规则包括可能可选地遍历文件树的命令；例如，命令 `chown file` 属于此规则，而执行树遍历的命令 `chown -R file` 则不属于。（后者在下文第三个领域中描述。）

如果明确意图是让命令操作符号链接而不是跟随符号链接——例如，希望 `chown slink` 更改 `slink` 所是的文件（无论它是否为符号链接）的所有权——则应使用 `-h` 选项。在上面的示例中，`chown root slink` 会更改 `slink` 所引用文件的所有权，而 `chown -h root slink` 会更改 `slink` 本身的所有权。

此规则有一些例外：

- [`mv(1)`] 和 [`rm(1)`] 命令不会跟随作为参数命名的符号链接，而是分别尝试重命名和删除它们。（注意，如果符号链接通过相对路径引用文件，将其移动到另一个目录很可能导致它停止工作，因为路径可能不再正确。）
- [`ls(1)`] 命令也是此规则的例外。为了与历史系统兼容（当 [`ls(1)`] 不进行树遍历——即未指定 `-R` 选项时），如果指定了 `-H` 或 `-L` 选项，或者未指定 `-F`、`-d` 或 `-l` 选项，则 [`ls(1)`] 命令会跟随作为参数命名的符号链接。（[`ls(1)`] 命令是唯一一个即使不遍历文件树，`-H` 和 `-L` 选项也会影响其行为的命令。）
- [`file(1)`] 命令也是此规则的例外。默认情况下，[`file(1)`] 命令不会跟随作为参数命名的符号链接。如果指定了 `-L` 选项，[`file(1)`] 命令会跟随作为参数命名的符号链接。

### 遍历文件树的命令

以下命令可选地或始终遍历文件树：[`chgrp(1)`]、[`chmod(1)`]、[`chown(1)`]、[`cp(1)`]、[`du(1)`]、[`find(1)`]、[`ls(1)`]、`pax(1)`、[`rm(1)`] 和 [`tar(1)`]。

重要的是要认识到，以下规则同样适用于文件树遍历期间遇到的符号链接以及作为命令行参数列出的符号链接。

*第一条规则* 适用于引用非目录文件的符号链接。适用于符号链接的操作在链接自身上执行，但除此之外链接被忽略。

命令 `rm -r slink directory` 将删除 `slink`，以及 `directory` 树遍历中遇到的任何符号链接，因为符号链接可以被删除。在任何情况下，[`rm(1)`] 都不会影响 `slink` 所引用的文件。

*第二条规则* 适用于引用目录的符号链接。默认情况下，引用目录的符号链接永远不会被跟随。这通常称为“物理”遍历，与“逻辑”遍历（跟随引用目录的符号链接）相对。

执行文件树遍历的命令应尽可能一致地遵循某些约定：

- 通过指定 `-H`（“半逻辑”）标志，可以使命令跟随命令行上命名的任何符号链接，而不管它们引用的文件类型。此标志旨在使命令行命名空间看起来像逻辑命名空间。（注意，对于不总是进行文件树遍历的命令，如果未同时指定 `-R` 标志，则 `-H` 标志将被忽略。）  
  （注意，`-H` 与前面讨论的 `-h` 标志不同。）  
  例如，命令 `chown -HR user slink` 将遍历以 `slink` 所指向文件为根的文件层次结构。`-H` 标志会为了要执行的操作和树遍历两者的目的，解引用命令行上指定的符号链接，就好像用户指定了符号链接所指向文件的名称一样。
- 通过指定 `-L`（“逻辑”）标志，可以使命令跟随命令行上命名的任何符号链接，以及遍历期间遇到的任何符号链接，而不管它们引用的文件类型。此标志旨在使整个命名空间看起来像逻辑命名空间。（注意，对于不总是进行文件树遍历的命令，如果未同时指定 `-R` 标志，则 `-L` 标志将被忽略。）  
  例如，命令 `chown -LR user slink` 将更改 `slink` 所引用文件的所有者。如果 `slink` 引用目录，`chown` 将遍历以该目录为根的文件层次结构。此外，如果 `chown` 遍历的任何文件树中遇到任何符号链接，它们将按照与 `slink` 相同的方式处理。
- 通过指定 `-P`（“物理”）标志，可以使命令提供默认行为。此标志旨在使整个命名空间看起来像物理命名空间。

对于默认不进行文件树遍历的命令，如果未同时指定 `-R` 标志，则 `-H`、`-L` 和 `-P` 标志将被忽略。此外，可以多次指定 `-H`、`-L` 和 `-P` 选项；最后指定的选项决定命令的行为。这旨在允许将命令别名设置为一种或另一种行为，然后在命令行上覆盖该行为。

[`ls(1)`] 和 [`rm(1)`] 命令对这些规则有例外：

- [`rm(1)`] 命令操作符号链接，而不是其引用的文件，因此永远不会跟随符号链接。[`rm(1)`] 命令不支持 `-H`、`-L` 或 `-P` 选项。
- 为了与历史系统保持兼容，[`ls(1)`] 命令的行为略有不同。如果未指定 `-F`、`-d` 或 `-l` 选项，[`ls(1)`] 将跟随命令行上指定的符号链接。如果指定了 `-L` 标志，[`ls(1)`] 会跟随所有符号链接，而不管其类型，无论是在命令行上指定还是在树遍历中遇到。
