# 6.2 Bash 启动文件

https://www.gnu.org/software/bash/manual/html_node/Bash-Startup-Files.html

本节描述 Bash 如何执行其启动文件。如果任何文件存在但无法读取，Bash 会报告错误。文件名中的波浪号会展开，如上面波浪号展开所述（参见 [Tilde Expansion]）。

交互式 shell 在 [Interactive Shells] 中描述。

## 作为交互式登录 shell 调用，或使用 `--login`

当 Bash 作为交互式登录 shell 调用，或作为带有 `--login` 选项的非交互式 shell 调用时，它首先读取并执行文件 `/etc/profile` 中的命令（如果该文件存在）。读取该文件后，它按顺序查找 `~/.bash_profile`、`~/.bash_login` 和 `~/.profile`，并读取和执行其中第一个存在且可读的文件中的命令。`--noprofile` 选项会阻止此行为。

当交互式登录 shell 退出时，或非交互式登录 shell 执行 `exit` 内建命令时，Bash 会读取并执行文件 `~/.bash_logout` 中的命令（如果该文件存在）。

## 🛠️ 作为交互式非登录 shell 调用

当 Bash 作为非登录 shell 的交互式 shell 运行时，它会读取并执行文件 `~/.bashrc` 中的命令（如果该文件存在）。`--norc` 选项会阻止此行为。`--rcfile file` 选项使 Bash 使用 `file` 而不是 `~/.bashrc`。

因此，通常你的 `~/.bash_profile` 包含以下行：

```bash
if [ -f ~/.bashrc ]; then . ~/.bashrc; fi
```

位于任何登录特定初始化之后（或之前）。

## 非交互式调用

当 Bash 以非交互方式启动时（例如运行 shell 脚本），它会在环境中查找变量 `BASH_ENV`，如果存在则展开其值，并将展开后的值用作要读取和执行的文件名。Bash 的行为就像执行了以下命令：

```bash
if [ -n "$BASH_ENV" ]; then . "$BASH_ENV"; fi
```

但不会使用 `PATH` 变量的值来搜索该文件名。

如上所述，如果非交互式 shell 使用 `--login` 选项调用，Bash 会尝试从登录 shell 启动文件中读取并执行命令。

## 以名称 `sh` 调用

如果 Bash 以名称 `sh` 调用，它会尽可能紧密地模仿历史版本 `sh` 的启动行为，同时遵守 `POSIX` 标准。

当作为交互式登录 shell 调用，或作为带有 `--login` 选项的非交互式 shell 调用时，它首先尝试按顺序读取并执行 `/etc/profile` 和 `~/.profile` 中的命令。`--noprofile` 选项会阻止此行为。

当以名称 `sh` 作为交互式 shell 调用时，Bash 会查找变量 `ENV`，如果已定义则展开其值，并将展开后的值用作要读取和执行的文件名。由于以 `sh` 调用的 shell 不会尝试从任何其他启动文件读取和执行命令，因此 `--rcfile` 选项无效。

以名称 `sh` 调用的非交互式 shell 不会尝试读取任何其他启动文件。

当以 `sh` 调用时，Bash 在读取启动文件后进入 `POSIX` 模式。

## 以 `POSIX` 模式调用

当 Bash 以 `POSIX` 模式启动时（例如使用 `--posix` 命令行选项），它会遵循 `POSIX` 标准处理启动文件。在此模式下，交互式 shell 会展开 `ENV` 变量，并读取和执行文件名为展开值的文件中的命令。不会读取其他启动文件。

## 由远程 shell 守护进程调用

Bash 会尝试判断其标准输入是否连接到网络连接，例如由历史上罕见使用的远程 shell 守护进程（通常是 `rshd`）或安全 shell 守护进程 `sshd` 执行时。如果 Bash 确定以这种方式非交互式运行，它会读取并执行文件 `~/.bashrc` 中的命令（如果该文件存在且可读）。如果以 `sh` 调用，Bash 不会读取此文件。`--norc` 选项会阻止此行为，`--rcfile` 选项使 Bash 使用不同的文件代替 `~/.bashrc`，但 `rshd` 和 `sshd` 通常不会使用这些选项调用 shell，也不允许指定它们。

## 以有效 `UID/GID` 与真实 `UID/GID` 不相等的方式调用

如果 Bash 启动时有效用户（组）ID 不等于真实用户（组）ID，且未提供 `-p` 选项，则不会读取任何启动文件，不会从环境继承 shell 函数，环境中的 `SHELLOPTS`、`BASHOPTS`、`CDPATH` 和 `GLOBIGNORE` 变量会被忽略，并且有效用户 ID 会被设置为真实用户 ID。如果在调用时提供了 `-p` 选项，启动行为相同，但有效用户 ID 不会被重置。
