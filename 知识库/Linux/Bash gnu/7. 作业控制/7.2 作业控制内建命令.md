# 7.2 作业控制内建命令

https://www.gnu.org/software/bash/manual/html_node/Job-Control-Basics.html

## bg

```text
bg [jobspec ...]
```

在后台恢复每个挂起的作业 `jobspec`，就像它是以 `&` 启动的一样。如果未提供 `jobspec`，shell 使用其当前作业的概念。除非在作业控制未启用时运行，或者在启用了作业控制时运行且任何 `jobspec` 未找到或指定了未启动作业控制的作业，否则 `bg` 返回零。

## fg

```text
fg [jobspec]
```

在前台恢复作业 `jobspec`，并使其成为当前作业。如果未提供 `jobspec`，`fg` 恢复当前作业。返回状态是放入前台的命令的退出状态；如果在作业控制禁用时运行，或者在启用了作业控制时运行且 `jobspec` 未指定有效作业或指定了未启动作业控制的作业，则返回非零。

## jobs

```text
jobs [-lnprs] [jobspec]
jobs -x command [arguments]
```

第一种形式列出活动作业。选项含义如下：

- `-l`  
  除常规信息外，还列出进程 ID。

- `-n`  
  仅显示自上次通知用户其状态以来状态已更改的作业信息。

- `-p`  
  仅列出作业进程组组长的进程 ID。

- `-r`  
  仅显示正在运行的作业。

- `-s`  
  仅显示已停止的作业。

如果提供了 `jobspec`，`jobs` 将输出限制为该作业的信息。如果未提供 `jobspec`，`jobs` 列出所有作业的状态。除非遇到无效选项或提供了无效 `jobspec`，否则返回状态为零。

如果提供了 `-x` 选项，`jobs` 会将 `command` 或 `arguments` 中找到的任何 `jobspec` 替换为相应的进程组 ID，并执行 `command`，向其传递 `arguments`，返回其退出状态。

## kill

```text
kill [-s sigspec] [-n signum] [-sigspec] id [...]
kill -l|-L [exit_status]
```

向每个 `id` 命名的进程发送由 `sigspec` 或 `signum` 指定的信号。每个 `id` 可以是作业规范 `jobspec` 或进程 ID `pid`。`sigspec` 是大小写不敏感的信号名（例如 `SIGINT`，带或不带 `SIG` 前缀）或信号编号；`signum` 是信号编号。如果未提供 `sigspec` 和 `signum`，`kill` 发送 `SIGTERM`。

`-l` 选项列出信号名。如果在提供 `-l` 时提供了任何参数，`kill` 列出与参数对应的信号名，返回状态为零。`exit_status` 是一个数字，指定信号编号或由信号终止的进程的退出状态；如果提供，`kill` 打印导致进程终止的信号名。`kill` 假定进程退出状态大于 `128`；小于该值的则是信号编号。`-L` 选项等价于 `-l`。

如果至少成功发送了一个信号，返回状态为零；如果发生错误或遇到无效选项，则返回非零。

## wait

```text
wait [-fn] [-p varname] [id ...]
```

等待每个 `id` 指定的子进程退出，并返回最后一个 `id` 的退出状态。每个 `id` 可以是进程 ID `pid` 或作业规范 `jobspec`；如果提供了 `jobspec`，`wait` 等待该作业中的所有进程。

如果未提供选项或 `id`，`wait` 等待所有正在运行的后台作业以及最后一个执行的进程替换（如果其进程 ID 与 `$!` 相同），返回状态为零。

如果提供了 `-n` 选项，`wait` 等待 `id` 中的任意一个，或者如果未提供 `id`，则等待任意作业或进程替换完成，并返回其退出状态。如果提供的 `id` 中没有一个是 shell 的子进程，或者未提供参数且 shell 没有未等待的子进程，退出状态为 `127`。

如果提供了 `-p` 选项，`wait` 将返回退出状态的作业的进程或作业标识符赋值给选项参数命名的变量 `varname`。该变量不能是只读的，并且在任何赋值之前会先被取消设置。这仅在与 `-n` 选项一起使用时有用。

在启用了作业控制时，提供 `-f` 选项会强制 `wait` 等待每个 `id` 终止后再返回其状态，而不是在其状态更改时返回。

如果 `id` 中没有一个指定 shell 的活动子进程，返回状态为 `127`。如果 `wait` 被信号中断，任何 `varname` 将保持未设置，返回状态将大于 `128`，如上所述（参见 [Signals]）。否则，返回状态是最后一个 `id` 的退出状态。

## disown

```text
disown [-ar] [-h] [id ...]
```

不带选项时，从活动作业表中移除每个 `id`。每个 `id` 可以是作业规范 `jobspec` 或进程 ID `pid`；如果 `id` 是 `pid`，`disown` 使用包含 `pid` 的作业作为 `jobspec`。

如果提供了 `-h` 选项，`disown` 不会从作业表中移除每个 `id` 对应的作业，而是标记它们，以便 shell 在收到 `SIGHUP` 时不会向该作业发送 `SIGHUP`。

如果未提供 `id`，`-a` 选项表示移除或标记所有作业；不带 `id` 参数的 `-r` 选项移除或标记正在运行的作业。如果未提供 `id`，且既未提供 `-a` 也未提供 `-r` 选项，`disown` 移除或标记当前作业。

除非 `id` 未指定有效作业，否则返回值为 `0`。

## suspend

```text
suspend [-f]
```

挂起此 shell 的执行，直到它收到 `SIGCONT` 信号。登录 shell，或未启动作业控制的 shell，不能被挂起；`-f` 选项将覆盖此限制并强制挂起。除非该 shell 是登录 shell，或者作业控制未启用且未提供 `-f` 选项，否则返回状态为 `0`。

当作业控制未激活时，`kill` 和 `wait` 内建命令不接受 `jobspec` 参数。它们必须提供进程 ID。
