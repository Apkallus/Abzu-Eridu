# 4.1 Bourne Shell 内建命令

https://www.gnu.org/software/bash/manual/html_node/Bourne-Shell-Builtins.html

以下 shell 内建命令继承自 Bourne Shell。这些命令按照 `POSIX` 标准的规定实现。

## `:`（冒号）

```sh
: [arguments]
```

除展开 `arguments` 并执行重定向之外不做任何事。返回状态为零。

## `.`（句点）

```sh
. [-p path] filename [arguments]
```

`.` 命令从 `filename` 参数读取命令，并在当前 shell 上下文中执行这些命令。

如果 `filename` 不含斜杠，`.` 会搜索它。如果提供 `-p`，`.` 将 `path` 视为以冒号分隔的目录列表，用于查找 `filename`；否则 `.` 使用 `PATH` 中的目录查找 `filename`。`filename` 不必可执行。当 Bash 不处于 `POSIX` 模式时，如果在 `$PATH` 中找不到 `filename`，它会搜索当前目录；但如果提供 `-p`，则不搜索当前目录。如果关闭 `sourcepath` 选项（见 [Shopt 内建命令]），`.` 不搜索 `PATH`。

如果提供任何 `arguments`，在执行 `filename` 时它们成为位置参数。否则位置参数不变。

如果启用 `-T` 选项，`.` 继承 `DEBUG` 上的任何 trap；如果未启用，则在调用 `.` 前后保存并恢复任何 `DEBUG` trap 字符串，并且 `.` 在执行期间取消设置 `DEBUG` trap。如果未设置 `-T`，且被 source 的文件更改了 `DEBUG` trap，则新值在 `.` 完成后继续存在。返回状态为从 `filename` 执行的最后一条命令的退出状态；如果没有执行命令，则为 0。如果找不到 `filename` 或无法读取，返回状态非零。此内建命令等价于 `source`。

## break

```sh
break [n]
```

退出 `for`、`while`、`until` 或 `select` 循环。如果提供 `n`，`break` 退出第 `n` 层外层循环。`n` 必须大于或等于 1。返回状态为零，除非 `n` 不大于或等于 1。

## cd —— 更改当前工作目录

```sh
cd [-L] [-@] [directory]
cd -P [-e] [-@] [directory]
```

将当前工作目录更改为 `directory`。如果未提供 `directory`，使用 `HOME` shell 变量的值。如果 shell 变量 `CDPATH` 存在，且 `directory` 不以斜杠开头，`cd` 将其用作搜索路径：`cd` 在 `CDPATH` 的每个目录名中搜索 `directory`，`CDPATH` 中的备选目录名用冒号（`:`）分隔。`CDPATH` 中的空目录名与当前目录含义相同。

`-P` 选项表示不跟随符号链接：在 `cd` 遍历 `directory` 时以及处理 `directory` 中的 `..` 实例之前解析符号链接。

默认情况下，或提供 `-L` 选项时，在 `cd` 处理 `directory` 中的 `..` 实例之后解析 `directory` 中的符号链接。

如果 `directory` 中出现 `..`，`cd` 通过移除紧邻的前一个路径名组成部分来处理它，直到斜杠或 `directory` 开头，并验证截至该点已处理的 `directory` 部分在移除路径名组成部分后仍是有效目录名。如果不是有效目录名，`cd` 返回非零状态。

如果随 `-P` 提供 `-e`，且 `cd` 在成功更改目录后无法成功确定当前工作目录，则返回非零状态。

在支持的系统上，`-@` 选项将文件关联的扩展属性作为目录呈现。

如果 `directory` 为 `-`，在尝试更改目录前将其转换为 `$OLDPWD`。

如果 `cd` 使用 `CDPATH` 中非空目录名，或 `-` 是第一个参数，且目录更改成功，`cd` 将新工作目录的绝对路径名写入标准输出。

如果目录更改成功，`cd` 将 `PWD` 环境变量设置为新目录名，并将 `OLDPWD` 环境变量设置为更改前当前工作目录的值。

如果成功更改目录，返回状态为零；否则非零。

## continue

```sh
continue [n]
```

`continue` 恢复外层 `for`、`while`、`until` 或 `select` 循环的下一次迭代。如果提供 `n`，Bash 恢复第 `n` 层外层循环的执行。`n` 必须大于或等于 1。返回状态为零，除非 `n` 不大于或等于 1。

## eval

```sh
eval [arguments]
```

`arguments` 会用空格分隔并拼接成一条命令。Bash 随后读取并执行该命令，并将其退出状态作为 `eval` 的退出状态返回。如果没有参数或只有空参数，返回状态为零。

## exec

```sh
exec [-cl] [-a name] [command [arguments]]
```

如果提供 `command`，它会替换 shell，而不创建新进程。`command` 不能是 shell 内建命令或函数。`arguments` 成为 `command` 的参数。如果提供 `-l` 选项，shell 会在传递给 `command` 的第零个参数开头放置一个短横线。这就是 `login` 程序所做的。`-c` 选项使 `command` 在空环境中执行。如果提供 `-a`，shell 将 `name` 作为第零个参数传递给 `command`。

如果由于某种原因无法执行 `command`，非交互式 shell 会退出，除非启用 `execfail` shell 选项。在这种情况下，它返回非零状态。如果文件无法执行，交互式 shell 返回非零状态。如果 `exec` 失败，子 shell 无条件退出。

如果未指定 `command`，可以使用重定向影响当前 shell 环境。如果没有重定向错误，返回状态为零；否则返回状态非零。

## exit

```sh
exit [n]
```

退出 shell，并向 shell 的父进程返回状态 `n`。如果省略 `n`，退出状态为最后执行命令的退出状态。shell 终止前会执行 `EXIT` 上的任何 trap。

## export

```sh
export [-fn] [-p] [name[=value]]
```

将每个 `name` 标记为要传递给后续执行命令的环境。如果提供 `-f` 选项，`name` 指 shell 函数；否则名称指 shell 变量。

`-n` 选项表示取消导出每个名称：不再将其标记为导出。如果未提供 `name`，或仅提供 `-p` 选项，`export` 会在标准输出上显示所有已导出变量的名称列表。同时使用 `-p` 和 `-f` 会显示已导出的函数。`-p` 选项以可重用为输入的格式显示输出。

`export` 允许在导出或取消导出变量的同时，通过在变量名后跟 `=value` 来设置变量的值。这会在修改导出属性的同时将变量值设置为 `value`。

返回状态为零，除非提供无效选项、某个名称不是有效 shell 变量名，或 `-f` 与不是 shell 函数的名称一起提供。

## false

```sh
false
```

不做任何事；返回非零状态。

## getopts

```sh
getopts optstring name [arg ...]
```

`getopts` 由 shell 脚本或函数用于解析位置参数并获取选项及其参数。`optstring` 包含要识别的选项字符；如果某个字符后跟冒号，则该选项应有一个参数，参数应通过空白与选项分隔。冒号（`:`）和问号（`?`）不得用作选项字符。

每次调用时，`getopts` 将下一个选项放入 shell 变量 `name`，如果 `name` 不存在则初始化，并将下一个要处理的参数索引放入变量 `OPTIND`。每次调用 shell 或 shell 脚本时，`OPTIND` 初始化为 1。当选项需要参数时，`getopts` 将该参数放入变量 `OPTARG`。

shell 不会自动重置 `OPTIND`；在同一 shell 调用中多次调用 `getopts` 以使用新参数集时，必须在调用之间手动重置。

到达选项末尾时，`getopts` 以大于零的返回值退出。`OPTIND` 设置为第一个非选项参数的索引，`name` 设置为 `?`。

`getopts` 通常解析位置参数，但如果提供更多 `arg` 值，`getopts` 改为解析这些值。

`getopts` 可以通过两种方式报告错误。如果 `optstring` 的首字符是冒号，`getopts` 使用静默错误报告。正常操作中，`getopts` 在遇到无效选项或缺少选项参数时打印诊断消息。如果变量 `OPTERR` 设置为 0，即使 `optstring` 的首字符不是冒号，`getopts` 也不显示任何错误消息。

如果 `getopts` 检测到无效选项，它会将 `?` 放入 `name`，并且如果不是静默模式，则打印错误消息并取消设置 `OPTARG`。如果 `getopts` 是静默模式，它将找到的选项字符赋给 `OPTARG`，并且不打印诊断消息。

如果找不到必需参数，且 `getopts` 不是静默模式，它将 `name` 的值设置为问号（`?`），取消设置 `OPTARG`，并打印诊断消息。如果 `getopts` 是静默模式，它将 `name` 的值设置为冒号（`:`），并将 `OPTARG` 设置为找到的选项字符。

如果找到指定或未指定的选项，`getopts` 返回 true。遇到选项末尾或发生错误时，它返回 false。

## hash

```sh
hash [-r] [-p filename] [-dt] [name]
```

每次调用 `hash` 时，它会记住作为 `name` 参数指定的命令的完整文件名，以便后续调用无需再搜索。命令通过搜索 `$PATH` 中列出的目录找到。与 `name` 关联的任何先前记住的文件名都会被丢弃。`-p` 选项阻止路径搜索，`hash` 使用 `filename` 作为 `name` 的位置。

`-r` 选项使 shell 忘记所有记住的位置。给 `PATH` 变量赋值也会清除所有哈希文件名。`-d` 选项使 shell 忘记每个 `name` 的记住位置。

如果提供 `-t` 选项，`hash` 打印每个 `name` 对应的完整路径名。如果随 `-t` 提供多个 `name` 参数，`hash` 会在每个对应的哈希完整路径之前打印每个 `name`。`-l` 选项以可重用为输入的格式显示输出。

如果未给参数，或仅提供 `-l`，`hash` 打印关于已记住命令的信息。`-t`、`-d` 和 `-p` 选项（作用于 `name` 参数的选项）互斥。只有一个会生效。如果提供多个，`-t` 的优先级高于 `-p`，二者的优先级都高于 `-d`。

返回状态为零，除非找不到某个 `name` 或提供无效选项。

## pwd

```sh
pwd [-LP]
```

打印当前工作目录的绝对路径名。如果提供 `-P` 选项，或启用 `set` 内建命令的 `-o physical` 选项（见 [Set 内建命令]），打印的路径名将不包含符号链接。如果提供 `-L` 选项，打印的路径名可能包含符号链接。返回状态为零，除非在确定当前目录名称时遇到错误或提供无效选项。

## readonly

```sh
readonly [-aAf] [-p] [name[=value]] ...
```

将每个 `name` 标记为只读。这些名称的值不能被后续赋值或 `unset` 更改。如果提供 `-f` 选项，每个 `name` 指 shell 函数。`-a` 选项表示每个 `name` 指索引数组变量；`-A` 选项表示每个 `name` 指关联数组变量。如果同时提供两个选项，`-A` 优先。如果未提供 `name` 参数，或提供 `-p` 选项，则打印所有只读名称的列表。其他选项可用于将输出限制为只读名称集合的子集。`-p` 选项以可重用为输入的格式显示输出。

`readonly` 允许在修改只读属性的同时，通过在变量名后跟 `=value` 来设置变量的值。这会在修改只读属性的同时将变量值设置为 `value`。

返回状态为零，除非提供无效选项、某个 `name` 参数不是有效 shell 变量或函数名，或 `-f` 选项与不是 shell 函数的名称一起提供。

## return

```sh
return [n]
```

停止执行 shell 函数或被 source 的文件，并将值 `n` 返回给调用者。如果未提供 `n`，返回值为最后执行命令的退出状态。如果 `return` 由 trap handler 执行，用于确定状态的最后命令是 trap handler 之前执行的最后一条命令。如果 `return` 在 `DEBUG` trap 期间执行，用于确定状态的最后命令是 trap handler 在调用 `return` 之前执行的最后一条命令。

当 `return` 用于终止由 `.`（`source`）内建命令执行的脚本时，它返回 `n` 或脚本内最后执行命令的退出状态作为脚本退出状态。如果提供 `n`，返回值为其最低有效 8 位。

与 `RETURN` trap 关联的任何命令会在函数或脚本之后恢复执行前执行。

如果 `return` 收到非数字参数，或在函数外且不在由 `.` 或 `source` 执行脚本期间使用，则返回状态非零。

## shift

```sh
shift [n]
```

将位置参数左移 `n`：从 `n+1` … `$#` 的位置参数重命名为 `$1` … `$#-n`。由 `$#` 到 `$#-n+1` 表示的位置参数被取消设置。`n` 必须是非负数且小于或等于 `$#`。如果未提供 `n`，假定为 1。如果 `n` 为零或大于 `$#`，位置参数不变。返回状态为零，除非 `n` 大于 `$#` 或小于零；否则非零。

## test, `[`

```sh
test expr
```

计算条件表达式 `expr` 并返回状态 0（真）或 1（假）。每个运算符和操作数必须是单独参数。表达式由 [Bash 条件表达式] 中描述的基本项组成。`test` 不接受任何选项，也不接受并忽略作为选项结束标志的 `--` 参数。使用 `[` 形式时，命令最后一个参数必须是 `]`。

表达式可使用以下运算符组合，按优先级递减列出。求值取决于参数数量；见下文。当有五个或更多参数时，`test` 使用运算符优先级。

- `! expr`  
  如果 `expr` 为假，则为真。
- `( expr )`  
  返回 `expr` 的值。可用于覆盖正常运算符优先级。
- `expr1 -a expr2`  
  如果 `expr1` 和 `expr2` 都为真，则为真。
- `expr1 -o expr2`  
  如果 `expr1` 或 `expr2` 为真，则为真。

`test` 和 `[` 内建命令根据参数数量使用一组规则计算条件表达式。

- 0 个参数  
  表达式为假。
- 1 个参数  
  当且仅当参数非空时表达式为真。
- 2 个参数  
  如果第一个参数是 `!`，当且仅当第二个参数为空时表达式为真。如果第一个参数是某个一元条件运算符（见 [Bash 条件表达式]），则一元测试为真时表达式为真。如果第一个参数不是有效一元运算符，表达式为假。
- 3 个参数  
  按下列顺序应用以下条件。

  1. 如果第二个参数是某个二元条件运算符（见 [Bash 条件表达式]），表达式结果为使用第一和第三个参数作为操作数的二元测试结果。当有三个参数时，`-a` 和 `-o` 运算符被视为二元运算符。
  2. 如果第一个参数是 `!`，值为使用第二和第三个参数的两参数测试的否定。
  3. 如果第一个参数恰好是 `(` 且第三个参数恰好是 `)`，结果为第二个参数的一参数测试。
  4. 否则，表达式为假。
- 4 个参数  
  按下列顺序应用以下条件。

  1. 如果第一个参数是 `!`，结果为剩余参数组成的三参数表达式的否定。
  2. 如果第一个参数恰好是 `(` 且第四个参数恰好是 `)`，结果为第二和第三个参数的两参数测试。
  3. 否则，按上述规则使用优先级解析并求值表达式。
- 5 个或更多参数  
  按上述规则使用优先级解析并求值表达式。

如果 shell 处于 `POSIX` 模式，或表达式是 `[[` 命令的一部分，`<` 和 `>` 运算符使用当前 locale 排序。如果 shell 不处于 `POSIX` 模式，`test` 和 `[` 命令使用 `ASCII` 排序按字典序排序。

使用 4 个或更多参数的历史运算符优先级解析在遇到看起来像基本项的字符串时可能导致歧义。`POSIX` 标准已弃用 `-a` 和 `-o` 基本项以及括号内表达式。脚本不应再使用它们。更可靠的做法是将 test 调用限制为单个基本项，并将 `-a` 和 `-o` 的使用替换为 shell 的 `&&` 和 `||` 列表运算符。例如，使用：

```sh
test -n string1 && test -n string2
```

而不是：

```sh
test -n string1 -a -n string2
```

## times

```sh
times
```

打印 shell 及其子进程使用的用户时间和系统时间。返回状态为零。

## trap

```sh
trap [-lpP] [action] [sigspec ...]
```

`action` 是 shell 收到任何 `sigspec` 信号时读取并执行的命令。如果省略 `action`（且只有一个 `sigspec`），或 `action` 等于 `-`，则每个指定 `sigspec` 的处理方式重置为 shell 启动时的值。如果 `action` 是空字符串，则 shell 及其调用的命令忽略每个 `sigspec` 指定的信号。

如果未提供参数，`trap` 会将每个被 trap 的信号关联的动作打印为一组 `trap` 命令，这些命令可重用为 shell 输入，以恢复当前信号处理方式。

如果不存在 `action` 且提供 `-p`，`trap` 会显示与每个 `sigspec` 关联的 trap 命令；如果未提供 `sigspec`，则显示所有被 trap 信号的命令，作为一组可重用为 shell 输入的 `trap` 命令，以恢复当前信号处理方式。`-P` 选项行为类似，但只显示与每个 `sigspec` 参数关联的动作。`-P` 要求至少一个 `sigspec` 参数。`-P` 或 `-p` 选项可在子 shell 环境中使用（例如命令替换），并且只要在 `trap` 用于更改信号处理之前使用，就会显示其父进程的 trap 状态。

`-l` 选项打印信号名及其对应编号的列表。每个 `sigspec` 是信号名或信号编号。信号名大小写不敏感，`SIG` 前缀可选。如果提供 `-l` 且没有 `sigspec` 参数，它会打印有效信号名列表。

如果 `sigspec` 为 `0` 或 `EXIT`，shell 退出时执行 `action`。如果 `sigspec` 为 `DEBUG`，则在每个简单命令、`for` 命令、`case` 命令、`select` 命令、`((` 算术命令、`[[` 条件命令、算术 `for` 命令之前，以及 shell 函数中第一条命令执行之前执行 `action`。有关 `extdebug` shell 选项对 `DEBUG` trap 影响的详细信息，请参见 [Shopt 内建命令]。如果 `sigspec` 为 `RETURN`，每次 shell 函数或由 `.` 或 `source` 内建命令执行的脚本完成执行时执行 `action`。

如果 `sigspec` 为 `ERR`，每当管道（可能由单个简单命令组成）、列表或复合命令返回非零退出状态时执行 `action`，但受以下条件约束。如果失败命令是紧跟在 `until` 或 `while` 保留字之后的命令列表的一部分、是 `if` 或 `elif` 保留字之后的测试的一部分、是在 `&&` 或 `||` 列表中执行的命令的一部分（除了最终 `&&` 或 `||` 之后的命令）、是管道中除最后一条之外的任何命令（受 `pipefail` shell 选项状态影响），或者命令返回状态正使用 `!` 反转，则不执行 `ERR` trap。这些条件与 `errexit`（`-e`）选项遵循的条件相同。

当 shell 非交互时，进入非交互 shell 时忽略的信号不能被 trap 或重置。交互式 shell 允许 trap 进入时忽略的信号。被 trap 的信号如果未被忽略，在创建子 shell 或子 shell 环境时会重置为原始值。

返回状态为零，除非 `sigspec` 未指定有效信号；否则非零。

## true

```sh
true
```

不做任何事，返回 0 状态。

## umask

```sh
umask [-p] [-S] [mode]
```

将 shell 进程的文件创建掩码设置为 `mode`。如果 `mode` 以数字开头，则解释为八进制数；否则解释为符号模式掩码，类似 `chmod` 命令接受的形式。如果省略 `mode`，`umask` 打印当前掩码值。如果提供 `-S` 且无 `mode` 参数，`umask` 以符号格式打印掩码；默认输出为八进制数。如果提供 `-p` 且省略 `mode`，输出格式可重用为输入。如果成功更改模式或未提供 `mode` 参数，返回状态为零；否则非零。

注意，当模式解释为八进制数时，umask 的每个数字从 `7` 中减去。因此，umask `022` 得到权限 `755`。

## unset

```sh
unset [-fnv] [name]
```

移除每个变量或函数 `name`。如果提供 `-v` 选项，每个 `name` 指 shell 变量，并移除该变量。如果提供 `-f` 选项，`name` 指 shell 函数，并移除函数定义。如果提供 `-n` 选项，且 `name` 是带 `nameref` 属性的变量，则取消设置 `name` 而不是其引用的变量。`-n` 与 `-f` 一起提供时无效果。如果未提供选项，每个 `name` 指变量；如果没有该名称的变量，则取消设置同名函数（如果有）。只读变量和函数不能取消设置。移除变量或函数时，也会从传递给后续命令的环境中移除它们。某些 shell 变量可能不能取消设置。某些 shell 变量取消设置后会失去特殊行为；此类行为在各变量描述中注明。返回状态为零，除非 `name` 为只读或不能取消设置。
