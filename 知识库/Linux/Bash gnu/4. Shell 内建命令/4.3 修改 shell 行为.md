# 4.3 修改 shell 行为

https://www.gnu.org/software/bash/manual/html_node/Modifying-Shell-Behavior.html

## 4.3.1 Set 内建命令

`set`

```bash
set [-abefhkmnptuvxBCEHPT] [-o option-name] [--] [-] [argument ...]
set [+abefhkmnptuvxBCEHPT] [+o option-name] [--] [-] [argument ...]
set -o
set +o
```

如果未提供选项或参数，`set` 会按当前区域设置排序，以可重新用作输入来设置或重置当前已设置变量的格式，显示所有 shell 变量和函数的名称与值。只读变量不能被重置。在 POSIX 模式下，仅列出 shell 变量。

当提供选项时，它们设置或取消 shell 属性。选项处理之后剩余的任何参数会替换位置参数。

如果指定了选项，其含义如下：

- `-a`
    
    每个创建或修改的变量或函数都会被赋予导出属性，并标记为导出到后续命令的环境中。

- `-b`
    
    使已终止后台作业的状态立即报告，而不是在打印下一个主提示符之前报告，或在某些情况下在前台命令退出时报告。这仅在启用作业控制时有效。

- `-e`
    
    如果管道（参见 [Pipelines]）返回非零状态，则立即退出；管道可能由单个简单命令（参见 [Simple Commands]）、列表（参见 [Lists of Commands]）或复合命令（参见 [Compound Commands]）组成。
    
    如果失败的命令是紧跟在 `while` 或 `until` 保留字之后的命令列表的一部分、`if` 语句测试的一部分、在 `&&` 或 `||` 列表中执行的任何命令的一部分（最终 `&&` 或 `||` 之后的命令除外）、管道中除最后一个命令之外的任何命令（受 `pipefail` shell 选项状态影响），或者命令的返回状态正用 `!` 取反，则 shell 不会退出。
    
    如果非子 shell 的复合命令因在 `-e` 被忽略时某个命令失败而返回非零状态，则 shell 不会退出。如果设置了 `ERR` 陷阱，则在 shell 退出前执行该陷阱。
    
    此选项分别应用于 shell 环境和每个子 shell 环境（参见 [Command Execution Environment]），并可能导致子 shell 在执行完子 shell 中的所有命令之前退出。
    
    如果复合命令或 shell 函数在 `-e` 被忽略的上下文中执行，则复合命令或函数体内执行的任何命令都不会受 `-e` 设置影响，即使已设置 `-e` 且命令返回失败状态。如果复合命令或 shell 函数在 `-e` 被忽略的上下文中执行时设置 `-e`，该设置不会生效，直到复合命令或包含函数调用的命令完成。

- `-f`
    
    禁用文件名展开（通配符展开）。

- `-h`
    
    在查找命令以执行时定位并记住（哈希）命令。此选项默认启用。

- `-k`
    
    所有形式为赋值语句的参数都放入命令的环境，而不仅仅是命令名之前的那些。

- `-m`
    
    启用作业控制（参见 [Job Control]）。所有进程在单独的进程组中运行。当后台作业完成时，shell 打印一行包含其退出状态的信息。

- `-n`
    
    读取命令但不执行它们。这可用于检查脚本的语法错误。交互式 shell 会忽略此选项。

- `-o option-name`
    
    设置与 `option-name` 对应的选项。如果提供 `-o` 但未提供 `option-name`，`set` 会打印当前 shell 选项设置。如果提供 `+o` 但未提供 `option-name`，`set` 会在标准输出上打印一系列 `set` 命令，以重建当前选项设置。有效选项名包括：
    
    - `allexport`
        
        与 `-a` 相同。
    
    - `braceexpand`
        
        与 `-B` 相同。
    
    - `emacs`
        
        使用 `emacs` 风格的行编辑接口（参见 [Command Line Editing]）。这也会影响用于 `read -e` 的编辑接口。
    
    - `errexit`
        
        与 `-e` 相同。
    
    - `errtrace`
        
        与 `-E` 相同。
    
    - `functrace`
        
        与 `-T` 相同。
    
    - `hashall`
        
        与 `-h` 相同。
    
    - `histexpand`
        
        与 `-H` 相同。
    
    - `history`
        
        启用命令历史，如 [Bash History Facilities] 所述。此选项在交互式 shell 中默认开启。
    
    - `ignoreeof`
        
        交互式 shell 在读取 EOF 时不会退出。
    
    - `keyword`
        
        与 `-k` 相同。
    
    - `monitor`
        
        与 `-m` 相同。
    
    - `noclobber`
        
        与 `-C` 相同。
    
    - `noexec`
        
        与 `-n` 相同。
    
    - `noglob`
        
        与 `-f` 相同。
    
    - `nolog`
        
        当前被忽略。
    
    - `notify`
        
        与 `-b` 相同。
    
    - `nounset`
        
        与 `-u` 相同。
    
    - `onecmd`
        
        与 `-t` 相同。
    
    - `physical`
        
        与 `-P` 相同。
    
    - `pipefail`
        
        如果设置，管道的返回值是最后一个（最右侧）以非零状态退出的命令的值，如果管道中所有命令都成功退出则为零。此选项默认禁用。
    
    - `posix`
        
        启用 POSIX 模式；在默认操作与 POSIX 标准不同的地方更改 Bash 行为以匹配标准（参见 [Bash and POSIX]）。旨在使 Bash 表现为该标准的严格超集。
    
    - `privileged`
        
        与 `-p` 相同。
    
    - `verbose`
        
        与 `-v` 相同。
    
    - `vi`
        
        使用 `vi` 风格的行编辑接口。这也会影响用于 `read -e` 的编辑接口。
    
    - `xtrace`
        
        与 `-x` 相同。

- `-p`
    
    开启特权模式。在此模式下，不处理 `$BASH_ENV` 和 `$ENV` 文件，不从环境继承 shell 函数，并且环境中的 `SHELLOPTS`、`BASHOPTS`、`CDPATH` 和 `GLOBIGNORE` 变量会被忽略。如果 shell 启动时有效用户（组）ID 不等于真实用户（组）ID，且未提供 `-p` 选项，则采取这些操作并将有效用户 ID 设置为真实用户 ID。如果启动时提供了 `-p` 选项，则有效用户 ID 不会被重置。关闭此选项会导致有效用户和组 ID 被设置为真实用户和组 ID。

- `-r`
    
    启用受限 shell 模式（参见 [The Restricted Shell]）。此选项一旦设置便无法取消。

- `-t`
    
    在读取并执行一个命令后退出。

- `-u`
    
    在执行参数展开时，将未设置的变量和参数（特殊参数 `@` 或 `*`，以及用 `@` 或 `*` 下标的数组变量除外）视为错误。错误消息会写入标准错误，非交互式 shell 将退出。

- `-v`
    
    在读取 shell 输入行时将其打印到标准错误。

- `-x` 🛠️
    
    在简单命令、`for` 命令、`case` 命令、`select` 命令和算术 `for` 命令及其参数或关联单词列表展开之后、执行之前，将其跟踪信息打印到标准错误。shell 会在命令及其展开参数之前打印 `PS4` 变量的展开值（提示符）。

    > 用来追踪调试，例如

    ```sh
    #!/bin/bash
    
    # 设置提示符，使用当前文件路径
    PS4='${BASH_SOURCE} >>> '

    set -x
    ls -al /challenge/
    set +x
    ```

- `-B`
    
    shell 将执行花括号展开（参见 [Brace Expansion]）。此选项默认开启。

- `-C`
    
    防止使用 `>`、`>&` 和 `<>` 的输出重定向覆盖现有文件。使用重定向操作符 `>|` 代替 `>` 将覆盖此行为并强制创建输出文件。

- `-E`
    
    如果设置，任何 `ERR` 陷阱都会被 shell 函数、命令替换和在子 shell 环境中执行的命令继承。通常在这种情况下不会继承 `ERR` 陷阱。

- `-H`
    
    启用 `!` 风格的历史替换（参见 [History Expansion]）。此选项在交互式 shell 中默认开启。

- `-P`
    
    如果设置，Bash 在执行 `cd` 等更改当前目录的命令时不会解析符号链接。它改用物理目录结构。默认情况下，Bash 在执行更改当前目录的命令时遵循逻辑目录链。
    
    例如，如果 `/usr/sys` 是指向 `/usr/local/sys` 的符号链接，则：
    
    ```sh
    $ cd /usr/sys; echo $PWD
    /usr/sys
    $ cd ..; pwd
    /usr
    ```
    
    如果 `set -P` 开启，则：
    
    ```sh
    $ cd /usr/sys; echo $PWD
    /usr/local/sys
    $ cd ..; pwd
    /usr/local
    ```

- `-T`
    
    如果设置，任何 `DEBUG` 和 `RETURN` 陷阱都会被 shell 函数、命令替换和在子 shell 环境中执行的命令继承。通常在这种情况下不会继承 `DEBUG` 和 `RETURN` 陷阱。

- `--`
    
    如果此选项后没有参数，则取消设置位置参数。否则，位置参数被设置为 `argument`，即使其中一些以 `-` 开头。

- `-`
    
    表示选项结束，并将所有剩余的 `argument` 赋给位置参数。`-x` 和 `-v` 选项会被关闭。如果没有参数，位置参数保持不变。

使用 `+` 而不是 `-` 会关闭这些选项。这些选项也可在调用 shell 时使用。当前选项集可在 `$-` 中找到。

剩余的 N 个 `argument` 是位置参数，按顺序赋给 `$1`、`$2`、…、`$N`。特殊参数 `#` 被设置为 N。

除非提供了无效选项，否则返回状态始终为零。
