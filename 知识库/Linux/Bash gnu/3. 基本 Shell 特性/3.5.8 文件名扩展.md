# 3.5.8 文件名扩展

在单词拆分之后，除非已设置 `-f` 选项（参见 [Set 内建命令]），Bash 会扫描每个单词中的字符 `*`、`?` 和 `[`。如果出现这些字符之一且未被引用，则该单词被视为一个 `pattern`，并替换为与该模式匹配的文件名排序列表（参见 [模式匹配]），排序结果受 `GLOBSORT` shell 变量的值影响（参见 [Bash 变量]）。

如果未找到匹配的文件名，并且 shell 选项 `nullglob` 已禁用，则该单词保持不变。如果设置了 `nullglob` 选项且未找到匹配项，则该单词会被移除。如果设置了 `failglob` shell 选项且未找到匹配项，Bash 会打印错误消息并且不执行命令。如果启用了 shell 选项 `nocaseglob`，则匹配时不考虑字母字符的大小写。

当模式用于文件名扩展时，文件名开头或紧跟斜杠之后的字符 `.` 必须被显式匹配，除非设置了 shell 选项 `dotglob`。为了匹配文件名 `.` 和 `..`，模式必须以 `.` 开头（例如 `.?`），即使设置了 `dotglob`。如果启用了 `globskipdots` shell 选项，则即使模式以 `.` 开头，文件名 `.` 和 `..` 也永远不会匹配。当不匹配文件名时，字符 `.` 不会被特殊对待。

匹配文件名时，斜杠字符必须始终由模式中的斜杠显式匹配，但在其他匹配上下文中，它可以由特殊模式字符匹配，如下所述（参见 [模式匹配]）。

参见 [Shopt 内建命令] 中 `shopt` 的描述，了解 `nocaseglob`、`nullglob`、`globskipdots`、`failglob` 和 `dotglob` 选项。

`GLOBIGNORE` shell 变量可用于限制匹配某个模式的文件名集合。如果设置了 `GLOBIGNORE`，则每个同时匹配 `GLOBIGNORE` 中某个模式的匹配文件名都会从匹配列表中移除。如果设置了 `nocaseglob` 选项，则与 `GLOBIGNORE` 中模式的匹配不区分大小写。当 `GLOBIGNORE` 已设置且非空时，文件名 `.` 和 `..` 总会被忽略。但是，将 `GLOBIGNORE` 设置为非空值会产生启用 `dotglob` shell 选项的效果，因此所有其他以 `.` 开头的文件名都会匹配。要恢复忽略以 `.` 开头文件名的旧行为，请将 `.*` 设为 `GLOBIGNORE` 中的一个模式。取消设置 `GLOBIGNORE` 时，`dotglob` 选项会被禁用。`GLOBIGNORE` 模式匹配遵循 `extglob` shell 选项的设置。

## 3.5.8.1 模式匹配

模式中出现的任何字符（下文描述的特殊模式字符除外）都匹配其自身。`NUL` 字符不能出现在模式中。反斜杠会转义其后的字符；匹配时，用于转义的反斜杠会被丢弃。若要按字面匹配特殊模式字符，必须引用它们。

特殊模式字符的含义如下：

- `*`  
  匹配任意字符串，包括空字符串。当启用 `globstar` shell 选项，且在文件名扩展上下文中使用 `*` 时，两个相邻的 `*` 作为单个模式使用，会匹配所有文件以及零个或多个目录和子目录。如果后面跟 `/`，两个相邻的 `*` 仅匹配目录和子目录。

- `?`  
  匹配任意单个字符。

- `[…]`  
  匹配方括号内任意一个字符。这称为*方括号表达式*，匹配单个字符。由连字符分隔的一对字符表示*范围表达式*；使用当前区域设置的排序序列和字符集，包含在这两个字符之间（含端点）的任意字符都会匹配。如果 `[` 后的第一个字符是 `!` 或 `^`，则匹配不在该范围内的任意字符。要匹配 `−`，将其作为集合中的第一个或最后一个字符。要匹配 `]`，将其作为集合中的第一个字符。
  
  范围表达式中字符的排序顺序以及范围包含的字符，由当前区域设置以及（如果设置）`LC_COLLATE` 和 `LC_ALL` shell 变量的值决定。
  
  例如，在默认 C 区域设置中，`[a-dx-z]` 等价于 `[abcdxyz]`。许多区域设置按字典顺序排序字符，在这些区域设置中，`[a-dx-z]` 通常不等价于 `[abcdxyz]`；例如，它可能等价于 `[aBbCcDdxYyZz]`。要获得方括号表达式中范围的传统解释，可以通过将 `LC_COLLATE` 或 `LC_ALL` 环境变量设置为 `C` 来强制使用 C 区域设置，或启用 `globasciiranges` shell 选项。
  
  在方括号表达式内，可以使用语法 `[:class:]` 指定*字符类*，其中 `class` 是 POSIX 标准定义的以下类之一：
  
  `alnum alpha ascii blank cntrl digit graph lower print punct space upper word xdigit`。
  
  字符类匹配属于该类的任意字符。`word` 字符类匹配字母、数字和下划线 `_`。
  
  例如，以下模式将匹配当前区域设置中属于 `space` 字符类的任意字符，然后匹配任意大写字母或 `!`、一个点，最后匹配任意小写字母或连字符：`[[:space:]][[:upper:]!].[-[:lower:]]`。
  
  在方括号表达式内，可以使用语法 `[=c=]` 指定*等价类*，它匹配与字符 `c` 具有相同排序权重（由当前区域设置定义）的所有字符。
  
  在方括号表达式内，语法 `[.symbol.]` 匹配排序符号 `symbol`。

如果使用 `shopt` 内建命令启用了 `extglob` shell 选项，shell 会识别若干扩展模式匹配操作符。在以下描述中，`pattern-list` 是由一个或多个模式组成的列表，模式之间用 `|` 分隔。匹配文件名时，`dotglob` shell 选项决定要测试的文件名集合，如上所述。复合模式可以由以下一个或多个子模式构成：

- `?(pattern-list)`  
  匹配给定模式的零次或一次出现。

- `*(pattern-list)`  
  匹配给定模式的零次或多次出现。

- `+(pattern-list)`  
  匹配给定模式的一次或多次出现。

- `@(pattern-list)`  
  匹配给定模式之一。

- `!(pattern-list)`  
  匹配除给定模式之一以外的任意内容。

`extglob` 选项会改变解析器的行为，因为圆括号通常被当作具有语法含义的操作符。为确保扩展匹配模式被正确解析，请确保在解析包含这些模式的构造（包括 shell 函数和命令替换）之前启用 `extglob`。

匹配文件名时，`dotglob` shell 选项决定要测试的文件名集合：启用 `dotglob` 时，文件名集合包括所有以 `.` 开头的文件，但文件名 `.` 和 `..` 必须由以点开头的模式或子模式匹配；禁用 `dotglob` 时，除非模式或子模式以 `.` 开头，否则集合不包含任何以 `.` 开头的文件名。如果启用了 `globskipdots` shell 选项，文件名 `.` 和 `..` 永远不会出现在集合中。如上所述，`.` 仅在匹配文件名时具有特殊含义。

对长字符串进行复杂的扩展模式匹配较慢，尤其是当模式包含交替分支且字符串包含多个匹配项时。对较短的字符串分别匹配，或使用字符串数组而不是单个长字符串，可能更快。
