# 3.2.5.2 条件结构

## `if`

```sh
if test-commands; then
  consequent-commands;
[elif more-test-commands; then
  more-consequents;]
[else alternate-consequents;]
fi
```

`test-commands` 列表被执行，如果其返回状态为零，则执行 `consequent-commands` 列表。如果 `test-commands` 返回非零状态，则依次执行每个 `elif` 列表，如果其退出状态为零，则执行相应的 `more-consequents` 并命令完成。如果存在 `else alternate-consequents`，并且最终 `if` 或 `elif` 子句中的最后一个命令具有非零退出状态，则执行 `alternate-consequents`。返回状态是最后执行命令的退出状态，如果没有条件测试为真，则为零。

## `case`

```sh
case word in
    [ [(] pattern [| pattern]...) command-list ;;]...
esac
```

`case` 将选择性地执行与第一个匹配 `word` 的 `pattern` 相对应的 `command-list`，从第一个模式到最后一个模式依次进行。匹配按照下面 [模式匹配] 中描述的规则执行。如果启用了 `nocasematch` shell 选项（参见 [The Shopt Builtin] 中 `shopt` 的描述），则匹配时不考虑字母字符的大小写。`|` 用于分隔模式列表中的多个模式，`)` 运算符终止模式列表。模式列表及其关联的 `command-list` 称为一个 `clause`。

每个子句必须以 `;;`、`;&` 或 `;;&` 终止。在 shell 尝试匹配模式之前，`word` 会进行波浪号展开、参数展开、命令替换、进程替换、算术展开和引号移除（参见 [Shell 参数展开]）。每个 `pattern` 也会进行波浪号展开、参数展开、命令替换、算术展开、进程替换和引号移除。

可以有任意数量的 `case` 子句，每个由 `;;`、`;&` 或 `;;&` 终止。第一个匹配的模式决定执行的命令列表。常见的惯用法是使用 `*` 作为最后一个模式来定义默认情况，因为该模式总是匹配。

下面是一个在脚本中使用 `case` 的示例，可用于描述动物的一个有趣特征：

```sh
echo -n "Enter the name of an animal: "
read ANIMAL
echo -n "The $ANIMAL has "
case $ANIMAL in
  horse | dog | cat) echo -n "four";;
  man | kangaroo ) echo -n "two";;
  *) echo -n "an unknown number of";;
esac
echo " legs."
```

如果使用 `;;` 运算符，`case` 命令在第一个模式匹配后完成。使用 `;&` 代替 `;;` 会导致执行继续到下一个子句关联的 `command-list`（如果有）。使用 `;;&` 代替 `;;` 会导致 shell 测试下一个子句中的模式（如果有），如果匹配成功则执行任何关联的 `command-list`，并继续执行 case 语句，就好像模式列表没有匹配一样。

如果没有模式匹配，返回状态为零。否则，返回状态是最后执行的 `command-list` 的退出状态。

## `select`

```sh
select name [in words ...]; do commands; done
```

`select` 结构允许轻松生成菜单。其语法与 `for` 命令几乎相同：

首先，展开 `in` 后面的单词列表，生成一个项目列表，并将展开的单词集合打印到标准错误流，每个单词前面带有一个数字。如果省略 `in words`，则打印位置参数，就像指定了 `in "$@"` 一样。然后 `select` 显示 `PS3` 提示符并从标准输入读取一行。如果该行由与某个显示单词对应的数字组成，则 `select` 将 `name` 的值设置为该单词。如果该行为空，`select` 再次显示单词和提示符。如果读取到 `EOF`，`select` 完成并返回 1。读取任何其他值会导致 `name` 设置为空。读取的行保存在变量 `REPLY` 中。

每次选择后都会执行 `commands`，直到执行 `break` 命令，此时 `select` 命令完成。

下面是一个示例，允许用户从当前目录中选择一个文件名，并显示所选文件的名称和索引。

```sh
select fname in *;
do
	echo you picked $fname \($REPLY\)
	break;
done
```

## `((…))`

```sh
(( expression ))
```

算术 `expression` 根据下面描述的规则求值（参见 [Shell 算术]）。`expression` 进行与双引号内相同的展开，但 `expression` 中未转义的双引号字符不被特殊处理并被移除。由于这可能导致空字符串，此命令将那些视为求值为 0 的表达式。如果表达式的值非零，则返回状态为 0；否则返回状态为 1。

## `[[…]]`

```sh
[[ expression ]]
```

求值条件表达式 `expression` 并返回状态零（真）或非零（假）。表达式由下面 [Bash 条件表达式] 中描述的原语组成。`[[` 和 `]]` 之间的单词不进行单词拆分和文件名展开。shell 对这些单词执行波浪号展开、参数和变量展开、算术展开、命令替换、进程替换和引号移除。条件运算符如 `-f` 必须不加引号才能被识别为原语。

当与 `[[` 一起使用时，`<` 和 `>` 运算符使用当前区域设置按字典顺序排序。

当使用 `==` 和 `!=` 运算符时，运算符右侧的字符串被视为模式，并按照下面 [模式匹配] 中描述的规则进行匹配，就像启用了 `extglob` shell 选项一样。`=` 运算符与 `==` 相同。如果启用了 `nocasematch` shell 选项（参见 [The Shopt Builtin] 中 `shopt` 的描述），则匹配时不考虑字母字符的大小写。如果字符串匹配（`==`）或不匹配（`!=`）模式，则返回值为 0，否则为 1。

如果你使用任何 shell 引用机制引用模式的任何部分，则引用的部分按字面匹配。这意味着引用部分中的每个字符都匹配自身，而不是具有任何特殊的模式匹配含义。

还有一个额外的二元运算符 `=~`，其优先级与 `==` 和 `!=` 相同。当你使用 `=~` 时，运算符右侧的字符串被视为 POSIX 扩展正则表达式模式并相应匹配（使用通常在 [regex(3)] 中描述的 POSIX `regcomp` 和 `regexec` 接口）。如果字符串匹配模式，则返回值为 0；如果不匹配，则为 1。如果正则表达式语法不正确，则条件表达式返回 2。如果启用了 `nocasematch` shell 选项（参见 [The Shopt Builtin] 中 `shopt` 的描述），则匹配时不考虑字母字符的大小写。

你可以引用模式的任何部分，以强制引用部分按字面匹配，而不是作为正则表达式（见上文）。如果模式存储在 shell 变量中，引用变量展开会强制整个模式按字面匹配。

如果模式匹配字符串的任何部分，则匹配成功。如果你想强制模式匹配整个字符串，请使用 `^` 和 `$` 正则表达式运算符锚定模式。

例如，以下内容将匹配一行（存储在 shell 变量 `line` 中），如果值中任何位置存在一个字符序列，该序列由任意数量（包括零个）的 `space` 字符类中的字符组成，紧接着是零个或一个 `a`，然后是一个 `b`：

```sh
[[ $line =~ [[:space:]]*(a)?b ]]
```

这意味着 `line` 的值如 `aab`、`  aaaaaab`、`xaby` 和 ` ab` 都将匹配，包含 `b` 的行也会匹配。

如果你想匹配正则表达式语法中的特殊字符（`^$|[]()\.*+?`），必须引用它以移除其特殊含义。这意味着在模式 `xxx.txt` 中，`.` 匹配字符串中的任何字符（其通常的正则表达式含义），但在模式 `"xxx.txt"` 中，它只能匹配字面 `.`。

同样，如果你想在模式中包含对正则表达式语法有特殊含义的字符，必须确保它没有被引用。例如，如果你想在字符串开头或结尾锚定模式，就不能使用任何形式的 shell 引用引用 `^` 或 `$` 字符。

如果你想在行首匹配 `initial string`，以下内容可以工作：

```sh
[[ $line =~ ^"initial string" ]]
```

但以下内容不行：

```sh
[[ $line =~ "^initial string" ]]
```

因为在第二个示例中 `^` 被引用了，不具有其通常的特殊含义。

有时在不使用引号的情况下正确指定正则表达式，或在注意 shell 引用和 shell 引号移除的同时跟踪正则表达式使用的引用，是很困难的。将正则表达式存储在 shell 变量中通常是避免 shell 特殊引用字符问题的有用方法。例如，以下内容与上面使用的模式等效：

```sh
pattern='[[:space:]]*(a)?b'
[[ $line =~ $pattern ]]
```

Shell 程序员应特别注意反斜杠，因为反斜杠既被 shell 也被正则表达式用于移除后续字符的特殊含义。这意味着在 shell 的单词展开完成后（参见 [Shell 展开]），模式中原本未引用的部分中剩余的任何反斜杠都可以移除模式字符的特殊含义。如果模式的任何部分被引用，shell 会尽力确保正则表达式将那些剩余的反斜杠视为字面量（如果它们出现在引用部分中）。

以下两组命令**不**等价：

```sh
pattern='\.'

[[ . =~ $pattern ]]
[[ . =~ \. ]]

[[ . =~ "$pattern" ]]
[[ . =~ '\.' ]]
```

前两个匹配将成功，但后两个不会，因为后两个中反斜杠将成为要匹配的模式的一部分。在前两个示例中，传递给正则表达式解析器的模式是 `\.`。反斜杠移除了 `.` 的特殊含义，因此字面 `.` 匹配。在后两个示例中，传递给正则表达式解析器的模式中反斜杠被引用了（例如 `\\\.`），这将无法匹配字符串，因为字符串不包含反斜杠。如果第一个示例中的字符串不是 `.`，比如 `a`，则模式将不匹配，因为模式中引用的 `.` 失去了匹配任何单个字符的特殊含义。

正则表达式中的方括号表达式也可能成为错误来源，因为通常在正则表达式中特殊的字符在方括号之间失去其特殊含义。但是，你可以使用方括号表达式来匹配特殊模式字符而无需引用它们，因此它们有时对此目的很有用。

尽管看起来可能是一种奇怪的写法，但以下模式将匹配字符串中的 `.`：

```sh
[[ . =~ [.] ]]
```

shell 在将模式传递给正则表达式函数之前执行任何单词展开，因此你可以假设 shell 的引用优先。如上所述，正则表达式解析器将根据其自身规则解释 shell 展开后模式中剩余的任何未引用反斜杠。目的是尽可能避免让 shell 程序员引用两次，因此 shell 引用应足以在必要时引用特殊模式字符。

数组变量 `BASH_REMATCH` 记录字符串中哪些部分匹配了模式。`BASH_REMATCH` 中索引为 0 的元素包含匹配整个正则表达式的字符串部分。正则表达式中括号子表达式匹配的子字符串保存在剩余的 `BASH_REMATCH` 索引中。`BASH_REMATCH` 中索引为 `n` 的元素是匹配第 `n` 个括号子表达式的字符串部分。

Bash 在全局作用域中设置 `BASH_REMATCH`；将其声明为局部变量将导致意外结果。

表达式可以使用以下运算符组合，按优先级递减顺序列出：

- `( expression )`  
  返回 `expression` 的值。这可用于覆盖运算符的正常优先级。
- `! expression`  
  如果 `expression` 为假，则为真。
- `expression1 && expression2`  
  如果 `expression1` 和 `expression2` 都为真，则为真。
- `expression1 || expression2`  
  如果 `expression1` 或 `expression2` 为真，则为真。

如果 `expression1` 的值足以确定整个条件表达式的返回值，则 `&&` 和 `||` 运算符不会求值 `expression2`。
