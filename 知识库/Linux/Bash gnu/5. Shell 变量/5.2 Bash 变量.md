# 5.2 Bash 变量

这些变量由 Bash 设置或使用，但其他 shell 通常不会特殊对待它们。

Bash 使用的一些变量在其他章节描述：用于控制作业控制设施的变量（参见 [Job Control Variables]）。

- `_`    
    （`$_`，一个下划线。）根据上下文有多种含义。在 shell 启动时，`$_` 被设置为用于调用 shell 或正在执行的 shell 脚本的路径名，该路径名通过环境或参数列表传入。随后，它展开为前台执行的上一简单命令的最后一个参数（展开后）。它还被设置为用于调用所执行每个命令的完整路径名，并放入导出给该命令的环境中。检查邮件时，`$_` 展开为邮件文件名。

- `BASH`    
    用于执行当前 Bash 实例的完整路径名。

- `BASHOPTS`    
    以冒号分隔的已启用 shell 选项列表。列表中的每个词都是 `shopt` 内建命令 `-s` 选项的有效参数（参见 [The Shopt Builtin]）。`BASHOPTS` 中出现的选项是 `shopt` 报告为 `on` 的选项。如果 Bash 启动时此变量在环境中，shell 会在读取任何启动文件之前启用列表中的每个选项。如果导出此变量，子 shell 将启用列表中的每个选项。此变量为只读。

- `BASHPID`    
    展开为当前 Bash 进程的进程 ID。在某些情况下（例如不需要重新初始化 Bash 的子 shell），这与 `$$` 不同。对 `BASHPID` 赋值无效。如果 `BASHPID` 未设置，它会失去特殊属性，即使随后重新设置也是如此。

- `BASH_ALIASES`    
    一个关联数组变量，其成员对应于 `alias` 内建命令维护的内部别名列表（参见 [Bourne Shell Builtins]）。添加到此数组的元素会出现在别名列表中；然而，当前取消设置数组元素不会从别名列表中移除别名。如果 `BASH_ALIASES` 未设置，它会失去特殊属性，即使随后重新设置也是如此。

- `BASH_ARGC`    
    一个数组变量，其值为当前 Bash 执行调用栈中每一帧的参数个数。当前子例程（shell 函数或用 `.` 或 `source` 执行的脚本）的参数个数位于栈顶。执行子例程时，传入的参数个数被压入 `BASH_ARGC`。shell 仅在扩展调试模式下设置 `BASH_ARGC`（关于 `shopt` 内建命令的 `extdebug` 选项，参见 [The Shopt Builtin]）。在 shell 已开始执行子例程后设置 `extdebug`，或在未设置 `extdebug` 时引用此变量，可能导致不一致的值。对 `BASH_ARGC` 赋值无效，且不能取消设置。

- `BASH_ARGV`    
    一个数组变量，包含当前 Bash 执行调用栈中的所有参数。最后一次子例程调用的最后一个参数位于栈顶；初始调用的第一个参数位于栈底。执行子例程时，shell 将提供的参数压入 `BASH_ARGV`。shell 仅在扩展调试模式下设置 `BASH_ARGV`（关于 `shopt` 内建命令的 `extdebug` 选项，参见 [The Shopt Builtin]）。在 shell 已开始执行脚本后设置 `extdebug`，或在未设置 `extdebug` 时引用此变量，可能导致不一致的值。对 `BASH_ARGV` 赋值无效，且不能取消设置。

- `BASH_ARGV0`    
    引用时，此变量展开为 shell 或 shell 脚本的名称（与 `$0` 相同；关于特殊参数 0 的描述，参见 [Special Parameters]）。给 `BASH_ARGV0` 赋值会将 `$0` 设置为相同的值。如果 `BASH_ARGV0` 未设置，它会失去特殊属性，即使随后重新设置也是如此。

- `BASH_CMDS`    
    一个关联数组变量，其成员对应于 `hash` 内建命令维护的内部命令哈希表（参见 [Bourne Shell Builtins]）。向此数组添加元素会使它们出现在哈希表中；然而，当前取消设置数组元素不会从哈希表中移除命令名。如果 `BASH_CMDS` 未设置，它会失去特殊属性，即使随后重新设置也是如此。

- `BASH_COMMAND`    
    展开为当前正在执行或即将执行的命令，除非 shell 正在执行由陷阱触发的命令，此时它是陷阱发生时刻正在执行的命令。如果 `BASH_COMMAND` 未设置，它会失去特殊属性，即使随后重新设置也是如此。

- `BASH_COMPAT`    
    该值用于设置 shell 的兼容级别。关于各种兼容级别及其效果，参见 [Shell Compatibility Mode]。该值可以是十进制数（例如 4.2）或整数（例如 42），对应于所需的兼容级别。如果 `BASH_COMPAT` 未设置或设置为空字符串，兼容级别设置为当前版本的默认值。如果 `BASH_COMPAT` 设置为不是有效兼容级别之一的值，shell 会打印错误消息并将兼容级别设置为当前版本的默认值。有效值的子集对应于下面描述的兼容级别（参见 [Shell Compatibility Mode]）。例如，4.2 和 42 是有效值，对应于 `compat42` `shopt` 选项，并将兼容级别设置为 42。当前版本也是有效值。

- `BASH_ENV`    
    如果在调用 Bash 执行 shell 脚本时设置了此变量，其值会被展开并用作启动文件名，在执​​行脚本之前读取。Bash 不使用 `PATH` 搜索生成的​​文件名。参见 [Bash Startup Files]。

- `BASH_EXECUTION_STRING`    
    `-c` 调用选项的命令参数。

- `BASH_LINENO`    
    一个数组变量，其成员是源文件中的行号，`FUNCNAME` 的每个对应成员在这些行被调用。`${BASH_LINENO[$i]}` 是源文件（`${BASH_SOURCE[$i+1]}`）中调用 `${FUNCNAME[$i]}` 的行号（如果在另一个 shell 函数内引用，则为 `${BASH_LINENO[$i-1]}`）。使用 `LINENO` 获取当前行号。对 `BASH_LINENO` 赋值无效，且不能取消设置。

- `BASH_LOADABLES_PATH`    
    以冒号分隔的目录列表，`enable` 命令在其中查找动态可加载的内建命令。

- `BASH_MONOSECONDS`    
    每次引用此变量时，它展开为系统单调时钟返回的值（如果可用）。如果没有单调时钟，则等同于 `EPOCHSECONDS`。如果 `BASH_MONOSECONDS` 未设置，它会失去特殊属性，即使随后重新设置也是如此。

- `BASH_REMATCH`    
    一个数组变量，其成员由 `[[` 条件命令的 `=~` 二元操作符赋值（参见 [Conditional Constructs]）。索引 0 的元素是匹配整个正则表达式的字符串部分。索引 `n` 的元素是匹配第 `n` 个括号子表达式的字符串部分。

- `BASH_SOURCE`    
    一个数组变量，其成员是定义 `FUNCNAME` 数组变量中对应 shell 函数名的源文件名。shell 函数 `${FUNCNAME[$i]}` 在文件 `${BASH_SOURCE[$i]}` 中定义，并从 `${BASH_SOURCE[$i+1]}` 调用。对 `BASH_SOURCE` 赋值无效，且不能取消设置。

- `BASH_SUBSHELL`    
    在每个子 shell 或子 shell 环境中，当 shell 开始在该环境中执行时加一。初始值为 0。如果 `BASH_SUBSHELL` 未设置，它会失去特殊属性，即使随后重新设置也是如此。

- `BASH_TRAPSIG`    
    设置为在执行陷阱动作期间，与该陷阱动作相对应的信号编号。关于信号编号和陷阱执行的信息，参见 `trap` 的描述（参见 [Bourne Shell Builtins]）。

- `BASH_VERSINFO`    
    一个只读数组变量（参见 [Arrays]），其成员保存此 Bash 实例的版本信息。赋给数组成员的值如下：
    
    - `BASH_VERSINFO[0]`        
        主版本号（发行版）。
    
    - `BASH_VERSINFO[1]`        
        次版本号（版本）。
    
    - `BASH_VERSINFO[2]`        
        补丁级别。
    
    - `BASH_VERSINFO[3]`        
        构建版本。
    
    - `BASH_VERSINFO[4]`        
        发行状态（例如 `beta`）。
    
    - `BASH_VERSINFO[5]`        
        `MACHTYPE` 的值。

- `BASH_VERSION`    
    展开为描述此 Bash 实例版本的字符串（例如 5.2.37(3)-release）。

- `BASH_XTRACEFD`    
    如果设置为对应于有效文件描述符的整数，Bash 会将启用 `set -x` 时生成的跟踪输出写入该文件描述符，而不是标准错误。这允许将跟踪输出与诊断和错误消息分开。当 `BASH_XTRACEFD` 未设置或被赋新值时，该文件描述符会被关闭。取消设置 `BASH_XTRACEFD` 或将其赋为空字符串会导致跟踪输出发送到标准错误。注意，将 `BASH_XTRACEFD` 设置为 2（标准错误文件描述符）然后取消设置它，会导致标准错误被关闭。

- `CHILD_MAX`    
    设置 shell 记住的已退出子进程状态值的数量。Bash 不允许将此值降低到 POSIX 规定的最小值以下，并且有最大值（当前为 8192）不能超过。最小值取决于系统。

- `COLUMNS`    
    由 `select` 命令用于在打印选择列表时确定终端宽度。如果启用了 `checkwinsize` 选项（参见 [The Shopt Builtin]），或在交互式 shell 中收到 `SIGWINCH` 时，会自动设置。

- `COMP_CWORD`    
    ` ${COMP_WORDS}` 中包含当前光标位置的单词的索引。此变量仅在可编程补全设施调用的 shell 函数中可用（参见 [Programmable Completion]）。

- `COMP_KEY`    
    用于调用当前补全函数的键（或键序列的最终键）。此变量仅在可编程补全设施调用的 shell 函数和外部命令中可用（参见 [Programmable Completion]）。

- `COMP_LINE`    
    当前命令行。此变量仅在可编程补全设施调用的 shell 函数和外部命令中可用（参见 [Programmable Completion]）。

- `COMP_POINT`    
    当前光标位置相对于当前命令开头的索引。如果当前光标位置位于当前命令末尾，则此变量的值等于 `${#COMP_LINE}`。此变量仅在可编程补全设施调用的 shell 函数和外部命令中可用（参见 [Programmable Completion]）。

- `COMP_TYPE`    
    设置为一个整数值，对应于导致调用补全函数的尝试补全类型：`TAB` 表示普通补全，`?` 表示连续按 Tab 后列出补全，`!` 表示在部分单词补全时列出备选项，`@` 表示如果单词未被修改则列出补全，`%` 表示菜单补全。此变量仅在可编程补全设施调用的 shell 函数和外部命令中可用（参见 [Programmable Completion]）。

- `COMP_WORDBREAKS`    
    Readline 库在执行单词补全时视为单词分隔符的字符集。如果 `COMP_WORDBREAKS` 未设置，它会失去特殊属性，即使随后重新设置也是如此。

- `COMP_WORDS`    
    一个数组变量，由当前命令行中的各个单词组成。该行按照 Readline 的拆分方式拆分，使用上面描述的 `COMP_WORDBREAKS`。此变量仅在可编程补全设施调用的 shell 函数中可用（参见 [Programmable Completion]）。

- `COMPREPLY`    
    一个数组变量，Bash 从中读取由可编程补全设施调用的 shell 函数生成的可能补全（参见 [Programmable Completion]）。每个数组元素包含一个可能的补全。

- `COPROC`    
    一个数组变量，用于保存未命名协进程的输出和输入文件描述符（参见 [Coprocesses]）。

- `DIRSTACK`    
    一个数组变量，包含目录栈的当前内容。目录按照 `dirs` 内建命令显示的顺序出现在栈中。给此数组变量的成员赋值可用于修改已在栈中的目录，但必须使用 `pushd` 和 `popd` 内建命令来添加和移除目录。给此变量赋值不会更改当前目录。如果 `DIRSTACK` 未设置，它会失去特殊属性，即使随后重新设置也是如此。

- `EMACS`    
    如果 Bash 在 shell 启动时在环境中找到此变量，且其值为 `t`，Bash 假定 shell 运行在 Emacs shell 缓冲区中，并禁用行编辑。

- `ENV`    
    当交互式 shell 在 POSIX 模式下调用时，其展开和执行方式类似于 `BASH_ENV`（参见 [Bash Startup Files]）（参见 [Bash and POSIX]）。

- `EPOCHREALTIME`    
    每次引用此参数时，它展开为自 Unix 纪元以来的秒数，作为具有微秒粒度的浮点值（关于纪元的定义，参见 C 库函数 `time` 的文档）。对 `EPOCHREALTIME` 的赋值会被忽略。如果 `EPOCHREALTIME` 未设置，它会失去特殊属性，即使随后重新设置也是如此。

- `EPOCHSECONDS`    
    每次引用此参数时，它展开为自 Unix 纪元以来的秒数（关于纪元的定义，参见 C 库函数 `time` 的文档）。对 `EPOCHSECONDS` 的赋值会被忽略。如果 `EPOCHSECONDS` 未设置，它会失去特殊属性，即使随后重新设置也是如此。

- `EUID`    
    当前用户的有效用户 ID 的数字值。此变量为只读。

- `EXECIGNORE`    
    以冒号分隔的 shell 模式列表（参见 [Pattern Matching]），定义通过 `PATH` 进行命令搜索时要忽略的文件名集合。完整路径名匹配这些模式之一的文件，在补全和通过 `PATH` 查找执行命令时不被视为可执行文件。这不影响 `[`、`test` 和 `[[` 命令的行为。命令哈希表中的完整路径名不受 `EXECIGNORE` 影响。使用此变量忽略设置了可执行位但不是可执行文件的共享库文件。模式匹配遵循 `extglob` shell 选项的设置。

- `FCEDIT`    
    `fc` 内建命令默认使用的编辑器。

- `FIGNORE`    
    以冒号分隔的后缀列表，在执行文件名补全时要忽略。后缀匹配 `FIGNORE` 中某项的文件名会从匹配文件名列表中排除。示例值为 `.o:~`。

- `FUNCNAME`    
    一个数组变量，包含当前执行调用栈中所有 shell 函数的名称。索引 0 的元素是任何当前正在执行的 shell 函数的名称。最底部的元素（索引最高的元素）是 `"main"`。此变量仅在 shell 函数执行时存在。对 `FUNCNAME` 赋值无效。如果 `FUNCNAME` 未设置，它会失去特殊属性，即使随后重新设置也是如此。
    
    此变量可与 `BASH_LINENO` 和 `BASH_SOURCE` 一起使用。`FUNCNAME` 的每个元素在 `BASH_LINENO` 和 `BASH_SOURCE` 中都有对应元素来描述调用栈。例如，`${FUNCNAME[$i]}` 是从文件 `${BASH_SOURCE[$i+1]}` 的第 `${BASH_LINENO[$i]}` 行调用的。`caller` 内建命令使用此信息显示当前调用栈。

- `FUNCNEST`    
    大于 0 的数值定义最大函数嵌套级别。超过此嵌套级别的函数调用会导致当前命令中止。

- `GLOBIGNORE`    
    以冒号分隔的模式列表，定义文件名展开时要忽略的文件名集合。如果某个文件名与文件名展开模式匹配，同时也匹配 `GLOBIGNORE` 中的某个模式，则它从匹配列表中移除。模式匹配遵循 `extglob` shell 选项的设置。

- `GLOBSORT`    
    控制文件名展开结果的排序方式。此变量的值指定文件名展开结果的排序条件和排序顺序。如果此变量未设置或设置为空字符串，文件名展开使用历史行为，即按名称排序，按 `LC_COLLATE` shell 变量确定的升序字典顺序排序。
    
    如果设置，有效值以可选的 `+`（被忽略）或 `-`（将排序顺序从升序反转为降序）开头，后跟排序说明符。有效的排序说明符有 `name`、`numeric`、`size`、`mtime`、`atime`、`ctime` 和 `blocks`，分别按名称、按数字而非字典顺序的名称、文件大小、修改时间、访问时间、inode 更改时间和块数对文件排序。如果任何非名称键比较相等（例如两个文件大小相同），排序使用名称作为次要排序键。
    
    例如，值 `-mtime` 按修改时间降序排序结果（最新在前）。
    
    `numeric` 说明符将仅由数字组成的名称视为数字，并按数值排序（因此例如 “2” 排在 “10” 前面）。使用 `numeric` 时，包含非数字的名称排在所有全数字名称之后，并按名称使用传统行为排序。
    
    排序说明符 `nosort` 完全禁用排序；Bash 按从文件系统读取结果的顺序返回结果，忽略任何前导 `-`。
    
    如果缺少排序说明符，默认为 `name`，因此值 `+` 等价于空字符串，值 `-` 按名称降序排序。
    
    任何无效值都会恢复历史排序行为。

- `GROUPS`    
    一个数组变量，包含当前用户所属组的列表。对 `GROUPS` 赋值无效。如果 `GROUPS` 未设置，它会失去特殊属性，即使随后重新设置也是如此。

- `histchars`    
    控制历史展开、快速替换和分词的​​两个或三个字符（参见 [History Expansion]）。第一个字符是历史展开字符，即开始历史展开的字符，通常为 `!`。第二个字符是快速替换字符，通常为 `^`。当它出现在行首时，历史替换会重复上一条命令，将一个字符串替换为另一个字符串。可选的第三个字符是历史注释字符，通常为 `#`，当它作为单词的第一个字符出现时，表示该行剩余部分是注释。历史注释字符会禁用该行剩余单词的历史替换。它不一定使 shell 解析器将行剩余部分视为注释。

- `HISTCMD`    
    当前命令的历史编号，或历史列表中的索引。对 `HISTCMD` 赋值无效。如果 `HISTCMD` 未设置，它会失去特殊属性，即使随后重新设置也是如此。

- `HISTCONTROL`    
    以冒号分隔的值列表，控制命令如何保存到历史列表。如果值列表包含 `ignorespace`，则以空格字符开头的行不会保存到历史列表。值 `ignoredups` 会使与上一历史条目匹配的行不被保存。值 `ignoreboth` 是 `ignorespace` 和 `ignoredups` 的简写。值 `erasedups` 会在保存当前行之前，从历史列表中移除所有与当前行匹配的先前行。上述列表之外的任何值都会被忽略。如果 `HISTCONTROL` 未设置或不包含有效值，Bash 会将 shell 解析器读取的所有行保存到历史列表，但受 `HISTIGNORE` 值的约束。如果多行复合命令的第一行被保存，第二行及后续行不会被测试，并且无论 `HISTCONTROL` 的值如何都会添加到历史中。如果第一行未被保存，命令的第二行及后续行也不会被保存。

- `HISTFILE`    
    保存命令历史的文件名。Bash 将默认值赋为 `~/.bash_history`。如果 `HISTFILE` 未设置或为空，shell 在退出时不保存命令历史。

- `HISTFILESIZE`    
    历史文件中包含的最大行数。当给此变量赋值时，如有必要会截断历史文件，通过删除最旧条目，使其包含不超过该行数的历史条目总数。如果历史列表包含多行条目，历史文件可能包含超过此最大值的行数，以避免留下部分历史条目。历史文件在 shell 退出时或由 `history` 内建命令写入后也会截断到此大小。如果值为 0，历史文件被截断为零大小。非数值和小于零的数值禁止截断。shell 在读取任何启动文件后将默认值设置为 `HISTSIZE` 的值。

- `HISTIGNORE`    
    以冒号分隔的模式列表，用于决定哪些命令行应保存到历史列表。如果命令行匹配 `HISTIGNORE` 值中的某个模式，则不会保存到历史列表。每个模式锚定在行首，必须匹配整行（Bash 不会隐式追加 `*`）。在应用 `HISTCONTROL` 指定的检查之后，每个模式与行进行测试。除了普通 shell 模式匹配字符外，`&` 匹配上一条历史行。反斜杠转义 `&`；在尝试匹配前会移除反斜杠。如果多行复合命令的第一行被保存，第二行及后续行不会被测试，并且无论 `HISTIGNORE` 的值如何都会添加到历史中。如果第一行未被保存，命令的第二行及后续行也不会被保存。模式匹配遵循 `extglob` shell 选项的设置。
    
    `HISTIGNORE` 包含 `HISTCONTROL` 的部分功能。模式 `&` 等同于 `ignoredups`，模式 `[ ]*` 等同于 `ignorespace`。将这两个模式用冒号分隔组合起来，提供 `ignoreboth` 的功能。

- `HISTSIZE`    
    历史列表中要记住的最大命令数。如果值为 0，命令不会保存到历史列表。小于零的数值会导致每条命令都保存到历史列表（没有限制）。shell 在读取任何启动文件后将默认值设置为 500。

- `HISTTIMEFORMAT`    
    如果此变量设置且不为空，其值用作 `strftime`(3) 的格式字符串，以打印 `history` 内建命令显示的每个历史条目关联的时间戳。如果设置此变量，shell 会将时间戳写入历史文件，以便在 shell 会话之间保留。这使用历史注释字符来区分时间戳和其他历史行。

- `HOSTFILE`    
    包含一个文件名，其格式与 `/etc/hosts` 相同，当 shell 需要补全主机名时应读取该文件。可能的​​主机名补全列表可能在 shell 运行时更改；值更改后下次尝试主机名补全时，Bash 将新文件的内容添加到现有列表。如果 `HOSTFILE` 已设置但没有值，或没有指定可读文件，Bash 尝试读取 `/etc/hosts` 以获取可能的​​主机名补全列表。当 `HOSTFILE` 未设置时，Bash 清除主机名列表。

- `HOSTNAME`    
    当前主机的名称。

- `HOSTTYPE`    
    描述 Bash 所运行机器的字符串。

- `IGNOREEOF`    
    控制 shell 在收到 EOF 字符作为唯一输入时的动作。如果设置，其值是 Bash 退出前可作为输入行第一个字符读取的连续 EOF 字符数。如果变量已设置但没有数值，或值为空，则默认为 10。如果变量未设置，则 EOF 表示 shell 输入结束。仅对交互式 shell 有效。

- `INPUTRC`    
    Readline 初始化文件的名称，覆盖默认的 `~/.inputrc`。

- `INSIDE_EMACS`    
    如果 Bash 在 shell 启动时在环境中找到此变量，它假定 shell 运行在 Emacs shell 缓冲区中，并可能根据 `TERM` 的值禁用行编辑。

- `LANG`    
    用于确定未由以 `LC_` 开头的变量专门选择的任何类别的区域设置类别。

- `LC_ALL`    
    此变量覆盖 `LANG` 的值以及任何其他指定区域设置类别的 `LC_` 变量。

- `LC_COLLATE`    
    此变量确定对文件名展开结果排序时使用的排序顺序，并确定文件名展开和模式匹配中范围表达式、等价类和排序序列的行为（参见 [Filename Expansion]）。

- `LC_CTYPE`    
    此变量确定文件名展开和模式匹配中字符的解释和字符类的行为（参见 [Filename Expansion]）。

- `LC_MESSAGES`    
    此变量确定用于翻译前面带 `$` 的双引号字符串的区域设置（参见 [Locale-Specific Translation]）。

- `LC_NUMERIC`    
    此变量确定用于数字格式化的区域设置类别。

- `LC_TIME`    
    此变量确定用于日期和时间格式化的区域设置类别。

- `LINENO`    
    当前正在执行的脚本或 shell 函数中的行号。行号从 1 开始。不在脚本或函数中时，该值不保证有意义。如果 `LINENO` 未设置，它会失去特殊属性，即使随后重新设置也是如此。

- `LINES`    
    由 `select` 命令用于确定打印选择列表时的列长度。如果启用了 `checkwinsize` 选项（参见 [The Shopt Builtin]），或在交互式 shell 中收到 `SIGWINCH` 时，会自动设置。

- `MACHTYPE`    
    完整描述 Bash 所执行系统类型的字符串，采用标准 GNU `cpu-company-system` 格式。

- `MAILCHECK`    
    shell 应以多高频率（以秒为单位）检查 `MAILPATH` 或 `MAIL` 变量中指定的文件中的邮件。默认值为 60 秒。当需要检查邮件时，shell 在显示主提示符之前进行检查。如果此变量未设置，或设置为不大于等于零的数字值，shell 禁用邮件检查。

- `MAPFILE`    
    一个数组变量，用于保存 `mapfile` 内建命令在未提供变量名时读取的文本。

- `OLDPWD`    
    由 `cd` 内建命令设置的上一工作目录。

- `OPTERR`    
    如果设置为值 1，Bash 会显示 `getopts` 内建命令生成的错误消息。每次调用 shell 时，`OPTERR` 初始化为 1。

- `OSTYPE`    
    描述 Bash 所运行操作系统的字符串。

- `PIPESTATUS`    
    一个数组变量（参见 [Arrays]），包含最近执行的前台管道中各命令的退出状态值列表，该管道可能仅由一条简单命令组成（参见 [Shell Commands]）。Bash 在执行多元素管道、带时间和取反的管道、简单命令、用 `(` 操作符创建的子 shell、`[[` 和 `((` 复合命令之后，以及在导致 shell 中止命令执行的错误条件之后设置 `PIPESTATUS`。

- `POSIXLY_CORRECT`    
    如果 Bash 启动时此变量在环境中，shell 在读取启动文件之前进入 POSIX 模式（参见 [Bash and POSIX]），就像提供了 `--posix` 调用选项一样。如果 shell 运行时设置它，Bash 启用 POSIX 模式，就像执行了以下命令：
    
    ```sh
    set -o posix
    ```
    
    当 shell 进入 POSIX 模式时，如果尚未设置此变量，则设置它。

- `PPID`    
    shell 父进程的进程 ID。此变量为只读。

- `PROMPT_COMMAND`    
    如果设置且为数组，每个已设置元素的值被解释为在打印主提示符（`$PS1`）之前执行的命令。如果设置但不是数组变量，则其值被用作要执行的命令。

- `PROMPT_DIRTRIM`    
    如果设置为大于零的数字，该值用作展开 `\w` 和 `\W` 提示符字符串转义时要保留的末尾目录组件数（参见 [Controlling the Prompt]）。移除的字符用省略号替换。

- `PS0`    
    此参数的值像 `PS1` 一样展开，并由交互式 shell 在读取命令之后、执行命令之前显示。

- `PS3`    
    此变量的值用作 `select` 命令的提示符。如果未设置，`select` 命令使用 `#? ` 作为提示符。

- `PS4` 🛠️    
    此参数的值像 `PS1` 一样展开，展开值是在设置 `-x` 选项时回显命令行之前打印的提示符（参见 [The Set Builtin]）。展开值的第一个字符会根据需要重复多次，以指示多个间接层级。默认值为 `+ `。

- `PWD`    
    由 `cd` 内建命令设置的当前工作目录。

- `RANDOM`    
    每次引用此参数时，它展开为 0 到 32767 之间的随机整数。给 `RANDOM` 赋值会初始化（播种）随机数序列。用相同常量值播种随机数生成器会产生相同的值序列。如果 `RANDOM` 未设置，它会失去特殊属性，即使随后重新设置也是如此。

- `READLINE_ARGUMENT`    
    使用 `bind -x` 定义的 Readline 命令在调用时获得的任何数字参数（参见 [Bash Builtin Commands]）。

- `READLINE_LINE`    
    Readline 行缓冲区的内容，供 `bind -x` 使用（参见 [Bash Builtin Commands]）。

- `READLINE_MARK`    
    Readline 行缓冲区中标记（保存的插入点）的位置，供 `bind -x` 使用（参见 [Bash Builtin Commands]）。插入点和标记之间的字符通常称为区域。

- `READLINE_POINT`    
    Readline 行缓冲区中插入点的位置，供 `bind -x` 使用（参见 [Bash Builtin Commands]）。

- `REPLY`    
    `read` 内建命令的默认变量；当 `read` 未提供变量名参数时，设置为读取的行。

- `SECONDS`    
    此变量展开为 shell 启动以来的秒数。对此变量赋值会将计数重置为所赋的值，展开值变为所赋的值加上自赋值以来的秒数。shell 调用时的秒数和当前时间始终通过以一秒分辨率查询系统时钟确定。如果 `SECONDS` 未设置，它会失去特殊属性，即使随后重新设置也是如此。

- `SHELL`    
    此环境变量展开为 shell 的完整路径名。如果 shell 启动时未设置，Bash 将当前用户登录 shell 的完整路径名赋给它。

- `SHELLOPTS`    
    以冒号分隔的已启用 shell 选项列表。列表中的每个词都是 `set` 内建命令 `-o` 选项的有效参数（参见 [The Set Builtin]）。`SHELLOPTS` 中出现的选项是 `set -o` 报告为 `on` 的选项。如果 Bash 启动时此变量在环境中，shell 会在读取任何启动文件之前启用列表中的每个选项。如果导出此变量，子 shell 将启用列表中的每个选项。此变量为只读。

- `SHLVL`    
    每次启动新的 Bash 实例时加一。旨在表示 Bash shell 嵌套的深度。

- `SRANDOM`    
    每次引用时展开为 32 位伪随机数。在支持 `/dev/urandom` 或 `arc4random` 的系统上，随机数生成器不是线性的，因此每个返回的数与它之前的数没有关系。随机数生成器不能播种，因此对此变量赋值无效。如果 `SRANDOM` 未设置，它会失去特殊属性，即使随后重新设置也是如此。

- `TIMEFORMAT`    
    此参数的值用作格式字符串，指定带 `time` 保留字前缀的管道的计时信息应如何显示。`%` 字符引入转义序列，展开为时间值或其他信息。转义序列及其含义如下；方括号表示可选部分。
    
    - `%%`        
        字面 `%`。
    
    - `%[p][l]R`        
        经过时间（秒）。
    
    - `%[p][l]U`        
        用户模式消耗的 CPU 秒数。
    
    - `%[p][l]S`        
        系统模式消耗的 CPU 秒数。
    
    - `%P`        
        CPU 百分比，计算为 (%U + %S) / %R。
    
    可选 `p` 是数字，指定精度，即小数点后的数字位数。值为 0 时不输出小数点或小数。`time` 最多打印小数点后六位数字；`p` 大于 6 的值会改为 6。如果未指定 `p`，`time` 打印小数点后三位数字。
    
    可选 `l` 指定更长的格式，包括分钟，形式为 `MM`m`SS`.`FF`s`。`p` 的值决定是否包含小数。
    
    如果此变量未设置，Bash 的行为就像它具有值：
    
    ```sh
    $'\nreal\t%3lR\nuser\t%3lU\nsys\t%3lS'
    ```
    
    如果值为空，Bash 不显示任何计时信息。显示格式字符串时会添加末尾换行符。

- `TMOUT`    
    如果设置为大于零的值，`read` 内建命令使用该值作为其默认超时（参见 [Bash Builtin Commands]）。当输入来自终端时，如果 `TMOUT` 秒后没有输入到达，`select` 命令（参见 [Conditional Constructs]）终止。
    
    在交互式 shell 中，该值被解释为发出主提示符后等待一行输入的秒数。如果在该秒数内没有完整的输入行到达，Bash 终止。

- `TMPDIR`    
    如果设置，Bash 使用其值作为目录名，Bash 在该目录中创建供 shell 使用的临时文件。

- `UID`    
    当前用户的真实用户 ID 的数字值。此变量为只读。
