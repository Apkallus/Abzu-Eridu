# 服务器端请求伪造 (SSRF)

服务器端请求伪造（SSRF）是一种 Web 安全漏洞，发生在应用程序执行请求时未验证用户提供的远程主机的情况下。攻击者可以根据程序如何处理来自所请求远程主机的响应，以不同的方式利用此漏洞。最常见的是，攻击者向应用程序的内部网络发出请求，并尝试访问内部服务。这可能允许攻击者访问敏感信息和/或利用在发现的服务中的新漏洞。

## 示例

想象以下使用 cURL 库发送简单 HTTP 请求的 PHP 代码。

```php
<?php 
if ( isset( $_GET['url'] ) ) {
    $url = $_GET['url'];
    $ch = curl_init( $url );
    
    // 包含响应头并启用 "curl_exec" 以返回 HTTP 响应
    curl_setopt( $ch, CURLOPT_HEADER, 1 );
    curl_setopt( $ch, CURLOPT_RETURNTRANSFER, true );
    
    // 使用 cURL 向给定 URL 发出 HTTP 请求
    $response = curl_exec( $ch );
    echo "HTTP response result : \n" . $response;
    curl_close( $ch );
} 
?>
```

PHP 代码从 GET 参数 `url` 获取用户输入，而未验证其值。因此，攻击者可以将任何主机设置为值，并从易受攻击的服务器执行 HTTP 请求。要利用 `url` 参数中的此服务器端请求伪造 (SSRF) 漏洞，我们可以按如下方式发出 HTTP 请求：

```
http://target.com/?url=http://localhost/404
```

当向易受攻击的应用程序发出此请求时，它将从 `url` 参数中提取值并向自身发出内部请求。我们可以执行模糊测试攻击，以查看是否可以在目标内部的其他端口上检测到任何正在运行的 HTTP 服务。为此，我们将使用 Wfuzz 工具并为其提供以下参数：

```bash
wfuzz -z range,0-65535 -u 'http://target.com/?url=http://localhost:FUZZ'
```

此命令准备了一次模糊测试攻击，并测试所有 65535 个端口，以查看是否有任何端口打开供我们交互。一旦找到开放端口，我们就可以继续攻击，尝试利用在该特定端口上运行的服务。
