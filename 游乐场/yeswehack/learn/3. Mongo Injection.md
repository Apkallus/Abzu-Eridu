# Mongo 注入

Mongo 注入（或 NoSQL 注入）是一种用于修改 MongoDB 查询含义的攻击方式。与使用特制字符串触发的 SQL 和 XPath 注入不同，Mongo 注入需要创建特制的对象。这种情况常见于使用 Express 和 MongoDB 的 Node.js 项目中。Mongo 注入比其他类型的注入更具局限性，因为虽然你可以改变查询的含义，但你仅限于该查询所运行的集合。

## 示例

假设我们有以下用于简单管理员登录的 JavaScript 代码：

```javascript
const express = require('express');
const bodyParser = require('body-parser');
const db = require('./db.js');

const app = express();

// parse application/json
app.use(bodyParser.json());

app.use(function (req, res) {
    const pass = req.body["pass"];
    const query = { username: "admin", password: pass };
    const user = db.collection("users").findOne(query);
    if (user) {
        res.end("Welcome admin");
    }
});
```

在第 12 行，POST 变量 `pass` 被插入到查询中而没有任何清理，这使得它容易受到 NoSQL 注入的攻击。攻击者可以提交 `pass[ywh]=test`，bodyParser 会将其解析为 `{"ywh": "test"}`，从而将类型从字符串更改为对象。

为了模拟这种行为，我们将使用 dojo 的 `jsonify` 函数，如果可能，该函数会将输入转换为 JSON 对象。这是变量替换后实际查询的样子：

```javascript
users.findOne({"username": "admin", "password": "hunter2"})
```

现在让我们看看当我们尝试注入恶意对象而不是字符串时会发生什么。

- 注入恶意对象
  当 `$pass` 被设置为 `{"$ne": "a"}` 时，查询的含义发生了改变，这就形成了一次注入。在这里，攻击者完全绕过了密码检查，因为末尾存在否定密码检查。但这并不是攻击者在这种场景下唯一能做的事情，通过使用 MongoDB 的更高级功能，可以提取匹配对象的值。如果网站在返回值为 true 或 false 时响应不同，那么你可以将其作为预言机来泄露数据库的内容。

  ```js
  users.findOne({"username": "admin", "password": {"$ne":"a"}})
  ```

- 注入预言机 `{"$regex": "^测试字符.*"}`
  这一次，仅当第一个字符是 'h' 时，查询才会返回 true。通过遍历字母表并更新正则表达式，就可以从数据库中恢复密码。

  ```js
  users.findOne({"username": "admin", "password": {"$regex": "^hunter2.*"}})
  ```

const user = db.users.findOne({"name": "admin", "password": §输入 pass§})

    const user = db.users.findOne({

### Injection in insert 

修改集合

此次注入点位于插入语句中。
尝试在你的邮件列表条目中注入一个额外字段。

-   目标
    插入一个包含 `{"HACK": "YesWeHack"}` 的条目

code

```js
db.maillinglist.insert({"mail": "§输入 mail§"})
db.maillinglist.find({"mail": "转义字符串"})
```

输入
```json
{"mail": "", "HACK": "YesWeHack"}
```

显示
```log
DeprecationWarning: Collection.insert() is deprecated. Use insertOne, insertMany, or bulkWrite.
```
- 挑战使用被废弃的函数，且由于 find 寻找被转义的字符串而必然找不到之前注入的字段
