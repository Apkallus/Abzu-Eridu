# 实验：通过 CRLF 注入实现 HTTP/2 请求走私

本实验容易受到请求走私的攻击，因为前端服务器会对 HTTP/2 请求进行降级，且未能充分清理传入的头部。

要解决本实验，请使用 HTTP/2 独有的请求走私向量来访问另一个用户的账户。受害者每 15 秒访问一次首页。

如果您不熟悉 Burp 用于 HTTP/2 测试的独有功能，请参阅[文档](/burp/documentation/desktop/http2)了解如何使用它们。

> **提示**
>
> 要向 HTTP/2 头部注入换行符，请使用 Inspector 下钻到头部，然后按下 `Shift + Enter` 键。请注意，当您双击头部时，此功能不可用。

> **提示**
>
> 我们在[之前的实验](/web-security/request-smuggling/exploiting#capturing-other-users-requests)中介绍了一些通过请求走私捕获其他用户请求的方法。

## 步骤

探测
- 访问主页
    ```http
    POST / HTTP/2
    Host: id.web-security-academy.net
    ```

- 存在“最近搜索”与评论功能，均可用来窃取信息
- 使用搜索功能
    ```http
    POST / HTTP/2
    Host: id.web-security-academy.net
    Content-Length: 10

    search=abc
    ```

    - 主页的最近搜索功能暂存信息
        ```html
        <a href="/?search=abc">
            abc
        </a>
        ```

尝试 H2 头部换行序列
