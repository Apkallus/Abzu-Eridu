# 实验室：部分构建竞争条件

本实验室包含一个用户注册机制。竞争条件使你能够绕过邮箱验证，使用并非你拥有的任意邮箱地址进行注册。

要解决本实验室，请利用此竞争条件创建一个账户，然后登录并删除用户 `carlos`。

> **注意**
> 解决本实验室需要 Burp Suite 2023.9 或更高版本。你还应使用最新版的 Turbo Intruder，可从 [BApp Store](https://portswigger.net/bappstore/9abaa233088242e8be252cd4ff534988) 获取。

> **提示**
> 你可能需要尝试不同方式来对齐竞争窗口，才能成功利用此漏洞。

## 步骤

侦察
- 访问注册端点
    - 提示信息：
        ```log
        If you work for GinAndJuice, please use your @ginandjuice.shop email address
        ```
        - 使用 `@ginandjuice.shop` 域名作为邮件后缀的账户似乎拥有特权

- 查看 JS 文件
    ```http
    GET /resources/static/users.js HTTP/2
    Host: id.web-security-academy.net
    ```

    - 响应
        ```js
        // 省略注册表单 JS 动态构造代码
        ... 
        const confirmEmail = () => {
            const container = document.getElementsByClassName('confirmation')[0];

            const parts = window.location.href.split("?");
            const query = parts.length == 2 ? parts[1] : "";
            const action = query.includes('token') ? query : "";

            const form = document.createElement('form');
            form.method = 'POST';
            form.action = '/confirm?' + action;

            const button = document.createElement('button');
            button.className = 'button';
            button.type = 'submit';
            button.textContent = 'Confirm';

            form.appendChild(button);
            container.appendChild(form);
        }
        ```
        - 分析此处的 URL 格式 `GET /confirm?token=令牌`，之后获取查询参数后使用 POST 提交
        - 当前文档似乎对应 `注册-确认` 两项功能函数，此处暴露确认端点与格式

- 访问确认注册端点
    ```http
    GET /confirm?token= HTTP/2
    Host: id.web-security-academy.net
    ```
    - 响应
        ```html

        </script>
        <script>

        ```
        - 存在确认注册端点，且功能函数使用之前的相同 JS 文件

分析竞争条件
- 此处使用 php 会话 cookie，而 php 或使用基于会话的锁定，之后的竞争条件测试需使用多会话
- 推测，注册账户步骤
    1. 浏览器提交注册请求
    2. 服务器根据注册信息创建关联令牌
        - 推测，中间状态
            1. 创建用户对象
                - 此时令牌为空
            2. 设置关联令牌
        - 竞争条件窗口，在注册账户而还未关联令牌时，使用空令牌访问目标功能 API，绕过邮箱验证
    3. 服务器发送注册邮件
        - 除非应用程序将不同会话使用相同的不安全线程容器。否则基于会话的锁定似乎消除了同一会话中的不安全容器访问导致的发送任意邮箱令牌到另一个邮箱的竞争条件漏洞

测试邮箱确认端点
- 普通空查询参数
    ```http
    POST /confirm?token= HTTP/2
    ```
    - 响应
        ```http
        HTTP/2 403 Forbidden
        Content-Type: application/json; charset=utf-8
        X-Frame-Options: SAMEORIGIN
        Content-Length: 11

        "Forbidden"
        ```

- 数组空查询参数
    ```http
    POST /confirm?token[]= HTTP/2
    ```
    - 响应
        ```http
        HTTP/2 400 Bad Request
        Content-Type: application/json; charset=utf-8
        X-Frame-Options: SAMEORIGIN
        Content-Length: 24

        "Incorrect token: Array"
        ```

- 使用数组空查询似乎可有效传递 null，而直接设置普通查询参数似乎仅为缺乏参数值

测试竞争条件，在重复器中
- 获取多组会话 cookie 与对应的注册表单 csrf 令牌，并且设置多个邮件确认端点请求
- 设置所有内容到单包攻击组
- 多次尝试后仍无法访问新注册确认端点，注意到注册端点的延迟通常高于邮件确认端点，或许微调
- 尝试增强攻击器扩展

测试竞争条件，在增强攻击器扩展
