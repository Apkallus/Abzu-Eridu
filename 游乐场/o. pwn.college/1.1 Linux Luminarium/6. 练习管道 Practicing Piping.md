# 练习管道

你可能已经注意到，运行某些命令时，它们会把数据输出到终端。到目前为止，这已经为你打印了许多 flag，但和许多事物一样，这项技术远比表面更深。命令行上输入输出处理机制，正是命令行强大能力的一部分。

本模块将教你*输入与输出重定向*。简单来说，Linux 中的每个进程都有三个初始的标准通信通道：

- 标准*输入*是进程接收输入的通道。例如，你的 shell 使用标准输入读取你输入的命令。
- 标准*输出*是进程输出正常数据的通道，例如前面挑战中打印给你的 flag，或 `ls` 等工具的输出。
- 标准*错误*是进程输出错误详情的通道。例如，如果你输错命令，shell 会通过标准错误输出该命令不存在。

由于这三个通道在 Linux 中使用非常频繁，它们有更短的名称：`stdin`、`stdout`、`stderr`。本模块将教你如何重定向、串联、阻塞以及以其他方式摆弄这些通道。祝你好运！

## 重定向输出

首先，让我们看看如何将 stdout 重定向到文件。你可以使用 `>` 字符来完成，如下所示：

```console
hacker@dojo:~$ echo hi > asdf
```

这会将 `echo hi` 的输出（即 `hi`）重定向到文件 `asdf`。然后你可以使用 `cat` 等程序输出该文件：

```console
hacker@dojo:~$ cat asdf
hi
```

在本挑战中，你必须使用这种输出重定向，将单词 `PWN`（全大写）写入文件名 `COLLEGE`（全大写）。

## 重定向更多输出

## 追加输出

输出重定向的一个常见用例是保存某些命令结果，以便后续分析。很多时候，你希望*汇总*执行：运行一堆命令，保存它们的输出，之后再用 `grep` 搜索。在这种情况下，你可能希望所有输出都持续追加到同一个文件，但 `>` 每次都会创建新的输出文件，删除旧内容。

你可以使用 `>>` 而不是 `>`，以*追加*模式重定向输入，如下所示：

```console
hacker@dojo:~$ echo pwn > outfile
hacker@dojo:~$ echo college >> outfile
hacker@dojo:~$ cat outfile
pwn
college
hacker@dojo:$
```

为了练习，请运行 `/challenge/run`，并将输出以追加模式重定向到文件 `/home/hacker/the-flag`。练习会将 flag 的前半部分写入该文件，如果 `stdout` 被重定向到该文件，则会将后半部分写入 `stdout`。如果你正确使用追加模式重定向，后半部分将追加到前半部分之后；但如果你使用*截断*模式（`>`）重定向，后半部分将*覆盖*前半部分，你就拿不到 flag！

## 重定向错误

就像标准输出一样，你也可以重定向命令的错误通道。这里，我们将了解*文件描述符编号*。文件描述符（FD）是一个*描述* Linux 中通信通道的数字。你其实一直在使用它们，只是没有意识到。我们已经熟悉三个：

- FD 0：标准输入
- FD 1：标准输出
- FD 2：标准错误

重定向进程通信时，你是按 FD 编号进行的，尽管有些 FD 编号是隐式的。例如，不带数字的 `>` 意味着 `1>`，即重定向 FD 1（标准输出）。因此，以下两个命令等价：

```console
hacker@dojo:~$ echo hi > asdf
hacker@dojo:~$ echo hi 1> asdf
```

从这里开始，重定向错误就很容易了。如果你有一个可能通过标准错误产生数据的命令（例如 `/challenge/run`），可以这样做：

```console
hacker@dojo:~$ /challenge/run 2> errors.log
```

这会将标准错误（FD 2）重定向到 `errors.log` 文件。此外，你还可以同时重定向多个文件描述符！例如：

```console
hacker@dojo:~$ some_command > output.log 2> errors.log
```

该命令会将输出重定向到 `output.log`，将错误重定向到 `errors.log`。

让我们把这一点付诸实践！在本挑战中，你需要像之前一样，将 `/challenge/run` 的输出重定向到 `myflag`，并将“错误”（在我们的例子中是指令）重定向到 `instructions`。你会注意到终端上不会打印任何内容，因为你已经重定向了一切！当你成功完成时，可以在 `instructions` 中找到指令/反馈，在 `myflag` 中找到 flag！

## 对错误使用 grep

你知道如何将错误重定向到文件，也知道如何将输出通过管道传给另一个程序，例如 `grep`。但如果你想直接对错误使用 `grep` 呢？

`>` 操作符将给定文件描述符重定向到文件，你已经使用 `2>` 重定向 fd 2，即标准错误。`|` 操作符*只将标准输出*重定向到另一个程序，并且不存在 `2|` 形式的操作符！它*只能*重定向标准输出（文件描述符 1）。

幸运的是，有 shell 的地方就有办法！

shell 有一个 `>&` 操作符，它将一个文件描述符重定向*到另一个文件描述符*。这意味着我们可以用两步流程来对错误使用 `grep`：首先，将标准错误重定向到标准输出（`2>&1`），然后像平常一样将现在合并后的 stderr 和 stdout 通过管道传出（`|`）！

## 使用 grep -v 过滤

`grep` 命令有一个非常有用的选项：`-v`（反转匹配）。普通 `grep` 显示匹配模式的行，而 `grep -v` 显示不匹配模式的行：

```console
hacker@dojo:~$ cat data.txt
hello hackers!
hello world!
hacker@dojo:~$ cat data.txt | grep -v world
hello hackers!
hacker@dojo:~$
```

有时，只筛选出你想要的数据的唯一方法，就是过滤掉你不想要的数据。在本挑战中，`/challenge/run` 会将 flag 输出到 stdout，但它也会在真实 flag 中混入超过 1000 个诱饵 flag（flag 中某处包含单词 `DECOY`）。你需要过滤掉诱饵，同时保留真实 flag！

使用 `grep -v` 过滤掉所有包含 "DECOY" 的行，揭示真实 flag！

## 使用 sed 过滤

`grep` 并不是匹配模式的唯一方法。有时真实数据和垃圾数据混在同一行中，而我们要过滤掉垃圾。为此，我们有 `sed`。`sed` 提供了一种简单的方法，将文本中的模式替换为另一个词。匹配和替换的语法很简单：

```sh
sed "s/oldword/newword/g"
```

- `s/` - 替换
- `oldword` - 要替换的单词
- `newword` - `oldword` 的替换内容
- `/g` - 全局（搜索该模式的所有出现）

## 使用 tee 复制管道数据

当你将数据从一个命令管道传给另一个命令时，你当然不再能在屏幕上看到它。这并不总是你想要的：例如，你可能想看到数据在命令之间流动的情况，以调试意外结果（例如，“为什么第二个命令不工作？？？”）。

幸运的是，有解决方案！`tee` 命令得名于*水管*中的“T 形分流器”，它会将流经管道的数据复制到命令行上提供的任意数量文件中。例如：

```console
hacker@dojo:~$ echo hi | tee pwn college
hi
hacker@dojo:~$ cat pwn
hi
hacker@dojo:~$ cat college
hi
hacker@dojo:~$
```

如你所见，通过向 `tee` 提供两个文件，我们最终得到了三份管道输入数据的副本：一份到 stdout，一份到 `pwn` 文件，一份到 `college` 文件。你可以想象如何用它来调试出问题的地方：

```console
hacker@dojo:~$ command_1 | command_2
Command 2 failed!
hacker@dojo:~$ command_1 | tee cmd1_output | command_2
Command 2 failed!
hacker@dojo:~$ cat cmd1_output
Command 1 failed: must pass --succeed!
hacker@dojo:~$ command_1 --succeed | command_2
Commands succeeded!
```

现在，你来试试！此进程的 `/challenge/pwn` 必须通过管道传给 `/challenge/college`，但你需要拦截数据，看看 `pwn` 需要你提供什么！使用 `tee` 将第一次尝试复制到文件中，检查保存的输出，然后带着学到的内容重试管道。

## 用于输入的进程替换

有时你需要比较两个命令的输出，而不是两个文件。你可能想先把每个输出保存到文件：

```console
hacker@dojo:~$ command1 > file1
hacker@dojo:~$ command2 > file2
hacker@dojo:~$ diff file1 file2
```

但有一种更优雅的方法！Linux 遵循[“一切皆文件”](https://en.wikipedia.org/wiki/Everything_is_a_file)的哲学。也就是说，系统努力为大多数资源提供类似文件的访问方式，包括正在运行程序的输入和输出！shell 遵循这一哲学，允许你例如将任何接受命令行文件参数的工具，连接到程序的输出，正如你在前几关学到的那样。

有趣的是，我们还可以更进一步，将程序的输入和输出连接到命令的*参数*上。这使用[进程替换](https://www.gnu.org/software/bash/manual/html_node/Process-Substitution.html)完成。要从命令读取（输入进程替换），使用 `<(command)`。当你写 `<(command)` 时，bash 会运行该命令，并将其输出连接到一个它会创建的临时文件。当然，这不是*真正的*文件，而是所谓的*命名管道*，因为它有文件名：

```console
hacker@dojo:~$ echo <(echo hi)
/dev/fd/63
hacker@dojo:~$
```

`/dev/fd/63` 是从哪里来的？`bash` 将 `<(echo hi)` 替换为连接到该命令输出的命名管道文件路径！当命令运行时，从这个文件读取将读取该命令标准输出的数据。通常，这是通过接受输入文件作为参数的命令来完成的：

```console
hacker@dojo:~$ cat <(echo hi)
hi
hacker@dojo:~$
```

当然，你可以多次指定它：

```console
hacker@dojo:~$ echo <(echo pwn) <(echo college)
/dev/fd/63 /dev/fd/64
hacker@dojo:~$ cat <(echo pwn) <(echo college)
pwn
college
hacker@dojo:~$
```

现在轮到你的挑战了！回想你在 Comprehending Commands 的 `diff` 挑战中学到的内容。在那个挑战中，你比较了两个文件。现在，你将比较两组命令输出：`/challenge/print_decoys` 会打印一堆诱饵 flag，`/challenge/print_decoys_and_flag` 会打印同样的诱饵加上真实 flag。

对 `diff` 使用进程替换，比较这两个程序的输出，找到你的 flag！

## 写入多个程序

现在你已经了解到，进程替换可以让命令输出以文件形式供读取，使用 `<(command)`。但你也可以使用进程替换来*写入*命令！

你可以用 `tee` 将数据复制到两个文件：

```console
hacker@dojo:~$ echo HACK | tee THE > PLANET
hacker@dojo:~$ cat THE
HACK
hacker@dojo:~$ cat PLANET
HACK
hacker@dojo:~$
```

你也使用过 `tee` 将数据复制到文件和命令：

```console
hacker@dojo:~$ echo HACK | tee THE | cat
HACK
hacker@dojo:~$ cat THE
HACK
hacker@dojo:~$
```

但如何复制到两个命令呢？正如 `tee` 在其手册页中所说，它被设计为写入文件和标准输出：

```text
TEE(1)                           User Commands                          TEE(1)

NAME
       tee - read from standard input and write to standard output and files
```

但等等！你刚刚学到 bash 可以使用进程替换让命令看起来像文件！要写入命令（输出进程替换），使用 `>(command)`。如果你写参数 `>(rev)`，bash 会运行 `rev` 命令（该命令从标准输入读取数据，反转其顺序，并写入标准输出！），但将其输入连接到一个临时命名管道文件。当命令写入此文件时，数据会进入该命令的标准输入：

```console
hacker@dojo:~$ echo HACK | rev
KCAH
hacker@dojo:~$ echo HACK | tee >(rev)
HACK
KCAH
```

上面发生了以下事件序列：

1. `bash` 启动 `rev` 命令，将一个命名管道（大概是 `/dev/fd/63`）连接到 `rev` 的标准输入
2. `bash` 启动 `tee` 命令，将一个管道连接到其标准输入，并用 `/dev/fd/63` 替换 `tee` 的第一个参数。`tee` 甚至从未看到参数 `>(rev)`；shell 在启动 `tee` 之前就*替换*了它
3. `bash` 使用 `echo` 内建命令将 `HACK` 打印到 `tee` 的标准输入
4. `tee` 读取 `HACK`，将其写入标准输出，然后写入 `/dev/fd/63`（连接到 `rev` 的 stdin）
5. `rev` 从其标准输入读取 `HACK`，反转它，并将 `KCAH` 写入标准输出

现在轮到你了！在本挑战中，我们有 `/challenge/hack`、`/challenge/the` 和 `/challenge/planet`。运行 `/challenge/hack` 命令，并将其输出复制为 `/challenge/the` 和 `/challenge/planet` 两个命令的输入！记住，`tee` 可以接受多个输出目标，而 `>(command)` 是一种目标。如果你需要复习这种方法，可以回看前面的挑战“使用 tee 复制管道数据”和“用于输入的进程替换”。

## 命名管道

你已经学习了使用 `|` 的管道，也看到了进程替换会创建临时命名管道（如 `/dev/fd/63`）。你也可以创建自己的*持久*命名管道，让它们留在文件系统上！这些称为 **FIFO**，代表先进先出（First In, First Out，按字节）。

你可以使用 `mkfifo` 命令创建 FIFO：

```console
hacker@dojo:~$ mkfifo my_pipe
hacker@dojo:~$ ls -l my_pipe
prw-r--r-- 1 hacker hacker 0 Jan 1 12:00 my_pipe
hacker@dojo:~$ ls -l some_file
-rw-r--r-- 1 hacker hacker 0 Jan 1 12:00 some_file
hacker@dojo:~$
```

注意权限开头的 `p`——这表明它是一个管道！这与普通文件（例如上面示例中的 `some_file`）开头的 `-` 明显不同。

与进程替换自动创建的命名管道不同：

- 你可以控制 FIFO 创建的位置
- 它们会一直存在，直到你删除它们
- 任何进程都可以按路径写入它们（例如 `echo hi > my_pipe`）
- 你可以用 `ls` 看到它们，并像文件一样检查它们

FIFO 的一个问题是，它们会“阻塞”对它们的任何操作，直到管道的读取端和写入端都就绪。例如，考虑以下情况：

```console
hacker@dojo:~$ mkfifo myfifo
hacker@dojo:~$ echo pwn > myfifo
```

为了服务 `echo pwn > myfifo`，bash 将以写入模式打开 `myfifo` 文件。然而，此操作会一直挂起，直到有东西*也*以读取模式打开该文件（从而完成管道）。这可以在另一个控制台中进行：

```console
hacker@dojo:~$ cat myfifo
pwn
hacker@dojo:~$
```

这里发生了什么？当我们运行 `cat myfifo` 时，管道两侧的连接都已设置好，并*解除阻塞*，允许 `echo pwn > myfifo` 运行，它将 `pwn` 送入管道，然后被 `cat` 读取。

当然，这在某种程度上也可以用普通文件完成：你已经学习了如何将内容 `echo` 到文件中，并将它们 `cat` 出来。为什么要使用 FIFO 呢？以下是关键区别：

1. **无磁盘存储：** FIFO 直接在内存中在进程之间传递数据——不会保存到磁盘
2. **数据是短暂的：** 一旦从 FIFO 读取数据，它就不见了（不同于文件中数据会持久保留）
3. **自动同步：** 写入者会阻塞，直到读取者就绪，反之亦然。这实际上很有用！它提供自动同步。考虑上面的例子：使用 FIFO 时，`cat myfifo` 或 `echo pwn > myfifo` 谁先执行都没关系；每个都会等待另一个。使用文件时，你需要确保在读取者之前执行写入者。
4. **复杂数据流：** FIFO 有助于促进复杂的数据流，以灵活的方式合并和拆分数据，等等。例如，FIFO 支持多个读取者和写入者。

本挑战是对 FIFO 的简单介绍。你需要创建一个 `/tmp/flag_fifo` 文件，并将 `/challenge/run` 的 stdout 重定向到它。如果成功，`/challenge/run` 会将 flag 写入 FIFO！去做吧！
