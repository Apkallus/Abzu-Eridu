Linux 文件系统是一棵“树”。也就是说，它有一个根（写作 `/`）。文件系统的根是一个目录，而每个目录都可以包含其他目录和文件。你通过文件的*路径*来引用文件和目录。从文件系统根开始的路径以 `/`（即文件系统的根）开头，并描述为了找到该文件必须逐层进入的目录集合。路径的每一部分都用另一个 `/` 分隔。

#### 定位自身

Linux 文件系统中有大量目录和大量文件。你可以使用 `cd`（change directory）命令并在其后将路径作为参数传入，从而在目录之间导航，如下所示：

```console
hacker@dojo:~$ cd /some/new/directory
hacker@dojo:/some/new/directory$
```

这会影响你进程（在这个例子中是 `bash` shell）的“当前工作目录”。每个进程都有一个当前所在的目录。这样做的原因会在本模块后面变得清楚。

#### 从 `/` 开始的隐式相对路径

现在你已经熟悉了引用绝对路径和切换目录的概念。如果你到处都使用绝对路径，那么你当前在哪个目录其实并不重要，正如你可能在前三个挑战中发现的那样。

然而，当前工作目录对于**相对**路径确实很重要。

- 相对路径是不从根目录开始的任何路径（即，不以 `/` 开头）。
- 相对路径是相对于你的**当前工作目录**（`cwd`）来解释的。
- 你的 `cwd` 就是提示符当前所在的目录。

这意味着你如何指定某个文件，取决于终端提示符所在的位置。

假设我们想访问位于 `/tmp/a/b/my_file` 的某个文件。

- 如果我的 `cwd` 是 `/`，那么该文件的相对路径是 `tmp/a/b/my_file`。
- 如果我的 `cwd` 是 `/tmp`，那么该文件的相对路径是 `a/b/my_file`。
- 如果我的 `cwd` 是 `/tmp/a/b/c`，那么该文件的相对路径是 `../my_file`。其中 `..` 指父目录。

切换目录和调用程序是两个独立的操作。例如：

```console
hacker@dojo:~$ cd /
hacker@dojo:/$ bin/echo Hello
Hello
```

第一条命令将当前工作目录切换到 `/`。第二条命令使用相对路径 `bin/echo` 调用 `/bin/echo`。

我们在这里试试吧！首先，将你的当前工作目录切换到 `/`。然后使用相对路径调用 `/challenge/run`。对于本关卡，我会给你一个提示。你的相对路径以字母 `c` 开头 😊

#### 从 `/` 开始的显式相对路径

此前，你的相对路径是“裸”的：它直接指定了要从当前目录向下进入的目录。在本关卡中，我们将探索更显式的相对路径。

在大多数操作系统（包括 Linux）中，每个目录都有两个可以在路径中引用的隐式条目：`.` 和 `..`。第一个 `.` 直接指向同一目录，因此以下绝对路径彼此完全相同：

- `/challenge`
- `/challenge/.`
- `/challenge/./././././././././`
- `/./././challenge/././`

以下相对路径也彼此完全相同：

- `challenge`
- `./challenge`
- `./././challenge`
- `challenge/.`

当然，如果你的当前工作目录是 `/`，上面的相对路径等价于上面的绝对路径。

本挑战将让你在相对路径中使用 `.`。你的当前工作目录必须是 `/`，并且你用来调用挑战的相对路径必须以 `.` 开头。准备好了！

#### 隐式相对路径

在本关卡中，我们将再练习一下使用 `.` 引用路径。本挑战需要你从 `/challenge` 目录运行它。这里事情会稍微棘手一点。

当你提供“裸”路径时，Linux 会明确避免自动在当前目录中查找。考虑以下情况：

```console
hacker@dojo:~$ cd /challenge
hacker@dojo:/challenge$ run
```

这*不会*调用 `/challenge/run`。这实际上是一种安全措施：如果 Linux 在你每次输入裸路径时都搜索当前目录中的程序，你可能会意外执行当前目录中恰好与核心系统工具同名的程序！因此，上面的命令会产生以下错误：

```text
bash: run: command not found
```

我们稍后会探索这一概念背后的机制，但在本挑战中，我们将学习如何在这种场景下显式使用相对路径来启动 `run`。做法是*告诉* Linux 你明确想执行当前目录中的程序，像之前关卡那样使用 `.`。现在就试试吧！

#### 甜蜜的家

每个用户都有一个*主目录*，通常位于文件系统中的 `/home` 下。在 dojo 中，你是 `hacker` 用户，你的主目录是 `/home/hacker`。主目录通常是用户存放大部分个人文件的地方。当你在 pwn.college 中一路前进时，这里将是你存放大部分解答的地方。

通常，你的 shell 会话启动时会以你的主目录作为当前工作目录。考虑初始提示符：

```console
hacker@dojo:~$
```

此提示符中的 `~` 表示当前工作目录，其中 `~` 是 `/home/hacker` 的简写。`bash` 提供并使用这种简写，因为同样，你的大部分时间都会花在主目录中。因此，只要 `bash` 看到 `~` 作为参数开头且符合路径形式出现，就会将其展开为你的主目录。考虑：

```console
hacker@dojo:~$ echo LOOK: ~
LOOK: /home/hacker
hacker@dojo:~$ cd /
hacker@dojo:/$ cd ~
hacker@dojo:~$ cd ~/asdf
hacker@dojo:~/asdf$ cd ~/asdf
hacker@dojo:~/asdf$ cd ~
hacker@dojo:~$ cd /home/hacker/asdf
hacker@dojo:~/asdf$
```

注意，`~` 的展开结果是*绝对*路径，并且只会展开开头的 `~`。例如，这意味着 `~/~` 会展开为 `/home/hacker/~`，而不是 `/home/hacker/home/hacker`。

有趣的事实：`cd` 会把你的主目录作为默认目标：

```console
hacker@dojo:~$ cd /tmp
hacker@dojo:/tmp$ cd
hacker@dojo:~$
```

现在轮到你来玩了！在本挑战中，`/challenge/run` 会把 flag 的副本写入你作为参数在命令行上指定的任何文件，但有以下约束：

1. 你的参数必须是绝对路径。
2. 该路径必须位于你的主目录内。
3. 在展开之前，你的参数必须不超过三个字符。

同样，你必须像下面这样把你的路径指定为 `/challenge/run` 的*参数*：

```console
hacker@dojo:~$ /challenge/run YOUR_PATH_HERE
```
