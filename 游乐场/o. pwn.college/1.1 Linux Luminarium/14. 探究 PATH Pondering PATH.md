# 思考 PATH

到目前为止，你已经通过多种方式调用过命令：

- 通过绝对路径（例如 `/challenge/run`）。
- 通过相对路径（例如 `./run`）。
- 通过仅命令名（例如 `ls`）。

前两种情况，即绝对路径和相对路径，很直接：`run` 文件位于 `/challenge` 目录中，两种情况都指向它（当然，前提是相对路径在 `/challenge` 作为当前工作目录时调用）。但最后一种情况呢？`ls` 程序位于哪里？shell 如何知道要到那里搜索它？

在本模块中，我们将揭开这层面纱并回答这个问题！请继续阅读。

#### PATH 变量

“shell 如何找到 `ls`？”这个问题的答案其实相当简单。有一个特殊的 shell 变量，称为 `PATH`，它存储一组目录路径，shell 将在这些目录中搜索与命令对应的程序。如果清空该变量，情况会很糟：

```console
hacker@dojo:~$ ls
Desktop    Downloads  Pictures  Templates
Documents  Music      Public    Videos
hacker@dojo:~$ PATH=""
hacker@dojo:~$ ls
bash: ls: No such file or directory
hacker@dojo:~$
```

没有 `PATH`，`bash` 就无法找到 `ls` 命令。

在本关中，你将破坏 `/challenge/run` 程序的运行。该程序将使用 `rm` 命令**删除** `flag` 文件。然而，如果它找不到 `rm` 命令，`flag` 就不会被删除，挑战会把它给你！因此，你必须让 `/challenge/run` 也找不到 `rm` 命令！

请记住：如果你没有成功，并且 `flag` 被删除，你将需要重新启动挑战再试一次！

#### 设置 PATH

好吧，清空 `PATH` 时情况会出问题。但用 `PATH` 做一些**有用**的事情又如何呢？

让我们探索一下，例如，如何向命令库中添加一个新的程序目录。回想一下，`PATH` 存储用于查找命令的目录列表；对于位于非标准位置的命令，我们通常必须通过其路径来执行：

```console
hacker@dojo:~$ ls /home/hacker/scripts
goodscript	badscript	okayscript
hacker@dojo:~$ goodscript
bash: goodscript: command not found
hacker@dojo:~$ /home/hacker/scripts/goodscript
YEAH! This is the best script!
hacker@dojo:~$
```

如果你维护了一些有用的脚本，并希望能够仅用命令名启动它们，这会很烦人。然而，通过向此列表添加目录或替换其中的目录，你可以让这些程序仅用命令名就能启动！例如：

```console
hacker@dojo:~$ PATH=/home/hacker/scripts
hacker@dojo:~$ goodscript
YEAH! This is the best script!
hacker@dojo:~$
```

让我们练习一下。本关的 `/challenge/run` 将仅用命令名运行 `win` 命令，但该命令存在于 `/challenge/more_commands/` 目录中，而该目录最初不在 `PATH` 中。`win` 命令是 `/challenge/run` **唯一**需要的东西，因此你可以直接用那一个目录覆盖 `PATH`。祝你好运！

#### 查找命令

当你输入命令名时，`$PATH` 变量中列出的许多目录中的**某个**内容才会真正被执行（当然，除非该命令是内建命令！）。但具体是哪个文件呢？你可以使用名副其实的 `which` 命令来查明：

```console
hacker@dojo:~$ which cat
/bin/cat
hacker@dojo:~$ /bin/cat /flag
YEAH
hacker@dojo:~$
```

与 shell 搜索命令时的行为类似，`which` 会按顺序查看 `$PATH` 中的每个目录，并打印它找到的第一个名称与你传入参数匹配的文件。

在本挑战中，我们在你的 `$PATH` 某处添加了一个 `win` 命令，但它不会给你 `flag`。相反，它与一个我们已设为你可读的 `flag` 文件位于同一目录中！你必须（使用 `which` 命令）找到 `win`，并从该目录中 `cat` 出 `flag`！

#### 添加命令

回想上一关的示例：

```console
hacker@dojo:~$ ls /home/hacker/scripts
goodscript	badscript	okayscript
hacker@dojo:~$ PATH=/home/hacker/scripts
hacker@dojo:~$ goodscript
YEAH! This is the best script!
hacker@dojo:~$
```

当然，我们在这里看到的是 `hacker` 通过带来自己的命令，让 shell 对自己更有用。随着时间推移，你可能会积累自己的优雅工具。让我们从 `win` 开始！

此前，`/challenge/run` 执行的 `win` 命令存储在 `/challenge/more_commands` 中。这一次，`win` 不存在！回想 [Chaining Commands] 的最后一关，创建一个名为 `win` 的 shell 脚本，将其位置添加到 `PATH`，并让 `/challenge/run` 能够找到它！

---

**提示：**  
`/challenge/run` 以 `root` 身份运行，并将调用 `win`。因此，`win` 可以直接 `cat` 出 `flag` 文件。再次说明，`win` 命令是 `/challenge/run` **唯一**需要的东西，因此你可以直接用那一个目录覆盖 `PATH`。但请记住，如果这样做，你的 `win` 命令将无法找到 `cat`。

你有三种方法可以避免这种情况：

1. 找出 `cat` 程序在文件系统上的位置。它**必须**位于 `PATH` 变量中的某个目录里，因此你可以打印该变量（参考 [Shell Variables] 来回忆如何操作！），并遍历其中的目录（回想不同条目由 `:` 分隔），找出哪个目录包含 `cat`，然后通过其绝对路径调用 `cat`。  
2. 设置一个 `PATH`，其中包含旧目录**加上**你创建 `win` 所在位置的新条目。  
3. 使用 `read`（再次参考 [Shell Variables]）读取 `/flag`。由于 `read` 是 `bash` 的内建功能，它不受 `PATH` 操作的影响。

现在，去 `win` 吧！
