你以为你，`hacker`，是机器中唯一的幽灵吗？典型的 Linux 系统上有许多用户！Linux 系统上的完整用户列表在 `/etc/passwd` 文件中指定（因历史原因得名——它实际上不再保存密码）。以下是 dojo 容器中的一个示例：

这里有很多用户，也有很多信息！每一行由 `:` 分隔，包含用户名、一个 `x` 作为密码*过去*所在位置的占位符（我们稍后会介绍它实际存放在哪里）、数字用户 ID、数字默认组 ID、长格式用户详情、主目录和默认 shell。

我们可以在底部看到 `hacker` 用户。那就是你！其余大多数用户要么因历史原因存在，要么是支持各种已安装软件的服务账户，或者是一些“实用”账户（例如，`nobody` 用户用于确保某些程序在没有任何特殊权限的情况下运行）。

一个重要的用户是 `root`：系统管理员。系统管理员有明显的安全影响：一个 `hacker` 用户如果能够通过 Linux 的各种功能以某种方式成为 `root` 用户，就能对系统造成严重破坏。黑客入侵系统的一个非常常见的目标就是提权到 `root`，因此必须不惜一切代价保护 `root`！

在本模块中，我们将探索用户相关的各种把戏，学习切换用户以管理系统的预期方式，并一路玩得开心！

## 使用 su 成为 root

需要成为 `root` 的不只是黑客。通常，作为计算机的所有者，你需要使用 `root` 访问权限来管理它。成为 `root` 是 Linux 用户相当常见的操作，为此有两个实用程序：`su` 和 `sudo`。

在本挑战中，我们将介绍较老的那个：`su`（**s**ubstitute **u**ser 命令）。它如今通常不再用于提权到 `root`，但它是一个来自更文明时代的优雅工具，我们先介绍它。

`su` 是一个 setuid 二进制文件：

```console
hacker@dojo:~$ ls -l /usr/bin/su
-rwsr-xr-x 1 root root 232416 Dec 1 11:45 /usr/bin/su
hacker@dojo:~$
```

因为它设置了 SUID 位，`su` 以 `root` 身份运行。以 `root` 身份运行时，它可以启动一个 `root` shell！当然，`su` 是有辨别力的：在允许用户提权到 `root` 之前，它会检查用户是否知道 `root` 密码：

```console
hacker@dojo:~$ su
Password: 
su: Authentication failure
hacker@dojo:~$
```

这种对 `root` 密码的检查正是 `su` 被淘汰的原因。现代系统很少设置 `root` 密码，而是使用不同的机制（我们稍后会学习）来授予管理访问权限。

但本挑战（且仅本挑战）*确实*有 `root` 密码。该密码是 `hack-the-planet`，你必须将它提供给 `su` 才能成为 `root`！去做吧，然后读取 flag！

## 使用 su 切换其他用户

不带参数时，`su` 会启动一个 `root` shell（在用 `root` 的密码认证之后）。不过，你也可以传入用户名作为参数，切换到*该*用户而不是 `root`。例如：

```console
hacker@dojo:~$ su some-user
Password:
some-user@dojo:~$
```

很棒！在本关卡中，你必须切换到 `zardus` 用户，然后运行 `/challenge/run`。Zardus 的密码是 `dont-hack-me`。祝你好运！

## 破解密码

当你为 `su` 输入密码时，它会将该密码与该用户存储的密码进行比较。这些密码*过去*存储在 `/etc/passwd` 中，但由于 `/etc/passwd` 是全局可读文件，这对密码不利，因此它们被移到了 `/etc/shadow`。以下是上一关示例中的 `/etc/shadow`：

```text

daemon:*:19873:0:99999:7:::
bin:*:19873:0:99999:7:::
sys:*:19873:0:99999:7:::
sync:*:19873:0:99999:7:::
games:*:19873:0:99999:7:::
man:*:19873:0:99999:7:::
lp:*:19873:0:99999:7:::
mail:*:19873:0:99999:7:::
news:*:19873:0:99999:7:::
uucp:*:19873:0:99999:7:::
proxy:*:19873:0:99999:7:::
www-data:*:19873:0:99999:7:::
backup:*:19873:0:99999:7:::
list:*:19873:0:99999:7:::
irc:*:19873:0:99999:7:::
gnats:*:19873:0:99999:7:::
nobody:*:19873:0:99999:7:::
_apt:*:19873:0:99999:7:::
systemd-timesync:*:19901:0:99999:7:::
systemd-network:*:19901:0:99999:7:::
systemd-resolve:*:19901:0:99999:7:::
mysql:!:19901:0:99999:7:::
messagebus:*:19901:0:99999:7:::
sshd:*:19901:0:99999:7:::
hacker::19916:0:99999:7:::
zardus:$6$bEFkpM0w/6J0n979$47ksu/JE5QK6hSeB7mmuvJyY05wVypMhMMnEPTIddNUb5R9KXgNTYRTm75VOu1oRLGLbAql3ylkVa5ExuPov1.:19921:0:99999:7:::
```

每行由 `:` 分隔，第一个字段是用户名，第二个是密码。值 `*` 或 `!` 实际上意味着该账户的密码登录被禁用，空白字段表示没有密码（这是一种并不罕见的错误配置，在某些配置下允许无密码 `su`），而像 Zardus 的 `$6$bEFkpM0w/6J0n979$47ksu/JE5QK6hSeB7mmuvJyY05wVypMhMMnEPTIddNUb5R9KXgNTYRTm75VOu1oRLGLbAql3ylkVa5ExuPov1.` 这样的长字符串，是上一关中 Zardus 的密码（本例中为 `dont-hack-me`）经过单向加密（哈希）后的结果。该文件中的其他字段有其他含义，你可以[在此处](https://www.cyberciti.biz/faq/understanding-etcshadow-file/)了解更多。

当你向 `su` 输入密码时，它会将密码单向加密（哈希），并将结果与存储值比较。如果结果匹配，`su` 就授予你该用户的访问权限！

但如果你不知道密码呢？如果你拥有密码的哈希值，你就可以*破解*它！尽管 `/etc/shadow` 默认只允许 `root` 读取，但泄露仍可能发生！例如，备份经常以未加密且保护不足的方式存储在文件服务器上，这导致了无数数据泄露。

如果黑客拿到了泄露的 `/etc/shadow`，他们就可以开始破解密码并造成严重破坏。破解可以通过著名的 [John the Ripper](https://www.openwall.com/john/) 完成，如下所示：

```console
hacker@dojo:~$ john ./my-leaked-shadow-file
Loaded 1 password hash (crypt, generic crypt(3) [?/64])
Will run 32 OpenMP threads
Press 'q' or Ctrl-C to abort, almost any other key for status
password1337      (zardus)
1g 0:00:00:22 3/3 0.04528g/s 10509p/s 10509c/s 10509C/s lykys..lank
Use the "--show" option to display all of the cracked passwords reliably
Session completed
hacker@dojo:~$
```

在这里，John the Ripper 破解了 Zardus 泄露的密码哈希，找出了真实值 `password1337`。可怜的 Zardus！

本关卡模拟了这个故事，给你一份 `/etc/shadow` 的泄露文件（位于 `/challenge/shadow-leak`）。破解它（这可能需要几分钟），`su` 到 `zardus`，然后运行 `/challenge/run` 获取 flag！

## 使用 sudo

在过去，典型的 Linux 系统有一个 `root` 密码，管理员会用它在以普通账户密码登录自己的账户后，通过 `su` 切换到 `root`。但 `root` 密码难以维护，它们（或它们的哈希！）可能泄露，而且不适合更大的环境（例如服务器集群）。为了解决这个问题，近几十年来，世界已从通过 `su` 进行管理转向通过 `sudo` 进行管理（*趣闻*：`sudo` 最初代表 **su**peruser **do**，但后来变成“`su` ‘do’”，而由于 `su` 代表“substitute user”，`sudo` 当前的含义是“substitute user, do”）。

与默认启动指定用户 shell 的 `su` 不同，`sudo` 默认以 `root` 身份运行命令：

```console
hacker@dojo:~$ whoami
hacker
hacker@dojo:~$ sudo whoami
root
hacker@dojo:~$
```

或者，与获取 flag 更相关的是：

```console
hacker@dojo:~$ grep hacker /etc/shadow
grep: /etc/shadow: Permission denied
hacker@dojo:~$ sudo grep hacker /etc/shadow
hacker:$6$Xro.e7qB3Q2Jl2sA$j6xffIgWn9xIxWUeFzvwPf.nOH2NTWNJCU5XVkPuONjIC7jL467SR4bXjpVJx4b/bkbl7kyhNquWtkNlulFoy.:19921:0:99999:7:::
hacker@dojo:~$
```

与依赖密码认证的 `su` 不同，`sudo` 检查策略来确定用户是否有权以 `root` 身份运行命令。这些策略定义在 `/etc/sudoers` 中，虽然这大多超出我们的范围，但有很多[资源](https://www.digitalocean.com/community/tutorials/how-to-edit-the-sudoers-file)可供学习！

因此，世界已转向 `sudo`，并且（就系统管理而言）将 `su` 抛在了身后。事实上，就连 pwn.college 的 Privileged Mode 也是通过给你 `sudo` 访问权限来提权的！
