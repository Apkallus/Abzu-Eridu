# 命令串联

在管道模块中，你已经探索了使用多个命令、通过管道在它们之间传递数据，以完成单个命令难以完成的稍复杂任务的概念。当然，这个概念也独立于数据传输：有时你可能想快速连续运行多个命令，以达成某种累积效果。

本模块将介绍除管道之外，命令可以被串联的几种方式。到最后，你将踏上编写 *Shell 脚本* 的道路！

#### 使用分号串联命令

串联命令最简单的方式是 `;`。在大多数上下文中，`;` 分隔命令的方式类似于 Enter 分隔行。所以，这样：

```console
hacker@dojo:~$ echo COLLEGE > pwn
hacker@dojo:~$ cat pwn
COLLEGE
hacker@dojo:~$
```

大致等同于这样：

```console
hacker@dojo:~$ echo COLLEGE > pwn; cat pwn
COLLEGE
hacker@dojo:~$
```

基本上，当你按下 Enter 时，你的 Shell 会执行你输入的命令，并在该命令终止后给你提示符以输入另一个命令。分号类似，只是没有提示符，并且你在任何内容执行之前输入两个命令。

现在试一试！在本关中，你必须运行 `/challenge/pwn`，然后运行 `/challenge/college`，用分号将它们串联起来。

#### 基于成功构建

你在[进程](https://pwn.college/linux-luminarium/processes/)模块中学习了退出码。现在让我们用它们来串联命令！

`&&` 运算符允许你仅当第一个命令成功时才运行第二个命令（按照 Linux 惯例，这意味着它以代码 0 退出）。这被称为“AND”运算符，因为两个条件都必须为真：第一个命令必须成功，然后第二个命令才会运行。这对于复杂的命令行工作流非常有用，其中某些操作依赖于其他操作的成功。

语法如下：

```console
hacker@dojo:~$ command1 && command2
```

这意味着：“运行 command1，如果它成功，则运行 command2。”

一些示例：

```console
hacker@dojo:~$ touch /home/hacker/file && echo "this will run"
success
this will run
hacker@dojo:~$ touch /file && echo "this will NOT run"
touch: cannot touch '/file': Permission denied
hacker@dojo:~$
```

第二次调用 `touch` 失败，因为 `hacker` 用户没有对 `/file` 的写访问权限，所以 `echo` 没有运行。

在本挑战中，你需要使用 `&&` 运算符串联程序 `/challenge/first-success` 和 `/challenge/second`。先分别运行每个命令，看看会发生什么（结果是你*不会*获得 flag）。但如果你用 `&&` 串联它们，flag 就会出现！

#### 处理失败

你刚刚学习了 `&&` 运算符，它仅在第一个命令成功时运行第二个命令。现在让我们学习它的反面：`||` 运算符允许你仅当第一个命令失败（以非零代码退出）时才运行第二个命令。这被称为“OR”运算符，因为要么第一个命令成功，要么第二个命令会运行。

语法如下：

```console
hacker@dojo:~$ command1 || command2
```

这意味着：“运行 command1，如果它失败，则运行 command2。”

一些示例：

```console
hacker@dojo:~$ touch /file || echo "touch failed, so this runs"
touch: cannot touch '/file': Permission denied
touch failed, so this runs
hacker@dojo:~$ touch /home/hacker/file || echo "this will NOT run"
hacker@dojo:~$
```

`||` 运算符对于提供回退命令或错误处理非常有用！

在本挑战中，你需要使用 `||` 运算符串联 `/challenge/first-failure` 和 `/challenge/second`。去吧！

#### 你的第一个 Shell 脚本

随着你组合越来越多的命令来实现复杂效果，组合后的提示符长度很快会变得非常烦人。发生这种情况时，你可以将这些命令放入一个文件，称为 *Shell 脚本*，并通过执行该文件来运行它们！例如，考虑我们的分号技巧：

```console
hacker@dojo:~$ echo COLLEGE > pwn; cat pwn
COLLEGE
hacker@dojo:~$
```

我们可以创建一个名为 `pwn.sh` 的 Shell 脚本（按照惯例，Shell 脚本经常以 `sh` 后缀命名）：

```bash
echo COLLEGE > pwn
cat pwn
```

然后，我们可以将它作为参数传递给 Shell（`bash`）的新实例来执行！当以这种方式调用 Shell 时，它不从用户那里接收命令，而是从文件中读取命令。

```console
hacker@dojo:~$ ls
hacker@dojo:~$ bash pwn.sh
COLLEGE
hacker@dojo:~$ ls
pwn
hacker@dojo:~$
```

你可以看到 Shell 脚本执行了两个命令，创建并打印了 `pwn` 文件。

现在轮到你了！与上一关相同，运行 `/challenge/pwn`，然后运行 `/challenge/college`，但这次放在名为 `x.sh` 的 Shell 脚本中，然后用 `bash` 运行它！

#### 重定向脚本输出

让我们尝试一些更棘手的事情！你已经用 `|` 在程序之间管道传输输出，但到目前为止，这只是在一条命令的输出和另一条命令的输入之间。但如果你想将多个程序的输出发送给一条命令呢？有几种方法可以做到这一点，我们在这里探索一种简单的方法：重定向脚本的输出！

对 Shell 来说，你的脚本只是另一条命令。这意味着你可以像在[管道](https://pwn.college/linux-luminarium/piping)模块中对命令所做的那样，重定向它的输入和输出！例如，你可以将它写入文件：

```console
hacker@dojo:~$ cat script.sh
echo PWN
echo COLLEGE
hacker@dojo:~$ bash script.sh > output
hacker@dojo:~$ cat output
PWN
COLLEGE
hacker@dojo:~$
```

所有各种重定向方法都有效：`>` 用于 stdout，`2>` 用于 stderr，`<` 用于 stdin，`>>` 和 `2>>` 用于追加模式重定向，`>&` 用于重定向到其他文件描述符，`|` 用于管道到另一条命令。

在本关中，我们将练习从你的脚本管道（`|`）到另一个程序。由于可执行脚本稍后才会介绍，当你管道传输脚本输出时，请用 `bash` 运行你的脚本。和之前一样，你需要创建一个 `.sh` 脚本，调用 `/challenge/pwn` 命令，随后调用 `/challenge/college` 命令，并将脚本的输出管道到对 `/challenge/solve` 命令的一次调用中。

#### 可执行 Shell 脚本

你已经编写了第一个 Shell 脚本，但通过 `bash script.sh` 调用它很麻烦。为什么需要那个 `bash`？

当你调用 `bash script.sh` 时，你当然是在启动 `bash` 命令，并以 `script.sh` 作为参数。这告诉 bash 从 `script.sh` 而不是标准输入读取命令，因此你的 Shell 脚本被执行。

事实证明，你可以避免手动调用 `bash`。如果你的 Shell 脚本文件是*可执行*的（回忆[文件权限](https://pwn.college/linux-luminarium/permissions)），你可以直接通过它的相对或绝对路径调用它！例如，如果你在主目录中创建 `script.sh` *并使其可执行*，你可以通过 `/home/hacker/script.sh` 或 `~/script.sh` 或（如果你的工作目录是 `/home/hacker`）`./script.sh` 来调用它。

#### 理解 Shebang

你正在迈向作为 Shell 脚本编写者的新生活！然而，到目前为止，你的 Shell 脚本*只能从 Shell 中启动*。上一关运行得很好（因为你从 `bash` Shell 中调用脚本），但如果你的脚本被例如用 Python（或任何其他语言）编写的程序调用，它就不会工作。

在 Linux 中调用程序时，Linux 内核首先检查文件以确定应如何运行它。这**不**使用扩展名（这就是为什么你*不必*将 Shell 脚本命名为 `.sh` 扩展名，或将 Python 脚本命名为 `.py` 扩展名，等等）。相反，Linux 查看文件的前几个字节来获取此信息。

程序有很多不同类型，但如果程序文件以字符 `#!` 开头（通常称为“[shebang](https://en.wikipedia.org/wiki/Shebang_(Unix))”），Linux 会将文件视为*解释型程序*，并将该行其余内容视为*解释器*的路径。然后，它调用解释器，并将程序文件的路径作为其唯一参数。

考虑这个 Shell 脚本：

```bash
#!/bin/bash

echo "Hello Hackers!"
```

它可以这样执行：

```console
hacker@dojo:~$ chmod a+x script.sh
hacker@dojo:~$ ./script.sh
Hello Hackers!
hacker@dojo:~$
```

当执行 `./script.sh` 时，Linux 打开文件，读取第一行，提取 `/bin/bash` 作为解释器，并执行 `/bin/bash ./script.sh` 来启动脚本！

注意，shebang 行必须是文件的**最开头**一行——它前面不能有空行或空格！

对于本挑战，在 `/home/hacker/solve.sh` 创建一个具有正确 shebang 并输出 "hack the planet" 的脚本。记得使其可执行，然后运行 `/challenge/run` 验证你的脚本工作正常！

---

> **趣闻：**  
> 你可能会看到的常见 shebang：
> 
> - `#!/bin/bash` 用于 bash 脚本
> - `#!/usr/bin/python3` 用于 Python 脚本
> - `#!/bin/sh` 用于 POSIX Shell 脚本——它是 `bash` 的更原始前身，功能更少，但与非 Linux 系统的兼容性更好！

#### 带参数编写脚本

你已经学习了如何制作 Shell 脚本，但到目前为止它们只是命令列表。当脚本能够接受参数时，它们会变得强大得多！这可能看起来像：

```console
hacker@dojo:~$ bash myscript.sh hello world
```

脚本可以使用特殊变量访问这些参数：

- `$1` 包含第一个参数（"hello"）
- `$2` 包含第二个参数（"world"）
- `$3` 将包含第三个参数（如果有的话）
- ……依此类推

这里有一个简单示例：

```console
hacker@dojo:~$ cat myscript.sh
#!/bin/bash
echo "First argument: $1"
echo "Second argument: $2"
hacker@dojo:~$ bash myscript.sh hello world
First argument: hello
Second argument: world
hacker@dojo:~$
```

1. 接收两个参数
2. 以相反顺序输出它们（先输出第二个参数，再输出第一个参数）

例如：

```console
hacker@dojo:~$ bash /home/hacker/solve.sh pwn college
college pwn
hacker@dojo:~$
```

#### 带条件编写脚本

现在你可以在脚本中使用参数了，让我们用条件逻辑让它们更智能！

在 bash 中，你可以使用 `if` 语句来做决定：

```bash
if [ "$1" == "ping" ]
then
    echo "pong"
fi
```

上面这段，用英语说就是 `if the first argument is "ping", print out "pong"`。该语法在几个方面有些苛刻。首先，你*必须*在 `if` 之后（如果你习惯 C 之类的语言，这与它们不同）、`[` 之后和 `]` 之前加空格。其次，`if`、`then` 和 `fi` 都必须位于不同行（或用分号分隔）；你不能把它们塞进同一条语句。这也有点奇怪：`if` 语句的终止符不是 `endif` 或 `end` 之类的东西，而是 `fi`（`if` 反过来写）。这是你必须记住的东西。

对于本挑战，在 `/home/hacker/solve.sh` 编写一个脚本，该脚本：

- 接收一个参数
- 如果参数是 "pwn"，输出 "college"
- 对于任何其他输入，不输出任何内容

示例：

```console
hacker@dojo:~$ bash /home/hacker/solve.sh pwn
college
hacker@dojo:~$ bash /home/hacker/solve.sh foo
hacker@dojo:~$
```

#### 带默认分支编写脚本

到目前为止，你的 `if` 语句处理了特定情况，但其他所有情况呢？这就是 `else` 的用武之地！

当 `if` 条件为假时，`else` 子句会执行：

```bash
if [ "$1" == "hello" ]
then
    echo "Hi there!"
else
    echo "I don't understand"
fi
```

注意，`else` 没有条件——它捕获之前没有匹配的所有情况。它也没有 `then` 语句。最后，`fi` 放在 `else` 块之后，表示整个复杂语句的结束！它也是可选的：你在上一关没有它，只有当你试图实现的逻辑需要它时，你才需要它。

这里有一个实用示例：

```bash
if [ "$1" == "start" ]
then
    echo "Starting the service..."
else
    echo "Unknown command. Use 'start' to begin."
fi
```

对于本挑战，在 `/home/hacker/solve.sh` 编写一个脚本，该脚本：

- 接收一个参数
- 如果参数是 "pwn"，输出 "college"
- 对于任何其他输入，输出 "nope"

示例：

```console
hacker@dojo:~$ bash /home/hacker/solve.sh pwn
college
hacker@dojo:~$ bash /home/hacker/solve.sh hack
nope
hacker@dojo:~$ bash /home/hacker/solve.sh anything
nope
hacker@dojo:~$
```

#### 带多个条件编写脚本

你已经学习了如何使用单个 `if` 语句检查一个条件。但如果你需要检查多个条件呢？你可以使用 `elif`（`else if` 的缩写）：

```bash
if [ "$1" == "one" ]
then
    echo "1"
elif [ "$1" == "two" ]
then
    echo "2"
elif [ "$1" == "three" ]
then
    echo "3"
else
    echo "unknown"
fi
```

注意，你*确实*需要在 `elif` 之后加 `then`，就像 `if` 一样。和之前一样，末尾的 `else` 捕获所有没有匹配的情况。

对于本挑战，在 `/home/hacker/solve.sh` 编写一个脚本，该脚本：

- 接收一个参数
- 如果参数是 "hack"，输出 "the planet"
- 如果参数是 "pwn"，输出 "college"
- 如果参数是 "learn"，输出 "linux"
- 对于任何其他输入，输出 "unknown"

示例：

```console
hacker@dojo:~$ bash /home/hacker/solve.sh hack
the planet
hacker@dojo:~$ bash /home/hacker/solve.sh pwn
college
hacker@dojo:~$ bash /home/hacker/solve.sh learn
linux
hacker@dojo:~$ bash /home/hacker/solve.sh foo
unknown
hacker@dojo:~$
```

一旦你的脚本工作正常，运行 `/challenge/run` 获取你的 flag！

> **注意：** 在创建脚本时，请务必严格遵循示例中的空格。与许多其他语言不同，bash 要求 `[` 和 `]` 与其他字符之间用空格分隔，否则无法解析条件。
