# Shell 变量

Linux 命令行界面实际上是一种复杂的编程语言，你可以用它编写真正的程序！由于命令行界面被通俗地称为“shell”，用这种语言编写的程序被称为“shell 脚本”。当你使用命令行时，你基本上是在逐行编写 shell 脚本！

像大多数编程语言一样，shell 支持变量。本模块将让你熟悉设置、打印和使用这些变量！

## 打印变量

让我们从打印变量开始。`/challenge/run` 程序不会、也不能给你 flag，但没关系，因为 flag 已经被放入名为 "FLAG" 的变量中了！只需让你的 shell 打印它！

你可以用多种方法完成，但我们将从 `echo` 开始。这个命令只是打印内容。例如：

```console
hacker@dojo:~$ echo Hello Hackers!
Hello Hackers!
```

你也可以用 `echo` 打印变量，方法是在变量名前加上 `$`。例如，有一个变量 `PWD`，它始终保存当前 shell 的当前工作目录。你可以这样打印它：

```console
hacker@dojo:~$ echo $PWD
/home/hacker
```

现在轮到你了。让你的 shell 打印出 `FLAG` 变量，解决这个挑战！

## 设置变量

当然，除了读取变量中存储的值，你还可以向变量写入值。与许多其他语言一样，这通过 `=` 完成。要将变量 `VAR` 设置为值 `1337`，你可以使用：

```console
hacker@dojo:~$ VAR=1337
```

注意 `=` 周围没有空格！如果你加了空格（例如 `VAR = 1337`），shell 将不会识别为变量赋值，而是会尝试运行 `VAR` 命令（该命令不存在）。

还要注意这里使用的是 `VAR` 而*不是* `$VAR`：`$` 只加在*访问*变量时。在 shell 术语中，这种添加 `$` 的行为会触发所谓的*变量扩展*，并且令人惊讶的是，这是许多潜在漏洞的来源（如果你感兴趣，在熟悉命令行后可以查看 Art of the Shell dojo！）。

设置变量后，你可以使用之前学到的技巧访问它们，例如：

```console
hacker@dojo:~$ echo $VAR
1337
```

要解决此关卡，你必须将 `PWN` 变量设置为值 `COLLEGE`。注意：变量的名称和值都区分大小写！`PWN` 与 `pwn` 不同，`COLLEGE` 与 `College` 也不同。

## 多词变量

在本关卡中，你将学习引号。空格在 shell 中有特殊意义，有些地方不能随意使用空格。回想我们的变量设置：

```console
hacker@dojo:~$ VAR=1337
```

这会将 `VAR` 变量设置为 `1337`，但如果你想将它设置为 `1337 SAUCE` 呢？你可能会尝试以下方式：

```console
hacker@dojo:~$ VAR=1337 SAUCE
```

这看起来合理，但不会生效，原因与 `=` 周围需要没有空格类似。当 shell 看到空格时，它会结束变量赋值，并将下一个词（本例中为 `SAUCE`）解释为命令。要将 `VAR` 设置为 `1337 SAUCE`，你需要*引用*它：

```console
hacker@dojo:~$ VAR="1337 SAUCE"
```

在这里，shell 将 `1337 SAUCE` 读取为单个 token，并愉快地将该值赋给 `VAR`。在本关卡中，你需要将变量 `PWN` 设置为 `COLLEGE YEAH`。祝你好运！

## 导出变量

默认情况下，你在 shell 会话中设置的变量是该 shell 进程局部的。也就是说，你运行的其他命令不会继承它们。你可以通过在自己的 shell 中调用另一个 shell 进程来实验这一点，如下所示：

```console
hacker@dojo:~$ VAR=1337
hacker@dojo:~$ echo "VAR is: $VAR"
VAR is: 1337
hacker@dojo:~$ sh
$ echo "VAR is: $VAR"
VAR is: 
```

在上面的输出中，`$` 提示符是 `sh` 的提示符，这是一个作为主 shell 进程的*子*进程调用的最小 shell 实现。它没有接收到 `VAR` 变量！

当然，这很合理。你的 shell 变量可能包含敏感或奇怪的数据，你不希望它泄漏到你运行的其他程序，除非明确应该如此。如何标记它应该被传递？你*导出*你的变量。当你导出变量时，它们会被传递到子进程的*环境变量*中。你会在其他挑战中遇到环境变量的概念，但你会在这里观察到它们的效果。下面是一个例子：

```console
hacker@dojo:~$ VAR=1337
hacker@dojo:~$ export VAR
hacker@dojo:~$ sh
$ echo "VAR is: $VAR"
VAR is: 1337
```

在这里，子 shell 接收到了 VAR 的值，并能够打印出来！你也可以合并前两行。

```console
hacker@dojo:~$ export VAR=1337
hacker@dojo:~$ sh
$ echo "VAR is: $VAR"
VAR is: 1337
```

在本挑战中，你必须调用 `/challenge/run`，其中 `PWN` 变量已被导出并设置为值 `COLLEGE`，而 `COLLEGE` 变量设置为值 `PWN` 但*不*导出（例如，不被 `/challenge/run` 继承）。祝你好运！

## 打印已导出的变量

试试 `env` 命令：它会打印你的 shell 中设置的每个*已导出*变量，你可以浏览其输出以找到 `FLAG` 变量！

## 存储命令输出

在使用 shell 的过程中，你经常希望将某些命令的输出存储到变量中。幸运的是，shell 通过所谓的[*命令替换*](https://www.gnu.org/software/bash/manual/html_node/Command-Substitution.html)使这变得非常简单！观察：

```console
hacker@dojo:~$ FLAG=$(cat /flag)
hacker@dojo:~$ echo "$FLAG"
pwn.college{blahblahblah}
hacker@dojo:~$
```

很好！现在，你来练习。将 `/challenge/run` 命令的输出直接读入名为 `PWN` 的变量，它将包含 flag！

---

> **冷知识：** 你也可以使用反引号代替 `$()`：在上面的示例中，使用 `FLAG=`cat /flag`` 代替 `FLAG=$(cat /flag)`。这是一种较旧的格式，有一些缺点。例如，想象你想*嵌套*命令替换。你会如何用反引号实现 `$(cat $(find / -name flag))`？pwn.college 的官方立场是，你应该使用 `$(blah)` 而不是 `` `blah` ``。

## 读取输入

我们将从读取用户（你）的输入开始。这使用名副其实的 `read` 内建命令完成，它*读取*输入到变量中！

下面是一个使用 `-p` 参数的示例，它允许你指定提示符（否则，现在阅读此内容的你将很难在下面的示例中区分输入和输出）：

```console
hacker@dojo:~$ read -p "INPUT: " MY_VARIABLE
INPUT: Hello!
hacker@dojo:~$ echo "You entered: $MY_VARIABLE"
You entered: Hello!
```

请记住，`read` 从你的标准输入读取数据！上面的第一个 `Hello!` 是*输入*而不是*输出*。让我们更明确地说明这一点。在这里，我们在每行开头标注了该行代表来自用户的 `INPUT` 还是到用户的 `OUTPUT`：

```console
 INPUT: hacker@dojo:~$ echo $MY_VARIABLE
OUTPUT:
 INPUT: hacker@dojo:~$ read MY_VARIABLE
 INPUT: Hello!
 INPUT: hacker@dojo:~$ echo "You entered: $MY_VARIABLE"
OUTPUT: You entered: Hello!
```

在本挑战中，你的任务是使用 `read` 将 `PWN` 变量设置为值 `COLLEGE`。祝你好运！

## 读取文件

通常，当 shell 用户想要将文件读入环境变量时，他们会这样做：

```console
hacker@dojo:~$ echo "test" > some_file
hacker@dojo:~$ VAR=$(cat some_file)
hacker@dojo:~$ echo $VAR
test
```

这可以工作，但它代表了脾气暴躁的黑客所说的["无用地使用 Cat"](https://porkmail.org/era/unix/award#cat)。也就是说，仅仅为了读取文件而运行另一个程序是一种浪费。事实证明，你可以直接使用 shell 的能力！

之前，你使用 `read` 将用户输入读入变量。你也之前将文件重定向到命令输入！把它们结合起来，你就可以用 shell 读取文件。

```console
hacker@dojo:~$ echo "test" > some_file
hacker@dojo:~$ read VAR < some_file
hacker@dojo:~$ echo $VAR
test
```

那里发生了什么？示例将 `some_file` 重定向到 `read` 的*标准输入*，因此当 `read` 读入 `VAR` 时，它从文件读取！现在，使用它来将 `/challenge/read_me` 读入 `PWN` 环境变量，我们将给你 flag！`/challenge/read_me` 会不断变化，因此你需要用一条命令将其直接读入 `PWN` 变量！
