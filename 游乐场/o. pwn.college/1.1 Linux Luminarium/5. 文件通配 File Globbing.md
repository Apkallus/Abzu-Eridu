# 文件通配

即使只学了几关，你可能已经厌倦了输入所有这些文件路径。幸运的是，shell 有一个解决方案：glob！这就是我们将在本模块中学习的内容。

在执行你输入的命令之前，shell 会先对它们执行*扩展*，其中之一就是 glob。glob 让你无需把所有文件名或完整路径都打出来，就能引用文件。让我们深入吧！

## 使用 `*` 匹配

我们将学习的第一个 glob 是 `*`。当 shell 在任何参数中遇到 `*` 字符时，会将其视为“通配符”，并尝试把该参数替换为任何匹配该模式的文件。展示给你看比解释更容易：

```console
hacker@dojo:~$ touch file_a
hacker@dojo:~$ touch file_b
hacker@dojo:~$ touch file_c
hacker@dojo:~$ ls
file_a	file_b	file_c
hacker@dojo:~$ echo Look: file_*
Look: file_a file_b file_c
```

当然，尽管在这个例子中 glob 产生了多个参数，它也可以同样简单地只匹配一个。例如：

```console
hacker@dojo:~$ touch file_a
hacker@dojo:~$ ls
file_a
hacker@dojo:~$ echo Look: file_*
Look: file_a
```

当匹配到零个文件时，默认情况下 shell 会保持 glob 不变：

```console
hacker@dojo:~$ touch file_a
hacker@dojo:~$ ls
file_a
hacker@dojo:~$ echo Look: nope_*
Look: nope_*
```

`*` 匹配文件名的任意部分，但 `/` 或开头的 `.` 字符除外。例如：

```console
hacker@dojo:~$ echo ONE: /ho*/*ck*
ONE: /home/hacker
hacker@dojo:~$ echo TWO: /*/hacker
TWO: /home/hacker
hacker@dojo:~$ echo THREE: ../*
THREE: ../hacker
```

现在，自己练习吧！从你的主目录开始，将目录切换到 `/challenge`，但使用 glob 让你传给 `cd` 的参数最多为四个字符！到达那里后，运行 `/challenge/run` 获取 flag！

## 使用 `?` 匹配

接下来，让我们学习 `?`。当 shell 在任何参数中遇到 `?` 字符时，会将其视为**单字符**通配符。它的工作方式与 `*` 类似，但只匹配*一个*字符。例如：

```console
hacker@dojo:~$ touch file_a
hacker@dojo:~$ touch file_b
hacker@dojo:~$ touch file_cc
hacker@dojo:~$ ls
file_a	file_b	file_cc
hacker@dojo:~$ echo Look: file_?
Look: file_a file_b
hacker@dojo:~$ echo Look: file_??
Look: file_cc
```

现在，自己练习吧！从你的主目录开始，将目录切换到 `/challenge`，但在传给 `cd` 的参数中用 `?` 字符代替 `c` 和 `l`！到达那里后，运行 `/challenge/run` 获取 flag！

## 使用 `[]` 匹配

接下来，我们将介绍 `[]`。方括号本质上是一种受限形式的 `?`，它不是匹配任意字符，而是匹配括号内指定的一些潜在字符子集。例如，`[pwn]` 将匹配字符 `p`、`w` 或 `n`。例如：

```console
hacker@dojo:~$ touch file_a
hacker@dojo:~$ touch file_b
hacker@dojo:~$ touch file_c
hacker@dojo:~$ ls
file_a	file_b	file_c
hacker@dojo:~$ echo Look: file_[ab]
Look: file_a file_b
```

在这里试试！我们在 `/challenge/files` 中放置了一堆文件。将工作目录切换到 `/challenge/files`，并向 `/challenge/run` 传入单个参数，使其通过方括号 glob 匹配到 `file_b`、`file_a`、`file_s` 和 `file_h`！

## 使用 `[]` 匹配路径

glob 是基于*路径*进行的，因此你可以用 glob 参数展开整个路径。例如：

```console
hacker@dojo:~$ touch file_a
hacker@dojo:~$ touch file_b
hacker@dojo:~$ touch file_c
hacker@dojo:~$ ls
file_a	file_b	file_c
hacker@dojo:~$ echo Look: /home/hacker/file_[ab]
Look: /home/hacker/file_a /home/hacker/file_b
```

现在轮到你了。我们再次在 `/challenge/files` 中放置了一堆文件。从你的主目录开始，运行 `/challenge/run`，传入单个参数，使其通过方括号 glob 匹配到 `file_b`、`file_a`、`file_s` 和 `file_h` 文件的绝对路径！

## 多个 glob

到目前为止，你一次只指定一个 glob，但你可以做得更多！Bash 支持在单个词中展开多个 glob。例如：

```console
hacker@dojo:~$ cat /*fl*
pwn.college{YEAH}
hacker@dojo:~$
```

上面发生的情况是，shell 查找 `/` 中所有以*任意内容*（包括空）开头、然后有一个 `f` 和一个 `l`、并以*任意内容*（包括 `ag`，从而组成 `flag`）结尾的文件。

现在你来试试。我们在 `/challenge/files` 中放置了几个名称愉快但各不相同的文件。`cd` 到那里并运行 `/challenge/run`，提供一个参数：一个短（3 个字符或更少）的 glob 词，其中包含两个 `*` glob，覆盖每个包含字母 `p` 的词。

## 混合 glob

现在，让我们把前面的关卡结合起来！我们在 `/challenge/files` 中放置了几个名称愉快但各不相同的文件。`cd` 到那里，并使用你学到的 glob，写一个单独的、短的（6 个字符或更少）glob，当作为参数传给 `/challenge/run` 时，将**仅**匹配文件 `challenging`、`educational` 和 `pwning`！

## 排除式 glob

有时，你想在 glob 中过滤掉文件！幸运的是，`[]` 正好能帮你做到这一点。如果括号中的第一个字符是 `!`，或者（在较新版本的 bash 中）是 `^`，则该 glob 反转，该括号实例匹配*未*列出的字符。例如：

```console
hacker@dojo:~$ touch file_a
hacker@dojo:~$ touch file_b
hacker@dojo:~$ touch file_c
hacker@dojo:~$ ls
file_a	file_b	file_c
hacker@dojo:~$ echo Look: file_[!ab]
Look: file_c
hacker@dojo:~$ echo Look: file_[^ab]
Look: file_c
hacker@dojo:~$ echo Look: file_[ab]
Look: file_a file_b
```

掌握了这些知识后，前往 `/challenge/files` 并运行 `/challenge/run`，传入所有不以 `p`、`w` 或 `n` 开头的文件！

> **注意：** 当 `!` 字符不是 `[]` glob 的第一个字符时，它在 bash 中有不同的特殊含义，所以如果事情开始变得难以理解，请记住这一点！`^` 没有这个问题，但与较旧的 shell 不兼容。

## Tab 补全

尽管使用 `*` 来缩短命令行上必须输入的内容可能很诱人，但这可能导致错误。你的 glob 可能展开为意想不到的文件，而你可能直到 `rm` 命令已经在运行时才发现！没有人能免于这种错误。

当你试图指定一个特定目标时，一个更安全的替代方案是*Tab 补全*。如果你在 shell 中按 Tab，它会尝试推断你要输入的内容并自动补全。自动补全非常有用，本挑战将探索它在指定文件方面的用途。

本挑战已将 flag 复制到 `/challenge/pwncollege`，你可以自由地 `cat` 该文件。但你不能直接输入文件名：我们使用了一些相当复杂的诡计来确保你*必须*使用 Tab 补全。试试看！

```console
hacker@dojo:~$ ls /challenge
Dockerfile  pwncollege
hacker@dojo:~$ cat /challenge/pwncollege
cat: /challenge/pwncollege: No such file or directory
hacker@dojo:~$ cat /challenge/pwn<TAB>
pwn.college{HECK YEAH}
hacker@dojo:~$
```

当你按下 Tab 键时，名称会展开，你就能读取文件。祝你好运！

## Tab 补全的多个选项

考虑以下情况：

```console
hacker@dojo:~$ ls
flag  flamingo  flowers
hacker@dojo:~$ cat f<TAB>
```

有多个选项！会发生什么？

发生的情况取决于具体的 shell 及其选项。默认情况下，`bash` 会自动展开，直到第一次出现多个选项的位置（在本例中是 `fl`）。当你*第二次*按 Tab 时，它会打印这些选项。其他 shell 和配置则会循环切换选项。

本挑战有一个 `/challenge/files` 目录，里面有一堆以 `pwncollege` 开头的文件。从 `/challenge/files/p` 左右开始使用 Tab 补全，一路找到 flag！

## 命令的 Tab 补全

Tab 补全不仅适用于文件！你也可以对命令进行 Tab 补全。本关卡有一个以 `pwncollege` 开头的命令，它会给你 flag。输入 `pwncollege` 并按 Tab 键自动补全它！

---

> **注意：** 你可以自动补全任何命令，但要小心：不加复核地随意自动补全，如果你意外运行了错误的命令，可能会在 shell 中造成严重破坏！
