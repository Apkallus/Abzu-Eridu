# 大胆破坏

> 能力越大，责任越大。

在 Luminarium 的学习过程中，你已经学会了如何浏览、操作和控制一台 Linux 机器。在我们把你送入广阔天地之前，用一些警示——**以及一点混乱**——来收尾是再公平不过的了。

以下是一组非穷尽的示例，这些看似无害的操作在真实系统上执行时，可能导致灾难性的数据丢失、拒绝服务，甚至不可恢复的系统损坏。在 pwn.college 上，它们都是可恢复的（通过重启你的容器），但在毫无防备的计算机上，它们是真实存在的危险。

练习它们，惊叹它们，**切勿**在任何重要的东西上运行它们。

#### Fork 炸弹

正如你在 [进程与作业] 模块中学到的，每当你启动一个程序，Linux 操作系统都会创建一个新进程。如果你创建进程的速度超过了内核的处理能力，进程表就会被填满，*一切*都将陷入停滞。这个新进程（例如 `ls` 调用的进程）是从父进程（例如 shell 实例）“fork”出来的。因此，这种引发的进程爆炸被称为“Fork 炸弹”。

你拥有实现它的工具：

- 编写一个小脚本（如同 [链接命令] 模块中那样）
- 使其可执行（如同 [感知权限] 模块中那样）
- 让它启动自身的一个副本到后台（如同 [进程与作业] 模块中那样）
- 然后启动*另一个*自身副本到后台！

每个副本将启动另外两个，那两个又各自启动两个，你将用如此多的进程淹没系统，以至于新进程无法启动！

本挑战包含一个 `/challenge/check`，它会尝试判断你的 fork 炸弹是否生效（例如，它是否无法启动新进程），如果生效则给你 flag。请确保在启动攻击*之前*（在另一个终端中）启动它；否则你将无法启动它！

---

**注意：**
毋庸置疑，这会使你的环境变得不可用。只需重启挑战（或启动另一个挑战）即可恢复到可用状态！

#### 磁盘空间末日

本容器中 `/home/hacker` 的可用空间只有区区 **1 GB**。在本关中，你将用大量垃圾填满 `/home/hacker`，以至于连一个 1 MB 的小文件都无法创建。发生这种情况时，你的工作区将变得不可用。我们将在本挑战中练习引发这种情况，稍后再进一步扩展。

如何填满磁盘？方法有很多。这里我们将教你 `yes` 命令！

```console
hacker@dojo:~$ yes | head
y
y
y
y
y
y
y
y
y
y
hacker@dojo:~$
```

`yes` 会永远不停地输出 `y`。典型用法是通过管道自动化确认提示（“你确定要删除此文件吗？”），但我们将在这里用它来创建一个充满“y”行的大文件。只需将 `yes` 重定向到主目录中的文件，一两分钟内就能填满磁盘！

本挑战要求你先填满磁盘，然后清理。流程如下：

1. 填满磁盘。
2. 运行 `/challenge/check`。它将尝试创建一个 1 MB 的临时文件。如果失败，你通过第一阶段，检查器会要求你释放空间。
3. 删除你创建的文件（使用 `rm`）以清理空间。
4. 再次运行 `/challenge/check`。如果它现在能创建临时文件（即你成功清理了主目录），你将获得 flag。

---

**注意：**
在本挑战中，`/home/hacker` 是一个小的临时主目录。你现有的主目录文件在此不可用，你在此保存的文件在挑战结束后不会保留。

**为什么分两个阶段？**
你的主目录会在挑战实例之间持久保留。如果我们让你把它保持填满状态，你的 pwn.college 将停止工作。这*远远*是 pwn.college 上出现奇怪问题最常见的原因！

**救命，它坏了！**
如果你填满了磁盘之后没有清理，你需要通过 `ssh` 登录来修复（通过删除那个文件）。这有点棘手，但我们在 [入门] 模块的“通过 SSH 连接”一节中描述了如何操作。

#### `rm -rf /`

想要清空一切重新开始？你可以！

```console
hacker@dojo:~$ ls /
bin etc blah blah blah
hacker@dojo:~$ rm -rf /
hacker@dojo:~$ ls /
bash: ls: command not found
hacker@dojo:~$
```

这里发生了什么？如你所知，`rm` 删除文件。`-r`（递归）标志删除目录及其包含的所有文件。`-f`（强制）标志忽略 `rm` 命令遇到的任何错误或可能有的顾虑。组合起来并指向 `/`，结果是灾难性的：系统被完全清除。在现代系统上，事情并没有*那么*简单，但你看到它时就会明白。

在本挑战中，你将做一件你可能永远不会再做的事：清除整个系统。我们实际上做了一些修改以保护你的主目录（正常情况下，它也会被清除！），但除此之外，你和 flag 之间唯一的障碍就是你清除驱动器的意愿。但在清除一切之前，请确保启动 `/challenge/check`，以便它观看烟花（并给你 flag）！

---

**注意：**
`rm` 需要运行一段时间。有很多东西要删除！

**注意：**
由于各种技术原因，你不太可能删除*所有内容*，包括我们在本关中用来保护你主目录的技术。别担心，你会造成足够的破坏！

#### `rm -rf /` 之后的生活

让我们深入探讨清除整个文件系统的影响。你现在已经是一个有经验的 `rm` 用户了，但之前，当你清除文件系统的杂乱内容时，`/challenge/check` 会为你打印出 flag。如果它没有呢？没有 `cat`，你该如何读取 `/flag`？

回想一下，在 [消化文档] 模块中，有些 shell 命令是*内建命令*。虽然 `ls`、`cat` 等不是，但 `read`（如果你还记得 [Shell 变量] 模块，它可以读取文件！）*是*。这意味着，即使你清除了整个文件系统，只要你有正在运行的 bash 实例，你就可以读取文件！

本挑战将迫使你尝试。它与上一个几乎相同，但你必须在你摧毁系统之后自己读取 flag。在你 `rm` 一切之后，你之前启动的 `/challenge/check` 将恢复 `/flag` 文件并使其可读。然后你就可以 `read` 它了！

#### `rm -rf /` 之后寻找意义

所以你能在没有 `cat` 的情况下生存！那没有 `ls` 呢？这一次，`/challenge/check` 将把 flag 恢复到一个*随机命名*的文件中。你需要在不使用 `ls` 命令的情况下找到它。

解决这个挑战有很多方法。`echo` 是内建命令，你可以对它的参数进行 [文件通配] 以展开为所有文件！例如，`echo *` 将打印当前目录中所有文件的名称。同样，你可以使用参数的 Tab 补全（按几次 Tab）让 shell 为你列出可能的文件。

无论你使用哪条路线，找到 `/challenge/check` 在你 `rm` 之后于 `/` 中创建的随机命名文件，读取它，拿到 flag！
