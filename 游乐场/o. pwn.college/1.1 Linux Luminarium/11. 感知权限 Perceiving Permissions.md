# 感知权限

本模块将让你接触 Linux 权限。它是你后续旅程中最重要的部分之一，负责调控不同用户对文件的访问。

在 Linux 中，文件具有不同的权限或文件模式。你可以使用 `ls -l` 查看文件或目录的权限。让我们创建一些文件并查看它们的权限：

```console
hacker@dojo:~$ mkdir pwn_directory
hacker@dojo:~$ touch college_file
hacker@dojo:~$ ls -l
total 4
-rw-r--r-- 1 hacker hacker    0 May 22 13:42 college_file
drwxr-xr-x 2 hacker hacker 4096 May 22 13:42 pwn_directory
hacker@dojo:~$
```

那里有很多信息，我们将在本模块中学习其中的许多内容！现在，我们先从高层面上看看上面的输出：

#### 文件类型

每一行的第一个字符表示文件类型。对于 `pwn_directory`，`d` 表示它是一个目录；对于 `college_file`，`-` 表示它是一个普通文件。还有其他类型，你会在 pwn.college 旅程的后续阶段遇到其中一些。

#### 权限

接下来的九个字符是文件或目录的实际访问权限，分为三组，每组三个字符：第一组表示拥有该文件的用户（称为“所有者”）对该文件的权限，第二组表示拥有该文件的组（称为“组”）对该文件的权限，第三组表示所有其他访问者（例如其他用户和其他组）对该文件的权限。我们将在本模块后面详细了解这些内容。

#### 所有权信息

有两列分别显示拥有该文件的用户（在本例中是用户 `hacker`），以及拥有该文件的组（在本例中也是组 `hacker`）。你会在这里亲自折腾这些内容！

#### 更改文件所有权

首先是文件所有权。Linux 中的每个文件都归属于系统上的某个用户。在日常生活中，这个用户通常就是你每天登录时使用的用户。

在共享系统上（例如计算机实验室），可能有许多人拥有不同的用户账户，并且都在自己的主目录中拥有自己的文件。但即使在非共享系统上（例如你的个人 PC），Linux 仍然有许多用于不同任务的“服务”用户账户。

最重要的两个用户账户是：

1. 你的用户账户！在 pwn.college 上，无论你的用户名是什么，这个账户都是 `hacker`。
2. `root`。这是管理账户，在大多数安全场景中都是终极目标。如果你接管了 `root` 用户，那你几乎肯定已经实现了黑客目标！

那又怎样？事实证明，我们阻止你直接执行 `cat /flag` 的方式，就是让 `/flag` 归属于 `root` 用户，配置其权限使其他用户无法读取它（你稍后会学习如何做到这一点），并配置实际的挑战程序以 `root` 用户身份运行（你稍后也会学习如何做到这一点）。结果是，当你执行 `cat /flag` 时，你会得到：

```console
hacker@dojo:~$ ls -l /flag
-r-------- 1 root root 53 Jul  4 04:47 /flag
hacker@dojo:~$ cat /flag
cat: /flag: Permission denied
hacker@dojo:~$
```

在这里，你可以看到 flag 归属于 `root` 用户（该行第一个 `root`）和 `root` 组（该行第二个 `root`）。当我们以 `hacker` 用户身份尝试读取它时，会被拒绝。然而，如果我们就是 `root`（黑客的梦想！），读取这个文件毫无问题：

```console
root@dojo:~# cat /flag
pwn.college{demo_flag}
root@dojo:~#
```

有趣的是，我们可以更改文件的所有权！这通过 `chown`（**ch**ange **own**er，更改所有者）命令完成：

```sh
chown [username] [file]
```

通常，只有 `root` 用户才能调用 `chown`。让我们再次假装自己是 `root`（这永远不会过时！），看看 `chown` 的典型用法：

```console
root@dojo:~# mkdir pwn_directory
root@dojo:~# touch college_file
root@dojo:~# ls -l
total 4
-rw-r--r-- 1 root root    0 May 22 13:42 college_file
drwxr-xr-x 2 root root 4096 May 22 13:42 pwn_directory
root@dojo:~# chown hacker college_file
root@dojo:~# ls -l
total 4
-rw-r--r-- 1 hacker root    0 May 22 13:42 college_file
drwxr-xr-x 2 root   root 4096 May 22 13:42 pwn_directory
root@dojo:~#
```

`college_file` 的所有者已更改为 `hacker` 用户，现在 `hacker` 可以对它做 `root` 之前能做的任何事！如果这是 `/flag` 文件，那就意味着 `hacker` 用户将能够读取它！

在本关中，我们将练习将 `/flag` 文件的所有者更改为 `hacker` 用户，然后读取 flag。仅在本挑战中，我让你可以以 `hacker` 用户身份尽情使用 `chown`（再次说明，通常这需要你是 `root`）。明智地使用这份力量，尽情 `chown` 吧！

#### 组与文件

分享即关怀，而共享已融入 Linux 的设计之中。文件既有拥有它的用户，也有拥有它的组。一个组可以包含多个用户，一个用户也可以属于多个组。

你可以使用 `id` 命令查看自己属于哪些组：

```console
hacker@dojo:~$ id
uid=1000(hacker) gid=1000(hacker) groups=1000(hacker)
hacker@dojo:~$
```

这里，`hacker` 用户**只**在 `hacker` 组中。组最常见的用途是控制对不同系统资源的访问。例如，pwn.college 中的“特权模式”会授予你 `root` 访问权限，以便更好地调试等。这是通过在你以特权模式启动时给你一个额外的组来实现的：

```console
hacker@dojo:~$ id
uid=1000(hacker) gid=1000(hacker) groups=1000(hacker),27(sudo)
hacker@dojo:~$
```

一个典型 Linux 桌面上的典型主用户会属于**很多**组。例如，这是 Zardus 的桌面：

```console
zardus@yourcomputer:~$ id
uid=1000(zardus) gid=1000(zardus) groups=1000(zardus),24(cdrom),25(floppy),27(sudo),29(audio),30(dip),44(video),46(plugdev),100(users),106(netdev),114(bluetooth),117(lpadmin),120(scanner),995(docker)
zardus@yourcomputer:~$
```

所有这些组让 Zardus 能够读取 CD 和软盘（现在谁还用这些呢？）、管理系统、播放音乐、向视频监视器绘制内容、使用蓝牙等等。通常，这种访问控制通过文件系统上的组所有权实现！例如，图形输出可以通过特殊的 `/dev/fb0` 文件完成：

```console
zardus@yourcomputer:~$ ls -l /dev/fb0
crw-rw---- 1 root video 29, 0 Jun 30 23:42 /dev/fb0
zardus@yourcomputer:~$
```

这个文件是一个特殊的设备文件（类型 `c` 表示它是“字符设备”），与它交互会改变显示输出（而不是像普通文件那样改变磁盘存储！）。Zardus 机器上的用户账户能够与它交互，因为该文件的组所有权是 `video`，而 Zardus 是 `video` 组的成员。

不过，dojo 中的 `/flag` 文件就没这种运气了！考虑以下情况：

```console
hacker@dojo:~$ id
uid=1000(hacker) gid=1000(hacker) groups=1000(hacker)
hacker@dojo:~$ ls -l /flag
-r--r----- 1 root root ... /flag
hacker@dojo:~$ cat /flag
cat: /flag: Permission denied
hacker@dojo:~$
```

这里，flag 文件归属于 `root` 用户和 `root` 组，而 `hacker` 用户既不是 `root` 用户，也不是 `root` 组成员，因此无法访问该文件。幸运的是，组所有权可以通过 `chgrp`（**ch**ange **gr**ou**p**，更改组）命令更改！除非你既是文件所有者又是新组的成员，否则这通常需要 `root` 权限，所以让我们以 `root` 身份看看：

```console
root@dojo:~# mkdir pwn_directory
root@dojo:~# touch college_file
root@dojo:~# ls -l
total 4
-rw-r--r-- 1 root root    0 May 22 13:42 college_file
drwxr-xr-x 2 root root 4096 May 22 13:42 pwn_directory
root@dojo:~# chgrp hacker college_file
root@dojo:~# ls -l
total 4
-rw-r--r-- 1 root hacker    0 May 22 13:42 college_file
drwxr-xr-x 2 root root   4096 May 22 13:42 pwn_directory
root@dojo:~#
```

在本关中，我已让 flag 可被拥有它的任意组读取，但目前这个组是 `root`。幸运的是，我也让你可以以 `hacker` 用户身份调用 `chgrp`！更改 flag 文件的组所有权，然后读取 flag！

#### 玩转组名

在前面的关卡中，你可能已经注意到，你的 `hacker` 用户是 `hacker` 组的成员，而 `zardus` 是 `zardus` 组的成员。Linux 中有一个惯例：每个用户都有自己的组，但情况不一定非要如此。例如，许多计算机实验室会将所有用户放入一个共享的 `users` 组中。

重点是，你之前使用 `hacker` 作为组，但在本关中，这行不通。我仍然允许你使用 `chgrp`，但我已经将你的用户所在组的名称随机化了。你需要使用 `id` 命令找出这个名称，然后用 `chgrp` 取得胜利！

#### 更改权限

现在我们已经熟悉了所有权。让我们谈谈硬币的另一面：文件权限。回顾我们的例子：

```console
hacker@dojo:~$ mkdir pwn_directory
hacker@dojo:~$ touch college_file
hacker@dojo:~$ ls -l
total 4
-rw-r--r-- 1 hacker hacker    0 May 22 13:42 college_file
drwxr-xr-x 2 hacker hacker 4096 May 22 13:42 pwn_directory
hacker@dojo:~$
```

提醒一下，第一个字符是文件类型。接下来的九个字符是文件或目录的实际访问权限，分为三组，每组三个字符：第一组表示拥有该文件的用户的权限（现在你理解这个了！），第二组表示拥有该文件的组的权限（现在你也理解这个了！），第三组表示所有其他访问者（例如其他用户和其他组）对该文件的权限。

这三组中的每个字符分别表示一种不同类型的权限：

- `r`：用户/组/其他可读取文件（或列出目录）
- `w`：用户/组/其他可修改文件（或在目录中创建/删除文件）
- `x`：用户/组/其他可将文件作为程序执行（或进入目录，例如使用 `cd`）
- `-`：无权限

对于上面的 `college_file`，`rw-r--r--` 权限项解码为：

- `r`：拥有该文件的用户（用户 `hacker`）可以读取它
- `w`：拥有该文件的用户（用户 `hacker`）可以写入它
- `-`：拥有该文件的用户（用户 `hacker`）**不能**执行它
- `r`：拥有该文件的组（组 `hacker`）中的用户可以读取它
- `-`：拥有该文件的组（组 `hacker`）中的用户**不能**写入它
- `-`：拥有该文件的组（组 `hacker`）中的用户**不能**执行它
- `r`：所有其他用户可以读取它
- `-`：所有其他用户**不能**写入它
- `-`：所有其他用户**不能**执行它

现在，让我们看看 `/flag` 的默认权限：

```console
hacker@dojo:~$ ls -l /flag
-r-------- 1 root root 53 Jul  4 04:47 /flag
hacker@dojo:~$
```

这里只设置了一个位：拥有该文件的用户（在本例中是 `root`）的 `r`（读）权限。拥有该文件的组（`root` 组）的成员以及所有其他用户都无权访问该文件。

你可能想知道，既然文件没有组访问权限，那些 `chgrp` 关卡是如何工作的。嗯，在那些关卡中，我以不同方式设置了权限：

```console
hacker@dojo:~$ ls -l /flag
-r--r----- 1 root root 53 Jul  4 04:47 /flag
hacker@dojo:~$
```

组有访问权限！这就是为什么对文件执行 `chgrp` 能让你读取它。

总之！与所有权一样，文件权限也可以更改。这通过 `chmod`（**ch**ange **mod**e，更改模式）命令完成。`chmod` 的基本用法是：

```sh
chmod [OPTIONS] MODE FILE
```

你可以通过两种方式指定 `MODE`：作为对现有权限模式的修改，或作为完全覆盖旧模式的新模式。

在本关中，我们将介绍前者：修改现有模式。`chmod` 允许你使用 `WHO+/-WHAT` 的模式格式调整权限，其中 `WHO` 是用户/组/其他，`WHAT` 是读/写/执行。例如，要为拥有文件的用户添加**读**访问权限，你可以指定模式 `u+r`。为组和其他（或所有模式）添加 `w` 和 `x` 访问权限也以相同方式指定。更多示例：

- `u+r`，如上所述，为用户权限添加读访问
- `g+wx` 为组权限添加写和执行访问
- `o-w` 移除其他用户的写访问
- `a-rwx` 移除用户、组和所有其他用户的所有权限

所以：

```console
root@dojo:~# mkdir pwn_directory
root@dojo:~# touch college_file
root@dojo:~# ls -l
total 4
-rw-r--r-- 1 root root    0 May 22 13:42 college_file
drwxr-xr-x 2 root root 4096 May 22 13:42 pwn_directory
root@dojo:~# chmod go-rwx *
root@dojo:~# ls -l
total 4
-rw------- 1 hacker root    0 May 22 13:42 college_file
drwx------ 2 root   root 4096 May 22 13:42 pwn_directory
root@dojo:~#
```

在本挑战中，你必须更改 `/flag` 文件的权限才能读取它！通常，你需要是文件所有者才能更改其权限，但在这个关卡中，我让 `chmod` 命令拥有全能权限，即使你是 `hacker` 用户，也可以 `chmod` 任何你想要的东西。这是终极力量。`/flag` 文件归属于 `root`，你无法更改这一点，但你可以让它可读。去解决它吧！

#### 可执行文件

到目前为止，你主要处理的是**读**权限。这很合理，因为你一直通过让 `/flag` 文件可读来读取它。在本关中，我们将探索执行权限。

当你调用一个程序（例如 `/challenge/run`）时，只有当你对该程序文件具有执行访问权限时，Linux 才会真正执行它。考虑：

```console
hacker@dojo:~$ ls -l /challenge/run
-rwxr-xr-x 1 root root    0 May 22 13:42 /challenge/run
hacker@dojo:~$ /challenge/run
Successfully ran the challenge!
hacker@dojo:~$
```

在这种情况下，`/challenge/run` 之所以能运行，是因为 `hacker` 用户可以执行它。由于该文件归属于 `root` 用户和 `root` 组，这要求在其他用户的权限上设置执行位。如果我们移除这些权限，执行就会失败！

```console
hacker@dojo:~$ chmod o-x /challenge/run
hacker@dojo:~$ ls -l /challenge/run
-rwxr-xr-- 1 root root    0 May 22 13:42 /challenge/run
hacker@dojo:~$ /challenge/run
bash: /challenge/run: Permission denied
hacker@dojo:~$
```

在本挑战中，`/challenge/run` 程序会给你 flag，但你必须先让它可执行！记住你的 `chmod`，让 `/challenge/run` 告诉你 flag！

#### 权限设置练习

除了像上一关那样添加和移除权限外，`chmod` 还可以直接整体设置权限，覆盖旧权限。这是通过使用 `=` 而不是 `-` 或 `+` 来完成的。例如：

- `u=rw` 设置用户的读写权限，并清除执行权限
- `o=x` 仅设置其他用户的可执行权限，清除读写权限
- `a=rwx` 为用户、组和其他用户设置读、写和执行权限！

但如果你想以不同方式更改用户权限和组权限呢？比如，你想为拥有文件的用户设置 `rw`，但只为拥有文件的组设置 `r`？你可以通过用 `,` 将多个模式链接到 `chmod` 来实现！

- `chmod u=rw,g=r /challenge/pwn` 将用户权限设为读写，组权限设为只读
- `chmod a=r,u=rw /challenge/pwn` 将用户权限设为读写，组和其他用户权限设为只读

此外，你可以用 `-` 将权限清零：

- `chmod u=rw,g=r,o=- /challenge/pwn` 将用户权限设为读写，组权限设为只读，其他用户权限设为无

请记住，出现在 `=` 之后的 `-` 与直接出现在 `u`、`g` 或 `o` 之后的 `-` 上下文不同（在后一种情况下，它会导致移除特定权限位，而不是移除所有权限）。

本关在上一关的基础上，要求进行更彻底的权限更改，你需要使用 `=` 和 `,` 链接来实现。祝你好运！

#### SUID 位

正如你在上一模块中探索的那样，在许多情况下，非 `root` 用户需要提升访问权限才能执行某些系统任务。系统管理员不可能在用户每次想做只有 `root`/`sudoers` 才能完成的任务时，都到场给他们密码。相反，“设置用户 ID”（SUID）权限位允许用户以程序文件所有者的身份运行程序。

这实际上正是让你运行的挑战程序能够读取 flag 的机制；在 pwn.college 之外，它也用于启用 `su`、`sudo` 等系统管理工具。带有 SUID 的文件权限看起来像这样：

```console
hacker@dojo:~$ ls -l /usr/bin/sudo
-rwsr-xr-x 1 root root 232416 Dec 1 11:45 /usr/bin/sudo
hacker@dojo:~$
```

代替可执行位的 `s` 部分表示该程序可**带 SUID** 执行。这意味着，无论哪个用户运行该程序（只要他们具有执行权限），程序都会以所有者用户（在本例中是 `root` 用户）的身份执行。

作为文件所有者，你可以使用 `chmod` 设置文件的 SUID 位：

```sh
chmod u+s [program]
```

但要小心！将 SUID 位赋予由 `root` 拥有的可执行文件，可能会给攻击者提供成为 `root` 的潜在攻击向量。你将在[程序滥用模块]中了解更多相关内容。

现在，我们将让你为 `/challenge/getroot` 程序添加 SUID 位，以便为你生成一个 `root` shell，让你自己 `cat` flag！
