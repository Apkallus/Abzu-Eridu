# 进程与作业

计算机执行软件来完成任务。在现代计算中，这些软件分为两类：*操作系统内核*（我们将在[稍后]学习）和*进程*，这里要讨论的是后者。Linux 启动时，会启动一个 *init*（initializer 的缩写）进程，它又启动一堆其他进程，这些进程再启动更多进程，直到最终你看到命令行 shell，它本身也是一个进程！当然，shell 会响应你输入的命令来启动进程。

在本模块中，我们将学习以多种令人兴奋的方式查看进程并与它们交互！

## 列出进程

首先，我们将学习使用 `ps` 命令列出正在运行的进程。根据你问谁，`ps` 要么代表“process snapshot”，要么代表“process status”，它会列出进程。默认情况下，`ps` 只列出你终端中运行的进程，老实说这不太有用：

```console
hacker@dojo:~$ ps
    PID TTY          TIME CMD
    329 pts/0    00:00:00 bash
    349 pts/0    00:00:00 ps
hacker@dojo:~$
```

在上面的示例中，我们有 shell（`bash`）和 `ps` 进程本身，这就是该特定终端上运行的全部内容。我们还看到每个进程都有一个数字标识符（*进程 ID*，即 PID），这是一个唯一标识 Linux 环境中每个运行进程的数字。我们还看到命令运行所在的终端（本例中为 `pts/0`），以及该进程到目前为止消耗的 *CPU 时间*总量（由于这些进程要求不高，它们甚至还没消耗 1 秒！）。

在大多数情况下，这就是默认 `ps` 会显示的全部内容。要让它有用，我们需要传入一些参数。

由于 `ps` 是一个非常古老的工具，其用法有点混乱。有两种指定参数的方式。

**“标准”语法：** 在这种语法中，你可以使用 `-e` 列出“每个”进程，使用 `-f` 获得“完整格式”输出，包括参数。这些可以合并为单个参数 `-ef`。

**“BSD”语法：** 在这种语法中，你可以使用 `a` 列出所有用户的进程，使用 `x` 列出不在终端中运行的进程，使用 `u` 获得“用户可读”的输出。这些可以合并为单个参数 `aux`。

这两种方法 `ps -ef` 和 `ps aux` 产生略有不同但可相互识别的输出。

`ps -ef` 和 `ps aux` 有许多共同点：两者都显示用户（`USER` 列）、PID、TTY、进程启动时间（`STIME`/`START`）、总消耗的 CPU 时间（`TIME`）以及命令（`CMD`/`COMMAND`）。`ps -ef` 还输出*父进程 ID*（`PPID`），即启动所涉进程的进程的 PID，而 `ps aux` 输出进程占用的系统总 CPU 和内存百分比。此外还有一堆其他内容，我们现在不深入。

> **注意：** `ps -ef` 和 `ps aux` 都会将命令列表截断到终端的宽度（这就是上面的示例在屏幕右侧对齐得如此整齐的原因）。如果你无法读取进程的完整路径，可能需要放大终端（或将输出重定向到某处以避免这种截断行为）！或者，你可以传入 `w` 选项*两次*（例如 `ps -efww` 或 `ps auxww`）来禁用截断。

## 终止进程

你已经启动了进程，查看了进程，现在你将学习*终止*进程！在 Linux 中，这使用名字颇具攻击性的 `kill` 命令完成。使用默认选项（本关卡只涉及这些），`kill` 会以给进程机会在消失前处理好事务的方式终止它。

假设你在另一个终端中启动了一个讨厌的 `sleep` 进程（`sleep` 是一个只是挂起命令行指定秒数的程序，本例中为 1337 秒），如下所示：

```console
hacker@dojo:~$ sleep 1337
```

我们如何摆脱它？你使用 `kill`，通过将进程标识符（`ps` 中的 `PID`）作为参数传入来终止它，如下所示：

```console
hacker@dojo:~$ ps -e | grep sleep
 342 pts/0    00:00:00 sleep
hacker@dojo:~$ kill 342
hacker@dojo:~$ ps -e | grep sleep
hacker@dojo:~$
```

现在，是时候终止你的第一个进程了！在本挑战中，只要 `/challenge/dont_run` 正在运行，`/challenge/run` 就会拒绝运行！你必须找到 `dont_run` 进程并 `kill` 它。如果你失败，`pwn.college` 将否认对你的任务知情。祝你好运。

## 中断进程

你已经学习了如何使用 `kill` 命令终止其他进程，但有时你只想摆脱堵塞终端的进程！幸运的是，终端为此有一个热键：`Ctrl-C`（例如，按住 `Ctrl` 键并按 `C`）会向等待终端输入的任何应用程序发送“中断”，通常这会导致应用程序干净地退出。

在这里试试！在你中断它之前，`/challenge/run` 会拒绝给你 flag。祝你好运！

## 终止行为异常的进程

有时，行为异常的进程会干扰你的工作。这些进程可能需要被终止……

在本挑战中，有一个诱饵进程占用着关键资源——位于 `/tmp/flag_fifo` 的命名管道（FIFO），就像在[练习管道]的 FIFO 挑战中一样，`/challenge/run` 想要将你的 flag 写入其中。你需要 `kill` 这个进程。

你的大致工作流程应该是：

1. 检查正在运行哪些进程。
2. 在列表中找到 `/challenge/decoy` 并弄清其进程 ID。
3. `kill` 它。
4. 运行 `/challenge/run` 获取 flag，而不被诱饵淹没（你不需要重定向其输出；它会自行写入 FIFO）。

祝你好运！

> **注意：** 即使终止了诱饵进程，你可能仍会看到一些诱饵 flag 出现。这是因为 Linux 管道是*带缓冲的*：概念上，它们有一段数据流经的长度，你可能在数据仍在管道中时终止了诱饵进程。已经进入管道的数据会继续流向另一端（你的 `cat`）。如果你等一秒钟，会看到诱饵停止，然后你可以运行 `/challenge/run` 并获胜！

## 挂起进程

你已经学习了用 `Ctrl-C` 中断进程，但还有不那么激烈的方法来收回终端！你可以用 `Ctrl-Z` 将进程*挂起*到后台。在本关卡中，我们将探索其工作方式，在下一关中，我们将弄清如何*恢复*这些挂起的进程！

本关卡的 `run` 希望看到另一个自身的副本正在运行，*并且使用同一个终端*。怎么做？使用终端启动它，然后挂起它，然后在第一个挂起时启动另一个副本！

## 恢复进程

通常，当你挂起进程时，你会在某个时候想恢复它们。否则为什么不直接终止它们呢？要恢复进程，你的 shell 提供了 `fg` 命令，这是一个内建命令，它会接收挂起的进程，恢复它，并将其放回终端前台。

去试试吧！本挑战的 `run` 需要你挂起它，然后恢复它。祝你好运！

## 后台运行进程

你已经用 `fg` 命令在*前台*恢复了进程。你也可以用 `bg` 命令在*后台*恢复进程！这将允许进程继续运行，同时把 shell 还给你，以便在此期间调用更多命令。

本关卡的 `run` 希望看到另一个自身的副本正在运行，*未被挂起*，并且使用同一个终端。怎么做？使用终端启动它，然后挂起它，然后用 `bg` 将其*后台化*，并在第一个在后台运行时启动另一个副本！

---

> **奥秘：** 如果你对更深层的细节感兴趣，可以看看如何查看挂起和后台化属性的区别！让我演示一下。首先，让我们挂起一个 `sleep`：

```console
hacker@dojo:~$ sleep 1337
^Z
[1]+  Stopped                 sleep 1337
hacker@dojo:~$
```

`sleep` 进程现在在后台*挂起*。我们可以通过使用 `-o` 选项启用 `stat` 列输出来用 `ps` 看到这一点：

```console
hacker@dojo:~$ ps -o user,pid,stat,cmd
USER         PID STAT CMD
hacker       702 Ss   bash
hacker       762 T    sleep 1337
hacker       782 R+   ps -o user,pid,stat,cmd
hacker@dojo:~$ 
```

看到那个 `T` 了吗？这意味着该进程因我们的 `Ctrl-Z` 而挂起。`bash` 的 `STAT` 列中的 `S` 意味着 `bash` 正在等待输入时睡眠。`ps` 列中的 `R` 意味着它正在积极运行，`+` 意味着它在前台！

看看我们在后台恢复 `sleep` 时会发生什么：

```console
hacker@dojo:~$ bg
[1]+ sleep 1337 &
hacker@dojo:~$ ps -o user,pid,stat,cmd
USER         PID STAT CMD
hacker       702 Ss   bash
hacker       762 S    sleep 1337
hacker      1224 R+   ps -o user,pid,stat,cmd
hacker@dojo:~$
```

砰！`sleep` 现在有了 `S`。它在睡眠时睡眠，但并未挂起！它也在*后台*，因此没有 `+`。

## 前台化进程

想象你有一个后台化的进程，你想再摆弄它一下。你怎么办？嗯，你可以像前台化挂起进程一样，用 `fg` 前台化一个后台化进程！本关卡将引导你完成。

## 启动后台进程

当然，你不必挂起进程来将其后台化：你可以一开始就将其后台启动！很简单；你只需在命令后附加 `&`，如下所示：

```console
hacker@dojo:~$ sleep 1337 &
[1] 1771
hacker@dojo:~$ ps -o user,pid,stat,cmd
USER         PID STAT CMD
hacker      1709 Ss   bash
hacker      1771 S    sleep 1337
hacker      1782 R+   ps -o user,pid,stat,cmd
hacker@dojo:~$ 
```

这里，`sleep` 正在后台积极运行，*未*挂起。现在轮到你练习了！将 `/challenge/run` 后台启动以获取 flag！

## 进程退出码

每个 shell 命令，包括每个程序和每个内建命令，在结束运行并终止时都会带有一个*退出码*。shell 或 shell 的用户（也就是你！）可以用它来检查进程是否成功完成了其功能（当然，这种判断取决于进程原本应该做什么）。

你可以使用特殊的 `?` 变量访问最近终止命令的退出码（别忘了在它前面加上 `$` 来读取其值！）：

```console
hacker@dojo:~$ touch test-file
hacker@dojo:~$ echo $?
0
hacker@dojo:~$ touch /test-file
touch: cannot touch '/test-file': Permission denied
hacker@dojo:~$ echo $?
1
hacker@dojo:~$
```

如你所见，成功的命令通常返回 `0`，失败的命令通常返回非零值，最常见的是 `1`，但有时是标识特定失败模式的错误码。

在本挑战中，你必须检索 `/challenge/get-code` 返回的退出码，然后以该错误码作为参数运行 `/challenge/submit-code`。祝你好运！
