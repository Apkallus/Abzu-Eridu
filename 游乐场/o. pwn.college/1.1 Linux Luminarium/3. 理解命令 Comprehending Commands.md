# 理解命令

本模块将向你介绍一些有用的 Linux 命令，它们会在你接下来的旅程中派上用场！这远非完整列表，我们会继续扩展本模块，但这些足以让你入门。

那么，废话不多说，让我们开始学习一些命令吧！

## `cat`：不是宠物，而是命令！

最重要的 Linux 命令之一是 `cat`。`cat` 最常用于读取文件，如下所示：

```console
hacker@dojo:~$ cat /path/to/file
Hello Hackers!
```

`cat` 会将多个文件连接（concatenate，名称由此而来）起来，如果提供多个参数。例如：

```console
hacker@dojo:~$ cat myfile
This is my file!
hacker@dojo:~$ cat yourfile
This is your file!
hacker@dojo:~$ cat myfile yourfile
This is my file!
This is your file!
hacker@dojo:~$ cat myfile yourfile myfile
This is my file!
This is your file!
This is my file!
```

最后，如果完全不提供参数，`cat` 将从终端输入读取并输出。我们将在后续挑战中探索这一点……

在本挑战中，我会将 flag 复制到你主目录（shell 启动时所在目录）中的 `flag` 文件。用 `cat` 去读它吧！

## 大海捞针式 `grep`

有时你可能用 `cat` 查看的文件太大。幸运的是，我们有 `grep` 命令来搜索所需内容！本挑战中我们将学习它。

`grep` 有很多用法，这里学习一种：

```console
hacker@dojo:~$ grep SEARCH_STRING /path/to/file
```

这样调用时，`grep` 会在文件中搜索包含 `SEARCH_STRING` 的文本行，并将它们打印到控制台。

本挑战中，我在 `/challenge/data.txt` 文件中放入十万行文本。用 `grep` 搜索 flag！

## 比较文件

当寻找相似文件之间的变化时，肉眼观察可能不是最高效的方法！这时 `diff` 命令就非常有用。

`diff` 逐行比较两个文件，并准确显示它们之间的差异。例如：

```console
hacker@dojo:~$ cat file1
hello
world
hacker@dojo:~$ cat file2
hello
universe
hacker@dojo:~$ diff file1 file2
2c2
< world
---
> universe
```

输出告诉我们第 2 行发生了变化（`2c2`），第一个文件中的 `world`（`<`）被第二个文件中的 `universe`（`>`）替换。

有时新增行时，你会看到类似：

```console
hacker@dojo:~$ cat old
pwn
hacker@dojo:~$ cat new
pwn
college
hacker@dojo:~$ diff old new
1a2
> college
```

这告诉我们，在第一个文件的第 1 行之后，第二个文件多了一行（`1a2` 表示“在 file1 的第 1 行之后，添加 file2 的第 2 行”）。

现在轮到你的挑战！`/challenge` 中有两个文件：

- `/challenge/decoys_only.txt` 包含 100 个假 flag
- `/challenge/decoys_and_real.txt` 包含全部 100 个假 flag 外加一个真 flag

使用 `diff` 找出这些文件之间的差异并获取 flag！

## 列出文件

到目前为止，我们一直告诉你该与哪些文件交互。但目录中可能包含许多文件（以及其他目录），我们不会总是告诉你它们的名称。你需要学会使用 `ls` 命令**列出**它们的内容！

`ls` 会列出作为参数提供给它的所有目录中的文件，如果未提供参数，则列出当前目录中的文件。观察：

```console

hacker@dojo:~$ ls

Documents  Music      Public    Videos
hacker@dojo:~$ ls /home/hacker
Desktop    Downloads  Pictures  Templates
Documents  Music      Public    Videos
hacker@dojo:~$
```

## 触碰文件

当然，你也可以*创建*文件！有几种方法可以做到，但这里我们看一个简单命令。你可以通过 `touch` 命令*触碰*文件来创建一个新的空白文件：

```console
hacker@dojo:~$ cd /tmp
hacker@dojo:/tmp$ ls
hacker@dojo:/tmp$ touch pwnfile
hacker@dojo:/tmp$ ls
pwnfile
hacker@dojo:/tmp$
```

就这么简单！本关中，请创建两个文件：`/tmp/pwn` 和 `/tmp/college`，然后运行 `/challenge/run` 获取 flag！

## 删除文件

文件无处不在。就像糖果包装纸一样，最终会太多。本关中，我们将学习清理！

在 Linux 中，你使用 `rm` 命令**删除**文件，如下所示：

```console
hacker@dojo:~$ touch PWN

hacker@dojo:~$ ls

hacker@dojo:~$ rm PWN
hacker@dojo:~$ ls
COLLEGE
hacker@dojo:~$
```

让我们练习。本挑战会在你的主目录中创建一个 `delete_me` 文件！删除它，然后运行 `/challenge/check`，它会确认你已删除该文件，然后给你 flag！

## 移动文件

你也可以用 `mv` 命令*移动*文件。用法很简单：

```console
hacker@dojo:~$ ls
my-file
hacker@dojo:~$ cat my-file
PWN!
hacker@dojo:~$ mv my-file your-file
hacker@dojo:~$ ls
your-file
hacker@dojo:~$ cat your-file
PWN!
hacker@dojo:~$
```

本挑战要求你将 `/flag` 文件移动到 `/tmp/hack-the-planet`（动手做吧）！注意，你*必须*使用 `mv` 命令，而不是其他方法（例如在 VSCode 中重命名文件）。完成后，运行 `/challenge/check`，它会检查并给你 flag。

## 复制文件

但如果你想保留原文件呢？你可以使用 `cp` 命令。用法与 `mv` 相同，但会保留源文件。命令是 `cp SOURCE DESTINATION`：第一个参数是现有文件，第二个是要创建副本的位置。

本挑战要求你将 `/flag` 文件复制到 `/tmp/hack-the-planet`（动手做吧）！完成后，运行 `/challenge/check`，它会检查并给你 flag。

---

> **注意：** 当 `cp` 的目标是目录时，`cp` 会使用源文件名将副本放入该目录中。对于本挑战，`/tmp/hack-the-planet` 应是复制文件本身的名称，而不是一个已存在的目录。

## 隐藏文件

有趣的是，`ls` 默认不会列出*所有*文件。Linux 有一个约定：以 `.` 开头的文件默认不会显示在 `ls` 以及一些其他上下文中。要用 `ls` 查看它们，需要带 `-a` 标志调用 `ls`，如下所示：

```console
hacker@dojo:~$ touch pwn
hacker@dojo:~$ touch .college
hacker@dojo:~$ ls
pwn
hacker@dojo:~$ ls -a
.college	pwn
hacker@dojo:~$
```

现在轮到你了！去找到 flag，它作为以点开头的文件隐藏在 `/` 中。

## 查找文件

现在我们知道如何列出、读取和创建文件。但如何找到它们呢？我们使用 `find` 命令！

`find` 命令接受描述搜索条件和搜索位置的可选参数。如果不指定搜索条件，`find` 会匹配每个文件。如果不指定搜索位置，`find` 会使用当前工作目录（`.`）。例如：

```console
hacker@dojo:~$ mkdir my_directory
hacker@dojo:~$ mkdir my_directory/my_subdirectory
hacker@dojo:~$ touch my_directory/my_file
hacker@dojo:~$ touch my_directory/my_subdirectory/my_subfile
hacker@dojo:~$ find
.
./my_directory
./my_directory/my_subdirectory
./my_directory/my_subdirectory/my_subfile
./my_directory/my_file
hacker@dojo:~$
```

指定搜索位置时：

```console
hacker@dojo:~$ find my_directory/my_subdirectory
my_directory/my_subdirectory
my_directory/my_subdirectory/my_subfile
hacker@dojo:~$
```

当然，我们也可以指定条件！例如，这里按名称过滤：

```console
hacker@dojo:~$ find -name my_subfile
./my_directory/my_subdirectory/my_subfile
hacker@dojo:~$ find -name my_subdirectory
./my_directory/my_subdirectory
hacker@dojo:~$
```

如果需要，你可以搜索整个文件系统！

```console
hacker@dojo:~$ find / -name hacker
/home/hacker
hacker@dojo:~$
```

现在轮到你了。我把 flag 隐藏在文件系统中的一个随机目录里。它仍然叫 `flag`。去找到它！

几点说明。首先，文件系统上还有其他名为 `flag` 的文件。如果你尝试的第一个文件没有真正的 flag，不要慌张。其次，文件系统中有很多地方普通用户无法访问。这些会导致 `find` 产生错误，但你可以忽略它们；我们不会把 flag 藏在那里！最后，`find` 可能需要一段时间；耐心点！

## 链接文件

如果你使用 Linux（或计算机）进行任何实际工作达到相当长的时间，你最终会遇到以下情况的某种变体：你希望两个程序访问同一份数据，但这些程序期望数据位于两个不同位置。幸运的是，Linux 为这个难题提供了解决方案：*链接*。

链接有两种：*硬*链接和*软*链接（也称为*符号*链接）。我们用类比来区分它们：

- **硬**链接就像你用多个地址来称呼你的公寓，而这些地址都直接指向同一个地方（例如 `Apt 2` 与 `Unit 2`）。
- **软**链接就像你搬家后，让邮政服务自动将邮件从旧地址转发到新地址。

在文件系统中，文件在概念上是该文件内容所在的地址。硬链接是索引该数据的另一个地址——对硬链接的访问和对原始文件的访问完全相同，因为它们会立即产生所需数据。软/符号链接则包含原始文件名。当你访问符号链接时，Linux 会意识到它是符号链接，读取原始文件名，然后（通常）自动访问该文件。大多数情况下，两种方式都会访问原始数据，但机制不同。

对大多数人来说，硬链接听起来更简单（比如，我在上面用一句话解释了它，而软链接用了两句），但它们有各种缺点和实现上的陷阱，这使得软/符号链接成为迄今为止更流行的替代方案。

在本挑战中，我们将学习符号链接（也称为 *symlink*）。符号链接使用 `ln` 命令创建，语法为 `ln -s TARGET LINK_NAME`。`TARGET` 是链接将指向的路径，`LINK_NAME` 是你要创建的新路径。例如：

```console
hacker@dojo:~$ cat /tmp/myfile
This is my file!
hacker@dojo:~$ ln -s /tmp/myfile /home/hacker/ourfile
hacker@dojo:~$ cat ~/ourfile
This is my file!
hacker@dojo:~$
```

你可以看到，访问符号链接会得到原始文件内容！在此示例中，`/tmp/myfile` 是目标，`/home/hacker/ourfile` 是链接名。

可以通过几种方法识别符号链接。例如，`file` 命令接受文件名并告诉你文件类型，它会识别符号链接：

```console
hacker@dojo:~$ file /tmp/myfile
/tmp/myfile: ASCII text
hacker@dojo:~$ file ~/ourfile
/home/hacker/ourfile: symbolic link to /tmp/myfile
hacker@dojo:~$
```

好，现在你来试试！本关中 flag 一如既往位于 `/flag`，但 `/challenge/catflag` 会改为读取 `/home/hacker/not-the-flag`。路径 `/home/hacker/not-the-flag` 是本挑战中的链接名。选择能让 `/challenge/catflag` 误以为在读取原文件并给你 flag 的目标！

---

> **警告：** 如果之前的实验在 `/home/hacker/not-the-flag` 留下了东西，请先删除它，以便 `ln` 能在那里创建符号链接。
