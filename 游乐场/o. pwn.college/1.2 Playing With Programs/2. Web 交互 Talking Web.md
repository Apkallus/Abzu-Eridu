# Talking Web

`HTTP`（超文本传输协议）是开放互联网的通用语言：Web 应用、服务器和客户端通过它进行交流。本模块将深入讲解构造、解码和操纵 `HTTP` 请求与响应的复杂技能。完成这段旅程后，你将不再完全依赖 Web 浏览器替你发起 `HTTP` 请求。你将掌握直接与 Web 服务器对话的技能，开启全新的可能性。

你将学习：

- `Headers`  
    携带请求或响应关键信息的元数据字段。

- `Paths`  
    你试图访问的特定位置或资源。

- `Arguments`  
    可以改变或决定请求行为的数据点。

- `Form Data`  
    从 Web 表单传输的数据。

- `JSON`  
    一种流行、轻量且人类可读的数据交换格式。

- `Cookies`  
    存储在用户计算机上的小型数据片段，对会话管理和跟踪至关重要。

- `Redirects`  
    Web 服务用于将浏览器从一个位置引导到另一个位置的方法。

## Commented Data

`HTTP` 是*超文本*传输协议。超文本这个名称来自 20 世纪末的技术乐观主义，它指的是携带额外数据的文本，这些数据说明文本*应该如何*被理解，而不仅仅是它意味着什么。在现代，这通过多种方式实现：`HTTP` 用于传输许多不同类型的资源，你的 Web 浏览器将它们组合起来，构建出你所看到并与之交互的网站。其中最古老的是超文本标记语言，也就是 `HTML`。

## HTTP Host Header (python)

不幸的是，现代互联网的大部分运行在少数几家公司的基础设施上，而这些公司运行的某个服务器可能负责为几十个不同域名提供网站。服务器如何决定提供哪个网站？`Host` 头部。

`Host` 头部是客户端（例如浏览器、curl 等）发送的*请求*头部，通常等于 `HTTP` 请求中输入的域名。当你访问 `https://pwn.college` 时，浏览器会自动将 `Host` 头部设置为 `pwn.college`，因此我们的服务器知道向你提供 `pwn.college` 网站，而不是其他东西。

到目前为止，你交互的挑战一直与 `Host` 无关。现在它们开始检查了。设置正确的 `Host` 头部并获取 flag！

## URL Encoding (netcat)

回想一下，`HTTP` 请求包含由空格分隔的字段？例如：`GET /solve HTTP/1.1`。如果路径（例如不是 `/solve`）内部有空格怎么办？这是很合理的情况，因为这些路径经常引用目录，而目录名中可能有空格！

如果放任不管，空格会破坏 `HTTP` 请求。考虑一个 `HTTP` 服务器试图理解 `GET /solve my challenge HTTP/1.1`。聪明的服务器也许能处理，但一个简单地一次读取一个单词的版本很可能会读到 `my` 而不是 `HTTP/1.1`，然后崩溃！

为了避免这种情况，URL 会使用 [URL Encoding](https://en.wikipedia.org/wiki/Percent-encoding) 进行*编码*。与你在 [Dealing with Data] 中看到的编码相比，这是一种简单的编码。任何棘手字符（例如空格）都只是进行十六进制编码，并在前面加上 `%`。当然，因为 `%` 因此本身也成了棘手字符，所以它也必须被编码。在上面的例子中，`/solve my challenge` 会变成 `/solve%20my%20challenge`，因为 ASCII 空格字符的十六进制值是 `0x20`。

总之，现在我们来练习。我们在端点中放了空格。你还能获取 flag 吗？

---

> **INFO:** 你会发现，使用 curl 时也需要对 URL 进行编码（不过我们不会强制你跳过这个圈），方式完全相同。然而，Python 的 requests 库会自动为你进行 urlencode。太有用了！

## JavaScript Redirects

在 Web 早期，`HTML` 虽然名为*超*文本，但相当静态。它描述布局，仅此而已。20 世纪 90 年代的某个时候，互联网的推动者们想：“如果网页能执行逻辑会怎样？”，于是 JavaScript 诞生了。

JavaScript 是一种编程语言，允许网页动态做出决定并执行操作。毫无疑问（而且不幸的是，因为它很糟糕），它是目前最重要的编程语言（不过幸运的是不是使用最多的），无论我们多么想避开它（我们提到它很糟糕了吗），在任何 Web 安全讨论中都必须考虑它。

`HTML` 通过 `<script>` 标签指定要执行的 JavaScript。这个标签告诉浏览器，标签内的内容是 JavaScript，浏览器会执行它。网上有很多关于如何编写 script 标签和 JavaScript 的资源，我们把这些资源的寻找留给你这位学习者作为练习。在这里，我们将练习一件非常具体的事情：使用 JavaScript 将浏览器重定向到另一个网页。

## Including JavaScript

JavaScript 在网页上下文中可以执行许多操作，因此可能导致意外情况和安全风险。你将在 Web Security 模块中探索其中一些情况，但我们会在这里打下基础。

在这一关，`/challenge/client` 不再打印网页，`/challenge/server` 也不再提供包含 flag 的 `HTML` 页面，而是提供一个 JavaScript 脚本，将全局 `flag` 变量设置为 flag 的值。你需要制作一个网页，将这个脚本*包含*到你的页面中（我们留给你自己查找相关文档——提示：涉及 `src`），然后创建另一个脚本以某种方式*外带*这个信息。外带是在所有者眼皮底下偷运敏感数据的艺术：在这个例子中，所有者就是 `/challenge/client` 和 `/challenge/server`。当然，在你页面上运行的 JavaScript 可以访问 `flag` 变量，但你需要以某种方式把它通信到外部世界。这可以通过几种不同方式完成，但最简单的方式可能是将客户端浏览器重定向（使用之前的 `window.location` 技巧！）到一个包含 flag 的 URL（类似于客户端在几关之前泄露给你那样），并让该请求发送到你可以看到 URL 日志的地方（例如 `/challenge/server` 的日志或你自己的 Web 服务器！）。

这听起来很多，但完全可行。我们的参考 HTML 解决方案文件只有 150 字节长！和之前一样，记住：你可以用自己的浏览器调试解决方案（并且可以在练习模式中以 root 身份运行它，以便能够包含 flag 脚本！）。

## HTTP (javascript)

现在，困难的部分开始了……通常，你需要外带的是网站上 JavaScript 可访问的其他数据，但你往往必须发起 `HTTP` 请求来检索它。在现代 JavaScript 中，`HTTP` 请求使用 `fetch()` 函数发起。它大致如下工作：

```javascript
fetch("http://google.com").then(response => response.text()).then(website_content => ???);
```

当然，`???` 是你要对网站内容执行的代码。这个 API 看起来如此疯狂，是因为 JavaScript 很疯狂，但也因为它实际上要解决一个困难问题。它必须在这样的环境中执行逻辑：网络错误、CPU 负载、笔记本电脑挂起和恢复、防火墙以及其他疯狂的事情都可能干扰它所依赖资源的加载和操作。上面的代码使用 JavaScript 的“promise”，这是一种复杂的编程模式，让你编写*将*在*尚未*可用的数据上执行的逻辑，并在数据最终可用时执行。`.then()` 是 promise 中指定最终执行内容的部分。这里，流程大致如下：

1. `fetch()` 返回一个 promise，并开始获取 `http://google.com`。这可能需要一段时间，可能永远不会成功，也可能立即成功。无论如何，它最初返回一个 `promise` 对象，该对象有一个 `then()` 成员函数，会在响应可用时运行。
2. 响应变为可用，承诺的代码执行。这段代码接收承诺的响应并调用 `response.text()`，它会检索 `http://google.com` 返回的*完整*文本内容。因为完整加载可能需要一段时间，所以这*也*返回一个 promise，*那个* promise 也有一个 `.then()` 方法，我们可以为其指定代码。
3. 最后，所有内容都可用，我们最终承诺的代码运行。这可以是任何操作，但对我们大多数目的而言，这里就是你像之前挑战中那样外带数据的地方。

这可能极其难以理解和调试。请准备好用练习模式下的 Firefox 调试。

在这一关，flag 不再被很好地包装在 JavaScript 中。它只是无聊的旧文本。你需要获取它并外带以得分。祝你好运！
