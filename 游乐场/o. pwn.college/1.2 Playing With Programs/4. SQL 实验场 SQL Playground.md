# SQL 游乐场

现代社会运行在互联网上，而互联网运行在数据库上。数据库保存着海量数据，从你的 pwn.college 分数（没错，我们有一个数据库！）到整个维基百科，再到不那么重要的事情，比如你的信用评分。只要你能描述出来，它就在某个数据库里。

数据库形态各异、大小不一，但可以说最常见、也绝对最*传统*的，是把数据条目存储在结构化表中。这些**结**构化表可以用一种专门的语言来**查**询，这种语言叫做结构化查询语言，即 `SQL`（通常读作“sequel”）。

SQL 的（误）用会导致各种潜在的安全问题，我们将在本平台的后续内容中探讨。现在，本模块将通过一系列挑战来教你（或者说，强迫你学习）SQL，这些挑战会让你接触到该语言中后续会变得相关的部分。

欢迎来到 SQL 游乐场。

#### SQL 查询

这个挑战将是你 SQL 之旅的起点。在这个挑战以及整个模块中，我们将使用一个叫做 [SQLite](https://sqlite.org/) 的 SQL 引擎。SQLite 是一个极其轻量的 SQL 引擎，它不使用复杂的 SQL 服务器进程来托管数据库，而是直接与数据库文件交互。这使得它非常适合用来做应用原型，我们在 pwn.college 的挑战中几乎所有 SQL 需求都用它，但你不会想把它用在比如生产网站上……在挑战文件（`/challenge/sql`）中，你会注意到我们通过 `TemporaryDB` 类使用了 SQLite。可以随意忽略那个类的内部实现——我们只是把它当作执行 SQL 查询并获取结果的包装器。请把注意力放在其余代码上！

这个挑战将从一条非常简单的查询开始。我们要学习的查询是 `SELECT`。你可以用 `SELECT` 来（😎）从数据库的表中*选择*数据。它的基本语法是 `SELECT what FROM where`，其中 `what` 和 `where` 是你指定的内容。`where` 通常是一个数据库表，而 `what` 是你希望查询获取的列。如果你不想操心要 `SELECT` 哪一列，可以写 `SELECT *`！

#### 过滤 SQL

任何非平凡的数据库都会有足够多的数据，以至于你必须对访问的内容保持*选择性*（🥁）。幸运的是，`SELECT` 查询可以用 `WHERE` 子句来过滤！这个挑战将要求你过滤数据，因为现在数据库里有很多垃圾数据！

这个挑战链接到了 WHERE 子句的 SQLite 文档，我们希望你去读一读。为了让你起步，TLDR 是：你可以在查询后附加 `WHERE condition`，其中 `condition` 是你指定的某个表达式，比如 `some_column < 10`（用于整数比较）或 `some_column = 'pwn'`（用于字符串比较）之类。

#### 基于表达式过滤

让我们进入更高级的过滤。在这个挑战中，我们去掉了 flag 标签，你需要基于 flag 数据的实际值来过滤！幸运的是，`SQLite`（以及所有 SQL 引擎）都提供了一些处理字符串的函数，你在这里会用到 `substr` 函数。`substr(some_column, start, length)` 从 `some_column` 列的 `start` 位置开始（第一个字符在位置 `1`，而不是像理智的语言那样从 `0` 开始）提取 `length` 个字符。你可以在查询接受表达式的任何地方使用它的结果，比如在 `WHERE` 子句中把结果值与字符串比较，就像上一个挑战那样！

#### SELECT 表达式

像 `substr` 这样的功能不只是用于过滤：你也可以 `SELECT` 这类表达式（替代或补充你通常指定列的位置）！当你不想（或者，在这个挑战中，无法获取）*全部*数据，而只想要对数据做某种计算的结果时，这非常方便。在这种情况下，挑战根本不会让你读取完整的 flag。你能一点一点地读取它吗？

#### 复合条件

到目前为止，我们的 `WHERE` 条件都相当简单。这个挑战通过向你的数据库注入诱饵数据，使其稍微复杂了一些。幸运的是，flag 标签回来了。

你需要*同时*基于 flag 标签和 flag 值进行过滤。类比其他编程语言，你可以用 `AND` 和 `OR` 这样的布尔运算符把条件表达式连接起来。构造一个强大的表达式，从诱饵中过滤出 flag！

#### 触及你的 LIMIT

你之前可以依靠 `WHERE` 子句把结果过滤到恰好一条，但在这次挑战中，我们拿掉了你用来过滤掉诱饵 flag 的 flag 标签！幸运的是，简单的 SQL 查询往往会按照数据插入数据库的顺序返回数据，而真正的 flag 是在诱饵 flag 之前插入的（但在一些垃圾数据之后）。你只需要用 `LIMIT` 把查询限制为 `1` 条结果，那条结果应该就是你的 flag！如果你需要，挑战中链接了 `LIMIT` 的文档！

#### 查询元数据

在实际的安全场景中，有时攻击者缺少某些信息，比如他们想查询的表的名称！幸运的是，每个 SQL 引擎都有某种方式来查询关于表的*元数据*（不过令人困惑的是，每个引擎的做法都不同！）。SQLite 使用一个特殊的 `sqlite_master` 表，在其中存储关于所有其他表的信息。你能找出包含 flag 的表的名称，并查询它吗？
