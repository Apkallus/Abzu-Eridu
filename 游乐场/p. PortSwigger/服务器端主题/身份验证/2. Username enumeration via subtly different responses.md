# 实验：通过细微不同的响应进行用户名枚举

本实验存在细微的用户名枚举和密码暴力破解攻击漏洞。它有一个具有可预测用户名和密码的账户，可以在以下单词列表中找到：

-   [候选用户名](https://portswigger.net/web-security/authentication/auth-lab-usernames)
-   [候选密码](https://portswigger.net/web-security/authentication/auth-lab-passwords)


为了解决本实验，请枚举一个有效的用户名，暴力破解该用户的密码，然后访问其账户页面。

## 步骤

使用不存在的凭据登录
- 请求

    ```http
    POST /login HTTP/2

    username=test_username&password=test_password
    ```

- 响应

    ```http
    HTTP/2 200 OK
    Content-Type: text/html; charset=utf-8
    X-Frame-Options: SAMEORIGIN
    Content-Length: 3335

    <body>
    <p class=is-warning>
        Invalid username or password.
    </p>
    ```

在攻击器使用字典对用户名进行爆破
- 响应均为200
- 将长度不一致的响应发送到对比器观察
    ```http
    HTTP/2 200 OK
    Content-Type: text/html; charset=utf-8
    X-Frame-Options: SAMEORIGIN
    Content-Length: 3356

    <body>
    <!-- -->
    <p class=is-warning>
        Invalid username or password.
    </p>
    ```
- 推测：一定不存在的凭据无额外注释 `<!-- -->`，可能存在的凭据拥有
    - 然而题目揭示这里仅拥有1个可预测账户，多次尝试后发现：使用同一凭证进行多次提交，注释似乎随机出现。并非账户名是否有效的触点

- 继续观察：设置观察点到无效提示元素 `<p class=is-warning></p>` 内
    - 其中一个账户的提示末尾不拥有 `.`
        ```html
        <p class=is-warning>
            Invalid username or password 
        </p>
        ```
        - 即，差异在于
            - `password </p>`
            - `password.</p>`

使用独特账户名继续在攻击器对密码字段爆破
- 最终得到独特的 302 响应
- 设置 cookie 到浏览器后成功登录
