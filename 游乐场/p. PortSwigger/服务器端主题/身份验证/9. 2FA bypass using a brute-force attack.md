# 实验：使用暴力破解攻击绕过 2FA

本实验的双因素认证存在暴力破解漏洞。你已经获得了有效的用户名和密码，但无法访问用户的 2FA 验证码。为了解决本实验，请暴力破解 2FA 代码并访问 Carlos 的账户页面。

受害者凭据：`carlos:montoya`

> **注意**
> 由于验证码会在你运行攻击时重置，你可能需要重复此攻击几次才能成功。这是因为新代码可能是你当前的 Intruder 攻击已经尝试过的数字。

> **提示**
> 你需要将 Burp 宏与 Burp Intruder 结合使用来解决此实验。有关宏的更多信息，请参阅 [Burp Suite 文档](https://portswigger.net/burp/documentation/desktop/settings/sessions)。精通 Python 的用户可能更喜欢使用可从 BApp 商店获取的 Turbo Intruder 扩展

## 步骤

执行普通登录步骤
1. 访问凭据端点
    ```http
    GET /login HTTP/2
    ```

2. 提交凭据
    ```http
    POST /login HTTP/2
    Cookie: session=jwYRtHDcHGmjMUqX3iNm9tsKckToGEbt

    csrf=Ym0kkcFXr2HaBhP5BMGGiLMyFUXklqL6&username=carlos&password=montoya
    ```

3. 访问验证码端点
    ```http
    GET /login2 HTTP/2
    ```

4. 提交验证码
    ```http
    POST /login2 HTTP/2
    Cookie: session=7M3fsCGWkIdIQVUmZXmATIa5p8zGoYHQ

    csrf=ys6dqmvF1na51VjPO4NqvKEVlNVc7ewW&mfa-code=1202
    ```

- 测试发现2次验证码错误后返回凭据端点

录制宏普通流程宏，以包含步骤中的 csrf 令牌
- 宏的使用方式：
    - 录制全4步宏
        - 设置宏为后置宏，在攻击器中对任意页面进行 null 载荷攻击以触发登录流程宏执行
    - 录制前3步宏
        - 设置宏为前置宏，在攻击器中设置第4步的提交验证码。burp 将自动在第4步中应用之前步骤得到的 cookie 与 csrf 令牌
- 设置单线程
- 持续爆破直到 302 响应
    - 将花费很长时间，设置宏的应用范围到当前 lab 域名以同时进行其他 lab

- 得到 302 响应后，关闭宏，设置 cookie 到重复器或浏览器，成功以目标用户身份登录
