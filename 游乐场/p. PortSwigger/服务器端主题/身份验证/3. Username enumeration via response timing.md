# 实验：通过响应时间进行用户名枚举

本实验存在利用其响应时间进行用户名枚举的漏洞。为了解决本实验，请枚举一个有效的用户名，暴力破解该用户的密码，然后访问其账户页面。

-   你的凭据：`wiener:peter`
-   [候选用户名](https://portswigger.net/web-security/authentication/auth-lab-usernames)
-   [候选密码](https://portswigger.net/web-security/authentication/auth-lab-passwords)


> **提示**
> 为了增加挑战性，本实验还实现了一种基于 IP 的暴力破解保护。但是，这可以通过操纵 HTTP 请求头轻松绕过。

## 步骤

尝试多次登录，探测爆破保护
- 多次失败登录后，服务器响应
    ```html
    <p class=is-warning>
    You have made too many incorrect login attempts. Please try again in 30 minute(s).
    </p>
    ```
    - 拥有尝试次数限制，之后尝试使用正确凭据登录仍无法解除限制

- 使用 `授权与访问控制 - 基于位置的访问控制` 小节中的 IP 地址混淆
    - 测试几个头部后，发现成功解除限制的头部 `X-Forwarded-For` 

解除爆破速率限制后继续查看响应时间差异
- 尝试正确与错误用户名，时间差异很小
    - 均为 180 ms

- 尝试增加密码长度
    `username=wiener&password=aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa`
    - 1000 ms

- 使用长密码成功增加应用程序处理时长，成功创造可用触点

尝试爆破用户名
- 发送到攻击器使用平行模式，头部的 IP 覆盖字段设置数字递增，用户名字段设置字典
    ```http
    X-Forwarded-For: §10000§

    username=§wiener§&password=aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa
    ```
    - 不同于集束炸弹模式的所有组合。平行模式仅平行对应载荷节，直到其中一个载荷节耗尽载荷

- 得到一个拥有与 wiener 响应时长接近的 hit 触点

尝试爆破目标用户密码
- 仍然使用平行模式，加载密码字典对密码进行爆破
    ```http
    X-Forwarded-For: §10300§

    username=apple&password=§test§
    ```
    - ip 速率限制包含多次尝试，此处可继续使用之前平行交叉模式的数字段

- 得到 302 响应，设置 cookie 到浏览器后成功登录
