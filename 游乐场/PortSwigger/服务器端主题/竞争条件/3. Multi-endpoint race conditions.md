# 实验室：多端点竞争条件

本实验室的购买流程中存在一个竞争条件，使你能够以非预期的价格购买商品。

要解决本实验室，请成功购买一件 **Lightweight L33t Leather Jacket**。

你可以使用以下凭据登录自己的账户：`wiener:peter`。

> **注意**
> 解决本实验室需要 Burp Suite 2023.9 或更高版本。

> **提示**
> 实验时，建议先购买礼品卡，因为之后可以兑换，避免商店信用额度耗尽。

## 步骤

侦察
- 添加商品到购物车
    ```http
    POST /cart HTTP/2
    Host: id.web-security-academy.net
    Cookie: session=QsYdCLl5jtPTVZdUzqqhrS8Wi9JYTIeA

    productId=2&redir=PRODUCT&quantity=1
    ```

- 确认购物车内容
    ```http
    POST /cart/checkout HTTP/2
    Host: id.web-security-academy.net
    Cookie: session=QsYdCLl5jtPTVZdUzqqhrS8Wi9JYTIeA

    csrf=WYRmdVAQYX4O21hdrdz898Vvo5XJBHq8
    ```

- 资金不足响应
    ```http
    HTTP/2 303 See Other
    Location: /cart?err=INSUFFICIENT_FUNDS
    X-Frame-Options: SAMEORIGIN
    Content-Length: 0
    ```

探测，探测延迟来源是否为网络延迟
- 确认并行单包延迟
    - 发送添加购物车、确认购物车请求到重复器，设置两个请求为并行单包组，测试几次延迟
- 确认顺序单连接延迟
    - 添加无关请求到组的第一项，并设置为顺序单连接，测试几次延迟
- 观察：顺序单连接的后续请求延迟降低，且时间接近
- 分析：此处的延迟为网络延迟，可继续进行并行单包攻击

批量兑换礼品卡
- 手动兑换一次礼品卡
- 将请求发送到攻击器
- 设置礼品卡参数为暴破点
- 在账户页面复制所有礼品卡，并粘贴到攻击器载荷
- 进行暴破以兑换所有礼品卡

并行单包攻击探测
- 添加1件礼品卡到购物车
- 发送添加购物车、确认购物车请求到重复器，设置并行单包攻击
- 多次尝试，发现最终订单页面出现多于添加数量的礼品卡兑换码
    - 此处 lab 限制可显示，但无法兑换多出的礼品卡，并非竞争条件失败
    
实行并行单包攻击
- 修改并行单包组中的商品从礼品卡到目标商品
- 重复步骤：
    - 添加礼品卡到购物车，确保购物车非空
    - 执行并行单包攻击，尝试在结算过程中添加目标商品
    - 若失败，移除目标商品
