# OWASP 云安全测试指南

**云安全测试指南（CSTG）** 是一份全面、厂商中立的云环境安全测试手册。它面向渗透测试人员、云与平台工程师、安全架构师、检测工程师和审计人员——任何需要评估或防御主流云提供商上运行的基础设施的人。

云提供商发布和变更服务的速度，超过任何单一团队能够跟踪的速度，而每一项新的托管服务都会带来自己的身份模型、网络暴露面和滥用路径。传统的网络与应用测试方法无法捕获这些特定于云提供商的风险：S3 存储桶策略、权限过大的 IAM 角色、附加到虚拟机的托管标识，或可写的部署存储桶，都不是端口扫描或 Web 代理能够发现的。CSTG 的存在就是为了以结构化、可重复、针对特定云提供商的测试方法填补这一空白。

## CSTG 的独特之处

- **攻击与防御并重。** 每个技术页面不仅记录如何枚举和利用弱点，还记录该弱点在提供商日志中留下的**检测**痕迹，以及关闭该弱点的具体**修复**措施。无论蓝队加固云资产，还是测试人员攻击云资产，本指南都同样有用。
- **感知访问权限。** 云评估受测试人员所获访问权限的限制——从匿名外部位置、单个泄露凭证、只读审计角色到高权限主体。每个页面都会声明其假设的访问级别，因此可以根据现有凭证实际可测试的范围来界定评估工作。
- **原子化且结构化。** 内容按每个提供商的**阶段 × 服务矩阵**组织，每个服务和测试阶段都有一个自描述页面。这使指南易于导航、贡献，也便于以程序化方式使用。
- **全面。** 目标是记录每项服务在真实世界中的完整技术集——枚举命令、真正重要的错误配置，以及随之而来的权限提升、横向移动、后利用和持久化路径。

## 指南如何组织

每个提供商都划分为多个测试阶段，而在每个阶段内，原子单元是一个单独的服务页面：

| 阶段 | 它回答的问题 |
| --- | --- |
| **基本信息** | 该提供商的身份、访问和资源模型如何运作？ |
| **未认证 / 外部** | 无凭证的攻击者能接触到哪些暴露面？ |
| **服务（枚举）** | 使用有效凭证时，部署了什么以及如何配置？ |
| **权限提升** | 低权限主体如何获得更多访问权限？ |
| **横向移动** | 访问权限如何在服务、账户之间移动，或移动到本地环境？ |
| **后利用** | 攻击者利用已获得的访问权限能做什么？ |
| **持久化** | 如何建立并隐藏持久访问？ |

本指南中最鲜明的边界是**未认证测试与已认证测试**，它反映了任何云评估中最重要的一个问题：*我们一开始拥有什么访问权限？*

每个页面都遵循固定结构——摘要、前提条件、枚举、错误配置与发现、利用、检测与日志记录、修复与加固、工具、参考资料——并带有机器可读的 frontmatter（提供商、服务、阶段、所需访问权限、所需权限）。有关编写格式和访问层级定义，请参见 [STRUCTURE.md](STRUCTURE.md)。

## 提供商指南

### Amazon Web Services（AWS）
身份（IAM/STS）、存储（S3、EBS）、计算（EC2、Lambda、ECS/EKS、ECR）、数据（RDS、DynamoDB）、应用与集成（API Gateway、SNS/SQS、Cognito）、基础设施即代码（CloudFormation）、机密与密钥（Secrets Manager、SSM、KMS），以及日志记录/监控（CloudTrail）。

### Microsoft Azure
身份（Entra ID、RBAC、托管标识）、存储（存储账户）、计算（虚拟机、AKS）、应用（App Service、Functions、Logic Apps）、自动化（自动化账户、ARM 模板）、机密与密钥（Key Vault），以及网络。

### Google Cloud Platform（GCP）
身份（IAM、服务账号）、存储（Cloud Storage）、计算（Compute Engine、GKE、Cloud Run、Cloud Functions）、数据（Cloud SQL）、构建与集成（Cloud Build、Pub/Sub）、机密与密钥（Secret Manager、KMS），以及 Workspace 转向。

### 托管应用平台（PaaS / BaaS）
这些平台服务的安全模型基于 API 密钥、令牌和应用层控制，而非基础设施 IAM。它们的阶段也相应调整。

- **Supabase**——anon 与 `service_role` 密钥模型、自动生成的 PostgREST API、PostgreSQL 行级安全（RLS），以及 Auth、Storage、Edge Functions。
- **Vercel**——访问令牌与团队角色、环境变量机密、部署保护与预览部署，以及无服务器 / 边缘函数。

## 使用指南

1. 确定本次评估可用的**访问权限**（提供商、凭证形式、权限级别、范围）——这决定了涉及哪些阶段和页面。
2. 按顺序完成各阶段：了解平台，测试外部攻击面，然后（在拥有凭证的情况下）进行枚举、提权、横向移动，并评估后利用与持久化。
3. 对每项发现，使用**检测与日志记录**
