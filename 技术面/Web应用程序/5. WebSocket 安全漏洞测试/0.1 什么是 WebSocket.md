# 什么是 WebSocket？

WebSocket 是一种通过 HTTP 发起的双向全双工通信协议。它们常用于现代 Web 应用程序中，用于流式数据传输和其他异步流量。

在本节中，我们将解释 HTTP 与 WebSocket 之间的区别，描述 WebSocket 连接是如何建立的，并概述 WebSocket 消息的格式。

## HTTP 与 WebSocket 的区别是什么？

Web 浏览器与网站之间的大多数通信都使用 HTTP。在 HTTP 中，客户端发送请求，服务器返回响应。通常，响应会立即返回，事务随即完成。即使网络连接保持打开状态，它也将用于单独的请求-响应事务。

一些现代网站使用 WebSocket。WebSocket 连接通过 HTTP 发起，并且通常是长连接。消息可以在任意时刻双向发送，本质上并非事务性的。连接通常会保持打开和空闲状态，直到客户端或服务器准备发送消息。

WebSocket 在需要低延迟或服务器主动推送消息的场景中尤其有用，例如金融数据的实时推送。

## WebSocket 连接是如何建立的？

WebSocket 连接通常使用客户端 JavaScript 创建，如下所示：

```javascript
var ws = new WebSocket("wss://normal-website.com/chat");
```

> **注意**
> `wss` 协议通过加密的 TLS 连接建立 WebSocket，而 `ws` 协议则使用未加密的连接。

为了建立连接，浏览器和服务器通过 HTTP 执行 WebSocket 握手。浏览器发出如下 WebSocket 握手请求：

```http
GET /chat HTTP/1.1
Host: normal-website.com
Sec-WebSocket-Version: 13
Sec-WebSocket-Key: wDqumtseNBJdhkihL6PW7w==
Connection: keep-alive, Upgrade
Cookie: session=KOsEJNuflw4Rd9BDNrVmvwBF9rEijeE2
Upgrade: websocket
```

如果服务器接受连接，它将返回如下 WebSocket 握手响应：

```http
HTTP/1.1 101 Switching Protocols
Connection: Upgrade
Upgrade: websocket
Sec-WebSocket-Accept: 0FFP+2nmNIf/h+4BP36k9uzrYGk=
```

此时，网络连接保持打开状态，可用于双向发送 WebSocket 消息。

> **注意**
> WebSocket 握手消息的几个特点值得注意：
> - 请求和响应中的 `Connection` 和 `Upgrade` 头表明这是一次 WebSocket 握手。
> - `Sec-WebSocket-Version` 请求头指定了客户端希望使用的 WebSocket 协议版本，通常为 `13`。
> - `Sec-WebSocket-Key` 请求头包含一个 Base64 编码的随机值，应在每次握手请求中随机生成。
> - `Sec-WebSocket-Accept` 响应头包含对 `Sec-WebSocket-Key` 请求头中的值与协议规范中定义的特定字符串进行拼接后计算出的哈希值。这样做是为了防止由配置错误的服务器或缓存代理引起的误导性响应。

## WebSocket 消息长什么样？

一旦 WebSocket 连接建立，客户端或服务器可以异步地双向发送消息。

一条简单的消息可以通过客户端 JavaScript 从浏览器发送，如下所示：

```javascript
ws.send("Peter Wiener");
```

原则上，WebSocket 消息可以包含任何内容或数据格式。在现代应用中，通常使用 JSON 在 WebSocket 消息中传输结构化数据。

例如，一个使用 WebSocket 的聊天机器人应用程序可能会发送如下消息：

```json
{"user":"Hal Pline","content":"I wanted to be a Playstation growing up, not a device to answer your inane questions"}
```
