# 信息泄露漏洞

信息搜集：解析目标应用程序并初步了解其运行机制的各种技巧，包括以大体上不会对应用程序造成危害的方法与其交互，将应用程序的内容与功能进行分类，判定它使用的技术并确定主要的攻击面。

信息泄露：在实际攻击的应用程序中提取出更多信息，主要包括以出人意料和恶意的方式与应用程序进行交互，利用应用程序的反常行为提取出有价值的信息。如果取得成功，攻击者就可以通过这种攻击获取用户证书之类的敏感数据，深入了解某种错误条件并据此调整攻击方向，或者发现应用程序所使用技术的更多细节，同时解析应用程序的内部结构与功能。

## 什么是信息泄露？

信息泄露（也称信息泄漏）是指网站在无意中向用户泄露敏感信息。根据上下文的不同，网站可能向潜在攻击者泄露各类信息，包括：

- 其他用户的数据，例如用户名或财务信息
- 敏感的商务或业务数据
- 关于网站及其基础设施的技术细节

泄露敏感的用户数据或业务数据的危险显而易见，但技术信息的泄露有时同样严重。尽管其中某些信息用途有限，但它可能成为暴露额外攻击面的起点，而该攻击面可能包含其他有价值的漏洞。你能够收集到的信息，甚至可能成为构建复杂、高严重性攻击时所需的最后一块拼图。

有时，敏感信息可能被粗心地泄露给那些只是以正常方式浏览网站的用户。但更常见的情况是，攻击者需要通过以非预期或恶意的方式与网站交互，来诱使信息泄露。然后，他们会仔细研究网站的响应，以尝试识别有趣的行为。

### 信息泄露的示例

以下是一些基本信息泄露的例子：

- 通过 `robots.txt` 文件或目录列表，暴露隐藏目录的名称、结构及其内容
- 通过临时备份文件提供源代码文件的访问
- 在错误消息中明确提及数据库表名或列名
- 不必要地暴露高度敏感的信息，例如信用卡详细信息
- 在源代码中硬编码 API 密钥、IP 地址、数据库凭据等
- 通过应用程序行为的细微差异，暗示资源或用户名的存在或缺失

在本主题中，你将学习如何发现和利用其中一些示例以及更多内容。

## 信息泄露漏洞是如何产生的？

信息泄露漏洞可能以无数种方式出现，但大致可归为以下几类：

- **未能从公共内容中移除内部内容**。例如，开发人员在标记中的注释有时会在生产环境中对用户可见。
- **网站及相关技术的不安全配置**。例如，未禁用调试和诊断功能，有时会给攻击者提供有用的工具来获取敏感信息。默认配置也可能使网站容易受到攻击，例如显示过于详细的错误消息。
- **应用程序的设计和行为存在缺陷**。例如，如果网站在不同错误状态下返回不同的响应，攻击者也可以利用这一点来[枚举敏感数据](https://portswigger.net/web-security/authentication/password-based#username-enumeration)，例如有效的用户凭据。

## 信息泄露漏洞的影响是什么？

信息泄露漏洞的影响既有直接的也有间接的，具体取决于网站的用途以及攻击者能够获取何种信息。在某些情况下，仅泄露敏感信息本身就可能对相关方产生严重影响。例如，在线商店泄露客户信用卡详细信息，很可能导致严重后果。

另一方面，泄露技术信息（例如目录结构或正在使用的第三方框架）可能几乎没有直接影响。然而，在不当的人手中，这可能是构建多种其他漏洞利用所需的关键信息。此时的严重性取决于攻击者能够利用这些信息做些什么。

### 如何评估信息泄露漏洞的严重性

尽管最终影响可能非常严重，但只有在特定情况下，信息泄露本身才算得上是高严重性问题。在测试过程中，技术信息的泄露通常只有在你能够演示攻击者如何利用它造成危害时才有意义。

例如，知道某个网站正在使用特定版本的框架，如果该版本已完全修补，则用途有限。但若该网站使用的是包含已知漏洞的旧版本，则这一信息变得至关重要。此时，实施毁灭性攻击可能就像应用公开已知的漏洞利用一样简单。

当你发现潜在敏感信息被泄露时，运用常识很重要。很可能在你测试的许多网站上，都可以通过多种方式发现细微的技术细节。因此，你的主要关注点应是泄露信息的实际影响和可利用性，而不仅仅是将其作为孤立问题来看待。明显的例外情况是，泄露的信息本身非常敏感，足以单独引起重视。

## 如何防范信息泄露漏洞

由于信息泄露可能以多种方式发生，完全预防颇为棘手。不过，你可以遵循一些通用最佳实践，以降低此类漏洞出现在自己网站上的风险。

- 确保参与网站制作的所有人员都充分了解哪些信息被视为敏感信息。有时看似无害的信息，对攻击者的用处可能远超人们的认知。强调这些风险有助于确保你的组织总体上更安全地处理敏感信息。
- 在 QA 或构建流程中，对任何代码进行潜在信息泄露的审计。自动化某些相关任务（例如删除开发者注释）应相对容易。
- 尽可能使用通用的错误消息，不要不必要地向攻击者提供有关应用程序行为的线索。
- 仔细检查生产环境中是否已禁用任何调试或诊断功能。
- 确保你完全了解所实施的任何第三方技术的配置设置及其安全影响。花时间调查并禁用你实际上不需要的任何功能和设置。
