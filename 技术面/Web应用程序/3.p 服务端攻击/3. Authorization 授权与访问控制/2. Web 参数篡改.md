# Web 参数篡改

由于概念上的重叠，许多研究人员将 Web 参数篡改和 IDOR 互换使用。但我倾向于区分它们。

IDOR 通常涉及操纵参数以未经授权访问或修改对象。相比之下，Web 参数篡改针对的是操纵参数以改变应用程序行为，例如绕过身份验证或禁用特定安全功能。虽然两种漏洞都涉及参数操纵，但其结果和影响不同。例如，绕过身份验证或更改安全设置是 Web 参数篡改的典型示例。

为了说明，让我们回顾最近一次渗透测试中的发现。在一次评估中，我们遇到了允许用户更改个人资料设置（如切换双因素认证或更新密码）的功能。应用程序要求用户在做出这些更改之前输入当前密码。

在输入错误密码并监控服务器响应后，我们注意到应用程序返回 `false` 值，表示密码输入错误。

有趣的是，在拦截响应中手动将响应从 `false` 改为 `true`，使我们无需正确密码即可更改双因素认证设置。随后，界面反映“双因素认证”设置现已可访问并可更改。
