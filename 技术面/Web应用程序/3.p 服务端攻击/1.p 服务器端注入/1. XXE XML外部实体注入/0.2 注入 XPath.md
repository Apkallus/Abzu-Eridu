# 注入XPath

如果Web应用程序将数据保存在 XML 文档中，那么它们可能使用 XPath 访问数据，以响应用户提交的输入。正如关系数据库通过 SQL 语言访问一样，XML 数据库使用 XPath 作为其标准查询语言。

XPath（XML路径语言）是一种用于导航 XML 文档并从中获取数据的解释型语言。XPath 使用路径标识符（类似于 URL）通过层级结构来导航 XML 文档。

如果这个输入未经任何过滤或净化就插入到 XPath 查询中，攻击者就通过控制查询来破坏应用程序的逻辑，或者获取未获授权访问的数据。

通常，XML文档并不是保存企业数据的首选工具。但是，它们常常被用于保存可根据用户输入获取的应用程序配置数据。小型应用程序也使用它们保存简单的信息，如用户证书、角色和权限。

在一些应用程序中，用户提交的数据可被直接嵌入到 XPath 查询中，查询的结果可能在应用程序的响应中返回，或者用于决定应用程序某些方面的行为。

由于从概念角度看，XPath 在目的和应用上与 SQL 非常相似，一个有趣的结果是 XPath 注入攻击遵循与 [SQL 注入] 攻击相同的逻辑。与 SQL 不同，XPath 注入攻击，没有 ACL 强制执行，于是我们的查询访问 XML 文档的每一部分。


## 语法速查

- `/` 根节点
- `//` 相对路径
- `/直接子元素` 根节点的直接子元素
- `[...]` 选取节点集
    - `[position()=1]` `[1]`
        节点集的第一个元素
- `元素=输入值` 元素的值与输入值是否匹配
- `and` `or` 逻辑符号
- `|` 合并节点集
- `""` 空字符串
- `name(/标签)`
    标签名称

- `attribute::属性名` `@属性名`
    标签属性

向下路径导航
- `child::*` `*`
    选择所有“标签”子节点
- `child::text()` `text()`
    选择所有“文本”子节点
- `child::node()` 
    选择“全部”子节点,无论其节点类型如何（包含文本节点）

向上路径导航
- `parent::node()` `..` 
    父节点

横向路径导航
- `following-sibling::标签` 下一个兄弟标签
- `preceding-sibling::标签` 上一个兄弟标签


SQL 差异
- 与SQL注入一样，注入一个数字值时不需要单引号。
- 与SQL查询不同，XPath查询中的关键字区分大小写，XML文档中的元素名也区分大小写。

## XPath 条件响应注入测试

[XPath 攻击模式最早由 Amit Klein 发表](https://dl.packetstormsecurity.net/papers/bypass/Blind_XPath_Injection_20040518.pdf)，与通常的 SQL 注入非常相似，促使应用程序根据攻击者指定的条件以不同的方式做出响应。

这种行为差异可用于测试任何特殊条件的真假，因此可通过它一次一个字节地提取出任意信息。与SQL一样，XPath语言也包含一个子字符串函数 `substring`，可用它一次一个字符地测试一个字符串的值。

为了初步了解这个问题，让我们设想一个管理应用程序身份验证的登录页面，用户必须在该页面输入其用户名和密码。假设我们的数据库由以下 XML 文件表示：

```xml
<?xml version="1.0" encoding="ISO-8859-1"?>
<users>
    <user>
        <username>gandalf</username>
        <password>!c3</password>
        <account>admin</account>
    </user>
    <user>
        <username>Stefan0</username>
        <password>w1s3c</password>
        <account>guest</account>
    </user>
    <user>
        <username>tony</username>
        <password>Un6R34kb!e</password>
        <account>guest</account>
    </user>
</users>
```

返回用户名为 `gandalf` 且密码为 `!c3` 的账户的 XPath 查询如下：

`string(//user[username/text()='gandalf' and password/text()='!c3']/account/text())`

如果应用程序未正确过滤用户输入，测试人员将能够注入 XPath 代码并干扰查询结果。例如，测试人员输入以下值：

```text
Username: ' or '1' = '1
Password: ' or '1' = '1
```

看起来很熟悉，使用这些参数，查询变为：

`string(//user[username/text()='' or '1' = '1' and password/text()='' or '1' = '1']/account/text())`

与常见的 SQL 注入攻击一样，我们创建了一个始终计算为真的查询，这意味着即使未提供用户名或密码，应用程序也将验证用户身份。与常见的 SQL 注入攻击一样，使用 XPath 注入时，第一步是在要测试的字段中插入一个单引号（`'`），在查询中引入语法错误，并检查应用程序是否返回错误消息。

如果对 XML 数据的内部细节不了解，并且应用程序未提供有助于我们重建其内部逻辑的有用错误消息，则执行[盲 XPath 注入](https://owasp.org/www-community/attacks/Blind_XPath_Injection)攻击，其目标是重建整个数据结构。该技术类似于基于推理的 SQL 注入，因为方法是注入代码以创建每次返回一位信息的查询。[盲 XPath 注入] 在 Amit Klein 的参考论文中有更详细的解释。

## 查找XPath注入漏洞

许多常用于探查SQL注入漏洞的攻击字符串如果被提交给一个易于受到XPath注入的函数，往往会导致反常行为。
- `'`
- `'--`

通常，与在SQL注入漏洞中一样，下面的一个或几个字符串将会引起应用程序的行为发生变化，但不会造成错误：

- `' OR 'a'='a`
- `' AND 'a'='b`
- `OR 1=1`
- `AND 1=2`

因此，任何时候，如果在探查SQL注入过程中发现一个漏洞的初步证据，但却无法对该漏洞加以利用，那么遇到的可能就是XPath注入漏洞。

### 渗透测试步骤

1. 尝试提父节点是否存在的探测，并确定它们是否会导致应用程序的行为发生改变，但不会造成错误

2. 如果上面的任何字符串导致应用程序的行为发生改变，但不会造成错误，很可能通过设计测试条件，一次提取一个字节的信息，从而获取任意数据。使用一系列字符串字节提取条件语句确定当前节点的父节点的名称

3. 提取出父节点的名称后，使用一系列子节点字符串字节条件提取 XML 树中的所有数据

## 盲 XPath 注入

即使不了解数据的绝对路径以及目标字段的名称，攻击者仍有可能发动完全盲目的攻击。XPath查询可包含与XML文档中当前节点有关的步骤，因此，从当前节点导航`position`到父节点`parent`或一个特定的子节点`child`。另外，XPath包含可查询文档元信息（包括特殊元素的名称）的函数。使用这些技巧就提取出文档中所有节点的名称与值，而不必提前知道与它的结构或内容有关的任何信息。

例如，使用前面描述的子字符串技巧，提取当前节点的父节点的名称

确定父节点的名称后，攻击者就轮流攻击它的每一个子节点，提取出它们的名称与值。通过索引指定相关子节点可不必知道任何节点的名称。

这种技巧可用在完全盲目的攻击中，这时应用程序在响应中不返回任何结果，我们设计一个注入的条件，通过索引指定目标节点。轮流攻击每个地址节点的每个子节点，并一次一个字符地提取出它们的值，攻击者就提取整个XML数据的内容。

XPath中有两个有用的函数，可帮助自动完成上述攻击，迅速遍历XML文档中的所有节点和数据。

- `count` 返回指定元素的子节点数量，可用于确定需要遍历的`position`值的范围。
- `string-length` 返回一个已提交字符串的长度，可用于确定需要遍历的`substring`值的范围。

### 布尔型 XPath 盲注

使用基于布尔的 XPath 盲注，攻击者基于给定的 XPath 表达式的真假作为触点。与 SQL 布尔盲注的 LENGTH + SUBSTR 相似，确认长度，逐字符暴破

- `string-length(字符串)` 
    查询字符串的长度
- `substring(字符串,起始位置,1)`
    迭代暴破整个字符串，递增起始位置参数

查询 XML 文档的结构（标签节点数量，以及其名称）：

1. `count(/*)>=1`
    查询根节点下的直接子标签元素（`/*`）数量（`count`）

2. `string-length(name(/*[1]))>=11`
    查询 `/*` 下，标签1的名称（`name`）长度

3. `substring(name(/*[1]),1,1)>="a"`
    二分法查询标签1的名称字符

代码：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<data>
    <user>
        <login>admin</login>
        <password>test</password>
        <realname>SuperUser</realname>
    </user>
    <user>
        <login>rezos</login>
        <password>rezos123</password>
        <realname>Simple User</realname>
    </user>
</data>
```

查询文本节点字符串时应用相似步骤：

- `string-length(//user[2]/*[2])`
    返回第2个用户的第2个节点元素值的长度 (`rezos123` 8)，

- `substring((//user[2]/*[2]),1,1)`
    返回该用户 `password` 节点元素值的第1个字符 (`r`)。


如果登录表单如下所示：

C#:

```csharp
String FindUser;
FindUser = "//user[login/text()='" + Request("Username") + "' And
            password/text()='" + Request("Password") + "']";
```

那么攻击者应该注入以下代码：

用户名： `' or substring((//user[1]/child::*[2]),1,1)="a" or ''='`

XPath 语法可能会让你想起常见的 [SQL 注入] 攻击，但攻击者必须考虑到这种语言不允许注释掉表达式的其余部分。为了规避这一限制，攻击者应使用 OR 表达式来使所有可能破坏攻击的表达式无效。

由于布尔化的特性，即使在小型 XML 文档中，查询数量也可能非常高（数千、数十万甚至更多）。这就是为什么这种攻击不是手动进行的。了解几个基本的 XPath函数后，攻击者能够在短时间内编写一个应用程序，该应用程序将自行重建文档结构并用数据填充它。
