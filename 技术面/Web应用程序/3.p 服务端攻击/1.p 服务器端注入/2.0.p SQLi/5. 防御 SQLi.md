## 防御措施

预防 SQL 注入的一种方法是使用**预编译语句**。预编译语句也称为参数化查询，它们使 SQL 注入几乎不可能发生。

以下代码容易受到 SQL 注入攻击，因为用户输入被直接拼接到查询中：

```java
String query = "SELECT * FROM products WHERE category = '"+ input + "'";
Statement statement = connection.createStatement();
ResultSet resultSet = statement.executeQuery(query);
```

将此代码重写为一种防止用户输入干扰查询结构的方式：

```java
PreparedStatement statement = connection.prepareStatement("SELECT * FROM products WHERE category = ?");
statement.setString(1, input);
ResultSet resultSet = statement.executeQuery();
```

在深入了解预编译语句的工作原理之前，理解 SQL 查询的执行过程很重要。SQL 是一种编程语言，SQL 查询本质上是一个程序。当 SQL 程序到达 SQL 服务器时，服务器会对其进行解析、编译和优化。最后，服务器执行程序并返回执行结果。

`查询 → 解析、编译、优化 → 执行 → 结果`

当你将用户提供的输入插入 SQL 查询时，你实际上是在使用用户输入动态地重写程序。攻击者可以提供干扰程序代码的数据，改变其逻辑。

`查询 + 用户输入 → 解析、编译、优化 → 执行 → 结果`
- 在编译前将用户输入拼接到查询中的 SQL 查询会使数据库将用户输入视为代码

预编译语句通过确保用户提供的数据不会改变 SQL 查询的逻辑来工作。这些 SQL 语句在任何用户提供的参数插入之前被发送到 SQL 服务器并编译。这意味着，你不是将完整的 SQL 查询传递给服务器编译，而是先定义所有 SQL 逻辑，编译它，然后在执行之前将用户提供的参数插入查询。参数插入最终查询后，查询将不再被解析和编译。

`查询 → 解析、编译、优化 → + 用户输入 → 执行 → 结果`
- 在编译后将用户输入拼接到查询中的 SQL 查询允许数据库区分 SQL 查询的代码部分和数据部分

原始语句中不存在的内容将被视为字符串数据，而非可执行的 SQL 代码，因此 SQL 查询的程序逻辑部分将保持不变。这允许数据库区分 SQL 查询的代码部分和数据部分，无论用户输入是什么样子。

参数化查询可用于任何不可信输入在查询中以数据形式出现的情况，包括 `WHERE` 子句和 `INSERT` 或 `UPDATE` 语句中的值。它们不能用于处理查询其他部分中的不可信输入，例如表名或列名，或 `ORDER BY` 子句。将不可信数据放入查询这些部分的应用程序功能需要采用不同的方法，例如：

- 对允许的输入值进行白名单验证。
- 使用不同的逻辑来实现所需的行为。

要使参数化查询有效防止 SQL 注入，查询中使用的字符串必须始终是硬编码**常量**。它绝不能包含来自任何来源的任何**变量**数据。不要试图逐案决定某个数据项是否可信，并在被认为是安全的情况下继续在查询中使用字符串拼接。很容易错误判断数据的可能来源，或者由于其他代码的更改而使可信数据被污染。

### PHP 示例

让我们看一个如何在 PHP 中安全执行 SQL 语句的示例。假设我们想使用用户提供的用户名和密码检索用户 ID，因此要执行此 SQL 语句：

```sql
SELECT Id FROM Users
WHERE Username=USERNAME AND Password=PASSWORD;
```

以下是在 PHP 中的做法：

```php
$mysqli = new mysqli("mysql_host", "mysql_username", "mysql_password", "database_name"); ①
$username = $_POST["username"]; ②
$password = $_POST["password"]; ③
```

在 PHP 中，我们首先与数据库建立连接 ①，然后从用户处检索作为 POST 参数的用户名和密码 ②③。

要使用预编译语句，你首先要定义查询的结构。我们写出不带参数的查询，并用问号作为参数的占位符：

```php
$stmt = $mysqli->prepare("SELECT Id FROM Users WHERE Username=? AND Password=?");
```

此查询字符串现在将由 SQL 服务器作为 SQL 代码编译。然后你可以分别发送查询的参数。以下代码行将用户输入插入 SQL 查询：

```php
$stmt->bind_param("ss", $username, $password);
```

最后，执行查询：

```php
$stmt->execute();
```

用户提供的用户名和密码值不会像语句模板那样被编译，也不会作为 SQL 代码的逻辑部分被执行。因此，如果攻击者向应用程序提供类似这样的恶意输入，整个输入将被视为普通数据，而不是 SQL 代码：

```
Password12345';--
```
