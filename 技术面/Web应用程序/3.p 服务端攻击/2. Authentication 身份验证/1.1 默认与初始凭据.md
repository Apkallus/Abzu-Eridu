# 默认与初始凭据

## 概述

许多 Web 应用程序和硬件设备都为内置管理账户设置了默认密码。虽然在某些情况下这些密码可能是随机生成的，但它们通常是静态的，这意味着攻击者可以轻松猜测或获取。

此外，当在应用程序中创建新用户时，这些用户可能会被设置预定义的密码。这些密码可能由应用程序自动生成，也可能由工作人员手动创建。在这两种情况下，如果生成方式不安全，攻击者就有可能猜测出这些密码。

## 测试目标

- 确定应用程序是否存在使用默认密码的用户账户。
- 审查新用户账户是否使用弱密码或可预测的密码创建。

## 如何测试

### 测试供应商默认凭据

识别默认密码的第一步是识别所使用的软件。

一旦识别出软件，尝试查找它是否使用默认密码，如果是，则密码是什么。这应包括：

- 搜索 "软件名称 默认密码"。
- 查看手册或供应商文档。
- 检查常见的默认密码数据库，例如 [CIRT.net](https://cirt.net/passwords)、[SecLists 默认密码](https://github.com/danielmiessler/SecLists/tree/master/Passwords/Default-Credentials) 或 [DefaultCreds-cheat-sheet](https://github.com/ihebski/DefaultCreds-cheat-sheet/blob/main/DefaultCreds-Cheat-Sheet.csv)。
- 检查应用程序源代码（如果可用）。
- 在虚拟机上安装应用程序并检查。
- 检查物理硬件上的标签（通常在网络设备上存在）。

如果找不到默认密码，请尝试常见选项，例如：

- "admin"、"password"、"12345" 或其他[常见默认密码](https://github.com/nixawk/fuzzdb/blob/master/bruteforce/passwds/default_devices_users%2Bpasswords.txt)。
- 空密码或空白密码。
- 设备的序列号或 MAC 地址。

如果用户名未知，尝试枚举用户名。或者，尝试常见选项，例如 "admin"、"root" 或 "system"。

### 可预测的用户名

一些应用程序根据某种可以预测的顺序自动生成账户用户名。如果应用程序以这种方式运转，弄清了用户名顺序的攻击者就可以很快获得全部有效用户名，以此作为后续攻击的基础。与依赖不断提交由词汇驱动请求的枚举方法不同，这种确定用户名的方法不需实施入侵，也很少给应用程序造成干扰。

#### 渗透测试步骤：可预测的用户名

1. 如果用户名由应用程序生成，设法获得几个连续的用户名，看能否从中看出任何顺序或模式。

2. 如果存在某种顺序或模式，向后推断列出所有可能的有效用户名。这种方法可作为需要有效用户名的登录蛮力攻击和其他攻击的基础，如利用访问控制漏洞。

### 可预测的初始密码

一些应用程序一次性或大批量创建用户，并自动指定初始密码，然后以某种方式将密码分配给所有用户。这种生成密码的方式可让攻击者能够预测其他应用程序用户的密码。基于内联网的企业应用程序常常存在这种漏洞。例如，应用程序为每位雇员创建一个账户，并向其发送一份打印好的密码通知。

- 使用通用密码或
    - 简单通用密码，例如 "Password1"。
    - 组织特定细节，例如组织名称或地址。

- 根据其用户名或工作职能创建的密码

- 包含某种顺序
    - 遵循简单模式的密码，例如如果账户在周一创建，则为 "Monday123"。
    - 账户详细信息的哈希或混淆部分，例如 `md5($username)`。
    - 基于时间的算法。
    - 弱伪随机数生成器（PRNG）。

#### 渗透测试步骤：可预测的初始密码

1. 如果密码由应用程序生成，设法获得几个连续的密码，看能否从中看出任何顺序或模式。

2. 如果存在某种顺序或模式，根据这种模式推断，获取其他应用程序用户的密码。

3. 如果密码呈现出一种可能与用户名相联系的模式，可以设法使用已知或猜测出的用户名与相应推断出的密码进行登录。

4. 其他情况下，可以使用推断出的密码列表作为利用一组枚举出的用户名或常见用户名实施蛮力攻击的基础。
