# 预防原型污染漏洞

我们建议修补在网站中发现的任何原型污染漏洞，无论这些漏洞是否可与可利用的小工具结合。即使你确信自己没有遗漏任何问题，也无法保证你自身代码或所用库的未来更新不会引入新的小工具，从而为有效的漏洞利用铺平道路。

## 清理属性键

防止原型污染漏洞较为明显的方法之一，是在将属性键合并到现有对象之前对其进行清理。这样，可以防止攻击者注入像 `__proto__` 这样引用对象原型的键。

使用允许键的白名单是最有效的方式。然而，由于这在许多情况下不可行，通常采用黑名单方式，从用户输入中移除任何潜在危险的字符串。

尽管这是一个快速修复方案，但真正健壮的黑名单机制本质上很棘手，这一点从某些网站成功屏蔽了 `__proto__`，却未能防范攻击者[通过构造函数污染对象原型](https://portswigger.net/web-security/prototype-pollution/client-side#prototype-pollution-via-the-constructor)中可以看出。同样，薄弱的实现也可能被[简单的混淆技术绕过](https://portswigger.net/web-security/prototype-pollution/client-side#bypassing-flawed-key-sanitization)。因此，我们仅建议将其作为权宜之计，而非长期解决方案。

## 阻止对原型对象的更改

防止原型污染漏洞更稳健的方法是彻底阻止原型对象被修改。

对对象调用 `Object.freeze()` 方法可确保其属性及属性值无法再被修改，也无法添加新属性。由于原型本身就是对象，你可以使用此方法主动切断任何潜在的污染源：

```javascript
Object.freeze(Object.prototype);
```

`Object.seal()` 方法类似，但仍允许更改现有属性的值。如果因某种原因无法使用 `Object.freeze()`，这可能是一个不错的折中方案。

## 防止对象继承属性

虽然可以使用 `Object.freeze()` 来阻断潜在的污染源，但你也可以采取措施消除小工具。这样，即便攻击者发现了原型污染漏洞，它也很可能无法被利用。

默认情况下，所有对象都直接或间接通过原型链继承自全局 `Object.prototype`。不过，你也可以通过 `Object.create()` 方法手动设置对象的原型。该方法不仅允许你将任何对象指定为新对象的原型，还可以创建原型为 `null` 的对象，从而确保它不会继承任何属性。

```javascript
let myObject = Object.create(null);
Object.getPrototypeOf(myObject);    // null
```

## 尽可能使用更安全的替代方案

另一项针对原型污染的稳健防御措施是使用提供内置保护的对象。例如，在定义选项对象时，可以使用 `Map` 代替普通对象。虽然 Map 仍然可能继承恶意属性，但它内置的 `get()` 方法只会返回直接在 Map 本身上定义的属性：

```javascript
Object.prototype.evil = 'polluted';
let options = new Map();
options.set('transport_url', 'https://normal-website.com');

options.evil;                    // 'polluted'
options.get('evil');             // undefined
options.get('transport_url');    // 'https://normal-website.com'
```

如果只是存储值而非 `key:value` 对，`Set` 是另一种替代方案。与 Map 类似，Set 提供的内置方法只返回直接在对象本身上定义的属性：

```javascript
Object.prototype.evil = 'polluted';
let options = new Set();
options.add('safe');

options.evil;           // 'polluted';
option.has('evil');     // false
options.has('safe');    // true
```
