# Web 消息操纵

在本节中，我们将介绍什么是 Web 消息操纵漏洞，并提供降低此类风险的建议。

## 概述

Web 消息传递（也称为[跨文档消息传递](https://html.spec.whatwg.org/multipage/web-messaging.html#web-messaging)）允许运行在不同域上的应用程序以安全的方式进行通信。在引入 Web 消息传递之前，不同源（iframe、选项卡和窗口之间）的通信受到同源策略的限制，并由浏览器强制执行。开发人员使用了多种技巧来完成这些任务，但其中大多数主要是不安全的。

浏览器内的这种限制是为了防止恶意网站从其他 iframe、选项卡等读取机密数据；然而，在某些合法情况下，两个受信任的网站需要相互交换数据。为了满足这一需求，[WHATWG HTML5](https://html.spec.whatwg.org/multipage/) 草案规范中引入了跨文档消息传递，并在所有主流浏览器中实现。它支持跨 iframe、选项卡和窗口的多个源之间的安全通信。

消息传递 API 引入了 [`postMessage()` 方法](https://developer.mozilla.org/en-US/docs/Web/API/Window/postMessage)，通过该方法可以跨源发送纯文本消息。它包含两个参数：消息和域。

当使用 `*` 作为域时，存在一些安全问题，我们将在下文讨论。为了接收消息，接收网站需要添加一个新的事件处理程序，该处理程序具有以下属性：

- Data，传入消息的内容；
- Origin，发送文档的来源；以及
- Source，源窗口。

以下是消息传递 API 的使用示例。发送消息：

```js
iframe1.contentWindow.postMessage("Hello world","https://www.example.com");
```

接收消息：

```js
window.addEventListener("message", handler, true);
function handler(event) {
    if(event.origin === 'chat.example.com') {
        /* 处理消息 (event.data) */
    } else {
        /* 忽略来自不受信任域的消息 */
    }
}
```

## 什么是基于 DOM 的 Web 消息操纵？

当脚本将攻击者可控制的数据作为 Web 消息发送给浏览器中的另一份文档时，就会产生 Web 消息漏洞。攻击者可以构造一个网页，当用户访问该页面时，会诱使用户的浏览器发送一条包含攻击者控制数据的 Web 消息，从而利用该 Web 消息数据作为“源”。更多关于将 Web 消息用作源的信息，请参阅 [控制 Web 消息源](/web-security/dom-based/controlling-the-web-message-source) 页面。

## 哪些汇可能导致基于 DOM 的 Web 消息操纵漏洞？

用于发送 Web 消息的 `postMessage()` 方法，如果用于接收消息的事件监听器以不安全的方式处理传入数据，则可能导致漏洞。
