# 基于 DOM 的漏洞

在本节中，我们将描述 DOM 的概念，解释 DOM 数据的不安全处理如何引入漏洞，并提供如何防范网站中基于 DOM 的漏洞的建议。

## 什么是 DOM？

文档对象模型（DOM）是网页浏览器对页面元素的层次化表示。网站可以使用 JavaScript 来操作 DOM 的节点、对象及其属性。DOM 操作本身并不是问题，实际上，它是现代网站运作方式的组成部分。然而，不安全地处理数据的 JavaScript 可能会导致各种攻击。当网站包含的 JavaScript 将攻击者可控制的值（称为*源*）传递到危险函数（称为*汇*）时，就会产生基于 DOM 的漏洞。

## 污点流漏洞

许多基于 DOM 的漏洞都可以追溯到客户端代码处理攻击者可控制数据的方式存在的问题。

### 什么是污点流？

为了利用或缓解这些漏洞，首先需要熟悉源与汇之间污点流的基本概念。

#### 源

源是 JavaScript 属性，它接受可能受攻击者控制的数据。源的一个示例是 `location.search` 属性，因为它从查询字符串读取输入，而查询字符串相对容易被攻击者操纵。本质上，任何可由攻击者控制的属性都是潜在的源，包括引用 URL（由 `document.referrer` 字符串暴露）、用户 Cookie（由 `document.cookie` 字符串暴露）和 Web 消息。

#### 汇

汇是潜在危险的 JavaScript 函数或 DOM 对象，如果攻击者可控的数据被传递给它，可能会导致不良影响。例如，`eval()` 函数就是一个汇，因为它会将传入的参数作为 JavaScript 执行。HTML 汇的示例是 `document.body.innerHTML`，因为它可能允许攻击者注入恶意 HTML 并执行任意 JavaScript。

从根本上说，当网站将数据从源传递到汇，而汇在客户端会话上下文中不安全地处理这些数据时，就会产生基于 DOM 的漏洞。

最常见的源是 URL，通常通过 `location` 对象访问。攻击者可以构造一个链接，将受害者引导至包含查询字符串或 URL 片段中携带的负载的易受攻击页面。考虑以下代码：

```javascript
goto = location.hash.slice(1)
if (goto.startsWith('https:')) {
  location = goto;
}
```

该代码容易受到基于 DOM 的开放重定向攻击，因为 `location.hash` 源以不安全的方式被处理。如果 URL 包含以 `https:` 开头的哈希片段，此代码会提取 `location.hash` 属性的值，并将其设置为 `window` 对象的 `location` 属性。攻击者可以通过构造以下 URL 来利用此漏洞：

`https://www.innocent-website.com/example#https://www.evil-user.net`

当受害者访问该 URL 时，JavaScript 会将 `location` 属性的值设置为 `https://www.evil-user.net`，从而自动将受害者重定向到恶意网站。这种行为很容易被用来构建网络钓鱼攻击等。

### 如何防止基于 DOM 的污点流漏洞

没有任何单一措施能够完全消除基于 DOM 的攻击威胁。然而，一般而言，避免基于 DOM 的漏洞最有效的方式是：不允许来自任何不受信任源的数据动态更改传递给任何汇的值。

如果应用程序的预期功能导致此行为不可避免，则必须在客户端代码中实施防御。在许多情况下，可以基于白名单对相关数据进行验证，仅允许已知安全的内容。而在其他情况下，则需要对数据进行清理或编码。这可能是一项复杂的任务，具体取决于数据将要插入的上下文，可能需要按适当的顺序组合使用 JavaScript 转义、HTML 编码和 URL 编码。

有关防范特定漏洞的更多措施，请参阅上方表格中链接的相应漏洞页面。

## DOM 覆盖（DOM Clobbering）

DOM 覆盖是一种高级技术，攻击者通过在页面中注入 HTML 来操纵 DOM，从而改变网站上 JavaScript 的行为。最常见的 DOM 覆盖形式是使用锚点元素覆盖全局变量，然后应用程序以不安全的方式使用该变量，例如生成动态脚本 URL。
