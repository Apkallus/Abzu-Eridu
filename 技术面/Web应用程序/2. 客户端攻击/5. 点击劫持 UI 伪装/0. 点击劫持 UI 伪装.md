# 点击劫持（UI 伪装）

UI 重新定向是一个术语，涵盖了多种攻击技术，包括点击劫持（clickjacking）、点赞劫持（likejacking）和击键劫持（strokejacking）。

在本节中，我们将解释什么是点击劫持，描述常见的点击劫持攻击示例，并讨论如何防御这些攻击。

## 什么是点击劫持？

点击劫持（Clickjacking）是 UI 伪装（UI redressing）的一个子集，是一种基于界面的攻击，用户被诱骗点击了诱饵网站上的某些内容，实际上点击的却是隐藏网站上的可操作内容。攻击者采用各种CSS技术。加载目标应用程序的iframe可以为任意大小，位于攻击者页面中的任何位置，并显示目标页面的任意位置。使用适当的样式属性，可以令该iframe变得完全透明，从而使其对用户不可见。请考虑以下示例：

一位 Web 用户访问了一个诱饵网站（可能是通过电子邮件提供的链接），并点击了一个按钮以赢取奖品。然而，他们不知不觉中被攻击者欺骗，按下了另一个隐藏按钮，结果导致在另一个网站上支付了账户款项。

该技术依赖于将一个不可见的、可操作的网页（或多个页面）嵌入到 iframe 中，其中包含按钮或隐藏链接。该 iframe 被覆盖在用户预期的诱饵网页内容之上。

与其他攻击一样，一个常见的前提是受害者已通过目标应用程序的身份验证。

这种攻击与 CSRF 攻击的不同之处在于，用户需要执行诸如点击按钮之类的操作，而 CSRF 攻击则依赖于在用户不知情或未输入的情况下伪造整个请求。

![点击劫持](https://portswigger.net/web-security/images/clickjacking-infographic.svg)

针对 CSRF 攻击的防护通常通过使用 CSRF 令牌来提供：一个特定于会话的、一次性使用的数字或 nonce。点击劫持攻击无法通过 CSRF 令牌缓解，因为目标会话是由从真实网站加载的内容建立的，且所有请求都在同域内发生。CSRF 令牌被放入请求中，并作为正常会话的一部分传递给服务器。与正常用户会话的区别在于，该过程发生在隐藏的 iframe 内。

如果进一步扩展上述基本攻击，攻击者可以在其界面中使用复杂的脚本代码，以诱使受害用户执行更加复杂的操作，而不仅仅是单击按钮。比方说，要实施攻击，需要诱使用户在输入字段（如转账页面的“金额”字段）中输入一些文本。在这种情况下，攻击者可以在其用户界面中包含一些诱使用户输入文本的内容，如用于输入电话号码以赢得奖励的表单。然后，攻击者的页面中的脚本可以对进行键击选择性处理，在用户输入相关字符时，将键击操作有效传递到目标界面，从而填写所需的输入字段。如果用户输入攻击者不希望在目标界面中输入的字符，该键击将不会传递给目标界面，攻击者的脚本将等待下一次键击。

另外，攻击者的页面中可以包含诱使用户执行拖动鼠标操作（就像玩简单的游戏一样）的内容。随后，在攻击者的页面中运行的脚本将选择性地处理生成的操作，使用户在不知情的情况下选择目标应用程序界面中的文本，并将其拖动到攻击者的界面中的输入字段中（或相反）。例如，在针对Web邮件应用程序实施攻击时，攻击者可以诱使用户将电子邮件中的文本拖动到其能够读取的输入字段中。或者，攻击者可以诱使用户建立某种规则，向某转发所有电子邮件，并将所需电子邮件地址从攻击者的界面拖动到定义该规则的表单的相关输入字段中。此外，由于链接和图像均可以作为URL进行拖动，攻击者甚至可以通过诱发拖动操作从目标应用程序的界面中拦截敏感URL，包括反CSRF令牌。

## 如何构造基本的点击劫持攻击

点击劫持攻击使用 CSS 来创建和操纵图层。攻击者将目标网站作为 iframe 图层叠加在诱饵网站上。使用样式标签和参数的示例如下：

```html
<head>
    <style>
        /* 2. 为了将 iframe 放置在诱饵内容上方，操纵 CSS 的 z-index 属性，赋予其比页面内容更高的值。堆叠顺序较高的元素出现在上面。在这种情况下，攻击者将 iframe 的 z-index 属性设置为高于其他元素。 */
        #target_website {
            position:relative;
            width:600px;
            height:600px;
            opacity:0.5; /* 目标操作接近透明 */
            z-index:2; /* 目标操作设置为更高的值 */
            }

        /* 4. 使用 CSS 定位属性（top、left 和 absolute）的组合，将目标操作按钮叠加在诱饵内容上。 */
        #decoy_website {
            position:absolute;
            width:50px;
            height:50px;
            z-index:1; /* 诱饵内容使用降低的值 */
            top: 100px;
            left: 100px;
            }
    </style>
</head>
...
<body>
    <!-- 3. 诱饵内容 -->
    <div id="decoy_website">
    ...decoy web content here...
    </div>

    <!-- 1. 创建一个 iframe，并将其源设置为目标操作页面。将 iframe 设置到诱饵内容上层。 -->
    <iframe id="target_website" src="https://vulnerable-website.com">
    </iframe>
</body>
```

目标网站 iframe 在浏览器中被定位，使得目标操作与诱饵网站精确重叠，使用适当的宽度和高度位置值。绝对和相对位置值用于确保目标网站无论在屏幕大小、浏览器类型还是平台上都能精确覆盖诱饵。z-index 决定了 iframe 和网站图层的堆叠顺序。opacity 值被定义为 0.0（或接近 0.0），以便 iframe 内容对用户透明。浏览器的点击劫持防护可能会应用基于阈值的 iframe 透明度检测（例如，Chrome 76 版包含此行为，但 Firefox 没有）。攻击者会选择透明度值，以便在触发防护行为之前达到预期效果。

> 心智模型：目标端点的子框架作为画布，诱饵元素作为指向画布中对应功能按钮的定点
>
> 快速 CSS：在浏览器的开发者工具中，在元素的样式栏中微调，右键复制元素的样式

另一种 CSS：`pointer-events: none` CSS 属性，对设置元素的任何交互（点击）都将传递到其下方的元素。

### Clickbandit

尽管你可以如上所述手动创建点击劫持概念验证，但在实践中这可能相当繁琐和耗时。在实际环境中测试点击劫持时，我们建议改用 Burp 的 [Clickbandit](https://portswigger.net/burp/documentation/desktop/tools/clickbandit) 工具。它允许你使用浏览器在可被框架嵌入的页面上执行所需的操作，然后创建一个包含适当点击劫持覆盖层的 HTML 文件。你可以在几秒钟内生成交互式概念验证，而无需编写一行 HTML 或 CSS。

Burp 的点击劫持工具可用作 POC。但对于之后的 lab 有时很难用，或需花费相对手动构造更多的时间调整

## 使用预填表单输入的点击劫持

一些需要表单填写和提交的网站允许在提交之前使用 GET 参数预填表单输入。其他网站可能需要在表单提交之前输入文本。由于 GET 值构成 URL 的一部分，目标 URL 可以被修改以包含攻击者选择的值，并且透明的“提交”按钮被覆盖在诱饵站点上，就像基本的点击劫持示例一样。

## 框架破坏脚本

只要网站可以被框架嵌入，点击劫持攻击就可能发生。因此，预防技术基于限制网站的框架功能。一种常见的通过 Web 浏览器实施的客户端防护是使用框架破坏或框架打破脚本。这些可以通过专有的浏览器 JavaScript 附加组件或扩展（如 NoScript）实现。脚本通常被设计为执行以下部分或全部行为：

- 检查并强制当前应用程序窗口是主窗口或顶层窗口
- 使所有框架可见
- 防止点击不可见的框架
- 拦截并向用户标记潜在的点击劫持攻击

框架破坏技术通常是特定于浏览器和平台的，并且由于 HTML 的灵活性，攻击者通常可以绕过它们。由于框架破坏器是 JavaScript，浏览器的安全设置可能会阻止其运行，或者浏览器甚至可能不支持 JavaScript。攻击者绕过框架破坏器的有效方法之一是使用 HTML5 iframe 的 `sandbox` 属性。当此属性设置为 `allow-forms` 或 `allow-scripts` 值而省略 `allow-top-navigation` 值时，框架破坏脚本可以被中和，因为 iframe 无法检查它是否在顶层窗口中：

```html
<iframe id="victim_website" src="https://victim-website.com" sandbox="allow-forms"></iframe>
```

`allow-forms` 和 `allow-scripts` 值都允许在 iframe 内执行指定的操作，但顶级导航被禁用。这抑制了框架破坏行为，同时允许目标站点内的功能。

假想的罕见场景：目标功能使用 JS 动态构建表单，于是无法直接禁用子框架 JS。若此时站点存在嵌入自定义 iframe 的功能，使用 `目标站点-攻击者子框架-目标功能子框架` 的多重子框架嵌套，从而通过 `top.location == self.location` 的 JS 防护

## 将点击劫持与 DOM XSS 攻击相结合

到目前为止，我们已经将点击劫持视为一种独立的攻击。从历史上看，点击劫持曾被用于执行诸如增加 Facebook 页面“点赞”等行为。然而，点击劫持的真正威力在于它被用作另一种攻击（如 DOM XSS 攻击）的载体时。假设攻击者首先已识别出 XSS 漏洞，那么实现这种组合攻击相对简单。然后将 XSS 漏洞与 iframe 目标 URL 结合起来，以便用户点击按钮或链接，从而执行 DOM XSS 攻击。

## 多步骤点击劫持

攻击者对目标网站输入的操纵可能需要多个动作。例如，攻击者可能想要诱骗用户从零售网站购买商品，因此在下单之前需要将商品添加到购物篮中。这些操作可以由攻击者使用多个 div 或 iframe 来实现。这类攻击需要攻击者具备相当高的精确度和谨慎性，才能做到有效且隐蔽。

类型
- 仅需一个目标功能子框架：操作步骤在同一页面或使用重定向
- 需多个子框架或更新子框架 src：多个目标功能存在漏洞，尝试构建组合攻击

## 如何预防点击劫持攻击

我们已经讨论了一种常见的浏览器端防护机制，即框架破坏脚本。然而，我们已经看到攻击者通常可以轻松绕过这些防护。因此，设计了服务器驱动的协议来限制浏览器的 iframe 使用并缓解点击劫持。

点击劫持是一种浏览器端行为，其成功与否取决于浏览器功能以及对现行 Web 标准和最佳实践的符合程度。服务器端对点击劫持的防护通过定义和传达对 iframe 等组件使用限制来提供。然而，防护的实施取决于浏览器对这些限制的遵守和执行。两种服务器端点击劫持防护机制是 X-Frame-Options 和 Content Security Policy。

### X-Frame-Options

X-Frame-Options 最初是作为 Internet Explorer 8 中的非官方响应头引入的，并迅速被其他浏览器采用。该头为网站所有者提供了对 iframe 或对象使用的控制，从而可以通过 `deny` 指令禁止将网页包含在框架中：

```http
X-Frame-Options: deny
```

或者，可以使用 `sameorigin` 指令将框架限制为与网站相同的源：

```http
X-Frame-Options: sameorigin
```

#### 弃用指令导致防护缺失

若使用**已弃用**的不受现代浏览器支持的 `allow-from` 指令限制指定网站，则可能存在防护缺失：

```http
X-Frame-Options: allow-from https://normal-website.com
```

让我们看一个示例报告。Periscope 是一个直播视频应用程序，在 2019 年 7 月 10 日被发现存在点击劫持漏洞。你可以在 https://hackerone.com/reports/591432/ 找到已披露的漏洞报告。该站点使用 `X-Frame-Options ALLOW-FROM` 指令来防止点击劫持。此指令允许页面指定允许嵌入它的 URL，但它是一个已废弃的指令，许多浏览器不支持它。这意味着如果受害者使用不支持该指令的浏览器（如最新的 Chrome、Firefox 和 Safari 浏览器），子域 `https://canary-web.pscp.tv` 和 `https://canary-web.periscope.tv` 上的所有功能都容易受到点击劫持攻击。由于 Periscope 的账户设置页面允许用户停用其账户，攻击者可以嵌入设置页面并诱骗用户停用其账户。

### 内容安全策略（CSP）

内容安全策略（CSP）是一种检测和预防机制，可缓解 XSS 和点击劫持等攻击。CSP 通常作为返回头在 Web 服务器中实现，形式如下：

```http
Content-Security-Policy: policy
```

其中 policy 是由分号分隔的策略指令字符串。CSP 向客户端浏览器提供有关允许的 Web 资源来源的信息，浏览器可以应用这些信息来检测和拦截恶意行为。

推荐的点击劫持防护是在应用程序的内容安全策略中加入 `frame-ancestors` 指令。`frame-ancestors 'none'` 指令的行为类似于 X-Frame-Options 的 `deny` 指令。`frame-ancestors 'self'` 指令大致等同于 X-Frame-Options 的 `sameorigin` 指令。以下 CSP 将框架白名单限制为仅同域：

```http
Content-Security-Policy: frame-ancestors 'self';
```

或者，可以将框架限制为指定站点：

```http
Content-Security-Policy: frame-ancestors normal-website.com;
```

为了有效防御点击劫持和 XSS，CSP 需要精心的开发、实施和测试，并应作为多层防御策略的一部分使用。
