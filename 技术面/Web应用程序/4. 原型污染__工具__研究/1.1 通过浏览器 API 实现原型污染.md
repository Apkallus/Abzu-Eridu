# 通过浏览器 API 实现原型污染

你可能会惊讶地发现，浏览器中常见的 JavaScript API 中存在许多广泛存在的原型污染小工具。在本节中，我们将展示如何利用这些小工具实现 DOM XSS，从而可能绕过开发人员实施的有缺陷的原型污染防御措施。

## PortSwigger 研究

本节中的实验基于 PortSwigger 的原创研究。如需深入了解我们是如何使用 DOM Invader 发现这些小工具及相关内容的，请参阅相关博文。

- [广泛存在的原型污染小工具 — Gareth Heyes](https://portswigger.net/research/widespread-prototype-pollution-gadgets)

## 通过 fetch() 实现原型污染

`Fetch` API 为开发者提供了一种使用 JavaScript 触发 HTTP 请求的简单方式。`fetch()` 方法接受两个参数：

- 要发送请求的 URL。
- 一个选项对象，允许你控制请求的各个部分，例如方法、头部、请求体参数等。

以下是使用 `fetch()` 发送 `POST` 请求的示例：

```javascript
fetch('https://normal-website.com/my-account/change-email', {
    method: 'POST',
    body: 'user=carlos&email=carlos%40ginandjuice.shop'
})
```

如你所见，我们显式定义了 `method` 和 `body` 属性，但还有许多其他可能的属性未定义。在这种情况下，如果攻击者能够找到合适的源，他们有可能用自己构造的 `headers` 属性污染 `Object.prototype`。然后，该属性可能被传递给 `fetch()` 的选项对象继承，并随后用于生成请求。

这可能导致一系列问题。例如，以下代码可能通过原型污染导致 DOM XSS：

```javascript
fetch('/my-products.json',{method:"GET"})
    .then((response) => response.json())
    .then((data) => {
        // ** 工具属性 **
        let username = data['x-username'];
        let message = document.querySelector('.message');
        if(username) {
            // ** 汇 **
            message.innerHTML = `My products. Logged in as <b>${username}</b>`;
        }
        let productList = document.querySelector('ul.products');
        for(let product of data) {
            let product = document.createElement('li');
            product.append(product.name);
            productList.append(product);
        }
    })
    .catch(console.error);
```

为了利用此漏洞，通过如下方式使用包含恶意 `x-username` 头的 `headers` 属性污染 `Object.prototype`（污染后，请求头属性添加字段 `x-username` 载荷）：

`?__proto__[headers][x-username]=<img/src/onerror=alert(1)>`

假设在服务端，从客户端请求提取该头部并设置返回的 JSON 文件中 `x-username` 属性的值。在上述存在漏洞的客户端代码中，该值被赋给 `username` 变量，随后被传递到 `innerHTML` 汇点，从而导致 DOM XSS。

> **注意**
> 使用此技术控制传递给 `fetch()` 的选项对象中的任何未定义属性。例如，这可能使你能够向请求中添加恶意请求体。

## 通过 Object.defineProperty() 实现原型污染

具有一定原型污染知识的开发者可能会尝试使用 `Object.defineProperty()` 方法来阻止潜在的小工具。此方法允许你在受影响的对象上直接设置一个不可配置、不可写的属性，如下所示：

```javascript
Object.defineProperty(vulnerableObject, 'gadgetProperty', {
    configurable: false,
    writable: false
})
```

这乍一看似乎是合理的缓解措施，因为它可以防止易受攻击的对象通过原型链继承恶意版本的小工具属性。然而，这种方法本身存在缺陷。

与前面提到的 `fetch()` 方法一样，`Object.defineProperty()` 也接受一个选项对象，即所谓的“描述符”。从上面的示例中看到这一点。开发者可以使用该描述符对象设置所定义属性的初始值。但是，如果他们定义此属性的唯一目的是防御原型污染，则可能根本不会设置值。

在这种情况下，攻击者可能会通过使用恶意 `value` 属性污染 `Object.prototype` 来绕过此防御。如果该属性被传递给 `Object.defineProperty()` 的描述符对象继承，攻击者控制的值可能会被赋值给小工具属性。（即，`Object.defineProperty()` 的 `value` 属性可设置目标对象的值。若此方法属性未定义，则同样可被污染：攻击者污染此方法属性间接设置目标对象）
