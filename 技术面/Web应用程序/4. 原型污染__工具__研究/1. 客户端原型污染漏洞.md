# 客户端原型污染漏洞

在本节中，你将学习如何在实际环境中发现客户端原型污染漏洞。为了帮助你巩固对这些漏洞工作原理的理解，我们将涵盖如何手动执行此操作，以及如何使用 DOM Invader 自动化处理大部分过程。你还将有机会通过在一些故意存在漏洞的实验室上利用原型污染进行 DOM XSS，来练习所学内容。

## 手动查找客户端原型污染源

手动查找原型污染源主要是反复试验的过程。简而言之，你需要尝试不同的方式向 `Object.prototype` 添加任意属性，直到找到有效的源。

在测试客户端漏洞时，这涉及以下高级步骤：

1. 尝试通过查询字符串、URL 片段和任何 JSON 输入注入任意属性。例如：  
   `vulnerable-website.com/?__proto__[foo]=bar`
   `vulnerable-website.com/?constructor[prototype][foo]=bar`

2. 在浏览器控制台中检查 `Object.prototype`，查看是否成功污染了任意属性：  
   ```javascript
   Object.prototype.foo
   // 返回 "bar" 表示你已成功污染原型
   // 返回 undefined 表示攻击未成功
   ```

3. 如果属性未添加到原型，请尝试使用不同的技术，例如改用点表示法而非方括号表示法，反之亦然：  
   `vulnerable-website.com/?__proto__.foo=bar`

4. 对每个潜在的源重复此过程。

> **提示**
> 如果这些技术均未成功，你或许仍能通过其构造函数来污染原型。我们将在后面更详细地介绍如何操作。

## 使用 DOM Invader 查找客户端原型污染源

如你所见，手动查找原型污染源可能是一个相当繁琐的过程。因此，我们推荐使用 DOM Invader，它已预装在 Burp 的内置浏览器中。DOM Invader 能够在浏览时自动测试原型污染源，从而节省大量时间和精力。

更多信息，请查看 [DOM Invader 文档](https://portswigger.net/burp/documentation/desktop/tools/dom-invader/prototype-pollution#detecting-sources-for-prototype-pollution)。

## 手动查找客户端原型污染小工具

一旦你识别出允许向全局 `Object.prototype` 添加任意属性的源，下一步便是找到合适的小工具来构造漏洞利用。实践中，我们推荐使用 DOM Invader，但了解手动过程也有助于加深对漏洞的理解。

1. 查看源代码，识别应用程序或其导入的任何库所使用的属性。

2. 在 Burp 中启用响应拦截（**Proxy > Options > Intercept server responses**），拦截包含你要测试的 JavaScript 的响应。

3. 在脚本开头添加 JS 调试语句 `debugger`，然后转发剩余的请求和响应。

4. 在 Burp 的浏览器中，前往加载目标脚本的页面。`debugger` 语句会暂停脚本的执行。

5. 脚本仍处于暂停状态时，切换到控制台并输入以下命令，将 `YOUR-PROPERTY` 替换为你认为可能是潜在小工具的属性之一：
   ```javascript
   Object.defineProperty(Object.prototype, 'YOUR-PROPERTY', {
       get() {
           console.trace();
           return 'polluted';
       }
   })
   ```
   该属性被添加到全局 `Object.prototype` 中，每当它被访问时，浏览器都会在控制台记录堆栈跟踪。

6. 按下按钮继续执行脚本并监控控制台。如果出现堆栈跟踪，则表明该属性在应用程序的某处被访问了。

7. 展开堆栈跟踪，使用提供的链接跳转到读取该属性的代码行。

8. 使用浏览器的调试器控件，逐步执行每个阶段，观察该属性是否被传递到汇点，例如 `innerHTML` 或 `eval()`。

9. 对你认为是潜在小工具的任何属性重复此过程。

## 通过构造函数进行原型污染

到目前为止，我们仅研究了如何通过特殊的 `__proto__` 访问器属性获取对原型对象的引用。由于这是原型污染的经典技术，一种常见的防御措施是在合并用户控制的对象之前，剥离其中键名为 `__proto__` 的所有属性。这种方法存在缺陷，因为还有不依赖 `__proto__` 字符串的其他方式可以引用 `Object.prototype`。

除非其原型被设置为 `null`，否则每个 JavaScript 对象都有一个 `constructor` 属性，其中包含用于创建该对象的构造函数引用。例如，使用字面量语法或显式调用 `Object()` 构造函数来创建新对象，如下所示：

```javascript
let myObjectLiteral = {};
let myObject = new Object();
```

然后，通过内置的 `constructor` 属性引用 `Object()` 构造函数：

```javascript
myObjectLiteral.constructor            // function Object(){...}
myObject.constructor                   // function Object(){...}
```

请记住，函数本质上也是对象。每个构造函数都有一个 `prototype` 属性，指向将由该构造函数创建的任何对象所分配的原型。因此，你也可以按如下方式访问任何对象的原型：

```javascript
myObject.constructor.prototype        // Object.prototype
myString.constructor.prototype        // String.prototype
myArray.constructor.prototype         // Array.prototype
```

由于 `myObject.constructor.prototype` 等同于 `myObject.__proto__`，这为原型污染提供了另一种向量。

```json
{
    "constructor": {
        "prototype": {
            "isAdmin": true
        }
    }
}
```

## 绕过有缺陷的键清理

网站试图防止原型污染的一种明显方法是在将属性键合并到现有对象之前对其进行清理。然而，一个常见的错误是未能递归清理输入字符串。例如，考虑以下 URL：

`vulnerable-website.com/?__pro__proto__to__.gadget=payload`

如果清理过程只是剥离字符串 `__proto__` 而未重复多次，则会得到以下 URL，这可能是有效的原型污染源：

`vulnerable-website.com/?__proto__.gadget=payload`
