## 如何识别不安全的反序列化

无论您是白盒测试还是黑盒测试，识别不安全的反序列化都相对简单。

在审计期间，您应查看所有传入网站的数据，并尝试识别任何看起来像序列化数据的内容。如果您了解不同语言使用的格式，则可以相对容易地识别序列化数据。在本节中，我们将展示 PHP 和 Java 序列化的示例。一旦识别出序列化数据，您就可以测试是否能够控制它。

> **提示**  
> 对于 Burp Suite Professional 用户，Burp Scanner 会自动标记任何包含序列化对象的 HTTP 消息。

### PHP 序列化格式

PHP 使用一种基本人类可读的字符串格式，用字母表示数据类型，用数字表示每个条目的长度。例如，考虑一个具有以下属性的 `User` 对象：

```php
class User {
    public name = "carlos";
    public isLoggedIn = true;
    public luckynum = 7;
}
```

序列化后，此对象可能如下所示：

```php
O:4:"User":3:{s:4:"name":s:6:"carlos";s:10:"isLoggedIn":b:1;s:8:"luckynum";i:7;}
```

PHP序列化字符串的基本结构是`数据类型:数据`。数据类型方面，`b`表示布尔值，`i`表示整数，`d`表示浮点数，`s`表示字符串，`a`表示数组，`O`表示特定类的对象实例。其中一些类型后面会跟有关于数据的附加信息

```php
b:布尔值;
i:整数值;
d:浮点值;
s:字符串长度:"字符串";
a:数组元素数量:{元素}
O:对象名称长度:"类名称":对象属性数量:{属性}
```

解释如下：
- `O:4:"User":3:`
    对象(Object => `O`)类名为4字符长的 `"User"`，拥有3个属性

- `s:4:"name"`
    属性名为字符串型(string => `s`)，4字符长的 `"name"`
- `s:6:"carlos"`
    属性值为字符串型，6字符长的 `"carlos"`
- `s:10:"isLoggedIn"`
    属性名为字符串型，10字符长的 `"isLoggedIn"`
- `b:1`
    属性值为布尔型(bool => `b`)，值 `true`
- `s:8:"luckynum"`
    属性名为字符串型，8字符长的 `"luckynum"`
- `i:7`
    属性值为整数型(int => `i`)，值7

PHP 序列化的原生方法是 `serialize()` 和 `unserialize()`。如果您有源代码访问权限，应首先在代码中查找 `unserialize()` 并进一步调查。

### Java 序列化格式

某些语言（如 Java）使用二进制序列化格式。这更难阅读，但仍可通过明显特征来识别序列化数据。例如，序列化的 Java 对象始终以相同的字节开头
- 十六进制编码为 `ac ed`
- Base64 编码为 `rO0`

或 HTTP 消息的`Content-Type`头设置为`application/x-java-serialized-object`

任何实现 `java.io.Serializable` 接口的类都可以被序列化和反序列化，分别对应特殊的自动执行方法`writeObject()`和`readObject()`。

让我们看一个示例。将此代码存储在名为`SerializeTest.java`的文件中：

```java
import java.io.ObjectInputStream;
import java.io.ObjectOutputStream;
import java.io.FileInputStream;
import java.io.FileOutputStream;
import java.io.Serializable;
import java.io.IOException;

① class User implements Serializable{
    ② public String username;
}

public class SerializeTest{
    public static void main(String args[]) throws Exception{
        ③ User newUser = new User();
        ④ newUser.username = "vickie";
        FileOutputStream fos = new FileOutputStream("object.ser");
        ObjectOutputStream os = new ObjectOutputStream(fos);
        ⑤ os.writeObject(newUser);
        os.close();

        FileInputStream is = new FileInputStream("object.ser");
        ObjectInputStream ois = new ObjectInputStream(is);
        ⑥ User storedUser = (User)ois.readObject();
        System.out.println(storedUser.username);
        ois.close();
    }
}
```

然后，在你存储文件的目录中，运行以下命令。它们将编译程序并运行代码：

```bash
$ javac SerializeTest.java
$ java SerializeTest
```

将看到输出字符串`vickie`。让我们稍微分解一下程序。首先，我们定义一个名为`User`的类，它实现了`Serializable`①。只有实现`Serializable`的类才能被序列化和反序列化。`User`类有一个`username`属性，用于存储用户的用户名②。

然后，我们创建一个新的`User`对象③并将其用户名设置为字符串`"vickie"`④。我们将`newUser`的序列化版本写入并存储到文件`object.ser`中⑤。最后，我们从文件中读取对象，反序列化它，并打印出用户的用户名⑥。

### Python Pickle

Python Pickle 是一种二进制格式，视觉识别较困难。协议 0 的载荷较易读，通常以句点（`.`）结尾。更高协议的载荷在 Cookie、令牌或作业/队列参数中表现为不透明的二进制或 Base64 数据块。

识别候选格式后，发送一个用于 Pickle 的受控带外（OOB）或良性崩溃探测载荷（例如执行 DNS 或 HTTP 回调到受控服务器的载荷）。通过观察回调、特定错误或进程崩溃，确认应用程序是否反序列化了该值。切勿以破坏性 RCE 载荷作为起点。

### Node.js（node-serialize）

在使用 `node-serialize` 库的 Node.js 应用程序中，序列化数据通常表现为类 JSON 字符串。风险的关键指标是立即执行函数表达式（IIFE）标记，开头模式 
- `_$$ND_FUNC$$_` 

```javascript
{"rce":"_$$ND_FUNC$$_function (){require('child_process').exec('id')}()"}
```

若在应用程序流量中观察到该标记，请将函数体替换为无害的 OOB 回调，并重新提交以确认执行。

### .NET 序列化

仍使用 `BinaryFormatter` 或 `NetDataContractSerializer` 的旧式应用程序通常将输出进行 Base64 编码。

.NET 序列化数据的常见开头模式
- 十六进制字节 `00 01 00 00 00 FF FF FF FF`
- Base64 字符串 `AAEAAAD/////`

建议将 `BinaryFormatter` 视为仅限旧系统使用；该功能已过时，并从现代 .NET 中移除。

```http
Cookie: SessionData=AAEAAAD/////AQAAAAAAAAAMAgAAAF...
```

### 带类型元数据的基于 JSON 的反序列化

某些 JSON 库支持多态类型。若接受攻击者控制的类型元数据，反序列化可能实例化意外类。

启用默认类型映射的 Jackson 通常包含 `@class` 类型标识：

```json
{"@class":"com.example.Exploit","cmd":"id"}
```

Fastjson 通常使用 `@type`：

```json
{"@type":"com.example.Exploit","cmd":"id"}
```

将攻击者可控的 `@class`、`@type` 或类似类型说明符视为高优先级发现项，然后针对该库使用安全 OOB 小工具进行确认。


## 白盒测试

### 代码审查与汇点函数

跟踪从不受信任输入到每个汇点的完整路径，并验证存在哪些控制措施。

常见汇点包括：

- Java：`java.io.ObjectInputStream.readObject()`、`readUnshared()`
- PHP：`unserialize()`
- Python：`pickle.loads()`、`marshal.loads()`、`shelve.open()`
- Node.js：`node-serialize.unserialize()`
- .NET：`BinaryFormatter.Deserialize()`、`NetDataContractSerializer.Deserialize()`

对于每个汇点：

1. 确认请求参数、Cookie、头、文件或队列消息是否可到达该汇点。
2. 检查允许类白名单、完整性检查（如 HMAC）或平台过滤器（如 Java 的 `ObjectInputFilter`）。
3. 记录缺失的控制措施、过于宽泛的白名单，或客户端可绕过的签名机制。

Apache Commons IO 的 `ValidatingObjectInputStream` 是 Java 的一种白名单实现方式；建议记录代码库实际使用的任何过滤器，包括 JDK 的 `ObjectInputFilter` 配置。
