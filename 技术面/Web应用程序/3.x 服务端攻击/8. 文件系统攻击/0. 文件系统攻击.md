#  Web 应用程序文件系统攻击

## 引言

Web应用程序中的许多功能通常都需要处理用户以文件或目录名提交的输入。一般情况下，这些输入会传递给接受文件路径的API（例如，用于检索本地文件系统中的文件）。应用程序将在它对用户请求的响应中处理该API调用的结果。如果用户提交的输入未经过正确确认，这种行为就可能导致各种安全漏洞，其中最常见的是文件路径遍历漏洞和文件包含漏洞。

“文件系统攻击”一词泛指因文件系统被访问或操作方式不当而产生的一类漏洞。这包括目录遍历、文件包含和文件上传攻击。每个攻击向量都利用了输入验证不当、文件系统权限配置错误或服务器设置不正确等问题。我们将涵盖目录遍历攻击及其影响，随后是文件包含漏洞、本地文件泄露，最后是文件上传攻击及其规避限制的技术。

传统上，Web 服务器和 Web 应用程序通过身份验证机制来控制对文件和资源的访问。Web 服务器尝试将用户的文件限制在“根目录”或“Web 文档根目录”内，该目录代表文件系统上的一个物理目录。用户应将此目录视为 Web 应用程序层次结构中的基础目录。

权限的定义通过访问控制列表（ACL）实现，ACL 标识哪些用户或组应该能够访问、修改或执行服务器上的特定文件。这些机制旨在防止用户访问敏感文件（例如类 Unix 平台上常见的 `/etc/passwd` 文件）或避免执行系统命令。

许多 Web 应用程序使用服务器端脚本包含不同类型的文件。使用此方法来管理图像、模板、加载静态文本等非常常见。不幸的是，如果输入参数（如表单参数、cookie 值）未正确验证，这些应用程序会暴露安全漏洞。

在 Web 服务器和 Web 应用程序中，此类问题出现在路径遍历/文件包含攻击中。通过利用此类漏洞，攻击者能够读取通常无法读取的目录或文件、访问 Web 文档根目录之外的数据，或从外部站点包含脚本和其他类型的文件。

## 路径分隔符特征

重要的是要注意，不同操作系统使用不同的路径分隔符：

- 类 Unix 操作系统：
    - 根目录：`/`
    - 目录分隔符：`/`
- Windows 操作系统：
    - 根目录：`<驱动器号>:`
    - 目录分隔符：`\` 或 `/`
- 经典 macOS：
    - 根目录：`<驱动器号>:`
    - 目录分隔符：`:`

开发人员常犯的错误是未考虑到所有编码形式，尝试各种编码方案。

## Windows 特定注意事项

- Windows shell：在 shell 命令中使用的路径末尾附加以下任何内容在功能上无差异（用来混淆）：
    - 路径末尾的尖括号 `<` 和 `>`
    - 路径末尾的双引号（正确闭合）
    - 多余当前目录标记，如 `./` 或 `.\\`
    - 带有任意可能存在或不存在项的多余父目录标记：
        - `file.txt`
        - `file.txt...`
        - `file.txt<spaces>`
        - `file.txt""""`
        - `file.txt<<<>>><`
        - `./././file.txt`
        - `nonexistant/../file.txt`

- Windows API：在将字符串作为文件名的任何 shell 命令或 API 调用中，以下项会被丢弃：
    - 句点
    - 空格

- Windows UNC 文件路径：用于引用 SMB 共享上的文件。有时，应用程序可被诱导引用远程 UNC 文件路径上的文件。如果如此，Windows SMB 服务器可能会将存储的凭据发送给攻击者，这些凭据可被捕获和破解。这些也可与自引用 IP 地址或域名一起使用以规避过滤器，或用于访问攻击者无法访问但 Web 服务器可访问的 SMB 共享上的文件。
    - `\\server_or_ip\path\to\file.abc`
    - `\\?\server_or_ip\path\to\file.abc`
    
- Windows NT 设备命名空间：用于引用 Windows 设备命名空间。某些引用允许使用不同路径访问文件系统。
    - 可能等同于驱动器号，如 `c:\`，甚至是未分配盘符的驱动器卷：`\\.\GLOBALROOT\Device\HarddiskVolume1\`
    - 指代机器上的第一个光盘驱动器：`\\.\CdRom0\`

## 路径遍历与文件包含的灰盒测试

当以灰盒测试方法进行分析时，测试人员需遵循与黑盒测试相同的方法。然而，由于他们可以审查源代码，因此可以更轻松、更准确地搜索输入向量。在源代码审查期间，他们可以使用简单工具（如 *grep* 命令）在应用程序代码中搜索一个或多个常见模式：包含函数/方法、文件系统操作等。

- PHP：
    `include()、include_once()、require()、require_once()、fopen()、readfile()、...`
- JSP/Servlet：
    `java.io.File()、java.io.FileReader()、...`
- ASP：
    `include file、include virtual、...`

使用在线代码搜索引擎（例如 [Searchcode](https://searchcode.com/)），也可能在互联网上发布的开源软件中找到路径遍历缺陷。

对于 PHP，测试人员可以使用以下正则表达式：

```text
(include|require)(_once)?\s*['"(]?\s*\$_(GET|POST|COOKIE)
```

## 额外进阶

- **各种图像解析器中的漏洞**：尝试复现已知漏洞并深入研究这些问题的根本原因。
- **绕过 disable_functions**：探索可用于绕过 `disable_functions` 的各种技术。这可能涉及上传 Python 或 Perl 等语言的 shell，甚至利用反向 shell。
- **文件上传场景**：检查 DOCX、PDF 和 XML 等文件扩展名可以被恶意利用的场景。
- **符号链接和 ZIP 炸弹**：调查可能容易受到 ZIP 炸弹和符号链接利用等攻击的服务器端 ZIP 提取功能。
- **使用无害扩展名的 DoS 攻击**：检查如何使用 PNG、JPG 和 GIF 等无害扩展名进行 DoS 攻击。
- **文件上传绕过**：探索使用附加空字节或利用双扩展名等技术绕过文件上传限制。
