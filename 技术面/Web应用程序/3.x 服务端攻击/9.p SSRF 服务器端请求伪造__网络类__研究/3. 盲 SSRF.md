
## 什么是盲 SSRF

当应用程序可以被诱导向提供的 URL 发出后端 HTTP 请求，但后端请求的响应未在应用程序的前端响应中返回时，就会出现盲 SSRF 漏洞。

### 盲 SSRF 漏洞的影响是什么？

盲 SSRF 漏洞的影响通常低于完全可见的 SSRF 漏洞，因为它们具有单向性质。它们不能轻易被利用来从后端系统检索敏感数据，尽管在某些情况下它们可以被利用来实现完全远程代码执行。

### 如何发现和利用盲 SSRF 漏洞

检测盲 SSRF 漏洞最可靠的方法是使用带外（OAST）技术。这涉及尝试触发对您控制的外部系统的 HTTP 请求，并监视与该系统的网络交互。

使用带外技术最简单、最有效的方法是使用 [Burp Collaborator](/burp/documentation/collaborator)。您可以使用 [Burp Collaborator](/burp/documentation/desktop/tools/collaborator) 生成唯一的域名，将这些域名作为载荷发送到应用程序，并监视与这些域的任何交互。如果观察到来自应用程序的传入 HTTP 请求，则说明它存在 SSRF 漏洞。

> **注意：** 在测试 SSRF 漏洞时，通常会观察到对提供的 Collaborator 域进行 DNS 查找，但没有后续的 HTTP 请求。这通常是因为应用程序尝试向该域发出 HTTP 请求，导致了初始的 DNS 查找，但实际的 HTTP 请求被网络级过滤阻止了。允许出站 DNS 流量在基础设施中相对常见，因为这在许多用途中都是需要的，但会阻止到非预期目标的 HTTP 连接。

仅仅识别出一个能够触发带外 HTTP 请求的盲 SSRF 漏洞本身并不能提供一条可利用的路径。由于您无法查看后端请求的响应，因此该行为不能用于探索应用程序服务器可以访问的系统上的内容。但是，它仍然可以被利用来探测服务器本身或其他后端系统上的其他漏洞。您可以盲目地扫描内部 IP 地址空间，发送旨在检测已知漏洞的载荷。如果这些载荷也使用盲带外技术，那么您可能会在未打补丁的内部服务器上发现一个关键漏洞。
- ssrf 初始脆弱主机：携带载荷到内网的最终脆弱主机
- 最终脆弱主机：发送 dns 带外请求到攻击者域名

利用盲 SSRF 漏洞的另一个途径是诱导应用程序连接到攻击者控制的系统，并向发起连接的 HTTP 客户端返回恶意响应。如果您能利用服务器 HTTP 实现中的严重客户端漏洞，您可能能够在应用程序基础设施内实现远程代码执行。
