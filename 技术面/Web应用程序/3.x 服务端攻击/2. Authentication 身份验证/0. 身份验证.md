# 身份验证

## 身份验证与授权攻击

应用程序在身份验证方面集成了许多安全控制措施，包括账户锁定机制、验证码（CAPTCHA）、“忘记密码”功能、多因素认证等。这些保护措施有时会因具体实现而被攻击者滥用。同样，多种攻击也可用于针对应用程序的授权机制。常见攻击包括强制浏览、不安全的直接对象引用（IDOR）等，这些通常会导致敏感数据泄露以及水平和垂直权限提升。

身份验证和授权各自承担不同的角色：

- **身份验证（Authentication）**：指验证用户身份的过程，通常通过用户名、电子邮件地址、密码或唯一令牌/PIN 码等凭据进行。
- **授权（Authorization）**：一旦身份验证成功且用户身份得到确认，下一步就是确定用户可以访问哪些资源。这个决策过程即称为授权。

现代 Web 应用程序依赖多种身份验证和授权机制。其中许多构成了单点登录（SSO）的基础，SSO 允许用户使用一组凭据访问多个应用程序。以下是一些常见的协议：

- **JSON Web Tokens（JWT）**：JSON Web Token 用于处理身份验证和在应用程序之间安全交换数据。它们既可用于身份验证，也可用于授权。
- **OAuth**：OAuth 是一种协议，主要用于第三方应用程序在不共享密码的情况下授权访问用户资源。OAuth 的主要用例是执行授权；但与其他协议结合时也可用于身份验证。
- **安全断言标记语言（SAML）**：SAML 允许在线服务交换身份验证和授权数据。其核心是一个 SSO 协议，允许用户在登录一次后访问多个应用程序。虽然其主要作用是提供身份验证，但也可传递用户属性用于授权目的。

## 身份验证漏洞

身份验证漏洞可能允许攻击者访问敏感数据和功能。它们还为进一步的攻击暴露了额外的攻击面。

许多最常见的验证漏洞实际上极其简单。任何人都可以在登录表单中输入字典中的单词，试图猜测有效的密码。另外，应用程序中也隐藏着一些细微的缺陷，只有对复杂的多阶段登录机制进行仔细分析后才能发现它们并对其加以利用。

## 什么是身份验证？

身份验证是验证用户或客户端身份的过程。网站可能暴露给任何连接到互联网的人。这使得健壮的身份验证机制成为有效 Web 安全不可或缺的一部分。

身份验证主要有三种类型：

- 你**知道**的东西，例如密码或安全问题答案。这些有时被称为“知识因素”。
- 你**拥有**的东西，这是一个物理对象，例如手机或安全令牌。这些有时被称为“拥有因素”。
- 你**是**什么或做什么。例如，你的生物特征或行为模式。这些有时被称为“固有因素”。

身份验证机制依赖于一系列技术来验证这些因素中的一个或多个。


## 身份验证漏洞是如何产生的？

身份验证机制中的大多数漏洞以下列两种方式之一发生：

- 身份验证机制薄弱，因为它们未能充分防御暴力破解攻击。
- 实现中的逻辑缺陷或糟糕的编码允许攻击者完全绕过身份验证机制。这有时被称为“损坏的身份验证”。

在 Web 开发的许多领域中，逻辑缺陷会导致网站出现意外行为，这可能不一定是安全问题。然而，由于身份验证对安全性如此关键，有缺陷的身份验证逻辑很可能使网站面临安全问题。

## 易受攻击的身份验证会造成什么影响？

身份验证漏洞的影响可能很严重。如果攻击者绕过身份验证或通过暴力破解进入另一个用户的账户，他们可以访问被入侵账户所拥有的所有数据和功能。如果他们能够入侵高权限账户（如系统管理员），他们可以完全控制整个应用程序，并可能获得对内部基础设施的访问权限。

即使入侵低权限账户，也可能仍会让攻击者访问他们本来不应该拥有的数据，例如商业敏感信息。即使该账户没有任何敏感数据的访问权限，它仍可能允许攻击者访问更多页面，从而提供进一步的攻击面。通常，高严重性攻击无法从公开可访问的页面发起，但可能从内部页面发起。
