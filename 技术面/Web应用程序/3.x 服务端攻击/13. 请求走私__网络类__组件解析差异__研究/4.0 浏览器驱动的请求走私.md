# 浏览器驱动的请求走私

在本节中，您将学习如何构造高严重性的漏洞利用，而无需依赖浏览器永远不会发送的格式错误请求。这不仅将全新的网站范围暴露给服务器端请求走私，还使您能够通过诱导受害者的浏览器投毒其与易受攻击的 Web 服务器之间的连接，来执行这些攻击的客户端变体。

> #### PortSwigger 研究
>
> 本节中的材料和实验基于 PortSwigger Research 的 [Browser-Powered Desync Attacks: A New Frontier in HTTP Request Smuggling](https://portswigger.net/research/browser-powered-desync-attacks)。这项研究还导致发现了使用[连接状态缺陷](https://portswigger.net/web-security/host-header/exploiting#connection-state-attacks)绕过 Host 头过滤器的一种技术。

## CL.0 请求走私

后端服务器有时可以被说服忽略 `Content-Length` 头，这实际上意味着它们会忽略传入请求的消息体。这为不依赖[分块传输编码](https://portswigger.net/web-security/request-smuggling#how-do-http-request-smuggling-vulnerabilities-arise)或 [HTTP/2 降级](https://portswigger.net/web-security/request-smuggling/advanced/http2-downgrading)的请求走私攻击铺平了道路。

## 客户端反同步攻击

传统上，请求走私被认为是服务器端问题，因为它只能使用 Burp Repeater 等专用工具来利用——标准浏览器根本不会发送触发反同步所需的那种请求。然而，基于从 [CL.0 攻击](https://portswigger.net/web-security/request-smuggling/browser/cl-0)中吸取的经验教训，有时可以使用完全与浏览器兼容的 HTTP/1 请求来引起反同步。

您可以使用这些与浏览器兼容的请求来触发浏览器和易受攻击的 Web 服务器之间的客户端反同步（CSD），从而攻击单服务器站点（否则它们对请求走私免疫）以及您无法直接访问的内部网络站点。

## 基于暂停的反同步攻击

看似安全的网站可能包含隐藏的反同步漏洞，只有在请求中途暂停时才会暴露出来。通过发送头部、承诺一个消息体，然后只是等待，您有时可以发现额外的反同步漏洞，这些漏洞可以用于服务器端和客户端的利用。
