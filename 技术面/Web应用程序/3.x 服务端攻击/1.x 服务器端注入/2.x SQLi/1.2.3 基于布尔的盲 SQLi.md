## 布尔 SQL 注入

当应用程序存在 SQL 注入漏洞，但其 HTTP 响应中不包含相关 SQL 查询的结果或任何数据库错误的详细信息时，即产生盲 SQL 注入。

此时，尝试使用布尔利用技术的推理方法，来恢复某些所需字段的值。此方法包括对服务器执行一系列布尔条件查询（这通常使用 `AND` 和 `OR` 运算符以及特定条件），观察答案，并最终推断出这些答案的含义。

这些技巧全都基于如下概念：使用一个注入查询有条件地在数据库中触发某种可以探测的行为，然后根据这种行为是否发生推断出所需信息。

如，使用条件的真假控制功能是否执行来推断数据，探测密码时循环每个字符的所有可能的ASCII编码，直到出现一个“触点”，就能够以每次一个字节的速度，提取出整个字符串。

示例的服务器查询为：

```sql
SELECT field1, field2, field3 FROM Users WHERE Id='$Id'
```

可用的标准函数，如：

- `[SUBSTR|SUBSTRING](text, start, length)`：返回从文本的 "start" 位置开始、长度为 "length" 的子字符串。*如果 "start" 大于文本长度，则函数返回空字符串 `''`*。

- `ASCII(string)`：返回输入字符串第一个字符的 ASCII 值。
    - 当字符串为空 `''`，返回 0
    - 当字符串为 NULL，返回 NULL

- `LENGTH(text)`：返回输入文本中的字符数。

基于这些函数，在第一个字符上执行测试，当发现其值后，再转到第二个字符，依此类推，直到发现整个值。测试将利用 SUBSTRING 函数一次只选择一个字符（选择单个字符意味着将长度参数设为 1），并利用 ASCII 函数获取 ASCII 值，以便进行数值比较。比较结果将与 ASCII 表中的所有值进行比较，直到找到正确的值。作为示例，我们将对 `Id` 使用以下值：

`$Id=1' OR ASCII(SUBSTRING(username,1,1))=97 AND '1'='1`

这创建了以下查询（从现在起，我们称之为“推理查询”）：

```sql
SELECT field1, field2, field3 FROM Users WHERE Id='1' OR ASCII(SUBSTRING(username,1,1))=97 AND '1'='1'
```

前一个示例当且仅当 username 字段的第一个字符等于 ASCII 值 97 时返回结果。
- 如果我们得到假值，则我们将增减 ASCII 表的索引并重复请求。
- 相反，如果我们得到真值，则将 ASCII 表索引设置为 0，并分析下一个字符，修改 SUBSTRING 函数的参数。

问题在于理解如何确认触点（区分返回真值与返回假值的测试）。为此，我们创建一个始终返回假的查询。这可以通过对 `Id` 使用以下值来实现：

`$Id=1' AND '1' = '2`

这将创建以下查询：

```sql
SELECT field1, field2, field3 FROM Users WHERE Id='1' AND '1' = '2'
```

从服务器获得的响应（即 HTML 代码）将是我们的测试的假值。这足以验证执行推理查询获得的值是否与之前执行的测试获得的值相等。有时，此方法不起作用。如果服务器对两个相同的连续 Web 请求返回两个不同的页面，我们将无法区分真值和假值。在这些特殊情况下，需要使用特定的过滤器来消除两次请求之间变化的代码，并获得一个模板。稍后，对于执行的每个推理请求，我们将使用相同的函数从响应中提取相关模板，并执行两个模板之间的控制以决定测试结果。

### 确定测试终止条件

接下来考虑如何确定测试的终止条件（即何时应该结束推理过程）：
- 一种技术使用 `SUBSTRING` 函数的特性（当参数 `start` 大于文本长度，函数返回空字符串 `''`）与 `ASCII` 函数的特性（当字符串为空 `''`，返回 0）。
    - 当测试将当前字符与 ASCII 代码 0（即，空字符串 `''`）进行比较且测试返回真值时，要么我们完成了推理过程（我们已经扫描了整个字符串），要么我们分析的字段为空字符串。

- 另一种技术使用 `SELECT LENGTH` 函数确认当前字段字符串长度

盲 SQL 注入攻击需要大量查询。测试人员可能需要自动工具来利用该漏洞。

此技术可用来提取数据库中的关键信息，如数据库版本、表名、列名和凭据

### 引发条件性错误

在前面的示例中，应用程序拥有一些主要功能，可以通过注入一个现有的SQL查询直接控制它们的逻辑。攻击者能够劫持应用程序计划执行的行为（成功或失败的操作）以获得想要的信息。然而，并非所有攻击都这样简单。有时，注入的查询并不会给应用程序的行为造成直接影响。或者，应用程序并不处理注入的一个子查询或批量查询。

此时，尝试触发可探测的行为差异的核心理念是：注入一个查询，依照某个特定的条件引发一个数据库错误。通常，数据库抛出的未处理错误会导致应用程序响应中的某些差异（HTTP 500 响应码，或某种错误消息或反常行为），从而推断推断注入条件的真假。

这种技巧利用了数据库在求条件语句的值时表现出的条件语句短路执行，使用WHERE子句的SELECT语句 

```sql
SELECT X FROM Y WHERE C
```

这条语句使数据库访问表Y的每一行，评估条件C。如果条件C为真，返回X。如果条件C永为假，永远不求出表达式X的值。

可以找到一个语法有效但如果求值就会生成错误的表达式X，对这种行为加以利用。在 Oracle 与 MS-SQL 中，被零除计算就是这样的表达式，如`1/0`。如果条件C为真，那么求表达式X的值，这造成一个数据库错误。如果条件C为假，就不会发生错误。因此，可以通过是否发生错误测试任意一个条件C。

为了了解其工作原理，假设依次发送两个请求：

```sql
$input='xyz' AND (SELECT CASE WHEN (1=2) THEN 1/0 ELSE 'a' END)='a'
$input='xyz' AND (SELECT CASE WHEN (1=1) THEN 1/0 ELSE 'a' END)='a'
```

这些输入使用 `CASE` 关键字来测试条件，并根据表达式是否为真返回不同的表达式：

- 对于第一个输入，`CASE` 表达式计算结果为 `'a'`，不会导致任何错误。
- 对于第二个输入，它计算结果为 `1/0`，会导致除以零错误。

这种技巧的目的是在应用程序中引发一个条件性响应，即使注入的查询不会给应用程序的逻辑或数据处理造成影响。因此，利用它就可以使用前面描述的推论技巧在各种情况下提取到所需要的数据。这种技巧的用途非常广泛，因为它可以用在可以注入子查询的各种注入点中。

例如：使用此技术，每次测试一个字符来检索数据：

```sql
$input='xyz' AND (SELECT CASE WHEN (Username = 'Administrator' AND SUBSTRING(Password, 1, 1) > 'm') THEN 1/0 ELSE 'a' END FROM Users)='a'
```

通过对 SQLMap 之类的 SQL 注入工具仔细设定这个条件，我们可以检索数据库中的每一条记录。

### 示例：Cookie 中的布尔盲 SQLi

假设一个应用程序使用跟踪 Cookie 来收集使用情况分析。对应用程序的请求包含如下 Cookie 头：

```http
Cookie: TrackingId=u5YD3PapBcR4lN3e7Tj4
```

当处理包含 `TrackingId` Cookie 的请求时，应用程序使用 SQL 查询来确定这是否是已知用户：

```sql
SELECT TrackingId FROM TrackedUsers WHERE TrackingId = 'u5YD3PapBcR4lN3e7Tj4'
```

此查询存在 SQL 注入漏洞，但查询结果不会返回给用户。然而，应用程序的行为确实会根据查询是否返回数据而有所不同。如果你提交一个已识别的 `TrackingId`，查询会返回数据，你会在响应中收到一条“欢迎回来”消息。

这种行为足以利用盲 SQL 注入漏洞。你可以根据注入的条件是否成立，有条件地触发不同的响应来检索信息。

为了理解这种利用方式，假设依次发送两个请求，包含以下 `TrackingId` Cookie 值：

```sql
$input = '…xyz' AND '1'='1'
$input = '…xyz' AND '1'='2'
```

- 第一个值导致查询返回结果，因为注入的 `AND '1'='1` 条件为真。因此，显示“欢迎回来”消息。
- 第二个值导致查询不返回任何结果，因为注入的条件为假。“欢迎回来”消息不显示。

这使我们能够确定任何单个注入条件的真假，并逐段提取数据。

例如，假设有一个名为 `Users` 的表，包含 `Username` 和 `Password` 列，并且有一个名为 `Administrator` 的用户。你可以通过发送一系列输入，每次测试一个字符来确定该用户的密码。

为此，首先使用以下输入：

```sql
$input = 'xyz' AND SUBSTRING((SELECT Password FROM Users WHERE Username = 'Administrator'), 1, 1) > 'm'
```

这会返回“欢迎回来”消息，表明注入条件为真，因此密码的第一个字符大于 `m`。

接下来，我们发送以下输入：

```sql
$input = 'xyz' AND SUBSTRING((SELECT Password FROM Users WHERE Username = 'Administrator'), 1, 1) > 't'
```

这不会返回“欢迎回来”消息，表明注入条件为假，因此密码的第一个字符不大于 `t`。

最终，我们发送以下输入，它返回“欢迎回来”消息，从而确认密码的第一个字符是 `s`：

```sql
$input = 'xyz' AND SUBSTRING((SELECT Password FROM Users WHERE Username = 'Administrator'), 1, 1) = 's'
```

我们可以继续这个过程，系统地确定 `Administrator` 用户的完整密码。
