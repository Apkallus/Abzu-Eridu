# 基于 DOM 的客户端 SQL 注入

在本节中，我们将讨论什么是基于 DOM 的客户端 SQL 注入，描述攻击者如何利用此漏洞，并提供减少此类攻击风险的建议。

## 什么是基于 DOM 的客户端 SQL 注入？

当脚本以不安全的方式将攻击者可控制的数据合并到客户端 SQL 查询中时，就会产生客户端 SQL 注入漏洞。攻击者可能利用此漏洞构造一个 URL，当其他用户访问该 URL 时，会在用户浏览器的本地 SQL 数据库中执行任意 SQL 查询。

## 基于 DOM 的客户端 SQL 注入有何影响？

此漏洞的潜在影响取决于网站对 SQL 数据库的使用方式。如果数据库用于存储敏感数据，例如社交网络中的消息，攻击者可能能够检索这些数据。

如果数据库用于存储待处理的用户操作，例如电子邮件应用程序中的待发消息，则攻击者可能能够修改这些数据，并代表用户执行任意操作。

## 哪些汇可能导致基于 DOM 的客户端 SQL 注入漏洞？

JavaScript 数据库函数 `executeSql()` 可能导致客户端 SQL 注入漏洞。

## 如何防止基于 DOM 的客户端 SQL 注入漏洞？

除了[基于 DOM 的漏洞](/web-security/dom-based)页面中描述的常规措施外，还应确保对所有数据库访问使用参数化查询（也称为预编译语句）。此方法通过两个步骤安全地将可能被污染的数据纳入 SQL 查询：

1. 应用程序指定查询的结构，为每项用户输入预留占位符。
2. 应用程序指定每个占位符的内容。由于查询的结构已在第一步中定义，第二步中格式错误的数据无法干扰查询结构。

在 JavaScript `executeSql()` API 中，可以在查询字符串中使用查询字符 `?` 来标识参数化项。对于每个参数化项，需要向 API 额外传递一个包含该项值的参数。为防止疏漏，并避免因应用程序代码库其他位置的变更引入漏洞，强烈建议将纳入数据库查询的每个可变数据项都进行参数化，即使其并非明显存在风险。
