# 基于 DOM 的 document.domain 操纵

在本节中，我们将介绍基于 DOM 的 `document.domain` 属性操纵，并提供减少此类攻击风险的建议。

## 什么是基于 DOM 的 document.domain 操纵？

当脚本使用攻击者可控制的数据来设置 `document.domain` 属性时，就会产生基于 DOM 的 document.domain 操纵漏洞。攻击者可能利用此漏洞构造一个 URL，当其他用户访问该 URL 时，会使响应页面设置任意的 `document.domain` 值。

浏览器在强制执行同源策略时会使用 `document.domain` 属性。如果来自不同来源的两个页面显式设置了相同的 `document.domain` 值，那么这两个页面可以不受限制地进行交互。如果攻击者能够使目标网站的一个页面与其控制的另一个页面（直接控制或通过类似 XSS 的漏洞控制）设置相同的 `document.domain` 值，则攻击者可能通过其已控制的页面完全攻陷目标页面。这为攻击者提供了与常规跨站脚本（XSS）漏洞相同的利用可能性。

浏览器通常对可赋给 `document.domain` 的值施加一些限制，并且可能阻止使用与页面实际来源完全不同的值。然而，这里有两个重要的注意事项。首先，浏览器允许使用子域或父域，因此攻击者可能能够将目标页面的域切换为相关网站的域，而该网站的安全态势可能较弱。其次，某些浏览器的特性使得切换到完全不相关的域成为可能。这些注意事项意味着，操纵页面 `document.domain` 属性的能力通常代表一个安全漏洞，其严重程度不亚于常规 XSS。
