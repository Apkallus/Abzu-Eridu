# 同源策略（SOP）

在本节中，我们将解释什么是同源策略（SOP）以及它是如何实现的。

## 什么是同源策略？

同源策略是一种 Web 浏览器安全机制，旨在防止网站相互攻击。

同源策略限制一个源上的脚本访问另一个源的数据。一个源由 URI 方案、域和端口号组成。例如，考虑以下 URL：

`http://normal-website.com/example/example.html`

它使用的方案是 `http`，域是 `normal-website.com`，端口号是 `80`。下表展示了当上述 URL 中的内容尝试访问其他源时，同源策略将如何应用：

| 被访问的 URL | 是否允许访问？ |
| --- | --- |
| `http://normal-website.com/example/` | 是：相同的方案、域和端口 |
| `http://normal-website.com/example2/` | 是：相同的方案、域和端口 |
| `https://normal-website.com/example/` | 否：不同的方案和端口 |
| `http://en.normal-website.com/example/` | 否：不同的域 |
| `http://www.normal-website.com/example/` | 否：不同的域 |
| `http://normal-website.com:8080/example/` | 否：不同的端口* |

*Internet Explorer 将允许此访问，因为 IE 在应用同源策略时不考虑端口号。

## 为什么需要同源策略？

当浏览器从一个源向另一个源发送 HTTP 请求时，与另一个域相关的任何 Cookie（包括身份验证会话 Cookie）也会作为请求的一部分发送。这意味着响应将在用户的会话中生成，并包含特定于用户的任何相关数据。如果没有同源策略，如果你访问了一个恶意网站，它就能够读取你的 Gmail 邮件、Facebook 私信等。

## 同源策略如何实现？

同源策略通常控制 JavaScript 代码对跨域加载内容的访问。页面资源的跨域加载通常是允许的。例如，SOP 允许通过 `<img>` 标签嵌入图片，通过 `<video>` 标签嵌入媒体，通过 `<script>` 标签嵌入 JavaScript。然而，虽然这些外部资源可以被页面加载，但页面上的任何 JavaScript 都无法读取这些资源的内容。

同源策略存在各种例外情况：

- 某些对象是跨域可写但不可读的，例如 iframe 或新窗口中的 `location` 对象或 `location.href` 属性。
- 某些对象是跨域可读但不可写的，例如 `window` 对象的 `length` 属性（存储页面上使用的框架数量）和 `closed` 属性。
- `replace` 函数通常可以在 `location` 对象上跨域调用。
- 你可以跨域调用某些函数。例如，你可以对新窗口调用 `close`、`blur` 和 `focus` 函数。`postMessage` 函数也可以在 iframe 和新窗口上调用，以便从一个域向另一个域发送消息。

由于历史遗留需求，同源策略在处理 Cookie 时更加宽松，因此它们通常可以从网站的所有子域访问，即使每个子域在技术上是一个不同的源。你可以使用 `HttpOnly` Cookie 标志来部分缓解此风险。

可以使用 `document.domain` 来放宽同源策略。这个特殊属性允许你为特定域放宽 SOP，但前提是该域是你的 FQDN（完全限定域名）的一部分。例如，你可能有一个域 `marketing.example.com`，并且你希望在 `example.com` 上读取该域的内容。为此，两个域都需要将 `document.domain` 设置为 `example.com`。然后，SOP 将允许两个域之间的访问，尽管它们的源不同。在过去，可以将 `document.domain` 设置为 TLD（如 `com`），这允许同一 TLD 上的任何域之间进行访问，但现在现代浏览器已阻止此行为。

## 不受 SOP 限制的跨域通信方式

- postMessage 窗口通信
- JS 回调函数端点
