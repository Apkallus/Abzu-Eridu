# 什么是 GraphQL？

GraphQL 是一种 API 查询语言，旨在促进客户端与服务器之间的高效通信。它允许用户精确指定他们希望在响应中获得的数据，有助于避免 REST API 中有时会出现的大响应对象和多次调用的问题。

GraphQL 服务定义了一个契约，客户端可通过该契约与服务器通信。客户端无需了解数据存储的位置。相反，客户端向 GraphQL 服务器发送查询，服务器则从相关位置获取数据。由于 GraphQL 与平台无关，它可以用多种编程语言实现，并可用于与几乎任何数据存储进行通信。

> **注意**
> 本页概述了 GraphQL 是什么及其工作原理。有关如何测试 GraphQL 漏洞的具体信息，请参阅 [GraphQL API 漏洞](https://portswigger.net/web-security/graphql)。

## GraphQL 如何工作

GraphQL 模式（schema）定义了服务数据的结构，列出了可用的对象（称为类型）、字段和关系。

GraphQL 模式描述的数据可通过三种操作类型进行操纵：

- **查询（Query）** —— 获取数据。
- **变更（Mutation）** —— 添加、更改或删除数据。
- **订阅（Subscription）** —— 类似于查询，但建立持久连接，服务器可通过该连接主动以指定格式向客户端推送数据。

所有 GraphQL 操作都使用同一个端点，通常以 POST 请求发送。这与 REST API 显著不同，后者通过一系列 HTTP 方法使用特定于操作的端点。在 GraphQL 中，操作的类型和名称决定了查询的处理方式，而非发送到的端点或使用的 HTTP 方法。

GraphQL 服务通常以请求结构的 JSON 对象作为操作响应。

## 什么是 GraphQL 模式？

在 GraphQL 中，模式代表了服务前端与后端之间的契约。它使用人类可读的模式定义语言，将可用数据定义为一系列类型。然后，服务可以实现这些类型。

定义的大多数类型都是对象类型，它们定义了可用的对象及其字段和参数。每个字段都有自己的类型，该类型可以是另一个对象，也可以是标量、枚举、联合、接口或自定义类型。

以下示例展示了一个简单的 Product 类型模式定义。`!` 运算符表示调用时该字段不可为空（即必填）。

```graphql
# 示例模式定义

type Product {
    id: ID!
    name: String!
    description: String!
    price: Int
}
```

模式还必须包含至少一个可用查询。通常，它们还包含可用变更的详细信息。

## 什么是 GraphQL 查询？

GraphQL 查询从数据存储中检索数据，大致相当于 REST API 中的 GET 请求。

查询通常包含以下关键组件：

- **`query` 操作类型** —— 从技术上讲是可选的，但建议使用，因为它明确告知服务器传入请求是一个查询。
- **查询名称** —— 可以是任何你想要的名字。查询名称是可选的，但建议使用，因为它有助于调试。
- **数据结构** —— 查询应返回的数据。
- **可选地，一个或多个参数** —— 用于创建返回特定对象详细信息的查询（例如“给我 ID 为 123 的产品的名称和描述”）。

以下示例展示了一个名为 `myGetProductQuery` 的查询，它请求 `id` 为 `123` 的产品的 `name` 和 `description` 字段。

```graphql
# 示例查询示意

query 自定义查询名称 {
    getProduct(参数字段名: 参数字段值) {
        返回字段a
        返回字段b
    }
}
```

```graphql
# 示例查询

query myGetProductQuery {
    getProduct(id: 123) {
        name
        description
    }
}
```

注意，产品类型在模式中可能包含比此处请求的更多的字段。仅请求所需数据的能力是 GraphQL 灵活性的重要体现。

若请求体中包含可选操作字段 `operationName`，需与查询字段 `query` 的自定义名称匹配

## 什么是 GraphQL 变更？

变更加以某种方式更改数据，包括添加、删除或编辑数据。它们大致相当于 REST API 的 POST、PUT 和 DELETE 方法。

与查询类似，变更具有操作类型、名称和返回数据的结构。然而，变更始终接受某种类型的输入。这可以是内联值，但在实践中通常作为变量提供。

以下示例展示了一个创建新产品的变更及其相关响应。在此情况下，服务被配置为自动为新产品分配 ID，该 ID 已按请求返回。

```graphql
# 示例变更请求示意

mutation {
    createProduct(设置字段a名: 设置字段a值, 设置字段b名: 设置字段b值) {
        id
        返回字段a
        返回字段a
    }
}
```

```graphql
# 示例变更请求

mutation {
    createProduct(name: "Flamin' Cocktail Glasses", listed: "yes") {
        id
        name
        listed
    }
}
```

```json
# 示例变更响应

{
    "data": {
        "createProduct": {
            "id": 123,
            "name": "Flamin' Cocktail Glasses",
            "listed": "yes"
        }
    }
}
```

## 查询和变更的组成部分

GraphQL 语法包含查询和变更的几种常见组件。

### 字段

所有 GraphQL 类型都包含可查询的数据项，称为字段。当你发送查询或变更时，你可以指定希望 API 返回哪些字段。响应会镜像请求中指定的内容。

以下示例展示了一个获取所有员工的 ID 和姓名详细信息的查询及其相关响应。在此示例中，`id`、`name.firstname` 和 `name.lastname` 是请求的字段。

```graphql
# 请求

query myGetEmployeeQuery {
    getEmployees {
        id
        name {
            firstname
            lastname
        }
    }
}
```

```json
# 响应

{
    "data": {
        "getEmployees": [
            {
                "id": 1,
                "name": {
                    "firstname": "Carlos",
                    "lastname": "Montoya"
                }
            },
            {
                "id": 2,
                "name": {
                    "firstname": "Peter",
                    "lastname": "Wiener"
                }
            }
        ]
    }
}
```

### 参数

参数是为特定字段提供的值。类型可接受的参数在模式中定义。

当你发送包含参数的查询或变更时，GraphQL 服务器会根据其配置决定如何响应。例如，它可能返回特定对象，而非所有对象的详细信息。

以下示例展示了一个以员工 ID 作为参数的 `getEmployee` 请求。在此情况下，服务器只返回与该 ID 匹配的员工的详细信息。

```graphql
# 带参数的示例查询

query myGetEmployeeQuery {
    getEmployees(id: 1) {
        name {
            firstname
            lastname
        }
    }
}
```

```json
# 查询响应

{
    "data": {
        "getEmployees": [
            {
                "name": {
                    "firstname": "Carlos",
                    "lastname": "Montoya"
                }
            }
        ]
    }
}
```

> **注意**
> 如果用户提供的参数用于直接访问对象，GraphQL API 可能存在访问控制漏洞，例如不安全的直接对象引用（IDOR）。

### 变量 —— 复用结构，多参数

变量允许你传入动态参数，而不是将参数直接内联到查询本身中。

基于变量的查询使用与内联参数查询相同的结构，但查询的某些方面是从一个单独的基于 JSON 的变量字典中获取的。它们允许你在多个查询中复用通用结构，只需更改变量本身的值。

在构建使用变量的查询或变更时，你需要：

1. 声明变量及其类型。
2. 在查询中的适当位置添加变量名。
3. 从变量字典中传入变量键和值。

以下示例展示了与上例相同的查询，但 ID 是作为变量而非查询字符串的直接部分传入的。

```graphql
# 带变量的示例查询示意

query 自定义名称($变量: 变量类型!) {
    查询方法(变量字段: $变量) {
        返回对象 {
            返回字段a
            返回字段b
        }
    }
}

# 变量
{
    "变量字段": 变量值
}
```

```graphql
# 带变量的示例查询

query getEmployeeWithVariable($id: ID!) {
    getEmployees(id: $id) {
        name {
            firstname
            lastname
        }
    }
}

# 变量
{
    "id": 1
}
```

在此示例中，变量在第一行声明（`$id: ID!`）。`!` 表示该字段为此查询的必填字段。然后它在第二行用作参数（`id: $id`）。最后，变量自身的值在变量 JSON 字典中设置。有关如何测试这些漏洞的信息，请参阅 [GraphQL API 漏洞](https://portswigger.net/web-security/graphql)。

### 别名

GraphQL 对象不能包含多个同名的属性。例如，以下查询无效，因为它试图返回两次 `product` 类型。

```graphql
# 无效查询

query getProductDetails {
    getProduct(id: 1) {
        id
        name
    }
    getProduct(id: 2) {
        id
        name
    }
}
```

别名使你可以通过显式命名希望 API 返回的属性来绕过此限制。你可以使用别名在一次请求中返回同一类型对象的多个实例，这有助于减少所需的 API 调用次数。

在以下示例中，查询使用别名为两个产品指定了唯一名称。该查询现在通过验证，并返回详细信息。

```graphql
# 使用别名的有效查询

query getProductDetails {
    product1: getProduct(id: "1") {
        id
        name
    }
    product2: getProduct(id: "2") {
        id
        name
    }
}
```

```json
# 查询响应

{
    "data": {
        "product1": {
            "id": 1,
            "name": "Juice Extractor"
        },
        "product2": {
            "id": 2,
            "name": "Fruit Overlays"
        }
    }
}
```

> **注意**
> 在变更中使用别名可让你在单个 HTTP 请求中发送多个 GraphQL 消息。
>
> 有关如何利用此技术绕过某些速率限制的更多信息，请参阅[使用别名绕过速率限制](https://portswigger.net/web-security/graphql#bypassing-rate-limiting-using-aliases)。

### 片段 —— 字段子集

片段是查询或变更的可复用部分。它们包含关联类型所属字段的子集。

一旦定义，它们可以被包含在查询或变更中。如果随后被更改，更改将反映在调用该片段的每个查询或变更中。

以下示例展示了一个 `getProduct` 查询，其中产品详细信息包含在 `productInfo` 片段中。

```graphql
# 示例片段

fragment productInfo on Product {
    id
    name
    listed
}
```

```graphql
# 调用片段的查询

query {
    getProduct(id: 1) {
        ...productInfo
        stock
    }
}
```

```json
# 包含片段字段的响应

{
    "data": {
        "getProduct": {
            "id": 1,
            "name": "Juice Extractor",
            "listed": "no",
            "stock": 5
        }
    }
}
```

## 订阅

订阅是一种特殊类型的查询。它们使客户端能够与服务器建立持久连接，以便服务器随后可以向客户端推送实时更新，而无需持续轮询数据。它们主要用于大型对象的小型更改和需要小型实时更新的功能（如聊天系统或协作编辑）。

与常规查询和变更一样，订阅请求定义了要返回的数据结构。

订阅通常使用 WebSocket 实现。

## 自省（Introspection）

自省是 GraphQL 的一项内置功能，使你能够向服务器查询有关模式的信息。它通常被 GraphQL IDE 和文档生成工具等应用程序使用。

与常规查询一样，你可以指定要返回的响应字段和结构。例如，你可能希望响应仅包含可用变异的名称。

自省可能带来严重的信息泄露风险，因为它可用于访问潜在敏感信息（如字段描述），并帮助攻击者了解如何与 API 交互。最佳实践是在生产环境中禁用自省功能。

[GraphQL 网站描述了自省](https://graphql.org/learn/introspection/)：

> “询问 GraphQL 模式关于它支持哪些查询的信息通常很有用。GraphQL 允许我们通过自省系统来做到这一点！”

> **注意**
> 有关如何使用 GraphQL 自省查询和测试自省漏洞的更多信息，请参阅 [GraphQL API 漏洞](https://portswigger.net/web-security/graphql)。
