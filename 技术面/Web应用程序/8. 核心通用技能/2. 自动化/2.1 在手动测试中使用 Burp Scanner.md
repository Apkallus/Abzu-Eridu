# 在手动测试中使用 Burp Scanner

在本节中，我们将展示多种方法，通过使用 Burp Scanner 来补充你自己的知识和直觉，从而优化手动测试工作流程。这不仅有助于覆盖更多测试面，还能让你将时间花在真正重要的事情上，而不是繁琐的初步工作上。

## 扫描特定请求

当你遇到某个有趣的功能或行为时，第一反应可能是将相关请求发送到 Repeater 或 Intruder 进行深入调查。但将请求也交给 Burp Scanner 处理通常是很有益的。它可以在你专注于其他更有价值的工作时，处理测试中更为重复性的方面。

如果你右键单击某个请求并选择 **Do active scan**，Burp Scanner 将使用其默认配置仅审计该请求。

![执行主动扫描](https://portswigger.net/web-security/essential-skills/images/scanning-active-scan.png)

这可能无法捕获所有可能的漏洞，但有可能在几秒钟内标记出那些原本可能需要数小时才能发现的问题。它也可能帮助你几乎立即排除某些攻击途径。你仍然可以使用 Burp 的手动工具进行更有针对性的测试，但现在可以将精力集中在特定的输入和较窄范围的潜在漏洞上。

即使你已经使用 Burp Scanner 对新目标进行常规爬取和审计，切换到这种更有针对性的审计方式也可以大幅减少整体扫描时间。

## 扫描自定义插入点

将扫描范围限制在单个请求上的好处显而易见，但你还可以更进一步，只测试该请求中的特定输入。你可以在消息编辑器中执行此操作。

高亮你感兴趣的插入点，然后右键单击并选择 **Scan selected insertion point**。

![扫描选中的插入点](https://portswigger.net/web-security/essential-skills/images/scan-selected-insertion-point.png)

这样你可以将注意力集中在你感兴趣的输入上，而不是扫描那些你知道不太可能有用的额外内容。

虽然你也可以使用 Intruder 定义一个插入点，但通常使用 [Scan manual insertion point](https://portswigger.net/bappstore/ca7ee4e746b54514a0ca5059329e926f) 扩展会更快捷。你可以高亮请求中的任意字符序列（通常是参数值），然后从上下文菜单中选择 **Extensions > Scan manual insertion point**。

这种方法可以极快地产生结果，只需几秒钟就能给你提供一些可用的信息。这也意味着你可以选择扫描 Burp Scanner 通常不使用的输入，例如自定义头部值。

## 扫描非标准数据结构

由于你可以在任意位置自由定义插入点，因此也可以针对值内的特定子字符串进行扫描。这在扫描非标准数据结构时尤其有用。

在处理 JSON 等常见格式时，Burp Scanner 能够解析数据并将负载放置在正确的位置，而不会破坏结构。但是，考虑一个如下所示的参数：

```
user=048857-carlos
```

凭直觉，我们可以猜测后端会将其视为两个不同的值：某种 ID 和看起来像用户名的部分，由连字符分隔。然而，Burp Scanner 会将整个内容视为单个值。因此，它只会将负载放在参数末尾，或者完全替换该值。

为了帮助扫描非标准数据结构，你可以扫描参数的某一部分。在本例中，你可能希望针对 `carlos` 进行测试。你可以在消息编辑器中高亮 `carlos`，然后右键单击并选择 **Scan selected insertion point**。

你也可以使用 Intruder 定义多个插入点。在上面的示例中，你可以为 `048857` 和 `carlos` 分别定义插入点，然后右键单击并选择 **Scan defined insertion points**。
