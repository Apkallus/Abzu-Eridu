## 终端

`Ctrl-R` 搜索历史命令，实时匹配当前输入
- `回车` 选定并执行
- `→` 右方向键选定并边界 

`.bashrc` 文件
- `PS4 & set` 格式显示指令
- `ls` 列出挑战目录内容
- `rm/mkdir/cp` 复制挑战目录内容到当前工作目录
- `mapfile/file/grep/sed` 将选定类型文件保存为数组批量处理
    - `basename` 从路径提取文件名
        - 使用 `binary.ninja` 静态分析
    - `checksec` 查看 elf 文件安全信息
- `ropper/ROPgadget` 查找 ROP 工具
    - `ropper` 对内核文件查找时在挑战中 Killed
- `objdump/grep` 查看 ret2cus 地址
- `/proc/cpuinfo` 查看 cpu 支持 
    - `shstk|ibt`

`dmesg -W &` 持续输出最新内核日志
`ps aux | grep` 打印进程信息
`kill -s 9` 终止进程
`while true; do 命令; sleep 0.5; done` 持续执行指令

结构：
- `pahole -C _IO_FILE /lib/x86_64-linux-gnu/libc.so.6` 查看数据结构布局，以确认字段偏移
- gdb 对指针进行强制类型转换后查看结构或字段
- `grep -R "struct _IO_FILE" /usr/include 2>/dev/null` 头文件中查找
- elixir.bootlin.com 查找
- 在编译的头 include 路径中查找常量/结构/原型
    `grep -r SOCK_STREAM /usr/include/x86_64-linux-gnu`

gdb:
- 在程序添加 `input()` 设置暂停
- gdb 运行到断点等待输入
- 使用 `Ctrl-B 方向键` 切换窗口到程序
- 按任意键继续运行,触发 gdb 断点

rop/shellcode:
- 使用 pwntool 的 `ELF()` 得到程序对象
    - `elf.address` 设置基址
    - `ROP(elf)` 设置 rop 对象
- 使用 `ROPgadget --binary` 或 `rp++ --unique -r2 -f` 或 `ropper --file` 查看工具
    - 在 pwntool 的 rop 对象使用 `rop.find_gadget(['pop rax', 'ret']).address` 得到工具地址
- `ldd` 查看链接的库文件路径


## 探测与利用

### 用户提权

```sh
# ⚠️ 拥有密码或无密码 -> 切换为其他用户
su root

# ⚠️ 拥有权限或无密码 -> 切换为其他组
newgrp root

# ⚠️ 拥有权限或无密码 -> 以拥有者权限执行
sudo id
```

### 修改文件权限

```sh
# ⚠️ 拥有权限，修改文件所有者或组
chown hacker /flag
chown 1000 /flag

# ⚠️ 拥有权限，修改文件组
chgrp hacker /flag
chgrp 1000 /flag

# ⚠️ 拥有权限，修改文件访问控制
chmod a+rwx,ug+s /flag
chmod 6777 /flag
```

### 文件目录操作

```sh
# 移除文件时检查目录权限，而非文件权限
rm target_file
mv my_file target_file
cp my_file target_file
```

### 操作进程

```sh
# 终止进程
kill 342

# 查看进程退出码
echo $?
```

### 环境变量

```sh
# 修改环境变量 `PATH` 以设置执行路径
PATH=''
PATH="/home/hacker:${PATH}"
```

### 记录

```sh
# 命令型：作为目标程序包装器，记录交互
script -q /tmp/log -c "/target_program"

# 终端型：记录所有交互，关闭双重回显，显式设置记录参数
script -q --echo never --log-io /tmp/io
```

`.bashrc`

## 交互

1. 与程序初步交互，查看程序输出与预期输入
2. 根据程序输出格式选择分隔串，以提取或发送数据
    - 提取
        - 初始分隔串：引言段与数据段的交界
        - 数据段分隔串（可选）：仅当数据段不规则时使用，通常不设置

    - 发送
        - 输入提示串，或数据段后即等待输入

    - 结果
        - 过程结果串
            - miss/hit 结果或触点串
            - 中间数据

        - 最终结果
            - 通常与过程结果串的格式不同
                - 连续读取而不是读取特定数量/行
                - 或模式不匹配后（显式检测或抛出异常）读取剩余数据并打印当前+剩余数据
    
    - 通用
        - 数据读取时分配到各处。
            - 例如多轮交互时，发送后重复读取将同时得到本轮结果 + 下一轮程序输出
                - 分配到结果读取1行，提取时重复读取（不会消耗预期外程序输出的同时，当最终结果格式不同时也可回显）
                

3. 解析格式以提取数据，或发送数据
    - 打印出 byte 型字符串，进行格式清理

## 数据

函数类型 
- 帮助型函数
    - 跨越多场景，至少部分通用

- 示意型函数
    - 概念与函数组合示意，需调整构建后使用

- 过程型函数
    - 特定场景下的语义与功能划分



函数结构
- 主函数作为入口
    - 多次调用过程函数

- 拆分逻辑到被调过程函数

    

调试
- 调试输出均设置为 log 的 `debug` 级，以快速切换输出详细程度
- 函数入口打印参数
- 打印关键中间与结果对象
- 使用 bytes 字节型打印 `f"bar {bar!r}"`

格式化
- 设置类而不是字典
    - 被分析器解析
        - 对象可添加文档说明，字段集中在一处易于查看
        - 字段输入 `.` 即引用。而不是字典的方括号+字符串

- 使用语义化名称
    - 对象/函数命名
    - 正则表达式的命名组匹配 `(?P<name>...)`
    - 若参数标注类型，此时被分析器解析，可使用精简命名

tips
- 注意空串处理
