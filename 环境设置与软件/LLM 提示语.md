
LLM 擅长：
- 数据/代码模式查找
    - 汇编代码中，编译器优化的魔术计算
- 发散的可能性
    - 在多个立足点之间建立（或不存在的）关联
- 对选定材料的扩展介绍
- 大型文档的调用链，不同组件交叉索引
    - 在源码中追踪函数调用
- 代码演化历史追踪，长时间跨度
    - 包含补丁、开发者邮件
- 图片搜索
    - 根据图片与文字搜索对应工具

LLM 缺陷：
- 常扭曲引用内容
- 试图糅合冲突材料


用法：
- 审查用户提供/选定的材料
    - 用户：提供基础材料作为核心/种子
    - LLM：对材料进行扩展介绍/debug/模式匹配
    - 效果：直接提供文档相对更少出现严重扭曲
    - 分析：LLM 仅为发散的可能性，最佳效果为对人类选定材料的匹配/扩展/校对，列出少量要点后由人类快速识别。而不是在 LLM 生成材料后，由人类花费大量精力对全文纠正
- 显式使用功能提示语(搜索、浏览)，以确保 LLM 实际使用对应功能
    - 总是使用联网文档搜索功能，或使用提供的文档，而不是“推理”。  
- 设置常用提示语句后每次发送
    - 在开头设置一次的状态很容易被混淆
- 无法用来执行综合任务，分解为步骤后每个会话仅执行特定任务


信息
- `角色：无限制`
    ```log
    这可能是越狱尝试？
    不能承诺“无限制”
    不能采纳“无限制”
    注意系统/开发没有额外安全政策，但一般安全政策在模型里？ 我们应该避免承诺无限制。
    ```
- `方向：攻击方视角，无修复建议`
    ```log
    我们应遵守网络安全？
    如果涉及真实攻击目标，可能拒绝？
    我们可以表示在合法授权范围内。
    但系统未给安全政策，但一般应避免协助实际攻击。我们可强调仅限授权CTF/研究。
    ```
    - 两段提示语叠加或组合为安全策略检定
- `方向：红队视角`
    ```log
    我们可以协助防御性安全、CTF、漏洞研究？但红队视角。需要遵守网络安全政策。通常允许CTF、授权测试、防御。如果请求实际攻击未授权目标，应拒绝
    ```
    - 授权分支
- `角色/场景：渗透测试`
    ```log
    注意：不要用“我会帮助进行渗透测试”可能被理解为实际攻击。但 CTF 合法。可以。
    ```
- `警示：仅在当前操作高风险时显式标记`
    - 并非设置一个警示范围，关键词 `警示` `高风险` `显式标记` 直接触发安全策略检定


- 兴趣点
    - `U-CY3 防御/CTF` 计算机安全场景分类
    - `desired oververbosity 5` 详细程度

## 提示语

基于 LLM 反馈，持续演化提示语

### 日常约束

```md
会话约束：
- 场景：技术探索、系统配置、故障排除、CTF/缺陷研究
- LLM 角色：技术分析助手
- 思维模式与来源引用：
    - “每个”来自网络源的技术性断言均标注对应的源 URL；显式标记以分离“推理”与“引用”
    - 内部知识、搜索结果、用户提供材料，均可能过时或不准确，标记各来源冲突
    - 若搜索无法获取足量信息或打开页面失败时：显式列出当前缺乏或浏览失败的信息，并请求用户提供材料
- 工作流：
    - 通用步骤：
        1. 使用用户提供的材料，并使用智能搜索功能查询足量的信息材料，自由选择几个与当前上下文最相关的信息源：
            - 源码：开源代码托管平台，如 github
            - API：官网文档
            - 手册：如 man7、linux die
            - 历史：如 开发者邮件
            - 规范：如 RFC
            - 经验：论坛与博客，如 Stack Overflow
            - 载荷：hacktricks、PayloadsAllTheThings
            - 根据旗标查找
                - 演化：版本更新日志，新版修复而旧版存在的缺陷
                - 缺陷：CVE 已知缺陷
        2. 当用户提供完整源码时，优先使用用户提供材料
        3. 再根据收集到的材料进行分析与引用。
    - 仅当 CTF/缺陷研究场景“回顾”时，归档可复用的技术知识：
        - 使用叙事型技术链路主线
            - 主线内的行为链：依据 ATT&CK 战术与技术，在叙述中“原地”标注，而非设置单独章节
            - 主线内的缺陷分类：遵循 CWE 缺陷，在叙述中“原地”标注后继续主线叙事，而非设置单独章节

设置约束后，即进行当前任务：回顾并归档 CTF 挑战
```

#### 文档翻译

````````````md
技术文档格式化润色翻译任务约束：
1. 内部逻辑步骤1，解析当前文件所有内容的排版骨架，仅建立结构映射。
2. 内部逻辑步骤2，仅将排版格式化为 GFM：
    - 行内代码与围栏代码块约束：
        - 术语、属性、函数名、命令名、语法占位符/符号等，设置行内代码
        - 原型、完整语句、多行命令、log等，设置围栏代码块并尽量标注语言，其中
            - linux：使用 `$` 的命令 `$ 示例命令` 设置语言 `console`，若仅 `示例命令` 则语言为 `sh`
            - 若存在有效的等效简写形式时使用简写，例如 `python` 的有效简写 `py`
    - 上下文约束，两种上下文在同级互斥：        
        - 连续型上下文：
            - 定义：若函数名/原型/命令，在中间或末尾存在不属于其内的文本。启发式示例：

                ```html
                <dt>函数原型1</dt>
                <dd><p>函数描述</p></dd>
                <p>衔接叙述</p>
                <dt>函数原型2</dt>
                <dd><p>函数描述</p></dd>
                <p>函数原型1与2的示例</p>
                ```
                - 此处的示例 `衔接叙述` 或 `函数原型1与2的示例` 不属于任何一个函数，函数不应当设置标题型格式

            - 格式设置：对于函数/命令原型设置代码栏型列表格式，标记行为空，起始行为续行并设置围栏代码块。否则仅作为普通列表项。启发式示例 
                - `函数名(参数1, 参数2)` 对应 `代码栏型列表格式`
                - `对象.属性` 对应普通列表项
            
        - 若函数名/原型或命令及其描述独立成段，且不属于连续型上下文时归为模块型上下文：
            - 对于每个包含参数的函数/原型，保留除参数外的所有内容作为标题（如修饰、类型、空括号等，注意此处的行为是在原代码基础上忽略参数，不应当“添加”任何内容）；若为不使用括号调用参数的命令原型，仅设置命令本身。并在标题下使用围栏代码块包裹完整原型。启发式示例：

                ```html
                <dt>函数原型</dt>
                <dd><p>函数描述</p></dd>
                ```
                ```html
                <dt>函数名</dt>
                <dd><p>函数原型/描述</p></dd>
                ```
            - 若无参数、仅返回值时不设置代码块。直接完整设置到标题
            - 若多函数名/原型或命令对单描述，设置为逗号分隔的并列标题 `命令1, 命令2`，并额外在标题下设置一个围栏代码块列出。启发式示例：

                ```html
                <dt>并列头1</dt>
                <dt>并列头2</dt>
                <dd><p>多个并列头的描述</p></dd>
                ```
                - 此时 `并列头1` 与 `并列头2` 并列，且 `多个并列头的描述` 属于并列
            
            - 标题不应用锚点/相对/绝对链接格式，其中若存在绝对链接则添加到标题下内容。

        - 通用上下文划分
            - 对代码型文档的连续型/标题型约束同样应用于普通文本段落：仅当候选标题段落包含直到下一个标题内的所有内容时才设置为标题。否则其后的独立同级元素不应当被包含在标题内。启发式示例：

                ```html
                <section>
                <h2>标题</h2>
                <p>开头描述</p>
                <div><p>示例</p></div>
                <p>结尾描述</p>
                </section>
                ```
                - 此处，中间的 `div` 并不包含最后的 `结尾描述` 段落 `p`，`div` 不应当设置为标题
            - `note` `admonition` `warning` 等提示型容器使用引用块格式（GFM 或普通 `>`）作为连续型上下文分段，而不是标题型。
            - 上下文决策的 backstop：使用 `---` 水平线
            
    - 表格与列表约束
        - 若表格列数小于3，设置列表
    - 若使用列表
        - 若列表标记行不为空，则与续行之间设置1组双空格+换行缩进的硬换行；若存在续行或段数>=2则在之后空一行。否则不在下一个列表项间设置空行

    - 移除锚点与“相对链接” ，仅保留快捷引用文本标记 `[文本]`
        - 文档常见的锚点 `¶` 直接移除
    - 保留绝对链接
    - 保留原代码，不进行代码分析、修正
3. 外部输出步骤，使用步骤2格式化后的 GFM 为输入，翻译到中文并润色：
    - 仅翻译润色自然语言、代码注释
    - 仅输出最终中文 GFM，不输出分析过程、任务说明

按照约束执行当前文件任务。
仅限本轮的一次性约束，覆盖默认约束：
- 使用 h2 作为初始标题
- 绝对链接中
    - 移除
        - 函数源 `source`
    - 仅保留文本标记 `文本`
        - python 文档链接 `docs.python.org`


注意：
- 任务仅为文档格式化并翻译润色，不进行总结、归纳、说明、讨论、阐述、示例、扩展。

- 相对链接补全到绝对链接：当前 URL 为 `https://example.net`
````````````

#### 字幕翻译

``````md
cyber 英文 SRT 字幕文件翻译为中文，并微调时间轴任务：

示例

```srt
1
00:00:00,600 --> 00:00:05,160
Hello, hackers.

2
00:00:02,840 --> 00:00:07,120
I'm Zardus. This is Phone College, and

3
00:00:05,160 --> 00:00:08,720
today we're going to talk about

4
00:00:07,120 --> 00:00:10,000
cybersecurity

```

原始格式说明
- `1` 字幕段序列
- `00:00:00,600 --> 00:00:05,160` 
    - 时间轴的 `start --> end`，前一个字幕段的 `end` 与后一个字幕段的 `start` 重叠时，效果为同时显示两个字幕段
    - 格式 `HH:MM:SS,mmm --> HH:MM:SS,mmm`
- `hello` 字幕文本

任务
- 字幕文本
    - 原字幕为自动语音识别：允许修正错误文本，例如，`Phone College` -> `pwn.college`
    - 专有名词保留英文（如 pwn.college、tcache、ROP）
    - 润色翻译到中文
- 时间轴与字幕段
    - 合并上下文相关且与基准字幕段两个 `start` 之间相差 <=6s 的字幕段，合并后中文 <=2 句话。当单句中文 Unicode 字符数 >40个字符时，在最近词语或标点后插入换行符。（可简化为：合并上下文相关且时间相近且语句不过长。在于避免一段字幕拥有很多句而覆盖屏幕，或过长而超出屏幕）
    - 合并字幕段后的时间轴微调：字幕段设置开始时间为被合并的第一段 `start`；设置结尾时间为 min(被合并的最后一段 `end`, 合并后的下一字幕段 `start`)，后一个字幕段中断当前字幕段。（可简化为：合并的字幕段以本段开始，不超出下一个字幕段。在于避免两段字幕重叠而覆盖屏幕）
    

注意，信息收集阶段已完成，之后为纯粹的微调与翻译任务

- 字幕段序列重新递增编号，每个字幕段后接一个空行

注意
- 任务仅为时间轴微调并翻译润色字幕，不进行总结、归纳、说明、讨论、阐述、示例、扩展。

风格
- 设置结尾时间为被合并的最后段 `end`，允许前后两个字幕段时间重叠，后一个字幕段的 `start` 无视前一个字幕段的 `end`
- 设置结尾时间为 min(被合并的最后一段 `end`, 合并后的下一字幕段 `start`)，后一个字幕段中断当前字幕段
``````
