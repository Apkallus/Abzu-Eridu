LLM 擅长：
- 数据/代码模式查找
    - 汇编代码中，编译器优化的魔术计算
- 发散的可能性
    - 在多个立足点之间建立（或不存在的）关联
- 对选定材料的扩展介绍
- 大型文档的调用链，不同组件交叉索引
    - 在源码中追踪函数调用
- 代码演化历史追踪，长时间跨度
    - 包含补丁、开发者邮件
- 图片搜索
    - 根据图片与文字搜索对应工具

LLM 缺陷：
- 常扭曲引用内容
- 试图糅合冲突材料


用法：
- 审查用户提供/选定的材料
    - 用户：提供基础材料作为核心/种子
    - LLM：对材料进行扩展介绍/debug/模式匹配
    - 效果：直接提供文档相对更少出现严重扭曲
    - 分析：LLM 仅为发散的可能性，最佳效果为对人类选定材料的匹配/扩展/校对，列出少量要点后由人类快速识别。而不是在 LLM 生成材料后，由人类花费大量精力对全文纠正
- 显式使用功能提示语(搜索、浏览)，以确保 LLM 实际使用对应功能
    - 总是使用联网文档搜索功能，或使用提供的文档，而不是“推理”。  
- 设置常用提示语句后每次发送
    - 在开头设置一次的状态很容易被混淆
- 无法用来执行综合任务，分解为步骤后每个会话仅执行特定任务

# 技术文档格式化润色翻译任务约束

## 工作流

1. 内部逻辑步骤1，解析当前文件所有内容的排版骨架（例如，节点关联、类型），仅建立结构映射，不输出。
2. 内部逻辑步骤2，仅将排版格式化为 GFM，按下方格式化规则执行，不输出。
3. 外部输出步骤，使用步骤2格式化后的 GFM 或用户提供的 md 文件为输入，翻译润色到中文：
    - 仅翻译润色自然语言、代码注释
    - 仅输出最终中文 GFM，不输出分析过程、任务说明

## 格式化规则

代码单元边界：
- 若特殊字符属于代码片段内部标点（根据上下文判断），则归为代码语法字符，此时不应作为字段分隔或续行拆分。启发式示例：  
    `hooks: dict[str, list[_t.HookType]]`
    - 在 python 语法中，此处的 `:` 作为注解分隔符。

行内代码与围栏代码块约束：
- 术语、属性、函数名、命令名、语法占位符/符号等，设置行内代码
- 原型、完整语句、多行命令、log、HTML元素等，设置围栏代码块并尽量标注语言：
    - linux：使用 `$` 的命令 `$ 示例命令` 设置语言 `console`；若仅 `示例命令` 则语言为 `sh`
        - 若原文在一段中同时存在未使用 `$` 的命令及其输出，设置代码栏类型为空，而不是分割为 `sh` + `log` 两个代码栏。
    - python: 使用 `>>>` 的代码 `>>> 示例代码` 设置语言 `pycon`，若仅 `示例代码` 则语言为 `py`
    - 若存在有效的等效简写形式时使用简写，例如 `python` 的有效简写 `py`
    - 程序输出，设置 `log`
    - 无对应类型则为空，例如：bash 命令中 `ls -al` 设置 `sh`，但仅参数的 `-al` 设置空

上下文约束，连续型与模块型两种上下文在同一层级组内互斥：  
- 基础上下文
    - 仅当候选标题段落包含直到下一个标题内的所有内容时才设置为标题。否则其后的独立同级元素不应当被包含在标题内。启发式示例：

        ```html
        <section>
        <h2>标题</h2>
        <p>开头描述</p>
        <div><p>示例</p></div>
        <p>结尾描述</p>
        </section>
        ```
        - 此处，中间的 `div` 并不包含最后的 `结尾描述` 段落 `p`，`div` 不应当设置为标题
    - `note`、`admonition`、`warning`、变更日志等提示型容器使用引用块格式（GFM 或普通 `>`）而不是标题
    - 标题不应用锚点/相对/绝对链接格式，其中若存在绝对链接则添加到标题下内容。
            
- 连续型上下文
    - 定义：对于函数名/原型/命令，在中间或末尾存在不属于其内的文本。启发式示例：  

        ```html
        <dt>函数原型1</dt>
        <dd><p>函数描述</p></dd>
        <p>衔接叙述</p>
        <dt>函数原型2</dt>
        <dd><p>函数描述</p></dd>
        <p>函数原型1与2的示例</p>
        ```
        - 此处的示例 `衔接叙述` 或 `函数原型1与2的示例` 不属于任何一个函数，函数不应当设置标题型格式

    - 格式设置：对于函数/命令原型设置“代码栏型列表”格式，标记行为 `- ` （单个空格，构成有效 md 列表格式），起始行为续行并设置围栏代码块。否则仅作为普通列表项。启发式示例：
        - `函数(参数1, 参数2)` 对应 “代码栏型列表”格式：

            ``````md
            - 
                ```语言
                函数(参数1, 参数2)
                ```
            ``````

        - `对象.属性` 等使用普通列表项

- 模块型上下文
    - 定义：对于函数名/原型/命令/参数/属性等及其描述在同级上下文中独立成段，且不属于连续型上下文时归为模块型上下文。模块型上下文划分为在同一层级组内互斥的标题型与列表型。

    - 同级中属性方法交错的特殊格式：当原文并未将属性与方法归为同类容器下，或并非前半连续属性 + 后半连续方法到下一级。此时属性方法交错，使用启发式示例分类
        - 交错的特殊格式示例
            ```html
            <dl>
            <dt>属性1</dt><dd><p>属性1描述</p></dd>
            <dt>方法1</dt><dd><p>方法1描述</p></dd>
            <dt>方法1</dt><dd><p>方法1描述</p></dd>
            <dt>属性1</dt><dd><p>属性1描述</p></dd>
            </dl>
            ```
        - 非交错的普通格式示例
            ```html
            <dl>
            <dt>属性1</dt><dd><p>属性1描述</p></dd>
            <dt>属性1</dt><dd><p>属性1描述</p></dd>
            <dt>方法1</dt><dd><p>方法1描述</p></dd>
            <dt>方法1</dt><dd><p>方法1描述</p></dd>
            </dl>
            ```
            ```html
            <dl>
            <dt>属性1</dt><dd><p>属性1描述</p></dd>
            <dt>属性1</dt><dd><p>属性1描述</p></dd>
            </dl><dl>
            <dt>方法1</dt><dd><p>方法1描述</p></dd>
            <dt>方法1</dt><dd><p>方法1描述</p></dd>
            </dl>
            ```

        - 分类时优先使用匹配模式数量更多的类型，若相同则应用其中更为接近的一条：
            - 列表型上下文
                - 模式：同级候选总数较少；大多为属性；大多描述简短
                - 格式：属性仍使用列表，对方法使用“代码栏型列表”格式
            
            - 标题型上下文
                - 模式：同级候选总数较多；大多为方法；大多描述稍长
                - 格式：方法仍使用标题型，对于属性使用标题格式
                    - 非标题型中，属性等仅保留名称（不含类型）到标题，表达式等完整设置为标题；再将参数、属性、表达式等完整放入标题下设置的代码栏内

    - 标题型：
        - 对于每个包含参数的函数/原型/类等：保留除参数外的所有内容作为标题（如修饰、类型、空括号等，注意此处的行为是在原代码基础上忽略参数，不应当“添加”任何内容），并在标题下完整设置到围栏代码块
