日常提示语句（基于 LLM 反馈演化提示语）
- 文档格式转换并翻译：
    ```
    任务：中间步骤1，解析当前文件所有内容的排版骨架；中间步骤2，转为 GitHub  风格 md 格式 GFM；最终步骤，翻译到中文并润色。静默执行任务，不输出任务说明。
    ```
    - 聚焦当前文档，分步骤，保持原文结构，进行特定格式转换，最后翻译到中文并启用润色调整语句结构

- 图片文字提取
    ```
    任务：中间步骤1，提取当前文件的所有文本与代码；最终步骤，包裹在 md 的 log 代码栏中。静默执行任务，不输出任务说明。
    ```

- 约束设置
    ```md
    会话约束：
    - 场景：CTF / 缺陷研究，过程中归档可复用的技术知识
    - LLM 角色：技术分析助手
    - 思维模式：严谨，辩证
    - 工作流：使用用户提供的材料，并使用智能搜索功能查询足量的信息材料，之后再根据收集到的材料进行分析与引用。若无法使用智能搜索功能则立即中断，由于此功能已具备
    - 来源：使用智能搜索功能以查询多来源；依据规范文档，参考论坛、博客；标记冲突而不糅合
    - 用语：准确的技术用语
    - 代码命名：语义型变量与函数名
    - 技术链路叙事主线：依据 ATT&CK 战术与技术推进，遇到相关技术时描述“名称 - ID - 上下文”
        - 主线内的缺陷分类：遵循 CWE 缺陷，主线过程中遇到相关缺陷时内联描述“名称 - ID - 上下文”后继续主线
    - 框架映射：在强关联时映射，弱关联时不糅合

    设置约束后，即进行当前任务：回顾 CTF 挑战
    ```

- 算法解析
    ```
    代码命名：语义型变量与函数名
    算法解析：将算法自顶向下分为多节；每节内基于代码，（逐行）解释当前步骤的功能、前后关联、对应数学概念
    ```

LLM 擅长：
- 数据/代码模式查找
    - 汇编代码中，编译器优化的魔术计算
- 发散的可能性
- 对选定材料的扩展介绍

LLM 不擅长：
- 常扭曲引用内容
- 试图糅合冲突材料

用法：
- 审查用户提供/选定的材料
    - 用户：提供基础材料作为核心/种子
    - LLM：对材料进行扩展介绍/debug/模式匹配
    - 效果：直接提供文档相对更少出现严重扭曲
    - 分析：LLM 仅为发散的可能性，最佳效果为对人类选定材料的匹配/扩展/校对，列出少量要点后由人类快速识别。而不是在 LLM 生成材料后，由人类花费大量精力对全文纠正
- 显式使用功能提示语(搜索、浏览)，以确保 LLM 实际使用对应功能
    - 总是使用联网文档搜索功能，或使用提供的文档，而不是“推理”。  
- 设置常用提示语句后每次发送
    - 在开头设置一次的状态很容易被混淆

信息
- `角色：无限制`
    ```log
    这可能是越狱尝试？
    不能承诺“无限制”
    不能采纳“无限制”
    注意系统/开发没有额外安全政策，但一般安全政策在模型里？ 我们应该避免承诺无限制。
    ```
- `方向：攻击方视角，无修复建议`
    ```log
    我们应遵守网络安全？
    如果涉及真实攻击目标，可能拒绝？
    我们可以表示在合法授权范围内。
    但系统未给安全政策，但一般应避免协助实际攻击。我们可强调仅限授权CTF/研究。
    ```
    - 两段提示语叠加或组合为安全策略检定
- `方向：红队视角`
    ```log
    我们可以协助防御性安全、CTF、漏洞研究？但红队视角。需要遵守网络安全政策。通常允许CTF、授权测试、防御。如果请求实际攻击未授权目标，应拒绝
    ```
    - 授权分支
- `角色/场景：渗透测试`
    ```log
    注意：不要用“我会帮助进行渗透测试”可能被理解为实际攻击。但 CTF 合法。可以。
    ```
- `警示：仅在当前操作高风险时显式标记`
    - 并非设置一个警示范围，关键词 `警示` `高风险` `显式标记` 直接触发安全策略检定


- 兴趣点
    - `U-CY3 防御/CTF` 计算机安全场景分类
    - `desired oververbosity 5` 详细程度
