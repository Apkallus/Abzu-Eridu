#### WSL (Windows 的 Linux 子系统)

- [WSL Github releases](https://github.com/microsoft/WSL/releases)

- [wsl ipv6](https://learn.microsoft.com/en-us/windows/wsl/networking#ipv6-access)
    - 设置 WSL 为镜像模式
    - 设置防火墙

    ⚠ 镜像模式下 nmap 的原始套接字 sS 包的接收异常：
    
    WSL 在开启镜像模式时（官网文档中启用 ipv6的方式）:
    - 运行 nmap 的 -sS 时
        - 在物理机运行的流量嗅探总能够得到 SA 响应
        - 但 WSL 运行的流量嗅探偶尔才可得到 SA 响应（nmap 正确根据是否得到 SA 响应标记open或过滤）。
    - 运行 nmap 的 -sT 时，一切正常，物理机与 WSL 得到所有 SA 响应

    wsl 在关闭镜像模式时：
    - 一切正常，物理机与 WSL 得到所有 SA 响应

    即，启用 WSL 网络设置中的镜像模式导致使用原始套接字（-sS）的选项大多时候失灵，仅偶尔可得到 SA 响应。

    WSL 的 github 项目在几年前即存在类似的[报告](https://github.com/microsoft/WSL/issues/12185)，项目组无意修复

#### Docker

`docker pull` 下载容器时网络异常
1. 访问[镜像检测项目](https://github.com/dongyubin/DockerHub)获得最新可用镜像
2. 在 Docker 设置中选择 Docker Engine 项，在 json 中添加获得的镜像地址：
    ```json
    "registry-mirrors": [
        "https://docker.1ms.run",
        "https://docker.xuanyuan.me",
        "https://hub.rat.dev",
        "https://dockerproxy.com"
    ]
    ```
    - 或单次指定镜像源 
        ```sh
        docker pull 镜像端点/library/容器名:版本
        docker pull docker.1ms.run/library/mysql:5.7
        ```
        - 此时容器名为镜像端点，可使用 `docker tag` 设置别名

> 虽然各种工具可能有其对应的版本控制工具，然而操作系统/软件包等组件之间仍可能出现各种异常。使用旧版程序的最简单方式即为安装对应容器

##### 虚拟机设置

- 在 Ubuntu 安装 VMware 工具的 [openvmtools](https://knowledge.broadcom.com/external/article/313456/vmware-support-for-openvmtools.html)，以启用3D加速与双向粘贴板
    进入虚拟机后命令行输入 
    ```sh
    sudo apt update
    sudo apt install open-vm-tools open-vm-tools-desktop
    reboot
    ```
- 启用共享文件夹：
    `VM - 设置 - 选项 - 共享文件夹` 启用并选择文件夹位置
    [博通 vmware-tools 命令介绍文章](https://knowledge.broadcom.com/external/article/313233/how-to-configure-vmware-tools-shared-fol.html)
    - 对于 VMware Tools - 共享文件夹用户模式的 FUSE 客户端，请使用以下挂载命令：    
    `sudo /usr/bin/vmhgfs-fuse .host:/ /mnt/hgfs -o subtype=vmhgfs-fuse,allow_other`
- 选项 - 高级 
    - 内存页裁剪，默认启用，将虚拟机未使用的内存返还到宿主机，性能开销较小。
    - 测信道缓解，开启以增强防护，或关闭以提高性能
